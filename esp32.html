ESP32 物联网教程

ESP32 是入门物联网最划算的一块板子：一块 ESP32-WROOM-32 上同时集成了 2.4GHz WiFi 和蓝牙， 不用再外挂 ESP-01、HC-05 之类的模块，接线、供电、代码量都省一半。它还带 240MHz 双核、 最多 34 个 GPIO、18 路 ADC 和 2 路 8 位 DAC，跑 Arduino 库毫无压力—— 用 WiFi.begin() 五六行就能连上路由器，用 PubSubClient 就能把数据发到 MQTT 平台。 学完这一套，你能独立做出「手机远程控制继电器 + 温湿度上云」这类毕设级别的小系统， 也是从 51/STM32 走向联网设备最平滑的一步。

7 个专题 芯片：ESP32-WROOM-32 工具：Arduino IDE 建议周期：4~6 周

Why ESP32

为什么选 ESP32 入门物联网

物联网入门最怕两件事：硬件东拼西凑、代码看不懂。ESP32 恰好把这两个坑都填了。

1

一块板子同时有 WiFi 和蓝牙

ESP32-WROOM-32 内部就带 2.4GHz WiFi（STA / AP / 混杂模式）和经典蓝牙 + BLE。 做联网项目不用再买 WiFi 模块，做手机遥控也不用额外插蓝牙模块，接线少一半，供电只需一根 USB 线。

2

Arduino 生态库多，几行代码就出效果

装好 esp32 board package 后，连路由器只要 WiFi.begin(ssid, password)， 读温湿度直接调 DHT 库，发 MQTT 用 PubSubClient。 不用啃寄存器手册，先把「能跑通」的正反馈拿到手，再回头补底层原理。

3

价格低、资料多，做毕设最容易出效果

一块开发板二三十元，烧了也不心疼；示例程序、开源库、视频教程遍地都是， 卡住了几乎都能搜到答案。答辩时「手机 App 远程控制 + 数据上云 + 曲线展示」这套组合， 比单纯的流水灯更容易讲出技术含量。

Foundations

基础篇：ESP32 多出来的那几层，先认全

ESP32 不是“51 加个 WiFi 模块”。它自带双核、RTOS、协议栈，用 C++ 写，还要讲网络。 这 5 篇把多出来的那几层一次讲清——从 FreeRTOS 任务是什么，到 IP、端口、MQTT 到底在传什么。

ESP32 上最容易翻车的三件事
  • · 供电——WiFi 发射瞬间电流能冲到 500mA，电脑 USB 口撑不住就会不停重启。
  • · 引脚——GPIO6~11 接了内部 Flash，GPIO34~39 只能输入，用错了程序直接不启动。
  • · 网络——很多人会照抄 MQTTClient.publish()，却不知道 Topic、端口、Broker 分别是什么，于是连不上也查不出原因。

下面这 5 篇就是按这三个坑排的。

Pitfalls

避坑提示

下面这几条是 ESP32 新手 90% 的「卡住」都发生在同一个地方，遇到问题先按顺序对一遍。

配网失败先确认路由器是 2.4GHz

ESP32-WROOM-32 的 WiFi 只支持 2.4GHz，不支持 5GHz。如果路由器把 2.4G 和 5G 合并成一个名字， 或者你填的是 5G 的 SSID，就会一直卡在连接超时。解决办法：进路由器后台把两个频段分开命名 （例如 MyWiFi-2.4G），把代码里的 ssid 改成 2.4GHz 那个；手机开的热点也要确认是 2.4GHz。

串口全是乱码 = 波特率不对

乱码几乎只有一个原因：串口监视器的波特率和程序里的 Serial.begin() 不一致。 教程统一用 115200，所以监视器右下角也要选 115200。另外确认开发板选的是 ESP32 Dev Module 而不是其他型号， 并检查是否装错串口驱动（CH340 / CP2102 对应不同芯片）。

GPIO6 ~ GPIO11 接了内部 Flash，不能乱用

GPIO6 到 GPIO11 这 6 个引脚在模组内部已经连到 SPI Flash，用来存放程序和数据。 把它们当普通 IO 接外设，轻则读数错误，重则程序直接跑飞、无法启动。接线时把这一片引脚空着即可， 能用的是 GPIO4、5、12~19、21~23、25~27、32~39 这些。

下载失败：按住 BOOT 键再点上传

提示 “Failed to connect to ESP32: Timed out waiting for packet header” 时，按住开发板上的 BOOT 键 → 点上传 → 等串口输出出现 “Connecting...” 再松开，通常就能下载进去。 如果仍然失败，换一根确认能传数据的 USB 线（很多线只能充电），并确认端口没被其他串口软件占用。

analogRead 在 WiFi 开启时会受影响

ESP32 的 ADC2（对应 GPIO0、2、4、12~15、25~27）与 WiFi 共用硬件资源， 只要 WiFi 一开始工作，ADC2 上的 analogRead() 就会失败或读数乱跳。 做联网项目时请一律改用 ADC1 的引脚：GPIO32 ~ GPIO39。

给 WiFi 协议栈留出运行时间

在 loop() 里加一个 delay() 或 vTaskDelay()， 让 WiFi 协议栈和系统任务有机会运行。如果 loop 里写 while 死等、 或者长时间不做任何延时，就会看到 “Task watchdog got triggered” 的看门狗复位，板子每隔几秒重启一次。

Pinout Reference

ESP32 常用引脚与功能速查

以 ESP32-WROOM-32 开发板（30 针 / 38 针常见版本）为准。接线前先看这张表，能省掉一半调试时间。

引脚 可用功能 注意事项
GPIO0 BOOT 按键、Strapping 引脚、普通数字 IO、ADC2 通道 上电瞬间为低电平会进入下载模式而不是运行程序；接按键时要保证松开时为高电平，否则程序不启动。
GPIO2 多数开发板的板载 LED（高电平点亮）、普通数字 IO、ADC2、PWM 同时是 Strapping 引脚，启动时会输出调试信息；不要接会把它拉低的外部电路。开 WiFi 后不能做 ADC。
GPIO4 / GPIO5 普通数字 IO、ADC2、PWM 输出、自定义 I2C 引脚 GPIO5 属于 Strapping 引脚，启动时需为高电平；接外部下拉电阻前先确认不影响启动。
GPIO12 ~ GPIO15 普通数字 IO、ADC2、PWM 输出 全是 Strapping 引脚，启动电平决定了 Flash 电压等配置；尤其 GPIO12 被拉高可能导致启动失败或反复重启，新手建议整组避开。
GPIO16 / GPIO17 普通数字 IO、PWM，默认是 UART2 的 RX / TX WROOM 模组上可正常使用（WROVER 模组被 PSRAM 占用）。外接模块时注意是 3.3V 逻辑电平，不能直接接 5V 信号。
GPIO21 / GPIO22 默认 I2C 的 SDA（21）与 SCL（22），也可做普通 IO 用 Wire 库接 OLED、传感器时就是这两个脚，别再重复分配给其他用途。模块一般自带 4.7k 上拉，没带要自己加。
GPIO25 / GPIO26 真正的 8 位 DAC 模拟输出（dacWrite），也可做 ADC2 全芯片只有这两个脚能输出模拟电压。开 WiFi 后不要再用它们做 analogRead。
GPIO32 ~ GPIO39 ADC1 通道（12 位分辨率），WiFi 开启时仍可正常采集 做联网项目时优先用这一组做模拟输入；GPIO37、GPIO38 在部分模组上没有引出。
GPIO34 ~ GPIO39 仅输入（input only），无内部上拉 / 下拉电阻 只能读电平，不能 digitalWrite，也不能用 INPUT_PULLUP；需要上拉时外接 10k 电阻到 3.3V。

提示：不同厂家开发板的引脚丝印与数量略有差异，接线前请以手上板子的丝印和原理图为准。

Full Example

完整示例：WiFi 连接并打印 IP

这段代码就是第 3 个专题的骨架：STA 模式连接路由器、带超时的连接循环、打印本机 IP， 并在 loop() 里做非阻塞的掉线重连检查。改掉 ssid 与密码即可直接编译上传。 

/*
 * wifi_sta.ino —— ESP32 STA 模式连接路由器并打印 IP
 * 硬件：ESP32-WROOM-32 开发板
 * 环境：Arduino IDE + esp32 board package，串口监视器波特率 115200
 * 注意：ESP32 只支持 2.4GHz WiFi，ssid 请填 2.4G 频段的名称
 */

#include <WiFi.h>

// ① 改成你自己的 WiFi 名称与密码（必须是 2.4GHz 频段）
const char* ssid     = "你的WiFi名称";
const char* password = "你的WiFi密码";

// ② 连接超时时间：15 秒还没连上就先放弃，避免程序死等
const unsigned long CONNECT_TIMEOUT_MS = 15000;

void setup() {
  Serial.begin(115200);          // 与串口监视器的波特率保持一致
  delay(300);                    // 等串口稳定，否则开头几行会是乱码

  Serial.println();
  Serial.println("ESP32 WiFi STA demo start");

  WiFi.mode(WIFI_STA);           // 明确设为 STA 模式（只连路由器，不开热点）
  WiFi.setAutoReconnect(true);   // 打开底层自动重连
  WiFi.begin(ssid, password);    // 开始连接路由器

  Serial.print("Connecting to ");
  Serial.println(ssid);

  unsigned long startMs = millis();
  // ③ 连接循环：每 500ms 查一次状态，超过 15s 就提示失败并退出
  while (WiFi.status() != WL_CONNECTED) {
    if (millis() - startMs > CONNECT_TIMEOUT_MS) {
      Serial.println();
      Serial.println("Connect timeout: 检查 SSID / 密码 / 是否为 2.4GHz");
      break;
    }
    delay(500);
    Serial.print('.');
  }

  if (WiFi.status() == WL_CONNECTED) {
    Serial.println();
    Serial.println("WiFi connected.");
    Serial.print("IP address : ");
    Serial.println(WiFi.localIP());     // 路由器分配到的 IP，手机同网段可访问
    Serial.print("Subnet mask: ");
    Serial.println(WiFi.subnetMask());
    Serial.print("Gateway    : ");
    Serial.println(WiFi.gatewayIP());
    Serial.print("RSSI       : ");
    Serial.print(WiFi.RSSI());          // 信号强度，越接近 0 越强
    Serial.println(" dBm");
  }
}

void loop() {
  // ④ 非阻塞重连检查：每 2 秒看一次状态，掉线了才重新连接
  static unsigned long lastCheckMs = 0;

  if (millis() - lastCheckMs >= 2000) {
    lastCheckMs = millis();

    if (WiFi.status() != WL_CONNECTED) {
      Serial.println("WiFi lost, reconnecting...");
      WiFi.disconnect();
      WiFi.begin(ssid, password);   // 重新发起连接，绝不在 loop 里 while 死等
    } else {
      Serial.print("Still online, IP = ");
      Serial.println(WiFi.localIP());
    }
  }

  // ⑤ 给 WiFi 协议栈和系统任务留出运行时间，避免看门狗复位
  delay(10);
}

烧录后打开串口监视器（115200），先看到 Connecting to ... 和几个点号，连上后会打印 IP、网关与信号强度。 如果一直打印点号直到超时，请回到上面的「避坑提示」逐条排查。
