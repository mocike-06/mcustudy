实训 & 毕设案例

四个可以直接拿去改的完整案例，每个都给出功能说明、硬件清单、核心代码与可扩展方向；课程设计、实训周、毕业设计都能用。

4 个案例 难度：从入门到综合 含硬件清单与代码

Topic Selection

选题建议

题目选得好，后面两个月是顺着做；题目选得飘，后面两个月全在买元件和改方案。

1

优先选买得到元件的题目

开题前先上立创商城、淘宝搜一遍核心器件，缺货、要打样、最小起订量 100 个的，直接换题。元件没到位的这两周，足够别人把功能跑通了。

2

功能不要贪多

一个做扎实的闭环，胜过五个半成品：能采集、能显示、能报警、能复现，就是一个及格的课设。堆了八个功能但每个都只跑通一次，答辩时最容易被问穿。

3

预留一个"可扩展方向"

在报告最后专门写一节"本设计的不足与改进方向"，答辩时这是加分项：老师问"还能怎么优化"，你有现成答案，而不是当场愣住。

进阶

案例 1：51 单片机智能小车

课程设计 / 实训周

定位：最经典的入门级综合题，覆盖 GPIO、定时器、中断、传感器时序四块内容，工作量可控、演示效果直观，适合两周实训或单片机课程设计。

功能说明

  • 上电自动进入循迹模式，左右两路红外探头压在 2cm 宽的黑线跑道上，走完全程不脱线
  • 定时器 0 产生 100Hz 软件 PWM，左右两轮占空比独立可调，通过差速实现转向与调速
  • 车头 HC-SR04 检测到前方 20cm 内有障碍时立即停车，障碍移开后 1s 自动恢复循迹
  • 两路红外同时丢线时原地停车并点亮报警 LED，避免小车冲出跑道烧电机
  • 板载按键在"循迹 / 停车 / 调试"三种模式间切换，LED 指示当前模式
  • 预留 HC-05 蓝牙接口，手机串口助手发单字符指令即可手动控方向

核心代码片段

#include <reg52.h>

/* ---------- 引脚定义：单片机接 L298N 与传感器 ---------- */
sbit L_IN1 = P1^0;      /* 左电机方向脚 1 */
sbit L_IN2 = P1^1;      /* 左电机方向脚 2 */
sbit R_IN1 = P1^2;      /* 右电机方向脚 1 */
sbit R_IN2 = P1^3;      /* 右电机方向脚 2 */
sbit ENA   = P1^4;      /* 左电机使能，接 L298N 的 ENA */
sbit ENB   = P1^5;      /* 右电机使能，接 L298N 的 ENB */
sbit TRACK_L = P3^2;    /* 左红外循迹：压黑线输出 0 */
sbit TRACK_R = P3^3;    /* 右红外循迹：压黑线输出 0 */
sbit TRIG = P3^4;       /* HC-SR04 触发脚 */
sbit ECHO = P3^5;       /* HC-SR04 回响脚，5V 电平可直接接 */

unsigned char duty_L = 60;   /* 左轮占空比 0~100，越大越快 */
unsigned char duty_R = 60;   /* 右轮占空比 0~100 */
unsigned char pwm_cnt = 0;   /* 软件 PWM 计数器 */

/* dir: 1=前进 0=后退 2=停止。两轮反向就是原地差速转向 */
void motor_left(unsigned char dir)
{
    if (dir == 1)      { L_IN1 = 1; L_IN2 = 0; }
    else if (dir == 0) { L_IN1 = 0; L_IN2 = 1; }
    else               { L_IN1 = 0; L_IN2 = 0; }   /* 两脚同低 = 滑行停止 */
}
void motor_right(unsigned char dir)
{
    if (dir == 1)      { R_IN1 = 1; R_IN2 = 0; }
    else if (dir == 0) { R_IN1 = 0; R_IN2 = 1; }
    else               { R_IN1 = 0; R_IN2 = 0; }
}

/* 定时器 0：每 100us 中断一次，累计 100 次 = 10ms，即 100Hz 软件 PWM */
void timer0_isr(void) interrupt 1
{
    TH0 = (65536 - 100) / 256;          /* 12MHz 晶振：1 机器周期 = 1us */
    TL0 = (65536 - 100) % 256;
    if (++pwm_cnt >= 100) pwm_cnt = 0;
    ENA = (pwm_cnt < duty_L) ? 1 : 0;   /* 占空比越大，平均电压越高 */
    ENB = (pwm_cnt < duty_R) ? 1 : 0;
}

/* 循迹判断：10ms 调用一次。避障同理——测距小于 20cm 时两轮一起停 */
void run_control(void)
{
    if (TRACK_L == 0 && TRACK_R == 1)      { duty_L = 20; duty_R = 75; }  /* 线偏左：左慢右快 */
    else if (TRACK_L == 1 && TRACK_R == 0) { duty_L = 75; duty_R = 20; }  /* 线偏右：左快右慢 */
    else if (TRACK_L == 0 && TRACK_R == 0) { duty_L = 55; duty_R = 55; }  /* 压线：直行 */
    else { motor_left(2); motor_right(2); }                               /* 丢线：停车 */
}

说明：51 单片机没有硬件 PWM 外设，只能靠定时器中断在软件里翻转使能脚；中断里的代码越短越好，所以方向判断放在主循环 run_control() 里做。定时器初始化（TMOD、EA、ET0、TR0）见 51 单片机教程定时器一节。

可扩展方向

想让老师眼前一亮，可以从这三个方向加功能
  • 接上 HC-05 蓝牙模块，把指令约定成"前进 / 后退 / 左转 / 右转 / 停"五个字符，手机蓝牙串口助手直接控车，报告中就能写一段"双模控制"。
  • 换成带霍尔编码器的电机做测速闭环，把固定的占空比换成 PID 输出，电池电压下降时车速仍然稳定，附上一张"设定速度 vs 实际速度"的曲线图。
  • 加一路 OpenMV 或 K210 摄像头做视觉巡线，把红外循迹升级成"识别路标 + 岔路决策"，从课设难度直接拉到毕设难度。

常见问题

电机一转，单片机就复位或程序跑飞

电机启动瞬间电流能冲到 2A 以上，和单片机共用一路电源会把 5V 直接拉垮。解决：电机用 12V 锂电池直供 L298N，单片机单独走一路 5V（LM2596 或独立电池），两路 GND 必须共地；L298N 板载 5V 输出不要再同时给单片机和自身逻辑供电。另外在电机两端各并一个 0.1uF 瓷片电容，能明显减少换向火花带来的干扰。

小车只会原地打转，或者一个轮子完全不转

先看 L298N 的 ENA/ENB 跳线帽有没有拔掉——不拔就用不了 PWM，电机只能全速运转，程序里怎么调占空比都没反应。再用万用表量 IN1/IN2：前进时应该是一高一低，两个都是低电平说明方向函数没被调用到。如果两个轮子转向相反，把其中一个电机的两根接线对调即可，不用改代码。

案例 2：51 温湿度采集系统

课程设计 / 实训周

定位：入门首选。单总线时序 + 液晶显示 + 按键设置，知识点刚好覆盖 51 教学大纲的主要章节，元件便宜、焊接量小，一周就能做出可演示的成品。

功能说明

  • 上电后每 2s 读一次 DHT11，一次读满 40 位数据并做校验和比对，校验失败自动整帧丢弃重读，最多重试 3 次
  • LCD1602 第一行显示湿度（%RH），第二行显示温度（℃），数值右对齐，位数变化时不跳位
  • 两个按键分别设置温度上限（默认 30℃）与湿度上限（默认 70%RH），设置值写入 AT24C02，断电不丢
  • 任一数值超过上限时蜂鸣器间隔 1s 报警，同时该数值在屏幕上闪烁显示
  • 串口以 9600bps 每 5s 上报一行 T=25C H=60% 格式的数据，可用串口助手直接画曲线
  • 传感器连续 3 次无响应时屏幕显示 Sensor Error，而不是显示 0，避免被误判成真实读数

硬件清单

核心代码片段

#include <reg52.h>
#include <intrins.h>              /* _nop_() 空指令，用来凑出微秒级延时 */

sbit DHT = P2^0;                  /* DATA 脚必须外接 4.7k~10k 上拉电阻 */

/* DHT11 走单总线，全靠时序吃饭：这里用空指令凑出约 30us */
void delay_30us(void)
{
    unsigned char i = 6;
    while (i--) { _nop_(); _nop_(); _nop_(); _nop_(); }
}

/* 读 1 个字节：高电平持续 26~28us 表示 0，70us 表示 1 */
unsigned char dht_read_byte(void)
{
    unsigned char i, dat = 0;
    for (i = 0; i < 8; i++) {
        while (DHT == 0);              /* 等这一位的 50us 低电平结束 */
        delay_30us();                  /* 延到数据位中间再采样，最稳 */
        dat <<= 1;
        if (DHT == 1) dat |= 0x01;     /* 仍是高电平，说明这一位是 1 */
        while (DHT == 1);              /* 等这一位走完，准备读下一位 */
    }
    return dat;
}

/* 完整读一帧 40 位：返回 0 成功，1 无响应，2 校验和错 */
unsigned char dht11_read(void)
{
    unsigned char buf[5], i;
    DHT = 0;  delay_ms(20);        /* 主机拉低至少 18ms 作为起始信号 */
    DHT = 1;  delay_30us();        /* 拉高 20~40us 后释放总线，等从机应答 */
    if (DHT != 0) return 1;        /* 从机没拉低：先查接线与上拉电阻 */
    while (DHT == 0);              /* 从机 80us 低电平应答 */
    while (DHT == 1);              /* 从机 80us 高电平，准备输出数据 */
    for (i = 0; i < 5; i++) buf[i] = dht_read_byte();
    if ((unsigned char)(buf[0] + buf[1] + buf[2] + buf[3]) != buf[4])
        return 2;                  /* 前 4 字节之和应等于第 5 字节 */
    humi = buf[0];  temp = buf[2]; /* buf[1]/buf[3] 是小数位，DHT11 恒为 0 */
    return 0;
}

/* 显示到 LCD1602：第一行湿度，第二行温度 */
void show_data(void)
{
    LCD_ShowString(0, 0, "Humidity: ");
    LCD_ShowNum(10, 0, humi, 2);   /* 整数两位，前导 0 由库函数补齐 */
    LCD_ShowString(0, 1, "Temp:     ");
    LCD_ShowNum(6, 1, temp, 2);
}

说明：delay_ms() 与 LCD_ShowString() / LCD_ShowNum() 属于通用驱动，完整实现见 51 单片机教程的延时与 LCD1602 章节。DHT11 的时序对延时精度敏感，若你的晶振不是 12MHz，需要按比例重算 delay_30us() 里的循环次数。

可扩展方向

从"能显示"升级到"能写进报告"的三个思路
  • 加 DS1302 时钟芯片，配合已有的 AT24C02 做成"带时间戳的温湿度记录仪"，每 10 分钟存一条，串口可导出一天的数据做趋势分析。
  • 把 DHT11 换成 DHT22（AM2302）：精度从 ±2℃ 提升到 ±0.5℃，小数位真正有效，报告里就能写一节"两种传感器实测对比"。
  • 加 ESP-01S 模块走 AT 指令，把数据上传到巴法云或 OneNet，手机随时查看历史曲线，题目直接从课设升级成"物联网环境监测"。

常见问题

LCD1602 背光亮着，但一个字都不显示（或只有一排黑方块）

九成是对比度没调：找到第 3 脚 VO，把它接的 10k 电位器慢慢拧，拧到字出现为止，别一上来就怀疑程序。其次检查 RW 脚有没有接地（只写模式最省事），以及初始化里的 0x38（8 位两行）、0x0C（开显示关光标）、0x06（写一个字符地址加一）这三条指令有没有写全——写指令之间必须留够延时，太快会初始化失败。

DHT11 一直校验错，或者读出来是 85 / 0 这种异常值

85℃ 是 DHT11 上电后的默认值，读到它说明你读得太早或根本没读通：上电后至少等 1s 再读第一帧，两次读取间隔也不能小于 1s，否则传感器内部还没完成转换。其次 DATA 脚没有 4.7k~10k 上拉电阻时，导线稍长高电平就拉不起来，直接表现就是一直返回 1（无响应）。如果买的是一体化模块，先确认它是三针还是四针——四针模块多出来的那个脚要悬空，别接到 VCC 上。

案例 3：STM32 OLED 数字电压表

实训周 / 毕业设计

定位：从 51 迈向 STM32 的过渡题。核心是 ADC 采集 + 数据滤波 + OLED 显示这条完整数据链，硬件最少（一块核心板 + 一块屏），调试重点全在软件上，很适合两周实训周。

功能说明

  • PA0 单通道采集 0~3.3V 直流电压，12 位分辨率，理论最小分辨 0.8mV
  • 每次显示前连续采样 16 次取平均，抑制电源纹波造成的末位跳动
  • OLED 第二行显示 U=x.xxxV，用整数运算拆出整数位与三位小数，不依赖浮点 printf
  • 第一行显示标题，第四行显示原始 ADC 值，方便对比换算结果是否正确
  • 每 200ms 刷新一次，兼顾读数稳定与响应速度，画面不闪
  • 外接分压电路可把量程扩展到 0~10V，只需改一个宏即可切换量程与显示说明

核心代码片段

#include "stm32f1xx_hal.h"
#include "oled.h"

extern ADC_HandleTypeDef hadc1;   /* CubeMX 生成的 ADC1 句柄，通道 IN0 = PA0 */
/* 测 0~3.3V 可以直连；超过 3.3V 必须先分压，绝不能直接接 ADC 引脚 */

#define SAMPLE_TIMES 16           /* 采样次数，取平均是最基础的软件滤波 */

/* 读一次 ADC 并换算成电压：VREF = 3.3V，12 位分辨率对应 0~4095 */
float adc_get_voltage(void)
{
    uint32_t sum = 0;
    for (uint8_t i = 0; i < SAMPLE_TIMES; i++) {
        HAL_ADC_Start(&hadc1);                       /* 启动一次规则转换 */
        if (HAL_ADC_PollForConversion(&hadc1, 10) == HAL_OK) {
            sum += HAL_ADC_GetValue(&hadc1);         /* 累加，最后统一除 */
        }
        HAL_ADC_Stop(&hadc1);
    }
    return (float)(sum / SAMPLE_TIMES) * 3.3f / 4095.0f;
}

int main(void)
{
    HAL_Init();
    SystemClock_Config();        /* 72MHz；ADC 时钟不得超过 14MHz，分频要算对 */
    MX_GPIO_Init();
    MX_ADC1_Init();
    OLED_Init();
    OLED_Clear();

    while (1) {
        float v = adc_get_voltage();
        uint16_t mv = (uint16_t)(v * 1000.0f + 0.5f);   /* 转毫伏并四舍五入 */

        OLED_ShowString(0, 0, "Voltage Meter", 12);
        OLED_ShowString(0, 2, "U=", 16);
        OLED_ShowNum(24, 2, mv / 1000, 1, 16);          /* 整数位，1 位 */
        OLED_ShowString(36, 2, ".", 16);
        OLED_ShowNum(44, 2, mv % 1000, 3, 16);          /* 三位小数，前导 0 补齐 */
        OLED_ShowString(80, 2, "V", 16);
        OLED_ShowString(0, 4, "raw:", 12);
        OLED_ShowNum(36, 4, (uint16_t)(v * 4095.0f / 3.3f), 4, 12);   /* 反算 ADC 原始值 */

        HAL_Delay(200);                                 /* 200ms 刷一次，避免闪屏 */
    }
}

说明：OLED_ShowString() / OLED_ShowNum() 是常见的 SSD1306 驱动接口（如江科大 0.96 寸 OLED 库），参数依次为 x、y 页、内容、字号。把电压拆成整数位和小数位显示，是为了避开 STM32 上浮点 printf 的庞大开销与精度陷阱。

可扩展方向

这个题目的上限其实很高
  • 做量程自动切换：用两个 GPIO 驱动模拟开关或继电器切换分压比，0~3.3V 与 0~30V 自动换挡，报告里就能写"自动量程电压表"。
  • 换用 ADS1115 外置 16 位 ADC（I2C 接口，内置 PGA），分辨率提升到 0.1mV 级别，可以测热电偶、称重传感器这类小信号。
  • 把平均滤波升级成中位值平均滤波（去掉一个最大值和一个最小值再平均）或一阶低通滤波，抗脉冲干扰能力更强，附上三种滤波的对比数据。

常见问题

读数一直跳，末位差几十个字

STM32 的 ADC 参考电压就是 VDDA，如果整块板子直接吃 USB 的 5V 再经 LDO 转 3.3V，LDO 的输出纹波会原封不动地反映到读数上。处理办法：在分压输出端并 0.1uF 瓷片 + 10uF 电解电容，被测信号与单片机必须共地，测量线尽量短，并且绝对不要和电机、继电器、LED 灯带共用一路电源。软件上把采样次数从 16 提到 64 也能立竿见影。

电压一超过 3.3V 读数就顶死在 4095（甚至烧引脚）

ADC 输入绝对不能超过 VDDA + 0.3V，超了轻则读数饱和、重则永久损坏引脚。测 9V 电池、12V 电源时必须先分压，比如 20k 上 + 10k 下，正好把 0~10V 压到 0~3.3V，程序中再乘以 3 还原。注意分压电阻本身就是负载，会拉低高内阻信号源（比如某些传感器输出），这种场合要先加一级电压跟随器再送进 ADC。

综合

案例 4：ESP32 手机 WiFi 远程控制 LED

毕业设计 / 创新实训

定位：物联网方向的入门综合题。把"硬件 + 网络 + 前端"三块串成一条完整链路，代码量不大但涉及面广，最适合做毕业设计的第一版原型，再往上加功能就是完整的智能家居。

功能说明

  • 上电自动以 STA 模式连接 2.4GHz 路由器，串口打印分配到的 IP 地址
  • 内置 WebServer 返回一个含"开灯 / 关灯"两个按钮的网页，不需要额外部署任何服务器
  • 路由 /led?state=on 与 /led?state=off 分别把 GPIO2 置高、置低，实测响应在 100ms 以内
  • 手机、平板、电脑连同一个路由器，浏览器输入 IP 即可控制，无需安装 APP
  • 参数缺失返回 400、未知路径返回 404，调试时能一眼区分是网络问题还是代码问题
  • 串口以 115200bps 输出连接过程与访问地址，连不上时能看出卡在哪一步

核心代码片段

#include <WiFi.h>
#include <WebServer.h>
const char *SSID     = "你的路由器名称";
const char *PASSWORD = "你的WiFi密码";

#define LED_PIN 2                    /* ESP32 开发板板载 LED 就是 GPIO2 */

WebServer server(80);                /* HTTP 服务监听 80 端口 */

/* 首页 HTML 直接写在程序里，手机浏览器访问模块 IP 就能看到按钮 */
const char INDEX_HTML[] PROGMEM = R"rawliteral(
<!DOCTYPE html><html><head><meta charset="utf-8"><title>ESP32 LED</title></head><body>
<h2>ESP32 远程控制</h2>
<p><a href="/led?state=on"><button>开灯</button></a>
<a href="/led?state=off"><button>关灯</button></a></p>
</body></html>)rawliteral";

void handleRoot(void) { server.send(200, "text/html; charset=utf-8", INDEX_HTML); }

/* 路由：/led?state=on 点亮，/led?state=off 熄灭 */
void handleLed(void) {
    if (!server.hasArg("state")) { server.send(400, "text/plain", "missing state"); return; }
    String s = server.arg("state");
    if (s == "on")       { digitalWrite(LED_PIN, HIGH); server.send(200, "text/plain", "LED ON"); }
    else if (s == "off") { digitalWrite(LED_PIN, LOW);  server.send(200, "text/plain", "LED OFF"); }
    else                 { server.send(400, "text/plain", "bad state"); }
}

void setup(void) {
    Serial.begin(115200);
    pinMode(LED_PIN, OUTPUT);
    digitalWrite(LED_PIN, LOW);
    WiFi.mode(WIFI_STA);                     /* STA 模式：像手机一样连路由器 */
    WiFi.begin(SSID, PASSWORD);
    while (WiFi.status() != WL_CONNECTED) {  /* 连不上就死等，串口打点方便排查 */
        delay(500);
        Serial.print(".");
    }
    Serial.print("访问地址: http://");
    Serial.println(WiFi.localIP());          /* 手机浏览器直接输入这个 IP */
    server.on("/", handleRoot);
    server.on("/led", handleLed);
    server.onNotFound([]() { server.send(404, "text/plain", "404 Not Found"); });
    server.begin();
}

void loop(void) {
    server.handleClient();                   /* 必须放在 loop 里，否则不响应请求 */
}

说明：这段代码在 Arduino IDE 里直接编译即可（开发板选 ESP32 Dev Module）。WebServer.h 是 ESP32 Arduino 核心自带的库，不需要额外安装；如果你用的是老的 ESP8266 例程，头文件名叫 ESP8266WebServer.h，不能混用。

可扩展方向

从"能控制"做到"像个产品"
  • 把按钮页面改成无刷新版本：用 fetch 请求 /led?state=on，再加一个 /state 接口做状态回显，页面刷新后显示的仍是真实状态，报告里可以写"前后端分离"。
  • 接入 MQTT（PubSubClient）连到巴法云或 Home Assistant，人在外面也能控制，还能顺带接入小爱同学、天猫精灵做语音控制。
  • 加一个 5V 继电器模块控制 220V 台灯，再配上电流检测或 ESP32-CAM 看实时画面，题目就从"控制一个 LED"升级成"智能插座 / 远程监控终端"。

常见问题

串口一直打印点，怎么都连不上 WiFi

先确认频段：ESP32 只支持 2.4GHz，连的是 5G 热点或路由器开了双频合一都会失败，建议把 2.4G 的 SSID 单独拆出来。其次是供电——WiFi 发射瞬间电流能冲到 500mA，USB 线材太差或电脑 USB 口带不动时模块会不断重启（串口能看到 rst 原因打印），在 3.3V 与 GND 之间并一个 470uF 电解电容通常就能解决。最后检查 SSID/密码里有没有中文或特殊字符，字符串里的双引号要转义。

网页能打开，但点按钮没反应，或者返回 404

先看路由注册是否写成 server.on("/led", handleLed)，路径必须和 HTML 里 href 的 /led?state=on 完全对得上，差一个字符就是 404。如果页面正常但 LED 不动，用串口打印一下 server.arg("state") 的实际取值，多半是参数名拼错。另外注意不同开发板板载 LED 的极性不一样，有的板子低电平才点亮，接外接 LED 时以实测为准。

Report & Defense

答辩 / 报告加分项

同样的工作量，写不写这几样东西，最后拿到的分数差得很远。

老师最想看到的四件事
  • 画出系统框图与流程图 —— 框图说清"输入 → 处理 → 输出"三段（传感器怎么接、主控做什么、执行器怎么动），流程图要覆盖主循环和中断两条线。评委不看代码也能一眼判断这个系统是不是你自己搭起来的。
  • 记录实测数据并做误差分析 —— 别只写"测量准确"。列出 5~10 组"标准值 vs 实测值"，算出绝对误差和相对误差，再解释误差从哪来：ADC 参考电压漂移、传感器自身 ±2℃ 精度、分压电阻的 1% 公差，都是能写进报告的实打实内容。
  • 写出你踩过的坑和解决办法 —— 比如"LCD 不显示，最后发现是对比度电位器没调"、"电机一转单片机就复位，最后发现是电源没分开"。这一节最能体现动手能力，也是答辩时老师最爱追问的地方，提前写好就不会被问住。
  • 说明成本清单 —— 按元件列一张表：单价 × 数量 = 小计，最后给出整机成本。这一项在"工程实践性"评分里往往单独占分，也方便下一届同学照着买。
