原理介绍

I2C（读作“I 方 C”，Inter-Integrated Circuit）是飞利浦发明的一种 两线制同步串行总线： 一根 SCL 负责时钟，一根 SDA 负责数据。 主机（我们的 STM32）产生时钟并决定跟谁说话，从机（OLED 模块）只能被动应答。 一条总线上可以挂很多个从机，靠地址区分—— 这就是为什么只用两根线就能同时接 OLED、EEPROM、温湿度传感器。

但 I2C 也是最容易“接上了却不工作”的总线，因为它有两个反直觉的设计： 引脚是开漏的，必须外加上拉电阻； 以及从机不响应时主机只会静静地等， 什么错误都不报。把这两点搞明白，I2C 的调试难度会下降一大半。

开漏输出与上拉电阻

先说一个很多人没想清楚的问题： 为什么 I2C 的两根线必须接上拉电阻，不接就没有高电平？

因为 I2C 的引脚是开漏（Open-Drain）结构。 普通推挽输出内部有上下两个 MOS 管，可以主动把引脚“推”到高电平，也可以“拉”到低电平。 而开漏输出只有下面那个管子：

  • 输出 0 时，下面的管子导通，把线牢牢拉到 GND，这是主动拉低。
  • 输出 1 时，下面的管子截止，引脚进入高阻态——相当于这根线被“松开”了，它自己产生不了高电平。

线被松开以后，是谁把它恢复到高电平的？答案就是上拉电阻。 电阻一端接 3.3V、一端接 SDA，当所有设备都松开时，电流经电阻把线充到 3.3V。 所以没有上拉电阻，总线永远停在低电平，通信根本不可能开始。 典型取值是 4.7kΩ（100kHz 总线）到 2.2kΩ（400kHz 总线）。

开漏结构为什么值得专门设计

正因为谁都不能主动输出高电平，所以 两个设备同时驱动总线也不会短路： 只要有一个拉低，线就是低；全都松开了，线才变高。 这正好实现了 I2C 需要的两个机制—— 线与（wired-AND），以及 时钟拉伸（从机来不及处理时可以把 SCL 拉低，让主机等它）。 代价就是必须外加上拉电阻。

模块自带的上拉电阻：好事也可能变成坑

市面上大多数 0.96 寸 OLED 模块板上已经焊了 4.7kΩ 上拉电阻。 这时候你不需要再加。如果你没检查就又并了一对 4.7kΩ， 等效上拉变成 2.35kΩ，100kHz 下通常还能工作，但总线电流翻倍， 有些模块会因此变得不稳定。 判断方法很简单：断电后用万用表量 SCL 对 VCC 的电阻， 读数在 5kΩ 左右说明板载已有上拉，读数是无穷大就必须自己加。

起始/停止条件与从机地址

I2C 的“通信开始”和“通信结束”不是靠额外的信号线，而是靠 两根线在特定时刻的相对变化来定义的。 关键规则是：SCL 为高电平时，SDA 必须保持稳定， 因为这段时间是从机读取数据的窗口。所以“在 SCL 高电平期间改变 SDA”就成了特殊命令： 

起始条件（Start）：SCL 为高时，SDA 由高变低
        ┌───────────┐
   SCL ─┘           └────────
        ┌──────┐
   SDA ─┘      └─────────────
              ↑ 这个下降沿就是 Start

停止条件（Stop）：SCL 为高时，SDA 由低变高
        ┌───────────┐
   SCL ─┘           └────────
             ┌──────┐
   SDA ──────┘      └────────
                    ↑ 这个上升沿就是 Stop

数据位：SCL 低电平时准备数据，SCL 高电平时数据必须稳定
        ┌───┐   ┌───┐   ┌───┐
   SCL ─┘   └───┘   └───┘   └──
        ┌───────┐───────┐───────
   SDA ─┘  bit  └  bit  └  bit
         ↑高电平期间保持不变，从机在这时候采样

一次完整的“写一字节”时序是这样的：Start → 7 位从机地址 → 第 8 位读写位（0 = 写，1 = 读） → 从机拉低 SDA 回应“ACK” → 数据字节 → ACK → …… → Stop。 注意第 9 个时钟不是数据，而是从机用来回应“我收到了”的应答位。 

Start | 0x3C (7位地址) | 0(写) | ACK | 0x00(控制字节:命令) | ACK | 0xAE(命令) | ACK | Stop

  把 7 位地址 0x3C 左移一位、低位补上读写位 0：
      0x3C << 1 | 0  =  0x78      ← 这就是代码里写的 OLED_I2C_ADDR
  如果是读操作：
      0x3C << 1 | 1  =  0x79

★ 所以“地址 0x3C”和“地址 0x78”说的是同一块屏，
  区别只是 0x3C 是数据手册里的 7 位形式，0x78 是实际出现在总线上的 8 位形式。
  看别人代码时不要被这两个数搞混。
模块背面 SA0 的接法 7 位地址 写地址（8 位） 说明
SA0 接 GND（默认）0x3C0x78绝大多数模块是这个，代码里先试它
SA0 接 VCC0x3D0x7A少数模块或同总线挂两块屏时用

还有一个必须记住的细节： SSD1306 在 I2C 上传输的每个字节前面都要多一个“控制字节”。 它是 0x00 时表示后面跟的是命令，是 0x40 时表示后面跟的是显存数据。 这就是为什么裸写 I2C 时序驱动 OLED 比驱动 EEPROM 麻烦一点—— 每字节都要多带一个“这是命令还是数据”的标签。

SSD1306 的页结构

屏幕是 128×64 个像素，但显存不是按“行”组织的，而是 按“页（Page）”组织的 8 位竖条。 这一点不搞清楚，你会发现自己想点亮第 3 行第 5 列的像素，却点亮了奇怪的位置。 

显存总大小 = 128 列 × 64 行 ÷ 8 行/字节 = 1024 字节

                列 0   列 1   列 2   ......   列 127
              ┌──────┬──────┬──────┬─────┬──────┐
   Page 0     │ 1字节│ 1字节│ 1字节│ ... │ 1字节│  ← 屏幕第  0~ 7 行
              ├──────┼──────┼──────┼─────┼──────┤
   Page 1     │ 1字节│ 1字节│ 1字节│ ... │ 1字节│  ← 屏幕第  8~15 行
              ├──────┼──────┼──────┼─────┼──────┤
   Page 2     │      │      │      │     │      │  ← 屏幕第 16~23 行
              ├──────┼──────┼──────┼─────┼──────┤
   Page 3     │      │      │      │     │      │  ← 屏幕第 24~31 行
              ├──────┼──────┼──────┼─────┼──────┤
   Page 4     │      │      │      │     │      │  ← 屏幕第 32~39 行
              ├──────┼──────┼──────┼─────┼──────┤
   Page 5     │      │      │      │     │      │  ← 屏幕第 40~47 行
              ├──────┼──────┼──────┼─────┼──────┤
   Page 6     │      │      │      │     │      │  ← 屏幕第 48~55 行
              ├──────┼──────┼──────┼─────┼──────┤
   Page 7     │      │      │      │     │      │  ← 屏幕第 56~63 行
              └──────┴──────┴──────┴─────┴──────┘

  一个字节的 8 个位，对应屏幕上竖着的 8 个像素：
        bit7  → 该页的最下面一行
        bit0  → 该页的最上面一行     （bit0 在最上，别记反了）

  所以“在 (x=0, y=0) 画一个点”= 把第 0 页第 0 列那个字节的 bit0 置 1

★ 0.91 寸的屏只有 64×32 个像素，只用到 Page 0~3，共 4 页。
  买了 0.91 寸的屏却套用 0.96 寸的初始化序列，就会只点亮上半屏 ——
  因为 0xA8 那条“多路复用比”命令还写着 0x3F（64 行），应该改成 0x1F（32 行）。

为什么 SSD1306 要用这种奇怪的竖条布局？因为它原本是给 按列扫描的驱动电路设计的： OLED 屏的每一列由一根源极驱动线控制，一次刷新就是一列一列地送。 用“页 + 列”的地址方式，正好能让列地址自动加 1 连续送数， 不需要每次重设坐标——这也是为什么我们的 OLED_WriteDataBuf 能一口气写 128 字节。

写显存不会闪屏，清屏再重画才会闪

SSD1306 内部有 1KB 的独立显存，屏幕的显示内容是芯片自己扫出来的。 你写显存的过程屏幕根本看不见，所以 “改一个数字”是不会闪的。 会闪是因为很多教程先调 OLED_Clear() 把整屏擦掉， 再从头画一遍——那一瞬间的空白就是你看到的闪烁。 正确做法是用固定宽度右对齐覆盖旧字符， 或者用 RAM 中的双缓冲一次性刷 1024 字节。具体做法见 数字电压表那一篇。

硬件 I2C 为什么容易卡死

按理说 STM32F103 片内有硬件 I2C 外设，用它应该比软件翻转 GPIO 更省事。 但实际做项目的人往往会告诉你：能不用硬件 I2C 就不用。 这不是偏见，有三个具体原因：

  1. 著名的总线死锁问题。 如果通信进行到一半时 MCU 复位了（比如你按了复位键重新下载程序）， 而从机正好处在“正在拉低 SDA 发送 ACK”的状态， 这时总线是被从机占住的。MCU 复位后 I2C 外设看到 SDA 是低电平， 判定“总线忙”，于是 BUSY 标志位一直不清零， 所有后续传输全部失败——而且复位都救不回来，必须断电。
  2. HAL 库的阻塞式 API 会无限等待。 HAL_I2C_Master_Transmit(&hi2c1, addr, buf, len, HAL_MAX_DELAY) 里的最后一个参数如果传 HAL_MAX_DELAY， 从机不响应时这个函数永远不会返回， 程序看起来就是“卡死在某一行”。
  3. 出错信息少，难定位。 硬件 I2C 出错只给你一个 HAL_ERROR 或 HAL_BUSY， 到底是没有 ACK、还是总线被占、还是时序错乱，你只能靠猜。 而软件模拟 I2C 的每一拍都是你自己写的， 拿示波器一量就知道卡在哪一位。

所以本页的做法是：用两个普通 GPIO 软件模拟 I2C。 好处是时序完全可控、引脚想换就换、调试时能一行一行跟； 代价是最高速率大约只有 100~300kHz，而且发送时 CPU 要全程参与。 对刷一块 1KB 显存的 OLED 来说，这个代价完全可以接受—— 实测全屏刷新约 30ms，人眼根本看不出。

什么时候还是得用硬件 I2C

需要高速（400kHz 以上）连续读取大量数据时，比如从 MPU6050 读六轴数据、 从 EEPROM 搬大块固件，软件模拟就会明显拖慢主循环。 这时候再用硬件 I2C，并且务必做到三件事： 所有调用都传有限的超时时间、 在错误回调里做外设软复位 （__HAL_I2C_DISABLE 后重新 HAL_I2C_Init）、 开机时先发 9 个时钟脉冲解锁可能被占住的总线。

上电前必查
  • VCC 和 GND 千万别接反。 OLED 模块没有反接保护，接反一次基本就报废了，而且烧掉的时候没有明显征兆。
  • 上拉电阻接到 3.3V，不要接到 5V。 虽然 F103 的 PB6/PB7 是 5V 容忍引脚（数据手册里标 FT），接 5V 不会立刻烧，但整个总线的电平判据都被抬高，还可能与 3.3V 供电的 OLED 产生灌电流。
  • 确认是 0.96 寸（64 行）还是 0.91 寸（32 行）。 买错屏最常见的现象就是“只有上半屏有字”，需要改初始化序列里的 0xA8 参数。
  • 杜邦线插紧。I2C 断一根线的现象是屏幕全黑，和“没供电”长得一模一样，很难分辨。

完整代码

驱动分成三个文件：oled.h 声明接口和引脚、 oled.c 实现软件 I2C 与 SSD1306 的全部操作、 main.c 把 ADC 采到的电压显示出来。 这三个文件加进工程就能编译，不需要额外安装任何库。

 * ===================================================================== */
#ifndef __OLED_H
#define __OLED_H

#include "main.h"       /* 提供 GPIO_TypeDef、GPIO_PIN_x、uint8_t 等定义 */

/* ---------------------------------------------------------------------
 * 软件 I2C 的引脚定义
 * 想换引脚只需要改这四行，不用动 oled.c —— 这是软件模拟 I2C 最大的好处。
 * 前提：CubeMX 里要把这两个脚配成 GPIO_Output + Output Open Drain
 * ------------------------------------------------------------------- */
#define OLED_SCL_PORT       GPIOB
#define OLED_SCL_PIN        GPIO_PIN_6
#define OLED_SDA_PORT       GPIOB
#define OLED_SDA_PIN        GPIO_PIN_7

/* ---------------------------------------------------------------------
 * SSD1306 的从机地址
 * 数据手册里的 7 位地址是 0x3C，左移一位补上读写位 0 之后是 0x78，
 * 这个 0x78 才是真正出现在总线上的字节。
 * 如果屏幕点不亮，第二个要试的就是 0x7A（对应 7 位地址 0x3D）。
 * ------------------------------------------------------------------- */
#define OLED_I2C_ADDR       0x78

/* ---------------------------------------------------------------------
 * 屏幕尺寸。0.96 寸是 128x64（8 页）；
 * 0.91 寸是 128x32（4 页），把 OLED_PAGES 改成 4，
 * 并把 oled.c 初始化序列里 0xA8 后面的参数从 0x3F 改成 0x1F。
 * ------------------------------------------------------------------- */
#define OLED_WIDTH          128
#define OLED_PAGES          8

/* ---- 对外接口 ------------------------------------------------------ */
void OLED_Init(void);                                            /* 上电初始化 */
void OLED_Clear(void);                                           /* 清空整屏显存 */
void OLED_ShowChar(uint8_t x, uint8_t y, char ch);               /* 显示一个 6x8 字符 */
void OLED_ShowString(uint8_t x, uint8_t y, const char *str);     /* 显示字符串 */
void OLED_ShowNum(uint8_t x, uint8_t y, uint32_t num, uint8_t len);  /* 高位补空格 */
void OLED_ShowNumZ(uint8_t x, uint8_t y, uint32_t num, uint8_t len); /* 高位补 0 */
void OLED_ShowCN(uint8_t x, uint8_t y, const uint8_t *hz);       /* 显示 16x16 汉字 */
uint8_t OLED_TestConnection(void);                               /* 探测从机是否应答 */

/* =====================================================================
 * oled.c —— SSD1306 OLED 驱动（软件模拟 I2C）
 * ---------------------------------------------------------------------
 * 目录：
 *   1. 软件 I2C 的底层时序（Start / Stop / 写字节 / 等应答）
 *   2. SSD1306 的命令与数据写入
 *   3. 初始化序列
 *   4. 6x8 ASCII 字库与字符、字符串、数字显示
 *   5. 16x16 汉字显示
 * ===================================================================== */
#include "oled.h"

/* =====================================================================
 * 1. 软件 I2C 底层时序
 * ===================================================================== */

/* 位延时。I2C 协议只规定最大频率（标准模式 100kHz、快速模式 400kHz），
 * 没有规定最小频率，所以时钟慢一点永远安全。
 * 这个循环在 72MHz 下产生约 2µs 的高/低电平，对应约 250kHz，
 * 在 SSD1306 支持的范围内。如果杜邦线很长导致通信不稳，把 20 改大即可。 */
static void I2C_Delay(void)
{
    for (volatile uint8_t i = 0; i < 20U; i++)
    {
        __NOP();        /* 空操作，占一个时钟周期，防止被编译器优化掉 */
    }
}

/* 把 SCL / SDA 拉高或拉低。
 * 因为引脚配成了开漏输出，"写 1" 实际是松开总线让上拉电阻把它拉高。 */
#define SCL_H()   HAL_GPIO_WritePin(OLED_SCL_PORT, OLED_SCL_PIN, GPIO_PIN_SET)
#define SCL_L()   HAL_GPIO_WritePin(OLED_SCL_PORT, OLED_SCL_PIN, GPIO_PIN_RESET)
#define SDA_H()   HAL_GPIO_WritePin(OLED_SDA_PORT, OLED_SDA_PIN, GPIO_PIN_SET)
#define SDA_L()   HAL_GPIO_WritePin(OLED_SDA_PORT, OLED_SDA_PIN, GPIO_PIN_RESET)

/* 读 SDA 的电平。
 * 技巧：STM32 的输入数据寄存器 IDR 一直在采样引脚电平，
 * 不管引脚被配成输入还是输出。所以开漏输出模式下可以直接读回总线状态，
 * 不需要来回切换引脚方向 —— 这正是判断 ACK 需要的。 */
#define SDA_READ()   HAL_GPIO_ReadPin(OLED_SDA_PORT, OLED_SDA_PIN)

/* ---------------------------------------------------------------------
 * 起始条件：SCL 为高时，SDA 由高变低
 * ------------------------------------------------------------------- */
static void I2C_Start(void)
{
    SDA_H();            /* 先确保两条线都是空闲的高电平 */
    SCL_H();
    I2C_Delay();

    SDA_L();            /* SCL 保持高，SDA 拉低 → 这就是 Start */
    I2C_Delay();

    SCL_L();            /* 拉低 SCL，准备发送数据位 */
    I2C_Delay();
}

/* ---------------------------------------------------------------------
 * 停止条件：SCL 为高时，SDA 由低变高
 * ------------------------------------------------------------------- */
static void I2C_Stop(void)
{
    SDA_L();            /* 先保证 SDA 是低 */
    I2C_Delay();

    SCL_H();            /* 先把 SCL 抬起来 */
    I2C_Delay();

    SDA_H();            /* SCL 为高时 SDA 上升 → 这就是 Stop */
    I2C_Delay();
}

/* ---------------------------------------------------------------------
 * 发送一个字节（高位在前）
 * ------------------------------------------------------------------- */
static void I2C_WriteByte(uint8_t byte)
{
    uint8_t i;

    for (i = 0; i < 8U; i++)
    {
        SCL_L();                        /* SCL 拉低期间准备数据，数据才允许变化 */
        I2C_Delay();

        if ((byte & 0x80U) != 0U)       /* 每次取最高位 */
        {
            SDA_H();
        }
        else
        {
            SDA_L();
        }
        byte = (uint8_t)(byte << 1);    /* 左移，把下一位顶到最高位 */
        I2C_Delay();

        SCL_H();                        /* SCL 拉高，从机在这一刻采样 SDA */
        I2C_Delay();
    }

    SCL_L();                            /* 8 位发完，拉低 SCL 准备应答位 */
    I2C_Delay();
}

/* ---------------------------------------------------------------------
 * 读取从机的应答位
 * 返回：0 = 收到 ACK（从机在线），1 = 没有应答（从机不在或地址错）
 * ------------------------------------------------------------------- */
static uint8_t I2C_WaitAck(void)
{
    uint8_t ack;

    SDA_H();            /* 主机松开 SDA，把发言权交给从机 */
    I2C_Delay();

    SCL_H();            /* 第 9 个时钟，从机如果在线就会把 SDA 拉低 */
    I2C_Delay();

    ack = (SDA_READ() == GPIO_PIN_RESET) ? 0U : 1U;   /* 低电平就是 ACK */

    SCL_L();
    I2C_Delay();

    return ack;
}

/* =====================================================================
 * 2. SSD1306 的命令与数据写入
 * ===================================================================== */

/* ---------------------------------------------------------------------
 * 写一条命令。
 * I2C 帧结构：[Start][0x78][ACK][0x00][ACK][命令][ACK][Stop]
 * 其中 0x00 是控制字节，告诉 SSD1306“接下来这个字节是命令”。
 * ------------------------------------------------------------------- */
static void OLED_WriteCmd(uint8_t cmd)
{
    I2C_Start();
    I2C_WriteByte(OLED_I2C_ADDR);   /* 从机地址 + 写方向 */
    I2C_WaitAck();
    I2C_WriteByte(0x00);            /* 控制字节 0x00 = 命令 */
    I2C_WaitAck();
    I2C_WriteByte(cmd);
    I2C_WaitAck();
    I2C_Stop();
}

/* ---------------------------------------------------------------------
 * 连续写 n 个显存字节。
 * 关键优化：只在开头和结尾各一次 Start/Stop，中间的 0x40 控制字节
 * 只发一次，之后 SSD1306 的列地址会自动加 1，数据一路灌进去就行。
 * 比“每个字节都走一次完整 I2C 事务”快 4 倍以上。
 * ------------------------------------------------------------------- */
static void OLED_WriteDataBuf(const uint8_t *buf, uint16_t n)
{
    uint16_t i;

    I2C_Start();
    I2C_WriteByte(OLED_I2C_ADDR);
    I2C_WaitAck();
    I2C_WriteByte(0x40);            /* 控制字节 0x40 = 显存数据 */
    I2C_WaitAck();

    for (i = 0; i < n; i++)
    {
        I2C_WriteByte(buf[i]);
        I2C_WaitAck();
    }

    I2C_Stop();
}

/* 写一个显存字节（字符显示用） */
static void OLED_WriteData(uint8_t dat)
{
    OLED_WriteDataBuf(&dat, 1U);
}

/* ---------------------------------------------------------------------
 * 设置写入位置：x = 列（0~127），page = 页（0~7）
 * ------------------------------------------------------------------- */
static void OLED_SetCursor(uint8_t x, uint8_t page)
{
    OLED_WriteCmd((uint8_t)(0xB0U | (page & 0x07U)));          /* 页地址 */
    OLED_WriteCmd((uint8_t)(0x00U | (x & 0x0FU)));            /* 列地址低 4 位 */
    OLED_WriteCmd((uint8_t)(0x10U | ((x >> 4) & 0x0FU)));      /* 列地址高 4 位 */
}

/* =====================================================================
 * 3. 初始化序列
 * ===================================================================== */

/* 逐条对应数据手册的命令表。★ 标记的两条是最常被漏掉的。 */
static const uint8_t OLED_INIT_CMDS[] = {
    0xAE,           /* 关闭显示：配置过程中先黑屏，避免看到花屏过程 */
    0x20, 0x00,     /* 寻址模式 = 水平寻址，写满一页自动跳到下一页 */
    0xB0,           /* 页地址从 0 开始 */
    0xC8,           /* COM 扫描方向 = 从下往上（配合 0xA1 得到正立画面） */
    0x00,           /* 列地址低 4 位 = 0 */
    0x10,           /* 列地址高 4 位 = 0 */
    0x40,           /* 显示起始行 = 0 */
    0x81, 0xCF,     /* 对比度 = 0xCF（0x00~0xFF，调大到 0xFF 最亮） */
    0xA1,           /* 段重映射：左右方向，和 0xC8 一起决定画面是否正立 */
    0xA6,           /* 正常显示（改成 0xA7 就是黑底白字反相） */
    0xA8, 0x3F,     /* ★ 多路复用比 = 0x3F+1 = 64 行。
                       0.91 寸屏（32 行）必须改成 0x1F，否则只亮上半屏 */
    0xA4,           /* 输出跟随显存内容（0xA5 是强制全亮，出厂测试用） */
    0xD3, 0x00,     /* 显示垂直偏移 = 0 */
    0xD5, 0x80,     /* 时钟分频与振荡频率，0x80 是官方推荐值 */
    0xD9, 0xF1,     /* 预充电周期，0xF1 配合内部电荷泵使用 */
    0xDA, 0x12,     /* ★ COM 引脚硬件配置 = 0x12（交替模式），
                       0.96 寸标准值。写错会出现隔行亮、半屏花 */
    0xDB, 0x40,     /* VCOMH 反压电平 */
    0x8D, 0x14,     /* ★★ 电荷泵使能：0x14 = 开启，0x10 = 关闭。
                       这一条漏了屏幕会完全不亮，是头号经典坑。
                       SSD1306 靠内部电荷泵产生约 7.5V 的驱动电压，
                       不开启就没有点亮的能量 */
    0xAF            /* 打开显示 */
};

/* ---------------------------------------------------------------------
 * 初始化 OLED
 * ------------------------------------------------------------------- */
void OLED_Init(void)
{
    uint16_t i;

    /* CubeMX 里如果忘了使能 GPIOB 时钟，下面两个脚永远不会动。
     * 这里补一句，让驱动不依赖 CubeMX 的勾选，更保险。 */
    __HAL_RCC_GPIOB_CLK_ENABLE();

    /* 依次发出初始化命令表里的每一条 */
    for (i = 0; i < sizeof(OLED_INIT_CMDS); i++)
    {
        OLED_WriteCmd(OLED_INIT_CMDS[i]);
    }

    /* 清空显存，避免上电后看到随机雪花点 */
    OLED_Clear();
}

/* ---------------------------------------------------------------------
 * 探测从机是否应答，用来区分“硬件没接好”和“代码写错了”
 * 返回：0 = 收到应答，OLED 在线；非 0 = 没有任何设备应答
 * ------------------------------------------------------------------- */
uint8_t OLED_TestConnection(void)
{
    uint8_t ret;

    I2C_Start();
    I2C_WriteByte(OLED_I2C_ADDR);
    ret = I2C_WaitAck();
    I2C_Stop();

    return ret;
}

/* ---------------------------------------------------------------------
 * 清屏：8 页 × 128 列全部写 0
 * ------------------------------------------------------------------- */
void OLED_Clear(void)
{
    uint8_t page;
    /* 一整页的空白显存。写成 static const 会放进 Flash，不占用 RAM */
    static const uint8_t blank_line[OLED_WIDTH] = { 0 };

    for (page = 0; page < OLED_PAGES; page++)
    {
        OLED_SetCursor(0, page);
        OLED_WriteDataBuf(blank_line, OLED_WIDTH);
    }
}

/* 在字库里查一个字符的点阵。
 * 查不到就退化成空格，这样即使字库不全也只是显示成空白，不会乱码。 */
static const uint8_t *Font6x8_Get(char ch)
{
    uint16_t i;

    for (i = 0; i < (sizeof(FONT_6X8) / sizeof(FONT_6X8[0])); i++)
    {
        if (FONT_6X8[i].code == ch)
        {
            return FONT_6X8[i].col;
        }
    }

    return FONT_6X8[0].col;     /* 第 0 个就是空格 */
}

/* ---------------------------------------------------------------------
 * 显示一个字符。x 单位是像素列（建议用 6 的倍数），y 是页号 0~7
 * ------------------------------------------------------------------- */
void OLED_ShowChar(uint8_t x, uint8_t y, char ch)
{
    if ((x > (OLED_WIDTH - 6U)) || (y >= OLED_PAGES))
    {
        return;     /* 越界直接返回，避免把显存写到屏外造成错位 */
    }

    OLED_SetCursor(x, y);
    OLED_WriteDataBuf(Font6x8_Get(ch), 6U);
}

/* ---------------------------------------------------------------------
 * 显示字符串。自动按 6 像素一个字符往右铺，超出屏宽就换到下一页
 * ------------------------------------------------------------------- */
void OLED_ShowString(uint8_t x, uint8_t y, const char *str)
{
    while (*str != '\0')
    {
        if (x > (OLED_WIDTH - 6U))      /* 这一页写满了 */
        {
            x = 0U;
            y = (uint8_t)(y + 1U);      /* 换到下一页继续 */
            if (y >= OLED_PAGES)
            {
                return;                 /* 整屏写满，收工 */
            }
        }

        OLED_ShowChar(x, y, *str);
        x = (uint8_t)(x + 6U);
        str++;
    }
}

/* ---------------------------------------------------------------------
 * 显示数字的内部实现
 * pad = ' ' 时高位补空格（适合显示原始值，旧数字能被覆盖干净）
 * pad = '0' 时高位补 0（适合显示小数位，例如 050 表示 0.050）
 * ------------------------------------------------------------------- */
static void OLED_ShowNumEx(uint8_t x, uint8_t y, uint32_t num, uint8_t len, char pad)
{
    uint8_t  i;
    uint32_t div = 1U;

    if ((len == 0U) || (len > 10U))
    {
        return;
    }

    /* 求出最高位的权值：len = 3 时 div = 100 */
    for (i = 1U; i < len; i++)
    {
        div *= 10U;
    }

    for (i = 0U; i < len; i++)
    {
        char ch;

        if ((pad == ' ') && (num < div))
        {
            ch = ' ';       /* 高位还没轮到有效数字，用空格占位 */
        }
        else
        {
            ch = (char)('0' + ((num / div) % 10U));
        }

        OLED_ShowChar((uint8_t)(x + i * 6U), y, ch);
        div /= 10U;
    }
}

void OLED_ShowNum(uint8_t x, uint8_t y, uint32_t num, uint8_t len)
{
    OLED_ShowNumEx(x, y, num, len, ' ');
}

void OLED_ShowNumZ(uint8_t x, uint8_t y, uint32_t num, uint8_t len)
{
    OLED_ShowNumEx(x, y, num, len, '0');
}

/* =====================================================================
 * 5. 16x16 汉字显示
 * ===================================================================== */

/* ---------------------------------------------------------------------
 * 显示一个 16x16 汉字。hz 指向 32 字节的点阵数据。
 *
 * 取模软件（PCtoLCD2002）设置：
 *   点阵大小 16x16，阴码，逐列式，顺向（高位在前），C51 格式
 * 这 32 字节的排布是：
 *   第 0~15 字节 → 汉字左半边的上半部分 + 下半部分（每列 2 字节）
 *   第 16~31 字节 → 汉字右半边，同样每列 2 字节
 * 换句话说，第 i 列的上半部分在 hz[i*2]，下半部分在 hz[i*2+1]。
 *
 * ★ y 必须是偶数（0、2、4、6），因为一个汉字要占两页。
 * ------------------------------------------------------------------- */
void OLED_ShowCN(uint8_t x, uint8_t y, const uint8_t *hz)
{
    uint8_t i;

    if ((y + 1U) >= OLED_PAGES)
    {
        return;     /* 汉字需要两页，底部不够就不画 */
    }

    OLED_SetCursor(x, y);                   /* 先写上半部分（16 列） */
    for (i = 0; i < 16U; i++)
    {
        OLED_WriteData(hz[i * 2U]);
    }

    OLED_SetCursor(x, (uint8_t)(y + 1U));   /* 再写下半部分 */
    for (i = 0; i < 16U; i++)
    {
        OLED_WriteData(hz[i * 2U + 1U]);
    }
}

/* =====================================================================
 * main.c —— ADC 采集 PA1 电压并在 OLED 上显示
 * 芯片：STM32F103C8T6（蓝药丸）    外设：SSD1306 0.96 寸 OLED（软件 I2C）
 * ---------------------------------------------------------------------
 * 显示布局（y 是页号，每页 8 像素高，一屏 8 页）：
 *   Page 0 : STM32 ADC OLED
 *   Page 2 : V=1.234V
 *   Page 4 : RAW=2048
 *   Page 6 : PA1  CH1
 * ===================================================================== */
#include "main.h"
#include "adc.h"
#include "gpio.h"
#include "oled.h"

/* ---------------------------------------------------------------------
 * 读一次 ADC1 的原始值（轮询方式，详细原理见 ADC 那一篇）
 * ------------------------------------------------------------------- */
static uint16_t ADC1_ReadRaw(void)
{
    uint16_t raw = 0xFFFF;

    HAL_ADC_Start(&hadc1);
    if (HAL_ADC_PollForConversion(&hadc1, 10U) == HAL_OK)
    {
        raw = (uint16_t)HAL_ADC_GetValue(&hadc1);
    }
    HAL_ADC_Stop(&hadc1);

    return raw;
}

/* ---------------------------------------------------------------------
 * 屏幕没有应答时用它报警：板载 LED（PC13，低电平点亮）快闪三次
 * 这样即使 OLED 全黑，你也能从 LED 判断出“是屏的问题”而不是“程序没跑”
 * ------------------------------------------------------------------- */
static void ErrorBlink(void)
{
    uint8_t i;

    for (i = 0; i < 6U; i++)
    {
        HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);
        HAL_Delay(80);
    }
    HAL_GPIO_WritePin(GPIOC, GPIO_PIN_13, GPIO_PIN_SET);   /* 灭 */
}

/* ---------------------------------------------------------------------
 * 把已经算好的毫伏值刷到屏幕上
 * ------------------------------------------------------------------- */
static void ShowVoltage(uint16_t raw, uint16_t mv)
{
    /* --- 第 2 页：V=x.xxxV ---
     * 全部用整数拼出来，不碰浮点：
     *   mv / 1000   → 整数位
     *   mv % 1000   → 小数位，用补 0 的方式显示，保证 3 位宽度 */
    OLED_ShowString(0, 2, "V=");
    OLED_ShowNum(12, 2, mv / 1000U, 1);     /* 整数位，1 个字符宽 */
    OLED_ShowChar(18, 2, '.');              /* 小数点，x 每次进 6 像素 */
    OLED_ShowNumZ(24, 2, mv % 1000U, 3);    /* 小数位，3 个字符宽，高位补 0 */
    OLED_ShowString(42, 2, "V");

    /* --- 第 4 页：RAW=xxxx ---
     * 用补空格的 ShowNum：数字变短时左边会被空格覆盖，
     * 不会留下上一个值的残影 —— 这就是“不闪屏刷新”的关键技巧 */
    OLED_ShowString(0, 4, "RAW=");
    OLED_ShowNum(24, 4, raw, 4);
}

int main(void)
{
    uint16_t raw;
    uint16_t mv;

    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();
    MX_ADC1_Init();

    /* F1 系列 ADC 必须做自校准，否则首次转换结果会明显偏大 */
    HAL_ADCEx_Calibration_Start(&hadc1);

    /* ---- 初始化 OLED ---- */
    OLED_Init();

    /* 先探测从机应答，这是区分“接线/地址问题”和“代码问题”的分水岭 */
    if (OLED_TestConnection() != 0U)
    {
        ErrorBlink();       /* 从机不应答，用 LED 报警，然后继续跑主循环 */
    }

    /* ---- 画静态内容，只画一次 ----
     * 固定不变的文字在开机时画一次就够了，主循环里只更新会变的部分。
     * 这样既省时间（软件 I2C 全屏刷新要几十毫秒），也避免了闪烁。 */
    OLED_ShowString(0, 0, "STM32 ADC OLED");
    OLED_ShowString(0, 6, "PA1  CH1");

    while (1)
    {
        raw = ADC1_ReadRaw();

        if (raw != 0xFFFF)
        {
            /* 电压 = 原始值 × 3300mV / 4095，先乘后除并用 32 位中间变量防溢出 */
            mv = (uint16_t)(((uint32_t)raw * 3300U) / 4095U);
            ShowVoltage(raw, mv);
        }

        /* 每 300ms 刷一次。太快了数字跳得看不清，
         * 而且软件 I2C 刷新本身要花时间，没必要那么频繁 */
        HAL_Delay(300);
    }
}

关键代码解析

  • #define SCL_H() HAL_GPIO_WritePin(..., GPIO_PIN_SET)—— 为什么“写 1”能让线变高？因为引脚是开漏输出， 写 1 只是让内部的下管截止、引脚进入高阻态，真正把它拉高的是外部的 4.7kΩ 上拉电阻。 这也意味着忘焊上拉电阻时，SCL_H() 是无效操作， 线永远停在低电平，屏幕自然全黑。这是本页第一条要记住的因果关系。
  • ack = (SDA_READ() == GPIO_PIN_RESET) ? 0U : 1U;—— 在开漏输出模式下读引脚电平，靠的是 STM32 的输入数据寄存器 IDR 始终在采样引脚真实电平这一特性。这样就不用来回切换引脚方向， 省掉了 HAL_GPIO_Init 的开销，时序也更干净。
  • OLED_WriteDataBuf(const uint8_t *buf, uint16_t n)—— 这个函数是整份驱动的性能核心。I2C 每次 Start/Stop 都要花好几个位时间， 如果每写一个字节都走一遍完整事务，清屏 1024 字节就要 1024 次 Start/Stop。 改成一次事务连写 n 字节后，实测全屏清屏从约 150ms 降到约 30ms。 能批量就批量，这是 I2C 驱动优化的第一原则。
  • 0x8D, 0x14——电荷泵使能。 SSD1306 的 OLED 像素需要约 7.5V 的驱动电压，而模块只供 3.3V， 多出来的电压靠芯片内部的电荷泵升压得到。 这条命令写错或漏掉，现象就是 I2C 通信完全正常（ACK 都有）、但屏幕一点光都不出。 遇到“全黑但有应答”，第一个就查它。
  • 0xA8, 0x3F 里的 0x3F—— 多路复用比，0x3F + 1 = 64 行。0.91 寸屏只有 32 行， 这个值必须改成 0x1F。改错的现象是“只有上半屏显示，下半屏永远黑”。
  • OLED_ShowNum 高位补空格、 OLED_ShowNumZ 高位补 0—— 两个函数共用一个 OLED_ShowNumEx，区别只有 pad 参数。 补空格是为了覆盖旧内容（RAW=2048 变成 RAW=57 时， 后两位会显示成空格而不是残留的 48）， 补 0 是为了小数位的定宽显示（50mV 要写成 .050 而不是 . 50）。 看清楚这两个使用场景的差别，就不会再闪屏了。
  • if ((x > (OLED_WIDTH - 6U)) || (y >= OLED_PAGES)) return;—— 越界检查。SSD1306 的列地址是循环的，写超了会绕回屏幕左边， 现象是莫名其妙的错位文字，很难查。加一行判断能省掉一晚上的调试。

汉字取模显示的原理

OLED 本身不认识汉字，它只认识显存里的 0 和 1。 所谓“显示汉字”，就是把汉字的图形 事先在电脑上转换成字节数组，存进单片机的 Flash， 需要时把数组搬进显存。这个过程叫“取模”。

一个 16×16 的汉字一共 256 个像素，也就是 256 个 0/1 位， 打包成字节就是 32 字节。 取模软件负责把图形变成这 32 字节，我们负责把它写对位置。 常用的 PCtoLCD2002 软件里要这样设置：

设置项 选什么 为什么
点阵大小16 × 16正好占两页（2 × 8 = 16 行），横向 16 列
字模选项阴码阴码 = 1 表示点亮。反了就会显示成“白底黑字”的方块
取模方式逐列式和 SSD1306 的竖条显存结构一致，可以直接按列搬
取模走向顺向（高位在前）决定 bit0 在上还是 bit7 在上。反了字会上下颠倒
输出格式C51 格式直接生成 0x12, 0x34, ... 的数组，粘进代码就能用

取模软件生成的结果，粘进代码里长这样（ 下面的数值必须用你自己的取模软件生成， 这里只展示数据格式）： 

/* 取模软件生成：16x16 汉字，逐列式，顺向，阴码
 * ---------------------------------------------------------------------
 * 这 32 个字节的排布规律（和 OLED_ShowCN 的实现一一对应）：
 *
 *   hz[0]  hz[1]   ← 第 0 列：上半部分 8 行、下半部分 8 行
 *   hz[2]  hz[3]   ← 第 1 列：上半、下半
 *   hz[4]  hz[5]   ← 第 2 列
 *   ......
 *   hz[30] hz[31]  ← 第 15 列：上半、下半
 *
 * 所以第 i 列的上半部分永远是 hz[i*2]，下半部分是 hz[i*2+1]，
 * 这就是 OLED_ShowCN 里那句话的来历。

const uint8_t HZ_DIAN[32] = {
    0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00,
    0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00,
    0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00,
    0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00
};      /* ← 把取模软件生成的 32 个数值替换到这里 */

/* 调用方式：x 是起始列，y 必须是偶数（汉字要占第 y 页和第 y+1 页） */
OLED_ShowCN(0, 4, HZ_DIAN);

/* 一行可以放 128 / 16 = 8 个汉字，所以“电压表”三个字这样写： */
OLED_ShowCN(0,  6, HZ_DIAN);    /* 第 1 个字，占列 0~15  */
OLED_ShowCN(16, 6, HZ_DIAN);    /* 第 2 个字，占列 16~31 */
OLED_ShowCN(32, 6, HZ_DIAN);    /* 第 3 个字，占列 32~47 */
汉字显示上下颠倒或左右镜像怎么办

这是取模设置和屏幕扫描方向不匹配造成的，不用改驱动代码，两条路选一条：

  • 改取模软件：把“顺向/逆向”或“高位在前/低位在前”反过来，重新生成 32 字节。
  • 改初始化命令：上下颠倒就改 0xC8 为 0xC0，左右镜像就改 0xA1 为 0xA0。 但注意这会让整个屏幕都翻转，ASCII 字符也会跟着变，所以只在你确认所有内容方向一致时才这么干。

常见报错排查方案

I2C 和 OLED 的调试有一个通用的分诊顺序，建议按这个顺序查， 能避免在错误的方向上浪费时间： 先量电源 → 再量两根线的空闲电平 → 再确认地址 → 最后才怀疑代码。

现象：屏幕完全不亮（全黑），程序跑得却很正常

原因：按概率从高到低排——① 上拉电阻缺失或虚焊，SCL/SDA 停在低电平，通信根本无法开始；② 从机地址不对（模块是 0x3D 而代码写的是 0x78）；③ 初始化序列里电荷泵那条 0x8D, 0x14 漏写或写成了 0x10；④ VCC 或 GND 有一根没插上。

解决：按顺序验：万用表量 OLED 的 VCC 与 GND 之间是不是 3.3V； 断电后量 SCL 对 VCC 的电阻（应当在 5kΩ 左右，无穷大就说明没上拉）； 上电量 SCL/SDA 的空闲电压（应当是 3.3V，不是就说明上拉没起作用）； 最后把 OLED_I2C_ADDR 改成 0x7A 再试一次。 这四步走完，绝大多数黑屏都能定位。

现象：程序卡死在 HAL_I2C_Master_Transmit，或者一直返回 HAL_BUSY

原因：这是硬件 I2C 的经典问题。如果上一次通信中途 MCU 复位（比如你按复位键重新下载），而从机正好在拉低 SDA 发 ACK，总线就被占住了；MCU 复位后看到 SDA 是低电平，判定总线忙，BUSY 标志一直不清零，之后所有传输全部失败。另外，超时参数如果传了 HAL_MAX_DELAY，函数就永远不会返回。

解决：三个办法。 ① 最简单：改用本文的软件模拟 I2C，不再依赖那个会死锁的外设； ② 如果必须用硬件 I2C，开机时先手动发 9 个 SCL 脉冲解锁总线（把 SCL 当普通 GPIO 翻转，直到 SDA 变高为止），再初始化 I2C 外设； ③ 所有调用一律传有限超时，并在返回 HAL_ERROR 时执行外设软复位：__HAL_I2C_DISABLE(&hi2c1); HAL_I2C_Init(&hi2c1);。

现象：屏幕亮了但显示花屏，或者只有一部分内容正确

原因：① 初始化序列不完整，特别是 0xA8（多路复用比）和 0xDA（COM 引脚配置）写错，会出现隔行亮或局部花屏；② 供电不稳——OLED 全屏点亮的瞬间电流会跳到 20mA 以上，USB 供电加上细杜邦线会造成电压跌落；③ 杜邦线太长（超过 20cm）导致 I2C 边沿变缓、位错乱。

解决：对照本页的初始化表逐条核对，重点确认 0xA8, 0x3F 和 0xDA, 0x12； 在 OLED 的 VCC 与 GND 之间并一个 100nF 加一个 10µF 电容； 把杜邦线换成 10cm 以内的短线，或者直接焊在洞洞板上。

现象：显示的文字上下颠倒，或者左右镜像

原因：屏幕的扫描方向和你的字模数据方向不匹配。涉及两条命令：0xA1 / 0xA0 控制段重映射（左右），0xC8 / 0xC0 控制 COM 扫描方向（上下）。不同厂家的模块出厂默认值不一样，同一份代码换一块屏就可能变反。

解决：在初始化序列里试四种组合，必有一种正立。注意这两个命令影响的是整屏所有内容，所以要改就整体改，不要只针对汉字调整。如果只有汉字方向不对而 ASCII 正常，那问题在取模软件的“顺向/逆向”设置，改软件重新生成即可。

现象：字符显示错位、串行，或者第二行字跑到别的位置去了

原因：坐标写越界了。SSD1306 的列地址是循环的：你从第 124 列开始写一个 6 像素宽的字符，它会写 124、125、126、127、然后绕回 0、1——结果就是屏幕左边莫名其妙冒出字符。另一个原因是把 y 当成了像素行号，实际上 y 是页号，取值范围只有 0~7。

解决：记住两条换算： 一行最多放 128 / 6 = 21 个字符； y 是页号（0~7），一个页号对应 8 个像素行。 本页的 OLED_ShowChar 里已经加了越界判断，如果你用的是别的库，记得自己补上。

小结与练习

这一篇把 I2C 和 OLED 从电气层一路讲到了像素层。需要带走的结论有六条：

  • 开漏结构决定了必须有上拉电阻——I2C 引脚只能主动拉低，高电平全靠外部电阻提供。
  • 起始/停止条件靠 SDA 在 SCL 高电平时的跳变定义，数据和它正好相反，必须在 SCL 高电平期间保持稳定。
  • 7 位地址 0x3C 和 8 位地址 0x78 是同一个东西，后者是左移一位补上读写位后的结果。
  • SSD1306 的显存是按页（8 像素竖条）组织的，128×64 一共 8 页 1024 字节；0.91 寸只有 4 页。
  • 每个字节前面都要带控制字节，0x00 是命令、0x40 是数据。
  • 能批量写就批量写，一次 Start/Stop 连发多个字节，是软件 I2C 提速的关键。

  3. 测一测你的 I2C 到底有多快。 在 OLED_Clear() 前后各读一次 HAL_GetTick()，把两次的差值通过串口打出来。 然后做三组对比：① 位延时循环 20 次；② 改成 5 次；③ 把 OLED_WriteDataBuf 改成每个字节一次完整 I2C 事务。 记录下三组的耗时，再想想：如果这块屏要用电池供电， 刷新时间越短意味着什么？（提示：CPU 醒着的时间越短，平均功耗越低）
