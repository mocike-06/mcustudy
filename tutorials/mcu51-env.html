原理介绍

学单片机遇到的第一个认知落差是：你写的代码不在你的电脑上运行。 在 PC 上写 Python，保存后双击就能跑；而单片机没有硬盘、没有操作系统， 它只会从自己的 Flash 存储器里逐条取出机器码执行。所以「把 .c 文件变成芯片能执行的东西」 中间必须经过三步翻译，这就是开发环境存在的全部理由：

  1. 编译（Compile）——Keil 的 C51 编译器把你的 .c 源文件翻译成 51 汇编，再汇编成机器码目标文件 .obj。
  2. 链接（Link）——链接器把所有 .obj 和启动代码拼起来，按 51 的存储空间（CODE 从 0000H 开始）绝对定位，产出可烧写文件。
  3. 下载（Download / 烧写）——STC-ISP 通过串口把这段机器码写进 STC89C52RC 片内的 Flash，断电也不会丢。

这三步里，Keil 负责前两步，STC-ISP 负责第三步。理解这个分工， 后面所有「编译过了但下载失败」「下载成功了但灯不亮」的问题，你都能立刻判断该去哪个软件里查。

工具链：为什么是两个软件

新手最容易混的地方是把 Keil 当成「下载器」。它不是——Keil 编译完就下班了， 它根本不知道你的板子插在哪个 USB 口上。真正和硬件打交道的是 STC-ISP， 它靠一根 USB 转串口线（CH340 / PL2303 芯片）与单片机的 P3.0 / P3.1 通信。

1

Keil µVision C51

编辑器 + 编译器 + 链接器。只负责把 .c 变成 .hex，与硬件无关，装完不需要联网。

2

STC-ISP 下载软件

把 .hex 文件通过串口写进芯片 Flash。STC 官方免费提供，换芯片型号时记得选对型号。

3

USB 转串口驱动

CH340 或 PL2303 驱动。没装驱动时设备管理器里会出现带感叹号的未知设备，STC-ISP 里也找不到 COM 口。

安装 Keil 时的三个关键选择
  • 一定要装 C51 版本（安装包名里带 C51）， 不是 MDK-ARM。ARM 版本里没有 reg52.h，也没有 51 的芯片库， 工程一建就报找不到头文件。
  • 安装路径不要带中文和空格，例如用 D:\Keil_v5。 编译器和链接器对路径里的非 ASCII 字符处理得不好，容易出现莫名的链接失败。
  • 用管理员身份安装，注册（License）时也用管理员身份打开 µVision， 否则写不进 License 信息。未注册的评估版有 2KB 代码上限，点灯这类小程序够用， 但代码一变大就会撞上 L250 报错。请使用学校提供的正版授权或官方评估版。

HEX 文件与 Create HEX File

编译成功后，Keil 在 Objects\ 目录里生成的是 .obj、.lst、.m51 这些 中间文件——它们是给链接器和调试器看的，不是给芯片的。 真正能被 STC-ISP 识别的只有 Intel HEX 格式的 .hex 文件： 它用纯 ASCII 文本记录「往哪个地址写哪些字节」，还自带校验和，因此能通过串口这种容易出错的链路安全传输。

而 Keil 出于历史原因，默认不生成 HEX—— 当年芯片多用编程器烧写 .obj，HEX 是可选项。所以你必须手动勾上 Options for Target → Output → Create HEX File。 这一勾没勾，现象非常典型：编译 0 错误 0 警告，看起来一切正常， 但 STC-ISP 打开文件时发现没有 .hex，或者你打开的是上一次实验留下的旧 .hex， 于是「下载成功、现象却是上一次的程序」。 

Test1\                        ← 工程文件夹
├─ Test1.uvproj               ← Keil 工程文件（老版本；新版为 .uvprojx），记录芯片型号与所有选项
├─ main.c                     ← 你写的源文件
├─ STARTUP.A51                ← 启动代码，Keil 自动加入，负责清零内存、跳到 main
└─ Objects\                   ← 所有中间产物与最终产物
   ├─ main.obj                ← 编译产物（机器码 + 未定位的符号）
   ├─ Test1.lst               ← 汇编清单：能看到 C 语句对应的汇编，调时序时很有用
   ├─ Test1.m51               ← 链接映射文件：能看到每个函数占了多少字节
   └─ Test1.hex               ← ★ 最终烧写文件，勾了 Create HEX File 才会出现

晶振频率为什么必须填对

Options for Target → Target → Xtal (MHz) 这个框填的是 你板子上真实焊的那颗晶振的频率， 它不是「随便写一个就行」的形式参数，而是会直接影响程序的三个东西：

  • 软件延时——Keil 的 _nop_() 和某些库延时按这个频率换算，更重要的是：你手写的空循环延时的实际时长， 取决于每秒执行多少条指令，而指令速度由晶振决定。
  • 定时器初值——12MHz 时一个机器周期是 1µs，11.0592MHz 时是 1.085µs。 同一组 TH0/TL0 初值，在两种晶振下的实际定时长度差 8.5%。
  • 串口波特率——波特率由定时器溢出率推导，频率填错或晶振选错， 串口收到的就是乱码。这也正是 11.0592MHz 这个「奇怪数字」存在的原因。
晶振 1 个机器周期 方式 1 定时器最大定时 9600bps 串口能否整除 什么时候选它
12.000MHz 1.000µs 65.536ms 不能，误差约 8.5% 只学 IO、定时器，要「1µs 一个好算」时
11.0592MHz 1.085µs 71.11ms 能，误差 0% 要用串口通信（几乎所有实训项目都会用到）

本教程后续统一按 11.0592MHz 讲解， 因为从串口那一节开始它省事得多；如果你的板子是 12MHz，把 Xtal 改成 12 并沿用本文的初值计算即可， 只是串口那几节的波特率需要另算。想快速验证某个初值到底定多久，可以用 51 延时计算器 现场对一下。

硬件接线说明

这一节分两部分：先在电脑上把软件装好，再把板子和电脑用一根 USB 转串口线连起来。 下载通路只有三根线，但接错任何一根都会卡在「正在检测目标单片机」， 所以下面这张接线表要照着逐根核对。

下载前必查（三条都查过再点下载）
  • 模块上的电压跳线帽是不是拨在 5V（51 单片机是 5V 系统，3.3V 电平可能识别不稳）。
  • TXD / RXD 是否交叉、GND 是否共地——这两条占了下载失败原因的八成。
  • 串口助手、Proteus、其他 STC-ISP 窗口是否还开着占用 COM 口，全部关掉。

完整代码

环境搭好后不要急着写复杂程序，先用下面这段「环境验证程序」把链路跑通： 它开机慢闪 3 次（证明程序真的跑起来了），然后进入 1Hz 心跳闪烁（证明主循环与延时都在工作）。 灯闪得起来，说明 Keil、HEX、STC-ISP、接线、晶振、复位全部正确。 

#include <reg52.h>              /* 51 单片机标准头文件：P0~P3、TMOD 等寄存器都在里面定义 */

/* ------------------------------------------------------------------
 * sbit：位定义。
 * 51 的 P1 口可以按位访问（P1.0~P1.7），sbit 就是把某一位单独取个名字，
 * 之后写 LED = 0 就等于把 P1.0 拉低，比整个字节赋值更好读。
 * 注意：P1 ^ 0 的 ^ 是「第几位」的意思，不是异或运算，这是 Keil 的语法。
 * ------------------------------------------------------------------ */
sbit LED = P1 ^ 0;              /* 把 P1.0 命名为 LED，对应板上的第一颗灯 */

/* ------------------------------------------------------------------
 * 软件延时函数：靠 CPU 空转消耗时间
 * 12MHz 晶振、默认 12T 模式下，内层 j 循环约 1ms
 * 它不精确：换晶振、改 Keil 优化等级（Options for Target → C51 → Level）
 * 都会让实际时间变化，所以只用来做「肉眼可见的节拍」
 * ------------------------------------------------------------------ */
void Delay_ms(unsigned int ms)
{
    unsigned int i, j;                  /* 51 的 int 是 16 位，最大 65535，够数到 65 秒 */
    for (i = ms; i > 0; i--)            /* 外层：重复 ms 次 */
        for (j = 110; j > 0; j--);      /* 内层：空循环，约 1ms */
}

void main(void)
{
    unsigned char i;

    P1 = 0xFF;                      /* 先让 8 颗灯全灭（灌电流接法：引脚输出低电平才亮） */

    /* ---------- 开机自检：慢闪 3 次 ---------- */
    for (i = 0; i < 3; i++)
    {
        LED = 0;                    /* 输出低电平 → 灯亮 */
        Delay_ms(300);              /* 亮 300ms */
        LED = 1;                    /* 输出高电平 → 灯灭 */
        Delay_ms(300);              /* 灭 300ms */
    }

    /* ---------- 主循环：1Hz 心跳 ---------- */
    while (1)                       /* 单片机程序不退出，必须写成死循环 */
    {
        LED = 0;
        Delay_ms(500);              /* 亮 0.5s */
        LED = 1;
        Delay_ms(500);              /* 灭 0.5s，一个完整周期约 1s */
    }
}

新建工程七步

代码只是原料，工程才是容器。下面七步是每次新建实验都要走的固定流程， 顺序不能颠倒（尤其是第 5 步和第 6 步，颠倒了就白编译一次）：

  1. Project → New µVision Project， 新建一个空文件夹（例如 D:\MCU\Test1）保存工程。 一个实验一个文件夹，别把多个实验塞在一起。
  2. 选芯片：在器件库里找 Atmel → AT89C52，或者如果你装了 STC 的器件库就选 STC MCU Database → STC89C52RC。 STC89C52RC 与 AT89C52 的内核、寄存器完全兼容，选 AT89C52 编译出来的代码一样能在 STC 上跑 （区别只是 STC 片内有 8KB Flash、支持 ISP 下载）。
  3. 新建 .c 源文件： File → New，写代码后 Ctrl+S 保存为 main.c。 ⚠️ 常见坑：保存时必须手动补上 .c 后缀， 否则会存成 main.c.txt 或没有后缀，Keil 不会把它当源文件。
  4. 加入 Group：左侧 Project 窗口里右键 Source Group 1 → Add Files to Group…， 文件类型选 C Source file (*.c)，选中 main.c 点 Add。 加对了左边会出现 main.c 这一行；加错了（比如加了 previous 实验的文件） 就会报重复定义。
  5. Target 选项：点击工具栏的魔术棒图标 （或 Project → Options for Target），在 Target 页把 Xtal (MHz) 改成 11.0592 或 12， 与板上晶振一致；同一页确认 Memory Model 是 Small、 Code Rom Size 是 Large。
  6. 勾选 Create HEX File：切到 Output 页，勾上 Create HEX File， 格式选 HEX-80。这一步不勾，Objects 目录里永远没有 .hex 文件。
  7. 编译（F7 / Build Target）， 在下方 Build Output 窗口看到 0 Error(s), 0 Warning(s). 和 creating hex file from ".\Objects\Test1"... 才算成功。 然后打开 STC-ISP：选型号 → 选 COM 口 → 打开 .hex → 点「下载/编程」 → 给板子断电再上电。

关键代码解析

  • sbit LED = P1 ^ 0;——这里有两个新手必踩的点： 一是 ^ 在 Keil C51 里表示「第几位」而非异或； 二是 sbit 只能用于可位寻址的存储区， P0~P3 的每一位地址都能被 8 整除，所以可以用； 而 TMOD（地址 0x89）就不行，这也是后面定时器一节必须整体赋值的原因。
  • P1 = 0xFF;——开机第一件事是让所有灯灭。 为什么是 0xFF（全 1）而不是 0x00？因为灌电流接法下低电平才亮， 全 1 表示所有引脚都是高电平，灯自然全灭。这也是 51 上电后的默认状态。
  • unsigned int i, j;——延时循环里变量用 unsigned int 而不是 int： 无符号比较在 51 上生成的汇编更短更快，延时也更容易估算； 另外 i > 0 在无符号下等价于 i != 0，编译出来就是一条判零指令。
  • for (j = 110; j > 0; j--);——分号就是空循环体。 这个 110 是实测凑出来的经验值，不同晶振、不同优化等级都要重调， 记住「软件延时是估的，定时器才是准的」。
  • void main(void)——51 的 main 不需要返回值也不需要参数， 程序运行到 while (1) 就再也不会离开， 单片机的「关机」只有断电。
验证 HEX 到底生成了没有

打开工程文件夹里的 Objects\ 目录， 找修改时间最新的那个 .hex。 如果时间对不上，说明这次编译没生成新文件， 回头检查 Create HEX File 有没有勾、以及 Build Output 里最后一行到底是 creating hex file 还是 Target not created。

现象演示说明

环境搭建的成功标准不是「没报错」，而是每一步都有可验证的实物回执。 下面把整条链路拆成五个检查点：前三个在电脑屏幕上，后两个在板子上。 任何一步对不上，就在那一步停下排查，不要往下走。

正确现象（按顺序出现）

  1. 编译结束，Build Output 最后两行是 0 Error(s), 0 Warning(s). 与 creating hex file from ".\Objects\Test1"...。
  2. Objects\ 目录里出现新的 Test1.hex，修改时间是刚刚。
  3. STC-ISP 点「下载/编程」后，右侧提示区依次出现：正在检测目标单片机 ... → 单片机型号 : STC89C52RC → 进度条 → 操作成功 !。
  4. 给板子断电再上电的瞬间，接 P1.0 的那颗灯慢闪 3 次（亮 300ms、灭 300ms，肉眼能一颗一颗数）。
  5. 随后进入 1Hz 心跳：亮 0.5 秒、灭 0.5 秒，用秒表量 10 个完整周期约 10 秒。

闪得飞快（几乎像常亮），慢闪 3 次也看不清 板上晶振频率与 Keil 里 Xtal 填的不一致（例如板子是 12MHz，却以为延时是 1ms） 把 Xtal 改成板上真实晶振频率，或按实际频率重算延时循环次数
10 个周期实测 13 秒左右（偏慢 30%） 延时循环被编译器优化或晶振偏低，属于软件延时的正常误差 记录实测值即可，要精确计时请改用定时器（见下一篇之后的定时器教程）
顺手记录实验数据

环境搭建这一步就值得记一张表：理论值 vs 实测值。 例如理论心跳周期 1.0s，实测 10 个周期 10.3s； 把「晶振频率、Xtal 设置、编译器优化等级、实测周期」四项一起写进实验报告， 后面讲到定时器时，这张表就是「为什么必须用硬件定时器」最有力的证据。

常见报错排查方案

下面六条是环境搭建阶段出现频率最高的报错，按 「报错原文 → 原因 → 解决」组织，可以直接用报错信息里的关键词搜索定位。

编译报错：main.c(1): fatal error C318: can't open file 'reg52.h'

原因：装的是 MDK-ARM 版本，或者装的是 C51 但器件选了 ARM 系列。ARM 的器件库里没有 51 的寄存器头文件路径。

解决：卸载后重装 Keil for C51；在 Options for Target → Device 里把芯片换成 Atmel AT89C52 或 STC89C52RC，重新编译。

编译报错：main.c(5): error C202: 'P1': undefined identifier

原因：漏写 #include <reg52.h>，或者头文件名写错（写成 reg52.H、REG52.H 在部分环境下不区分大小写但路径不对）。

解决：在文件第一行补上 #include <reg52.h>。注意它用的是尖括号（去系统的 INC 目录找），不是双引号。

链接报错：*** ERROR L104: MULTIPLE PUBLIC DEFINITIONS / 或 L104: MULTIPLE PUBLIC DEFINITIONS 指向两个 main

原因：一个工程里加了两个包含 main() 的 .c 文件——最典型的是「把上一次实验的文件也 Add 进了 Source Group 1」。

解决：在左侧工程树里右键多余的文件 → Remove File（只从工程移除，不会删硬盘上的文件）。一个工程只留一个 main。

编译报错：*** FATAL ERROR L250: CODE SIZE LIMIT IN RESTRICTED VERSION EXCEEDED

原因：Keil 评估版（未注册）有 2KB 代码上限，链接时超了。点灯、流水灯这类程序通常没超，一旦加入 LCD、多个库函数就容易撞上。

解决：使用学校提供的正版授权（用管理员身份运行 µVision，在 File → License Management 里填入并 Add LIC）；或在学习阶段换用 SDCC 等免费工具链。请勿使用来源不明的注册机。

下载失败：一直停在「正在检测目标单片机 ...」，最后提示「请给 MCU 上电」

原因：按可能性排序——① COM 口被串口助手/另一个 STC-ISP 窗口占用；② 选错 COM 号；③ TXD/RXD 没交叉或 GND 没共地；④ 没有冷启动：STC 芯片只在「上电复位那一刻」的极短时间里检测下载命令，程序已经在跑的芯片是不会响应下载的。

解决：先关掉所有占用串口的软件；在设备管理器确认 CH340 对应的 COM 号并在 STC-ISP 里选它；核对三根线；然后先点「下载/编程」，再给板子断电、重新上电，顺序不能反。

下载失败：握手失败 / 提示「此芯片无法识别，请检查型号」/ 下载到一半中断

原因：下载波特率设得太高（USB 转串口模块与劣质杜邦线在高波特率下信号质量差），或者板子由 USB 模块的 5V 供电时电流不足（下载瞬间电流冲高导致芯片掉电复位）。

解决：在 STC-ISP 里把「最高波特率」从 115200 逐级降到 9600 甚至 4800 再试；换短一点、质量好一点的杜邦线；给开发板接独立电源，避免下载瞬间掉电。

没有报错但就是不对

「零报错零警告但现象不对」时，先做三件事： ① 确认 STC-ISP 打开的 .hex 是刚生成的那个（看文件时间）； ② 确认 Xtal 填的频率与板上晶振一致； ③ 按一下板子的复位键看现象有没有重新从头开始（能重新开始说明程序在跑，是逻辑问题；没反应说明硬件没工作）。 这三条能把问题范围缩小一半以上。

小结与练习

这一篇讲的其实是一条单向流水线：.c → 编译 → .hex → 串口下载 → 芯片 Flash → 执行。 需要刻在脑子里的只有三件事：Keil 只编译不下载、Create HEX File 不勾就没有烧写文件、 STC 下载必须冷启动。把这三条记住，环境问题基本就只剩接线问题了。

动手练习
  1. 验证「软件延时不准」：把 Delay_ms(500) 改成 Delay_ms(1000)， 用手机秒表量 10 个完整周期的实际耗时，和理论值 20 秒对比，把误差百分比记下来。
  2. 验证晶振设置的影响：把 Options for Target → Target 里的 Xtal 从 11.0592 改成 24， 重新编译下载（代码一个字都不改），观察灯闪的快慢有没有变化，并解释为什么。
  3. 故意制造一次失败并读报错：取消勾选 Create HEX File 后重新编译， 记下 Build Output 少了一行什么内容、Objects 目录里少了哪个文件、 STC-ISP 这时会给你什么提示。把这次「报错原文」抄进实验报告—— 以后在实验室遇到同样提示，你能一眼定位。
