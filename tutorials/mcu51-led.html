原理介绍

流水灯是几乎所有单片机教材的第一个实验，但很多人做完也只是「抄了一段能跑的代码」。 这一节要把三件事讲透：字节怎么变成引脚电平、 为什么必须让引脚去「吸」电流、 一个字节怎么自己循环移位。 理解了这三件事，后面驱动继电器、数码管、步进电机都是同一套思路的延伸。

P1 口 8 位并行输出

51 的四个 IO 口（P0~P3）在芯片内部都是一组特殊功能寄存器（SFR）， 每个口对应一个 8 位寄存器 + 8 个输出锁存器 + 8 个驱动场效应管。以 P1 为例：

  • P1 的字节地址是 0x90，8 个位分别是 P1.0 ~ P1.7，位地址 0x90 ~ 0x97。
  • 因为 0x90 能被 8 整除，所以 P1 是可位寻址（bit-addressable）的—— 你既能整体写 P1 = 0xFE;，也能单独写 P1 ^ 0 = 0;（或先 sbit 起个名字）。
  • 写 P1 = 0xFE; 这一个动作，在硬件上是 8 个锁存器同时被更新，8 个引脚的电平在同一时刻确定—— 这就是「并行输出」的含义，也是为什么流水灯可以做到 8 路完全同步。
为什么是 P1 而不是 P0

上一节讲过，P0 是开漏结构，要输出高电平必须外接 10kΩ 上拉电阻； 而 P1/P2/P3 内部自带弱上拉，直接接 LED 就能用。 所以入门实验统一用 P1 口，省掉一组排阻，也少一处出错的地方。 等你以后需要外扩存储器或驱动总线时，才会回头去处理 P0 的上拉问题。

灌电流与拉电流：为什么推荐「吸」不推荐「推」

同一个 LED，接法不同，程序里的电平逻辑完全相反。所以接线之前必须先把这件事定下来：

接法 怎么接 什么时候亮 引脚电流能力 结论
灌电流（推荐） LED 正极经限流电阻接 +5V，负极接引脚 引脚输出低电平（0）时亮 下拉管导通，可吸收约 20mA 亮度足、稳定，工程首选
拉电流 LED 正极接引脚，负极接地 引脚输出高电平（1）时亮 内部弱上拉，只有几百微安（不到 1mA） 灯很暗甚至不亮，不建议

为什么差别这么大？因为 51 的准双向口输出级是「一个弱上拉管 + 一个强下拉管」： 输出 1 时电流要经过内部上拉电阻，内阻大、能给的电流就小； 输出 0 时下拉管直接导通到地，通道阻抗低，能「吸」走大电流。 记住一句话：51 的引脚擅长「吸」，不擅长「推」。

限流电阻怎么算：从 300Ω 到 470Ω

LED 是二极管，导通后两端电压基本固定（红色约 1.8~2.0V），多出来的电压必须由电阻承担， 否则电流会失控烧掉 LED 或引脚。计算只用一条欧姆定律： 

已知：电源 VCC = 5V，红色 LED 正向压降 Vf ≈ 2V，期望电流 I = 10mA

        R = (VCC - Vf) / I
          = (5V - 2V) / 0.010A
          = 300Ω

300Ω 不是标准阻值，最近的 E24 标称值有两个：

   330Ω → 实际电流 (5-2)/330 = 9.1mA   （接近目标，亮度高）
   470Ω → 实际电流 (5-2)/470 = 6.4mA   （留足余量，亮度仍清晰可见）

本教程选 470Ω，原因有三条：
  ① 8 路同时点亮时总电流只有 8 × 6.4mA ≈ 51mA，不会让芯片和电源吃力；
  ② 电阻功耗小、不发热，长时间运行稳定；
  ③ 亮度差 30% 肉眼几乎看不出，但可靠性差别很大。

注意：如果用的是蓝光或白光 LED（Vf ≈ 3.0~3.4V），
      (5-3.4)/470 = 3.4mA，灯会明显偏暗，
      这时应改用 220Ω 或 180Ω，并按同样公式复核电流不要超过 10mA。
电阻 电流（红色 LED，Vf=2V） 8 路总电流 适用场景
1kΩ3.0mA24mA室内暗环境、只是看状态
470Ω6.4mA51mA推荐，亮度与安全兼顾
330Ω9.1mA73mA要亮一点，且不长时间全亮
220Ω13.6mA109mA不推荐 8 路同时点亮，总电流偏大
不接仅受内阻限制，可达 100mA 以上—禁止，会烧 LED 甚至烧引脚

位运算与循环左移

流水灯的本质是一个字节的循环移位。 灌电流接法下，哪一位是 0，对应的灯就亮。所以「只有最低位那盏灯亮」的初始状态是 1111 1110，也就是十六进制 0xFE。

步数 二进制 十六进制 亮的灯 这一字节是怎么来的
11111 11100xFEP1.0初始值
21111 11010xFDP1.10xFE 循环左移 1 位
31111 10110xFBP1.20xFD 循环左移 1 位
41111 01110xF7P1.30xFB 循环左移 1 位
51110 11110xEFP1.40xF7 循环左移 1 位
61101 11110xDFP1.50xEF 循环左移 1 位
71011 11110xBFP1.60xDF 循环左移 1 位
80111 11110x7FP1.70xBF 循环左移 1 位
回到 11111 11100xFEP1.00x7F 循环左移 1 位

普通左移 << 的问题在于：最高位会被移出丢弃。 0x7F（0111 1111）左移一位变成 1111 1110， 看起来正好，但如果初始状态里最高位是 1（比如两颗灯一起流动），移出去的那一位就永远丢了， 循环会出现「断点」。所以正确的写法是把移出去的那一位补回来： 

设 led = 0xFE = 1111 1110

第一步：led << 1         左移一位，最高位被挤出 8 位之外
       1111 1110  →  1 1111 1100        （C 语言里运算结果按 int 处理，共 9 位）

第二步：led >> 7         把最低位移到最高位的位置上
       1111 1110  →  0000 0001

第三步：按位或 |         把两部分拼起来
       1 1111 1100
   |   0 0000 0001
   ─────────────────
       1 1111 1101
       截断成 8 位 → 1111 1101 = 0xFD   ✔ 灯从 P1.0 走到了 P1.1

关键在于赋值回 unsigned char 时发生了截断：
   (led << 1) | (led >> 7) 的运算结果是 16 位（或 int）的 0x1FD，
   赋给 unsigned char 类型的 led 时只保留低 8 位 0xFD，高位那个 1 自然消失，
   而被 >> 7 补上来的那一位留在了最低位——这就是「循环」的由来。
为什么不能只写 led = led << 1;

只左移不补位，0xFE 走到 0x7F 之后，下一次左移变成 0xFE（恰好转了一圈）—— 看起来居然也能用！但如果初始值不是「单灯」，比如 0xFC（两颗灯）， 走到 0x3F 之后左移得到 0x7E，那一位「移丢」了，接下来就再也回不到 0xFC， 循环会出现越来越多的灯，最后全亮并卡住。 这就是为什么必须老老实实写全 (led << 1) | (led >> 7)。

软件延时为什么不准

流水灯的「慢动作」靠空的 for 循环消耗时间。教材通常写 for (j = 110; j > 0; j--); 并标注「约 1ms」， 但很少有人告诉你这个 110 是怎么来的——因为它是在特定环境下凑出来的。 影响它的因素有四类：

影响因素 为什么会影响时长 偏差量级
晶振频率 1 个机器周期 = 12 / fosc，12MHz 是 1µs，11.0592MHz 是 1.085µs 约 8.5%
编译器优化等级 Options for Target → C51 → Level 0~9，等级越高生成的汇编越短；极端情况下空循环可能被整段优化掉 可达数倍
循环变量的类型 unsigned char 的加一/比较是 8 位运算，unsigned int 是 16 位，指令条数差好几倍 数倍
中断打断 定时器或外部中断一旦触发，CPU 要跳去执行中断服务程序，延时会被拉长 取决于中断频率

正确的态度是：把软件延时当成「模糊节拍」而不是「时间」。 它够用，是因为流水灯只需要「人眼能看清」； 一旦要用它做串口波特率、数码管动态扫描、红外解码这类对时序有要求的场合， 就必须换成定时器。本文最后给的练习会让你亲手标定一次这个延时， 并用秒表算出它的真实误差——这比记住「110 等于 1ms」有用得多。

接线顺序建议

  1. 先接电源与地（40/20 脚 + 104 电容），上电量一次电压，确认 5V 且不短路。
  2. 接晶振与两个 30pF 电容，再接复位电路，最后把第 31 脚 EA 接到 +5V。
  3. 把 8 个 470Ω 电阻的一端连成一条公共线接到 +5V，另一端分别接 8 颗 LED 的正极。
  4. 把 8 颗 LED 的负极分别接到 P1.0 ~ P1.7，按顺序接，并在心里记住 P1.0 对应哪一颗。
  5. 接下载线：模块 TXD→P3.0、RXD→P3.1、GND 共地。
  6. 全部接完，用万用表通断档逐路确认「电阻—LED—引脚」这条链是通的，再上电。
上电前必查
  • LED 的长短脚有没有插反——反了不亮，而且不会烧，所以非常容易被误判为程序问题。
  • 限流电阻有没有漏掉：漏一个就可能烧掉那颗 LED 和对应的引脚。
  • 公共线是不是接在 +5V 上而不是 GND 上。接到 GND 上就是「共阴」接法，程序逻辑正好相反（写 1 才亮）。
  • 8 根信号线有没有插错位（比如 P1.0 接到了 P1.4）。现象是「顺序乱了但确实在流」，属于接线问题而不是代码问题。

完整代码

下面这段代码可以直接复制进 Keil 编译下载：上电先全灭一次， 然后一颗灯从 P1.0 依次走到 P1.7，走到头自动回到 P1.0 循环。 每行都有注释，注释里写的是「为什么这么写」，不只是「这行做了什么」。 

#include <reg52.h>              /* 51 单片机标准头文件，里面定义了 P1、P0 等寄存器 */

/* ------------------------------------------------------------------
 * 软件延时函数（单位：约毫秒）
 * 12MHz 晶振、默认 12T 模式下，内层循环约 1ms
 * 11.0592MHz 时机器周期长 8.5%，同样的循环次数实际约 1.09ms
 * 注意：这个延时不精确，换晶振或改优化等级就要重新标定
 * ------------------------------------------------------------------ */
void Delay_ms(unsigned int ms)
{
    unsigned int i, j;                  /* 51 的 int 是 16 位，最大 65535 */
    for (i = ms; i > 0; i--)            /* 外层循环 ms 次，每次约 1ms */
        for (j = 110; j > 0; j--);      /* 内层空循环：靠 CPU 空转消耗时间 */
}

void main(void)
{
    /* 0xFE = 1111 1110，最低位是 0，对应 P1.0 那颗灯亮（灌电流接法） */
    unsigned char led = 0xFE;

    P1 = 0xFF;                          /* 上电先让 8 颗灯全灭（高电平 = 熄灭） */

    while (1)                           /* 单片机程序不退出，主循环必须是死循环 */
    {
        P1 = led;                       /* 把当前状态送到 P1 口，8 个引脚同时更新 */
        Delay_ms(200);                  /* 保持 200ms，太快人眼会看成一片全亮 */

        /* ----------------------------------------------------------
         * 循环左移一位
         * led << 1 ：整体左移，最高位被移出 8 位之外（暂时保留在 int 的高位）
         * led >> 7 ：把最低位挪到最高位
         * 兩者按位或，再赋回 unsigned char，高 8 位被截断 → 实现循环
         * ---------------------------------------------------------- */
        led = (led << 1) | (led >> 7);
    }
}

关键代码解析

  • unsigned char led = 0xFE;——为什么用 unsigned char 而不是 int？ 因为只需要 8 位，用最小的类型既省 RAM（51 只有 128 字节可用的内部 RAM）， 也让「赋值时自动截断成 8 位」这个循环移位的关键机制自然成立。
  • P1 = led;——这一行不是「设置某个引脚」， 而是一次性覆盖整个 P1 口的 8 个锁存器。 所以你在别处对 P1 做的任何修改都会被这一行冲掉，这也是为什么流水灯程序里不要同时用 P1 口做别的事。
  • Delay_ms(200)——数字怎么定？ 以「人眼舒适」为准：小于 50ms 会把流水看成一段模糊的亮带， 大于 500ms 又显得卡顿。200ms 是常见的折中值，8 步走完一圈约 1.6 秒。
  • led = (led << 1) | (led >> 7);——这是全篇的核心。 括号不能省：虽然 << 的优先级高于 |， 但写清楚能让读代码的人立刻看懂「左移 + 右移 7 位 拼起来」这个意图。
  • while (1)——单片机的 main 函数不能返回。 如果它退出了，CPU 会继续执行 Flash 后面未使用的空间（通常是 0xFF），行为不可预测。 标准做法就是死循环，或者写成 for (;;)。

两种等价写法（对照理解）

循环移位不是只能手写位运算。下面两种写法效果完全相同， 分别代表「用库函数」和「用查表」两种思路，代码都是完整可编译的。 想验证某个字节对应哪几位、二进制长什么样，可以用 进制转换工具现场对一下。 

#include <reg52.h>
#include <intrins.h>             /* _crol_ / _cror_ / _nop_ 等内联函数在这里声明 */

void Delay_ms(unsigned int ms)
{
    unsigned int i, j;
    for (i = ms; i > 0; i--)
        for (j = 110; j > 0; j--);
}

void main(void)
{
    unsigned char led = 0xFE;

    P1 = 0xFF;
    while (1)
    {
        P1 = led;
        Delay_ms(200);
        led = _crol_(led, 1);       /* 循环左移 1 位，等价于 (led << 1) | (led >> 7) */
    }
}
#include <reg52.h>

/* 把 8 个状态直接写死在数组里，可读性最好，也最省 CPU（不用做移位运算） */
unsigned char code table[8] = {0xFE, 0xFD, 0xFB, 0xF7, 0xEF, 0xDF, 0xBF, 0x7F};

void Delay_ms(unsigned int ms)
{
    unsigned int i, j;
    for (i = ms; i > 0; i--)
        for (j = 110; j > 0; j--);
}

{
    unsigned char i;

    P1 = 0xFF;
    while (1)
    {
        for (i = 0; i < 8; i++)     /* 依次输出表里的 8 个状态 */
        {
            P1 = table[i];
            Delay_ms(200);
        }
    }
}
注意 code 关键字

写法 B 里的 unsigned char code table[8] 用的是 Keil C51 特有的 存储类型修饰符 code，表示把这个数组放在 片内 Flash（程序存储器）而不是只有 128 字节的 RAM 里。 漏写 code 时数组会占用宝贵的 RAM，程序一大就会报 *** ERROR L107: ADDRESS SPACE OVERFLOW。

现象演示说明

流水灯的现象很容易描述，但「偏差现象」的种类特别多，而且大多数偏差都能直接定位到 某个具体原因。所以下面这张判据表比「正确现象」更有用。

正确现象

  1. 上电瞬间 8 颗灯全灭（因为程序一开始就把 P1 写成了 0xFF）。
  2. 紧接着接 P1.0 的那颗灯亮起，其余 7 颗全灭。
  3. 亮点以约每 200ms 一格的速度，从 P1.0 依次移动到 P1.7。
  4. 走到最后一颗后，立刻回到 P1.0 重新开始，中间没有停顿也没有跳格。
  5. 任何时刻始终只有一颗灯亮；8 步走完一圈约 1.6 秒，可用秒表核对。

观察点与判据

你观察到的 说明什么 下一步查什么
8 颗灯全灭，完全不动 程序没跑起来，或没下载进去 量 VCC、(31 脚) EA、(18 脚) XTAL2，并用 STC-ISP 重新冷启动下载
8 颗灯全亮且不流动 P1 口的低 8 位全是 0，说明移位写成了 led = led << 1; 一路移到 0x00 后卡住 检查循环移位那一行是否写全了 (led << 1) | (led >> 7)
只有一颗灯常亮，从不移动 led 变量没有被更新，或 P1 = led; 后面又写了一次固定值把它覆盖了 确认移位语句在 while (1) 循环体内，且循环里没有别的 P1 赋值
流动方向相反（从 P1.7 往 P1.0 走） 程序是对的，只是「左边」的定义和你想象的不同 把移位改成 (led >> 1) | (led << 7)，或者干脆把 LED 的物理顺序反过来插
流动速度太快，看起来像一片全亮 延时太短（或被编译器优化掉了空循环） 把 Delay_ms(200) 调大；检查 C51 优化等级不要设成最高
有 1~2 颗灯始终不亮，其余正常流动 这一路 LED 接反、电阻虚焊，或引脚线没插紧 把该 LED 的负极直接用导线短到 GND，亮说明 LED 没问题 → 问题在引脚/连线
灯很暗，几乎看不清亮没亮 接成了拉电流接法（LED 正极接引脚），或限流电阻误用了 10kΩ 确认 LED 负极接引脚、正极经 470Ω 接 +5V；核对电阻色环
亮灭顺序乱（比如 1→3→2→5…） 8 根信号线插错了位置 按 P1.0→P1.7 的顺序重新核对杜邦线
上电后现象和上一次实验一样 STC-ISP 打开的 .hex 是旧的 重新在 Objects 目录里选最新的 .hex 再下载
顺手标定你的延时函数

用手机秒表量「8 步走完一圈」的实际耗时，和理论值比较： 如果程序里延时是 Delay_ms(200)，理论一圈 = 8 × 200ms = 1.6 秒。 实测如果是 1.75 秒，说明你的延时循环比标称慢约 9%—— 这个数字就是你这套「晶振 + 编译器 + 优化等级」组合的修正系数， 以后写软件延时时可以按它折算。把「理论值 / 实测值 / 偏差」写进实验报告， 是很专业的一笔。

常见报错排查方案

下面六条按「报错原文 / 现象原文 → 原因 → 解决」组织。 前三条是编译期的，后三条是运行期的——运行期的问题更值得花时间读， 因为现象和原因之间的对应关系不是一眼能看出来的。

编译报错：main.c(3): error C202: 'P1': undefined identifier

原因：漏写了 #include <reg52.h>，编译器不知道 P1 这个符号对应哪个寄存器地址。

解决：在文件最上面补上头文件。如果补了还报错，检查工程 Device 选的是不是 AT89C52/STC89C52RC 这类 51 芯片（选了 ARM 芯片就没有这个头文件）。

编译报错：main.c(12): error C141: syntax error near '='

原因：把赋值语句写在了函数外面。例如在 #include 之后直接写 led = 0xFE;——函数外只能做变量定义和声明，不能写可执行语句。

解决：把初始化语句挪进 main 里；如果确实要在定义时初始化，写成 unsigned char led = 0xFE; 放在函数内部即可。

编译警告：main.c(18): warning C206: 'Delay_ms': missing function-prototype

原因：函数在被调用之前没有声明。C89/Keil C51 要求先声明后使用，警告本身不致命，但编译器会因为不知道参数类型而做出错误的参数传递假设，可能引发难查的运行异常。

解决：把 Delay_ms 的定义写在 main 之前（本文示例就是这么做的），或在文件开头补一行声明 void Delay_ms(unsigned int ms);。

现象：下载成功，但 8 颗灯同时全亮、完全不会流动

原因：移位语句写成了 led = led << 1;。0xFE 一路左移，第 8 次变成 0x00（8 位全是 0），此后左移仍然是 0x00，于是 8 颗灯全亮并永久卡住。灌电流接法下「全亮」正是全 0 的表现。

解决：写全循环移位：led = (led << 1) | (led >> 7);，用括号把两部分包起来再赋值。也可以改用 _crol_(led, 1)。

现象：方向正好相反，或者流动顺序错乱

原因：两种情况要分开判断——① 只是方向相反（严格从 P1.7 → P1.0），说明代码没错，是你的「左边」定义与接线顺序不同；② 顺序错乱（比如 1→4→2→6），那是信号线插错了位置。

解决：方向问题改一句就行：led = (led >> 1) | (led << 7);；接线问题必须重新逐根核对 P1.0~P1.7 与 LED 的对应关系（给每根线贴标签是最省事的办法）。

现象：4 颗灯亮、4 颗灯暗，或每颗灯亮度都不一样

原因：这不是程序问题，而是电流问题——限流电阻取值不一致（混用了 220Ω 和 1kΩ）、LED 型号混用（红/绿/蓝的 Vf 差很多），或者公共线用的是面包板的细长跳线导致压降过大。

解决：统一使用同一批次的 LED 与同规格电阻（用万用表逐个量一遍阻值）；公共 +5V 线改用粗一点的线或直接焊在铜箔上。

程序明明对了，现象却总差一格

如果你觉得「灯先亮 P1.1 才轮到 P1.0」，先别改代码，先数接线。 这类问题的根源几乎总是「LED 与引脚的一一对应关系」记错了。 建议在第一颗 LED 旁边贴一小张纸写上「P1.0」，成本极低但能省掉半小时排查。

小结与练习

这一篇走完了 51 驱动 LED 的完整链路：从灌电流接法为什么比拉电流好， 到用限流电阻把电流控制在 6.4mA，再到用一个字节的循环移位实现流水效果， 最后是现象对照表和六条高频问题的排查路径。 真正需要记住的只有两点：低电平点亮， 以及 循环移位必须左右移配合、再靠赋值截断成 8 位。

动手练习
  1. 两颗灯一起流动：把初始值改成 0xFC（1111 1100）， 其余代码一行不改，观察现象；然后回答：为什么这次的循环移位必须用 (led << 1) | (led >> 7)，而不能只写左移？请用移位过程中具体出现的字节值来论证。
  2. 用软件延时做呼吸灯，并解释为什么吃力：用「快速亮灭 + 改变亮灭时间比例」的方式模拟渐亮渐暗。 做完之后想一想：51 只有空循环延时，做不到真正精确的 PWM， 呼吸效果会抖；要做出干净的呼吸灯，需要用什么硬件资源？（提示：定时器 + 中断，见下一篇。）
  3. 标定你的延时函数：写一个只翻转 P1.0 的程序，让它在 Delay_ms(500) 下闪烁， 用秒表量 20 个周期的总时间，算出实际延时与标称值的偏差百分比； 再把 C51 优化等级从 Level 8 改成 Level 0，重新标定一次，比较两次结果并解释原因。
