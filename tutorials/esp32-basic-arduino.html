原理介绍

学 51 的时候，工具链是透明的：你写完 C，Keil 编译，烧录器把 hex 写进芯片， 芯片从 main() 第一行开始跑。ESP32 不一样—— 中间隔着一层 Arduino 框架和一层 ESP-IDF，而这两层恰好是最容易让人困惑的地方： 「我写的 setup() 到底是被谁调用的？」 「为什么装了库还要选板子？」「为什么同样的代码在别人的电脑上编译不过？」 本节就回答这些问题。

Arduino 到底是什么

最常见的误解是把 Arduino 当成「一种芯片」或者「一门语言」。都不是。 Arduino 是一套让嵌入式变简单的抽象层，它包含三部分：

  • 一套约定：一个程序必须提供 setup() 和 loop() 两个函数。
  • 一套 API：digitalWrite()、analogRead()、Serial.print() 这些函数，把底层寄存器操作包成人话。
  • 一套工具链：Arduino IDE、编译器、烧录脚本，点一个按钮就把这一串跑完。

语言上，你写的是 C++（C 是它的子集），只是被限制了写法： 不写 main()，不自己管理启动流程。所以「Arduino 语言」严格说不存在， 它就是 C++ 加一层框架。你在 51 上写的 C 代码，绝大多数可以直接搬进来（除了 reg51.h 那些寄存器定义）。

ESP32 Arduino Core

ESP32 不是 Arduino 官方做的芯片，那为什么能在 Arduino IDE 里开发？ 因为 Espressif（乐鑫）官方维护了一个移植层，叫 ESP32 Arduino Core（在开发板管理器里显示为 「esp32 by Espressif Systems」）。它的工作就是：把 ESP-IDF 的功能包装成 Arduino API。

│    void setup() { Serial.begin(115200); }                    │
│    void loop()  { digitalWrite(2, HIGH); delay(1000); }      │

  出问题时按这个层次「自下而上」排查：
  硬件接线 → IDF 报错（串口日志）→ Arduino API 用法 → 你的逻辑。
为什么这件事对你很重要

因为 Arduino API 不是万能的：某些功能（精细的定时器、DMA、任务优先级、省电模式） 它没有封装，你必须直接调 ESP-IDF 的函数。 知道了层次关系，你就知道「Arduino 里怎么用 IDF 的功能」——直接 #include 对应的 IDF 头文件调就行，两者本来就在同一个工程里。 本页后面的 ESP-IDF 版闪灯就是活例子。

setup 与 loop 到底执行几次

函数执行次数什么时候执行该放什么
setup()1 次芯片复位并启动完成后初始化：串口、引脚模式、连 WiFi、初始化传感器
loop()无限次setup() 返回后立刻开始，一次结束马上再来一次主逻辑：读传感器、判断、输出

关键点在于：框架在你背后生成了一个 main()。 它大概长这样（简化版，真实代码在 core 里）： 

// 这是 ESP32 Arduino Core 内部的骨架，你不需要写，但要理解
extern void setup();
extern void loop();

void loopTask(void *pvParameters) {
    setup();                 // ① 只调用一次
    for (;;) {               // ② 无限循环
        loop();              //    每次 loop() 返回就再调一次
        // 这里还会做一些系统维护（例如喂看门狗、让出 CPU）
    }
}

extern "C" void app_main() {             // ESP-IDF 的入口
    // ... IDF 的初始化：NVS、WiFi 协议栈、事件循环 ...
    xTaskCreatePinnedToCore(loopTask,    // 把 loopTask 变成一个 FreeRTOS 任务
                            "loopTask",
                            8192,        // 栈大小
                            NULL, 1, NULL,
                            1);          // 固定在 Core1 上运行
}

所以真实的调用链是： app_main() → 创建 loopTask → setup() → while(1) { loop(); }。这解释了四件事：

  • 为什么 loop 里不能写死循环：while(1); 会让这个任务永远不让出 CPU，系统的其他任务（WiFi、看门狗）都会饿死。
  • 为什么 loop 里可以放心用 delay：delay() 内部是 vTaskDelay()，它会把 CPU 让给别的任务，不是 51 那种「空转耗时间」。
  • 为什么变量能保持：loop() 是同一个任务反复调用，局部 static 变量和全局变量都不会重置；但普通局部变量每次进入都是新的。
  • 为什么你的代码跑在 Core1：xTaskCreatePinnedToCore(..., 1) 最后那个参数就是核心编号，WiFi 协议栈在 Core0。

esptool.py 是什么

它是 Espressif 官方的串口烧录工具，一个 Python 脚本， 负责「通过串口把 bin 写进 Flash」这件事。 Arduino IDE 只是替你调用它，并把过程打印在下面的输出窗口里—— 你在输出里看到的 esptool.py v4.5.1、 Chip is ESP32-D0WD-V3、Hash of data verified. 都是它打印的。理解了这一步，以后看到上传报错就知道该往哪儿找原因。

ESP-IDF 是什么

ESP-IDF（Espressif IoT Development Framework）是乐鑫的官方 SDK， 也是 ESP32 的「原生开发方式」。它比 Arduino 底层得多，也更强大、更啰嗦。 最直观的区别是入口函数：

对比项Arduino（ESP32 Arduino Core）ESP-IDF
程序入口setup() + loop()app_main()
循环方式框架替你写 while(1)自己写，或用 FreeRTOS 任务
点灯pinMode + digitalWritegpio_set_direction + gpio_set_level
延时delay(1000)vTaskDelay(pdMS_TO_TICKS(1000))
构建系统Arduino IDE 一键CMake + idf.py build
配置方式IDE 菜单里选板子idf.py menuconfig（上千个配置项）
上手难度低，十分钟点灯高，先要装工具链、理解工程结构
控制精度够用（教学、原型）完全控制（任务优先级、内存分区、省电、DMA）

要特别注意：Arduino 不是「另一种 ESP32」，它就是 IDF 的封装。 你在 Arduino 里能 #include "driver/gpio.h" 直接用 IDF 的 API， 因为 core 本来就是基于 IDF 编译的。所以「学 Arduino 还是学 IDF」并不是非此即彼， 而是「从哪一层开始」。

Arduino 还是 ESP-IDF

你的情况建议理由
刚学完 51/STM32，做课程实验Arduino把精力放在「硬件与时序」上，而不是构建系统上
做毕设/竞赛原型，要快速出功能Arduino海量现成库：传感器、显示屏、MQTT 全都有
需要精确的任务优先级、双核调度Arduino 起步，局部用 IDFArduino 里可以直接调 FreeRTOS 的 xTaskCreatePinnedToCore()
做量产产品，要求最小体积/最低功耗ESP-IDF能裁掉用不到的组件、精细配置电源管理与分区
要用 ESP32 的高级外设（DMA、LCD、I2S 细节）ESP-IDF这些在 Arduino API 里覆盖不全
公司/项目组已有 IDF 代码库ESP-IDF不要为了「简单」重写一遍
给学生的实际建议

先用 Arduino 把「电、时序、协议」这些东西做熟，等你开始抱怨 「Arduino 这个功能不给我用」的时候，就是转向 IDF 的时机。 本站 ESP32 方向的教程都走 Arduino 路线，需要时再指出对应的 IDF 写法—— 就像本页的闪灯对比那样。

库管理与版本冲突

Arduino 的「库」就是别人写好的代码包。三种来源，装的位置不同：

来源怎么装装在哪特点
库管理器IDE 左侧「库管理器」图标，搜名字点安装用户目录下的 Arduino/libraries最推荐，能一键切换版本
手动 ZIP「项目 → 加载库 → 添加 .ZIP 库」同上装 GitHub 上的新版或小众库时用
开发板核心自带装 ESP32 core 时一起装core 安装目录里WiFi.h、Wire.h、SPI.h 属于这一类，不用单独装

用户库目录在 Windows 上通常是 C:\Users\你的用户名\Documents\Arduino\libraries。 如果两个库重名，IDE 会优先用用户目录里的那个，而且会弹警告—— 这是「改了库但没生效」的常见原因。

版本冲突的典型样子（务必记住这个案例）

ESP32 Arduino Core 从 2.x 升到 3.x 时，LEDC（PWM）的 API 变了： 旧写法是 ledcSetup(通道, 频率, 分辨率) + ledcAttachPin(引脚, 通道)， 新写法合并成 ledcAttach(引脚, 频率, 分辨率)。 于是你在网上抄的教程代码可能直接报 error: 'ledcSetup' was not declared in this scope。 这不是你写错了，是 core 版本与教程不匹配。

解决： ① 在「开发板管理器」里把 esp32 降到教程对应的版本（比如 2.0.17）； ② 或者查新 API 文档改写代码（推荐，长期看更省事）； ③ 记住一条铁律：照着教程装同版本的 core，能省掉一半的报错。

开发板配置为什么关键

选「ESP32 Dev Module」还是「ESP32-WROOM-DA Module」看起来无所谓，实际上 IDE 会用它决定一大串参数：

参数典型值（ESP32 Dev Module）选错的后果
Flash 大小4MB选成 2MB 会写出错误的分区表，程序可能启动不了
分区表方案Default 4MB with spiffs决定 APP 分区大小，选错会「Flash 溢出」或浪费空间
上传速度921600线材差时改 115200 更稳
CPU 频率240MHz降低会变慢（但更省电）
Flash 模式QIO少数模组需要 DIO，选错会启动失败

另外还有个更基础的错误：根本没装 ESP32 core，板子列表里只有 Arduino Uno。 这时候编译 #include <WiFi.h> 会报「No such file or directory」， 因为 Uno 的 core 里没有 WiFi 库（Uno 也没有 WiFi 硬件）。 遇到这个报错先看板子选对没有，比看代码快得多。

硬件准备与下载电路

「代码没问题、板子没问题，就是上传不了」——这类问题九成出在线、驱动、和下载模式这三件事上。

USB 数据线还是充电线

USB 线里其实有 4 根（或 5 根）线：VBUS（5V）、GND、 D+、D-。 便宜的「充电线」为了省成本，只焊了 VBUS 和 GND，里面根本没有数据线。 表现就是：板子上的电源灯亮着，但电脑的端口列表里没有新串口，或者有端口却上传失败。 

数据线（能烧录）                        充电线（只能供电）
  ┌────────────┐                          ┌────────────┐
  │ VBUS  ─────┼── 5V                     │ VBUS  ─────┼── 5V
  │ D-    ─────┼── 数据                    │ D-    ────╳   （没接）
  │ D+    ─────┼── 数据                    │ D+    ────╳   （没接）
  │ GND   ─────┼── 地                      │ GND   ─────┼── 地
  └────────────┘                          └────────────┘

判别方法：
 ① 最可靠：换一根你确定用来传过文件的线，一试就知道；
 ② 看电脑：插上后「设备管理器 → 端口」有没有新出现的 COM 口；
 ③ 看线径/做工：数据线通常更粗一点，但这个不可靠；
 ④ 摸温度：劣质充电线长时间供电会发热（内阻大），也解释了你
    为什么一连 WiFi 就重启——见上一篇的峰值电流。

串口驱动

ESP32 开发板上有一颗「USB 转串口」芯片，把 USB 信号变成串口给 ESP32 用。 电脑要认它，就得装对应驱动。常见三种：

芯片常见于驱动认出来的名字
CP2102 / CP2104官方 DevKitC 开发板Silicon Labs CP210x 驱动Silicon Labs CP210x USB to UART Bridge (COMx)
CH340 / CH9102多数廉价国产开发板沁恒 CH341SER 驱动USB-SERIAL CH340 (COMx)
FT232RL老式模块、部分自制板FTDI VCP 驱动USB Serial Port (COMx)

装没装好看「设备管理器 → 端口 (COM 和 LPT)」： 正常会有 COM3 之类的条目；没装驱动则会出现在 「其他设备」下面，带黄色感叹号，名字是 USB2.0-Serial 之类。 Arduino IDE 的端口菜单是灰的、点不动，就是这个原因， 装完驱动（或换一根数据线）端口才会出现。

BOOT 与 EN 键

板子上那两个小按钮，是「手动进下载模式」用的：

按键接到芯片哪里按下去的意义什么时候用
EN（有的板标 RST）CHIP_PU 复位脚让芯片重新启动上传后程序没跑起来、想重新开始
BOOTGPIO0按住 = 把 GPIO0 拉低。芯片上电时若 GPIO0 为低，就停在下载模式等串口自动下载失败时手动进下载模式

正常情况下你不需要按它们，因为板上有自动下载电路：esptool 会通过串口的 DTR/RTS 自动完成「按住 BOOT → 点 EN → 松开 BOOT」这个动作。 当自动电路不起作用（比如 GPIO0 被外设拉低、串口芯片不支持、某些精简板没有这两条控制线）时， 就手动来一遍： 

① 按住 BOOT 不放
② 点一下 EN（RST），松开 EN     <- 这一步让芯片在 GPIO0 为低的情况下重新启动
③ 松开 BOOT
④ 立刻在 IDE 里点「上传」

上传完成后程序会自动运行（esptool 会做一次硬复位）。
如果上传完没反应，按一下 EN 即可。

反例：只在按下 BOOT 时上传、却没点 EN —— 芯片还在跑旧程序，看不到下载模式。

完整代码

同一个功能（GPIO2 上的板载 LED 闪灯）写两遍： 第一遍用 Arduino API，第二遍用 ESP-IDF API。对照着看，你就明白「框架包装了什么」。

Arduino 版闪灯

/*
 * ESP32 基础篇 / Arduino 框架与 ESP-IDF
 * 程序一：Arduino API 闪灯
 *
 * 硬件：ESP32-WROOM-32 开发板，板载 LED 接在 GPIO2
 *       （不同板子可能接在 GPIO2 或 GPIO5，用 LED_BUILTIN 最保险）
 */

#define LED_PIN 2

void setup() {
  Serial.begin(115200);
  delay(300);

  pinMode(LED_PIN, OUTPUT);          // 配置为输出

  Serial.println("========================================");
  Serial.println("Arduino 版闪灯");
  Serial.println("你应该看到：GPIO2 上的 LED 每秒闪一次");
  Serial.println("同时本行下方每秒打印一次计数");
  Serial.println("========================================");
}

void loop() {
  static unsigned long count = 0;
  count++;

  digitalWrite(LED_PIN, HIGH);       // 点亮
  delay(500);
  digitalWrite(LED_PIN, LOW);        // 熄灭
  delay(500);

  Serial.printf("第 %lu 次闪烁 | 运行 %lu 秒 | 空闲堆 %u 字节\n",
                count, millis() / 1000, ESP.getFreeHeap());
}

ESP-IDF 版闪灯

下面这段是 ESP-IDF 工程里的 main/main.c， 在 IDF 里用 idf.py build flash monitor 编译烧录。 如果你只想在 Arduino IDE 里体会 IDF 的写法，可以把文件后半部分原样贴进 loop()——因为 ESP32 Arduino Core 就是 IDF。 

/*
 * 程序二：ESP-IDF API 闪灯（与上面完全等价的功能）
 * 工程结构：
 *   blink/
 *     CMakeLists.txt
 *     main/CMakeLists.txt
 *     main/main.c        <-- 本文件
 */

#include <stdio.h>
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"
#include "driver/gpio.h"

#define LED_PIN GPIO_NUM_2

void app_main(void)                 // IDF 的入口，代替 setup()
{
    // ① 复位引脚，清掉上电时的默认状态（Arduino 的 pinMode 内部会做这件事）
    gpio_reset_pin(LED_PIN);

    // ② 配置为输出（对应 Arduino 的 pinMode(LED_PIN, OUTPUT)）
    gpio_set_direction(LED_PIN, GPIO_MODE_OUTPUT);

    printf("ESP-IDF 版闪灯启动\n");

    unsigned long count = 0;

    // ③ while(1) 就是 Arduino 的 loop()，只是这里要自己写
    while (1) {
        gpio_set_level(LED_PIN, 1);                     // 点亮（对应 digitalWrite(HIGH)）
        vTaskDelay(pdMS_TO_TICKS(500));                 // 延时（对应 delay(500)）

        gpio_set_level(LED_PIN, 0);                     // 熄灭
        vTaskDelay(pdMS_TO_TICKS(500));

        count++;
        printf("第 %lu 次闪烁 | 运行 %lu 秒\n",
               count, (unsigned long)(esp_log_timestamp() / 1000));
    }
}

编译输出的体积解读

上传时 Arduino IDE 会在下面输出两行关键数字。很多人从来不看他，但它能提前告诉你 「程序是不是快装不下了」「内存是不是快用完了」： 

项目使用了 273940 字节，占用了 (20%) 程序存储空间。最大为 1310720 字节。
全局变量使用了22096字节，(6%)的动态内存，余留305584字节局部变量。最大为327680字节。
数字含义怎么理解
273940 字节 你的程序编译后的大小（代码 + 只读数据） 放在 Flash 的 APP 分区里。带 WiFi 的空程序大约 250~300KB，加一个 MQTT 库会到 400KB 以上
最大 1310720 字节 APP 分区的大小（1280KB） 不是 4MB。4MB Flash 还要分给 bootloader、分区表、NVS、SPIFFS。想给程序更大空间，去改 Partition Scheme
20% 占用率 超过 90% 就该考虑裁库或换分区方案了；100% 直接报错
全局变量 22096 字节 静态分配的 RAM（全局变量、static 变量） 这部分编译时就要占好，不由堆分配
余留 305584 字节 还能给「局部变量 + 运行时堆」用 ESP32 总共约 320KB DRAM 可用，剩下这些是动态内存的上限参考
最容易误读的一点

「最大为 327680 字节」这行里的 327680 ≈ 320KB， 不等于芯片有 520KB SRAM 的那 520KB。 因为一部分 SRAM 被 IDF 内核、WiFi 协议栈缓冲区、DMA 描述符提前占掉了， 这个数字是「编译器视角里可用的一部分」。想知道真实剩余内存， 要在运行时用 ESP.getFreeHeap() 打印（见本页代码）。

第 4 次闪烁 | 运行 4 秒 | 空闲堆 311224 字节
为什么串口监视器要选 115200
  • 它是 ESP32 的「默认语言」：芯片内部的 ROM bootloader 上电后就用 115200 打印启动信息，你的程序若用别的波特率，前面那段启动日志会变成乱码，看不到复位原因——而复位原因恰恰是排错最需要的信息。
  • 足够快又不挑线：115200 下每毫秒约 11 个字节，打印调试信息绰绰有余；而 921600 在劣质 USB 线上容易丢字符，所以上传用它提速、监视器用 115200 稳。
  • 教程与库的默认值：几乎所有示例都写 Serial.begin(115200)，跟着写能少一类「我这没输出」的问题。

波特率是「双方约定」：代码 Serial.begin(115200)、 监视器也选 115200，两边一致才有可读输出。 数值不一致的典型现象就是满屏乱码。

常见报错排查方案

下面九条按「报错原文 → 原因 → 解决」写。前四条几乎是每个 ESP32 新手都会遇到的， 建议直接记住报错原文，以后一眼就能定位。

报错原文：A fatal error occurred: Failed to connect to ESP32: Timed out waiting for packet header

原因： 芯片没有进入下载模式，esptool 喊了半天没人应。常见四种： ① USB 线是充电线（没有数据线）； ② 串口被别的软件占用（另一个串口监视器、串口调试助手）； ③ 自动下载电路不起作用（GPIO0 被外设拉低、板子没引出 DTR/RTS）； ④ 选了错误的端口。

解决： ① 换一根确定能传数据的数据线； ② 关掉所有可能占用串口的软件（包括 Arduino IDE 自己开着的串口监视器）； ③ 手动进下载模式：按住 BOOT → 点一下 EN → 松开 BOOT → 立刻点上传； ④ 拔掉 GPIO0/GPIO2/GPIO12/GPIO15 上的所有外接电路再试； ⑤ 把「上传速度」从 921600 降到 115200。

报错原文：串口监视器里全是乱码，例如 ets Jul 29 2019 12:21:46 后面跟一堆问号和方块

原因： 波特率不匹配。芯片（或其 ROM bootloader）用 115200 发数据， 而监视器用了 9600 或 74880 之类的值，收到的字节被错误地切成字符。 少数情况是代码里 Serial.begin() 写了别的值， 或者模块晶振不是 40MHz（山寨板）。

解决： ① 把监视器右下角波特率改成 115200； ② 检查代码里的 Serial.begin() 是不是也是 115200； ③ 只有启动那几行乱码、后面正常：说明你的程序波特率不是 115200 而 ROM 日志是， 两边统一成 115200 即可； ④ 全篇都乱码且换波特率无效：怀疑板子晶振/Flash 模式问题，试着把 Flash Mode 从 QIO 改成 DIO。

报错原文：error: 'ledcSetup' was not declared in this scope（或某个库函数找不到、重复定义）

原因： 库/core 版本与代码不匹配。最典型的就是 ESP32 Arduino Core 3.x 改了 LEDC 的 API （ledcSetup + ledcAttachPin 合并成 ledcAttach），而你抄的教程是 2.x 时代的代码。 也可能是同一功能装了两个库（比如两个 MQTT 库都定义了同名类）。

解决： ① 打开「开发板管理器」看 esp32 的版本，把它换成教程对应的版本（常见 2.0.17）； ② 或者按新版 API 改写这几行（长期更推荐）； ③ 重复定义：把多余的库删掉，只留一个，注意用户库目录优先于 core 自带库； ④ 养成习惯：拿到示例代码先看它要求的 core 版本和库版本。

报错原文：项目使用了 1500000 字节，占用了 (114%) 程序存储空间。最大为 1310720 字节。 / text section exceeds available space in board

原因： 程序比 APP 分区还大，装不下。诱因通常是：板子型号选错（选了 2MB Flash 的板子， 分区表给 APP 的空间更小）、分区方案选错、或者塞进了太多库。

解决： ① 确认板子选的是 ESP32 Dev Module、Flash 大小 4MB； ② 「Partition Scheme」改成 Huge APP (3MB No OTA/1MB SPIFFS) 这类给 APP 更大空间的方案； ③ 精简库：一个项目里不要同时装多个同类库（比如三个 JSON 库）； ④ 打开「编译时显示详细输出」看究竟是哪些库把体积撑大了。

报错原文：端口菜单是灰的 / 列表里没有 COM 口（设备管理器里是「其他设备 USB2.0-Serial」并带黄色感叹号）

原因： 串口驱动没装。板上的 USB 转串口芯片（CH340、CP2102、FT232）需要对应驱动， 新装的 Windows 系统默认不带 CH340 驱动；也可能是数据线只有供电线。

解决： ① 看板子上 USB 口旁边那颗小芯片的丝印，确定是 CH340 还是 CP2102； ② 装对应驱动（沁恒 CH341SER / Silicon Labs CP210x），装完重新插拔； ③ 设备管理器里出现 COMx 才算成功； ④ 还是不行就换一根数据线、换一个 USB 口，排除线的问题。

报错原文：Task watchdog got triggered. The following tasks did not reset the watchdog in time: IDLE0 / rst:0x7 (TG0WDT_SYS_RESET)

原因： 某个任务长时间霸占 CPU 不让出，导致系统的空闲任务（IDLE0）得不到执行， 任务看门狗超时后强制复位。最常见的是这种写法： while (digitalRead(pin) == HIGH);（等按键）， 或者 while(1){ /* 干重活，没有 delay */ }。

解决： ① 在任何等待循环里加 delay(1) 或 vTaskDelay(1)， 给系统留出让出 CPU 的机会； ② 把「等一个事件」改成状态机：用 millis() 定时检查，而不是死等； ③ 顺带纠正一个常见误解：单独的 delay(15000) 不会触发任务看门狗 ——它内部是 vTaskDelay，会让出 CPU。 但它会让你的程序 15 秒内不响应任何输入、WiFi 心跳也可能受影响， 所以长延时同样要用「状态机 + millis()」代替。

报错原文：A fatal error occurred: Could not open port COM3, the port is busy / Access is denied

原因： 串口被占用了。最经典的情形：你刚用串口监视器看完日志，没关就点上传； 或者后台还开着串口调试助手、Python 脚本、另一个 Arduino 窗口。

解决： ① 关掉串口监视器窗口（右上角放大镜图标再点一次）再上传； ② 关掉所有可能读串口的软件：串口助手、PuTTY、VSCode 的串口插件、上一轮脚本； ③ 还占用就在设备管理器里禁用再启用该端口，或者拔插一次 USB； ④ 养成交替习惯：监视器和上传不能同时进行。

报错原文：fatal error: WiFi.h: No such file or directory（或 Wire.h、PubSubClient.h 找不到）

原因： 两种：① 板子型号选的根本不是 ESP32（比如选了 Arduino Uno，它的 core 里没有 WiFi 库）； ② 没有安装 ESP32 Arduino Core，或者库没装进库目录。

解决： ① 先看「工具 → 开发板」是不是 ESP32 系列（ESP32 Dev Module）； ② 没有 ESP32 选项 → 在「首选项 → 附加开发板管理器网址」里加上乐鑫的 JSON 地址， 再到开发板管理器搜 esp32 安装； ③ 是第三方库找不到 → 用库管理器搜索安装同名库； ④ 确认库名拼写与大小写完全一致（Windows 下大小写不敏感，但 Linux/macOS 上敏感，代码要保持一致）。

现象：上传成功、日志也显示 Hash of data verified，但串口什么都没有，程序像没跑

原因： ① 程序里压根没有 Serial.begin()（没有初始化串口就没有输出）； ② 串口监视器波特率不是 115200； ③ 上传后芯片仍在下载模式（少见，多见于手动下载后忘了复位）； ④ 程序卡在 setup() 里的某个等待（例如连 WiFi 又没设超时）。

解决： ① 确认代码第一行有 Serial.begin(115200);，后面至少有一句 Serial.println("boot ok");； ② 监视器波特率改成 115200； ③ 按一下板上的 EN 键重新启动； ④ 在 setup() 每一段之前加一句打印，用「最后看到哪句」定位卡在哪。

小结与练习

这一页要你记住的六件事

  • Arduino 是抽象层 + 约定 + 工具链，不是芯片也不是语言；语言就是 C++。
  • 层次关系：你的代码 → Arduino API → ESP-IDF → 寄存器，所以 Arduino 里可以直接调 IDF。
  • 框架在你背后生成了 main()：setup() 一次，loop() 被 while(1) 反复调用，跑在 Core1 的任务里。
  • 点上传 = 编译 → 链接 → 生成 bin → esptool.py 复位进下载模式 → 串口写 Flash → 复位运行。
  • 体积那两行数字决定你会不会「Flash 溢出」：APP 分区默认只有 1280KB，不是 4MB。
  • 报错优先看三处：端口有没有（线/驱动）、能不能进下载模式（BOOT/EN、GPIO0）、版本对不对（core、库、板子型号）。

自检题

  1. 用你自己的话说明：setup() 和 loop() 分别被执行几次？谁在调用它们？
  2. 为什么 loop() 里写 while(1); 会让 WiFi 掉线甚至触发看门狗，而写 delay(10000) 不会触发看门狗？
  3. ESP32 Arduino Core 与 ESP-IDF 是什么关系？在 Arduino 工程里能调用 IDF 的函数吗？举例说明。
  4. 「最大为 1310720 字节」这个数字是怎么来的？如果程序超过它，有哪两种解决办法？
  5. 同学说他上传时一直报 Failed to connect to ESP32，请给出至少四条排查建议，并说明原理。
  6. 为什么串口监视器建议选 115200？如果把监视器设成 9600 会发生什么？
  7. 手动进下载模式的正确按键顺序是什么？为什么必须先按 BOOT 再点 EN？
  8. 「全局变量使用了 22096 字节，余留 305584 字节」——这两个数字分别是哪部分内存？运行时想知道真实剩余内存该调用什么？

动手练习

  1. 亲手走一遍完整流程：编译 Arduino 版闪灯，把 IDE 输出的 「程序占用 / 全局变量」两行抄进实验报告，然后打开「编译时显示详细输出」， 数一数总共编译了多少个源文件，感受一下「你的一页代码 + 一整个 SDK」的差别。
  2. 复现一次版本冲突：在开发板管理器里把 esp32 core 从一个版本切到另一个版本， 编译同一份使用 ledcSetup() 的代码，观察报错原文。 以后看到类似报错就知道是版本问题，而不是自己的逻辑错。
  3. 做一次「手动下载」演练：按住 BOOT → 点 EN → 松开 BOOT → 点上传， 对比自动下载的区别，并把两种流程写进实验报告。 这是以后遇到「死活连不上」时唯一可靠的后手。
