原理介绍

先说结论：ADC 的本质是一台“用已知电压去猜未知电压”的天平。 它手里有一个由内部参考电压 VREF+ 驱动的精密 DAC，还有一套比较电路。 每猜一次，就把 DAC 的输出和外部待测电压比一比，根据“大了还是小了”缩小猜测范围。 猜够次数以后，剩下的那个数字就是转换结果。

STM32F103C8T6 内部有 2 个 12 位逐次逼近型（SAR）ADC， 一共 10 个外部通道加若干内部通道。10 个外部通道挂在 PA0~PA7 和 PB0~PB1 上， 所以你把电位器接到 PA1，就是在用 ADC1 的通道 1。理解这一点很重要： ADC 的“通道号”和 GPIO 的脚位是固定绑定的，不是随便指定的， 想换通道就得换引脚。

逐次逼近型 ADC 原理

逐次逼近（Successive Approximation Register）用的是 二分查找的思路。假设参考电压是 3.3V，要测一个 2.0V 的电压， 12 位转换过程可以简化成这样一个过程：

  1. 先把最高位（第 11 位）置 1，DAC 输出 3.3V 的一半 = 1.65V。比较：1.65V < 2.0V，说明猜小了，这一位保留 1。
  2. 再把第 10 位置 1，输出变成 1.65 + 0.825 = 2.475V。比较：2.475V > 2.0V，猜大了，这一位改回 0。
  3. 第 9 位：1.65 + 0.4125 = 2.0625V，还是比 2.0V 大，这位也是 0。
  4. 第 8 位：1.65 + 0.20625 = 1.856V，比 2.0V 小，这位留 1。
  5. ……如此一位一位往下试，试满 12 次，就得到了 12 位的转换结果。

这也解释了两件事：第一，12 位 ADC 一次转换至少要 12 个比较周期， STM32 的规则通道固定需要 12.5 个 ADC 时钟周期（多出来的 0.5 个是对齐开销）， 这个 12.5 加上采样时间，就是后面算转换速度的公式； 第二，整个过程的精度完全依赖那个内部 DAC 的参考电压—— 参考电压不准，猜得再准也没意义。这是下一小节的伏笔。

一句话记住 SAR 的工作方式

“从最大的一位开始，一位一位地试，试完就定，不回头。” 因为每一位只需要一次比较，所以 12 位只要 12 次，而不是 4096 次—— 这就是逐次逼近能做得又快又省电的原因。

12 位分辨率与参考电压的关系

“12 位”指的是转换结果是 12 个二进制位，能表示 2^12 = 4096 个不同的档位，编号从 0 到 4095。 这 4096 个档位均匀地铺在 0V 到参考电压之间，所以每一档代表的电压（叫 1 个 LSB）是： 

1 LSB = VREF+ / 4096

以蓝药丸（VREF+ = 3.3V）为例：
1 LSB = 3.3V / 4096 ≈ 0.000806V ≈ 0.8mV

也就是说：电压每变化 0.8mV，ADC 结果才会动 1 个数
反过来，ADC 结果每变化 1，代表电压变化了 0.8mV

换算公式就是这条，请抄在笔记本上：

核心换算公式

实际电压 = ADC 原始值 × 3.3 / 4095

比如读到 2048，电压就是 2048 × 3.3 / 4095 ≈ 1.6504V； 读到 4095，就是 3.3V（满量程）。

除以 4095 还是 4096？

严格推导的话，1 LSB 等于 VREF/4096， 所以 电压 = ADC值 × 3.3 / 4096 在数学上更“正统”； 但工程上为了满量程恰好落到 3.3V，绝大多数代码都写 4095。 两者的差别只有约 0.024%，对 0.8mV 的分辨率来说完全可以忽略。 本页统一用 4095，你只要别在同一个工程里混用两套公式就行。

还有个容易被忽略的点：参考电压从哪来？ 蓝药丸这种最小系统板没有独立的 VREF+ 引脚引出，VREF+ 在芯片内部直接连到 VDDA， 而 VDDA 又和 3.3V 供电轨并在一起。所以你代码里写的 3.3 其实是一个“假设值”—— USB 供电时实测经常是 3.26V 到 3.30V。这就是为什么很多人明明代码没错， 测出来的电压却总差 1%~2%。想更准有两个办法：用万用表量一下 VDDA 的真实值写进宏定义， 或者后面对照标准表做标定——标定的做法在 数字电压表那一篇里详细讲。

ADC 时钟为什么不能超过 14MHz

ADC 内部是逐次逼近的比较逻辑，每一拍都要完成 “设置 DAC → 等待稳定 → 比较 → 写入结果”这一整套动作。 这些动作靠开关电容电路实现，电容充放电是需要时间的。 时钟给得太快，DAC 还没稳定下来比较器就采走了结果， 相当于用没写完的答案去判卷，误差会明显变大，甚至高几位直接乱跳。

数据手册给出的硬性上限是 ADCCLK ≤ 14MHz。 而 STM32F103 的 ADC 挂在 APB2 总线上，APB2 在标准配置下是 72MHz， 所以必须经过一个专门的分频器降到 14MHz 以下。这个分频比只有四档可选， 没有 5 分频，所以能用的其实只有两档：

CubeMX 里的选项 分频后 ADCCLK 是否合规 换算一次要多久（采样 55.5 周期）
PCLK2 / 236MHz超限 2.5 倍，禁止—
PCLK2 / 418MHz仍然超限—
PCLK2 / 612MHz合规，推荐约 5.7µs
PCLK2 / 89MHz合规，最保守约 7.6µs

转换时间的公式也要记住： 

T_转换 = (采样周期数 + 12.5) / ADCCLK

例：ADCCLK = 12MHz，采样时间选 55.5 周期
T = (55.5 + 12.5) / 12MHz = 68 / 12MHz ≈ 5.67µs

→ 一轮最多约 17.6 万次采样，对绝大多数项目绰绰有余
CubeMX 里最容易踩的一脚

CubeMX 默认的分频比往往不是你想要的。在 Clock Configuration 页里，找到 ADC 那一栏的 Prescaler 下拉框， 必须手动改成 /6 或 /8。 改完顺手看一眼旁边显示的 ADCCLK 数值是不是 12 或 9——这是唯一可信的确认方式。

采样时间与信号源内阻的关系

这是新手最难自己悟出来的一条，也是“读数总比万用表低”的头号原因。

ADC 的输入端内部有一个采样保持电容，STM32F1 的典型值是 C_ADC ≈ 8pF。 采样阶段，这个电容通过你的信号源和它自己的内阻 R_ADC（约 1kΩ）充电； 采样结束时电容上的电压就是被转换的电压。问题在于： 充电是需要时间的，而 RC 充电是一条指数曲线，永远不会“充满”。

充电时间常数 τ = (R_源 + R_ADC) × C_ADC。 要让误差小于 0.5 个 LSB，需要大约 8~9 个 τ 的充电时间。 如果信号源内阻是 10kΩ，τ = (10k + 1k) × 8pF ≈ 88ns， 8.5τ ≈ 750ns；而采样时间如果只给 1.5 个周期（12MHz 下只有 125ns）， 电容根本来不及充到真实电压，读出来必然偏低。

STM32F103 的采样时间一共 8 档，CubeMX 的 ADC 配置页里每个通道都能单独选：

采样周期数 12MHz 下实际采样时长 适合的信号源内阻 典型用途
1.5125ns< 1kΩ运放输出的低阻信号，追求速度
7.5625ns< 5kΩ一般传感器输出
13.51.13µs< 10kΩ较通用的折中值
28.52.38µs< 20kΩ带 RC 滤波的信号

采样时间选长了，唯一代价是转换变慢——而 5.7µs 和 20µs 对“读个电压显示出来”这种应用毫无区别。 所以新手可以直接选 55.5 或 71.5 周期， 等以后真做高速采样（比如音频）再回来优化。 宁慢勿偏，这是 ADC 调参的第一原则。

轮询 / 中断 / DMA 怎么选

结果都放在 ADC 的数据寄存器里，区别只在于“谁来把结果搬走”。三种方式各有明确的使用边界：

方式 关键函数 CPU 占用 适合的场合
轮询 HAL_ADC_Start
HAL_ADC_PollForConversion
HAL_ADC_GetValue		 高，全程死等 单通道、低速、主循环里读一下就用。代码最简单，最适合入门
中断 HAL_ADC_Start_IT
HAL_ADC_ConvCpltCallback		 中，只在转换完成时进一次中断 单通道、需要定时自动采一批数据，又不想让主循环空等
DMA HAL_ADC_Start_DMA 低，硬件自动搬运，几乎不打扰 CPU 多通道扫描的必选项；也用于高速连续采样

为什么多通道一定要用 DMA？因为规则通道组里所有通道 共用同一个数据寄存器 ADC_DR。 扫描模式下 ADC 会按顺序自动采完所有通道，每采完一个就覆盖一次 DR。 如果靠 CPU 去读，你必须在这个通道被覆盖之前把值取走—— 12MHz 下两个通道之间只有几微秒，稍微被别的事情耽误一下，数据就串位了。 而 DMA 是硬件直接把每次结果搬运到内存数组的不同位置， 一次搬运只消耗一个总线周期，CPU 完全不用管。

注入通道是什么

规则通道（Regular）就是上面说的“排成一队按顺序采”，一队最多 16 个。 注入通道（Injected）只有 4 个，但它是 可以打断规则通道的“插队通道”： 注入组一触发，ADC 会暂停规则组的转换，先把自己的 4 个通道采完， 结果放进独立的 JDR1~JDR4 寄存器，然后规则组从断点继续。 它适合“平时慢慢采温度，一旦出现过流就立刻插进来采电流”这类需要优先响应的场合。 入门阶段先把规则组用熟，注入组知道有这么回事就够了。

硬件接线说明

这一节的目标是“闭着眼睛也能接对”。核心只有一句话： 把待测电压送进 PA1，并且保证两者的地是连在一起的。 新手 80% 的 ADC 问题都出在地没共或者引脚配错了模式，而不是代码。

  1. 电位器两端必须一端接 3.3V、一端接 GND，接成“分压”而不是“变阻”

接线顺序建议

  1. 先只接电源，万用表确认蓝药丸的 3.3V 排针对 GND 是 3.3V，再往下做。
  2. 接电位器：两端分别接 3.3V 和 GND，用万用表量滑臂对 GND 的电压，转动手柄应该在 0~3.3V 平滑变化。这一步验证了信号源本身没问题。
  3. 把滑臂接到 PA1。接之前先断电，避免手抖把线碰到 5V 上。
  4. 最后接串口模块，注意 TX/RX 交叉，GND 一定要连。
上电前必查：ADC 引脚不能超过 3.3V
  • 数据手册规定任意引脚电压不得超过 VDD + 0.3V，对 3.3V 系统就是 3.6V。直接把 5V 信号接进 PA1，轻则读数永远是 4095，重则烧掉这个引脚甚至整片芯片。
  • 测 5V 及以上的电压时，必须先分压再接进来，具体做法见数字电压表那一篇。
  • 确认电位器接的是 3.3V 而不是 5V 排针。蓝药丸上 3.3V 和 5V 排针挨得很近，插错一排很常见。

 *   ADCCLK   = PCLK2 / 6 = 12MHz     ← 必须 ≤ 14MHz
 *   ADC1_IN1 = PA1，采样时间 71.5 周期
 *   USART1   = 115200 8N1（PA9 = TX，PA10 = RX）

#include "adc.h"

/* ---------------------------------------------------------------------
 * 换算用的两个常量
 *
 * VREF_V  ：参考电压。蓝药丸没有独立引出 VREF+，它在芯片内部与 VDDA
 *           相连，而 VDDA 就是 3.3V 供电轨。USB 供电时实测常为 3.26~3.30V，
 *           想让读数更准就用万用表量一下 VDDA，把真实值填在这里。
 *

 *           配合公式 电压 = 码值 × VREF / 4095 使用
 * ------------------------------------------------------------------- */

#define ADC_FULL      4095.0f

/* 串口发送用的单字节缓冲，放全局是为了不占用栈 */
static uint8_t g_tx_byte;

/* ---------------------------------------------------------------------
 * 函数：ADC1_ReadRaw
 * 功能：启动一次 ADC1 规则通道转换，用轮询方式取回结果
 * 返回：0 ~ 4095 的原始码值
 *       读取失败时返回 0xFFFF，调用者据此判断这次数据不可信
 * ------------------------------------------------------------------- */
static uint16_t ADC1_ReadRaw(void)
{
    uint16_t raw = 0xFFFF;      /* 先填一个明显不可能的值作为失败标志 */

    /* 1) 启动转换。
     *    CubeMX 没勾 Continuous，所以每调用一次只转换一次，
     *    转换完 ADC 会自动停下，不需要我们再关它。 */
    HAL_ADC_Start(&hadc1);

    /* 2) 等待转换完成，第二个参数是超时时间（单位 ms）。
     *    这里绝对不能写 HAL_MAX_DELAY：万一 ADC 没配好，
     *    程序会永远卡死在这一行，连串口都来不及打印任何信息。 */
    if (HAL_ADC_PollForConversion(&hadc1, 10U) == HAL_OK)
    {
        /* 3) 转换结束标志 EOC 已置位，把数据寄存器读走。
         *    读取动作本身会清掉 EOC 标志，为下一轮做准备。 */
        raw = (uint16_t)HAL_ADC_GetValue(&hadc1);
    }

    /* 4) 关闭 ADC。单次模式下不关也不影响功能，
     *    但关掉更省电，也让下次启动的行为更干净。 */
    HAL_ADC_Stop(&hadc1);

    return raw;
}

/* ---------------------------------------------------------------------
 * 函数：ADC_ToMilliVolt
 * 功能：把 ADC 原始码值换算成毫伏（定点整数，避免用浮点）
 *
 * 为什么要用毫伏而不是伏特？
 *   用整数毫伏表示电压，显示时只需一次除法和取余就能拆出整数位和小数位，
 *   全程不碰浮点，速度快、也没有浮点舍入误差。
 *
 * ★ 溢出提醒：
 *   raw 最大 4095，4095 × 3300 = 13,513,500，
 *   这个数远远超过 16 位无符号整数的上限 65535，
 *   所以中间结果必须先转成 uint32_t 再乘，否则结果会被截断成乱七八糟的值。
 * ------------------------------------------------------------------- */
static uint16_t ADC_ToMilliVolt(uint16_t raw)
{
    uint32_t mv;

    /* 电压(mV) = raw × 3300 / 4095
     * 先乘后除，保证整除精度；用 32 位中间变量防止溢出 */
    mv = ((uint32_t)raw * 3300U) / 4095U;

    return (uint16_t)mv;
}

/* ---------------------------------------------------------------------
 * 函数：main
 * ------------------------------------------------------------------- */
int main(void)
{
    uint16_t raw;       /* ADC 原始码值 0 ~ 4095 */
    uint16_t mv;        /* 换算后的电压，单位毫伏 */

    /* HAL 库初始化：把 SysTick 配成 1ms 心跳，HAL_Delay 依赖它 */
    HAL_Init();

    /* 配置系统时钟到 72MHz。必须在任何外设初始化之前调用 */
    SystemClock_Config();

    /* CubeMX 生成的外设初始化，顺序不重要，但都要在 HAL_Init 之后 */
    MX_GPIO_Init();
    MX_ADC1_Init();
    MX_USART1_UART_Init();

    /* ★ ADC 自校准：F1 系列强烈建议做，而且必须在启动转换之前做。
     *   芯片内部有一个自校准电容网络，上电后要做一次校准把偏差写进
     *   ADC 的校准寄存器，不做的话第一次转换的结果会明显偏大。
     *   这一步耗时约 几微秒，正常情况下都是立刻返回。 */
    HAL_ADCEx_Calibration_Start(&hadc1);

    /* 开机先打个招呼，方便确认串口通路是通的 */
    printf("STM32F103 ADC1 demo start, VREF = %.2fV\r\n", (double)VREF_V);

    while (1)
    {
        raw = ADC1_ReadRaw();

        if (raw == 0xFFFF)
        {
            /* 超过 10ms 都没转换完，说明 ADC 没配好，直接报错 */
            printf("ADC read timeout!\r\n");
        }
        else
        {
            mv = ADC_ToMilliVolt(raw);

            /* 分开打印：先给原始码值（调试用），再给人看的电压值。
             * %u.%03u 的写法把毫伏拆成“整伏”和“毫伏余数”，
             * 例如 1650mV → 1.650，不需要任何浮点运算。 */
            printf("RAW = %4u    V = %u.%03u V\r\n",
                   raw, (unsigned)(mv / 1000U), (unsigned)(mv % 1000U));
        }

        /* 每 500ms 打印一次。太快了串口助手会刷屏看不清，
         * 而且 printf 是阻塞发送，太频繁会拖慢主循环 */
        HAL_Delay(500);
    }
}

上面用到了 printf。Keil 的 printf 默认走“半主机”模式，会把字符往调试器里送而不是串口， 必须自己做一次重定向。把下面这段单独存成 usart_retarget.c 并加入工程即可。 

/* =====================================================================
 * usart_retarget.c —— printf 重定向到 USART1
 * ---------------------------------------------------------------------
 * Keil 使用前提（两个都要做，缺一不可）：
 *   1. Options for Target → Target 选项卡 → 勾选 Use MicroLIB
 *      不勾的话会链接半主机库，程序可能卡在启动阶段跑不起来
 *   2. 本文件必须加入工程参与编译
 * ===================================================================== */
#include "main.h"
#include "usart.h"
#include <stdio.h>

/* ---------------------------------------------------------------------
 * fputc 是 C 标准库里 printf 的底层输出函数：
 * printf 每拼好一个字符，就回调一次 fputc 把该字符送出去。
 * 我们只要在这个函数里把字符丢给串口，printf 就变成“串口打印”了。
 * ------------------------------------------------------------------- */
int fputc(int ch, FILE *f)
{
    uint8_t byte = (uint8_t)ch;

    /* (void)f 是为了消掉“未使用参数”的编译警告 */
    (void)f;

    /* 用阻塞方式发一个字节，超时 100ms。
     * 这里绝对不能用 HAL_MAX_DELAY：串口线没接好时会让程序永久卡住。 */
    HAL_UART_Transmit(&huart1, &byte, 1U, 100U);

    /* 按标准库约定，返回写入的字符；返回 EOF 表示出错 */
    return ch;
}

关键代码解析

  • HAL_ADCEx_Calibration_Start(&hadc1)—— F1 系列 ADC 独有的自校准。它的作用是让芯片测量自己内部电容网络的偏差并补偿掉。 漏掉这一句的典型现象是：第一次读到的值明显偏大，之后就正常了， 或者整体恒偏几十个码值。写代码时养成“ADC 初始化之后立刻校准”的习惯。
  • HAL_ADC_Start + HAL_ADC_PollForConversion + HAL_ADC_GetValue——轮询三件套，顺序不能乱。 Start 写 CR2 的 ADON 位启动转换； PollForConversion 循环查 SR 寄存器的 EOC 位； GetValue 读 DR 寄存器并顺带清标志。
  • ((uint32_t)raw * 3300U) / 4095U—— 这个强制类型转换不是可选项。如果不写 (uint32_t)， C 语言会按 16 位做乘法，4095 × 3300 的结果被截断成低 16 位， 算出来的电压会是一个毫无规律的数。这是新手最常见的“算出来完全不对”的原因。
  • mv / 1000U 与 mv % 1000U—— 整数拆小数位的标准技巧。1650mV 拆成 1 和 650， 配合 %03u 补前导零打印成 1.650。 全程整数运算，比 printf("%.3f", v) 快得多， 在中断或高速循环里差别很明显。
  • HAL_ADC_PollForConversion(&hadc1, 10U) 里的 10U——超时时间。它的意义不在于“等 10ms”， 而在于“万一硬件有问题，程序还能活着走出去打印错误”。 所有 HAL 的阻塞调用都应该给一个有限超时，这是嵌入式代码的基本素养。
  • #define VREF_V 3.3f——把参考电压写成宏而不是散落在各处的 3.3，是为了以后标定时只改一个地方。 当你发现读数系统性偏低 1.5% 时，把这里改成实测的 VDDA 值就全部修正了。

多通道扫描为什么要配 DMA

下面这段代码演示了“同时采集 PA0 和 PA1 两个通道”的写法。注意看 HAL_ADC_Start_DMA 的第三个参数： 它是要搬运的数据个数， 这里等于通道数，DMA 就会把每个通道的结果依次写进数组的不同元素里。 

/* ---------------------------------------------------------------------
 * CubeMX 相对单通道要额外改三处：
 *   ADC1 → Scan Conversion Mode       = Enabled
 *          Number Of Conversion       = 2
 *          Rank 1: Channel = ADC_IN0（PA0），Sampling Time = 71.5 Cycles
 *          Rank 2: Channel = ADC_IN1（PA1），Sampling Time = 71.5 Cycles
 *          Continuous Conversion Mode = Enabled   （让 DMA 连续搬，不用反复启动）
 *   ADC1 → DMA Settings → Add → ADC1
 *          Mode      = Circular      （循环模式，缓冲区满了自动从头再来）
 *          Data Width= Half Word / Half Word（ADC 是 12 位，用 16 位刚好）
 *   DMA1 Channel1 的 NVIC 中断可以不开，纯搬运不需要 CPU 介入
 * ------------------------------------------------------------------- */

/* 缓冲区：每个通道一个 uint16_t，必须和通道数一样大 */
uint16_t g_adc_dma_buf[2] = { 0 };   /* [0] = PA0，[1] = PA1 */

/* 启动：第三个参数是“要搬运多少个数据”，单位是数据个数而不是字节数。
 * 传 2 表示搬 2 个 uint16_t，正好把两个通道各搬一次。
 * 传错了（比如传成 4）会导致 DMA 越界写到数组外面，把别的变量踩坏。 */
HAL_ADC_Start_DMA(&hadc1, (uint32_t *)g_adc_dma_buf, 2U);

/* 之后主循环里随时读数组即可，DMA 会在后台不断刷新它。
 * 因为是 Circular 模式，不需要重新调用 Start。 */
while (1)
{
    /* volatile 提醒：这两个变量是被 DMA 硬件改写的，
     * 编译器不能把它们缓存进寄存器。
     * 严谨的写法是在定义时加 volatile，这里为了简短只在注释里说明。 */
    printf("PA0 = %4u, PA1 = %4u\r\n",
           g_adc_dma_buf[0], g_adc_dma_buf[1]);
    HAL_Delay(200);
}

/* ---------------------------------------------------------------------
 * 停止采集用 HAL_ADC_Stop_DMA(&hadc1);
 * ------------------------------------------------------------------- */
DMA 缓冲区一定要加 volatile

在被 DMA 或中断改写的变量上加 volatile 不是可选的。 编译器看到主循环里没有代码修改 g_adc_dma_buf， 可能会“聪明地”把它优化成只读一次内存，于是你永远看到同一个旧值。 正确写法： volatile uint16_t g_adc_dma_buf[2];

现象演示说明

烧录完成后打开串口助手（波特率 115200）， 应该立刻看到开机信息，随后每 500ms 冒出一行数据。 下面这张表把“你看到的”和“它说明什么”对应起来，用来做自查。

正确现象

  1. 上电后第一行是 STM32F103 ADC1 demo start, VREF = 3.30V，说明串口通了。
  2. 之后每 500ms 出现一行 RAW = xxxx V = x.xxx V。
  3. 电位器拧到最小（滑臂到 GND）时，RAW 接近 0，电压显示 0.000V 附近。
  4. 电位器拧到最大（滑臂到 3.3V）时，RAW 接近 4095，电压显示约 3.29V。
  5. 缓慢旋转电位器，RAW 和电压值应该单调、平滑地跟着变，中间任何位置都不跳变。
  6. 把手离开电位器不动时，RAW 的波动应该在 ±3 个数以内（约 ±2.4mV）。

观察点与判据

你观察到的 说明什么 下一步查什么
RAW 始终是 0，电压也是 0 PA1 没有真正接到信号，或引脚没被配成模拟输入 万用表量 PA1 对 GND 的电压；CubeMX 里确认 PA1 显示为 ADC1_IN1 且是绿色
RAW 一直接近 4095 且不随电位器变化 PA1 上有个高于 3.3V 的电压，或引脚悬空被拉高 立刻断电量 PA1 电压；检查电位器两端是不是接到了 5V 排针上
RAW 在 0 和 4095 之间乱跳 典型的地没共，或信号线太长拾取了干扰 把电位器 GND 与单片机 GND 直接连一根短粗线；在 PA1 对地并一个 100nF 电容
读数规律地比万用表低 5%~15% 采样时间太短，采样电容没充满 把 Rank 1 的 Sampling Time 从 1.5 改到 71.5 周期，重新生成代码
读数整体偏低 1%~2% 且非常稳定 不是噪声问题，是参考电压假设值不准 万用表量 VDDA 真实值，改 VREF_V 宏；或做标定
最大只能到 3.29V，到不了 3.30V 这是正常的，4095 对应的是 4095/4096 倍参考电压 无需处理，这 0.8mV 的差就是 1 个 LSB
串口全是乱码 波特率不一致，或晶振没起振导致主频不是 72MHz 串口助手改成 115200；确认 RCC 选了外部晶振而不是内部 RC
顺手记录实验数据

做课设或报告时，建议做一个“三点标定”记录： 分别把电位器拧到低、中、高三个位置，记录 万用表读数、ADC 原始值、程序换算值三列。 然后算一下相对误差 (程序值 − 万用表值) / 万用表值。 如果三个点的误差方向一致、大小接近，就说明是系统误差（参考电压不准）， 可以乘一个修正系数修掉；如果误差忽正忽负，那才是噪声，要靠滤波解决。 能分清这两类误差，是从“会抄代码”到“会做测量”的分水岭。

常见报错排查方案

下面五条按“报错原文 / 现象 → 原因 → 解决”来写，方便你直接搜索比对。

现象：程序卡死在 HAL_ADC_PollForConversion，串口一行字都不打印

原因：ADC 根本没在转换，EOC 永远不会置位。最常见的三种情形是——忘了调用 HAL_ADC_Start 就直接轮询；MX_ADC1_Init() 没被调用（CubeMX 里勾了但 main 里没生成）；或者超时参数写成了 HAL_MAX_DELAY，把“卡住”变成了“永久卡住”。

解决：先检查 main() 里三个 MX_xxx_Init() 的顺序和拼写；再把超时改成 10U，让函数能返回错误；在 HAL_ADC_Start 之后加一句 if (HAL_ADC_Start(&hadc1) != HAL_OK) { printf("start fail\r\n"); } 把问题暴露出来。另外确认 ADC 的时钟预分频已经设过——ADCCLK 没配置时 ADC 不会工作。

现象：读数永远是 0 或者永远接近 4095，转动电位器毫无反应

原因：引脚模式不对。用 CubeMX 配置 ADC 通道时，对应引脚会自动变成模拟模式；但如果你是手动改代码、或者在 GPIO 页里把 PA1 又配成了输入/输出，两种配置会打架——GPIO 配置后执行会覆盖掉 ADC 的模拟模式。另一个常见原因是电位器接成了“变阻”而不是“分压”，滑臂悬空或直接落在电源上。

解决：CubeMX 里 Pinout view 中确认 PA1 显示的是 ADC1_IN1 而不是 GPIO_Input；生成代码后检查 MX_GPIO_Init() 里没有出现 GPIO_PIN_1 的重复配置。硬件上把电位器两端分别接 3.3V 和 GND，量一下滑臂对 GND 是不是 0~3.3V 平滑变化。

现象：编译通过，但算出来的电压是 200 多伏这种离谱值

原因：16 位整数溢出。raw * 3300 里 raw 是 uint16_t，C 语言会按 16 位运算，4095 × 3300 = 13,513,500 超出 65535，高位被丢掉，剩下的余数再除以 4095 就得到一个随机数。

解决：把中间变量强制提升到 32 位： mv = ((uint32_t)raw * 3300U) / 4095U;。 记忆口诀：先转类型，再相乘；先乘后除，精度不丢。

现象：读数在小范围内持续抖动，末位一直闪，稳定不了

原因：三类噪声叠加——电源纹波（USB 供电尤其明显）、信号源内阻偏高导致采样不足、以及 ADC 本身的量化噪声（±1 LSB 是物理上无法消除的）。注意最后一位本来就会跳，这是 12 位 ADC 的正常表现，不是故障。

解决：按性价比排序做三件事：① 在 PA1 与 GND 之间并一个 100nF 陶瓷电容，尽量靠近引脚；② 把采样时间从 1.5/7.5 改到 71.5 周期；③ 连续采 16 次求和再右移 4 位（相当于除以 16），噪声会按 √16 = 4 倍下降。做完这三步，抖动通常能压到 ±2 个码值以内。

现象：多通道扫描时，两个通道读出来几乎一样，或者只有第一个通道对

原因：没开 DMA。扫描模式下所有规则通道共用同一个数据寄存器 DR，ADC 按顺序采完通道 1 就覆盖 DR，接着采通道 2 又覆盖一次。CPU 只读一次的话，读到的永远是最后那个通道的值；如果开的是中断而中断响应不及时，就会读到串位的值。

解决：在 CubeMX 的 ADC1 → DMA Settings 里 Add 一条 DMA 请求，Mode 选 Circular，数据宽度选 Half Word；然后用 HAL_ADC_Start_DMA(&hadc1, (uint32_t *)buf, 通道数) 启动。记得给缓冲区加 volatile，否则编译器优化后你看到的还是旧值。

小结与练习

这一篇把 ADC 从里到外走了一遍。真正需要带走的结论只有四条： 逐次逼近靠 12 次二分查找完成转换； 电压 = 码值 × 3.3 / 4095，1 LSB 约 0.8mV； ADCCLK 必须 ≤ 14MHz，72MHz 的 APB2 只能选 /6 或 /8； 以及采样时间要跟信号源内阻匹配，宁慢勿偏。

再补一句工程判断：什么时候用轮询、什么时候必须上 DMA？ 判断标准不是“哪个高级”，而是 “转换结果会不会在 CPU 取走之前被覆盖”。 单通道单次转换，中间隔了 500ms，怎么都不会被覆盖，轮询最省事； 多通道扫描或连续高速采样，两个结果之间只隔几微秒，就必须交给 DMA。

动手练习
  1. 加一个自己算出来的阈值判断。 让程序在电压超过 2.0V 时打印 OVER，低于 1.0V 时打印 LOW。 注意比较要用毫伏整数（2000 / 1000），别引入浮点。 想一想：如果阈值是 2.05V，用毫伏表示是多少？（答案：2050）
  2. 做一次三点标定实验。 用万用表量电位器滑臂的真实电压，同时记录程序打印的值， 分别在低、中、高三个位置各记一组。 算出三组的相对误差，判断它属于系统误差还是随机误差， 然后试着把误差修掉（提示：改 VREF_V 宏，或者乘一个修正系数）。 这个实验做一遍，比读十页 ADC 原理都有用。
  3. 把轮询改成 DMA。 按 多通道扫描那一节的清单， 在 CubeMX 里加上 PA0 通道并开启 DMA，让两个通道同时采集并打印。 观察点：改成 DMA 之后，两个通道的值是不是都不串位了？ 如果你把 CubeMX 里的 DMA Mode 从 Circular 改成 Normal， 会看到什么现象？（提示：只搬一轮，数组不再更新）
