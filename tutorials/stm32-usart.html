原理介绍

USART 是 Universal Synchronous/Asynchronous Receiver/Transmitter （通用同步/异步收发器）的缩写。我们平时说的「串口」通常指它的 异步模式：通信双方没有共享的时钟线， 全靠事先约定好的节奏（波特率）各自采样。 正因为没有时钟线，异步串口只需要两根信号线—— 一根发、一根收，就能双向通信，这也是它成为调试首选接口的原因。

关键点在于「约定节奏」这四个字： 接收方必须知道发送方每一位持续多长时间。 这个时间就是波特率的倒数。所以串口通信的第一条纪律是： 两端波特率必须一致，而且这个波特率必须由准确的时钟分频出来。

一帧数据长什么样

异步串口是「面向位」的，它没有时钟线,也没有片选线,靠帧结构自己同步。 一帧数据由四段组成，从上到下依次是： 

        空闲（高电平）
   ────────┐            ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐           ┌────────
           └──┐  ┌───┐  │ D0│   │ D1│   │ D2│   │ D3│   │ D4│   │ D5│   │ D6│   │ D7│   ┌───┘
              │  │   │  └───┘   └───┘   └───┘   └───┘   └───┘   └───┘   └───┘   └───┘   │
              └──┘   └──────────────────────────────────────────────────────────────────┘
           起始位   数据位 D0~D7（LSB 先发，低位在前）                          停止位

  ① 起始位（1 位，低电平）：接收方检测到从高到低的下降沿，就知道「一帧开始了」，
     并从这一刻起启动自己的采样定时器
  ② 数据位（8 位或 9 位）：先发最低位 D0。发送 0x41（字符 'A'）时的位序是
     1 0 0 0 0 0 1 0（D0=1, D1=0 ... D6=1, D7=0）
  ③ 校验位（0 位或 1 位，可选）：奇校验/偶校验/无校验，用来发现单比特错误
  ④ 停止位（1 / 1.5 / 2 位，高电平）：把线拉回空闲态，也给接收方留一点处理时间

  注意：波特率算的是「位」的速率，不是字节。
  115200 波特率下，一个字节要发 10 位（1 起始 + 8 数据 + 1 停止），
  所以实际吞吐约 11520 字节/秒，而不是 115200 字节/秒。

采样是怎么做的？接收方在起始位的下降沿之后， 等 1.5 个位时间再采第一个数据位（正好落在第 0 位的正中间）， 之后每过一个位时间采一次。 STM32 的 USART 采用 16 倍过采样： 每个位时间里采 16 个点，最后取第 8、9、10 三个点的多数值作为这一位的值。 这样做的好处是能抗住一定程度的噪声和时钟误差。

波特率与时钟的关系

波特率不是凭空产生的，它由外设时钟分频得到。USART 的波特率寄存器 BRR 就是一个分频系数，公式是： 

             fCK
  USARTDIV = ───────────────
             16 × 波特率

  其中 fCK 是挂载该 USART 的总线时钟：
    USART1 挂在 APB2 → fCK = PCLK2 = 72MHz
    USART2/3 挂在 APB1 → fCK = PCLK1 = 36MHz

  BRR 寄存器是「定点数」格式：
    高 12 位 = 整数部分（Mantissa）
    低 4 位  = 小数部分（Fraction），以 1/16 为单位

  以 72MHz、115200 波特率为例：
    USARTDIV = 72000000 / (16 × 115200) = 39.0625
    整数部分 39  → 39 = 0x27
    小数部分 0.0625 × 16 = 1
    所以 BRR = 0x271，CubeMX 生成的代码里 BaudRate = 115200 会被自动算成这个值

  误差 = |实际波特率 − 目标波特率| / 目标波特率，一般要求小于 2%~3%

把常用波特率在 72MHz 下算一遍，你会看到一个很舒服的结果——误差全是 0：

波特率 USARTDIV（72MHz 时） BRR 值 实际误差
9600468.750x1D4C0%
19200234.3750x0EA60%
38400117.18750x07530%
5760078.1250x04E20%
11520039.06250x02710%

这就是为什么 STM32F1 的经典配置是「8MHz 晶振 × 9 = 72MHz」： 72MHz 能被这些标准波特率整除到小数点后正好 4 位二进制小数， 硬件分频不产生任何累积误差。反过来说， 如果你的板子实际跑在 8MHz（HSE 没起振，回退到内部 HSI）， BRR 仍按 72MHz 算，实际波特率就只有目标的九分之一，收下来必然全是乱码。

为什么波特率不对就全是乱码

这是新手最常问的问题：明明「只差一点点」，为什么不是偶尔错一个字符，而是干脆整段乱码？ 因为误差是逐位累积的，不是一次性偏移：

位序 接收方采样时刻 若波特率偏大 5%（接收方节奏偏慢）时的偏移量
起始位检测下降沿0（同步点，没有误差）
D01.5 位时间处0.075 位（还在位中间，采对）
D45.5 位时间处0.275 位（仍能采对）
D78.5 位时间处0.425 位（接近位边界，开始危险）
停止位9.5 位时间处0.475 位（采到相邻位，报帧错误）
偏移量 = 采样点位序 × 相对误差。误差超过约 5% 时，最后几位就会越过位边界，采到相邻位的电平 → 数据位整体错位，解码结果变成一个稳定的错误字符（这就是「乱码」）。

两点结论： ① 停止位的作用之一就是给累积误差兜底—— 它固定为高电平，一旦采样到低电平就能立刻判定「这帧错了」，硬件会置位帧错误标志 FE； ② 波特率不一致时收到的字符往往是固定且重复的错误字符， 比如 115200 发、9600 收，你会看到一串很规律的乱码而不是随机噪声。 反过来，如果乱码看起来完全随机、每次都不一样，那更可能是接线或电平问题，不是波特率。

看乱码就能定位问题的方向
  • 固定重复的乱码——两端设置的波特率不一致（或单片机时钟不是你以为的那个值）。
  • 完全随机、每次不同的乱码——TX/RX 没交叉、地线没接、信号线虚接、或者电平不匹配。
  • 只错个别字符——波特率误差在临界值附近，或者线太长、有干扰。这种情况在实验室的杜邦线上很常见。

阻塞收发的用法与超时参数

HAL 提供了两种收发方式：阻塞（轮询）和 中断。先看阻塞的两个 API 原型： 

/* 发送：把 pData 指向的 Size 个字节全部发出去，直到最后一个字节移出移位寄存器才返回 */
HAL_StatusTypeDef HAL_UART_Transmit(UART_HandleTypeDef *huart,
                                    const uint8_t *pData,
                                    uint16_t Size,
                                    uint32_t Timeout);   /* 单位：毫秒 */

/* 接收：阻塞等待，直到收满 Size 个字节，或者超时 */
HAL_StatusTypeDef HAL_UART_Receive(UART_HandleTypeDef *huart,
                                   uint8_t *pData,
                                   uint16_t Size,
                                   uint32_t Timeout);

/* 返回值：
 *   HAL_OK      —— 成功
 *   HAL_TIMEOUT —— 超时（接收时最常见：对方没发够 Size 个字节）
 *   HAL_BUSY    —— 外设正忙（上一次传输还没结束）
 *   HAL_ERROR   —— 硬件错误（校验错、帧错、噪声标志被置位）
 *
 * Timeout 怎么填：
 *   - HAL_MAX_DELAY —— 无限等待，一直到成功为止
 *   - 具体毫秒数   —— 比如 100 表示最多等 100ms
 *   注意：超时的判定依赖 HAL_GetTick()，也就是依赖 SysTick 1ms 中断。
 *   如果没调 HAL_Init()，超时会立刻触发。
 *
 * 致命限制：阻塞函数会占住 CPU 空转等硬件。
 *   115200 波特率下发 100 个字节要 8.7ms，这 8.7ms 里主循环完全停住。
 *   发数据可以忍，收数据绝对不能忍——所以接收一律用中断方式。

中断接收与回调：为什么必须在回调里重新开启接收

中断接收的入口只有一行： 

/* 启动中断接收：告诉 HAL「我要收 Size 个字节，收到就通知我」
 * 这个函数本身立刻返回，不阻塞主循环 */
HAL_UART_Receive_IT(&huart1, &rx_byte, 1);   /* 收 1 个字节就触发一次回调 */

/* 收满 Size 个字节后，HAL 会自动调用这个弱函数（weak function）。
 * 它在 stm32f1xx_hal_uart.c 里有一个空实现，
 * 你在自己的代码里重新定义一个同名函数，就会覆盖掉它 —— 这叫「回调」 */
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
  if (huart->Instance == USART1)            /* 先判断是不是 USART1 触发的 */
  {
    /* ★★★ 关键：在这里必须重新开启下一次接收 ★★★
     * 因为 HAL_UART_Receive_IT 是「一次性」的：
     * 收满 1 个字节后，HAL 内部会把接收状态复位、
     * 关掉 RXNE 中断，然后才调用回调。
     * 如果回调里不再调一次 HAL_UART_Receive_IT，
     * 接收就永远停在这里 —— 现象是「只收到第一个字符，后面再发都没反应」。 */
    HAL_UART_Receive_IT(&huart1, &rx_byte, 1);
  }
}
两个必须记住的细节
  • 接收缓冲区必须是全局变量或静态变量，不能是局部变量。 因为 HAL_UART_Receive_IT() 只保存了指针， 等回调发生时函数早已返回、栈上的局部变量已经失效——数据会写到一片垃圾内存里。 这是个「有时候能用、有时候莫名死机」的隐蔽 bug。
  • 回调的运行环境是中断。所以回调里只做最轻的事：存数据、置标志、重新开启接收。 千万不要在里面 HAL_Delay()、不要 printf() 大段内容、 不要做浮点运算——业务逻辑全部放回主循环处理。

还有一种情况会让接收「卡死」：溢出错误（ORE）。 如果上一帧还没被取走、下一帧又到了，硬件会置位 ORE 标志。 这个标志一旦置位且没被清除，RXNE 中断就不再产生，接收彻底停止。 稳妥的做法是实现错误回调，在里面清标志并重新开启接收： 

/* 收到错误（溢出 ORE / 帧错 FE / 噪声 NE / 校验错 PE）时 HAL 会调用它 */
void HAL_UART_ErrorCallback(UART_HandleTypeDef *huart)
{
  if (huart->Instance == USART1)
  {
    /* 读 SR 再读 DR 可以清掉 ORE/RXNE/FE/NE/PE 这几个标志，
     * HAL 提供了现成的宏，省得自己查手册 */
    __HAL_UART_CLEAR_OREFLAG(huart);

    /* 错误处理后必须重新开启接收，否则外设停在错误状态不再收数据 */
    HAL_UART_Receive_IT(&huart1, &rx_byte, 1);
  }
}

printf 重定向到串口

C 语言的 printf() 最终会把每个字符交给一个叫 fputc() 的底层函数输出。C 库提供的是弱符号， 我们只要定义自己的 fputc()，把字符塞进串口发送函数， 就完成了「printf 打到串口」的重定向——这就是所谓「重定向」的全部含义。 

#include <stdio.h>        /* printf / fputc 的声明都在这里，必须包含 */

/* 重定向 printf 到 USART1。
 * 参数说明：
 *   ch —— 要输出的那一个字符（注意：标准库传进来的是 int）
 *   f  —— 文件流指针，标准库会传 stdout，我们不用管它
 * 返回值——按惯例返回写出去的字符本身 */
int fputc(int ch, FILE *f)
{
  /* 把 ch 转成 uint8_t 指针，发 1 个字节。
   * 这里用 HAL_MAX_DELAY：调试打印宁可慢一点，也不能因为超时丢字符，
   * 否则你会看到 printf 输出的字符串缺字，反而更难排查 */
  HAL_UART_Transmit(&huart1, (uint8_t *)&ch, 1, HAL_MAX_DELAY);
  return ch;
}

/* 顺带把 scanf 也接过来（可选）。不实现它，只要不用 scanf 就不会报错 */
int fgetc(FILE *f)
{
  uint8_t ch = 0;
  HAL_UART_Receive(&huart1, &ch, 1, HAL_MAX_DELAY);
  return (int)ch;
}
Keil 里必须勾上 Use MicroLIB

Keil 默认的标准库依赖「半主机（semihosting）」机制—— 它会把 printf 的输出重定向到调试器的控制台，而不是你的串口。 未勾选时最常见的报错是 Error: L6915E: Library reports error: __use_no_semihosting was requested, but _ttywrch was referenced。 解决办法：Options for Target → Target → 勾选 Use MicroLIB。 MicroLIB 是 ARM 专门为裸机做的精简 C 库，不依赖操作系统，正好适合我们。

如果因为其他原因不能勾（比如用了需要标准库的功能）， 就得手动禁用半主机，代价是要自己补桩函数，见排错一节。

硬件接线说明

蓝药丸本身没有 USB 转串口芯片，所以需要一个 USB-TTL 模块 （常见芯片是 CH340、CP2102、PL2303）把 USB 转成 TTL 电平的串口。 这个模块和单片机之间只有三根线是必须的： TX 交叉接 RX、RX 交叉接 TX、GND 接 GND。

USB-TTL 与蓝药丸接线表

USB-TTL 模块引脚 蓝药丸引脚 是否必须 说明
TXD（模块的发送脚） PA10（USART1_RX） 必须 交叉：模块发、单片机收。接成 PA9 就成了「两端都在发」，谁也收不到
RXD（模块的接收脚） PA9（USART1_TX） 必须 交叉：单片机发、模块收。只做单向打印时，这三根里的这一根也不能省——否则你发了也看不到
GND GND 必须 共地。两边的电平必须有同一个参考点，否则串口助手会收到乱码或全 0
3V3 3V3 可选 给板子供电。蓝药丸已插 USB 时不要接，避免两路电源倒灌
5V 5V 不接 调试阶段不需要从模块的 5V 给板子供电
模块上的 3.3V/5V 跳线 — 建议 选 3.3V 档。PA9/PA10 虽然标着 FT（耐 5V），但整板其他引脚不耐 5V，统一 3.3V 最稳

上电前必查
  • TX/RX 是否交叉。这是串口调试排名第一的错误。判断口诀：模块的 TX 接单片机的 RX，因为 TX 是「发送」端，要送到对方的「接收」端。
  • GND 是否连上。只接两根信号线、不接地线，有时能收到几个字符，但更多时候是乱码。地线是电气参考，不是「可选的第二根电源线」。
  • 别把 5V 接到 PA9/PA10 之外的地方。模块如果有 5V 引脚，不要顺手接到板子的任意引脚上——很多引脚不耐 5V。
  • 串口助手不要和下载软件抢串口。如果用的是「USB-TTL 冒充 ST-Link」之外的方案（比如串口下载），下载时串口助手必须关掉，否则会报「串口被占用」。

完整代码

这份代码做三件事： ① 上电后用 printf 打印一段开机横幅；② 主循环每 1 秒打印一次运行计数； ③ 中断接收：你从串口助手发的每个字符都会被原样回显（echo）。 这样就同时覆盖了 printf 重定向和 HAL_UART_Receive_IT 两条主线。

关于工程文件的一点说明

下面这份 main.c 把 USART1 的句柄 huart1 和初始化函数 MX_USART1_UART_Init() 都写在了一起，方便独立阅读。 如果你是用 CubeMX 生成的工程，huart1 默认定义在 usart.c 里，直接粘贴会出现 Symbol huart1 multiply defined 的链接错误—— 这时把工程里的 usart.c 移除（或删掉其中重复的定义）即可。 PA9/PA10 的复用功能配置由 CubeMX 生成在 stm32f1xx_hal_msp.c 的 HAL_UART_MspInit() 里 （老版本 CubeMX 会放在 usart.c），这段不用你操心。 

#ifndef __MAIN_H
#define __MAIN_H

#include "stm32f1xx_hal.h"

/* 串口句柄：在 main.c 里定义，这里用 extern 声明，
 * 好让 stm32f1xx_it.c 里的 USART1_IRQHandler() 也能引用它 */
extern UART_HandleTypeDef huart1;

void Error_Handler(void);

#endif /* __MAIN_H */
/* ============================================================================
 * main.c —— STM32F103C8T6 USART1 串口通信示例
 * 功能：
 *   ① 上电打印开机横幅
 *   ② 主循环每秒打印一次运行计数（演示 printf 重定向）
 *   ③ 中断接收：串口助手发来的每个字符原样回显（演示 HAL_UART_Receive_IT）
 * 硬件：USB-TTL 的 TXD → PA10，RXD → PA9，GND → GND
 * 串口参数：115200, 8 数据位, 无校验, 1 停止位
 * ============================================================================ */

#include "main.h"
#include <stdio.h>          /* printf / fputc 需要它（对应 USER CODE BEGIN Includes 区块） */

/* ------------------------------ 全局变量 ------------------------------ */
UART_HandleTypeDef huart1;     /* USART1 句柄：在 main.h 里已声明为 extern 供中断文件使用 */

/* ★ 接收缓冲区必须是全局变量：
 * HAL_UART_Receive_IT() 只保存指针，回调发生时局部变量早已失效 */
uint8_t rx_byte = 0;           /* 每收到一个字节就存在这里 */
volatile uint8_t rx_flag = 0;  /* volatile 告诉编译器「这个变量会被中断改」，禁止优化掉 */

/* ------------------------------ 私有函数声明 ------------------------------ */
void SystemClock_Config(void);
static void MX_GPIO_Init(void);
static void MX_USART1_UART_Init(void);
void Error_Handler(void);

/* ============================================================================
 * main()：程序入口
 * ============================================================================ */
int main(void)
{
  uint32_t counter = 0;        /* 运行计数，每秒加一 */

  HAL_Init();                  /* 初始化 HAL：Flash 等待周期 + SysTick 1ms 中断 */
  SystemClock_Config();        /* 时钟 72MHz：这直接决定了波特率能不能算准 */
  MX_GPIO_Init();              /* 顺手初始化 GPIOC，方便接 LED 做状态指示 */
  MX_USART1_UART_Init();       /* 初始化 USART1：115200-8-N-1 */

  /* ---------- 第一次开启中断接收。注意：这里只是「上一次」，
   *            之后每次收完都要在回调里重新开启 ---------- */
  HAL_UART_Receive_IT(&huart1, &rx_byte, 1);

  printf("\r\n====================================\r\n");
  printf(" McuStudy STM32F103C8T6 USART1 Demo\r\n");
  printf(" Baudrate: 115200  8-N-1\r\n");
  printf(" 输入任意字符，会被原样回显\r\n");
  printf("====================================\r\n");

  while (1)
  {
    if (rx_flag == 1)                       /* 中断收到一个字节，置了标志 */
    {
      rx_flag = 0;                          /* 先清标志，再处理数据 */

      printf("收到字符：%c  (HEX: 0x%02X)\r\n", rx_byte, rx_byte);

      /* 回显：把你发的字符原样发回去。用阻塞发送没问题——
       * 主循环里发 1 个字节只需要约 87us，不会影响什么 */
      HAL_UART_Transmit(&huart1, &rx_byte, 1, 100);
    }

    /* 每秒打印一次计数，作为「程序还活着」的心跳 */
    printf("运行中... 计数 = %lu\r\n", counter);
    counter++;
    HAL_Delay(1000);
  }
}

/* ============================================================================
 * USART1 初始化：115200-8-N-1
 * ★ 时钟使能在 HAL_UART_MspInit() 里已经做了一遍（CubeMX 自动生成），
 *   这里再开一次是幂等的，不会重复配置，只是让本文件更自解释
 * ============================================================================ */
static void MX_USART1_UART_Init(void)
{
  __HAL_RCC_USART1_CLK_ENABLE();        /* USART1 挂在 APB2 上 */

  huart1.Instance          = USART1;                  /* 用哪个 USART 外设 */
  huart1.Init.BaudRate     = 115200;                  /* 波特率：两端的这一项必须完全一致 */

  huart1.Init.WordLength   = UART_WORDLENGTH_8B;      /* 数据位 8 位 */
  huart1.Init.StopBits     = UART_STOPBITS_1;         /* 停止位 1 位 */
  huart1.Init.Parity       = UART_PARITY_NONE;        /* 无校验 */
  huart1.Init.Mode         = UART_MODE_TX_RX;         /* 收发都要用 */
  huart1.Init.HwFlowCtl    = UART_HWCONTROL_NONE;     /* 不用硬件流控（RTS/CTS），三线制够用 */
  huart1.Init.OverSampling = UART_OVERSAMPLING_16;    /* 16 倍过采样，抗噪能力最好 */

  if (HAL_UART_Init(&huart1) != HAL_OK)
  {
    Error_Handler();          /* 初始化失败：通常是波特率算不出来（时钟不对）或引脚被占用 */
  }
}

/* ============================================================================
 * printf 重定向：把 C 库的 fputc 换成「往 USART1 发一个字节」
 * 记得在 Keil 里勾选 Target → Use MicroLIB
 * ============================================================================ */
int fputc(int ch, FILE *f)
{
  /* HAL_MAX_DELAY 表示无限等待。调试打印宁可慢一点，也不要丢字符 */
  HAL_UART_Transmit(&huart1, (uint8_t *)&ch, 1, HAL_MAX_DELAY);
  return ch;
}

/* ============================================================================
 * 中断接收完成回调
 * 收满 1 个字节后由 HAL 自动调用（它在中断上下文里执行）
 * ★★★ 必须在这里重新开启接收，否则只能收到第一个字符 ★★★
 * ============================================================================ */
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
  if (huart->Instance == USART1)              /* 工程里还有别的串口时，务必先判断来源 */
  {
    rx_flag = 1;                              /* 只置标志，把耗时的工作留给主循环 */

    /* 重新武装：不开这一句，接收就永久停在这里 */
    HAL_UART_Receive_IT(&huart1, &rx_byte, 1);
  }
}

/* ============================================================================
 * 错误回调：处理溢出等异常，防止接收永久卡死
 * ============================================================================ */
void HAL_UART_ErrorCallback(UART_HandleTypeDef *huart)
{
  if (huart->Instance == USART1)
  {
    __HAL_UART_CLEAR_OREFLAG(huart);          /* 清溢出标志（读 SR 再读 DR 的封装） */
    HAL_UART_Receive_IT(&huart1, &rx_byte, 1);/* 重新开启接收 */
  }
}

/* ============================================================================
 * GPIO 初始化：这里只开 GPIOC 的时钟，方便你后续把 PC13 接成状态灯
 * ============================================================================ */
static void MX_GPIO_Init(void)
{
  GPIO_InitTypeDef GPIO_InitStruct = {0};

  __HAL_RCC_GPIOC_CLK_ENABLE();               /* 不开时钟，后面写 PC13 全是无效操作 */

  HAL_GPIO_WritePin(GPIOC, GPIO_PIN_13, GPIO_PIN_SET);

  GPIO_InitStruct.Pin   = GPIO_PIN_13;
  GPIO_InitStruct.Mode  = GPIO_MODE_OUTPUT_PP;
  GPIO_InitStruct.Pull  = GPIO_NOPULL;
  GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;
  HAL_GPIO_Init(GPIOC, &GPIO_InitStruct);
}

/* ============================================================================
 * 时钟配置：HSE(8MHz) → PLL ×9 → SYSCLK = 72MHz
 * ★ 串口能不能通信，八成取决于这一段是否真的生效：
 *   如果 HSE 没起振、不小心回退到 8MHz 的 HSI，
 *   波特率就会差 9 倍，收下来全是乱码
 * ============================================================================ */
void SystemClock_Config(void)
{
  RCC_OscInitTypeDef RCC_OscInitStruct = {0};
  RCC_ClkInitTypeDef RCC_ClkInitStruct = {0};

  RCC_OscInitStruct.OscillatorType = RCC_OSCILLATORTYPE_HSE;
  RCC_OscInitStruct.HSEState       = RCC_HSE_ON;
  RCC_OscInitStruct.HSEPredivValue = RCC_HSE_PREDIV_DIV1;
  RCC_OscInitStruct.HSIState       = RCC_HSI_ON;
  RCC_OscInitStruct.PLL.PLLState   = RCC_PLL_ON;
  RCC_OscInitStruct.PLL.PLLSource  = RCC_PLLSOURCE_HSE;
  RCC_OscInitStruct.PLL.PLLMUL     = RCC_PLL_MUL9;          /* 8MHz × 9 = 72MHz */
  if (HAL_RCC_OscConfig(&RCC_OscInitStruct) != HAL_OK)
  {
    Error_Handler();
  }

  RCC_ClkInitStruct.ClockType = RCC_CLOCKTYPE_HCLK | RCC_CLOCKTYPE_SYSCLK
                              | RCC_CLOCKTYPE_PCLK1 | RCC_CLOCKTYPE_PCLK2;
  RCC_ClkInitStruct.SYSCLKSource   = RCC_SYSCLKSOURCE_PLLCLK;
  RCC_ClkInitStruct.AHBCLKDivider  = RCC_SYSCLK_DIV1;       /* HCLK  = 72MHz */
  RCC_ClkInitStruct.APB1CLKDivider = RCC_HCLK_DIV2;         /* PCLK1 = 36MHz */
  RCC_ClkInitStruct.APB2CLKDivider = RCC_HCLK_DIV1;         /* PCLK2 = 72MHz ← USART1 用它 */
  if (HAL_RCC_ClockConfig(&RCC_ClkInitStruct, FLASH_LATENCY_2) != HAL_OK)
  {
    Error_Handler();
  }
}

/* ============================================================================
 * 出错处理
 * ============================================================================ */
void Error_Handler(void)
{
  __disable_irq();
  while (1)
  {
  }
}
/* 如果你的工程因为其他原因不能勾 Use MicroLIB，
 * 就用下面这段禁用半主机。把它放在 main.c 的开头附近。
 * 报错原文通常是：
 *   Error: L6915E: Library reports error: __use_no_semihosting was requested,
 *          but _ttywrch was referenced */
#pragma import(__use_no_semihosting)    /* 告诉链接器：我不要半主机 */

struct __FILE { int handle; };          /* MicroLIB 之外的库需要一个 FILE 结构体 */
FILE __stdout;

void _sys_exit(int x) { x = x; }        /* 库要求的桩函数，实现留空即可 */
void _ttywrch(int ch)  { ch = ch; }

/* 有了这几行，再实现前面的 fputc()，printf 就能正常输出到串口了 */

关键代码解析

  • volatile uint8_t rx_flag——volatile 不是可有可无的修饰。 没有它，编译器看到主循环里没人改过 rx_flag， 就可能把它优化成「只读一次、后面一直用寄存器里的旧值」， 于是中断里明明置了 1，主循环却永远看不到。凡是「中断改、主循环读」的变量都要加 volatile。
  • if (huart->Instance == USART1)——回调是全局的， 只要任意一个串口收完数据都会进这个函数。项目里同时用了 USART1 和 USART2 时， 少了这句判断就会串口互相抢数据。
  • HAL_UART_Receive_IT(&huart1, &rx_byte, 1) 出现在三个地方： main() 里启动第一次，回调里重新武装，错误回调里恢复。 这三处缺一不可——「为什么只能收到一次」的答案就在这里。
  • printf("...%c...0x%02X...")——%02X 表示 「至少两位、不足补 0、大写十六进制」。用 HEX 一起打印能立刻区分 「收到的是乱码还是正常字符」：如果字符显示奇怪但 HEX 是 0x41，那其实是对的，只是编码显示问题。
  • \r\n——串口助手的「换行」需要回车（\r）+ 换行（\n）两个字符。 只写 \n 的话，有些串口助手会出现「新内容覆盖在同一行开头」的现象。
  • HAL_UART_Init() 内部会自动按当前 PCLK2 计算 BRR。 所以时钟配置必须发生在串口初始化之前——顺序反了，HAL 会按错误的总线频率算分频，现象正是乱码。

现象演示说明

正确现象

  1. 打开串口助手，选中 USB-TTL 对应的 COM 口，设置 115200-8-N-1，点「打开串口」。
  2. 按一下板子上的复位键，串口助手立刻收到开机横幅： McuStudy STM32F103C8T6 USART1 Demo 等四行文字，换行整齐。
  3. 之后每秒出现一行 运行中... 计数 = 0、= 1、= 2……数字递增，间隔稳定。
  4. 在串口助手的发送框里输入 A 并发送，立刻收到两行： 收到字符：A (HEX: 0x41) 和回显出来的一个 A。
  5. 连续发送 12345，会收到 5 组回显——不会只收到第一个字符，说明回调里的重新开启接收生效了。

观察点与判据

你观察到的 说明什么 下一步查什么
完全收不到任何字符 物理链路没通，或串口助手没打开对 查 COM 口选得对不对、TX/RX 是否交叉、GND 是否连上；把串口助手的显示模式切到 HEX，直接看有没有字节进来
收到的是固定重复的乱码（比如一串 锟斤拷 或规律符号） 两端波特率不一致，或单片机时钟不是 72MHz 先把串口助手改成 115200；再把 SystemCoreClock 加入 Watch 确认是 72000000
乱码完全随机，每次都不一样 不是波特率问题，而是电气问题 重点查地线（必须共地）、杜邦线是否松动、模块电平跳线是不是选错、周围有没有强干扰源
只收到第一个字符，后面发送无反应 HAL_UART_RxCpltCallback 里没有重新调用 HAL_UART_Receive_IT 补上那一行；顺便确认回调函数名拼写完全正确——写错了不会报错，只是永远不执行
每次只收到半行、或者字符串缺字 printf 与中断接收抢串口，或发送超时太短 把 fputc 里的超时改成 HAL_MAX_DELAY；检查是不是在主循环和回调里同时往串口写数据
程序在收到数据后死机 回调里做了耗时操作（延时、大量打印），或者触发了溢出错误没被处理 回调里只置标志；确认实现了 HAL_UART_ErrorCallback 并清除 ORE 标志
顺手记录实验数据

用手机秒表量 10 行 运行中... 的总耗时，除以 10， 应等于 1000ms；再算一下单字节发送时间： 10 位 ÷ 115200 = 86.8µs， 用这个数可以估算「打印 40 个字符的一行大约占用 3.5ms」。 这种量化估算在写实训报告、评估通信负载时非常有用， 也是面试里「你怎么评估串口占用率」这类问题的标准答法。

常见报错排查方案

串口这一篇的排错思路很特别：先分清「乱码」和「收不到」是两类完全不同的问题， 再用现象反推是时钟、配置、接线还是代码。下面五条按出现频率排序。

现象：串口助手收到的全是乱码（固定重复的那种）

原因：收发两端波特率不一致。对 STM32 来说还有一层隐藏原因—— 代码里写的是 115200，但实际时钟不是 72MHz（HSE 没起振，HAL 回退到内部 HSI 8MHz）， 于是 BRR 的分频基准错了，实际波特率只有设定值的九分之一。

解决：① 串口助手设成 115200-8-N-1，和代码一致； ② 在 Debug 的 Watch 窗口加入 SystemCoreClock，确认是 72000000，不是 8000000； ③ 确认 SystemClock_Config() 在 MX_USART1_UART_Init() 之前调用—— 顺序反了，HAL 会按错误的总线频率算分频。

现象：只收到第一个字符，之后再发什么都没反应

原因：HAL_UART_Receive_IT() 是一次性的。 收满指定长度后，HAL 会复位接收状态、关闭 RXNE 中断，然后才调用回调。 如果回调里没有重新调用它，接收就永久停在那里。

解决：在 HAL_UART_RxCpltCallback() 的最后 重新调用一次 HAL_UART_Receive_IT(&huart1, &rx_byte, 1)。 如果补上后仍然只有一次，检查两件事：回调函数名是否与 HAL 定义的完全一致； stm32f1xx_it.c 里的 USART1_IRQHandler() 有没有调用 HAL_UART_IRQHandler(&huart1)（CubeMX 生成的工程里默认有）。

编译报错：Error: L6915E: Library reports error: __use_no_semihosting was requested, but _ttywrch was referenced

原因：使用了 Keil 的标准 C 库，而标准库默认依赖「半主机」机制（把 printf 输出到调试器控制台）。裸机环境里没有操作系统提供这套机制，链接器于是报错。

解决：Options for Target → Target 勾选 Use MicroLIB，重新编译即可。 如果因为其他原因不能勾（例如用了需要完整标准库的特性），就在 main.c 里补上禁用半主机的桩函数： #pragma import(__use_no_semihosting) 加上空的 _sys_exit()、_ttywrch() 实现。

编译报错：Error: L6200E: Symbol huart1 multiply defined (by usart.o and main.o)

原因：把本教程的 main.c 直接粘进了 CubeMX 生成的工程，而工程里的 usart.c 也定义了 huart1，同一个全局变量被定义了两遍。链接器不知道该用哪一个。

解决：只保留一份定义。要么把工程里的 usart.c 从工程中移除 （右键文件 → Remove File），要么把 main.c 里的 UART_HandleTypeDef huart1; 删掉、 改回用 usart.h 提供的 extern 声明。 相应的初始化函数也要保留一份，不能两边都有 MX_USART1_UART_Init()。

现象：收不到任何数据，但代码和接线看起来都对

原因：按可能性排序——① TX/RX 没交叉（模块 TX 接到了 PA9，两端都在发）；② 没有共地； ③ 串口助手选的 COM 口不是 USB-TTL 那一个（电脑上常有多个虚拟串口）； ④ 串口助手的波特率虽然对了，但数据位/停止位/校验位设错； ⑤ USB-TTL 模块的驱动没装，设备管理器里根本没有 COM 口。

解决：最快的一招是把模块的 TX 和 RX 两根线对调一下再试—— 这是排查交叉问题最直接的办法。其次打开 Windows 设备管理器，插拔模块看哪个 COM 口在增减； 最后把串口助手的显示模式切成 HEX，如果能看到一堆 00 或固定字节， 说明线路是通的、只是参数不对。

另外一类：一收到数据就死机

现象是串口助手发一个字符，板子就再也不响应了（连每秒的心跳都没了）。 原因几乎都是在回调里做了不该做的事：调用 HAL_Delay()、 大段 printf()、或者死等某个标志。 回调运行在中断上下文里，一旦它长时间不返回，主循环就彻底停摆； 如果它还等待 SysTick 计数，就是永久死锁。 解决：回调里只做「存数据 + 置标志 + 重新开接收」三件事， 所有打印和处理逻辑搬回主循环。

小结与练习

串口是嵌入式开发里最万能的调试手段：学会它，你就能「看见」程序内部发生了什么。 这一篇需要带走的结论有五条：

  • 一帧 = 起始位 + 8 数据位（LSB 先）+ 可选校验 + 停止位，波特率算的是位速率，一个字节约 10 位。
  • BRR = fCK / (16 × 波特率)，整数部分占高 12 位、小数占低 4 位；72MHz 下标准波特率误差为 0。
  • 误差逐位累积——这就是「差一点就整段乱码」的原因，容忍度大约 2%~3%。
  • 中断接收是一次性的，回调里必须重新 HAL_UART_Receive_IT()，缓冲区必须是全局变量。
  • TX/RX 交叉 + 共地，这是三线制串口能通的全部硬件条件。
动手练习
  1. 故意制造乱码：把串口助手的波特率改成 9600（代码不变），观察收到的是什么； 再改成 115200 确认恢复正常。把两次的乱码截图对比一下， 体会「固定重复的乱码」和「随机乱码」的区别——这是以后一眼定位问题的关键经验。
  2. 做一个命令行小灯：让串口接收 '1' 时点亮 PC13、 接收 '0' 时熄灭，并回显 LED ON / LED OFF。 提示——在回调里把 rx_byte 存进一个环形缓冲区会比只存一个字节更实用， 但先按「存一个字节 + 置标志」的方式做出来，再考虑升级。
  3. 对比两种接收方式的差异：把中断接收换成阻塞式的 HAL_UART_Receive(&huart1, &rx_byte, 1, 100)， 观察每秒的心跳打印是否还准时。想清楚为什么工程代码里几乎不用阻塞接收， 以及什么场景下阻塞接收反而更合适。
