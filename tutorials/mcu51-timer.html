定时器原理与定时

上一篇的软件延时只能当「模糊节拍」，这一篇把它换成硬件定时。 核心只有一句话：定时器就是一个自动数机器周期的计数器，数满了就通知 CPU 一声。 学会它，你就能得到与代码写法无关的精确时间——数码管扫描、串口波特率、红外解码、电机调速全都建立在这上面。

原理介绍

上一篇的 Delay_ms 是靠 CPU 空转消耗时间，写多少条指令、编译器怎么优化， 时间就跟着变，所以它「不准」。定时器的思路完全不同： 让一个独立的硬件计数器去数时钟，数到约定的个数就举手报告。 CPU 在这期间可以去干别的活，时间到了再回来处理——这就是「定时」与「延时」的本质区别。

机器周期与晶振的换算

51 的时钟链路是这样的：晶振产生频率 fosc → 芯片内部振荡电路整形 → 得到 时钟周期（振荡周期） → 再 12 分频 → 得到 机器周期。 定时器数的不是时钟周期，而是机器周期。所以： 

基本关系：
    时钟周期  = 1 / fosc
    机器周期  = 12 / fosc        （标准 8051 是 12T 芯片：12 个时钟 = 1 个机器周期）
    定时时间  = 机器周期 × 计数值

  fosc = 12MHz      →  时钟周期 83.3ns  →  机器周期 1.000µs
  fosc = 11.0592MHz →  时钟周期 90.4ns  →  机器周期 1.085µs
  fosc = 6MHz       →  时钟周期 166.7ns →  机器周期 2.000µs

一句话记住：12MHz 晶振下，1 个机器周期 = 1µs。
定时器数 50000 个机器周期，就是 50000µs = 50ms。

注意芯片制程差异：
  STC89C52RC 是 12T（本教程用的芯片），按上面公式算；
  STC15 / STC8 系列是 1T（1 个时钟 = 1 个计数），
  把同一段程序搬过去，定时时间会变成原来的 1/12 —— 必须重算初值。
对比项 软件延时（上一篇） 硬件定时器（本篇）
时间由什么决定 指令条数 × 编译器优化结果 机器周期数 × 晶振频率
精度来源 不可控，换优化等级就变 晶振精度（常见 ±20~±50ppm，即 0.002%~0.005%）
CPU 占用 100% 空转，不能做别的事 几乎不占用，定时期间 CPU 可执行其他代码
能否同时计数 不能 能（C/T 位置 1 时变成对外部脉冲计数，可测频率）
典型用途 流水灯、开机闪灯等对时间不敏感处 数码管动态扫描、串口波特率、PWM、测周期/脉宽

TMOD 与 TCON 寄存器逐位说明

用定时器就是配置三个寄存器：TMOD（选工作方式）、TCON（启动与标志）、 IE（要不要中断）。51 内部有 T0 和 T1 两个定时器，T0 用低 4 位配置、T1 用高 4 位。 

TMOD （地址 0x89，复位值 0x00）

  bit7  bit6  bit5  bit4 │ bit3  bit2  bit1  bit0
  GATE  C/T   M1    M0   │ GATE  C/T   M1    M0
  └──── 属于定时器 T1 ───┘ └──── 属于定时器 T0 ───┘

GATE —— 门控位
    0 = 只由 TR0（或 TR1）控制启停；定时器软件启动      ← 平时都用 0
    1 = 还要 INT0 引脚为高电平才计数，用于测量脉宽

C/T  —— 计数/定时选择位
    0 = 定时器模式：对内部机器周期计数，时间 = 计数 × 1µs   ← 定时就用 0
    1 = 计数器模式：对 T0（P3.4）/ T1（P3.5）引脚的外部脉冲下降沿计数

M1 M0 —— 工作方式选择位
    0 0 = 方式 0：13 位定时器（TL0 只用低 5 位）
    0 1 = 方式 1：16 位定时器（最常用）
    1 0 = 方式 2：8 位自动重装
    1 1 = 方式 3：T0 拆成两个 8 位定时器（T1 停止），很少用

为什么不能写 sbit TR0 = TMOD^4;？
    位寻址要求地址能被 8 整除（位地址 = 字节地址 + 位号）。
    TMOD 的地址是 0x89，0x89 / 8 除不尽 → 不可位寻址，
    所以只能用 TMOD = 0x01; 或 TMOD |= 0x01; 整体赋值，不能单独改某一位。
    而 TCON 的地址是 0x88（整除了！）→ 可位寻址，TR0 / TF0 都能单独操作。
寄存器（地址） 位 名称 含义 本实验取什么值
TCON（0x88，可位寻址） bit4 TR0 定时器 0 运行控制：1 = 启动计数，0 = 停止 TR0 = 1;
bit5 TF0 定时器 0 溢出标志：计满时硬件置 1；进中断时硬件自动清零，查询方式必须软件清零 不用手动动它
IE（0xA8，可位寻址） bit7 EA 总中断开关：1 = 打开所有被允许的中断 EA = 1;
bit1 ET0 定时器 0 中断允许：1 = 允许 T0 溢出时产生中断 ET0 = 1;
特殊功能寄存器 — TH0 定时器 0 高 8 位（方式 2 时它当重装值仓库） 0x3C
— TL0 定时器 0 低 8 位（真正在计数的部分） 0xB0

中断服务函数要放在哪个地址，是芯片设计时就固定好的。51 的中断向量表如下—— 你写 interrupt 1，编译器就把函数放到 000BH 那一格： 

中断源          中断号   向量地址   说明
外部中断 0 INT0    0      0003H      P3.2 引脚
定时器 0  T0       1      000BH      ← 本篇用这个
外部中断 1 INT1    2      0013H      P3.3 引脚
定时器 1  T1       3      001BH
串口中断  RI/TI    4      0023H

写法（中断号直接跟在函数后面，不是参数）：
    void Timer0_ISR(void) interrupt 1
    {
        ...中断里要做的事...
    }

要点：
  ① 中断函数必须是 void 返回、不带参数；
  ② 中断号必须是 0~31 的常量，写错不会报错，但中断会跳到错误的地址，现象变得不可预测；
  ③ 不用在 main 里调用它 —— 中断发生时硬件自动跳转过去执行。

工作方式与初值计算

方式决定「计数器有几个位」——位数越多，一次能定的时间越长。计数器的行为是： 从你写入的初值开始往上数，数到满（溢出）就置标志位。 所以初值越大，剩下的步数越少，定时越短；这就是「初值 = 满值 − 步数」的来历。

方式 M1 M0 位数 最大计数 12MHz 下最大定时 溢出后怎么重装 典型用途
方式 0 0 0 13 位 8192 8.192ms 软件手动重装 兼容早期 8048，已基本淘汰
方式 1 0 1 16 位 65536 65.536ms 软件手动重装 通用定时，本教程主用
方式 2 1 0 8 位 256 256µs 硬件自动重装 串口波特率发生器、固定小间隔节拍
方式 3 1 1 两个 8 位 256 × 2 256µs 各自手动重装 T0 拆成两个定时器，同时 T1 停用

把三种方式的初值算法写在一起，其实就是一句话：初值 = 满值 − 需要的机器周期数。

第 1 步：把时间换算成机器周期数
    12MHz → 1 个机器周期 = 1µs
    N = 50ms / 1µs = 50000

第 2 步：确认这个数放得下
    方式 1 最大 65536 → 50000 装得下 ✔
    （如果要定 100ms，50000 装得下但 100000 超了 → 只能定 50ms 再软件数 2 次）

第 3 步：算初值
    初值 = 65536 − 50000 = 15536

第 4 步：拆成高 8 位和低 8 位
    15536 ÷ 256 = 60 余 176
    TH0 = 60  = 0x3C
    TL0 = 176 = 0xB0
    即 TH0 = 0x3C; TL0 = 0xB0;

三种方式的通用公式：
    方式 0（13 位）：初值 = 8192  − N ；TH0 = 初值 / 32 ，TL0 = 初值 % 32
    方式 1（16 位）：初值 = 65536 − N ；TH0 = 初值 / 256，TL0 = 初值 % 256
    方式 2（8 位） ：重装值 = 256 − N ；TH0 = TL0 = 重装值（N 最大 256）

如果晶振换成 11.0592MHz（1 个机器周期 = 1.085µs）：
    N = 50ms / 1.085µs ≈ 46080
    初值 = 65536 − 46080 = 19456 = 0x4C00  →  TH0 = 0x4C; TL0 = 0x00;
    同一段程序、同一个 50ms 目标，初值完全不同 —— 这就是「换晶振必须重算初值」的原因。

为什么选 50ms 而不是 1 秒

方式 1 一次最多只能定 65.536ms，写不下 1 秒。 标准做法是「短定时 + 软件计数」：定 50ms，中断 20 次就是 1 秒。 片内还有一个 T1 也能当定时器，但真正需要长时间定时时， 用「短周期 + 计数」比用更大的定时器更灵活——因为计数目标可以随时改，而定时器初值一改就要重算。

方式 1 为什么要手动重装，方式 2 为什么不用

这是定时器最容易出错、也最能体现「懂原理」的地方。关键在于溢出之后计数器从哪儿重新开始： 

方式 1（16 位，TH0 + TL0）：溢出后从 0x0000 继续数

    写入 TH0=0x3C TL0=0xB0（= 15536）
      → 数 50000 个机器周期 → 到 0xFFFF → 再来一个脉冲就溢出
    
    溢出时：TF0 置 1，然后 TH0/TL0 自动变成 0x0000
      → 如果你不在中断里重装，下一轮从 0 数到满 = 65536 个周期 = 65.536ms
      → 定时从 50ms 变成 65.536ms，误差 (65536-50000)/50000 = +31%

    所以：方式 1 的中断服务函数第一件事就是重新写 TH0 / TL0。

方式 2（8 位，TL0 计数 + TH0 存重装值）：溢出后硬件自动把 TH0 装回 TL0

    TH0 = 0x38（重装值 56 = 256 - 200）
      → TL0 从 0x38 数到 0xFF 溢出 → 硬件立即把 TH0 的值再装进 TL0
      → 永远只需要初始化一次，中断里不用（也不能）重装
      → 代价是只有 8 位，12MHz 下最长只能定 256µs

一句话：方式 1 是「软件重装」，方式 2 是「硬件重装」。
        要长定时用方式 1，要固定小间隔/波特率用方式 2。
手动重装的隐藏误差，以及怎么消掉它

中断响应本身需要时间（现场保护 + 跳转，通常十几个机器周期，约十几微秒）， 再加上 TH0 = …; TL0 = …; 这两条指令执行期间计数器没有停， 每轮都会丢掉这么一小段时间。单次约十几微秒，相对 50ms 只有万分之几， 但一秒累计 20 轮，长时间跑就会慢慢偏。

要求更严时的标准做法是在重装前后把计数器停掉： TR0 = 0; TH0 = 0x3C; TL0 = 0xB0; TR0 = 1; ——让「重装」这件事在时间上也是原子的。日常实验用不到， 但你要知道这个误差存在，并且知道它从哪儿来。

硬件接线说明

定时器在芯片内部，所以这个实验不需要新增任何一个元件—— 上一篇接好的板子原样拿来用，只换程序。这正是本节要强调的第一个知识点。

最常见的误解：T0 引脚要接线吗？

不需要。T0 是 P3.4 引脚（第 14 脚）的复用功能， 只有在 TMOD 的 C/T 位 = 1（计数器模式）时才有意义—— 那时它是「外部脉冲输入」，你才需要往它上面接信号。 C/T = 0（定时器模式）时，计数源是芯片内部的机器周期， 与这个引脚完全无关，悬空即可。

引脚 / 元件 本实验怎么接 与上一篇是否相同 说明
P1.0（第 1 脚） LED 负极；LED 正极经 470Ω 接 +5V 相同 灌电流接法，低电平点亮；本实验用它显示定时结果
P1.1 ~ P1.7 可保持上一篇的 8 路 LED 不变 相同 不用的引脚留着不影响定时器工作
P3.4 / T0（第 14 脚） 悬空 — 定时器模式下不需要外部信号；练计数器模式时才接脉冲源
P3.5 / T1（第 15 脚） 悬空 — 同上
晶振 12MHz + 两个 30pF 看板子，可能要换 本页初值全部按 12MHz 计算；若板上是 11.0592MHz，必须按 0x4C00 重算
复位电路 10µF + 10kΩ 相同 复位会清 TMOD/TCON，程序重新初始化一遍
EA（第 31 脚）/ 电源 +5V；40 脚 +5V 带 104 去耦 相同 —
示波器 / 频率计（选配） 探头接 P1.0（或另接 P1.1 输出方波） 新增可选 用来验证 1Hz 方波，比肉眼数秒准得多

上电前检查

  1. 确认板上晶振的实际频率。丝印看不清就用频率计测，或直接看 STC-ISP 检测到的芯片信息——初值算错，现象就是时间差一倍以上。
  2. 确认 EA（第 31 脚）接在 +5V，否则程序根本不会从片内 Flash 执行。
  3. 确认 P1.0 那一路的 LED 仍是灌电流接法（正极经电阻接 +5V，负极接引脚），否则亮灭逻辑正好相反。
  4. 若接了示波器，先确认探头地线夹在板子 GND 上，避免引入干扰或短路。

完整代码

目标：12MHz 晶振下，用方式 1 每 50ms 中断一次，累计 10 次（500ms）翻转一次 P1.0， 得到周期 1 秒的闪烁。代码可直接编译下载，逐行有中文注释。 

#include <reg52.h>                  /* 51 寄存器定义，含 TMOD / TCON / IE / TH0 / TL0 */

sbit LED = P1^0;                    /* 把 P1.0 命名为 LED，灌电流接法：0 亮 1 灭 */

unsigned char count = 0;            /* 中断次数计数，50ms × 10 = 500ms（最大 255，够用） */

/* ------------------------------------------------------------------
 * 定时器 0 初始化：方式 1（16 位定时器），12MHz 下定 50ms
 * ------------------------------------------------------------------ */
void Timer0_Init(void)
{
    TMOD &= 0xF0;                   /* 清掉低 4 位（T0 的设置），保留高 4 位（不动 T1） */
    TMOD |= 0x01;                   /* 低 4 位设为 0001：GATE=0, C/T=0, M1=0, M0=1 → 方式 1 */

    TH0 = 0x3C;                     /* 初值 65536 - 50000 = 15536 = 0x3CB0 → 高 8 位 */
    TL0 = 0xB0;                     /* 低 8 位。写入后计数器从这里开始往上数 */

    EA  = 1;                        /* 打开总中断开关（总闸） */
    ET0 = 1;                        /* 允许定时器 0 溢出时产生中断（分闸） */
    TR0 = 1;                        /* 启动定时器 0，开始计数 */
}

/* ------------------------------------------------------------------
 * 定时器 0 中断服务函数
 * interrupt 1 表示定时器 0，编译器会把它放到向量地址 000BH
 * 不需要在 main 里调用：T0 溢出时 CPU 自动跳转过来
 * ------------------------------------------------------------------ */
void Timer0_ISR(void) interrupt 1
{
    TH0 = 0x3C;                     /* 方式 1 必须手动重装！否则下一次定时变成 65.536ms */
    TL0 = 0xB0;                     /* 这两条指令本身也耗时，属于重装误差的来源 */

    count++;                        /* 每 50ms 加一 */
    if (count >= 10)                /* 累计到 10 次 = 500ms */
    {
        count = 0;                  /* 计数器清零，准备下一轮 */
        LED = !LED;                 /* 翻转 LED：500ms 亮、500ms 灭 → 周期 1s，即 1Hz */
    }
}

void main(void)
{
    LED = 1;                        /* 上电先让灯灭（灌电流接法：高电平熄灭） */
    Timer0_Init();                  /* 配置并启动定时器 */

    while (1)
    {
        /* 主循环空转。定时完全由硬件负责，
           这里可以放按键扫描、串口收发等任务，不会影响定时精度 */
    }
}

关键代码解析

  • TMOD &= 0xF0; TMOD |= 0x01;——为什么要写成两句， 而不是直接 TMOD = 0x01;？ 第一句是「读—改—写」：把低 4 位清零，保留高 4 位里 T1 的原有设置； 第二句再或上方式 1 的编码。如果直接整体赋值，T1 的配置会被一起清成 0—— 当程序里同时用 T1 做波特率发生器时，这一赋值就会把串口波特率弄乱。 另外注意不能写 TMOD ^ 4 = 0; 之类的位操作， 因为 TMOD 地址 0x89 不可位寻址，只能整体赋值。
  • TH0 = 0x3C; TL0 = 0xB0;——0x3CB0 = 15536， 计数器从 15536 数到 65535 再溢出，正好 65536 − 15536 = 50000 个机器周期。 12MHz 下 50000 × 1µs = 50ms。这两行写初值时和中断里重装时都要出现， 漏掉后者是新手最典型的错误。
  • EA = 1; ET0 = 1; TR0 = 1;——三件事缺一不可： EA 是总闸，ET0 是定时器 0 这一路的分闸，TR0 才是真的让计数器开始跑。 少任何一个，中断都不会发生，现象都是「灯一动不动」。
  • void Timer0_ISR(void) interrupt 1——中断号 1 对应定时器 0 （向量地址 000BH）。函数必须 void 返回、无参数； 写成 interrupt 0 会占用外部中断 0 的向量，现象立刻变得不可预测。
  • LED = !LED;——对 sbit 定义的位变量， 推荐用逻辑非 !；位取反 ~ 是按位取反运算符， 语义上更适合整字节（例如 P1 = ~P1; 会让 8 个灯同时取反）。两者在这里都能用， 但把「位用 !、字节用 ~」当成习惯，读代码的人不会误会。
  • count 为什么用 unsigned char 而不是 unsigned int？因为它只需要数到 10，而 8 位变量自增在 51 上是 一条指令，不会被中断打断；16 位变量的自增是两条指令，主循环若同时读这个变量就可能读到半个值。 这是一个很小但很真实的工程考虑。

查询方式（不用中断）写法

如果只是要一段「精确延时」，不要求后台自动跑，可以不用中断： 启动定时器后用 while (!TF0); 等标志位。 代价是等待期间 CPU 被占住，好处是不涉及中断优先级和现场保护，逻辑更简单。 请特别注意标志位的清零——这是查询方式最容易踩的坑。 

#include <reg52.h>

sbit LED = P1^0;

/* ------------------------------------------------------------------
 * 用定时器 0 实现精确毫秒延时（12MHz）
 * 每个 1ms 都由定时器硬件计时，不受编译器优化等级影响
 * ------------------------------------------------------------------ */
void Timer0_Delay_ms(unsigned int ms)
{
    unsigned int i;

    for (i = 0; i < ms; i++)        /* 循环 ms 次，每次等 1ms */
    {
        TMOD &= 0xF0;               /* 每次重新配置，保证状态确定 */
        TMOD |= 0x01;               /* 方式 1：16 位 */

        TH0 = 0xFC;                 /* 65536 - 1000 = 64536 = 0xFC18 */
        TL0 = 0x18;

        TF0 = 0;                    /* 关键：查询方式必须软件清标志，否则第二次判断立刻通过 */
        TR0 = 1;                    /* 启动计数 */

        while (!TF0);               /* 空等，直到硬件把 TF0 置 1（约 1ms） */

        TR0 = 0;                    /* 停止计数，准备下一轮 */
    }
}

void main(void)
{
    LED = 1;                        /* 上电灯灭 */

    while (1)
    {
        LED = !LED;                 /* 翻转 LED */
        Timer0_Delay_ms(500);       /* 精确定时 500ms */
    }
}

方式 2 完整示例（硬件自动重装）

把上面的 50ms 换成 200µs 节拍：方式 2 只有 8 位，200µs 对应 200 个机器周期， 重装值 = 256 − 200 = 56 = 0x38。累计 2500 次就是 500ms。 注意中断服务函数里没有重装语句——这就是方式 2 最大的好处。 

#include <reg52.h>

sbit LED = P1^0;

unsigned int tick = 0;              /* 200µs × 2500 = 500ms，需要 16 位变量 */

void Timer0_Init(void)
{
    TMOD &= 0xF0;                   /* 保留 T1 的设置 */
    TMOD |= 0x02;                   /* 低 4 位 0010：M1=1, M0=0 → 方式 2（8 位自动重装） */

    TH0 = 0x38;                     /* 重装值 = 256 - 200 = 56 = 0x38，TH0 只当"仓库" */
    TL0 = 0x38;                     /* 计数器本体也从同一个值开始 */

    EA  = 1;
    ET0 = 1;
    TR0 = 1;
}

void Timer0_ISR(void) interrupt 1
{
    /* 方式 2 由硬件自动把 TH0 装回 TL0，这里不需要（也不应该）重装 */

    tick++;                         /* 每 200µs 加一 */
    if (tick >= 2500)               /* 2500 × 200µs = 500ms */
    {
        tick = 0;
        LED = !LED;                 /* 每 500ms 翻转，周期 1s */
    }
}

void main(void)
{
    LED = 1;
    Timer0_Init();

    while (1)
    {
    }
}
两种方式怎么选

需要长定时（几十毫秒级）→ 方式 1，但记得在中断里手动重装； 需要固定小间隔（几百微秒以内）或做串口波特率发生器 → 方式 2，让硬件替你重装， 连中断都可以不开（波特率发生器就是纯硬件在跑）。 判断依据只有一个：256 个机器周期够不够用。 12MHz 下 256µs 够，1ms 就不够了。

现象演示说明

定时器实验的现象只有「闪」和「不闪」两种，但闪的快慢精确地反映了你的初值和重装有没有写对。 所以这一节最重要的动作是：用秒表或频率计测量，而不是用眼睛判断。

正确现象

  1. 上电后 P1.0 的 LED 亮 0.5 秒、灭 0.5 秒，稳定循环，肉眼看起来是均匀的 1Hz 闪烁。
  2. 用秒表量 20 个完整周期（亮+灭算一个周期）：应为 20.0 秒左右，误差应在 0.1 秒内（手工计时的误差主要来自人）。
  3. 用万用表频率档或示波器量 P1.0：应读到 1.000Hz 左右的方波，占空比接近 50%。
  4. 在主循环里加入其他任务（比如按键扫描）后，闪烁周期不变——这正说明定时与 CPU 在做什么无关。

现象与判据

测到的现象 周期 原因
亮 0.5s 灭 0.5s，稳定 1.000s 正确：方式 1 初值 0x3CB0 + 中断里重装 + 计数 10 次
闪得比预期慢一点，长时间也稳定 ≈1.085s 板上晶振其实是 11.0592MHz，但初值按 12MHz 算的（慢 8.5%）。改 TH0=0x4C、TL0=0x00
闪得明显慢，节奏均匀 ≈1.310s 忘了在中断里手动重装 TH0/TL0：每轮变成 65.536ms，慢了 31%
亮灭各 50ms，快得晃眼 0.100s 中断里少了 count >= 10 的判断，每次中断就翻转

忽快忽慢、偶尔漏一次 不稳定 中断服务程序太长被别的中断再打断；或电源不稳、复位电路受干扰（回想最小系统那一篇）

把「测得准」变成实验结论

写实验报告时，别写「灯正常闪烁」，而要写：「用频率计测得 P1.0 输出 1.0002Hz， 理论值 1.0000Hz，相对误差 0.02%，误差来源为晶振精度与中断重装延迟」。 顺便把上一篇软件延时的实测值也列出来对比—— 你会发现软件延时的误差通常在百分之几，而定时器的误差在万分之几， 这个数量级的差别就是「为什么要学定时器」的答案。

常见报错排查方案

定时器的问题有个特点：编译能过、下载成功、但现象不对。 所以下面的条目里，编译期和运行期各占一半，运行期的更要逐条对号入座。

编译报错：main.c(12): error C202: 'TR0': undefined identifier

原因：漏了 #include <reg52.h>。TR0、TF0、TMOD、TH0 这些名字都定义在头文件里，编译器不认识它们。

解决：补上头文件，并确认工程 Device 选的是 AT89C52 / STC89C52RC 这类 51 芯片（选了 STM32 芯片自然没有这个头文件）。

编译报错：main.c(8): error C142: 'TMOD': invalid base type / 试图写 sbit TR0 = TMOD^4;

原因：把不可位寻址的寄存器当成了可位寻址的。TMOD 地址是 0x89，不能被 8 整除，所以不能用 sbit 定义它的某一位，也不能用 TMOD^4 = 0; 这种写法。

解决：改为整体赋值并配合位掩码：TMOD &= 0xF0; TMOD |= 0x01;。需要单独操作某一位时，改用可位寻址的 TCON（地址 0x88）：TR0 = 1; TF0 = 0;。

链接报错：*** WARNING L1: UNRESOLVED EXTERNAL SYMBOL SYMBOL: TIMER0_ISR MODULE: main.obj (MAIN)

原因：链接器找不到中断服务函数的实体——通常是函数名改了但某处声明没改，或者把中断函数写成了「只有声明没有函数体」，也可能被 #if 0 之类的条件编译挡掉了。

解决：确保中断服务函数有且只有一个完整定义（含函数体），名字与声明完全一致；本项目只有 main.c 一个文件，直接搜索函数名即可定位。

现象：灯完全不闪，保持上电时的状态

原因：中断链条断了一环。任何一处不对，现象都一样：漏 EA = 1;（总闸没开）、漏 ET0 = 1;（分闸没开）、漏 TR0 = 1;（定时器没启动）、漏调用 Timer0_Init()，或者中断号写错导致 CPU 跳到了别的向量地址。

解决：按「TMOD → TH0/TL0 → EA → ET0 → TR0 → 中断号 1」的顺序逐项核对。快速定位技巧：临时把 EA = 1; 注释掉，同时把主循环改成直接翻转 LED——如果这样能闪，说明前面的配置都对，问题就在中断使能或中断号上。

现象：闪烁周期约 1.31 秒，比设计的 1 秒慢了 31%

原因：中断服务函数里忘了重装初值。方式 1 溢出后计数器从 0x0000 重新开始，下一轮要数 65536 个机器周期 = 65.536ms，而不是 50ms。

解决：在中断服务函数的第一件事写回 TH0 = 0x3C; TL0 = 0xB0;；或者改用方式 2（硬件自动重装，但只有 8 位，最长 256µs）。判断误差大小的通用公式：(65536 − N) / N。

现象：查询方式下第一次等待正常，之后 LED 疯狂翻转

原因：查询方式忘了软件清除溢出标志 TF0 = 0;。第一次溢出后 TF0 一直是 1，后面的 while (!TF0); 立即通过，等于完全没有等待。

解决：在启动定时器之前写 TF0 = 0;。记住两者的区别：中断方式下 TF0 由硬件自动清零，查询方式下必须软件清零——这正是很多人从查询改成中断后「反而不会写」的原因。

一条设计原则：中断服务函数要短

中断里只做「必须马上做的事」——重装初值、计数、置标志，然后立刻返回。 不要在中断里调用长延时、浮点运算、串口打印（printf）， 否则主程序会被长时间挂起；如果中断自身又被打断，还可能造成逻辑错乱。 需要处理的事情多，就在中断里置一个标志，让主循环去干活—— 这就是「前台/后台」结构，后面写数码管扫描和按键消抖时会反复用到。

小结与练习

定时器的全部逻辑可以浓缩成四步：选方式（TMOD）→ 算初值（满值 − 机器周期数）→ 开中断（EA/ET0/TR0）→ 溢出后处理（方式 1 手动重装，方式 2 硬件重装）。 把这四步走顺，你手里就有了一把与代码写法无关的时间尺子； 后面无论是让数码管稳定不闪、让串口波特率准确，还是测一个方波的频率，用的都是它。

动手练习
  1. 改成一个 2 秒周期的闪烁：仍用方式 1 与 50ms 初值 0x3CB0， 只在中断里改计数阈值 count >= 20； 然后回答：为什么不能把 TH0/TL0 直接算成「一次定时 1 秒」？ 请用方式 1 的最大定时值（65.536ms）来论证。
  2. 用方式 2 产生 2kHz 方波：需要每 250µs 翻转一次（周期 500µs → 2kHz）， 重装值 = 256 − 250 = 6，即 TH0 = TL0 = 0x06。 用示波器或万用表频率档验证，然后解释：为什么用方式 2 做不出 1kHz 方波 （提示：1kHz 需要 500µs 的半周期，超过了 8 位 256µs 的上限）。
  3. 把查询方式延时和软件延时放在一起测：用本篇的 Timer0_Delay_ms(500) 和上一篇的 Delay_ms(500) 各做一个闪烁程序， 分别用秒表量 20 个周期的总时间，算出各自的相对误差； 再把 C51 优化等级从 Level 8 改到 Level 0，重测一次。 用数据回答：哪一种延时的误差会随优化等级变化？为什么？
