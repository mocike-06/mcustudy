原理介绍

前面几篇教程里，单片机的“输出”要么是几个 LED，要么得靠电脑上的串口助手。 LCD1602 的意义在于：让设备自己把数据说出来。 它的名字就是规格——16 个字符 × 2 行， 每个字符由 5×8 点阵组成，工作电压 5V，一共 16 个引脚。

关键点在于：LCD1602 不是一块“傻屏”，它板上焊着一片 HD44780 控制器（以及 KS0066、SPLC780D、ST7066 等兼容芯片）。 你不需要自己画点阵，只要把 ASCII 字符码丢给它， 它自己会去内部的字符库（CGROM）里取出字模显示出来。 这就像给打印机发文字，而不是发像素——这正是它比点阵屏好用的地方。

内部资源 容量 作用
DDRAM 80 字节 显示数据存储器，存“这一格显示哪个字符码”；可见的只有前 16×2 格
CGROM 固定字库 字符发生 ROM，存了数字、字母、日文假名等固化字模，ASCII 码直接能用
CGRAM 64 字节 字符发生 RAM，可以自定义 8 个 5×8 点阵字符（每个占 8 字节）
IR / DR 两个寄存器 指令寄存器与数据寄存器；写指令还是写数据，靠 RS 引脚区分
BF / AC 状态位与地址计数器 BF 是忙标志，AC 记录当前 DDRAM/CGRAM 地址；光标位置就是 AC 决定的

理解了“写进去的是字符码、由控制器去查字模”这一点， 后面所有的指令（清屏、开显示、光标定位）就都好理解了： 它们本质上都是在操作 DDRAM 里的地址计数器 AC。

引脚与三根控制线

16 个引脚分成三组：电源与背光、控制线、数据线。

脚号 名称 作用 接法
1VSS电源地接 GND
2VDD电源正接 +5V（接反会烧模块）
3V0对比度调节接 10kΩ 电位器中点，不接就是一片空白
4RS寄存器选择：0 = 指令，1 = 数据接 P3.5
5RW读写选择：0 = 写，1 = 读接 P3.6
6E使能：下降沿锁存数据接 P3.7
7~14D0~D78 位数据总线（双向）接 P2.0~P2.7
15A背光正极经 100Ω 接 +5V
16K背光负极接 GND
三根控制线记法：先选对象，再定方向，最后按一下
  • RS 选对象：这次要写的是“指令”（0）还是“要显示的字符”（1）。
  • RW 定方向：是单片机写给屏幕（0），还是单片机读屏幕的状态（1）。
  • E 按一下：前面两根线选好、数据放到总线上稳定之后，给 E 一个脉冲，屏幕在下降沿把数据收走。

RS / RW / EN 的时序

这是整篇教程的核心。写一个字节的完整动作只有四步，但每一步都有理由： 

            ┌──── 数据必须在这一段已经稳定 ────┐
   RS/RW ───┘                                   └───   （先设好，不能和数据同时变）
                                                        tAS ≥ 40ns
   D0~D7  ═══════ 有效数据 ═══════════════════════       （放上总线并稳定）
                                          tDSW ≥ 80ns
                    ┌──────────────────┐
   E      ──────────┘                  └──────────       （高电平脉宽 tPW ≥ 450ns）
                    ▲                  ▲
                 上升沿              下降沿 ← 就在这一刻，数据被锁存进控制器

   写完之后还有一件事：控制器要花时间去“执行”这条指令
     · 写数据 / 大多数指令：约 40us
     · 清屏（0x01）、光标复位（0x02）：1.64ms
   这段时间里它不接受新指令 —— 这就是“延时”或“判忙”存在的理由

三个时间常数要记住：地址建立 ≥40ns、数据建立 ≥80ns、EN 高电平 ≥450ns。 这些数字都很小，12MHz 的 51 执行一条指令就要 1µs，所以“随手写”通常也能满足。 真正会坑人的不是这三个纳秒级的参数，而是指令的执行时间。

为什么写完指令必须等一会儿

控制器收到指令后要真的去干活：清屏指令要遍历 80 字节 DDRAM 把它们写成空格， 需要 1.64ms；其它指令大约 40µs。 在这期间它处于“忙”状态，你再送指令就会被丢弃——表现就是 “初始化写了但屏幕没反应”“清屏清不干净”“字符位置错乱”。 解决办法有两个，下面立刻讲。

方案 A：固定延时（简单可靠）

每条指令后一律延时 2ms，清屏后延时 10ms。优点是代码短、绝对不会因为读时序出错而卡死； 缺点是慢：写满一屏 32 个字符要 32 × 40µs ≈ 1.3ms， 但按固定延时算要 30ms 以上，刷新率被压到 30Hz 以下。本篇完整代码用这个方案。

方案 B：读忙标志 BF 判忙（更快）

控制器有一个状态字：读操作时 D7 就是忙标志 BF， BF = 1 表示它还在忙，这时候等它变 0 就行，比无脑延时精确得多，速度也能快十倍以上。 代价是要把 RW 拉高、把数据总线当输入来读——所以数据线必须选一个“能读”的口， 这也是本篇把数据线放在 P2 而不是 P0 的原因之一（P0 是开漏口，没有上拉就既写不出高电平、也读不到高电平）。 

/* 读状态字判忙：读操作时 D7 = BF，BF = 1 表示控制器还在执行上一条指令
 * 注：8 位模式读一次就是完整的 8 位状态；
 *     4 位模式要读两次（先读到的高 4 位里含 BF，随后还要补一次低 4 位）
 */
void LCD_WaitBusy(void)
{
    LCD_DATA = 0xFF;              /* 准双向口作输入前先写 1，内部弱上拉才生效 */
    LCD_RS = 0;                   /* 读的是指令寄存器（也就是状态字） */
    LCD_RW = 1;                   /* 方向：读 */

    do
    {
        LCD_EN = 1;               /* 读操作同样靠 E 的下降沿把状态送到总线上 */
        LCD_Delay_short();
        LCD_EN = 0;
    } while (LCD_DATA & 0x80);    /* 只关心最高位 D7：还是 1 就继续等 */

    LCD_RW = 0;                   /* 读完恢复成写模式，否则后面的写指令会被当成读 */
}
判忙方案的唯一风险：万一没人应答，程序会卡死在循环里

如果 LCD 没接好、BF 一直是 1，while (LCD_DATA & 0x80); 就会永远转下去，程序表面上“死机”了。 工程上要在循环里加一个超时计数（比如等不到就跳出并返回错误）， 新手阶段可以先只用方案 A 的固定延时，等系统跑通了再换成判忙。

8 位与 4 位总线的取舍

LCD1602 支持两种接法，区别就在于“一个字节是分一次送还是分两次送”：

对比项 8 位总线（本篇示例） 4 位总线
占用 IO 8 根数据 + 3 根控制 = 11 个 4 根数据（只用 D4~D7）+ 3 根控制 = 7 个
一个字节怎么送 一次送完 分两次：先送高 4 位，再送低 4 位
代码复杂度 直观，时序一眼看懂 要写半字节函数；初始化有专门的“唤醒”序列
速度 快一倍 慢一倍（数据量不变，但每次多一轮 E 脉冲）
适不适合你的项目 IO 富余、初学阶段 还要接按键、传感器、串口时，这 4 个 IO 很值钱

51 一共只有 32 个 IO。用 8 位总线接完 LCD 就只剩 21 个，再挂个 DHT11、几个按键、 串口（还要占 2 个），很快就会紧张。所以真实产品里 4 位模式更常见； 但对初学者来说，先用 8 位模式把 RS/RW/EN 的时序彻底搞清楚，再改成 4 位，学习效率最高。 

/* 送半个字节（4 位）：只改 P2 的高 4 位，低 4 位留给别的用途 */
void LCD_WriteNibble(unsigned char nib)
{
    P2 = (P2 & 0x0F) | (nib << 4);     /* 高 4 位 = 数据，低 4 位保持不变 */
    LCD_EN = 1;
    LCD_Delay_short();
    LCD_EN = 0;                          /* 下降沿锁存这半个字节 */
    LCD_Delay_short();
}

/* 4 位模式下写一条指令：先高 4 位，再低 4 位 */
void LCD_WriteCmd4(unsigned char cmd)
{
    LCD_RS = 0;
    LCD_RW = 0;
    LCD_WriteNibble(cmd >> 4);           /* 高 4 位先送 */
    LCD_WriteNibble(cmd & 0x0F);         /* 低 4 位后送 */
    Delay_ms(2);                         /* 留出指令执行时间 */
}

/* 4 位模式的“唤醒”序列（上电后必须先做这一步，否则进不了 4 位模式）：
 *   Delay_ms(50) → 写 0x33 → 写 0x32 → 再按 8 位模式的方式写 0x28 / 0x0C / 0x06 / 0x01
 *   其中 0x28 表示：4 位总线(DL=0)、2 行(N=1)、5×8 点阵(F=0)
 */

初始化指令序列

上电后必须按固定顺序写一串指令，LCD 才知道该怎么工作。顺序不能换，时间不能省。

顺序 指令 二进制 含义 执行时间
0 等待 — 上电后控制器内部复位需要 >15ms，先等 50ms ≥15ms
1 0x38 0011 1000 功能设置：DL=1（8 位总线）、N=1（两行）、F=0（5×8 点阵） 40µs
2 0x0C 0000 1100 显示开关：D=1 开显示、C=0 关光标、B=0 不闪烁 40µs
3 0x06 0000 0110 输入模式：I/D=1 地址自动 +1、S=0 整屏不移动 40µs
4 0x01 0000 0001 清屏：DDRAM 全部写空格，光标回左上角 1.64ms

几个容易写错的点：

  • 0x38 建议连写三次。 上电瞬间总线电平可能不确定， 控制器有可能误判成 4 位模式。HD44780 手册明确要求在初始化阶段重复写功能设置指令， 用 8 位模式时写三次是最省心的做法。少了这一步，典型现象是一排黑方块或者只有一半字符正常。
  • 0x38 不要写成 0x30。 0x30 是“8 位、单行”， 写错的直接后果是第二行怎么都显示不出来——这个坑每年都要坑一批人。
  • 0x0C 和 0x0E 的区别。 0x0C 是开显示、关光标； 0x0E 是开显示、开光标（屏幕上会有一条下划线）；0x0F 再加上闪烁。 调试阶段可以临时用 0x0F，能直观看到光标停在哪里，对排查“字符为什么写到别处去了”特别有用。
  • 0x06 里的 S 位。 S=1 时每写一个字符整屏会跟着移动， 做“滚动字幕”才用它；正常显示要写 0，否则字符会自己跑。

光标定位：0x80 + 地址

要在指定位置显示，先写一条“设置 DDRAM 地址”的指令，格式是 1 + 7 位地址，也就是 0x80 | 地址。 两行的地址是分开排的：

显示位置 DDRAM 地址 写入的指令 说明
第一行第 1 格 0x00 0x80 清屏后光标默认就在这里
第一行第 16 格 0x0F 0x8F 第一行地址范围 0x00 ~ 0x0F
第二行第 1 格 0x40 0xC0 不是 0x10，第二行从 0x40 开始
第二行第 16 格 0x4F 0xCF 第二行地址范围 0x40 ~ 0x4F
超出 0x0F / 0x4F 会怎样

DDRAM 实际有 80 字节，第一行写到第 17 个字符时不会自动换行到第二行， 而是继续往后写（跑到 0x10），那部分不属于可见区域，屏幕上什么都看不到。 所以显示字符串时要么自己控制长度，要么在函数里加边界判断 （col + 字符串长度 ≤ 16），否则会莫名其妙“丢字”。

用 CGRAM 做自定义字符

内置字库只有标准字符。想在屏幕上显示“℃”“电池图标”“箭头”怎么办？ 用 CGRAM 自己画：每个自定义字符占 8 个字节，每个字节代表一行点阵， 只有低 5 位有效（因为字符是 5 列宽），一共能放 8 个。

写入的地址有个固定算法：CGRAM 地址 = 0x40 + 字符码 × 8。 例如字符码 0x00 的点阵从 0x40 开始，字符码 0x01 的从 0x48 开始，依此类推。 定义完之后，显示时直接写字符码 0x00 ~ 0x07 就行。 

/* 5×8 点阵：每一行用 5 个二进制位表示，1 = 点亮，0 = 熄灭
 *
 *      列:  4 3 2 1 0
 *   第0行    0 0 0 0 0     0x00
 *   第1行    0 1 0 1 0     0x0A   ← 两个凹口
 *   第2行    1 1 1 1 1     0x1F
 *   第3行    1 1 1 1 1     0x1F
 *   第4行    0 1 1 1 0     0x0E
 *   第5行    0 0 1 0 0     0x04   ← 尖尖的底
 *   第6行    0 0 0 0 0     0x00
 *   第7行    0 0 0 0 0     0x00
 */
unsigned char code HeartChar[8] = {
    0x00, 0x0A, 0x1F, 0x1F, 0x0E, 0x04, 0x00, 0x00
};

/* 把点阵写进 CGRAM 的 0 号位置（以后用字符码 0x00 显示它） */
void LCD_LoadCustomChar(void)
{
    unsigned char i;

    LCD_WriteCmd(0x40);                  /* CGRAM 地址 0x00 = 0x40 + 0×8 */
    for (i = 0; i < 8; i++)
        LCD_WriteData(HeartChar[i]);     /* 依次写 8 行点阵 */

    LCD_WriteCmd(0x80);                  /* 关键：把地址指针切回 DDRAM！
                                          * 忘记这一句，后面显示的字符会被写进 CGRAM 里，
                                          * 屏幕上什么都不出来，而且自定义字符也被改坏 */
}
显示自定义字符时必须直接写字符码，不能放进字符串

自定义字符的字符码是 0x00，而 C 语言里 0x00 正是字符串的结束符 '\0'。 所以 LCD_ShowString(1, 15, "\0"); 会显示空白—— 必须用 LCD_WriteData(0x00); 单独写这一格。

硬件接线说明

LCD1602 是“线多但每根都明确”的典型外设：11 根信号线 + 2 根电源 + 2 根背光。 接线的难点不在数量，而在对比度引脚 V0—— 它是初学者第一大坑，症状是“背光亮着，但屏幕上什么都没有”。

2 VDD +5V 不要接 3.3V，模块对比度会异常
3 V0 10kΩ 电位器的中间脚（另两脚接 +5V 与 GND） 必须接；没电位器时可串 1kΩ 到地应急
4 RS P3.5 0 = 指令，1 = 数据
5 RW P3.6 0 = 写，1 = 读（判忙时才拉高）
6 E P3.7 下降沿锁存数据

接线顺序建议

  1. 先接 VSS / VDD / 背光，上电确认背光亮起来（这一步能排除模块本身的供电问题）。
  2. 接 V0 电位器，先不用管程序，直接上电调一下，让屏幕出现“一排黑方块”——这说明对比度通路是好的。
  3. 接三根控制线 RS / RW / EN 到 P3.5 / P3.6 / P3.7。
  4. 接数据线：D0 对 P2.0、D1 对 P2.1……D7 对 P2.7，一根一根核对，别图快。
  5. 全部接完复检一遍，最后上电。
上电前必查
  • VDD 与 VSS 有没有接反——这是唯一会立刻损坏模块的错误。
  • V0 有没有接。悬空时对比度电压不确定，屏幕通常是“背光亮、无字符”。
  • 8 根数据线的顺序有没有错位。错一位的现象是“字符能显示但读起来不对”。
  • RW 有没有可靠接地或接到 P3.6。悬空的 RW 可能被干扰成高电平，控制器会进入读模式，写指令全部失效。
  • 背光有没有串限流电阻。大尺寸模块背光电流可达 100mA 以上，直接接 5V 会让整机电流吃紧。

完整代码

这是一份可以直接编译下载的 8 位总线驱动：初始化、写指令、写数据、光标定位、 显示字符串、显示定长数字、自定义字符，一共七个函数。 主程序在第一行显示固定标题，第二行做一个每秒递增的计数器—— 注意它只刷新变化的那几个字符，不清屏， 这是“显示不闪”的关键。 

#include <reg52.h>
#include <intrins.h>                 /* 为了用 _nop_()，防止空循环被优化掉 */

/* ---------------- 引脚定义 ----------------
 * 数据总线选 P2 而不是 P0：P2 是准双向口，内部有弱上拉，可以直接写也可以直接读；
 * P0 是开漏输出，不加上拉电阻既写不出高电平，也读不到高电平（判忙会失效）。
 */
#define LCD_DATA   P2               /* D0~D7 → P2.0~P2.7 */

sbit LCD_RS = P3^5;                 /* RS：0 = 指令寄存器，1 = 数据寄存器 */
sbit LCD_RW = P3^6;                 /* RW：0 = 写，1 = 读 */
sbit LCD_EN = P3^7;                 /* EN：下降沿把总线上的数据锁存进控制器 */

sbit LED_RUN = P1^0;                /* 心跳灯：程序还活着就能看见 */

/* ------------------------------------------------------------------
 * 毫秒延时：只给主循环和指令等待用，不要放进中断服务函数
 * 12MHz 晶振下内层循环约 1ms
 * ------------------------------------------------------------------ */
void Delay_ms(unsigned int ms)
{
    unsigned int i, j;
    for (i = ms; i > 0; i--)
        for (j = 110; j > 0; j--);
}

/* ------------------------------------------------------------------
 * 极短延时：满足两个时间要求
 *   1. EN 高电平脉宽 tPW ≥ 450ns
 *   2. 大多数指令 / 写数据的执行时间约 40us
 * 12MHz 下这个循环约 60~80us，比上面两个要求都大，属于“够用且省事”的写法。
 * 想提速就换成 LCD_WaitBusy() 判忙方案。
 * ------------------------------------------------------------------ */
void LCD_Delay_short(void)
{
    unsigned char i;
    for (i = 0; i < 15; i++)
        _nop_();
}

/* ------------------------------------------------------------------
 * 给 EN 一个完整的使能脉冲：拉高 → 保持 → 拉低
 * 数据在这条脉冲的下降沿被控制器锁存
 * ------------------------------------------------------------------ */
void LCD_EN_Pulse(void)
{
    LCD_EN = 1;                     /* 拉高使能，控制器开始读总线 */
    LCD_Delay_short();              /* 保持高电平（要求 ≥450ns，这里余量极大） */
    LCD_EN = 0;                     /* 下降沿：数据被锁存 */
}

/* ------------------------------------------------------------------
 * 写一条指令：RS = 0
 * ------------------------------------------------------------------ */
void LCD_WriteCmd(unsigned char cmd)
{
    LCD_RS   = 0;                   /* 目标是“指令寄存器” */
    LCD_RW   = 0;                   /* 方向是“写” */
    LCD_DATA = cmd;                 /* 数据放上总线并稳定下来 */
    LCD_EN_Pulse();                 /* 打一个使能脉冲，下降沿锁存 */

    if (cmd < 0x03)                 /* 0x01 清屏、0x02 光标复位：要 1.64ms */
        Delay_ms(2);
    else                            /* 其它指令约 40us，短延时已经覆盖 */
        LCD_Delay_short();
}

/* ------------------------------------------------------------------
 * 写一个数据（字符码）：RS = 1
 * ------------------------------------------------------------------ */
void LCD_WriteData(unsigned char dat)
{
    LCD_RS   = 1;                   /* 目标是“数据寄存器” */
    LCD_RW   = 0;                   /* 方向是“写” */
    LCD_DATA = dat;
    LCD_EN_Pulse();
    LCD_Delay_short();              /* 写数据的执行时间是 40us，已覆盖 */
}

/* ------------------------------------------------------------------
 * 初始化：顺序不能换，等待时间不能省
 * ------------------------------------------------------------------ */
void LCD_Init(void)
{
    Delay_ms(50);                   /* 上电后控制器内部复位需要 >15ms，等 50ms 更稳 */

    /* 8 位总线、2 行显示、5×8 点阵；连写三次保证同步（手册要求） */
    LCD_WriteCmd(0x38);
    Delay_ms(5);
    LCD_WriteCmd(0x38);
    LCD_WriteCmd(0x38);

    LCD_WriteCmd(0x0C);             /* 开显示(D=1)、关光标(C=0)、不闪烁(B=0) */
    LCD_WriteCmd(0x06);             /* 写入后地址自动 +1(I/D=1)，整屏不移动(S=0) */
    LCD_WriteCmd(0x01);             /* 清屏，光标回左上角（函数内已等 2ms） */

    LCD_RUN = 1;                    /* 初始化完成，心跳灯灭一下表示走到这里了 */
}

/* ------------------------------------------------------------------
 * 光标定位：第一行 DDRAM 0x00~0x0F，第二行 0x40~0x4F
 * 指令格式 = 0x80 | 地址
 * ------------------------------------------------------------------ */
void LCD_SetCursor(unsigned char row, unsigned char col)
{
    unsigned char addr;

    addr = (row == 0) ? 0x00 : 0x40;    /* 第 0 行从 0x00 起，第 1 行从 0x40 起 */

    if (col > 15) col = 15;             /* 简单边界保护：最多 16 列 */
    LCD_WriteCmd(0x80 | (addr + col));  /* 第二行第 1 格 = 0x80|0x40 = 0xC0 */
}

/* 在指定位置显示一个字符 */
void LCD_ShowChar(unsigned char row, unsigned char col, char c)
{
    LCD_SetCursor(row, col);
    LCD_WriteData((unsigned char)c);
}

/* 在指定位置显示一个以 '\0' 结尾的字符串
 * 注意：本函数不做“超出 16 列就截断”的处理，调用时要自己保证不写超
 */
void LCD_ShowString(unsigned char row, unsigned char col, char *s)
{
    LCD_SetCursor(row, col);
    while (*s != '\0')
        LCD_WriteData((unsigned char)(*s++));
}

/* 显示一个定长十进制数：num = 25、len = 3 → 显示 “025”
 * 定长显示的好处是数字变化时不会因为位数变化而残留旧字符
 */
void LCD_ShowNum(unsigned char row, unsigned char col, unsigned int num, unsigned char len)
{
    unsigned char buf[5];
    unsigned char i;

    if (len > 5) len = 5;                       /* 最多 5 位 */

    for (i = 0; i < len; i++)
    {
        buf[len - 1 - i] = (unsigned char)('0' + num % 10);   /* 从最低位往前填 */
        num /= 10;
    }

    LCD_SetCursor(row, col);
    for (i = 0; i < len; i++)
        LCD_WriteData(buf[i]);
}

/* ------------------------------------------------------------------
 * 可选：读忙标志判忙（比固定延时快得多）
 * 读操作时 D7 = BF，1 表示控制器还在忙
 * 用之前请确认数据总线所在的口可以读（P2 可以，P0 必须加上拉电阻）
 * ------------------------------------------------------------------ */
void LCD_WaitBusy(void)
{
    LCD_DATA = 0xFF;                /* 作输入前先写 1，让内部弱上拉生效 */
    LCD_RS   = 0;                   /* 读状态字 */
    LCD_RW   = 1;                   /* 读模式 */

    do
    {
        LCD_EN = 1;
        LCD_Delay_short();
        LCD_EN = 0;
    } while (LCD_DATA & 0x80);      /* D7 还是 1 → 继续等 */

    LCD_RW = 0;                     /* 恢复成写模式 */
}

void main(void)
{
    unsigned int sec = 0;

    LED_RUN = 0;                    /* 心跳灯先点亮，表示程序开始跑 */

    LCD_Init();                     /* 初始化必须在显示之前 */

    /* 第一行：固定标题，只写一次，之后不再动它 */
    LCD_ShowString(0, 0, "McuStudy LCD1602");

    /* 第二行：做一个每秒 +1 的秒表
     * 关键：只覆盖变化的那几个字符，绝不重新清屏
     */
    LCD_ShowString(1, 0, "Run ");
    LCD_ShowString(1, 9, " s");

    while (1)
    {
        LCD_ShowNum(1, 5, sec, 3);  /* 只刷新第 6~8 这三格 */
        sec++;

        LED_RUN = ~LED_RUN;         /* 心跳灯跟着翻转，一眼看出程序没卡住 */
        Delay_ms(1000);
    }
}

关键代码解析

  • #define LCD_DATA P2——宏定义末尾绝对不能加分号。 写成 #define LCD_DATA P2;，展开后就变成 P2; = cmd;，编译器会报一句让人摸不着头脑的 error C129: missing ';' before ...。
  • LCD_EN_Pulse()——把“拉高 → 延时 → 拉低”封成一个函数， 是因为写指令和写数据都要用，而且将来改成 4 位模式时只需要改这一处。 顺序永远是：先设 RS/RW → 再放数据 → 最后给 EN 脉冲。 把 EN 拉高之后再改数据，数据就没有“稳定时间”，会锁存到错误的值。
  • if (cmd < 0x03) Delay_ms(2);——两条慢指令（0x01 清屏、0x02 光标复位） 单独照顾。用数值比较来区分，比每条指令都等 2ms 快，也比每条都只等 60µs 安全。
  • LCD_WriteCmd(0x80 | (addr + col));——位或运算构造地址指令。 因为地址只占低 7 位，最高位固定是 1，所以用或运算最自然。 注意 0x80 | 0x00 = 0x80（第一行首格）， 0x80 | 0x40 = 0xC0（第二行首格）。
  • LCD_ShowNum(1, 5, sec, 3)——定长显示是关键技巧。 如果只写变化的位数，秒数从 9 变到 10 时会多出一位、从 10 变到 9 时又会残留一个字符 （屏幕上出现“9 0”这种鬼影）。定长补零就没有这个问题，而且不需要清屏。
  • LCD_DATA = 0xFF;——判忙函数里的第一句。 51 的准双向口在作输入前要先写 1，否则内部下拉会把引脚钳在低电平， 读回来永远是 0，判忙就会误判成“一直不忙”。
  • _nop_() 来自 intrins.h——它的作用有两个： 一是提供确定的延时，二是让编译器知道这段循环“有副作用”， 否则某些优化等级下空循环可能被整段删掉，延时直接变成 0。
调试小技巧：把光标打开

把 LCD_WriteCmd(0x0C) 临时改成 LCD_WriteCmd(0x0F)，屏幕上会出现一个闪烁的光标。 光标停在哪里，就说明控制器认为“当前地址”在哪里—— 排查“字符怎么写到别的地方去了”“字符串是不是写超了”时，这一招比读代码快得多。 调试完记得改回 0x0C。

现象演示说明

正确现象

  1. 上电后背光亮起；大约 50ms 之后第一行出现 McuStudy LCD1602（16 个字符刚好占满一行）。
  2. 第二行显示 Run 000 s，其中数字每秒递增一次：001、002、003……
  3. 数字变化时只有数字那三个格子变，屏幕其余部分完全不动、不闪。
  4. 旋转 10kΩ 电位器，字符会从“看不清”到“清晰”再到“出现黑块”，能找到一个对比度最舒服的位置。
  5. 接在 P1.0 的心跳灯每秒翻转一次，说明主循环在正常转，屏幕不刷新时程序也没卡住。

观察点与判据

你观察到的 说明什么 下一步查什么
背光亮着，但屏幕上一个字符都没有 对比度没调好，或初始化没执行 先调 V0 电位器；确认 V0 确实接了；再确认程序里有 Delay_ms(50) 的上电等待
显示一排 16 个黑方块（调对比度只能变浓变淡） 控制器上电了，但功能设置指令没写进去 检查 EN 脉冲后有没有延时；0x38 是否连写了三次；RS / RW 有没有接反
字符能显示，但有些字不对、缺笔画 数据总线某一位虚接或顺序错位 显示一行 0123456789ABCDEF 逐位对照，量 D0~D7 每根线的通断
第一行正常，第二行怎么都不显示 功能设置写成了单行模式，或第二行地址算错 确认写的是 0x38 而不是 0x30；第二行地址是 0x40，不是 0x10
字符显示位置整体偏掉、写到看不见的地方 列号超了 15，或者字符串长度超出一行 临时把指令改成 0x0F 打开光标，看它停在哪里
整屏每秒闪一下 主循环里重复调用了 LCD_Init() 或 0x01 清屏 把清屏移到初始化里只做一次，刷新改成覆盖式写字符
顺手量一下刷新速度

把 LCD_ShowNum 那一行放进一个循环跑 100 次， 用秒表量总耗时，就能算出“写 3 个字符需要多久”，再乘以 32 就是刷满一屏的时间。 这套数据（固定延时方案的实测刷新率）写进实验报告，正好能引出下一篇的判忙优化。

常见报错排查方案

编译报错：error C129: missing ';' before 'LCD_DATA'

原因：宏定义末尾多写了一个分号——#define LCD_DATA P2;。预处理会把分号一起替换进去，代码就变成 P2; = cmd;，语法自然不成立。

解决：去掉宏定义末尾的分号，写成 #define LCD_DATA P2。这个坑同样适用于 #define FOSC 11059200UL; 之类的写法，凡是宏定义都以“不加分号”为准。

现象：背光亮着，但屏幕上没有任何字符

原因：按可能性从高到低：① V0 对比度引脚悬空或电位器没调；② 上电延时不够（控制器内部复位需要 >15ms，程序还没等够就开始写指令）；③ RS / RW / EN 接错位置，指令根本没进去；④ 数据线与 P2 的顺序整体接反。

解决：先只做一件事——上电后慢慢旋转电位器， 从一端转到另一端，看屏幕有没有出现黑方块或隐约的字。出现了就说明硬件通路是好的，问题在初始化； 全程毫无变化，就用量万用表确认 V0 的电压确实在 0~5V 之间可调（正常清晰显示时 V0 大约在 0.5~1.5V）。

现象：屏幕显示一排 16 个黑方块，怎么调对比度都不消失

原因：控制器已经上电并完成了内部复位（所以有方块），但初始化指令没有被正确接收。常见原因：EN 脉冲太短（拉高后立刻拉低，不满足 450ns）、0x38 只写了一次导致控制器停在 4 位模式、RW 悬空被当成读模式。

解决：在 EN 拉低之后补一个短延时；把 0x38 连写三次；确认 RW 稳定接在 P3.6 且接地良好。另外把初始化里的三条功能设置指令之间的间隔拉长到 5ms 试试，能通过就说明是时序太急。

现象：字符能显示，但有些字缺笔画、或者显示成别的字符

原因：数据总线上某一位虚接或接错顺序。数据线少一位，字符码就变了——例如 'A'（0x41）可能显示成 'I'；某位虚接则表现为“有时对有时错”。

解决：用 LCD_ShowString(0, 0, "0123456789ABCDEF"); 显示一整行，逐个字符对照正常字模，能快速定位是哪一位出错。然后用万用表通断档量 D0~D7 每一根线：LCD 的 D0 必须接 P2.0，接反顺序是最常见的低级错误。

现象：屏幕整屏一闪一闪，或者文字每秒重刷一次看得出跳动

原因：把 LCD_Init()（里面含 0x01 清屏）放进了主循环。清屏会把 80 字节 DDRAM 全部重写，屏幕必然黑一下再重画，人眼就能看到闪烁。

解决：初始化只在 main 开头调用一次；刷新数据时用“定位 + 覆盖写”的方式，只改动变化的那几格。如果必须整屏更新，也可以先把整行拼进一个 16 字节缓冲数组，再一次性写出去，减少中间状态。

还有两个高频小坑
  • 用 P0 口做数据线的，屏幕上全是乱码或黑块。 P0 是开漏输出，没有内部上拉，写 1 时引脚处于高阻态，LCD 根本读不到高电平。 解决办法是换到 P2，或者给 P0 加一片 10kΩ 排阻上拉到 +5V。
  • 链接警告 WARNING L16: UNCALLED SEGMENT, IGNORED FOR OVERLAY PROCESS。 这是因为本文把 LCD_WaitBusy() 写好了却没有调用它。 它不是错误，只是提醒你有个函数没被使用；真正想用判忙时，把它插到写指令 / 写数据之后替换固定延时即可。

小结与练习

LCD1602 是学“总线时序”最好的教具：它同时具备“多根控制线 + 一个数据总线 + 明确的时序要求”， 又不像高速总线那样难以观测。把下面五句话记住，绝大多数屏幕问题都能自己定位：

  • RS 选对象、RW 定方向、EN 下降沿锁存——三根线的分工。
  • 写完必须等——普通指令 40µs，清屏和光标复位 1.64ms。
  • 初始化顺序不能换——等 50ms → 0x38 连写三次 → 0x0C → 0x06 → 0x01。
  • 地址靠 0x80 + 偏移——第一行 0x00 起，第二行 0x40 起，写成 0xC0 才是第二行第一格。
  • 刷新用覆盖、不要清屏——这是屏幕不闪的唯一诀窍。

另外记住那条最实用的排错经验：背光亮但没字符先查对比度，出现黑方块一定是初始化没进去。 这两句话能省掉你一半的排查时间。

动手练习
  1. 改成 4 位总线。 只接 D4~D7 到 P2.4~P2.7，写出分两次送半字节的 LCD_WriteCmd4 / LCD_WriteData4，并补上 4 位模式专属的唤醒序列（0x33 → 0x32 → 0x28）。 改完后回答：省下来的 4 个 IO 你打算接什么？
  2. 用判忙替换固定延时。 把 LCD_WaitBusy() 插到 LCD_EN_Pulse() 之后， 删掉那些 LCD_Delay_short() 与 Delay_ms(2)， 然后测一下写满一屏 32 个字符的耗时。提示：用定时器 0 计时，或者干脆用秒表量 100 次的总时间。
  3. 做几个自定义字符。 用 CGRAM 画出“℃”“电池”“向上的箭头”三个图标并显示在第二行。 画出点阵的关键是先想清楚每一行哪几列点亮，再把 5 位二进制写成十六进制。
  4. 把上一课的串口接进来。 让电脑发过来的字符直接显示在 LCD 上（收到一个显示一个、自动换行）， 做成一块最简单的“串口屏”。想一想：显示和接收哪个放在中断里更合理？为什么？
