原理介绍

你在 51 上写的 C 代码长这样：定义全局变量、写 main()、 在 while(1) 里操作寄存器。 到了 Arduino，代码变成两个函数、调用一堆带点号的写法、字符串有两种类型—— 这些看起来「不像 C」的东西，其实都是 C++ 的特性。 好消息是：你不需要学完整的 C++， 只要看懂五件事——类、对象、方法、字符串、头文件，Arduino 生态的代码就全都能读了。

为什么 Arduino 用 C++

C 是 C++ 的子集：任何合法的 C 代码几乎都是合法的 C++ 代码。 Arduino 选择 C++ 而不是 C，唯一的原因是它需要「封装」这个能力：

需求C 的做法C++ 的做法（Arduino 用的）
把「一个串口」的配置和数据捆在一起一堆全局变量 + 一堆函数，靠命名区分（uart0_init、uart0_send）一个 HardwareSerial 类，Serial.begin()、Serial.print()
同一个函数处理不同类型写 print_int、print_float、print_str函数重载：都叫 print()，编译器按参数类型挑
让多个设备（3 个串口）用同一套代码复制三份同一个类造三个对象：Serial、Serial1、Serial2
库作者提供接口头文件里放函数声明头文件里放类定义，用户只看到公开方法，内部实现可以改
给你的实用结论

你在 51 上积累的 C 技能一样有效：变量、数组、指针、if、 for、函数、位运算，全都照用。 需要新学的只是「看懂别人用类写的东西」，以及「自己偶尔写一个小类」。 本页的程序三就会带你写一个。

类：一张图纸

类（class）是一张图纸：它规定「这类东西有哪些数据」和「能做哪些操作」， 但本身不占运行时的空间。看一个最像生活的例子——一个 LED： 

class Led {
  private:                 // 内部数据：外面看不到，只能通过下面的方法改
    int  pin;              // 这个 LED 接在哪个引脚
    bool state;            // 当前是亮还是灭

  public:                  // 对外提供的操作面板
    Led(int p) {           // 构造函数：造对象时自动执行，用来初始化
      pin   = p;
      state = false;
    }

    void begin() {         // 初始化硬件
      pinMode(pin, OUTPUT);
      digitalWrite(pin, LOW);
    }

    void on() {
      digitalWrite(pin, HIGH);
      state = true;
    }

    void off() {
      digitalWrite(pin, LOW);
      state = false;
    }

    bool isOn() {          // 查询状态
      return state;
    }
};                         // 注意这个分号，class 定义结束必须有

两个关键词解释一切：

  • private（私有）：图纸的内部电路，外面不能直接碰。别人只能通过 on()/off() 操作，这样你以后想改成「点亮前先检查电压」也不会影响调用者。
  • public（公开）：图纸的操作面板。约定俗成的规矩是：数据私有，操作公开。

对象：按图纸造出来的实物

对象（object）是按图纸造出来的实物，它在运行时实实在在占内存。 用同一个类可以造出很多个对象： 

Led led1(2);      // 造一个 LED 对象，接在 GPIO2（板载 LED）
Led led2(4);      // 再造一个，接在 GPIO4（外接 LED）

void setup() {
  led1.begin();   // 各管各的，互不干扰
  led2.begin();
}

void loop() {
  led1.on();
  led2.off();
  delay(500);
  led1.off();
  led2.on();
  delay(500);
}

现在回头看 Arduino 里最常见的那个 Serial： 它就是 ESP32 core 在启动时替你先造好的一个对象， 属于 HardwareSerial 类。 core 内部的代码大致是： 

// 在 ESP32 Arduino Core 的头文件里：
extern HardwareSerial Serial;    // 声明：有一个叫 Serial 的对象，类型是 HardwareSerial
extern HardwareSerial Serial1;
extern HardwareSerial Serial2;

// 在 core 的源文件里：
HardwareSerial Serial(0);        // 定义：用 0 号 UART 造出来（也就是下载/日志口）
HardwareSerial Serial1(1);       // 1 号 UART
HardwareSerial Serial2(2);       // 2 号 UART

// 所以你写的 Serial.begin(115200) 其实是：
// 「找到名叫 Serial 的那个对象，让它执行 begin，参数是 115200」
// 而 Serial1.begin(9600, SERIAL_8N1, 16, 17) 就是让第二个对象，
// 用 GPIO16/17 当 TX/RX，跑 9600 波特率。
一句话记住类与对象

类 = 图纸（编译期，不占内存）；对象 = 实物（运行期，占内存）。 HardwareSerial 是图纸，Serial、 Serial1、Serial2 是三件实物。 你写 Led led1(2); 就是「照着 Led 图纸造一件实物， 顺便把它的引脚设成 2」。

方法调用：那个点号是什么

Serial.begin(115200) 里的点号读作「的」： 让 Serial 这个对象，执行它的 begin 方法，参数是 115200。 等价于 C 里你可能写过的 uart_init(0, 115200)， 只是 C++ 把「操作谁」写在了前面，读起来更自然。

写法怎么读什么情况用
Serial.begin(115200)Serial 的 begin，参数 115200初始化，必须给参数（波特率）
Serial.println()Serial 的 println，没参数只换行
Serial.println(123)Serial 的 println，参数 123打印数字并换行
Serial.print("abc")Serial 的 print，参数 abc打印后不换行
led1.on()led1 的 on，没参数自定义对象的方法

为什么有的方法要参数有的不要？ 因为参数就是「这次操作需要的信息」。 begin() 必须知道用多快的速度通信，所以它要参数； println() 只是输出一个换行符，不需要额外信息。 另外注意 print 与 println 的唯一区别就是后者末尾多输出一个换行符： 用 print 连续打印会挤在一行，这是新手最常见的「输出看起来乱」的原因。

还有一个 C++ 特性你会经常遇到——函数重载： 同一个名字、不同参数类型，编译器自动挑。 Serial.print() 其实有十几个版本，分别接受整数、浮点、字符串、字符。所以你写 Serial.print(65) 和 Serial.print("65")， 打印出来都是 65，但走的是完全不同的两段代码。

Serial 常用方法速查

方法作用示例
begin(波特率)初始化串口Serial.begin(115200);
print(x)输出文本形式，不换行Serial.print(3.14, 2); → 3.14
println(x)输出文本形式并换行Serial.println("ok");
printf(格式, …)按格式串输出（最好用）Serial.printf("v=%.2f\n", v);
write(字节)发送原始字节，不做任何转换Serial.write(0x41); → 发出字母 A
available()接收缓冲区里还有几个字节if (Serial.available()) …
read()读走一个字节（返回 int，-1 表示没有）int c = Serial.read();
readString()读到一整行字符串（返回 String，慎用）String s = Serial.readString();
readStringUntil('\n')读到指定字符为止自己做命令行交互时常用
flush()等待发送缓冲区发完复位前确保日志发出去
end()关闭串口要用 GPIO1/3 做别的事时
print 与 write 的区别（新手必错）
Serial.print(65);        // 输出两个字符：'6' 和 '5'   （ASCII 0x36 0x35）
Serial.write(65);        // 输出一个字节：0x41         （就是字母 'A'）

Serial.print("A");       // 输出一个字符：'A'          （等于 write(0x41)）
Serial.write("A");       // 输出一个字节：'A'          （同上，因为 "A" 会退化成首字符）

// 结论：
//   要给人看  -> print / println / printf
//   要给设备发协议字节（十六进制指令、二进制帧） -> write

「我明明发了 0x41，串口助手却收到 65」——原因就是用错了 print。

String 类：好用但危险

Arduino 提供了一个 String 类，让你像脚本语言一样拼字符串： 

String msg = "温度: ";
msg += 25.6;                       // 数字自动变字符串
msg += " 度, 设备: ";
msg += "ESP32-01";
Serial.println(msg);
Serial.println(msg.length());      // 字符个数
Serial.println(msg.substring(4, 8)); // 取子串

int   n = String("123").toInt();    // 字符串转数字
float f = String("3.14").toFloat();

看起来很美，但它的每一条「方便」都建立在运行时动态申请内存之上： 每次拼接都可能重新 malloc 一块更大的内存、复制过去、释放旧的。 在一块只有几百 KB 堆、而且必须连续可用的单片机上，这会带来两个后果： 

堆内存示意（[空] 表示空闲块，[占] 表示已分配）

开始：
  [空 200KB ..................................... 连续一大块 ]

反复拼接 String s += "abc"（每次要更大的连续空间）：
  [占小][空 4][占中][空 8][占大][空 2][占更大] ……

最后：
  [占][空][占][空][占][空][占][空][占]
   空闲总量看起来还有 50KB，但没有一块连续空间能放下你要的 1KB。

  结果：malloc 失败 -> 程序崩溃重启
  串口常见：Guru Meditation Error / malloc failed / 堆数字慢慢下降不回升
场景用 String 行不行原因
setup() 里拼一句启动日志可以只执行一次，之后可以 = "" 或让它出作用域
固定格式的报告字符串可以拼接次数有限
在 loop() 里每秒拼接、连续跑几天不要用这就是堆碎片的标准配方，几小时到几天后必崩
接收网络报文再拼接不要用报文长度不可控，容易瞬间申请大块内存
把 String 传给库函数看库的接口很多库只接受 const char*，要写 s.c_str() 转换
真要长期用 String，至少做两件事

① 提前 reserve：msg.reserve(128); 一次申请够，后续拼接不再反复扩容； ② 用完就清：msg = ""; 让缓冲区被回收。
但更推荐的做法是：循环里一律用 char[] + snprintf， 本页程序二会用实测数据让你看到差别。

字符数组与 snprintf

C 语言的字符串就是「一串字符 + 结尾的 \0」。 char buf[32] 是 32 个字节的固定空间， 编译期就分配好，不再申请释放，也就不可能产生碎片。 格式化输出用 snprintf()： 

// ① 固定字符串
char name[] = "ESP32-01";           // 编译器自动算长度：8 个字符 + 1 个 '\0' = 9 字节

// ② 空缓冲区 + snprintf 格式化（最常用）
char buf[64];
float t = 25.63;
int   h = 58;
snprintf(buf, sizeof(buf), "温度: %.1f 度, 湿度: %d%%", t, h);
Serial.println(buf);                // 温度: 25.6 度, 湿度: 58%

// ③ 拼接两个片段：注意把指针往后挪
char line[96];
int pos = 0;
pos += snprintf(line + pos, sizeof(line) - pos, "设备: %s; ", name);
pos += snprintf(line + pos, sizeof(line) - pos, "温度: %.1f;", t);
Serial.println(line);               // 设备: ESP32-01; 温度: 25.6;
要点说明
\0 结尾没有它 Serial.println(buf) 会一直往后读到乱七八糟的内存，输出乱码甚至崩溃
sizeof(buf)整个数组的字节数（32 字节的数组就是 32），不是字符串长度。写 snprintf 时用它当上限，这是防溢出的关键
snprintf 的返回值「本来想写多长」，不一定等于实际写入长度。截断时返回值会大于缓冲区大小，所以按上面的写法要判断是否写满
strcpy / strcat不检查长度，是溢出重灾区。ESP32 上可用 strlcpy() / strlcat()（自带长度限制）
const char*字符串字面量（"abc"）的类型，指向只读区，不能改它的内容

如果你用 String 接收数据、而库函数要 const char*， 用 s.c_str() 转换即可。 但注意 c_str() 返回的指针指向 String 内部缓冲区， String 一变，指针就可能失效——别长期保存它。

命名空间与常量从哪来

你从来没定义过 HIGH、LOW、 INPUT、OUTPUT， 为什么直接就能用？因为它们定义在 Arduino core 的头文件里， 由框架替你 #include 进来了： 

// core 里大致是这样定义的（简化）：
#define HIGH 1
#define LOW  0
#define INPUT        0x01
#define OUTPUT       0x03
#define INPUT_PULLUP 0x05

// LED_BUILTIN 是「板载 LED 的引脚号」，由开发板定义决定：
//   ESP32 Dev Module 上通常等于 2
//   所以你写 digitalWrite(LED_BUILTIN, HIGH) 就等于操作 GPIO2
//   换板子时这个值可能不同，用这个名字比写死 2 更保险

// 命名空间：给名字分门别类，避免重名。
// 标准库的东西都在 std 里，例如 std::string、std::vector，
// Arduino 代码里常写 using namespace std; 就是为了省掉 std:: 前缀。
// ESP32 core 自己也有一些命名空间，比如 arduino::String，
// 平时你用 String 就行，编译器会自动找到。

include 与头文件

#include 是编译前的文本替换：把那个文件的声明复制到你的代码里， 这样编译器才知道 WiFi、Serial 这些名字是什么东西。

写法去哪找例子
#include <WiFi.h>先在系统的 include 路径里找（core、库、SDK 的头文件都在这条路径里）库和 core 提供的头文件
#include "myfile.h"先在你自己的工程目录找，再找系统路径自己写的头文件

「装了库就能 include」的原理就在这里：库安装时会把自己的目录加入编译器的搜索路径， 所以 #include <PubSubClient.h> 才能被你找到。 头文件里通常只有声明（类长什么样、函数怎么调）， 真正的实现在同目录的 .cpp 或预编译库里—— 这也是为什么你改了库的 .cpp 却「没生效」时， 要检查是不是有两个同名库（用户库目录优先）。

串口是调试的眼睛

为什么嵌入式离不开串口打印

在电脑上写程序，你可以打断点、单步、看变量窗口。在单片机上， 这些手段基本都不可用（或者很贵、很麻烦）：

调试手段电脑上ESP32 上评价
串口打印—一条 USB 线就够，几乎零成本主力手段，本页讲的就是它
断点 / 单步标配需要 JTAG 调试器（如 ESP-Prog）+ OpenOCD，配置麻烦值得学，但不是入门必需
LED 闪烁—一个灯只能表达两三种状态只能当「程序活着吗」的心跳
逻辑分析仪 / 示波器—看时序、看波形，几十一百多块就能买到入门款调 I2C/SPI/舵机时序必备
万用表—验证电压、通断、电流上一篇已经用过

串口打印的本质是「把程序内部的思考过程输出出来」。 新手调试最常见的错误是「盯着代码想哪里错了」，而正确的做法是： 在你怀疑的每一步前面加一句打印，跑一遍，看最后打印出的是哪一句—— 程序卡在哪、变量是多少，一目了然。 本页的程序二之所以能让你「看到」堆碎片，用的就是这个办法。

接线与波特率

用板载 USB 口时你不必接任何线：USB 转串口芯片已经和 ESP32 的 GPIO1（TX）、GPIO3（RX） 连好了。 但如果你用外置 USB-TTL 模块（比如给焊在板子上的模组接线），就要注意三点： 

USB-TTL 模块          ESP32
   TX   ────────────►  RX (GPIO3)        <-- 交叉！TX 接对方的 RX
   RX   ◄────────────  TX (GPIO1)
   GND  ─────────────  GND               <-- 必须共地
   3V3  ─────────────  （一般不要接，ESP32 自己有供电）
   5V   ─────────────  VIN（想用模块供电时才接）

  电平警告：如果模块的 TX 是 5V 电平（老式模块），
            必须在 TX 与 ESP32 RX 之间加分压（1kΩ + 2kΩ），
            否则会烧 GPIO3 —— 见上一篇「3.3V 供电与 GPIO 安全」。

  另外：GPIO1/GPIO3 在程序启动时会被 ROM bootloader 用来打印启动日志，
        所以这两个脚不要接别的东西（别接传感器、别接按键）。
要点正确做法错了会怎样
代码里的波特率Serial.begin(115200);不写就完全没有输出（这是新手第一大「没反应」原因）
监视器的波特率同样选 115200不一致就是满屏乱码
串口监视器的「行尾符」只看输出时无所谓；做输入交互时要按代码期望设置（通常「换行符 \n」）用 readStringUntil('\n') 时永远读不到结尾
接外置模块TX/RX 交叉、共地、3.3V 电平不交叉收不到；不共地收到乱码；接 5V 烧脚
用其他串口Serial1.begin(9600, SERIAL_8N1, 16, 17); 指定 RX/TX 引脚不指定引脚就没有输出
顺带说：为什么还要学「不用串口」的调试

串口打印会占用时间（115200 下打印 100 字节约 9 毫秒）和缓冲区。 在中断服务函数里打印可能导致崩溃或丢数据； 在严格时序的场合（比如软件模拟单总线）打印会破坏时序。 所以：平时用串口，时序敏感的地方用逻辑分析仪，硬件问题用万用表。

完整代码

三个程序依次递进：先练「怎么把话说清楚」（打印格式）， 再验证「两种字符串的代价」（内存实测），最后写「自己的第一个类」。 三个都能直接编译上传。

程序一：Serial 打印格式演示

/*
 * ESP32 基础篇 / C++ 与 Arduino API
 * 程序一：Serial 打印格式演示
 *
 * 不需要任何外接元件，只要 USB 线。
 * 目标：搞清 print / println / printf / write 四种输出的区别。
 */

int   iVal = 65;
float fVal = 3.14159;
char  cVal = 'A';

void setup() {
  Serial.begin(115200);     // 不写这一行，后面所有打印都不会出现

程序二：String 与 char[] 对比

这个程序把「反复拼接字符串」做两遍，一遍用 String、 一遍用 char[]，每遍前后都用 ESP.getFreeHeap() 量一下堆内存。跑完你会看到：String 版本把堆吃掉了，而且不会完全还回来。 

/*
 * 程序二：String 与 char[] 的内存代价对比
 *
 * 每个循环拼接 200 次，每次追加 10 个字符（总共 2000 字符）。
 * 分别用两种方式实现，并测量堆内存的前后变化。
 *
 * 观察重点：
 *   ① String 版：拼接后堆明显下降，即使把内容清空也回升不完全 -> 碎片
 *   ② char[] 版：堆完全不变（缓冲区是编译期分配好的）
 */

const int LOOPS = 200;          // 拼接次数
const int CHUNK = 10;           // 每次追加的字符数

void printHeapLine(const char *tag, uint32_t before, uint32_t after) {
  long delta = (long)after - (long)before;
  Serial.printf("%s 堆: %7u -> %7u  净变化 %+ld 字节\n", tag, before, after, delta);
}

// ---------- 方式 A：String ----------
void testString() {
  Serial.println("---- 方式 A：String 拼接 ----");

  uint32_t heapStart = ESP.getFreeHeap();
  Serial.printf("起始空闲堆: %u 字节\n", heapStart);

  String s = "";
  s.reserve(64);                      // 故意给一个「不够用」的初始容量
  for (int i = 0; i < LOOPS; i++) {
    s += "abcdefghij";                // 每次都可能重新 malloc + 复制 + free
  }
  uint32_t heapAfterBuild = ESP.getFreeHeap();

  Serial.printf("拼接完成，字符串长度 %u 字符\n", s.length());
  printHeapLine("[拼接后]", heapStart, heapAfterBuild);

  s = "";                             // 释放内容
  delay(10);                          // 给系统一点时间整理
  uint32_t heapAfterFree = ESP.getFreeHeap();

  printHeapLine("[清空后]", heapStart, heapAfterFree);
  Serial.printf("-> 还差 %ld 字节没有还回来（这就是碎片）\n\n",
                (long)heapStart - (long)heapAfterFree);
}

// ---------- 方式 B：char 数组 ----------
void testCharArray() {
  Serial.println("---- 方式 B：char 数组 + snprintf 拼接 ----");

  // static：放在静态区而不是任务栈上。8KB 的任务栈放不下 2KB 以上的局部数组，
  // 这里用 static 更安全，也顺便说明「空间是编译期就定好的」。
  static char buf[LOOPS * CHUNK + 1];

  uint32_t heapStart = ESP.getFreeHeap();
  Serial.printf("起始空闲堆: %u 字节\n", heapStart);

  int pos = 0;
  for (int i = 0; i < LOOPS; i++) {
    int written = snprintf(buf + pos, sizeof(buf) - pos, "abcdefghij");
    if (written < 0 || written >= (int)(sizeof(buf) - pos)) {
      Serial.println("缓冲区已满，提前结束（这正是我们期望的防溢出行为）");
      break;
    }
    pos += written;
  }
  uint32_t heapAfterBuild = ESP.getFreeHeap();

  Serial.printf("拼接完成，字符串长度 %d 字符\n", pos);
  printHeapLine("[拼接后]", heapStart, heapAfterBuild);

  buf[0] = '\0';                      // 清空只是写一个结束符，内存本来就在那儿
  uint32_t heapAfterFree = ESP.getFreeHeap();
  printHeapLine("[清空后]", heapStart, heapAfterFree);
  Serial.printf("-> 净变化 %+ld 字节（堆完全没动）\n\n",
                (long)heapAfterFree - (long)heapStart);
}

void setup() {
  Serial.begin(115200);
  delay(300);

  Serial.println("==================================================");
  Serial.println("String 与 char[] 的内存代价对比");
  Serial.printf("拼接 %d 次 × %d 字符 = %d 字符\n", LOOPS, CHUNK, LOOPS * CHUNK);
  Serial.printf("测试开始前，空闲堆 %u 字节\n", ESP.getFreeHeap());
  Serial.println("==================================================");

  testString();
  testCharArray();

  Serial.println("==================================================");
  Serial.println("结论：");
  Serial.println("  String     : 方便，但每次拼接都在堆上申请/释放，");
  Serial.println("               长期运行会产生碎片，最终 malloc 失败并重启。");
  Serial.println("  char[]     : 写法啰嗦，但空间固定、零碎片、确定性最好。");
  Serial.println("  工程建议     : 循环里、网络收发、长期运行的程序 —— 用 char[] + snprintf。");
  Serial.println("==================================================");
  Serial.println("下面进入心跳循环，你可以继续观察堆数字是否稳定。");
}

void loop() {
  static unsigned long tick = 0;
  tick++;

  // 心跳：如果这里每轮都掉一点，说明有东西在泄漏内存
  Serial.printf("[心跳 %3lu] 空闲堆 %u 字节 | 历史最小 %u 字节\n",
                tick, ESP.getFreeHeap(), ESP.getMinFreeHeap());

  delay(3000);
}

程序三：自定义类与实例化

最后一个程序写一个真正有用的类：一个「带闪烁功能的 LED」。 它会让你体会类的价值——两个 LED 用同一套代码，各自记着自己的状态。 

/*
 * 程序三：自定义类
 *
 * 接线：GPIO2  -> 板载 LED（不用接线）
 *       GPIO4  -> 外接 LED 正极，负极经 220Ω 电阻接 GND
 *
 * 目标：理解 class（图纸）、对象（实物）、方法（操作）三者的关系。
 */

class Led {
  private:
    int           pin;          // 只属于自己的数据
    bool          state;
    unsigned long lastToggle;
    unsigned long interval;     // 闪烁周期

  public:
    // 构造函数：造对象时自动执行
    Led(int p, unsigned long ms) {
      pin        = p;
      state      = false;
      interval   = ms;
      lastToggle = 0;
    }

    // 初始化硬件（放在 setup 里调用）
    void begin() {
      pinMode(pin, OUTPUT);
      digitalWrite(pin, LOW);
    }

    void on() {
      digitalWrite(pin, HIGH);
      state = true;
    }

    void off() {
      digitalWrite(pin, LOW);
      state = false;
    }

    void toggle() {
      state = !state;
      digitalWrite(pin, state ? HIGH : LOW);
    }

    // 非阻塞闪烁：每次 loop 调用一次，到点自己翻转
    // 注意这里没有 delay —— 两个对象因此可以各自闪烁、互不影响
    bool update(unsigned long now) {
      if (now - lastToggle >= interval) {
        lastToggle = now;
        toggle();
        return true;            // 返回 true 表示「这一轮翻转了」
      }
      return false;
    }

    bool isOn() {
      return state;
    }

    int getPin() {
      return pin;
    }
};

// ---------- 造两个对象 ----------
Led ledFast(2, 200);    // GPIO2 上的板载 LED，200ms 翻转一次
Led ledSlow(4, 1000);   // GPIO4 上的外接 LED，1000ms 翻转一次

void setup() {
  Serial.begin(115200);
  delay(300);

  ledFast.begin();
  ledSlow.begin();

  Serial.println("==================================================");
  Serial.println("自定义类实验：两个 LED 用同一个类，各自独立闪烁");
  Serial.printf("对象 ledFast: 引脚 GPIO%d, 周期 200ms\n", ledFast.getPin());
  Serial.printf("对象 ledSlow: 引脚 GPIO%d, 周期 1000ms\n", ledSlow.getPin());
  Serial.println("关键点：update() 里没有 delay，所以两个对象互不阻塞。");
  Serial.println("==================================================");
}

void loop() {
  unsigned long now = millis();

  // 两个对象各管各的，谁也不用等谁
  if (ledFast.update(now)) {
    Serial.printf("[%6lu ms] ledFast(GPIO%d) 现在 %s\n",
                  now, ledFast.getPin(), ledFast.isOn() ? "亮" : "灭");
  }

  if (ledSlow.update(now)) {
    Serial.printf("[%6lu ms] ledSlow(GPIO%d) 现在 %s\n",
                  now, ledSlow.getPin(), ledSlow.isOn() ? "亮" : "灭");
  }
}
这个类为什么比「两个全局变量 + 一堆函数」好

① 状态跟着对象走：ledFast 的 lastToggle 和 ledSlow 的互不影响， 你不会再写出 lastToggle1、lastToggle2 这种名字； ② 想加第三个 LED 只要再写一行 Led led3(5, 500);； ③ 内部实现可以改：以后想把「翻转」改成 PWM 呼吸灯， 只要改 toggle()，调用它的地方一行都不用动。

关键代码解析

代码作用易错点
Serial.begin(115200)初始化串口漏写 = 一点输出都没有，而且不报错
Serial.println(v, 4)浮点保留 4 位小数不写位数时默认 2 位
Serial.printf("%d", i)格式化输出格式符与类型不匹配会打出垃圾值（unsigned long 要用 %lu，uint32_t 用 %u）
Serial.write(0x41)发原始字节写成 print 就会发出两个字符 65
String s; s += x;动态字符串拼接循环里反复拼接 → 堆碎片；reserve() 能缓解
snprintf(buf, sizeof(buf), …)安全的格式化拼接第二个参数是整个缓冲区大小，不是剩余空间；拼接时要传 sizeof(buf) - pos
ESP.getFreeHeap()查当前空闲堆它是「总量」，找泄漏还要看 ESP.getMinFreeHeap()（历史最小值）
class Led { public: … };定义类结尾的分号别漏；private 数据只能被自己的方法访问
Led ledFast(2, 200);用构造函数造对象定义了带参数的构造函数后，编译器不再生成默认构造函数，写 Led ledFast; 会报错

常见报错排查方案

下面八条是学 C++ / Arduino API 阶段最常见的翻车方式，每条按 现象 → 原因 → 解决 写。

现象：程序上传成功，但串口监视器里一个字都没有

原因： 最常见的原因是忘了写 Serial.begin()—— 没有初始化，Serial.print() 就什么都不发，而且编译器不会报错。 其次要确认监视器波特率也是 115200。

解决： ① 检查 setup() 第一行是不是 Serial.begin(115200);； ② 在它后面加一句 Serial.println("boot ok"); 作为「程序活着」的标志； ③ 监视器波特率改成 115200； ④ 按一下 EN 键重新启动，看是否有启动日志（如果有启动日志但没你的打印，说明卡在 setup 里了）。

现象：程序跑几十分钟到几小时后自己重启，串口打印 Guru Meditation Error、malloc failed 或 rst:0x3 (SW_RESET)

原因： 堆碎片。典型写法是在 loop() 里反复 String msg = "..."; msg += 变量;， 每次拼接都在堆上申请新块、释放旧块，时间一长堆被切成无数小块， 某次需要一块较大的连续内存时就分配失败。 用 ESP.getFreeHeap() 打印能看到它缓慢下降或回升不完全。

解决： ① 循环里的字符串拼接全部改成 char buf[128] + snprintf()（本页程序二的写法）； ② 必须用 String 时加 reserve() 一次性申请够，用完 = "" 释放； ③ 不要用 String 接收网络报文（长度不可控）； ④ 用 ESP.getMinFreeHeap() 观察历史最低点， 如果一路走低，就是泄漏或碎片。

报错原文：invalid operands of types 'const char [8]' and 'const char [6]' to binary 'operator+'

原因： 你在用 + 拼接两个字符串字面量（const char*）。 C++ 里 + 对两个指针没有意义——指针相加只存在于语言层面做地址运算， 不是「连接字符串」。只有至少一侧是 String 对象时， + 才会被重载成拼接。

解决： ① 让左边是 String：String s = String("abc") + "def";； ② 或者更推荐：char buf[32]; snprintf(buf, sizeof(buf), "%s%s", "abc", "def");； ③ 传给只接受 const char* 的库函数时， 用 s.c_str() 转换，别把 String 直接传进去； ④ 注意 c_str() 的指针会随 String 变化而失效，不要长期保存。

现象：想发送十六进制指令 0x41，串口助手却收到字符 65（两个字节）

原因： 用了 Serial.print(0x41)。 print 会把数值转成十进制文本再发出去， 于是 65 被拆成 '6' 和 '5' 两个字节； 而你想要的是一个字节 0x41。

解决： ① 发原始字节用 Serial.write(0x41)； ② 发一串字节用 Serial.write(buf, len)，其中 buf 是 uint8_t[]； ③ 调试协议时建议用「串口助手 + HEX 显示模式」，能看到真实字节而不是被当文本解释的结果； ④ 记住判断标准：给人看用 print，给设备用 write。

现象：串口输出乱码、丢字符，或者打印很快时内容缺几段

原因： ① 代码与监视器波特率不一致（最常见，表现为全篇乱码）； ② 打印速率超过串口带宽：115200 下每秒约 11520 字节， 如果 loop() 里不加延时地狂打印，缓冲区满了就会丢； ③ 监视器软件自身的缓冲或换行符设置问题。

解决： ① 两边统一 115200； ② 打印加节流：用 millis() 保证最快 100ms 打一次， 关键调试信息用 if (debugEnabled) 开关控制； ③ 怀疑丢字符时改打印为「序号 + 内容」，序号跳号就说明中间丢了； ④ 需要高速日志时把波特率提到 921600（双方都要改）。

现象：Serial1 什么都收不到、也没有输出（Serial 正常）

原因： ESP32 有 3 个 UART，但只有 Serial（UART0）默认接好了 USB 转串口芯片。 Serial1 的引脚是可以自由指定的， 不指定就不知道接到哪里，自然没有输出。

解决： ① 初始化时指定引脚：Serial1.begin(9600, SERIAL_8N1, 16, 17); （参数顺序是：波特率、帧格式、RX 引脚、TX 引脚）； ② 接线要交叉：外设 TX → GPIO16（ESP32 的 RX），外设 RX → GPIO17； ③ 共地，并确认外设是 3.3V 电平（5V 要分压）； ④ 别选 GPIO6~11（接 Flash）和输入专用脚 34~39。

报错原文：no matching function for call to 'Led::Led()'

原因： 你给类写了带参数的构造函数（比如 Led(int p, unsigned long ms)）， 之后写了 Led led3; 这种不带参数的声明。 C++ 的规则是：一旦你自己定义了任何构造函数， 编译器就不再自动生成默认构造函数。

解决： ① 声明时把参数补上：Led led3(5, 500);； ② 或者自己补一个默认构造函数：Led() { pin = 2; interval = 500; state = false; }； ③ 更好的做法是用默认参数：Led(int p = 2, unsigned long ms = 500) { … }， 这样既能 Led led3; 也能 Led led3(5, 500);； ④ 顺带检查数组形式的对象：Led leds[3]; 同样要求有默认构造函数。

现象：用 length() 得到的「字符数」比看到的中文字符多一倍

原因： String::length() 和 strlen() 返回的是字节数，不是「字数」。 UTF-8 编码下一个汉字占 3 个字节，所以「温度」的 length 是 6。 按字节截断还可能把汉字切成半个，显示成乱码。

解决： ① 明确区分「字节长度」和「显示宽度」，别用字节数去算屏幕排版； ② 需要截断中文时按 UTF-8 的首字节特征判断字符边界，或干脆不要截断； ③ 串口监视器显示正常就说明编码没问题，不要试图「修复」它； ④ 如果要用中文，源文件必须保存为 UTF-8（Arduino IDE 默认就是）。

小结与练习

这一页要你记住的六件事

  • Arduino 用 C++ 只是为了封装；你在 51 上学的 C 语法全部有效。
  • 类 = 图纸，对象 = 实物；Serial 就是 HardwareSerial 类造出来的一个对象。
  • 对象.方法(参数) 读作「让谁做什么」；print 与 println 只差一个换行。
  • print 发文本，write 发原始字节：发协议帧用 write。
  • String 方便但会在堆上反复申请释放，循环里滥用必然产生碎片； 长期运行的程序用 char[] + snprintf。
  • 串口是最便宜也最有效的调试手段：在怀疑的地方加打印，比盯着代码想快十倍。

自检题

  1. 用「图纸 / 实物」的说法解释：HardwareSerial 与 Serial 分别是什么？为什么 HardwareSerial 不占运行内存？
  2. Serial.print(65) 与 Serial.write(65) 分别发出几个字节？分别是什么？
  3. 为什么在 loop() 里写 String s; s += x; 跑几天会重启？请从「堆需要连续空间」的角度解释。
  4. 把 snprintf(buf, sizeof(buf), "%d", n) 里的 sizeof(buf) 改成 strlen(buf) 会发生什么？为什么？
  5. HIGH、OUTPUT、LED_BUILTIN 是从哪来的？为什么不用自己定义？
  6. String 要传给只接受 const char* 的库函数，应该怎么做？为什么不能长期保存转换出来的指针？
  7. 程序三里 update() 没用 delay，为什么两个 LED 还能各自保持节奏？如果用 delay 会怎样？
  8. 你要写一个类来表示「按键」，它至少需要哪些私有数据、哪些公开方法？请写出来（不用写完整实现）。

动手练习

  1. 做一次内存实验：把程序二的 LOOPS 从 200 改成 2000 再跑一遍，记录「清空后没还回来」的字节数。 这个数字随拼接次数增大，就说明碎片在累积。
  2. 用 char[] 重写一段旧代码：找一段你自己以前写的、 在 loop() 里用 String 拼接上报内容的代码， 改写成 snprintf 版本，比较两次运行时 ESP.getMinFreeHeap() 的变化曲线。
  3. 给按键写一个类：包含引脚、上次电平、上次时间； 公开方法 begin()、pressed()（带消抖， 按下返回一次 true）。写完造两个对象，分别接 GPIO4 和 GPIO13， 在串口里看到两个按键互不干扰的打印。
