原理介绍

很多人以为「装个 Keil 就能开发 STM32」，于是卡在第一天：器件列表里翻不到 STM32F103C8，或者代码编译通过却下载不进去。 原因不是操作错了，而是 STM32 的开发环境本来就是 三个软件分工协作，少一个都会在某个环节断掉：

  • Keil MDK（µVision）——编辑器 + 编译器 + 调试器前端。它负责把你的 C 代码翻译成机器码，并驱动 ST-Link 把机器码写进芯片。
  • Device Family Pack（DFP，芯片包）——ST 官方提供的「芯片说明书」：启动文件、寄存器定义头文件、Flash 烧写算法。Keil 本体不含任何具体芯片的信息。
  • STM32CubeMX——图形化配置工具。点几下把引脚、时钟、外设配好，一键生成 HAL 库初始化代码和可以直接打开的 Keil 工程。

从源码到芯片的链路

理解这条链路，你就能明白每一类报错发生在哪一环，也就知道该改哪个设置，而不是乱点。

        │
        │  ① 编译（armclang，Keil 自带）      需要：头文件路径 Include Paths
        ▼
   main.o 等目标文件
        │
        │  ② 链接（armlink）                  需要：HAL 驱动 .c 全部加入工程
        ▼
   Project.axf   （含机器码 + 调试信息）

        │  ③ 转换（fromelf）                  需要：勾选 Create HEX File（可选）
        ▼

芯片包里装了什么（为什么必须装）

Keil MDK 安装完之后，它的 Device 列表是空的一大半—— 它只认识 ARM 内核，不认识 ST 的具体型号。点击 Pack Installer 图标安装 Keil::STM32F1xx_DFP 之后， 下面这些东西才会出现在你的电脑上：

芯片包提供的内容 典型文件 缺了它会怎样
启动文件 startup_stm32f103xb.s 链接报 Undefined symbol Reset_Handler
寄存器与外设定义 stm32f103xb.h 编译报 identifier "GPIOC" is undefined
CMSIS 内核头文件 core_cm3.h 报 cannot open source input file "core_cm3.h"
Flash 烧写算法 STM32F10x_128.FLM 下载报 No Algorithm found for: 08000000H
器件数据库（型号/内存/外设） Pack 内的 .pdsc 描述文件 Device 列表里根本找不到 STM32F103C8
安装芯片包的两种方式
  • 联网安装——Keil 菜单 Pack Installer，左侧展开 STMicroelectronics，右侧 Devices 里选 STM32F1 Series，点 Keil::STM32F1xx_DFP 的 Install。
  • 离线安装——下载 Keil.STM32F1xx_DFP.2.x.x.pack 文件，双击它会自动用 Pack Installer 打开并安装。校园网环境推荐这种方式。

验证有没有装好：Project → Options for Target → Device， 在搜索框输入 STM32F103C8，能选中并看到 Flash 容量 64KB、RAM 20KB 就对了。

时钟树怎么看：8MHz 是怎么变成 72MHz 的

时钟是 STM32 的「心跳」。芯片内部几乎所有东西（内核、总线、外设、SysTick）都是从同一个时钟源分频/倍频出来的， CubeMX 里那个像树一样的图就是干这件事的。蓝药丸的默认路线是： 板载 8MHz 无源晶振 → PLL 九倍频 → 72MHz。逐节点读一遍：

时钟树节点 值 它喂给谁 / 为什么是这个值
HSE 外部高速时钟 8 MHz 板载无源晶振，接在 OSC_IN / OSC_OUT（LQFP48 封装上是 PD0 / PD1）。不用内部 HSI 是因为 HSI 精度差，串口容易乱码
PLL Source HSE 倍频器的输入源必须选 HSE，否则等于白装晶振
PLL Mul 倍频系数 ×9 8MHz × 9 = 72MHz，这是 F103 允许的最高主频
SYSCLK 系统时钟 72 MHz 整棵树的输出，也是工程里 SystemCoreClock 的值
AHB Prescaler /1 HCLK = 72 MHz 内核、SysTick、DMA、SRAM 都跑这个频率（HAL_Delay 的 1ms 就来自它）
APB1 Prescaler /2 PCLK1 = 36 MHz USART2/3、I2C、TIM2~TIM7 挂在这里。注意：APB1 分频不为 1 时，定时器时钟会自动 ×2 变回 72MHz
APB2 Prescaler /1 PCLK2 = 72 MHz GPIO、USART1、SPI1、ADC 挂在这里，所以我们用 USART1 时波特率算得特别准
Flash Latency 2 WS 72MHz 下 Flash 取指来不及，必须插 2 个等待周期；CubeMX 会自动填，不用手改
为什么偏偏选 72MHz 这条路线

因为 72MHz 是 8MHz 的整数倍，而且所有「标准波特率」在 72MHz 下都能整除： 72000000 / (16 × 115200) = 39.0625， 小数部分刚好能用 4 位分数寄存器表示，误差为 0。 换成别的时钟，串口就会出现千分之几的累积误差，长帧通信就会偶发乱码。 这就是「8MHz 晶振 + 9 倍频」成为 STM32F1 默认配置的原因。

为什么必须先使能外设时钟

这是新手第一大坑，而且它的表现非常「像硬件坏了」： 代码一行没错、编译零报错、下载成功，引脚却纹丝不动。 原因在 STM32 的省电设计里——

  • 芯片复位后，所有外设的时钟默认是关闭的（RCC->APB2ENR 里对应位是 0）。
  • 时钟就是数字电路的「节拍」，没有时钟，外设内部的寄存器根本不会响应写入：你写进去的值被丢掉了。
  • 这个丢弃是静默的。不会报错、不会产生异常，程序照样往下跑，只是引脚永远不动。
  • HAL 库的哲学是「时钟由你负责开」——HAL_GPIO_Init() 只写 GPIO 自己的寄存器，不会替你去开 RCC 的时钟门。

所以 CubeMX 生成的每一个 MX_xxx_Init() 里，第一句永远是这个： 

static void MX_GPIO_Init(void)
{
  GPIO_InitTypeDef GPIO_InitStruct = {0};

  /* 开时钟：宏内部展开成 SET_BIT(RCC->APB2ENR, RCC_APB2ENR_IOPCEN);
     IOPCEN 就是 "IO Port C ENable"，置 1 后 GPIOC 的寄存器才可写 */
  __HAL_RCC_GPIOC_CLK_ENABLE();
  __HAL_RCC_GPIOA_CLK_ENABLE();     /* 用哪个端口就开哪个，多开一个没坏处，漏开一定出问题 */

  /* 下面这些配置只有在时钟已经打开的前提下才写得进去 */
  GPIO_InitStruct.Pin   = GPIO_PIN_13;
  GPIO_InitStruct.Mode  = GPIO_MODE_OUTPUT_PP;
  GPIO_InitStruct.Pull  = GPIO_NOPULL;
  GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_HIGH;
  HAL_GPIO_Init(GPIOC, &GPIO_InitStruct);
}
灯不亮时的第一条自查

打开你的 MX_GPIO_Init()，看第一行有没有 __HAL_RCC_GPIOx_CLK_ENABLE()。 每条外设总线对应不同的宏，别开错： GPIOA/B/C、AFIO 在 APB2； USART2/3、TIM2~TIM7、I2C1 在 APB1； USART1、SPI1、ADC1 在 APB2。 拿不准就在 CubeMX 里点一下该外设，它会自动生成对应的使能语句。

USER CODE BEGIN / END 区块的意义

CubeMX 生成的代码只是「骨架」，你写的逻辑要往里填。但 CubeMX 有个特点： 每次点 GENERATE CODE 都会按模板重新输出整个文件。 如果它无脑覆盖，你辛苦写的代码就没了。所以它用注释把文件切成两类地盘： 

/* USER CODE BEGIN Includes */              /* ← 自己 include 的头文件写这里 */
#include <stdio.h>
/* USER CODE END Includes */

/* USER CODE BEGIN PV */                    /* ← 自己定义的全局变量写这里 */
uint8_t rx_byte;
/* USER CODE END PV */

int main(void)
{
  HAL_Init();
  SystemClock_Config();
  MX_GPIO_Init();

  /* USER CODE BEGIN 2 */                  /* ← 上电只执行一次的初始化写这里 */
  /* USER CODE END 2 */

  while (1)
  {
    /* USER CODE BEGIN 3 */                /* ← 主循环逻辑写这里 */
    HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);
    HAL_Delay(500);
    /* USER CODE END 3 */
  }
}

/* USER CODE BEGIN 4 */                    /* ← 自己的回调函数、工具函数写这里 */
/* USER CODE END 4 */

规则只有一句：BEGIN 与 END 之间的内容会被原样保留，块外的任何修改都会在下次生成时被覆盖。 所以别去改 MX_GPIO_Init() 函数体——你改了，下次生成就白改； 要加引脚，回 CubeMX 里点，或者把代码写进 USER CODE 块，用 HAL 调用补配置。

一个好习惯

建好工程后，先什么都不改，直接点一次 GENERATE CODE， 这样你能分清哪些内容是 CubeMX 生成的、哪些是你自己加的。 以后遇到「我明明写了却不见了」，多半就是写在块外面了。

硬件接线说明

环境搭建阶段只需要一片蓝药丸和一个 ST-Link V2（十几块钱那种 USB 棒就行）， 接线只有四根，但接错的后果很典型：接反电源可能烧板，漏接地线会出现「能识别但下载失败」。

ST-Link 与蓝药丸接线表

ST-Link 引脚 蓝药丸引脚 是否必须 说明
SWDIO PA13（板上标 SWDIO） 必须 SWD 双向数据线，Keil 靠它读写芯片内部寄存器
SWCLK PA14（板上标 SWCLK） 必须 SWD 时钟线，由调试器驱动，频率在 Debug 设置里改
GND GND 必须 给两边提供公共参考电位，少了它 SWD 会时通时断
3.3V 3V3 建议 给目标板供电。若蓝药丸已插 USB 供电，这一根可以不接，避免两路电源互相倒灌
RST R（NRST） 可选 调试器可复位目标。当 PA13/PA14 被程序改写导致连不上时，靠它救回来
5V 5V 不用接 蓝药丸板载稳压器会把 5V 降到 3.3V，但调试阶段不需要你从 ST-Link 供 5V

接线示意图

        ST-Link V2                              STM32F103C8T6 蓝药丸
      ┌─────────────┐                          ┌────────────────────────┐
      │        SWDIO├──────────────────────────┤ PA13  (板上标 SWDIO)   │
      │        SWCLK├──────────────────────────┤ PA14  (板上标 SWCLK)   │
      │          GND├──────────────────────────┤ GND                    │
      │          3V3├──────────────────────────┤ 3V3                    │
      │          RST├──────────────────────────┤ R   (NRST，可选的第五根)│
      │           5V├── ─ ─ 不接 ─ ─ ─ ─ ─ ─ ─ ┤ 5V                     │
      └─────────────┘                          │                        │
                                               │ PC13 ──[R]── LED ── 3V3│  ← 板载 LED，低电平点亮
                                               │ BOOT0 跳线帽接 0 侧     │  ← 从 Flash 启动
                                               └────────────────────────┘

  最小可用接法：SWDIO + SWCLK + GND 三根（目标板用 USB 供电）
  连不上的时候再加：3V3 和 RST
  杜邦线尽量短（15cm 以内），排线过长是「有时能连、有时连不上」的常见原因

上电前的检查清单

  1. 先用万用表确认 ST-Link 的 3V3 和 GND 没有接反——反接一次就可能把芯片的电源脚打坏。
  2. 确认 BOOT0 的跳线帽接在 0 一侧（靠 0 的那两个针）。跳错到 1 会进系统存储器，你的程序不会运行。
  3. 只保留一路供电：要么 USB 供，要么 ST-Link 的 3V3 供，别两个同时接。
  4. 接好后先不插电脑，目视复查一遍四根线的顺序，再插 USB。
别把 PA13 / PA14 当普通 IO 用掉

PA13 和 PA14 出厂默认就是 SWD 调试口，你不需要任何配置就能用它们下载程序。 但如果程序里把这两个脚配成了普通输出（比如做 LED 流水灯时图方便）， 芯片一上电就执行那段代码，SWD 口随即失效， 下次就下载不进去了。 救回来的两个办法：① Debug 设置里把连接方式改成 Connect under Reset； ② 按住板上复位键点下载，出现下载进度时再松手。 这也是给足 SWD 引脚存在感的唯一理由——它们不是「空着的两个 IO」。

完整代码

下面这份 main.c 是环境验证程序： 它让板载 LED（PC13）以 1Hz 闪烁。代码是自包含的—— 把 CubeMX 通常生成在 main.c 里的 SystemClock_Config()、MX_GPIO_Init()、Error_Handler() 都写全了，只用 GPIO，不引用其他文件的变量， 整份替换掉工程里的 main.c 就能编译。 它的作用不是「点灯」，而是同时验证三件事：编译链路通、下载链路通、时钟树配对了。 

/* ============================================================================
 * main.c —— STM32F103C8T6 环境验证程序
 * 功能：蓝药丸板载 LED（PC13）以 1Hz 频率闪烁
 * 用途：验证 ①Keil 能编译 HAL 工程 ②ST-Link 能下载 ③时钟树确实跑在 72MHz
 * 说明：本文件自包含，可直接整份替换 CubeMX 生成的 main.c
 * ============================================================================ */

#include "stm32f1xx_hal.h"        /* HAL 库总头文件：把全部外设驱动声明都包含进来 */

/* ------------------------------ 私有函数声明 ------------------------------ */
void SystemClock_Config(void);    /* 时钟配置：HSE 8MHz 经 PLL 倍频到 72MHz */
static void MX_GPIO_Init(void);   /* GPIO 初始化：把 PC13 配成推挽输出 */
void Error_Handler(void);         /* 出错时停在这里，方便调试器断点观察 */

/* ============================================================================
 * main()：程序入口
 * 上电复位后 CPU 从 0x08000000 取中断向量表，跳到 Reset_Handler，
 * 最终调用 main()。单片机程序永不退出，所以结尾必须是死循环。
 * ============================================================================ */
int main(void)
{
  /* 第一步：初始化 HAL 库。它做两件重要的事——
   *   ① 按 SystemCoreClock 设置 Flash 等待周期，保证 72MHz 下取指不出错；
   *   ② 把 SysTick 配成每 1ms 中断一次并累加 uwTick，HAL_Delay() 全靠它计时 */
  HAL_Init();

  /* 第二步：配置时钟。必须在配置外设之前做，因为外设参数（比如波特率）
   *         都是按最终频率算出来的 */
  SystemClock_Config();

  /* 第三步：初始化 GPIO。函数内部第一句就是开 GPIOC 时钟，漏了就白配 */
  MX_GPIO_Init();

  /* 第四步：进主循环。这里就是「你的程序」真正的地盘 */
  while (1)
  {
    HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);  /* 翻转 PC13：亮变灭、灭变亮 */
    HAL_Delay(500);                          /* 阻塞延时 500ms → 亮 0.5s + 灭 0.5s = 1Hz */
  }
}

/* ============================================================================
 * 时钟配置：HSE(8MHz) → PLL ×9 → SYSCLK = 72MHz
 *   AHB = /1  → HCLK  = 72MHz（内核、SysTick）
 *   APB1 = /2 → PCLK1 = 36MHz（TIM2 等，定时器时钟自动 ×2 回到 72MHz）
 *   APB2 = /1 → PCLK2 = 72MHz（GPIO、USART1）
 * ============================================================================ */
void SystemClock_Config(void)
{
  RCC_OscInitTypeDef RCC_OscInitStruct = {0};   /* 振荡器配置结构体，先清零避免随机值 */
  RCC_ClkInitTypeDef RCC_ClkInitStruct = {0};   /* 总线时钟配置结构体 */

  /* ---------- 1. 打开外部晶振，并把 PLL 配成 HSE × 9 ---------- */
  RCC_OscInitStruct.OscillatorType = RCC_OSCILLATORTYPE_HSE;  /* 操作对象：外部高速时钟 */
  RCC_OscInitStruct.HSEState       = RCC_HSE_ON;              /* 使能 8MHz 晶振 */
  RCC_OscInitStruct.HSEPredivValue = RCC_HSE_PREDIV_DIV1;     /* 预分频 /1，进 PLL 前不降频 */
  RCC_OscInitStruct.HSIState       = RCC_HSI_ON;              /* 内部 8MHz 也留着：HSE 起振失败时 HAL 会回退到它 */
  RCC_OscInitStruct.PLL.PLLState   = RCC_PLL_ON;              /* 打开 PLL */
  RCC_OscInitStruct.PLL.PLLSource  = RCC_PLLSOURCE_HSE;       /* PLL 输入源选 HSE */
  RCC_OscInitStruct.PLL.PLLMUL     = RCC_PLL_MUL9;            /* 倍频 ×9 → 8MHz × 9 = 72MHz */

  if (HAL_RCC_OscConfig(&RCC_OscInitStruct) != HAL_OK)
  {
    /* 返回不是 HAL_OK，说明晶振没起振或 PLL 没锁相。
     * 先量 OSC_IN/OSC_OUT 有没有振荡波形，再查两个 20pF 电容有没有虚焊 */
    Error_Handler();
  }

  /* ---------- 2. 把系统时钟切到 PLL 输出，并设置各总线分频 ---------- */
  RCC_ClkInitStruct.ClockType = RCC_CLOCKTYPE_HCLK | RCC_CLOCKTYPE_SYSCLK
                              | RCC_CLOCKTYPE_PCLK1 | RCC_CLOCKTYPE_PCLK2;
  RCC_ClkInitStruct.SYSCLKSource   = RCC_SYSCLKSOURCE_PLLCLK; /* 系统时钟源 = PLL */
  RCC_ClkInitStruct.AHBCLKDivider  = RCC_SYSCLK_DIV1;         /* HCLK  = 72MHz */
  RCC_ClkInitStruct.APB1CLKDivider = RCC_HCLK_DIV2;           /* PCLK1 = 36MHz */
  RCC_ClkInitStruct.APB2CLKDivider = RCC_HCLK_DIV1;           /* PCLK2 = 72MHz */

  /* 第三个参数是 Flash 等待周期：72MHz 必须用 FLASH_LATENCY_2（2 个等待周期），
   * 少了它 CPU 取指快过 Flash 输出，程序会跑飞或进 HardFault */
  if (HAL_RCC_ClockConfig(&RCC_ClkInitStruct, FLASH_LATENCY_2) != HAL_OK)
  {
    Error_Handler();
  }
}

/* ============================================================================
 * GPIO 初始化：只配一个 PC13 推挽输出
 * 蓝药丸的板载 LED 接法是 3V3 → 电阻 → LED → PC13，
 * 所以输出低电平（RESET）点亮、输出高电平（SET）熄灭。
 * ============================================================================ */
static void MX_GPIO_Init(void)
{
  GPIO_InitTypeDef GPIO_InitStruct = {0};

  /* ★ 时钟使能永远放在第一条。
   * 宏展开后是 SET_BIT(RCC->APB2ENR, RCC_APB2ENR_IOPCEN)，即打开 GPIOC 的门控时钟；
   * 不开时钟，下面所有寄存器写入都会被硬件丢弃，而且不会有任何报错 */
  __HAL_RCC_GPIOC_CLK_ENABLE();
  __HAL_RCC_GPIOA_CLK_ENABLE();     /* GPIOA 后面接按键、串口都要用，顺手开掉 */

  /* 先输出高电平，让 LED 一开始是灭的，避免上电瞬间闪一下 */
  HAL_GPIO_WritePin(GPIOC, GPIO_PIN_13, GPIO_PIN_SET);

  GPIO_InitStruct.Pin   = GPIO_PIN_13;                 /* 操作 PC13 */
  GPIO_InitStruct.Mode  = GPIO_MODE_OUTPUT_PP;         /* 推挽输出：既能输出高也能输出低 */
  GPIO_InitStruct.Pull  = GPIO_NOPULL;                 /* 输出模式不需要内部上下拉 */
  GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_HIGH;        /* 输出翻转速度 50MHz；点灯用 LOW 也够，这里留默认高档 */
  HAL_GPIO_Init(GPIOC, &GPIO_InitStruct);              /* 把上面的配置真正写进 GPIOC 寄存器 */
}

/* ============================================================================
 * 出错处理：关中断后死循环
 * 调试时在 while(1) 上打个断点，停下来看调用栈就知道是哪一步失败的
 * ============================================================================ */
void Error_Handler(void)
{
  __disable_irq();                  /* 关总中断，防止 SysTick 继续打断 */
  while (1)
  {
  }
}

关键代码解析

  • HAL_Init()——它必须第一个执行。 内部会调用 HAL_InitTick(TICK_INT_PRIORITY)， 把 SysTick 配成 1ms 中断并开始累加 uwTick。 后面所有 HAL_Delay() 都是读这个计数在空转等待，所以没调 HAL_Init() 的工程里 HAL_Delay() 会立刻返回、延时完全失效。
  • HAL_RCC_OscConfig() 与 HAL_RCC_ClockConfig()——一个管「产生时钟」，一个管「分配时钟」。 注意第二个的 FLASH_LATENCY_2 是位置参数，不是结构体成员，手写时最容易漏。
  • __HAL_RCC_GPIOC_CLK_ENABLE()——一个纯宏，编译后就是一条对 RCC->APB2ENR 的置位指令，没有任何函数调用开销。 记住它的命名规律：__HAL_RCC_ + 「外设名」 + _CLK_ENABLE()。
  • HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13)——HAL 里没有「翻转」硬件操作， 它是先读 ODR 寄存器再取反写回。优点是直白，缺点是读改写不是原子操作， 多任务/中断并发操作同一个引脚时要用 HAL_GPIO_WritePin() 明确写电平。
  • Error_Handler()——HAL 的通用兜底。 它不做任何「修复」，只是把程序停下来。调试阶段这是好事：你能立刻看到失败点， 量产代码里则应该改成复位或报警逻辑。

现象演示说明

环境搭建是「全有或全无」的活儿：现象对了，说明每一步都对；现象不对，下面这张对照表能帮你把范围缩到一环。

正确现象

  1. 编译输出末尾是 0 Error(s), 0 Warning(s).，并显示 Program Size: Code=... RO-data=... RW-data=... ZI-data=...。
  2. 点下载后 Build Output 出现 Programming Done. Verify OK.，蓝药丸上的 PWR 电源灯常亮。
  3. 板载 LED（PC13，靠近排针的那颗）以大约 1 秒一个完整周期闪烁：亮 0.5s、灭 0.5s，节奏均匀。
  4. 按 Ctrl+F5 进调试，程序停在 main() 第一行；按 F5 全速运行，LED 继续闪，说明调试器接管后程序照常跑。
  5. 在 Watch 窗口加入 HAL_GetTick()，每按一次 F10 单步，数值大约增加 1——这直接证明 SysTick 的 1ms 中断在正常工作。

常见报错排查方案

下面五条是环境搭建阶段出现率最高的故障，按「报错原文 → 原因 → 解决」写，方便你直接搜索比对。

Device 列表里找不到 STM32F103C8（或提示 Error: Device not found）

原因：Keil 本体不含任何具体芯片的器件数据库，必须装 Device Family Pack 才会出现 STM32F1 系列。装的是别的系列包（比如只装了 STM32F4xx_DFP）同样找不到。

解决：打开 Pack Installer，在 Devices 里展开 STMicroelectronics → STM32F1 Series，安装 Keil::STM32F1xx_DFP；离线环境就双击 Keil.STM32F1xx_DFP.2.x.x.pack。装完重启 Keil，再在 Options for Target → Device 里搜 STM32F103C8。

编译报错：error: #5: cannot open source input file "stm32f1xx_hal.h": No such file or directory

原因：头文件搜索路径没配。编译器只会去 Include Paths 列出的目录里找头文件，而 HAL 库的头文件在 Drivers 目录下，不在 Core 目录里。

解决：Options for Target → C/C++ → Include Paths，把这四个目录都加进去： Core\Inc、 Drivers\STM32F1xx_HAL_Driver\Inc、 Drivers\CMSIS\Device\ST\STM32F1xx\Include、 Drivers\CMSIS\Include。 另外确认 C/C++ 的 Define 里有 USE_HAL_DRIVER 和 STM32F103xB，缺了会报另一串「未定义」的错误。

下载报错：Error: Flash Download failed - "Cortex-M3"

原因：按可能性从高到低排——① Debug 选项卡里选的调试器不是 ST-Link（比如还是默认的 ULINK/J-LINK）；② SWD 时钟频率太高，杜邦线太长导致信号质量差；③ 目标板没供电；④ 程序把 PA13/PA14 改成了普通 GPIO，SWD 口被占用。

解决：先确认 Debug 下拉框选的是 ST-Link Debugger，Settings → Debug → Port 选 SW、Max Clock 降到 1MHz； 再确认 3V3/GND 已接好；仍然失败就把 Connect 方式改成 Connect under Reset， 或者按住板上复位键点下载、出现进度条再松手——这一步专门对付「SWD 引脚被程序占用」。

No ST-LINK detected / ST-LINK USB communication error

原因：USB 侧的问题，与目标板无关：① ST-Link 驱动没装（Windows 设备管理器里显示黄色感叹号）；② 用的 USB 线只能充电、没有数据线芯；③ ST-Link 被其他软件占用（STM32CubeProgrammer、串口助手、另一个 Keil 实例）。

解决：装官方 ST-Link 驱动后重新插拔；换一根能传数据的 USB 线（拿它连手机能传文件就说明可以）；关掉所有可能占用调试器的软件再试。若设备管理器里出现的是 STM32 STLink 而不是 ST-Link Debug，说明装的是新版独立驱动，Keil 5.3x 需要在 Debug 设置里手动指定 DLL。

下载成功、Verify OK，但板载 LED 纹丝不动

原因：最典型的是 GPIO 时钟没有使能——代码全对、编译零错、下载成功，但对 GPIOC 寄存器的写入被硬件静默丢弃了。其次是程序卡在 Error_Handler()，或者 BOOT0 跳线在 1 侧导致芯片从系统存储器启动。

解决：按这个顺序查：① MX_GPIO_Init() 第一行有没有 __HAL_RCC_GPIOC_CLK_ENABLE()； ② 进 Debug 暂停，看 PC 指针是不是停在 Error_Handler() 的 while(1) 上； ③ 确认 BOOT0 跳线帽在 0 侧； ④ 用万用表量 PC13 对地电压，应该在 0V 与 3.3V 之间来回跳——如果一直 3.3V，说明程序确实没跑到那一行。

另外一类：重新生成代码后，自己写的代码消失了

这不是报错，但同样常见。原因是代码写在了 USER CODE BEGIN/END 块外面， CubeMX 重新生成时按模板覆盖了。 解决：把逻辑挪进对应的 USER CODE 块，或者干脆不在 CubeMX 里重复生成—— 改引脚时只改 MX_GPIO_Init() 之外的部分就行。 养成「生成完先扫一眼 USER CODE 块在哪」的习惯，这类事故可以完全避免。

小结与练习

这一篇把 STM32 的开发环境从「三个软件怎么分工」讲到「线怎么接、设置怎么点、报错怎么查」。 真正需要记住的只有三点：

  • Keil 只认识内核，芯片信息来自芯片包（DFP）——找不到型号、算法缺失、头文件缺失，先怀疑包。
  • 时钟树是 8MHz → PLL ×9 → 72MHz——它决定了延时、波特率、PWM 频率等一切时间相关参数的基准。
  • 外设时钟不使能，一切配置等于没写——这是唯一一个「没有报错却完全不动」的坑，必须形成条件反射。
动手练习
  1. 改闪烁节奏：把 HAL_Delay(500) 改成 100ms，观察 LED 的变化； 再把 500 改成 50，想一想为什么看起来像是「变暗了」而不是「闪得更快」——这正好是下一篇 PWM 调光的引子。
  2. 故意制造第一大坑：把 MX_GPIO_Init() 里的 __HAL_RCC_GPIOC_CLK_ENABLE() 注释掉，重新编译下载，观察 LED 是否完全不动、有没有任何报错。 亲手复现一次，比读十遍文字记得都牢。做完记得改回来。
  3. 证明 SysTick 在工作：把 HAL_GetTick() 的值赋给一个全局变量 uint32_t tick_now;，在 Debug 的 Watch 窗口里观察它。 解释一下：为什么这个变量每秒增加约 1000？如果 SystemCoreClock 显示 8000000，它会变成多少？
