原理介绍

GPIO 是 General Purpose Input Output（通用输入输出）的缩写。 它的本质是一组可以被程序随意控制电平的引脚，每个引脚背后都有一小套硬件电路： 输入方向上有施密特触发器（把带毛刺的模拟电压整形成干净的高低电平）和输入数据寄存器 IDR；输出方向上有输出数据寄存器 ODR、输出驱动级和复用选择器。

STM32F103C8T6 把引脚分成若干「端口」：GPIOA、GPIOB、GPIOC， 每个端口有 16 个引脚（PA0~PA15、PB0~PB15、PC0~PC15）。 不过 LQFP48 封装的蓝药丸并不是每个都引出： 实际能用的是 PA0~PA15、PB0~PB15、PC13~PC15， 其中 PA13/PA14 已经被 SWD 调试口占用（上一篇讲过），PC13 板上接了 LED。

八种工作模式与四种常用

每个引脚都可以被配置成八种模式之一。八种听起来多，其实只要抓住两条线索就能记住： 方向（输入 / 输出） 和 由谁控制（CPU 还是外设）。

模式 HAL 宏怎么写 典型用途 关键特点
浮空输入 GPIO_MODE_INPUT
+ GPIO_NOPULL		 外部已经有上下拉电阻的场合、总线输入 电平完全由外部决定，引脚悬空时读值随机
上拉输入 GPIO_MODE_INPUT
+ GPIO_PULLUP		 按键另一端接 GND 的场合 空闲读到高电平，按下读到低电平
下拉输入 GPIO_MODE_INPUT
+ GPIO_PULLDOWN		 按键另一端接 3.3V 的场合 空闲读到低电平，按下读到高电平
模拟输入 GPIO_MODE_ANALOG ADC 采集电压 断开数字输入缓冲，避免数字电路干扰模拟量
推挽输出 GPIO_MODE_OUTPUT_PP LED、继电器、驱动数字芯片 高、低电平均主动驱动，速度快
开漏输出 GPIO_MODE_OUTPUT_OD I2C 总线、电平转换、多机「线与」 只能主动拉低，高电平靠外部上拉电阻
复用推挽输出 GPIO_MODE_AF_PP USART、SPI、PWM 等外设占用引脚 引脚交给外设控制，CPU 不再直接写它
复用开漏输出 GPIO_MODE_AF_OD 硬件 I2C 的 SDA/SCL 同上，但以开漏形式输出

初学阶段真正会用到的只有四种：推挽输出、开漏输出、上拉输入、下拉输入。 记住两句话就够用了：

  • 要主动驱动一个负载（LED、蜂鸣器），用推挽输出——它能把引脚强推到高电平，也能强拉到低电平。
  • 要把多个设备的信号接在同一根线上，用开漏输出——因为开漏「只能拉低、不能拉高」， 任何一方拉低总线，总线就是低，不会出现两个芯片一个推高一个拉低的打架短路（这叫「线与」）。I2C 就是这么工作的。
推挽与开漏的一句话记忆

推挽 = 能推也能拉（主动输出高和低）； 开漏 = 只能拉、不能推（高电平得靠外面上拉电阻）。 所以开漏输出的电路上如果漏了上拉电阻，现象是「输出低有效、输出高完全没反应」， 很多人会误以为芯片坏了。

GPIO_InitTypeDef 结构体：四个字段管四件事

HAL 库把所有配置项装进一个结构体，填好之后交给 HAL_GPIO_Init() 一次性写进寄存器。字段不多，但每个都有讲究： 

GPIO_InitTypeDef GPIO_InitStruct = {0};   /* 一定要先清零，否则未赋值的字段是随机值 */

/* ① Pin —— 要配置哪些引脚。
 * 可以按位或组合，一次配多个：GPIO_PIN_0 | GPIO_PIN_1
 * 每一个 GPIO_PIN_x 宏就是一个位掩码，GPIO_PIN_13 展开是 0x2000 */
GPIO_InitStruct.Pin   = GPIO_PIN_13;

/* ② Mode —— 工作模式，决定这个引脚是输入还是输出、推挽还是开漏
 * 可选：GPIO_MODE_INPUT / GPIO_MODE_OUTPUT_PP / GPIO_MODE_OUTPUT_OD
 *       GPIO_MODE_AF_PP / GPIO_MODE_AF_OD / GPIO_MODE_ANALOG */
GPIO_InitStruct.Mode  = GPIO_MODE_OUTPUT_PP;

/* ③ Pull —— 内部上下拉。
 * 只有输入模式才起作用：GPIO_PULLUP / GPIO_PULLDOWN / GPIO_NOPULL
 * 输出模式写 GPIO_NOPULL 即可（输出级已经主动驱动了，不需要上下拉）
 * 注意 F1 的内部上下拉电阻约 40kΩ，只够给按键定电平，不能当外部上拉用 */
GPIO_InitStruct.Pull  = GPIO_NOPULL;

/* ④ Speed —— 输出翻转速度，只对输出模式有效
 * 低 / 中 / 高对应约 2MHz / 10MHz / 50MHz
 * 原则：够用即可。速度越高，边沿越陡、EMI 越大、功耗越高。
 * 点灯用 LOW 完全够；SPI、PWM 这类要考虑信号完整性时才用 HIGH */
GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;

HAL_GPIO_Init(GPIOC, &GPIO_InitStruct);   /* 最后一步：把配置写进 GPIOC 寄存器 */
复用同一个结构体时，必须把每个字段都重新赋值

常见写法是定义一个 GPIO_InitStruct，配完 LED 再配按键。 危险在于：如果你第二次只改了 Pin 和 Mode， 却没改 Speed，它会沿用上一次的值—— 而这个值恰好是从「输出模式」带过来的，配输入时虽然被忽略， 但一旦你后面又配输出，行为就和你以为的不一样。 每一段初始化都把四个字段写全，是最省心的习惯。

三个读写函数：WritePin / TogglePin / ReadPin

函数原型 作用 使用要点
void HAL_GPIO_WritePin(GPIO_TypeDef *GPIOx, uint16_t GPIO_Pin, GPIO_PinState PinState) 把指定引脚写成确定电平 用 GPIO_PIN_SET（高）或 GPIO_PIN_RESET（低）。 它写的是 BSRR 寄存器，单条指令完成置位/复位，是原子操作
void HAL_GPIO_TogglePin(GPIO_TypeDef *GPIOx, uint16_t GPIO_Pin) 翻转引脚电平 底层是「读 ODR → 取反 → 写回」，不是原子操作； 中断和主循环同时操作同一引脚时可能丢翻转变电平
GPIO_PinState HAL_GPIO_ReadPin(GPIO_TypeDef *GPIOx, uint16_t GPIO_Pin) 读取引脚当前电平 读的是 IDR 寄存器，返回 GPIO_PIN_SET 或 GPIO_PIN_RESET， 建议用宏比较而不是直接当 0/1 用

三个函数的参数都是「端口 + 引脚」，所以同一段逻辑换引脚只要改这两个参数。 这也是 HAL 相比直接操作寄存器更好维护的地方。

按键为什么要配上下拉？为什么要消抖？

第一个问题：不配上拉或下拉，引脚就是一根天线。 按键只是一个机械开关，它只有「接通」和「断开」两种状态。 如果我们把按键接在引脚和 GND 之间，那么按下时引脚被接到 GND（明确的低电平）， 但松开时引脚和任何电位都不相连——这叫悬空。 悬空引脚的电压由周围环境的电磁干扰决定，可能读 0、可能读 1，手指靠近都会变， 这就是「不按也会乱触发」的根本原因。 解决办法就是给引脚一个确定电平：配上拉电阻（空闲为高）或下拉电阻（空闲为低）。

第二个问题：机械触点在闭合瞬间会「弹跳」。 金属触点在闭合的几毫秒内会反复通断， 一般持续 5~20ms。 对 72MHz 的单片机来说，这相当于几十万条指令， 如果程序每轮循环都读引脚，就会把一次按下识别成「按了十几次」， 现象是「按一下，LED 闪了好几下」或者「数码管数字乱跳」。

软件消抖的思路很简单，分两步：

1

延时确认

第一次读到现在低电平后不要立刻动作，先延时 20ms（躲过弹跳期），再读一次； 两次都是低电平，才认定是「真的按下了」。

2

等待释放

确认按下之后，等按键松手再返回。否则程序在按住期间会一轮一轮反复上报， 变成「按住不放就连续触发」。等释放的写法是一个 while 循环，边等边延时。

还有更专业的做法

上面是「阻塞式消抖」，简单可靠，适合初学者。 但它会在延时的 20ms 里卡住整个主循环。 更专业的做法有两种：① 用定时器每 10ms 扫描一次按键，连续两次采样一致才更新状态（状态机消抖）； ② 直接把按键接到外部中断引脚，在中断里启动定时器延时再确认。 等学完定时器那一篇，可以回来把这段代码升级掉。

HAL_Delay 靠什么计时

上面两处消抖都用了 HAL_Delay()，它的实现值得说清楚，因为很多人以为它是「空循环估算」。 其实它是靠 SysTick 定时器中断计数的：

  1. HAL_Init() 内部调用 HAL_InitTick()，把 ARM 内核自带的 SysTick 定时器配成 每 1ms 中断一次，中断服务程序里执行 uwTick++；
  2. HAL_Delay(20) 先记下当前 uwTick，然后在一个 while 里反复读取， 直到差值达到 20 才返回——本质是「查表式等待」，不是精确的硬件定时。
两个必须知道的限制
  • 如果没调用 HAL_Init()，SysTick 不计数， HAL_Delay() 会立刻返回，所有延时都失效——按键消抖也就跟着失效了。
  • 不要在优先级高于 SysTick 的中断里调用 HAL_Delay()。 因为那样 SysTick 中断无法抢占，uwTick 不再增加， 程序会永久卡死在这个延时里。这是「串口接收中断里加了个延时，结果整个板子死机」的经典原因。

硬件接线说明

这一节用到两类器件：一个是板载 LED（不用接线，但要记住它是低电平点亮）， 另一个是按键（接 PA0，另一端接 GND，靠单片机内部上拉定电平）。 想把 LED 接在外面练手，就再按表里的 PA1 接一路。

  逻辑对照：
    PC13 板载 LED —— 写 0（RESET）点亮，写 1（SET）熄灭
    PA1  外接 LED —— 写 1（SET）点亮，写 0（RESET）熄灭
    PA0  按键     —— 内部上拉，空闲读到 GPIO_PIN_SET(1)，按下读到 GPIO_PIN_RESET(0)

  为什么按键不外加电阻：STM32 每个 GPIO 内部都有约 40kΩ 的可编程上拉/下拉，
  配 GPIO_PULLUP 就等效于在引脚与 3.3V 之间接了一个 40kΩ 电阻，省掉一个元件。
上电前必查
  • 按键一定要跨接在 PA0 与 GND 之间。四个脚的轻触开关同一侧的两个脚是常通的，别把两端都插在同一侧——这样按键永远处于「一直按下」状态。
  • 外接 LED 的长短脚别插反。插反不会烧，但会「怎么都不亮」，很容易误判成程序问题。
  • 驱动 LED 必须串限流电阻。省掉它，短时间能亮，但电流会超过引脚能力，久了伤引脚也伤 LED。
  • PC13 是特殊引脚：数据手册明确规定它只能灌电流（sink），不能当电流源（source），而且速度不超过 2MHz。所以外部负载不要挂在 PC13 上要求它输出高电平去驱动。

完整代码

功能：按一下 PA0 上的按键，翻转 PC13 板载 LED 的状态， 同时让 PA1 的外接 LED 做相反电平的同步动作。 代码自包含，把 CubeMX 生成的 main.c 整份替换即可编译。 按键扫描函数带着完整的 20ms 消抖和等待释放逻辑，是这段程序最值得细看的地方。 

/* main.h 里通常放引脚宏定义，好处是改引脚只改这一处 */
#ifndef __MAIN_H
#define __MAIN_H

#include "stm32f1xx_hal.h"

/* 板载 LED：PC13，低电平点亮 */
#define LED_Pin          GPIO_PIN_13
#define LED_GPIO_Port    GPIOC

/* 外接 LED：PA1，高电平点亮 */
#define LED2_Pin         GPIO_PIN_1
#define LED2_GPIO_Port   GPIOA

/* 按键：PA0，配内部上拉，按下为低 */
#define KEY_Pin          GPIO_PIN_0
#define KEY_GPIO_Port    GPIOA

#endif /* __MAIN_H */
/* ============================================================================
 * main.c —— STM32F103C8T6 GPIO 输入输出示例
 * 功能：按一下 PA0 上的按键，翻转 PC13 板载 LED；PA1 外接 LED 同步反向变化
 * 要点：① 时钟使能 ② 引脚模式选择 ③ 按键消抖 ④ HAL_Delay 依赖 SysTick
 * ============================================================================ */

#include "main.h"                 /* 里面 include 了 stm32f1xx_hal.h 和引脚宏定义 */
#include <stdio.h>                 /* 本示例没用到 printf，写在这里是提醒它属于 USER CODE Includes */

/* ------------------------------ 私有函数声明 ------------------------------ */
void SystemClock_Config(void);    /* 时钟配置：HSE 8MHz → PLL ×9 → 72MHz */
static void MX_GPIO_Init(void);   /* GPIO 初始化：一个输出 + 一个输出 + 一个输入 */
void Error_Handler(void);         /* 出错时停在这里，方便调试器观察 */
static uint8_t Key_Scan(void);    /* 按键扫描：带消抖，检测到一次完整按下返回 1 */

/* ============================================================================
 * main()：程序入口
 * ============================================================================ */
int main(void)
{
  uint8_t led_on = 0;             /* 记录当前 LED 状态：0 = 灭，1 = 亮 */

  HAL_Init();                     /* 初始化 HAL：设置 Flash 等待周期 + 启动 SysTick 1ms 中断 */
  SystemClock_Config();           /* 配置时钟：72MHz */
  MX_GPIO_Init();                 /* 配置 GPIO：PC13 / PA1 输出，PA0 输入上拉 */

  /* 上电先把两盏灯都置为熄灭状态，避免复位瞬间闪一下 */
  HAL_GPIO_WritePin(LED_GPIO_Port,  LED_Pin,  GPIO_PIN_SET);    /* 板载 LED 低电平点亮 → 置高 = 灭 */
  HAL_GPIO_WritePin(LED2_GPIO_Port, LED2_Pin, GPIO_PIN_RESET);  /* 外接 LED 高电平点亮 → 置低 = 灭 */

  while (1)
  {
    if (Key_Scan() == 1)          /* 只有「检测到一次完整按下」时才返回 1 */
    {
      led_on ^= 1;                /* 状态取反：0 变 1、1 变 0 */

      /* 两盏灯逻辑相反，所以同一个状态要写成相反的引脚电平 */
      HAL_GPIO_WritePin(LED_GPIO_Port,  LED_Pin,
                        led_on ? GPIO_PIN_RESET : GPIO_PIN_SET);
      HAL_GPIO_WritePin(LED2_GPIO_Port, LED2_Pin,
                        led_on ? GPIO_PIN_SET : GPIO_PIN_RESET);
    }
  }
}

/* ============================================================================
 * 按键扫描函数：返回 1 表示「发生了一次按下」（已消抖、已等释放）
 * 返回 0 表示当前没有有效的按键事件
 * 这是最朴素但最可靠的阻塞式消抖，代价是消抖期间主循环被卡住约 20ms
 * ============================================================================ */
static uint8_t Key_Scan(void)
{
  /* 第一遍读：如果读到高电平，说明没按（上拉把引脚拉高了），直接返回 */
  if (HAL_GPIO_ReadPin(KEY_GPIO_Port, KEY_Pin) == GPIO_PIN_RESET)
  {
    HAL_Delay(20);                /* 延时 20ms，跳过机械触点的弹跳期（5~20ms） */

    /* 第二遍读：弹跳结束后仍然是低电平，才认定是「真按下」 */
    if (HAL_GPIO_ReadPin(KEY_GPIO_Port, KEY_Pin) == GPIO_PIN_RESET)
    {
      /* 等待松手：按住不放的期间一直在这里循环，保证一次按下只上报一次 */
      while (HAL_GPIO_ReadPin(KEY_GPIO_Port, KEY_Pin) == GPIO_PIN_RESET)
      {
        HAL_Delay(10);            /* 边等边让出时间，避免空转太频繁 */
      }
      return 1;                   /* 只上报一次按键事件 */
    }
  }
  return 0;                       /* 没按，或只是弹跳产生的假信号 */
}

/* ============================================================================
 * GPIO 初始化
 * 三个引脚：PC13 推挽输出（板载 LED）、PA1 推挽输出（外接 LED）、PA0 输入上拉（按键）
 * ★ 第一句永远是时钟使能：不开时钟，下面所有配置都会被硬件静默丢弃
 * ============================================================================ */
static void MX_GPIO_Init(void)
{
  GPIO_InitTypeDef GPIO_InitStruct = {0};   /* 先清零，避免未赋值的字段是随机值 */

  __HAL_RCC_GPIOA_CLK_ENABLE();             /* PA0 / PA1 在 GPIOA，开 APB2 上的 GPIOA 时钟 */
  __HAL_RCC_GPIOC_CLK_ENABLE();             /* PC13 在 GPIOC */

  /* ---------------- ① PC13：板载 LED，推挽输出 ---------------- */
  HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);   /* 先写灭，避免上电闪一下 */

  GPIO_InitStruct.Pin   = LED_Pin;                /* GPIO_PIN_13 */
  GPIO_InitStruct.Mode  = GPIO_MODE_OUTPUT_PP;    /* 推挽输出：高低都主动驱动 */
  GPIO_InitStruct.Pull  = GPIO_NOPULL;            /* 输出模式不需要上下拉 */
  GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;    /* 点灯用最低速就够，PC13 手册也要求低速 */
  HAL_GPIO_Init(LED_GPIO_Port, &GPIO_InitStruct); /* 写进 GPIOC 寄存器 */

  /* ---------------- ② PA1：外接 LED，推挽输出 ---------------- */
  HAL_GPIO_WritePin(LED2_GPIO_Port, LED2_Pin, GPIO_PIN_RESET);  /* 先写灭 */

  GPIO_InitStruct.Pin   = LED2_Pin;               /* GPIO_PIN_1 */
  GPIO_InitStruct.Mode  = GPIO_MODE_OUTPUT_PP;    /* 同样推挽输出 */
  GPIO_InitStruct.Pull  = GPIO_NOPULL;
  GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;
  HAL_GPIO_Init(LED2_GPIO_Port, &GPIO_InitStruct);

  /* ---------------- ③ PA0：按键，输入 + 内部上拉 ---------------- */
  GPIO_InitStruct.Pin   = KEY_Pin;                /* GPIO_PIN_0 */
  GPIO_InitStruct.Mode  = GPIO_MODE_INPUT;        /* 输入模式 */
  GPIO_InitStruct.Pull  = GPIO_PULLUP;            /* ★ 关键：内部约 40kΩ 上拉，按键松开时引脚确定为高电平 */
  GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;    /* 输入模式下该字段被忽略，但仍写全，避免误读 */
  HAL_GPIO_Init(KEY_GPIO_Port, &GPIO_InitStruct);
}

/* ============================================================================
 * 时钟配置：HSE(8MHz) → PLL ×9 → SYSCLK = 72MHz
 * 与上一篇完全相同，这里一并给出以保证本文件可独立编译
 * ============================================================================ */
void SystemClock_Config(void)
{
  RCC_OscInitTypeDef RCC_OscInitStruct = {0};
  RCC_ClkInitTypeDef RCC_ClkInitStruct = {0};

  RCC_OscInitStruct.OscillatorType = RCC_OSCILLATORTYPE_HSE;  /* 用外部晶振 */
  RCC_OscInitStruct.HSEState       = RCC_HSE_ON;              /* 打开 8MHz 晶振 */
  RCC_OscInitStruct.HSEPredivValue = RCC_HSE_PREDIV_DIV1;     /* 预分频 /1 */
  RCC_OscInitStruct.HSIState       = RCC_HSI_ON;              /* 保留 HSI 作为回退 */
  RCC_OscInitStruct.PLL.PLLState   = RCC_PLL_ON;              /* 打开 PLL */
  RCC_OscInitStruct.PLL.PLLSource  = RCC_PLLSOURCE_HSE;       /* PLL 源选 HSE */
  RCC_OscInitStruct.PLL.PLLMUL     = RCC_PLL_MUL9;            /* ×9 → 72MHz */
  if (HAL_RCC_OscConfig(&RCC_OscInitStruct) != HAL_OK)
  {
    Error_Handler();               /* 晶振没起振 / PLL 没锁定会走到这里 */
  }

  RCC_ClkInitStruct.ClockType = RCC_CLOCKTYPE_HCLK | RCC_CLOCKTYPE_SYSCLK
                              | RCC_CLOCKTYPE_PCLK1 | RCC_CLOCKTYPE_PCLK2;
  RCC_ClkInitStruct.SYSCLKSource   = RCC_SYSCLKSOURCE_PLLCLK; /* 系统时钟用 PLL 输出 */
  RCC_ClkInitStruct.AHBCLKDivider  = RCC_SYSCLK_DIV1;         /* HCLK  = 72MHz */
  RCC_ClkInitStruct.APB1CLKDivider = RCC_HCLK_DIV2;           /* PCLK1 = 36MHz */
  RCC_ClkInitStruct.APB2CLKDivider = RCC_HCLK_DIV1;           /* PCLK2 = 72MHz */
  if (HAL_RCC_ClockConfig(&RCC_ClkInitStruct, FLASH_LATENCY_2) != HAL_OK)
  {
    Error_Handler();               /* 72MHz 必须配 2 个 Flash 等待周期 */
  }
}

/* ============================================================================
 * 出错处理
 * ============================================================================ */
void Error_Handler(void)
{
  __disable_irq();                 /* 关总中断，避免 SysTick 继续打断 */
  while (1)
  {
  }
}

关键代码解析

  • HAL_GPIO_ReadPin() == GPIO_PIN_RESET——注意 HAL 用的是 GPIO_PIN_RESET 这个枚举，不是数字 0。 虽然它的值确实是 0，但用宏能让代码自解释，也避免以后改库时踩坑。 为什么不写成 if (!HAL_GPIO_ReadPin(...))？ 因为这依赖「RESET 就是 0」这个实现细节，属于隐式假设。
  • HAL_Delay(20) 之后的第二次读取才是消抖的核心。 只延时一次不复查的写法，在触点弹跳特别严重的老旧按键上依然会误触发。
  • while (HAL_GPIO_ReadPin(...) == GPIO_PIN_RESET)——等待释放。 少了它，按住不放时主循环会遍历成千上万次，每次都翻转一次 LED， 看起来就是「灯在疯狂闪」，这也是初学者最常见的「按键不听话」现象。
  • led_on ^= 1;——异或 1 就是取反。 用变量记录状态，比直接读回引脚电平更可靠：读回引脚在输出模式下虽然能读， 但如果引脚外部被拉低（比如短路），读回值会和你想的不一样。
  • GPIO_InitStruct.Pull = GPIO_PULLUP;——这一行决定了按键松开时的电平。 把它删掉（或写成 GPIO_NOPULL），你会立刻看到「不按也乱触发」的现象， 值得亲手试一次。
想改成一个按键控制两盏灯交替亮？

把 led_on ^= 1; 换成两个 HAL_GPIO_TogglePin() 调用即可： 分别翻转 PC13 和 PA1。但要注意两盏灯的点亮逻辑相反（一个低电平亮、一个高电平亮）， 所以「同时亮同时灭」需要让两个引脚输出相反的电平，而不是相同的电平。 这个细节正是练习 2 要你亲手验证的内容。

现象演示说明

GPIO 是「看得见摸得着」的一篇，现象非常好判断。建议第一次运行时按下面的顺序观察， 每一步都能对应代码里的某一行。

正确现象

  1. 上电或按复位键之后，PC13 板载 LED 处于熄灭状态（因为程序开头先写了灭）。
  2. 按住 PA0 上的按键不放，LED 状态不发生变化——这是「等待释放」在起作用，是正确行为，不是没反应。
  3. 松开按钮的瞬间，板载 LED 点亮；再按一次、松开，LED 熄灭。如此往复，一次按下对应一次翻转。
  4. 如果接了 PA1 的外接 LED，它会与板载 LED 同时亮、同时灭（因为代码里给的是相反电平，而两个 LED 的点亮逻辑本身就相反）。
  5. 连续快速按十次，LED 老老实实翻转十次，不会出现「按一下闪好几下」。

观察点与判据

你观察到的 说明什么 下一步查什么
不按按键，LED 也会自己乱翻转 PA0 处于悬空状态，读到随机电平 确认 GPIO_InitStruct.Pull = GPIO_PULLUP; 没有被写成 GPIO_NOPULL；确认按键另一端确实接在 GND
按键按下去完全没反应 电平方向反了，或引脚没接对 用万用表量 PA0 对地电压：松开应约 3.3V，按下应约 0V。若一直 3.3V，检查按键是不是插在了同一侧的两个脚上
按一下，LED 连续翻转好几次 消抖没起作用 确认 HAL_Delay(20) 和第二次读取都在；确认 HAL_Init() 被调用过（否则延时失效）
按住不放，LED 疯狂闪烁 缺少「等待释放」的 while 循环 补上 while (HAL_GPIO_ReadPin(KEY_GPIO_Port, KEY_Pin) == GPIO_PIN_RESET)
板载 LED 反了：该亮的时候灭、该灭的时候亮 正常，说明你用的是高电平点亮的思维 记住 PC13 是「低电平点亮」，把两个 GPIO_PIN_SET / RESET 对调即可
什么都不动，包括按键也没反应 多半是 GPIO 时钟没使能，或程序没下载进去 查 MX_GPIO_Init() 第一行的两个 __HAL_RCC_GPIOx_CLK_ENABLE()；再进 Debug 看程序是否卡在 Error_Handler()
顺手记录实验数据

用手机秒表或逻辑分析仪量一下：从电平变化到 LED 真正点亮，中间大约有 20ms 的延迟—— 这正是消抖延时带来的代价。做实训报告时可以把它写成 「按键响应延迟 ≤ 20ms，人眼不可感知，但换来了 100% 的消抖成功率」， 这种量化说明比「效果良好」有价值得多。

常见报错排查方案

GPIO 相关的问题有个特点：大部分不报错，只是行为不对。 所以这一节除了编译错误，也把几种典型的「代码没错但现象错」一起按 「报错/现象原文 → 原因 → 解决」写出来。

编译报错：error: #20: identifier "GPIO_PIN_13" is undefined

原因：当前文件没有包含 HAL 库头文件。写法有两种：直接 #include "stm32f1xx_hal.h"，或者包含了 main.h 而 main.h 里又包含了 HAL 头文件。用了 CubeMX 的 LED_Pin 宏却发现未定义，通常是漏了 #include "main.h"。

解决：在文件顶部补上 #include "main.h"；如果连 main.h 都找不到，去 Options for Target → C/C++ → Include Paths 里把 Core\Inc 加进去。

编译报错：error: #268: declaration may not appear after executable statement in block

原因：这是 C89 的语法限制。Keil 默认的 C 标准较老，变量声明必须写在语句块的最前面；而你在赋值语句之后又声明了变量。

解决：把变量声明挪到函数（或花括号块）的开头；或者到 Options for Target → C/C++ → Misc Controls 里加上 --c99，让编译器按 C99 标准编译。推荐后者，写起来更自由。

现象：代码编译下载都正常，按键按下 LED 毫无反应

原因：按可能性排序——① 按键没有真正接到 PA0（插在面包板同一列的坑里，实际没连通）；② GPIOA 时钟没使能，PA0 的输入配置没生效，读到的永远是 0 或永远是 1；③ 引脚号写错，宏定义里 KEY_Pin 写成了别的引脚；④ 把 PA13/PA14 当成按键脚用了，那两个脚已经归 SWD 调试器所有。

解决：先用万用表量 PA0 对地电压验证接线（松开接近 3.3V、按下接近 0V）； 再检查 MX_GPIO_Init() 里是否同时有 __HAL_RCC_GPIOA_CLK_ENABLE() 和 HAL_GPIO_Init(KEY_GPIO_Port, &GPIO_InitStruct)； 最后在 Debug 里把 HAL_GPIO_ReadPin(KEY_GPIO_Port, KEY_Pin) 加入 Watch 窗口，直接看读到的值。

现象：一次按下触发多次翻转，或按住时 LED 狂闪

原因：前者是缺消抖（机械触点在 5~20ms 内反复通断）；后者是缺「等待释放」的循环，程序在按住期间一轮一轮重复识别成新的按下事件。这两个是初学者写按键代码时最典型的两个缺陷。

解决：把 Key_Scan() 按本页代码补全成三段式： 读一次 → 延时 20ms 再读一次 → while 等释放。 同时确认 HAL_Init() 在 while(1) 之前被调用过， 否则 HAL_Delay() 不工作，消抖会静默失效。

现象：LED 一直亮或一直灭，TogglePin / WritePin 都没效果

原因：GPIO 时钟没使能（写操作被静默丢弃），这是第一大坑；其次是引脚模式配成了输入或模拟模式，输出寄存器写了也传不到引脚；还有一种少见情况：引脚被外设复用（比如配成了 GPIO_MODE_AF_PP），这时 CPU 不再直接控制它。

解决：三步自查——① 第一句是不是 __HAL_RCC_GPIOC_CLK_ENABLE()； ② Mode 是不是 GPIO_MODE_OUTPUT_PP 而不是 GPIO_MODE_INPUT 或 GPIO_MODE_ANALOG； ③ 调试时在 HAL_GPIO_TogglePin() 那一行打断点，看它是否真的被执行到（排除程序卡在 Error_Handler()）。

另外一类：中断里用了 HAL_Delay，结果整块板子死机

现象是串口一收到数据、或者按键一触发中断，程序就再也不动了。 原因不是 GPIO，而是在优先级高于 SysTick 的中断服务函数里调用了 HAL_Delay()： 此时 SysTick 无法抢占该中断，uwTick 停止增加，延时变成无限等待。 解决：中断服务函数里只做最轻的事（记标志、存数据、清标志）， 消抖和业务逻辑一律放回主循环处理。

小结与练习

这一篇把 GPIO 从「模式怎么选」讲到「按键怎么才听话」。需要记住的结论有四条：

  • 推挽输出驱动负载，开漏输出接总线——开漏的高电平必须靠外部上拉电阻，没有上拉就别用开漏。
  • 输入引脚必须给它一个确定电平——上拉或下拉二选一，悬空一定乱。
  • 按键消抖 = 延时复查 + 等释放——两段缺一不可，分别对付弹跳和重复触发。
  • HAL_Delay 依赖 SysTick 的 1ms 中断——它在主循环里很好用，但绝不能在高级别中断里调用。
动手练习
  1. 复现「不按也乱触发」：把 GPIO_InitStruct.Pull = GPIO_PULLUP; 改成 GPIO_NOPULL，重新下载后不要碰按键，观察 LED 是否自己乱闪。 再用手指碰一碰 PA0 的排针，现象会更明显。做完把这一行改回来，并在笔记里写一句结论。
  2. 做成「按一下亮、再按一下灭」的双灯交替：让 PC13 与 PA1 的外接 LED 交替亮 （即一盏亮时另一盏灭）。提示——两个引脚的点亮逻辑相反，先想清楚「同时亮」需要写什么电平组合。
  3. 加一个长按功能：短按（按住不到 1 秒）翻转 LED，长按（按住超过 2 秒）让 LED 快速闪烁三下。 提示——把 Key_Scan() 改成「按下时开始计时、松手时返回按住的时长」， 用 HAL_GetTick() 做时间戳比 HAL_Delay() 更合适，想想为什么。
