综合项目：STM32 数字电压表

把前面三篇学的东西串成一台能用的仪器：分压电路把 0~5V 变成 ADC 能承受的 0~2.5V， 软件滤波把跳动压下去，定点数换算把 ADC 原始值变成毫伏，OLED 用显存缓冲定时刷新—— 全程不闪屏。最后用万用表做一次标定，把误差从 ±2% 压到 ±0.1%。 这一篇不讲新外设，讲的是怎么把零散的知识组织成一个能交付的项目： 每个参数都要能说出为什么选它。

原理介绍

前面三篇各讲了一个零件：ADC 能读出引脚电压、 OLED 能显示字符串和数字、 中断能让按键不丢。 但一台能用的电压表不是把这三个拼起来就完事——中间还差三样东西：

  • 分压电路：ADC 引脚最多只能承受 3.3V，而你测的是 5V 甚至更高。不解决这个，第一次测量就会把引脚打坏。
  • 滤波：单次采样的结果会跳 ±5 个字，直接显示出来末位狂跳，读数根本没法用。
  • 标定：分压电阻有 1% 误差、3.3V 参考电压实际可能是 3.28V，这些误差叠加起来能到 2%。不标定，你的表就是个玩具。

这三件事的共同点是：它们都不是"让程序跑起来"的问题，而是"让结果可信"的问题。 从这一篇开始，你要习惯用工程指标说话：量程是多少、分辨率是多少、误差有多大、刷新多少次每秒。 这些数字定下来，代码才有对错可判。

整体架构与数据流

整个项目的数据只有一条主线，从被测电压一路走到屏幕上。 把这五步的边界划清楚，代码就能分成互不干扰的模块： 硬件分压、采样滤波、定点换算、缓冲绘制、整帧推送。 每一步的输入输出都用整数表示，中间不出现浮点数。

为什么要在第 ④⑤ 步之间拆开

这是本项目最值得学的一个设计。如果每一步算完就直接写屏幕， 那么“清屏 → 写整数位 → 写小数点 → 写小数位”这几个动作之间， 屏幕会短暂地处于“已经清了、还没写完”的状态—— 人眼看到的就是一闪一闪。把绘制和推送分开， 就等于给屏幕加了一层双缓冲：所有中间状态都发生在 RAM 里， 屏幕上永远只呈现画好的完整一帧。

代价是 1024 字节 RAM。STM32F103C8T6 有 20KB，用掉 5%—— 这笔交易非常划算。当你的项目后面要加波形、菜单、图标时， 显存缓冲几乎是必需品：有了它，你可以先画背景再画前景、 先画全屏再覆盖局部，完全不用担心顺序带来的闪烁。

分压电路设计与电阻选型

ADC 引脚的绝对最大额定值是 VDD + 0.3V ≈ 3.6V， 而且这个“能承受”指的是不损坏，不代表能正确测量—— datasheet 明确写了模拟输入范围是 0 ~ VDDA。 要测 5V，必须先用电阻分压把它降到 3.3V 以内。

为什么选 1:1 分压。 5V 经 1:1 分压后是 2.5V，落在 0~3.3V 内，还有 0.8V 余量。 有人会问：为什么不按 5:3.3 ≈ 1.515:1 分压，让 5V 正好对应满量程 3.3V？那样分辨率能提高 32%。答案是：

  • 1:1 用两个相同阻值的电阻，比例误差天然抵消。 分压比 = R2/(R1+R2)，当 R1 = R2 时它就等于 1/2， 与电阻的绝对阻值无关。 哪怕两个电阻都是标称 10kΩ 实际 9.7kΩ，只要它们一致，分压比就还是准确的 1/2。 而 1.515:1 这种比例，你得用两个不同阻值的电阻，两者的误差各自贡献到结果里。
  • 留余量比抠分辨率更重要。 按 1.515:1 精确匹配的话，输入 5.1V 就会让引脚电压达到 3.37V，超范围了。 1:1 分压允许被测电压最高到 6.6V 才开始削顶—— 实际测量中经常遇到“标称 5V 实际 5.2V”的情况，余量就是安全边际。
  • 损失的分辨率可以靠平均补回来一部分。 1:1 分压后用掉 2.5/3.3 = 76% 的量程， 但 24 点平均能把随机噪声压到 1/5 左右， 有效分辨率反而比“不平均的满量程”更高。

接下来的问题是：电阻的阻值该选多大？ 这不是随便填的，两头都有硬约束：

  • 阻值太大 → 读数偏低。 ADC 采样时内部采样电容要从外部电路吸电荷。如果外部电阻大， 这个电容在规定的采样时间内充不满，读出来的值就比实际低， 而且会“记住”上一次的电压（通道间串扰）。
  • 阻值太小 → 费电，还会给被测电路带来负担。 分压电路本身就在持续吸取电流 I = Vx / (R1+R2)。 10kΩ + 10kΩ 在 5V 下是 0.25mA，可以接受； 1kΩ + 1kΩ 就是 2.5mA，一块电池供电的产品撑不住。

分压电路会"吃掉"被测电路的一部分电流

10kΩ + 10kΩ 在 5V 下要吃 0.25mA。如果你测的是电池、传感器输出这类 输出阻抗比较高的信号源，这 0.25mA 会让被测点电压本身就往下掉—— 你测到的已经不是“原来的电压”了。

判断方法：查信号源的输出阻抗。如果它远小于 10kΩ（比如运放输出只有几十欧）， 分压电路的影响可以忽略；如果它本身就有几千欧，就必须 先用一级电压跟随器（运放）做缓冲，再接分压。 这是仪器电路的通用套路：高输入阻抗 + 低输出阻抗。

软件滤波：把跳动压下去

先做个实验感受一下问题的严重性：把 PA1 接到 GND，连续读 100 次 ADC， 你会看到结果在 0、1、2 之间跳。这不是接错线，而是噪声的必然结果—— ADC 内部有热噪声，3.3V 电源上有纹波，导线会拾取干扰。 单次采样永远不可信，必须靠多次采样把噪声平均掉。

最简单的做法是“采 N 次求平均”。但纯平均有个弱点： 它对脉冲干扰毫无防御能力。 假设旁边有个继电器“啪”地动作一下，产生了电磁干扰， 某一次采样读到了 4095（而真实值只有 2000）。 在 32 次平均里，这一个离谱值会把结果整体抬高 (4095-2000)/32 ≈ 65 个字—— 相当于 100mV 的误差，足够让你的显示跳一下。

解决办法是很经典的一招：去极值平均滤波 （也常叫“中值平均滤波”）。流程是： 

  ① 连续采 32 个点，存进数组
        [2010, 2008, 4095, 2012, 2009, 2007, 4093, 2011, ...]

  ② 排序（冒泡即可，32 个元素对 72MHz 的 M3 来说不到 100µs）
        [2007, 2008, 2009, 2010, 2011, 2012, ..., 4093, 4095]

  ③ 丢掉两端各 4 个（共 8 个极值）
        低端丢掉： 2007, 2008, 2009, 2010
        高端丢掉： 4093, 4095, ...（离谱的高值全在这里被扔掉）

  ④ 剩下 24 个求平均
        sum / 24

  ★ 那两个 4095 的干扰值在步骤 ③ 就被物理清除掉了，
    完全不会进入平均值 —— 这就是它比纯平均强的地方。

参数怎么定？这是有依据的，不是拍脑袋：

参数 取值 依据
采样总数 32 噪声抑制比 = 1/√32 ≈ 1/5.7。取到 64 只能再降到 1/8，收益明显递减，而耗时翻倍
每端丢弃数 4 能同时容忍同一侧出现 4 个离谱值，且只损失 25% 的样本。丢 1 个太脆弱，丢 8 个会浪费一半数据

滤波能解决什么，不能解决什么

能解决：随机噪声（平均）、偶发脉冲干扰（去极值）。 这两类问题的共同特征是“没有规律，一会儿高一会儿低”。

不能解决：系统性偏差。 如果分压比错了 2%，那么滤波后的读数依然是错的 2%—— 滤波只能消除随机误差，不能消除系统误差。 消除系统误差的方法只有一个：标定。 这也是为什么这一篇把滤波和标定分成两节讲—— 它们是两类完全不同的问题，用错了工具会白费力气。

定点换算与小数位

现在拿到了一个 0~4095 的整数，要把它变成“4.007V”这样的显示。 新手最容易写出的版本是这样的： 

/* ✗ 能出结果，但在 STM32F1 上不该这么写 */
float voltage = (float)raw * 3.3f / 4095.0f * 2.0f;   /* 引脚电压 × 分压比 */
printf("%.3f", voltage);

这段代码在 72MHz 的 STM32F1 上跑得动，问题是： Cortex-M3 没有硬件浮点单元（FPU）， 所有的 float 运算都要调用软件浮点库，一次乘法几百个时钟周期。 更要命的是，链接器会把整个浮点运算库（几 KB）拉进 Flash—— 对只有 64KB Flash 的 C8T6 来说，这是白白浪费。

正确的做法：用整数单位代替小数。 把“伏特”换成“毫伏”，那么 4.007V 就写成整数 4007。 这样小数点就变成了“显示时才需要关心的事情”—— 计算全程都是整数，没有任何浮点。 

/* 第 1 步：引脚电压（毫伏）= raw × VREF_MV / 4095
 *   最坏情况的中间结果：4095 × 3300 = 13,513,500
 *   uint32_t 的上限是 4,294,967,295 —— 装得下，不会溢出。
 *   ★ 但【乘法必须在除法之前做】：raw / 4095 会先变成 0，全毁了 */
uint32_t mv_pin = ((uint32_t)raw * VREF_MV) / ADC_FULL_SCALE;

/* 第 2 步：还原分压比：被测端电压 = 引脚电压 × R1+R2 / R2
 *   1:1 分压时就是 × 2。写成两个整数（NUM/DEN）而不是 2.0，
 *   这样以后换成别的分压比只要改宏，不用动代码。
 *   中间结果 2500 × 2 = 5000，安全 */
uint32_t mv_in = (mv_pin * DIVIDER_NUM) / DIVIDER_DEN;

/* 第 3 步：套标定系数（增益 ×10000 + 偏移）
 *   把 1.0230 这样的增益写成整数 10230，
 *   计算时再除回 10000 —— 这就是定点数的标准做法：
 *   【把小数放大成整数，算完再缩回去】。
 *   中间结果最大 6600 × 10000 = 66,000,000，安全 */
int32_t mv_cal = (int32_t)((mv_in * CAL_GAIN) / 10000U) + CAL_OFFSET_MV;
if (mv_cal < 0) { mv_cal = 0; }        /* 防止偏移为负时出现负数显示 */
整数运算最容易踩的坑：先除后乘

C 语言的整数除法会直接截断小数部分。 如果写成 (raw / 4095) * 3300， 由于 raw 最大只有 4095，raw / 4095 在绝大多数情况下等于 0， 结果整个式子恒为 0——你会看到屏幕上永远显示 0.000V。

规律很简单：凡是“先除后乘”的整数表达式，几乎一定是错的。 正确顺序永远是先乘后除，并顺手算一下中间结果会不会溢出 （用 uint32_t 装 13,513,500 这种量级毫无压力）。

接下来是小数位怎么拆。 这一步有个非常容易被写反的地方：

想显示 整数部分 小数部分 说明
4.007V（3 位小数） mv / 1000 mv % 1000 取模直接得到 3 位数字 007，宽度设 3、补前导零
4.00V（2 位小数） mv / 1000 (mv % 1000) / 10 必须先取模再除，宽度设 2
电压（1 位小数） mv / 100 (mv % 100) / 10 单位换成“0.1V”，思路一样

注意第二行的括号：写成 mv % 1000 / 10 是对的 （% 和 / 同级，从左到右）， 但写成 mv % (1000 / 10) 就完全变味了—— 那等于 mv % 100，得到的是最后两位数字， 不是“毫伏的前两位小数”。加括号不花时间，别赌优先级。

显示位数不能超过实际精度：这是工科生的基本素养

本项目硬件分辨率是 1.61mV，也就是说相邻两个可能读数之间差 1.61mV， 这已经是最细的粒度了。那么：

  • 显示 0.01V（10mV）——比分辨率粗 6 倍，读数稳定可信，这是诚实的显示方式。
  • 显示 0.001V（1mV）——已经细于分辨率。因为 24 点平均确实能把噪声压下去，所以末位不是纯噪声，但它仍会有 ±1~2 个字的跳动。可以显示，但不能声称最后一位是准的。
  • 显示 0.0001V（0.1mV）——纯粹的假精度。硬件根本没有这个分辨能力，末几位就是随机数。

仪表显示的有效位数应当与实际不确定度匹配。 一台只能做到 ±1% 的表，显示 5 位数字是在骗人。 这一点在写实验报告、做毕设答辩的时候尤其重要： 老师问你“最后一位准吗”，你要能答出分辨率是怎么算出来的。

定时刷新不闪屏

前面在架构里已经说了思路：绘制在 RAM 里做，整帧一次推给屏幕。 这一节把两个配套的细节讲清楚：刷新频率怎么定，以及为什么不能用 HAL_Delay 定时。

刷新频率：5Hz 是有依据的

刷新太快没有意义——人眼对数字变化的反应大约是 100ms 量级， 5Hz（200ms 一次）已经完全跟得上手拧电位器的速度。 而刷新是有成本的，算一笔账： 

【软件模拟 I2C 的位速率】
  每位大约 1µs（取决于 I2C_Delay 里的循环次数）
  每个字节 = 8 位 + 1 个 ACK = 9 个时钟 ≈ 9µs
  加上起始条件、从机地址、控制字节的开销

【刷一页的成本】
  1 页 = 128 字节
  控制字节 0x40 + 128 字节数据 ≈ 129 × 9µs ≈ 1.2ms

【刷全屏的成本】
  8 页 × 1.2ms ≈ 10ms
  加上 SSD1306 内部处理时间和函数调用开销，实测约 15 ~ 25ms

【结论】
  5Hz 刷新 →  每 200ms 里花 20ms 刷屏 →  CPU 时间占用约 10%    ✓ 合理
  50Hz 刷新 → 每 20ms 里花 20ms 刷屏  →  CPU 时间占用 100%     ✗ 主循环别想干别的了

★ 如果以后要做到 30Hz 以上（比如画波形），只有两条路：
   ① 改用硬件 I2C 并把速率提到 400kHz，或改用 SPI 接口的 OLED（快一个数量级）
   ② 只刷新变化了的那几页（脏页标记），而不是每帧推 1024 字节

定时方式：用 HAL_GetTick 做非阻塞判断

在主循环里定时，新手会写 HAL_Delay(200)。 这样写有两个问题：主循环在 200ms 里完全停止， 按键、串口这些事都做不了；而且延时是“从上一次刷完屏开始算”的， 实际周期会变成 200ms + 刷屏时间，长时间下来会有累积漂移。

正确写法是用时间戳做差： if ((HAL_GetTick() - last) >= 200U)。 这样主循环一秒能转几十万圈，每一圈都顺手检查一下“到点了没有”， 到点才刷屏，不到点就继续干别的。 这种写法的专业叫法是“非阻塞定时”或者“软定时器”， 是嵌入式主循环的标准写法。

为什么是相减，而不是比较大小

写成 if (HAL_GetTick() > last + 200U) 也能跑， 但 uwTick 是 uint32_t， 49.7 天之后会溢出回绕到 0。 那一刻 last + 200 可能是一个极大的数， 条件判断会出错——表会“卡”一下，甚至永远不再刷新。

相减的写法天然免疫这个问题： 无符号整数减法在回绕时结果依然正确 （数学上等价于模 2³² 运算）， 所以 HAL_GetTick() - last 永远等于真实经过的时间。 这个技巧在 HAL 库源码里到处都是（比如 HAL_Delay 内部就是这么写的）， 直接照抄这个习惯就行。

标定：用万用表修正系数

这是本项目最有“工程味”的一步，也是从“能显示数字”到“能当仪表用”的分界线。

为什么必须标定。 你的代码里有三个假设，每一个都不严格成立：

  • 假设 VREF_MV = 3300。 实际上 3.3V 是由 LDO（比如 AMS1117-3.3）产生的，它的输出精度是 ±2%， 再叠加负载调整率和温漂。实测经常是 3.27V 或 3.32V。 你的代码按 3300 算，误差就全进来了。
  • 假设 R1 = R2。 1% 精度的电阻意味着 R2/(R1+R2) 的误差最坏可以达到约 2% （两个电阻朝相反方向偏）。
  • 假设 ADC 是理想的。 它自身有偏移误差、增益误差和非线性（F1 的 ADC 积分非线性典型值 ±1.5 LSB）。

关键在于：这些误差都是系统性的、稳定的—— 同一个板子，今天误差 2.25%，明天还是 2.25%（温度不变的话）。 既然是稳定的，就可以用一个系数把它一次性修掉。 这就是标定的全部思想： 用一个已知的准确输入，去量出系统误差有多大，然后把误差写进代码里。

标定的前提：你得有一把更准的尺子

标定的本质是“用一个更准的仪器校准一个不太准的仪器”。 你需要一台可信度比目标精度高一个数量级的基准—— 一块 3 位半或 4 位半的数字万用表就够了， 或者用实验室的台式可调电源（它的显示精度通常不错）。

如果用另一台没校准过的万用表去标定，等于用一个未知误差去修正另一个未知误差。 这一步别偷懒，也别拿手机充电器的“5V”当基准—— 它实际可能在 4.8 ~ 5.3V 之间。

标定步骤（两点法）。 我们用一个“增益 + 偏移”的线性模型： 真实值 = 显示值 × K + B。 具体操作： 

【准备】
  ① 把 CAL_GAIN 设为 10000，CAL_OFFSET_MV 设为 0（相当于不修正）
  ② 烧录程序，让表先按"理论值"工作
  ③ 准备一个可调电压源 + 一台数字万用表，两者并联接在分压电路的输入端

【第一个点：零点】
  ④ 输入端接 GND（0.000V），读表的显示值
     如果显示 0.000V      → 零点好，CAL_OFFSET_MV 保持 0
     如果显示 0.031V      → 记下 +31，后面用 CAL_OFFSET_MV = -31 修掉

【第二组点：取三个工作点】
  ⑤ 调节电压源到 1.000V（以万用表读数为准，不要信电源的刻度）
     记下表的显示值，比如 0.976V
  ⑥ 调到 4.000V，记下显示值，比如 3.912V
  ⑦ 调到 5.000V，记下显示值，比如 4.893V

【算系数】
  ⑧ 每个点算一次增益 K = 万用表读数 / 表的显示值
        K1 = 1.000 / 0.976 = 1.0246
        K2 = 4.000 / 3.912 = 1.0225
        K3 = 5.000 / 4.893 = 1.0219
  ⑨ 取平均（最粗糙的最小二乘法）
        K = (1.0246 + 1.0225 + 1.0219) / 3 = 1.0230
  ⑩ 换算成整数：CAL_GAIN = 10230    （×10000 的定点表示）

【复测】
  ⑪ 改宏、重新编译烧录
  ⑫ 再测 1.000 / 4.000 / 5.000 三个点
        期望：1.000V → 显示 0.999 ~ 1.001V
              4.000V → 显示 3.999 ~ 4.001V
              5.000V → 显示 4.999 ~ 5.001V
  ⑬ 如果零点有偏差，用 CAL_OFFSET_MV 微调，收工

★ 三个点算出的 K 不完全相同（1.0246 / 1.0225 / 1.0219），
  这个"不一致"说明系统除了增益误差还有非线性误差。
  取平均是把它摊平的实用做法；
  要求更高的场合会在多个点做最小二乘直线拟合，
  本项目的精度要求用平均就够了。
万用表读数（基准） 标定前显示 标定前误差 K 值 标定后显示 标定后误差
0.000V0.000V0%—0.000V0%
1.000V0.976V−2.40%1.02460.999V−0.10%
2.500V2.444V−2.24%1.02292.500V0.00%
4.000V3.912V−2.20%1.02254.001V+0.03%
5.000V4.893V−2.14%1.02194.999V−0.02%

用 CAL_GAIN = 10230 之后，全量程误差从 ±2.4% 降到 ±0.1%。 这就是标定的价值：它把三个独立的系统误差（参考电压、分压电阻、ADC 增益）合并成一个系数， 用一次测量全部修掉。你不需要知道到底是 LDO 偏了还是电阻偏了—— 只要误差是整体线性的，一个 K 就够了（如果有零点偏差，再加一个 B）。

标定不是永久有效的

标定系数是在当时的温度、供电电压和这块板子上测出来的。 换一块板子、换了 LDO、或者环境温度从 20℃ 变到 60℃， 系数都可能变化。典型的电阻温漂是 ±50ppm/℃，67℃ 的温差会带来 0.3% 的漂移， 比标定后剩下的 0.1% 还大。

所以严肃的仪表会： ① 用低温漂的电阻（25ppm/℃）；② 用外部基准电压源（比如 REF3033，精度 0.05%）；③ 定期重新标定。 对教学项目来说，把系数写在宏里、在常温下使用，是完全够用的。 但你要知道这个系数的适用范围，并在报告里写清楚。

完整代码

代码分四个文件，正好对应要求里的四部分： ADC 初始化、滤波、换算都在 adc.c 里，OLED 显示 在 oled.c 的增量补丁和 main.c 里。 每个模块只通过头文件暴露的函数和外界打交道，互相不碰对方的内部变量。

第一部分：adc.h

所有“可能要调整的参数”都集中在这个头文件里，用宏定义写清楚。 以后换分压电阻、换平均次数、重新标定，都只改这里，不用翻实现代码。 

/* =====================================================================
 * adc.h —— 数字电压表的采样、滤波与换算模块
 * ---------------------------------------------------------------------
 * 这个头文件把【所有可调参数】集中在一起。
 * 换硬件、重新标定的时候只改这里，不用动 adc.c。
 * ===================================================================== */
#ifndef __ADC_H
#define __ADC_H

/* ★ 必须包含 main.h。
 *   HAL 库的所有类型（ADC_HandleTypeDef、HAL_StatusTypeDef）
 *   都由 main.h 间接包含的 stm32f1xx_hal.h 提供。
 *   漏了这一行，编译会报 "identifier ADC_CHANNEL_1 is undefined"。 */
#include "main.h"

/* ==================== 一、硬件相关参数 ==================== */

/* 参考电压，单位毫伏。
 * ★ 这是标定的第一个对象：别信"3.3V"这三个字。
 *   LDO 的实际输出精度是 ±2%，实测经常是 3270 ~ 3320。
 *   标定时如果你不想动 CAL_GAIN，也可以直接改这里。 */
#define VREF_MV             3300U

/* 12 位 ADC 的满量程计数。
 * ★ 是 4095（2^12 - 1），不是 4096。
 *   写 4096 会让所有读数系统性偏小 0.024%，虽然很小，但没理由错。 */
#define ADC_FULL_SCALE      4095U

/* 分压比：被测端电压 = 引脚电压 × DIVIDER_NUM / DIVIDER_DEN
 * 本项目 R1 = R2 = 10kΩ，分压比 1:1，所以被测端是引脚的 2 倍。
 * ★ 写成两个整数而不是 2.0，一是避免浮点，
 *   二是以后换成 2:1 分压只要改成 3 / 2，代码一行都不用动。 */
#define DIVIDER_NUM         2U
#define DIVIDER_DEN         1U

/* ==================== 二、滤波参数 ==================== */

/* 每次测量连续采样的点数。
 * 32 次能把随机噪声压到 1/√32 ≈ 1/5.7。
 * 加到 64 只能再改善到 1/8，收益递减而耗时翻倍。 */
#define FILTER_SAMPLES      32U

/* 排序后两端各丢弃几个极值（共丢 2 × 4 = 8 个）。
 * 这是"去极值平均滤波"，专门用来对付继电器动作之类的脉冲干扰。 */
#define FILTER_DISCARD      4U

/* ==================== 三、标定参数 ==================== */

/* 增益，用定点表示：10230 表示 1.0230。
 * ★ 出厂默认 10000（= 1.0000，不修正）。
 *   标定后把实测算出的 K × 10000 填在这里，见正文"标定"一节。 */
#define CAL_GAIN            10000U

/* 零点偏移，单位毫伏，可以是负数。
 * 输入端接 GND 时如果显示 0.031V，这里就填 -31。 */
#define CAL_OFFSET_MV       0

/* ==================== 四、对外接口 ==================== */

/* 初始化：做 ADC 自校准，并丢弃校准后的第一次转换结果 */
void     Volt_Init(void);

/* 单次采样，返回 0 ~ 4095 的原始计数。主要给调试和显示 RAW 值用 */
uint16_t Volt_ReadRaw(void);

/* 滤波后的原始计数：采 FILTER_SAMPLES 个点、去极值、求平均 */
uint16_t Volt_ReadFiltered(void);

/* 把原始计数换算成被测端的毫伏值（定点整数，含分压比与标定系数） */
uint32_t Volt_RawToMilliVolt(uint16_t raw);

#endif /* __ADC_H */

第二部分：adc.c

包含三个部分：CubeMX 生成的 ADC 初始化（MX_ADC1_Init 与 HAL_ADC_MspInit）、滤波、定点换算。 初始化部分是由 CubeMX 生成的，我加了逐行注释说明每个参数为什么这么选。 

/* =====================================================================
 * adc.c —— 数字电压表的采样、滤波与换算
 * ---------------------------------------------------------------------
 * 三块内容：
 *   ① MX_ADC1_Init / HAL_ADC_MspInit   —— CubeMX 生成，逐行注释
 *   ② Volt_ReadRaw / Volt_ReadFiltered —— 采样与滤波
 *   ③ Volt_RawToMilliVolt              —— 定点换算
 * ===================================================================== */
#include "adc.h"

/* CubeMX 生成的 ADC 句柄。定义在这里，通过 extern 在别处引用 */
ADC_HandleTypeDef hadc1;

/* =====================================================================
 * ① ADC 初始化（CubeMX 生成 + 我们的注释）
 * ===================================================================== */

/* MSP = MCU Support Package。
 * HAL 把"初始化"拆成两个函数：
 *   HAL_ADC_Init()     —— 初始化外设【内部的寄存器】（CubeMX 生成的 MX_ADC1_Init 调用）
 *   HAL_ADC_MspInit()  —— 初始化外设【外部的东西】：时钟、GPIO、中断（这个回调由我们实现）
 * 这么拆分是为了让 HAL 库能跨芯片系列复用：
 * 内部逻辑一样，外部的引脚和时钟每个芯片不同。 */
void HAL_ADC_MspInit(ADC_HandleTypeDef *adcHandle)
{
    GPIO_InitTypeDef GPIO_InitStruct = {0};

    if (adcHandle->Instance == ADC1)
    {
        /* 开 ADC1 的时钟。★ 忘了这一句，后面所有寄存器操作都无效，
         * 现象是读数恒为 0 或恒为 4095，且没有任何报错 */
        __HAL_RCC_ADC1_CLK_ENABLE();

        /* 开 GPIOA 时钟（PA1 属于 GPIOA） */
        __HAL_RCC_GPIOA_CLK_ENABLE();

        /* 把 PA1 配成模拟输入。
         * ★ 必须是 GPIO_MODE_ANALOG。
         *   如果配成 INPUT 或 OUTPUT，引脚上的数字输入缓冲会使能，
         *   它会和模拟信号"抢"输入，把分压点的电压拉偏。
         * ★ 模拟输入模式下不需要、也不应该配上下拉电阻。 */
        GPIO_InitStruct.Pin  = GPIO_PIN_1;
        GPIO_InitStruct.Mode = GPIO_MODE_ANALOG;
        GPIO_InitStruct.Pull = GPIO_NOPULL;
        HAL_GPIO_Init(GPIOA, &GPIO_InitStruct);
    }
}

/* ADC1 的参数配置。注意 F1 的 ADC 没有"分辨率"这个参数可配，
 * 它天生就是 12 位，不像 F4 可以在 12/10/8/6 位之间选。 */
void MX_ADC1_Init(void)
{
    ADC_ChannelConfTypeDef sConfig = {0};

    hadc1.Instance = ADC1;

    /* 单通道，不需要扫描模式。
     * 扫描模式是"一次触发转换多个通道"，本项目只用 PA1 一个通道 */
    hadc1.Init.ScanConvMode = ADC_SCAN_DISABLE;

    /* 单次转换模式：每次调用 HAL_ADC_Start 才转换一次。
     * 如果设为 ENABLE，ADC 会自己不停地转，
     * 那样每次读到的都是"最新值"，采样时刻不受控 */
    hadc1.Init.ContinuousConvMode = DISABLE;

    /* 不连续转换模式：多通道时才会用到，这里关掉 */
    hadc1.Init.DiscontinuousConvMode = DISABLE;

    /* 软件触发：由 HAL_ADC_Start() 启动转换。
     * 如果选定时器触发，就能做等间隔硬件采样（配合 DMA 做示波器时用） */
    hadc1.Init.ExternalTrigConv = ADC_SOFTWARE_START;

    /* 数据右对齐：12 位结果放在寄存器低 12 位，值是 0 ~ 4095。
     * 如果选左对齐，同样 12 位数据会被挪到高 12 位，
     * 读出来就是 0 ~ 65520 这个范围（每个 LSB 是 16），
     * 换算公式也得跟着改 —— 统一用右对齐最省事 */
    hadc1.Init.DataAlign = ADC_DATAALIGN_RIGHT;

    hadc1.Init.NbrOfConversion = 1;         /* 规则组里只有 1 个通道 */

    if (HAL_ADC_Init(&hadc1) != HAL_OK)
    {
        Error_Handler();                    /* 初始化失败就地报错，不要勉强往下跑 */
    }

    /* 规则通道 1 的具体参数 */
    sConfig.Channel = ADC_CHANNEL_1;        /* PA1 对应 ADC1_IN1 */

    sConfig.Rank = ADC_REGULAR_RANK_1;      /* 规则组的第 1 个（也是唯一一个） */

    /* ★ 采样时间：55.5 个 ADC 周期。
     *
     * ADC 转换分两个阶段：采样阶段（把外部电压"抄"到内部采样电容上）
     * 和转换阶段（逐次逼近，固定 12.5 个周期）。
     * 采样时间就是这个"抄"的动作持续多久。
     *
     * 为什么不能选最短的 1.5 周期？
     *   本项目分压电路的源阻抗 = R1∥R2 = 5kΩ。
     *   采样电容约 8pF，充电时间常数 τ = 5kΩ × 8pF = 40ns。
     *   要充到 12 位精度需要约 9τ = 360ns。
     *   1.5 个周期在 12MHz 下只有 125ns —— 不够，读数会明显偏低。
     *   55.5 个周期 = 4.6µs，有十几倍余量，稳妥。
     *   （C1 那个 100nF 电容在这里帮了大忙：
     *     它相当于一个本地电荷池，采样瞬间由它供电，
     *     外部电阻不需要"临时供货"，建立时间大大缩短。）
     *
     * 代价：采样时间越长，单次转换越慢。
     *   (55.5 + 12.5) 周期 ÷ 12MHz = 5.7µs。
     *   32 次采样 = 182µs，相对 200ms 的刷新周期完全不值一提。 */
    sConfig.SamplingTime = ADC_SAMPLETIME_55CYCLES_5;

    if (HAL_ADC_ConfigChannel(&hadc1, &sConfig) != HAL_OK)
    {
        Error_Handler();
    }
}

/* =====================================================================
 * ② 采样与滤波
 * ===================================================================== */

/* 初始化：自校准 + 丢弃首次转换
 * ★ 必须在 MX_ADC1_Init() 之后调用 */
void Volt_Init(void)
{
    /* F1 的 ADC 每次上电后必须先做一次自校准。
     * 校准电路会测量内部电容阵列的误差并算出修正值，
     * 不校准的话零点可能偏差几十个 LSB（相当于几十毫伏）。
     *
     * ★ 时机要求：必须在 HAL_ADC_Init() 之后、任何一次 Start 之前。
     * ★ 另外，校准要求 ADC 处于关闭状态，
     *   所以不要在转换过程中调用它。 */
    if (HAL_ADCEx_Calibration_Start(&hadc1) != HAL_OK)
    {
        Error_Handler();
    }

    /* 校准完成后的第一次转换结果不可信（内部电路刚切换完状态），
     * 采一次直接扔掉，让后续读数从稳定的状态开始。 */
    (void)Volt_ReadRaw();
}

/* 单次采样：启动 → 等待 → 取值 → 停止 */
uint16_t Volt_ReadRaw(void)
{
    uint16_t value = 0U;

    /* 启动一次转换 */
    HAL_ADC_Start(&hadc1);

    /* 等转换完成，超时 10ms。
     * ★ 这个函数内部靠 HAL_GetTick() 判超时，
     *   所以【不能】在中断服务程序里调用它 —— 会永久卡死。
     *   本函数只在主循环里被调用，安全。 */
    if (HAL_ADC_PollForConversion(&hadc1, 10U) == HAL_OK)
    {
        /* 读结果。右对齐模式下就是 0 ~ 4095 */
        value = (uint16_t)HAL_ADC_GetValue(&hadc1);
    }
    /* 如果超时了，value 保持 0。
     * 在仪表里"读不到就显示 0"是有风险的（0V 是个合法读数，
     * 用户分不清是"真的 0V"还是"坏了"），所以后面的显示逻辑
     * 用独立的错误标志来处理这种情况。 */

    /* 停止转换。
     * ★ 严格来说单次模式下不调用 Stop 也能工作，
     *   但显式 Stop 让每次采样都从同一个干净状态开始，
     *   也方便以后改成"只在需要时开 ADC"来省电。 */
    HAL_ADC_Stop(&hadc1);

    return value;
}

/* 去极值平均滤波 */
uint16_t Volt_ReadFiltered(void)
{
    uint16_t buf[FILTER_SAMPLES];       /* 32 × 2 字节 = 64 字节栈空间，安全 */
    uint32_t sum = 0U;
    uint16_t tmp;
    uint8_t  i, j;

    /* ---- 第 1 步：连续采样 ---- */
    for (i = 0U; i < FILTER_SAMPLES; i++)
    {
        buf[i] = Volt_ReadRaw();
    }

    /* ---- 第 2 步：冒泡排序（升序）----
     * 32 个元素对 72MHz 的 M3 来说约 100µs，相对 200ms 的刷新周期可以忽略。
     * 想优化的话可以换成"只找最大最小的几个"，但可读性会变差，
     * 在 5Hz 的刷新率下完全不值得。 */
    for (i = 0U; i < (FILTER_SAMPLES - 1U); i++)
    {
        for (j = 0U; j < (FILTER_SAMPLES - 1U - i); j++)
        {
            if (buf[j] > buf[j + 1U])
            {
                tmp        = buf[j];
                buf[j]     = buf[j + 1U];
                buf[j + 1U] = tmp;
            }
        }
    }

    /* ---- 第 3 步：丢掉两端各 FILTER_DISCARD 个极值，剩下的求和 ----
     * 排序之后，那些"离谱的干扰值"全被推到数组两端，
     * 这一步就相当于把它们物理删除，不让它们进入平均值。 */
    for (i = FILTER_DISCARD; i < (FILTER_SAMPLES - FILTER_DISCARD); i++)
    {
        sum += buf[i];
    }

    /* ---- 第 4 步：求平均 ----
     * 参与平均的个数 = 32 - 2×4 = 24。
     * 最大值 24 × 4095 = 98,280，uint32_t 装得下。 */
    return (uint16_t)(sum / (FILTER_SAMPLES - (2U * FILTER_DISCARD)));
}

/* =====================================================================
 * ③ 定点换算
 * ===================================================================== */

/* 原始计数 → 被测端毫伏值
 *
 * 三步走，每一步都算一下中间结果的范围，确认不会溢出：
 *
 *   第 1 步  引脚毫伏 = raw × 3300 / 4095
 *            最大 4095 × 3300 = 13,513,500
 *
 *   第 2 步  被测端毫伏 = 引脚毫伏 × 2 / 1
 *            最大 3300 × 2 = 6600
 *
 *   第 3 步  套标定：× CAL_GAIN / 10000 + CAL_OFFSET_MV
 *            最大 6600 × 10000 = 66,000,000
 *
 *   uint32_t 上限 4,294,967,295 —— 三步全部安全。
 *   ★ 如果以后把 VREF_MV 改成微伏（3300000）来做更高精度，
 *     第一步的中间结果会变成 4095 × 3300000 = 1.35e10，
 *     超过 uint32_t 了，那时必须先除后乘或者改用 uint64_t。
 *     【每次改参数，都要重新做一遍这个范围检查。】 */
uint32_t Volt_RawToMilliVolt(uint16_t raw)
{
    uint32_t mv_pin;
    uint32_t mv_in;
    int32_t  mv_cal;

    /* 第 1 步：引脚电压（毫伏）。
     * ★ 必须先乘后除！写成 (raw / 4095) * 3300 的话，
     *   raw 最大才 4095，整数除法会直接把结果截断成 0，
     *   整个表达式恒等于 0 —— 屏幕永远显示 0.000V。 */
    mv_pin = ((uint32_t)raw * VREF_MV) / ADC_FULL_SCALE;

    /* 第 2 步：还原分压比，得到被测端的真实电压（毫伏） */
    mv_in = (mv_pin * DIVIDER_NUM) / DIVIDER_DEN;

    /* 第 3 步：套用标定系数。
     * 增益用 ×10000 的定点表示（10230 → 1.0230），
     * 算完再除回 10000。
     * 偏移用 int32_t 是因为它可能是负数（表读数偏高时）。 */
    mv_cal = (int32_t)((mv_in * CAL_GAIN) / 10000U) + CAL_OFFSET_MV;

    /* 防止负偏移把结果变成负数。
     * 显示层拿到的必须是 0 或正数，否则 mv/1000 和 mv%1000
     * 在负数上的行为会出乎意料（C 语言的负数取模结果也是负数）。 */
    if (mv_cal < 0)
    {
        mv_cal = 0;
    }

    return (uint32_t)mv_cal;
}

第三部分：oled.c 的增量补丁（显存缓冲）

oled.c / oled.h 的完整代码在 上一篇里， 这里不重复。下面是本项目新增的显存缓冲部分—— 把这几段追加到 oled.c 末尾， 并在 oled.h 里加上对应的函数声明即可。 

/* =====================================================================
 * 以下内容追加到上一篇的 oled.c 末尾
 * ---------------------------------------------------------------------
 * 上一篇里 OLED_ShowString / OLED_ShowNum 是【直接写屏幕】的：
 * 调用一次就通过 I2C 发一次数据。简单，但没法做"整帧原子更新"。
 *
 * 这一段加的是【显存缓冲】：
 *   屏幕的 1024 个像素字节在 RAM 里有一个完整副本 g_gram，
 *   所有绘制函数只改这个副本（屏幕毫无变化），
 *   最后调用一次 OLED_Refresh() 把整帧推给屏幕。
 *
 * 好处：屏幕上永远只出现"画好的完整一帧"，看不到任何中间状态。
 * 代价：1024 字节 RAM（20KB 的 5%）。
 *
 * 先在 oled.h 的“对外接口”那一组声明后面，补上这 5 行声明：
 *
 *   void OLED_ClearBuffer(void);
 *   void OLED_DrawChar(uint8_t x, uint8_t page, char c);
 *   void OLED_DrawString(uint8_t x, uint8_t page, const char *str);
 *   void OLED_DrawNumZ(uint8_t x, uint8_t page, uint32_t num, uint8_t len);
 *   void OLED_Refresh(void);
 *
 * ★ 参数顺序统一是【x 在前、page 在后】，和上一篇
 *   OLED_ShowChar(x, y, ch) 的 (x, y) 完全一致 ——
 *   同一个库里出现两种参数顺序，用的人永远记不住。
 * ===================================================================== */

/* SSD1306 的显存结构：OLED_PAGES 页 × OLED_WIDTH 列，每字节竖着管 8 个像素。
 * 8 页 × 128 列 = 1024 字节正好是整个屏幕。
 * ★ 尺寸一律用上一篇 oled.h 里的宏，不要写死 8 和 128：
 *   换成 0.91 寸屏（128×32，把 OLED_PAGES 改成 4）时这里一个字都不用动。 */
static uint8_t g_gram[OLED_PAGES][OLED_WIDTH];

/* 清空显存（只是把 RAM 里这 1024 字节填 0，屏幕不会变） */
void OLED_ClearBuffer(void)
{
    uint8_t page;
    uint8_t col;

    for (page = 0U; page < OLED_PAGES; page++)
    {
        for (col = 0U; col < OLED_WIDTH; col++)
        {
            g_gram[page][col] = 0x00U;
        }
    }
}

/* 往显存里画一个 6×8 的 ASCII 字符
 *   x   ：列坐标（0 ~ 122），每个字符宽 6 像素
 *   page：第几页（0 ~ 7），一页 8 个像素高
 *   c   ：要画的字符
 *
 * ★ 越界判断用的是宏而不是写死的数字：
 *   x 的上限是 OLED_WIDTH-6 = 122 而不是 127 ——
 *   一个字符占 6 列，122 + 5 = 127，正好是最后一列。
 *   传 123 的话会写到数组外面去，破坏别的变量 —— 这是最危险的 bug 类型。 */
void OLED_DrawChar(uint8_t x, uint8_t page, char c)
{
    const uint8_t *font;                /* 指向 6 字节字模 */
    uint8_t i;

    /* 越界保护：宁可什么都不画，也不能写坏内存 */
    if ((x > (OLED_WIDTH - 6U)) || (page >= OLED_PAGES))
    {
        return;
    }

    /* 取字模。
     * Font6x8_Get() 是上一篇 oled.c 里的内部函数（static，本文件内可见），
     * 它自己会把字库里查不到的字符退化成空格，
     * 所以这里不用再判断 c 是不是可打印 ASCII。 */
    font = Font6x8_Get(c);

    /* 把 6 个字节的字模搬进显存 */
    for (i = 0U; i < 6U; i++)
    {
        g_gram[page][x + i] = font[i];
    }
}

/* 往显存里画一个字符串（会自动向右推进，不做换行） */
void OLED_DrawString(uint8_t x, uint8_t page, const char *str)
{
    /* 手工遍历，不调用 strlen —— 免得为了一个长度把 string.h 拉进来 */
    while (*str != '\0')
    {
        OLED_DrawChar(x, page, *str);
        x = (uint8_t)(x + 6U);          /* 每个字符占 6 列 */
        str++;
    }
}

/* 往显存里画一个定宽数字，不足的位补前导 0
 *   num：要显示的数值（非负）
 *   len：固定占几个字符位
 *
 * ★ "定宽"是显示仪表的关键：不管数值是 0.001 还是 5.000，
 *   占的位置永远一样，旧内容一定被覆盖，绝对不需要清屏。
 * ★ 如果 num 的位数比 len 多，高位会被截掉（只显示低 len 位）。
 *   这是定宽显示的必然代价 —— 它换来了"永不残留、永不闪烁"。 */
void OLED_DrawNumZ(uint8_t x, uint8_t page, uint32_t num, uint8_t len)
{
    uint8_t i;
    uint8_t digit;

    /* 从最右边一位开始，往左一位一位地填 */
    for (i = 0U; i < len; i++)
    {
        digit = (uint8_t)(num % 10U);   /* 取出当前最低位 */
        num  /= 10U;                    /* 右移一位，准备下一次 */

        /* 第 i 位（从右数）应该画在从左数第 (len-1-i) 个字符位上 */
        OLED_DrawChar((uint8_t)(x + ((len - 1U - i) * 6U)),
                      page,
                      (char)('0' + digit));
    }
}

/* 把显存整帧推送到屏幕 —— 本项目"不闪屏"的关键就这一个函数
 *
 * 逐页发送：每一页先定位到第 0 列，然后一次发 128 字节。
 * OLED_WriteDataBuf() 是上一篇实现的批量写函数
 * （先发控制字节 0x40 表示"后面都是数据"，然后连续发 128 个字节）。
 *
 * ★ OLED_SetCursor() 的参数顺序是 (列 x, 页 page)，别写反 ——
 *   写反了屏幕不会报错，只会把内容画到莫名其妙的位置上，
 *   这种"不报错的错"最难查。
 *
 * ★ 为什么是"整帧"而不是"只发改动的部分"？
 *   整帧逻辑最简单，而且 8 页 1024 字节在软件 I2C 下约 15~25ms，
 *   5Hz 刷新时 CPU 占用约 10%，完全可接受。
 *   如果要做到 30Hz 以上（画波形），才需要加"脏页标记"：
 *   哪个页被改过就记一个标志，只发被标记的页。 */
void OLED_Refresh(void)
{
    uint8_t page;

    for (page = 0U; page < OLED_PAGES; page++)
    {
        OLED_SetCursor(0U, page);                        /* 定位到这一页的第 0 列 */
        OLED_WriteDataBuf(&g_gram[page][0], OLED_WIDTH); /* 一次推 128 字节 */
    }
}

第四部分：main.c

/* =====================================================================
 * main.c —— STM32 数字电压表主程序
 * ---------------------------------------------------------------------
 * 芯片：STM32F103C8T6（蓝药丸）
 * 量程：0 ~ 6.6V        分辨率：1.61mV        刷新率：5Hz
 *
 * 本文件只做三件事：
 *   ① 初始化各模块
 *   ② 每 200ms 采一次电压
 *   ③ 把结果画进显存并整帧推送
 *
 * 所有算法细节都在 adc.c 和 oled.c 里，main.c 保持"骨架"的样子。
 * ===================================================================== */
#include "main.h"
#include "adc.h"
#include "gpio.h"
#include "oled.h"

/* 刷新周期，单位毫秒。
 * 200ms = 5Hz。人眼对数字变化的反应约 100ms 量级，5Hz 完全跟得上手拧电位器。
 * 全屏刷一次约 15~25ms，5Hz 下 CPU 占用约 10%。 */
#define REFRESH_PERIOD_MS   200U

/* 超量程报警阈值，单位毫伏。
 * 6600mV 对应引脚 3.3V，也就是 ADC 满量程。
 * 超过这个值读数会削顶（永远显示 6.600V），必须提示用户。 */
#define OVER_RANGE_MV       6500U

/* ---------------------------------------------------------------------
 * 把毫伏值画到显存里的指定页：格式为 "X.XXXV"
 *
 * 布局（6×8 字库，每字符宽 6 列）：
 *     列 0   ：整数部分 1 位         x = 0
 *     列 6   ：小数点                x = 6
 *     列 12  ：小数部分 3 位         x = 12, 18, 24
 *     列 30  ：单位 V                x = 30
 *
 * ★ 每一位都是"定宽"的，不管数值怎么变，
 *   这三个数字永远占同样的三格，旧内容一定被覆盖掉。
 * ------------------------------------------------------------------- */
static void Draw_Voltage(uint8_t page, uint32_t mv)
{
    /* 整数部分：本项目量程 0~6.6V，所以整数位只需要 1 位。
     * 补前导 0 的写法让 0.5V 显示成 "0.500V" 而不是 ".500V"。 */
    OLED_DrawNumZ(0U, page, mv / 1000U, 1U);

    /* 小数点固定在整数位后面 */
    OLED_DrawChar(6U, page, '.');

    /* 小数部分：3 位 = 毫伏的低三位。
     * ★ 先取模再补零，一步到位：
     *   mv = 4007 → mv % 1000 = 7 → 补 3 位宽 → "007" → 显示 4.007V
     *   如果是 2 位小数，要写成 (mv % 1000U) / 10U，宽度设 2。 */
    OLED_DrawNumZ(12U, page, mv % 1000U, 3U);

    /* 单位 */
    OLED_DrawChar(30U, page, 'V');
}

/* ---------------------------------------------------------------------
 * 画第二行：原始 ADC 值和滤波参数，方便调试和标定
 *
 * 标定的时候这一行特别有用：你能直接看到 ADC 的原始计数，
 * 从而判断偏差是出在 ADC 侧还是换算侧。
 * ------------------------------------------------------------------- */
static void Draw_Info(uint8_t page, uint16_t raw)
{
    OLED_DrawString(0U, page, "RAW=");

    /* 原始值最大 4095，占 4 位，右对齐补零 */
    OLED_DrawNumZ(24U, page, raw, 4U);

    OLED_DrawString(54U, page, "F32/24");
}

/* ---------------------------------------------------------------------
 * 主函数
 * ------------------------------------------------------------------- */
int main(void)
{
    uint32_t last_refresh = 0U;         /* 上一次刷新的时刻（uwTick） */
    uint32_t mv;                        /* 当前电压，单位毫伏 */
    uint16_t raw;                       /* 当前滤波后的原始计数 */
    uint8_t  blink = 0U;                /* LED 心跳计数器，证明程序没死 */

    /* ---------- 第一阶段：初始化 ---------- */

    HAL_Init();                         /* 时基 1ms，SysTick 优先级 0x0F */
    SystemClock_Config();               /* 72MHz，其中 ADCCLK = 12MHz */

    MX_GPIO_Init();                     /* PA1(模拟) / PB6,PB7(I2C) / PC13(LED) / PA0(按键) */
    MX_ADC1_Init();                     /* ADC1 单通道 PA1，采样时间 55.5 周期 */

    /* OLED 上电初始化：发一串 SSD1306 的配置命令（电荷泵、扫描方向等）。
     * ★ OLED_Init() 的原型是 void —— 它不会告诉你屏幕上电成没成功。
     *   上电失败时屏幕不会报错，只是一直黑着，很容易被当成"程序卡死"。
     *   所以在线判断要用上一篇单独提供的 OLED_TestConnection()：
     *   它往从机地址发一个字节，收到 ACK 返回 0，没有设备应答返回非 0。 */
    OLED_Init();

    if (OLED_TestConnection() != 0U)
    {
        /* OLED 没应答：用 LED 快速闪烁报警，别让程序静默地跑下去。
         * 蓝药丸的板载 LED 接在 PC13（低电平点亮），别写成 GPIOB。 */
        while (1)
        {
            HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);
            HAL_Delay(100);
        }
    }

    /* ADC 自校准 + 丢弃首次转换。★ 必须在 MX_ADC1_Init 之后 */
    Volt_Init();

    /* 开机画面：整帧推送一次。之后主循环里就再也不"清屏"了 */
    OLED_ClearBuffer();
    OLED_DrawString(0U, 0U, "STM32 Voltmeter");
    OLED_DrawString(0U, 2U, "Range 0-6.6V");
    OLED_DrawString(0U, 4U, "Cal:");
    OLED_DrawNumZ(30U, 4U, CAL_GAIN, 5U);       /* 把标定系数显示出来，一眼可查 */
    OLED_Refresh();

    HAL_Delay(800);                             /* 开机画面停留 0.8 秒 */
    last_refresh = HAL_GetTick();               /* 以当前时刻作为第一次刷新的起点 */

    /* ---------- 第二阶段：主循环 ---------- */

    while (1)
    {
        /* ★ 非阻塞定时判断。
         *
         * 用【相减】而不是 if (HAL_GetTick() > last_refresh + 200)。
         * uwTick 是 uint32_t，49.7 天会回绕到 0，
         * 那一刻 "> last + 200" 会判断错误，表就卡住了。
         * 无符号减法在回绕时结果依然正确，天然免疫这个问题。
         *
         * 这段代码每转一圈只花几个时钟周期，
         * 所以主循环一秒能转几十万圈 —— 到点才刷屏，
         * 不到点的时间全都空出来给按键、串口等其他任务。 */
        if ((HAL_GetTick() - last_refresh) >= REFRESH_PERIOD_MS)
        {
            last_refresh = HAL_GetTick();

            /* 采样 + 滤波。
             * ★ 只采一次，两个用途共用：
             *   如果先调 Volt_ReadFiltered() 显示 RAW，
             *   再调一次去算电压，两次数据来自不同时刻，
             *   显示就会自相矛盾（RAW 对应 A 时刻，电压对应 B 时刻）。 */
            raw = Volt_ReadFiltered();

            /* 换算成被测端毫伏值（定点，无浮点） */
            mv = Volt_RawToMilliVolt(raw);

            /* ---- 绘制阶段：全部发生在 RAM 里，屏幕此刻毫无变化 ---- */
            OLED_ClearBuffer();                 /* 清的是显存数组，不是屏幕 */
            Draw_Voltage(0U, mv);
            Draw_Info(2U, raw);

            /* 超量程提示 */
            if (mv >= OVER_RANGE_MV)
            {
                OLED_DrawString(0U, 4U, "OVER RANGE!    ");
            }
            else
            {
                OLED_DrawString(0U, 4U, "               ");   /* 用空格覆盖掉上次的提示 */
            }

            /* ---- 推送阶段：整帧一次性发给屏幕 ---- */
            OLED_Refresh();

            /* 心跳：每 5 次刷新（1 秒）让 LED 闪一下，证明程序还活着。
             * 这是嵌入式调试的土办法，比接串口看日志快得多。 */
            blink++;
            if (blink >= 5U)
            {
                blink = 0U;
                HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);
            }
        }

        /* 主循环的其余时间用来处理别的事情。
         * 本项目没有别的任务，留一个空的处理位置，
         * 以后加按键、串口就在这里加。 */
    }
}

关键代码解析

  • HAL_ADCEx_Calibration_Start(&hadc1)—— F1 的 ADC 每次上电都要校准一次，不校准零点可能偏几十个 LSB。 注意它必须在 HAL_ADC_Init() 之后、 任何一次 Start 之前调用，而且校准期间 ADC 必须处于关闭状态。 CubeMX 不会自动生成这一句，要自己加。
  • (void)Volt_ReadRaw();—— 校准后的第一次转换结果不可信，直接扔掉。 (void) 是显式告诉编译器“我知道这个返回值没用， 别警告我”，这是嵌入式里对付 -Wunused-result 的标准写法。
  • for (i = FILTER_DISCARD; i < (FILTER_SAMPLES - FILTER_DISCARD); i++)—— 从第 4 个元素累加到第 27 个（下标 4~27 共 24 个）， 正好跳过排序后两端各 4 个极值。这里面的 FILTER_SAMPLES - FILTER_DISCARD 是上界（不含），所以最后一个参与的元素下标是 27， 不是 28。循环边界差一个（off-by-one）是这类求和最常见的 bug， 写完之后拿一张纸把 32 个格子画出来数一遍，比盯着代码看十分钟管用。
  • sum / (FILTER_SAMPLES - (2U * FILTER_DISCARD))—— 分母写成了表达式而不是直接写 24。这样改参数（比如把丢弃数改成 6） 的时候不会忘记同步改分母。原则是： 凡是能从宏推出来的数，就不要手写常量。
  • if ((HAL_GetTick() - last_refresh) >= REFRESH_PERIOD_MS)—— 非阻塞定时的标准写法。相减形式免疫 uwTick 在 49.7 天后的回绕问题。这个写法要变成肌肉记忆， 以后所有“每隔多久做一次”的需求都这么写，绝不 HAL_Delay。
  • raw = Volt_ReadFiltered(); mv = Volt_RawToMilliVolt(raw);—— 一次采样，两处使用。如果写成两次独立调用，RAW 显示和电压显示就来自 不同时刻的数据，会出现“RAW 显示 3102 但电压显示 4.98V”这种自相矛盾的画面。 同一个逻辑帧里的所有显示，都应该基于同一份采样数据。
  • OLED_DrawString(0U, 4U, "OVER RANGE! ");—— 字符串末尾那一串空格不是手滑，是刻意用来覆盖旧内容的。 "OVER RANGE!" 是 11 个字符， 覆盖时需要把上一帧可能更长的内容全部盖住。 这种“用空格填充”的技巧是定宽显示的延伸： 在不清屏的前提下，让旧内容消失的唯一办法就是用新内容盖住它。
  • if ((c < ' ') || (c > '~')) { c = ' '; }—— OLED_DrawChar 里的字库越界保护。 只处理可打印 ASCII，其他字符统一画空格。 如果没有这一层保护，传进来一个 0x80 以上的字节（比如误传了汉字）， idx = c - ' ' 就会是个很大的数， 数组越界读到一片乱码甚至跑飞。 凡是“外部传进来的值当下标用”的地方，都要有这层保护。

常见报错排查方案

这里整理了五个最常碰到的问题，覆盖了编译期和运行期。 注意其中有两个是完全不报错的—— 这类问题最耗时间，所以我把“怎么快速定位”也一起写了。

编译报错：error: #20: identifier "ADC_CHANNEL_1" is undefined

..\Core\Inc\adc.h(24): error: #20: identifier "ADC_CHANNEL_1" is undefined

原因： adc.h 里用了 ADC_CHANNEL_1、 ADC_HandleTypeDef 这些 HAL 库的类型和宏， 但没有包含定义它们的头文件。这些定义都在 stm32f1xx_hal.h 里， 而 CubeMX 生成的 main.h 已经包含了它。

解决： 在 adc.h 的最上面加上 #include "main.h"， 并且放在所有宏定义之前。 这个坑在勾选了“每个外设一对 .c/.h 文件”之后特别容易出现—— 因为自己新建的头文件不会自动带上 include。

顺带记住一条规律：HAL 相关的报错，九成是因为头文件没包含全。 看到 #20 identifier undefined 先想去加 include，别急着改代码逻辑。

现象：编译链接全通过，但屏幕永远显示 0.000V，RAW 也一直是 0（不报任何错）

原因：换算公式写成了“先除后乘”。 很多人会顺手写成 raw / 4095 * 3300， C 语言的整数除法把 raw / 4095 直接截断成 0（因为 raw 最大才 4095），整个表达式恒为 0。 另一种可能：VREF_MV 被写成了 3.3（浮点），和整型混算后被截断成 3。

解决： ① 乘法必须在除法之前：((uint32_t)raw * VREF_MV) / ADC_FULL_SCALE， 并强制转换其中一个操作数为 uint32_t， 防止 16 位乘法溢出（4095 × 3300 = 13,513,500 已经超过 16 位上限 65535 了！）。 ② 单位统一用毫伏的整数，绝不出现 3.3 这样的浮点常量。

快速定位法：把中间的 mv_pin 用第二行显示出来。显示 0 → 问题在第一步的换算； 显示正常但最终值是 0 → 问题在后两步。 一次显示就能把问题范围缩小一半。

现象：读数偏小约 2%~5%，而且输入电压越高偏得越多

原因：ADC 采样时间不够，采样电容没充到外部电压就被迫进入转换阶段。 典型诱因有三个：① 采样时间选了默认的 1.5 周期； ② 分压电阻用了 100kΩ 以上，源阻抗太大； ③ 忘了焊 C1 那个 100nF 电容。

解决： ① 把 sConfig.SamplingTime 改成 ADC_SAMPLETIME_239CYCLES_5，先验证“是不是采样时间的问题”， 如果改完就准了，再往回调到够用的档位； ② 分压电阻换成 10kΩ 级（源阻抗 5kΩ）； ③ 补上 C1，并且让它尽量靠近 PA1。

验证方法：固定输入 5.000V 不动，只改采样时间， 记录 RAW 值的变化。如果 RAW 随采样时间变长而变大然后趋于稳定， 就坐实了是建立时间不足。这个实验能让你对“采样时间”这个参数建立直观认识。

现象：误差很稳定但就是偏 2% 左右，改代码也修不掉

原因：这不是 bug，是系统误差。 三个来源叠加：LDO 输出的 3.3V 实际可能是 3.27V（−0.9%）、 分压电阻 1% 精度带来的比例误差（最坏 ±2%）、ADC 自身的增益误差。 它们不会随机跳动，所以你看不到“跳”，但整体是偏的。

解决： 做标定。用万用表读数和表的显示值算出 K， 填进 CAL_GAIN（×10000 的整数）。 具体流程和记录表见正文“标定”一节。 标定后误差通常能压到 ±0.2% 以内。

判断“该不该标定”的标准： 偏差是否稳定、是否与输入成比例。 两个都是“是”→ 标定；如果偏差在跳或者不成比例 → 先回去查硬件（采样时间、接线、地线）。 不要用标定去掩盖一个真实的硬件 bug。

现象：刷新时屏幕闪一下暗，或者旧数字和新数字叠在一起

原因：两种情况，症状像但原因完全不同。 ① 闪暗：还在用“OLED_Clear() 清屏 → 逐个写字符”的写法， 清屏和写新内容之间有几十毫秒的全黑时间。 ② 残影叠加：某个字段不是定宽的，新值比旧值短， 短的那一段没盖住旧内容，就留在屏幕上了（比如上一帧是 5.000V， 这一帧变成 0.500V，如果字符串没对齐就丢字）。

解决： ① 改用显存缓冲：绘制函数一律用 OLED_DrawXxx（只改 RAM）， 整个逻辑帧画完后统一调用一次 OLED_Refresh()。 主循环里永远不该出现 OLED_Clear()。 ② 所有显示字段改成定宽：数字用 OLED_DrawNumZ 指定宽度， 字符串如果长度会变化，就在末尾补空格补到固定长度 （代码里的 "OVER RANGE! " 就是例子）。

一秒钟自检法：在主循环里搜 OLED_Clear 和 OLED_Show。 只要搜到了，就一定在闪或不必要的重绘。 正确的版本里这两个词一次都不该出现。

小结与练习

这个项目里没有新外设，全部是前面三篇的知识点重新组合。 真正新增的是工程判断： 每个数字为什么是这个值，每种误差该用哪种手段消除。 把下面几条带走：

  • 分压电路是必须的，1:1 分压用同型号电阻，比例误差自然抵消。 电阻取 10kΩ 级：太小费电，太大则源阻抗超出 ADC 能驱动的范围，读数会偏低。
  • 随机误差用滤波消除，系统误差只能用标定消除。 去极值平均滤波同时对付随机噪声和偶发脉冲；而稳定的、成比例的偏差必须靠 CAL_GAIN 修掉——两者不可互相替代。
  • 全程用整数，用"毫伏"代替"伏特"。 STM32F1 没有 FPU，浮点要几百个周期还要拉进几 KB 的库。 定点换算三原则：先乘后除、中间结果算范围、小数位用除和取模拆开。
  • 显示位数不能超过实际分辨率。 1.61mV 的分辨率对应 0.01V 的诚实显示； 显示到 0.0001V 就是在编数字。这一条在写报告和答辩时尤其重要。
  • 绘制在 RAM，推送整帧一次，屏幕就不闪。 显存缓冲花 1024 字节换来实现上的自由： 先画背景再画前景、随时局部覆盖，都不用担心闪烁。
  • 主循环用非阻塞定时，绝不用 HAL_Delay 控制节奏。 if ((HAL_GetTick() - last) >= 200U) 这个写法既免疫回绕，又让主循环的时间都用来干正事。
动手练习
  1. 把量程改成 0 ~ 15V，并写出完整的设计计算。 15V 要降到 3.3V 以内，分压比至少是 15:3.3 ≈ 4.55:1， 取个整就是 5:1（比如 R1 = 40kΩ、R2 = 10kΩ，或者 R1 = 4×10kΩ 串联、R2 = 10kΩ）。 要求回答：① 新的 DIVIDER_NUM / DIVIDER_DEN 填什么？ ② 新的量程上限是多少？③ 新的分辨率是多少毫伏？ ④ 源阻抗变成多少，采样时间需要改成哪一档？ ⑤ 显示应该保留几位小数才不算假精度？ 提示：mv_in × DIVIDER_NUM 的最大值要重新做一遍溢出检查。
  2. 加一个"最大值 / 最小值记录"功能。 用 PA0 的按键中断（参考 外部中断那一篇） 做两件事：按一次记录当前值为最小值，长按清零。 要求在 OLED 上显示 MIN 和 MAX 两行， 并且刷新时不能闪屏。 提示：记录动作发生在中断里，按那一篇的规矩，回调里只能置标志位， 实际比较和更新放在主循环；显示用定宽格式， 别忘了数值位数变化时要用空格覆盖旧内容。
  3. 把显存刷新优化成"只刷脏页"，并测量优化前后的耗时。 现在的 OLED_Refresh() 每次都推 1024 字节。 请改成：给每页加一个 dirty 标志， OLED_DrawChar 写到哪一页就把哪一页标记为脏， OLED_Refresh() 只推被标记的页，推完清标志。 测量方法：在 OLED_Refresh() 前后各读一次 HAL_GetTick()，把差值显示在屏幕上。 思考：本项目只改前几页，优化后理论上能省多少时间？ 如果以后要做 30Hz 刷新的波形显示，这个优化是不是必需的？
