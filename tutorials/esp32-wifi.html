原理介绍

在 51 和 STM32 上做联网，你得外挂一个 ESP-01 模块，用 AT 指令一板一眼地敲 AT+CWJAP="ssid","pwd"，还要处理模块返回的 WIFI CONNECTED 字符串。 ESP32 把 Wi-Fi 射频直接做进了芯片，还提供了一套 面向对象的 C++ 库， 连网这件事被压缩成了两行代码。

但简单不等于可以盲写。这套库背后是一个异步的状态机： 射频芯片自己去做扫描、认证、四次握手、DHCP 申请， 你的 CPU 只管时不时问一句「现在到哪一步了」。 如果你按顺序思维去写（发命令 → 等结果 → 继续）， 程序就会卡死；理解了这个异步模型，代码自然就写对了。

STA 与 AP：两种模式怎么选

ESP32 的 Wi-Fi 有两种基本工作模式，理解它们的最好比喻是 手机的 Wi-Fi 和手机的热点：

对比项 STA 模式（Station，工作站） AP 模式（Access Point，接入点）
角色 客户端，去连别人的路由器 热点，等着别人来连自己
手机类比 手机连家里的 Wi-Fi 手机开个人热点
ESP32 的 IP 由路由器 DHCP 分配，如 192.168.1.37 固定为 192.168.4.1
能不能上互联网 能（路由器通外网就行） 不能，除非同时开 STA 做转发
能连几个设备 同时只连一个路由器 最多 4~8 个客户端
典型用途 上传传感器数据到服务器、远程控制、MQTT 设备首次配网、无路由器时的直连调试
调用方式 WiFi.mode(WIFI_STA) WiFi.softAP("名字", "密码")

实际项目里最常用的其实是第三种组合： WIFI_AP_STA 双模同时开。 设备第一次上电时自己开热点，你用手机连上去填 Wi-Fi 密码； 填完切到 STA 连路由器。这就是小米、涂鸦那些智能插座「配网」的原理。 本页先把最基础、也最常用的纯 STA 模式走通， 双模配网属于进阶内容，思路是一样的。

一句话选型

要联网，就选 STA；要给别人连，才用 AP。 课设和毕设里 90% 的场景是 STA。看到网上教程里 WiFi.softAP 就以为是「连 Wi-Fi」， 是新手非常常见的一个误解——它恰恰是自己发 Wi-Fi。

WiFi.status() 与超时重连

WiFi.begin(ssid, password) 这个名字很有误导性：它并不「开始连接并等你连上」， 而是「把连接请求丢给后台，立刻返回」。 真正的连接过程由射频子系统和 Wi-Fi 任务在另一个 CPU 核心上完成， 耗时从几百毫秒到十几秒不等（要看信号强度、路由器响应、DHCP 快慢）。

所以紧跟在 begin() 后面写 Serial.println(WiFi.localIP())， 打印出来一定是 0.0.0.0。 正确的做法是轮询 WiFi.status()， 它会返回一个数字告诉你现在处于哪个阶段：

返回值 枚举名 含义 你该做什么
0WL_IDLE_STATUS空闲，还没开始连调用 WiFi.begin()
1WL_NO_SSID_AVAIL扫不到这个 SSID查名字拼写、是否 5GHz、距离是否太远
2WL_SCAN_COMPLETED扫描完成（扫描模式下才有）不用管
3WL_CONNECTED已连接可以读 IP、发数据了
4WL_CONNECT_FAILED认证失败九成是密码错，其次是加密方式不兼容
5WL_CONNECTION_LOST连上之后又断了会自动重连，也可以自己接管
6WL_DISCONNECTED未连接（正在尝试中也是这个）耐心等，但要设超时；持续为 6 说明连不上

有了状态码，就能理解为什么必须有超时。 如果 SSID 写错了，芯片会一直重试，状态永远停在 6。 如果你的代码写成 while (WiFi.status() != WL_CONNECTED);， 程序就永久卡在那里，按键不响应、传感器不采集、看门狗还可能把你复位掉。 网上的「一行代码连 Wi-Fi」教程基本都是这种写法， 在实验室跑得通，一到现场就是灾难。 

  ✗ 新手写法（会卡死）                ✓ 工程写法（推荐）

  WiFi.begin(ssid, pwd);              WiFi.begin(ssid, pwd);
  while (WiFi.status()                 记录开始时刻
         != WL_CONNECTED) {            ...
    delay(500);              ← 死等   每次 loop 检查一次：
  }                                     连上了 -> 进入「已连接」状态
  Serial.println(localIP());            超过 15 秒还没连上
                                           -> 断开，进入「冷却」状态
  问题：                                   冷却 5 秒后 -> 重新开始连接
   · 连不上时永远出不来
   · 期间按键 / 传感器全部停摆      好处：
   · 看门狗超时会直接复位芯片         · 主循环一直在跑，其他功能不受影响
   · 电池设备功耗居高不下             · 失败可恢复，能一直重试下去
                                      · 能区分「连不上」和「连上又掉线」

ESP32 的 Arduino 核心自带一个 WiFi.setAutoReconnect(true)， 默认就是开的，掉线后它会自己重连。听起来很省事，但它有两个问题： 一是你无法感知它重连的过程，二是重连策略不可控（间隔、次数都是固定的）。 本页的例子里我们把它关掉，自己写状态机， 因为工程上你必须知道设备现在是「在连」「没连上」还是「连上过又掉了」—— 这三种情况的处理方式完全不同。

2.4GHz、5GHz 与信号强度

ESP32 的射频只支持 2.4GHz 频段，不支持 5GHz。 这不是软件限制，也不是刷固件能解决的——是芯片里的射频前端物理上只覆盖 2.412~2.484GHz。这一条本身就值得写在便利贴上， 因为「家里 Wi-Fi 明明很好，就是连不上」的最常见原因就是它。

对比项 2.4GHz 5GHz
ESP32 是否支持支持不支持
常用信道1 ~ 1336 ~ 165
速度较慢（理论 150Mbps 级别）快得多
穿墙能力强，绕射好弱，隔一堵墙就明显掉速
干扰严重（微波炉、蓝牙、邻居 Wi-Fi 都在这）相对干净
对 ESP32 的意义唯一的可用频段，够用（传传感器数据只要几 KB）连不上，别再怀疑代码了

现在很多路由器默认开启「双频合一 / 智能连接 / Band Steering」， 也就是 2.4G 和 5G 用同一个 SSID，由路由器决定把你分到哪一频段。 这个功能对手机很友好，对 ESP32 却是灾难： 路由器可能一直把 ESP32 往 5GHz 上赶，而 ESP32 根本没这个能力。 做实验前请进路由器管理页面，把两个频段拆成不同的 SSID （例如 MyHome 和 MyHome_5G）， 让 ESP32 明确去连 2.4G 的那个。这一条操作能解决掉大量「玄学连不上」。

连上之后还要能判断信号好不好，靠的是 WiFi.RSSI()， 单位是 dBm，是一个负数，越接近 0 越好：

RSSI 范围（dBm） 信号评价 实际表现
-30 ~ -50极佳贴着路由器，几乎不会掉线
-50 ~ -60良好同一房间，稳定
-60 ~ -70一般隔一堵墙，能用，偶尔丢包
-70 ~ -80较差隔两堵墙，容易掉线重连
-80 以下极差连接不稳定或根本连不上，该换位置了

凭据不要硬编码在代码里

几乎所有教程都写成这样： WiFi.begin("MyHome", "12345678"); 在自己电脑上跑没问题，但这个习惯会带来三个真实的麻烦：

  • 泄露。 代码一旦发给同学、上传到 GitHub、或者作为课设交了电子版， 你家 Wi-Fi 密码就等于公开了。学校实验室的路由器密码泄露， 还可能牵出管理责任。
  • 改一次编译一次。 拿到实验室要改成实验室的 Wi-Fi，拿回家要改回自己家的， 每次都得重新编译上传，效率极低。
  • 没法交付。 毕设答辩时老师问「这个设备拿到别的实验室能用吗」， 如果答案是「得改代码重新烧录」，那这个作品就不算完整。

正确的做法分三个层次，按项目规模选：

方案 做法 适合场景 缺点
secrets.h 把账号密码放进单独的头文件，主程序 #include 它，并把该文件加进 .gitignore 个人开发、课设、毕设 换 Wi-Fi 仍要重新编译
Preferences（NVS） 用 ESP32 的 Preferences 库把凭据写进 Flash 的 NVS 分区，运行时读取 需要掉电保存、少量可配置参数 需要自己写一套读写逻辑
AP 配网 首次上电开热点，手机连上去在网页里填 Wi-Fi，保存后重启切 STA 要交付给别人的产品 代码量最大，属于进阶内容
从第一天就养成 secrets.h 的习惯

本页示例用最轻量的 secrets.h 方案。 它不是最先进的技术，但是性价比最高的一个习惯： 只需要多建一个文件，就能彻底避免密码泄露。 等你以后用 Git 管理代码时，会庆幸自己从一开始就这么做。

硬件接线说明

这一节名副其实地轻松：一根外接线都不需要。 天线已经集成在模组里（那块金属屏蔽罩下面）， 你要做的「接线」是把开发板和路由器连到同一个网络世界里。 但这里有几条硬件和网络环境上的注意事项，忽略它们同样会连不上。

操作顺序建议

  1. 先进路由器管理页面，把 2.4G 和 5G 的 SSID 分开，记下 2.4G 的名字和密码。
  2. 用手机连一次这个 2.4G 的 SSID，确认密码是对的、能上网。这一步排除掉一半的问题。
  3. 在 Arduino IDE 里新建 secrets.h，把 SSID 和密码填进去。
  4. 开发板只插 USB，不接任何外设。Wi-Fi 实验期间外设越少，变量越少。
  5. 上传程序，打开串口监视器（115200），观察状态机的打印。
  6. 连上之后，把打印出来的 IP 抄下来——后面做网页控制、MQTT 都要用这个地址。
上电前必查
  • 目标 SSID 是不是 2.4GHz 的。这一条值得单独确认一次，不要凭感觉。
  • 路由器有没有开「AP 隔离 / 客户端隔离」。开了的话 ESP32 连得上，但电脑访问不到它。
  • 路由器有没有开 MAC 地址过滤。校园网和实验室网络经常有这一层。
  • USB 线是不是能带 500mA 的。Wi-Fi 发射瞬间掉电复位是极常见的现象。
  • 手和金属物有没有挡住模组的天线一侧。

完整代码

一共两个文件。secrets.h 存放凭据， esp32-wifi-sta.ino 是主程序。 两个文件要放在同一个文件夹里， 文件夹名和 .ino 文件名必须一致， 这是 Arduino IDE 的硬性要求。 

/* =====================================================================
 *  secrets.h —— Wi-Fi 凭据
 *
 *  ⚠ 重要：把这个文件名加进 .gitignore，绝对不要上传到 GitHub。
 *  ⚠ 交课设 / 毕设电子版时，记得把这里换成占位符再交。
 *
 *  为什么用 #ifndef 包一层？防止这个头文件被重复包含时
 *  造成宏重复定义的编译警告。这是 C 头文件的标准写法。
 * ===================================================================== */
#ifndef SECRETS_H
#define SECRETS_H

/* 这里填 2.4GHz 那个 SSID，不是 5GHz 的 */
#define WIFI_SSID       "MyHome_2G"

/* 密码区分大小写，注意别把数字 0 和字母 O 看混 */
#define WIFI_PASSWORD   "your-password-here"

#endif  /* SECRETS_H */
/* =====================================================================
 *  esp32-wifi-sta.ino —— ESP32 STA 模式连接路由器
 *
 *  特性：
 *    1. 单次连接超时 15 秒，超时不会死等，会主动断开并进入冷却
 *    2. 冷却 5 秒后自动重试，无限次重试，全程不阻塞主循环
 *    3. 连上之后持续监视，掉线自动回到重试流程
 *    4. 板载 LED 用不同闪烁节奏指示三种状态，不看串口也能判断
 *    5. 周期性打印 IP / RSSI / 信道 / 网关 / 运行时间
 *
 *  目标板：ESP32 Dev Module（ESP32-WROOM-32）
 *  依赖文件：secrets.h（同目录，存放 SSID 与密码）
 *  波特率：115200
 * ===================================================================== */

#include <WiFi.h>        /* ESP32 Arduino 核心自带，不需要在库管理器里安装 */
#include "secrets.h"     /* 用引号而不是尖括号：表示这是本工程目录下的头文件 */

/* ---------------- 可调参数：想改行为只改这几行 ---------------- */
#define PIN_STATUS_LED      2            /* 板载 LED；外接 LED 可改成 16 */
#define WIFI_TIMEOUT_MS     15000UL      /* 单次连接最多等 15 秒 */
#define RETRY_INTERVAL_MS   5000UL       /* 失败后冷却 5 秒再重试 */
#define REPORT_INTERVAL_MS  5000UL       /* 连上后每 5 秒报告一次状态 */

/* =====================================================================
 *  连接状态机
 *  为什么要有这三个状态，而不是简单地「连上 / 没连上」：
 *    · CONNECTING   正在尝试，需要计时判断是否超时
 *    · WAIT_RETRY   已经失败，需要计时决定何时重试
 *    · CONNECTED    已连上，需要监视是否掉线
 *  三种状态要干的事完全不同，混在一起写就会变成一团 if-else
 * ===================================================================== */
enum WifiState {
    ST_CONNECTING,      /* 正在连接 */
    ST_WAIT_RETRY,      /* 连接失败，冷却中 */
    ST_CONNECTED        /* 已连接 */
};

WifiState state        = ST_CONNECTING;
uint32_t  stateEnterMs = 0;      /* 进入当前状态的时刻（毫秒时间戳） */
uint32_t  lastReportMs = 0;      /* 上一次打印状态报告的时刻 */

/* ---------------------------------------------------------------------
 * 把 WiFi.status() 的枚举翻译成中文
 * 排错时这一行日志比什么都值钱：能一眼区分「找不到 SSID」和「密码错」
 * ------------------------------------------------------------------- */
const char* statusText(wl_status_t s) {
    switch (s) {
        case WL_IDLE_STATUS:     return "0 WL_IDLE_STATUS 空闲，还没开始连";
        case WL_NO_SSID_AVAIL:   return "1 WL_NO_SSID_AVAIL 找不到这个 SSID（名字错 / 5GHz / 太远）";
        case WL_SCAN_COMPLETED:  return "2 WL_SCAN_COMPLETED 扫描完成";
        case WL_CONNECTED:       return "3 WL_CONNECTED 已连接";
        case WL_CONNECT_FAILED:  return "4 WL_CONNECT_FAILED 认证失败（多半是密码错）";
        case WL_CONNECTION_LOST: return "5 WL_CONNECTION_LOST 连接丢失";
        case WL_DISCONNECTED:    return "6 WL_DISCONNECTED 未连接（正在尝试中也是这个）";
        default:                 return "未知状态码";
    }
}

/* ---------------------------------------------------------------------
 * 把 RSSI 数值翻译成人话
 * ------------------------------------------------------------------- */
const char* rssiText(int rssi) {
    if (rssi >= -50) return "极佳";
    if (rssi >= -60) return "良好";
    if (rssi >= -70) return "一般";
    if (rssi >= -80) return "较差";
    return "极差，建议换个位置";
}

/* ---------------------------------------------------------------------
 * 状态切换的唯一入口
 * 所有状态变化都必须经过这里，保证 stateEnterMs 一定被更新，
 * 否则计时判断会算错——这是状态机最容易出的 bug
 * ------------------------------------------------------------------- */
void enterState(WifiState s) {
    state        = s;
    stateEnterMs = millis();
}

/* ---------------------------------------------------------------------
 * 发起一次连接
 * 注意 WiFi.begin() 是「非阻塞」的：它只把请求丢给后台任务就立刻返回，
 * 所以后面必须靠轮询 WiFi.status() 才知道连上没有
 * ------------------------------------------------------------------- */
void startConnect() {
    WiFi.mode(WIFI_STA);              /* 只做工作站模式，不做热点，省内存也省电 */

    /* 关闭 Wi-Fi 省电模式：
     * 默认开启时，射频会在没有数据时打盹，路由器发来的包要等到下一个
     * 唤醒周期才处理，表现为「响应慢、延迟忽高忽低」。
     * 代价是平均电流从约 20mA 升到约 100mA。插着 USB 供电时完全值得。 */
    WiFi.setSleep(false);

    /* 关掉核心自带的自动重连。它虽然是默认开启的，但重连过程不可观测、
     * 策略不可控，会和我们的状态机互相干扰。重连这件事自己管更清楚。 */
    WiFi.setAutoReconnect(false);

    WiFi.begin(WIFI_SSID, WIFI_PASSWORD);   /* 立刻返回，真正的连接在后台进行 */

    Serial.printf("[WiFi] 正在连接 \"%s\" ...\n", WIFI_SSID);
}

/* ---------------------------------------------------------------------
 * 打印一次详细的连接报告
 * ------------------------------------------------------------------- */
void reportStatus() {
    int rssi = WiFi.RSSI();           /* 信号强度，单位 dBm，负数，越接近 0 越好 */

    Serial.printf("[状态] IP=%-15s RSSI=%d dBm (%s)\n",
                  WiFi.localIP().toString().c_str(), rssi, rssiText(rssi));
    Serial.printf("       网关=%s  子网掩码=%s\n",
                  WiFi.gatewayIP().toString().c_str(),
                  WiFi.subnetMask().toString().c_str());
    Serial.printf("       DNS=%s  信道=%d  主机名=%s\n",
                  WiFi.dnsIP().toString().c_str(),
                  WiFi.channel(),
                  WiFi.getHostname());
    Serial.printf("       已运行 %lu 秒，空闲堆 %u 字节\n",
                  millis() / 1000, ESP.getFreeHeap());
}

void setup() {
    Serial.begin(115200);
    delay(800);                        /* 等串口枚举完成，避免开头丢字 */

    pinMode(PIN_STATUS_LED, OUTPUT);
    digitalWrite(PIN_STATUS_LED, LOW);

    Serial.println();
    Serial.println("=== ESP32 WiFi STA 模式演示 ===");

    /* 打印 MAC 地址很有用：路由器后台的「已连接设备」列表里靠它认设备，
     * 做 MAC 绑定、MAC 过滤时也都要用 */
    Serial.printf("本机 MAC 地址 : %s\n", WiFi.macAddress().c_str());
    Serial.printf("连接超时      : %lu 秒\n", WIFI_TIMEOUT_MS / 1000);
    Serial.printf("重试间隔      : %lu 秒\n", RETRY_INTERVAL_MS / 1000);
    Serial.println("-----------------------------------");

    startConnect();
    enterState(ST_CONNECTING);
}

void loop() {
    /* ================= 状态机主体 =================
     * 每次 loop 只做「检查一下、必要时切状态」这一点点事，
     * 绝不在这里 delay 或死等，主循环始终是通畅的 */
    switch (state) {

        /* ---------- 状态 1：正在连接 ---------- */
        case ST_CONNECTING:
            if (WiFi.status() == WL_CONNECTED) {
                /* 连上了：立刻读一次 IP。注意要在这一步之后才能读，
                 * 在 begin() 之后马上读一定是 0.0.0.0 */
                Serial.println("[WiFi] 连接成功！");
                Serial.printf("       IP 地址 : %s\n", WiFi.localIP().toString().c_str());
                Serial.printf("       网关    : %s\n", WiFi.gatewayIP().toString().c_str());
                Serial.printf("       信道    : %d\n", WiFi.channel());
                Serial.printf("       耗时    : %lu ms\n", millis() - stateEnterMs);

                digitalWrite(PIN_STATUS_LED, HIGH);   /* 常亮表示已连接 */
                lastReportMs = millis();
                enterState(ST_CONNECTED);

            } else if (millis() - stateEnterMs >= WIFI_TIMEOUT_MS) {
                /* 超时：不再干等，主动断开并进入冷却。
                 * 这就是「为什么一定要设超时」的落地写法 */
                Serial.printf("[WiFi] 连接超时（已等 %lu 秒）\n", WIFI_TIMEOUT_MS / 1000);
                Serial.printf("       当前状态码 : %s\n", statusText(WiFi.status()));
                Serial.println("       进入冷却，稍后自动重试");

                WiFi.disconnect();        /* 不带参数：只断开，不关闭射频 */
                digitalWrite(PIN_STATUS_LED, LOW);
                enterState(ST_WAIT_RETRY);
            }
            break;

        /* ---------- 状态 2：冷却中，等够间隔再试 ---------- */
        case ST_WAIT_RETRY:
            if (millis() - stateEnterMs >= RETRY_INTERVAL_MS) {
                startConnect();           /* 重新发起连接 */
                enterState(ST_CONNECTING);
            }
            break;

        /* ---------- 状态 3：已连接，监视掉线 ---------- */
        case ST_CONNECTED:
            if (WiFi.status() != WL_CONNECTED) {
                /* 连上之后又断了。常见原因：走远了、路由器重启、
                 * 同频干扰、或者 AP 把长时间空闲的客户端踢掉 */
                Serial.printf("[WiFi] 连接丢失！状态码 : %s\n",
                              statusText(WiFi.status()));
                digitalWrite(PIN_STATUS_LED, LOW);
                enterState(ST_WAIT_RETRY);   /* 回到重试流程，不直接重连 */
                break;                       /* 跳出 switch，避免下面继续用到失效的连接 */
            }

            /* 还连着：周期性报告一次 */
            if (millis() - lastReportMs >= REPORT_INTERVAL_MS) {
                lastReportMs = millis();
                reportStatus();
            }
            break;
    }

    /* ================= 状态指示灯 =================
     * 三种状态三种节奏，不用开串口监视器就能看出板子在干什么：
     *   连接中 -> 200ms 快闪
     *   冷却中 -> 1000ms 慢闪
     *   已连接 -> 常亮
     * 同样是非阻塞写法：靠时间戳翻转，不用 delay */
    updateStatusLed();
}

/* ---------------------------------------------------------------------
 * 状态指示灯：非阻塞闪烁
 * 注意 digitalWrite 是「立刻返回」的，所以这里不需要任何延时，
 * 只是每隔一段时间翻转一次电平而已
 * ------------------------------------------------------------------- */
void updateStatusLed() {
    static uint32_t lastToggleMs = 0;
    static bool     ledOn        = false;

    if (state == ST_CONNECTED) {
        /* 已连接：直接常亮，不再翻转 */
        digitalWrite(PIN_STATUS_LED, HIGH);
        return;
    }

    /* 连接中用短周期（快闪），冷却中用长周期（慢闪） */
    uint32_t period = (state == ST_CONNECTING) ? 200UL : 1000UL;

    if (millis() - lastToggleMs >= period) {
        lastToggleMs = millis();
        ledOn = !ledOn;
        digitalWrite(PIN_STATUS_LED, ledOn ? HIGH : LOW);
    }
}

关键代码解析

  • #include "secrets.h" 用的是引号不是尖括号。 引号表示「先在本工程目录里找」，尖括号表示「去系统库目录里找」。 这是 C 预处理器的规则，不是风格问题——写成尖括号会直接报找不到文件。
  • WiFi.begin(WIFI_SSID, WIFI_PASSWORD) 是非阻塞的。 它只把 SSID 和密码交给后台的 Wi-Fi 任务就返回了。 所以下一行读 WiFi.localIP() 一定是 0.0.0.0。 这一点和 ESP8266 老库的行为不同，很多老教程的写法搬过来会「看起来很怪」。
  • WiFi.setSleep(false)—— 关掉省电模式。默认开启时射频会周期性打盹， 路由器发来的数据包要等下一个唤醒周期才处理。 表现为 TCP 响应延迟从几十毫秒变成几百毫秒、忽快忽慢。 做网页控制、MQTT 这类要即时响应的场景，一定要关掉它。 代价是平均电流从 20mA 涨到 100mA 左右，插着 USB 时完全可以接受。
  • WiFi.setAutoReconnect(false)—— 把重连的控制权从核心库手里拿过来。 核心库的自动重连默认是开的，但它在重连时你完全感知不到， 日志里也看不出发生了什么。自己写状态机之后， 「在连」「连不上」「连上又掉」三种情况都有明确日志。
  • enterState() 这个看起来有点多余的函数， 实际上是整个状态机不出 bug 的关键。 如果散落在各处直接给 state 赋值， 很容易忘记同步更新 stateEnterMs， 于是超时判断会算出一个荒唐的结果（比如负数时长或者立刻超时）。 把「状态」和「状态的进入时刻」绑成一个原子操作， 这是写状态机的通用经验。
  • millis() - stateEnterMs >= WIFI_TIMEOUT_MS—— 注意是「当前时间减去进入时刻」而不是「当前时间大于某个时刻」。 前者天然处理了 millis() 约 49 天溢出归零的问题， 后者会在溢出时出错。减法比较是无符号时间戳的正确用法， 这个习惯在你写长期运行的设备时非常重要。
  • WIFI_TIMEOUT_MS 后面的 UL 后缀不能省。 ESP32 上 int 是 32 位， 15000 这种常量在小项目里没事， 但如果算式里混进了更大的数就可能溢出。 养成给时间常量加 UL（unsigned long）的习惯， 能让编译器替你挡住这类问题。
  • ST_CONNECTED 分支里那个 break; 是刻意写的： 掉线之后立刻跳出 switch， 不再执行 reportStatus()。 否则会拿着一个已经失效的连接去读 IP 和 RSSI，打印出误导性的数据。 这类「状态刚变化就继续用旧状态」的错误，是并发程序里最隐蔽的一类 bug。
顺手把 secrets.h 挡在 Git 之外

如果这个工程用 Git 管理，在工程根目录执行下面这一行， 以后 secrets.h 就不会被提交： 

# 把 secrets.h 写入忽略规则（>> 是追加，不会覆盖已有内容）
echo "secrets.h" >> .gitignore

# 建议再建一个模板文件提交上去，让别人知道该填什么
cp secrets.h secrets.h.example
# 然后把 example 里的密码换成占位符再提交

# 检查一下：这条命令应该没有任何输出
git check-ignore -v secrets.h

最后那条 git check-ignore 是自查用的： 有输出说明规则生效了，没有输出说明没生效，得回去检查 .gitignore 的路径写得对不对。

常见报错排查方案

连不上的原因很多，但排查顺序是固定的： 先看状态码，再看频段，最后才怀疑代码。 下面五条按这个顺序排列。

报错原文：状态码一直停在 6 WL_DISCONNECTED，偶尔闪一下 1 WL_NO_SSID_AVAIL

原因： ESP32 扫不到或者不愿意加入这个网络。按概率从高到低： ① 目标是 5GHz 频段（这是最大的一条，占一半以上）； ② 路由器开了「双频合一」，把 ESP32 往 5GHz 上赶； ③ SSID 拼写错误，或者大小写不对； ④ 路由器关闭了 SSID 广播（隐藏网络需要额外指定信道和 BSSID）； ⑤ 距离太远，信号弱到扫不到。

解决： 第一步，进路由器管理页面把 2.4G 和 5G 的 SSID 改成两个不同的名字， ESP32 明确去连 2.4G 那个。第二步，用手机连一次这个 2.4G 的 SSID， 确认密码和可用性。第三步，如果确实是隐藏网络， 把手机放在路由器旁边，用手机看当前连接的信道号， 然后调用带信道参数的版本： WiFi.begin(ssid, password, channel, bssid, true)。 第四步，把开发板挪到离路由器三米以内再试一次， 排除距离因素后再考虑代码。

报错原文：状态码为 4 WL_CONNECT_FAILED（认证失败）

原因： 网络找到了，握手没通过。三种可能： ① 密码错了（最常见，注意数字 0 和字母 O、数字 1 和字母 l）； ② 路由器用的是 WPA3 或「WPA2/WPA3 混合」模式， 老版本 ESP32 核心对 WPA3-SAE 支持不完整； ③ 路由器开了 MAC 地址白名单，ESP32 的 MAC 不在名单里。

解决： 先把密码复制粘贴到记事本里逐字符核对一遍，别靠肉眼。 然后进路由器把加密方式临时改成 WPA2-PSK (AES)， 安全模式选「WPA2 个人版」，不要选「WPA3 个人版」或「混合」。 如果开了 MAC 过滤，把串口打印出来的那个 MAC 地址 （形如 24:6F:28:A1:B3:C4）加到白名单里， 或者干脆先关掉过滤做实验。 实验室、宿舍的公共网络很多还有一层网页认证（Portal）， ESP32 是无法完成这种认证的，只能换成手机热点。

报错原文：fatal error: secrets.h: No such file or directory

原因： 编译器在工程目录里找不到这个头文件。 三个可能：文件根本没建； 建了但保存成了 secrets.h.txt（记事本的默认行为）； 或者文件建在了别的文件夹里。

解决： 在 Arduino IDE 里点标签栏右侧的「∨」下拉菜单， 选「新建标签页」，输入名字 secrets.h， 这样建出来的文件一定在正确位置。 如果是在文件管理器里手动建的，先在「查看 → 文件扩展名」里打开扩展名显示， 确认文件名真的以 .h 结尾而不是 .h.txt。 最后确认文件夹结构是正确的： 文件夹名和 .ino 文件名相同，三个文件在同一层。

报错原文：（没有报错）连上了，但 IP 打印成 0.0.0.0，电脑也 ping 不通

原因： 分两种情况。 如果状态码已经是 3（已连接）却仍然是 0.0.0.0， 说明 TCP/IP 层还没拿到地址——路由器 DHCP 地址池满了， 或者路由器响应太慢，而你在 begin() 之后立刻就读了 IP。 如果状态码是 3、IP 也正常，但电脑 ping 不通， 那就是路由器的「AP 隔离 / 客户端隔离」在拦截局域网内的互访。

解决： 第一，确认读 IP 的代码写在 WiFi.status() == WL_CONNECTED 的分支里面， 而不是 begin() 的下一行（本页代码已经这么做了）。 第二，重启路由器释放 DHCP 租约，或者进管理页面把地址池从 192.168.1.100~192.168.1.199 扩大到 .100~.250。第三，进路由器无线设置里 关掉「AP 隔离 / 客户端隔离 / 无线隔离」。 第四，如果是校园网，多半有这一层限制且你无权修改， 直接改用手机热点做完实验。

报错原文：（没有报错）连上以后每隔几十秒掉一次线，反复自动重连

原因： 按概率排： ① 供电不足——Wi-Fi 发射瞬间电流冲到 500mA， 劣质 USB 线压降过大，芯片掉电复位（日志里会有 Brownout）； ② 信号弱或同频干扰严重，2.4GHz 上挤着微波炉、蓝牙、邻居的十几个 AP； ③ 路由器把长时间没有数据往来的客户端踢下线（节能策略）； ④ 开了省电模式导致心跳包延迟过高，被路由器判定为空闲。

解决： 先换一根粗一点的短 USB 线、换到机箱后面板的口，排除供电。 再看 RSSI：低于 -75 就把开发板挪近，或者加一个有外置天线的开发板版本。 然后在路由器里把 2.4GHz 信道固定为 1、6、11 中的一个 （这三个是互不重叠的信道），不要用「自动」。 确认 WiFi.setSleep(false) 已经调用。 如果要彻底避免被踢，可以在 loop() 里 每 30 秒主动做一次无害的网络活动（比如读一次 RSSI 并打印）， 让路由器认为这个客户端一直活跃。

小结与练习

这一篇真正的收获不是「会连 Wi-Fi」，而是学会了一种 处理异步操作的思维方式。 把它收成三句话：

第一，要联网就用 STA，要给别人连才用 AP。 softAP 是自己发热点，不是连 Wi-Fi，这个误解要先破掉。 第二，网络操作永远是异步的，必须配超时和状态机。 WiFi.begin() 立刻返回，成功与否靠轮询 WiFi.status()； 设了超时才不会被一块连不上的网络拖死。 第三，连不上先查频段，再查状态码。 ESP32 只有 2.4GHz；状态码 1 是找不到网络、4 是密码错、6 是未连接—— 这三个数字能帮你把排查范围一下子缩小到具体的一步。

超时与重试策略 15 秒超时 / 5 秒重试
动手练习
  1. 把超时改成 5 秒，观察差异。 把 WIFI_TIMEOUT_MS 改成 5000， 故意写错密码，数一数日志里「连接超时」出现的间隔变成了多少。 然后想一想：如果这块板子用电池供电， 超时设长一点和短一点，各自省电还是费电？ （提示：射频工作时的电流是空闲时的好几倍。）
  2. 加一个 RSSI 采样与统计。 在 ST_CONNECTED 状态里每 500ms 采一次 RSSI， 累计 20 次后算出平均值、最大值、最小值打印一次。 拿着板子在家里走一圈，记录不同房间的三组数据， 画一张「距离 — RSSI」的粗略曲线。 这份实测数据可以直接写进实验报告。
  3. 把状态机扩成「设备自身的状态指示」。 让板载 LED 在四种情况下有四种不同表现： 连接中快闪、冷却中慢闪、已连接常亮、已连接但 RSSI 低于 -75 时 每 3 秒闪一下「警报」式的双闪。 这个练习的价值在于：你会发现 updateStatusLed() 也会变复杂， 从而理解为什么「状态多的时候一定要用状态机，不要用一堆 if」。
