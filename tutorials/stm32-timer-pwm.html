定时器与 PWM 输出

从「数数」讲到「调光」：定时器其实就是一个会自动归零的计数器， PSC 与 ARR 决定它数多快、数到多少；把计数器和比较寄存器一组合，就得到了 PWM。 这一篇会推清 f = 72MHz / ((PSC+1)*(ARR+1)) 的来龙去脉， 讲明白 APB1 上那个「定时器时钟要乘 2」的经典陷阱， 最后用 TIM2 CH1 → PA0 做一个真正的硬件呼吸灯。

原理介绍

定时器和 GPIO、串口有个本质区别： 它一旦启动，就和 CPU 无关了。 你只要把参数配好、按下开关，它就在后台按自己的节奏数数、翻转引脚， CPU 可以继续干别的事。这就是「硬件定时」与「软件循环延时」的根本差别， 也是呼吸灯不用 HAL_Delay() 也能平滑变化的原因。

定时器就是一个会数数的计数器

STM32F103C8T6 里面有四个通用/高级定时器可用： TIM1（高级，挂 APB2）、 TIM2、TIM3、TIM4（通用，挂 APB1）。 它们内部的核心结构简单得让人意外，只有三个东西： 

   时钟源                预分频器               计数器                自动重装寄存器
  TIMxCLK ──▶ [ PSC 预分频 ] ──▶ CK_CNT ──▶ [ CNT 计数器 ] ──▶ 数到 ARR 就归零
   72MHz        ÷ (PSC+1)        计数时钟      0 → 1 → 2 → ...     并把更新事件标志置 1
                                                                            │
                                                    比较寄存器 CCR ◀─────────┤
                                                                            ▼
                                                              OCxREF ──▶ 输出到引脚（PWM）
                                                            （CNT 与 CCR 比较的结果）

  三个寄存器的分工：
    PSC（Prescaler，预分频器）——「数多快」。把 72MHz 降到自己需要的计数频率
    CNT（Counter，计数器）——「数到几了」。这个值每来一个计数脉冲就加 1
    ARR（Auto-Reload Register，自动重装）——「数到多少归零」。它决定了周期
    CCR（Capture/Compare Register，比较/捕获）——「翻转到哪」。它决定了占空比

  为什么叫「自动重装」：CNT 数到 ARR 之后，硬件自动把 CNT 清零并重新开始，
  整个过程不需要 CPU 参与 —— 所以 PWM 一旦启动就能一直输出，CPU 卡死也不影响。

定时器时钟从哪来：APB1 上那个「×2」

这是定时器这一篇最容易被忽略、又最容易算错的地方。 上一篇我们知道：AHB = 72MHz， APB1 = 36MHz，APB2 = 72MHz。 TIM2/3/4 挂在 APB1 上，那它们的时钟是不是 36MHz？ 不是，是 72MHz。

规则：APB 预分频不为 1 时，定时器时钟 = APB 时钟 × 2

STM32 参考手册里的原话是：如果 APB 预分频系数为 1，定时器时钟等于 APB 时钟； 否则定时器时钟等于 APB 时钟的两倍。 我们的配置里 APB1CLKDivider = RCC_HCLK_DIV2， 所以 TIM2/3/4 的时钟是 36MHz × 2 = 72MHz； 而 APB2 预分频是 1，所以 TIM1 的时钟正好也是 72MHz。

这个设计是为了补偿分频带来的损失，让定时器在常见配置下都能拿到 72MHz。 但它同时也是一个经典的「算错频率」陷阱： 如果按 36MHz 去算 PSC，实际输出频率会是计算值的两倍， 现象就是「呼吸灯节奏比预想快一倍」或者「舵机疯狂抖动」。

一句话结论：本文涉及的所有定时器（TIM1~TIM4）在 72MHz 主频配置下， 计数源时钟都是 72MHz。CubeMX 的时钟树界面里也会在旁边标出这个值，配置时可以直接核对。

PSC 与 ARR：频率公式怎么推出来

公式不要死记，推一遍就永远忘不掉。整个过程只有两步分频： 

第一步：预分频器把 72MHz 降成「计数时钟」
                        72MHz
        CK_CNT  =  ─────────────            （PSC 是 16 位寄存器，取值 0~65535）
                       PSC + 1

  为什么是 PSC+1：PSC 写 0 表示「不分频」（÷1），写 71 表示「÷72」。
  所以分频系数永远是 PSC+1，这是新手最容易漏掉的那个 1。

第二步：计数器从 0 数到 ARR，一共数 ARR+1 个脉冲才算一个完整周期
        （0,1,2,...,ARR —— 数一数就知道是 ARR+1 个数）

                     CK_CNT          72MHz
        f_PWM  =  ───────────  =  ───────────────────
                    ARR + 1        (PSC+1) × (ARR+1)

  ────────────────────────── 反过来用 ──────────────────────────
  要 PWM 频率 f，只需要把 (PSC+1)×(ARR+1) 安排成 72MHz / f 就行。
  习惯做法：先固定计数时钟为 1MHz（PSC = 71），这样每个计数就是 1µs，
            周期用 µs 直接读出来，最好算。

  例：要 1kHz 的 PWM（周期 1ms = 1000µs）
      PSC = 71        → CK_CNT = 72MHz / 72 = 1MHz（1 个计数 = 1µs）
      ARR = 1000 - 1  → 1000µs / 1µs = 1000 个计数，ARR = 999
      验证：f = 72MHz / (72 × 1000) = 1000Hz ✔
      分辨率：CCR 可以取 0~1000，也就是 0.1% 的调节精度

  例：要 50Hz 的舵机信号（周期 20ms = 20000µs）
      PSC = 71        → 同样 1MHz
      ARR = 20000 - 1 → ARR = 19999
      验证：f = 72MHz / (72 × 20000) = 50Hz ✔
      好处：CCR 的数值直接就是脉宽微秒数，1.5ms 就写 1500，非常直观

顺带说一句：同一个定时器还能当「精确秒表」用。把 ARR 设成长周期、打开更新中断， 每溢出一次进一次中断，就得到一个和主频严格挂钩的定时—— 这正是替代 HAL_Delay() 的正规做法： 

/* 配置：1MHz 计数时钟，ARR = 49999 → 每 50ms 溢出一次 */
htim3.Init.Prescaler = 71;          /* CK_CNT = 1MHz */
htim3.Init.Period    = 49999;       /* 50000 个计数 × 1µs = 50ms */

HAL_TIM_Base_Init(&htim3);
HAL_TIM_Base_Start_IT(&htim3);      /* 注意是 Base_Start_IT，不是 PWM_Start */

/* 每 50ms 自动进来一次。这个回调运行在中断里，只做最轻的事 */
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
  static uint8_t cnt = 0;
  if (htim->Instance == TIM3)
  {
    if (++cnt >= 10)                /* 10 × 50ms = 500ms */
    {
      cnt = 0;
      HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);   /* 每 500ms 翻转一次 LED */
    }
  }
}

PWM 是怎么产生的：比较寄存器 CCR

PWM（Pulse Width Modulation，脉冲宽度调制）说白了就是 在固定的周期里，控制高电平占多长时间。 周期由 ARR 定死，高电平长度由 CCR 决定——硬件每一刻都在做同一件事： 比较 CNT 和 CCR 的大小，然后决定引脚输出高还是低。 

  CNT  0 ──────────▶ 300 ──────────▶ 999 ──▶ 归零，重新开始
       │              │                │
       │   CNT < CCR  │  CNT ≥ CCR     │
       ▼              ▼                ▼
   ┌───────────────┐                ┌───────────────┐
   │   高电平      │    低电平      │   高电平      │    ← PWM 模式 1：CNT < CCR 时输出有效电平
   └───────────────┘                └───────────────┘
   │◀── 300 ──────▶│◀──── 700 ────▶│
       高电平时间        低电平时间
   └────────────────── 1000 ──────────────────────┘
                     一个周期（ARR+1 = 1000 个计数）

  占空比（Duty Cycle）= 高电平时间 / 周期 = CCR / (ARR + 1)
  本例：300 / 1000 = 30%

  ★ 为什么分母是 ARR+1 而不是 ARR：
    因为 CNT 是 0~ARR 共 ARR+1 个状态，这是同一个「差一」问题，
    和前面 PSC+1 是同一个道理。

  ★ 极值行为：
    CCR = 0        → CNT 永远不会小于 0 → 输出恒为低 → 0%（全灭）
    CCR = ARR+1    → CNT 永远小于 CCR   → 输出恒为高 → 100%（全亮）
    所以想让 LED 全亮，CCR 写 1000（ARR=999 时）比写 999 更好，后者还差一点点。

改用「PWM 模式 2」就是把上面两个电平对调（CNT < CCR 时输出低电平）； 再加上输出极性设置 TIM_OCPOLARITY_HIGH / LOW， 一共有四种组合。实际项目里 99% 的情况用 PWM 模式 1 + 高极性就够了， 记住「占空比越大越亮」这条直觉即可。

LED 为什么能被 PWM 调光

因为 LED 只有「亮」和「灭」两种状态，它调亮度的方式不是降低电压， 而是快速开关、控制开的时间比例。 只要开关频率高于人眼的临界闪烁频率（约 60~90Hz）， 人眼看到的就是「平均亮度」——这就是 PWM 调光的全部原理。 同样的思路还能控制电机转速（平均电压）、加热功率（平均功率）。

调光为什么用 1kHz 以上、舵机为什么用 50Hz

PWM 频率的选择完全取决于「负载的惯性」：负载反应越快，频率就得越高。

应用 推荐频率 为什么是这个值
LED 调光 / 呼吸灯 > 1kHz（本文用 1kHz） 人眼临界闪烁频率约 60~90Hz，只要高于它就不觉得闪。但低频 PWM 在快速移动视线或头部时会出现频闪条纹（频闪效应），手机摄像头拍摄会出现滚动黑带。取 1kHz 以上可以彻底避免，成本只是分辨率从 20000 档降到 1000 档，对调光完全够用
直流电机调速 1kHz ~ 20kHz 太低会有可听噪声和转矩脉动；取 20kHz 以上（高于人耳上限）可以消除啸叫，代价是开关损耗上升
舵机（SG90 / MG996R） 严格 50Hz（周期 20ms） 舵机内部是一颗专用控制芯片，它按「每 20ms 收到一个脉冲」来解析角度。脉宽 0.5~2.5ms 对应 0°~180°。频率偏离太多（比如给 1kHz）会让内部电路无法识别，表现为抖动、抽风或完全不动
蜂鸣器发声 音频范围 200Hz ~ 5kHz 此时 PWM 频率就是音调本身，占空比固定 50% 时声音最响（方波能量最大）

舵机的角度与脉宽对应关系（这也是实训报告里可以直接抄的标定表）：

目标角度 脉宽 PSC=71 / ARR=19999 时的 CCR 值 占空比
0°0.5 ms5002.5%
45°1.0 ms10005%
90°（中位）1.5 ms15007.5%
135°2.0 ms200010%
180°2.5 ms250012.5%
看出来了：舵机根本不吃「占空比」这一套

舵机看的是绝对脉宽（毫秒数），而不是占空比百分比。 所以驱动舵机时千万别用「设置占空比 7.5%」这种思路—— 一旦你把频率从 50Hz 改成 100Hz，同样的 7.5% 占空比脉宽就变成了 0.75ms， 舵机转到的角度完全变了。 先把周期定成 20ms，再直接用 CCR 写微秒数，这才是舵机的正确用法。

HAL 的四个关键 API

PWM 输出的整个流程只需要记住四个函数，顺序不能乱： 

/* ① 初始化时基单元：把 PSC / ARR / 计数模式写进寄存器
 *    CubeMX 生成的 MX_TIM2_Init() 里就调用了它 */
HAL_StatusTypeDef HAL_TIM_PWM_Init(TIM_HandleTypeDef *htim);

/* ② 配置输出通道：设置 PWM 模式、极性、初始 CCR、是否预装载
 *    没有这一步，引脚不会有任何波形 —— 这是最常被漏掉的一步 */
HAL_StatusTypeDef HAL_TIM_PWM_ConfigChannel(TIM_HandleTypeDef *htim,
                                            TIM_OC_InitTypeDef *sConfig,
                                            uint32_t Channel);

/* ③ 启动输出：使能计数器 + 打开对应通道的输出
 *    ★ 一旦调用，硬件就开始自己跑了，CPU 不再参与 */
HAL_StatusTypeDef HAL_TIM_PWM_Start(TIM_HandleTypeDef *htim, uint32_t Channel);

/* ④ 动态改占空比：只改 CCR，周期不受影响，变化立刻生效
 *    这是一个宏，直接写寄存器，所以它能在中断里安全、快速地调用 */
__HAL_TIM_SET_COMPARE(&htim2, TIM_CHANNEL_1, 300);   /* CCR = 300 */

/* 配套的几个宏，调试时很有用 */
__HAL_TIM_GET_COMPARE(&htim2, TIM_CHANNEL_1);        /* 读回当前 CCR */
__HAL_TIM_SET_AUTORELOAD(&htim2, 19999);             /* 改周期（会改变频率） */
__HAL_TIM_SET_PRESCALER(&htim2, 71);                 /* 改预分频 */

/* 需要停止输出时（比如做「关灯」动作） */
HAL_TIM_PWM_Stop(&htim2, TIM_CHANNEL_1);
配置和启动是两件事，缺一不可

HAL_TIM_PWM_ConfigChannel() 只是「告诉它怎么输出」， 真正的开关是 HAL_TIM_PWM_Start()。 只配置不启动，现象就是「一切看起来都对，示波器上却是一条直线」。 反过来，只启动不配置通道，那条线会一直是低电平。

硬件接线说明

先强调一件很容易踩坑的事： 板载 LED（PC13）不能用来做 PWM。 PC13 不属于任何一个定时器的输出通道，它只能当普通 GPIO 用。 所以这个实验必须外接一只 LED 到 PA0—— 它正好是 TIM2 的通道 1（TIM2_CH1）。

  因为它不再由 CPU 直接控制，而是把输出权交给定时器外设。

  舵机接法（选做）：

上电前必查
  • 确认 LED 接在 PA0 而不是 PC13。接 PC13 上，代码再对也不会有 PWM——那是最容易被误判成「程序没跑起来」的情况。
  • LED 方向别插反。PWM 输出的是高电平有效的方波，正极接 PA0。
  • 必须串限流电阻。PWM 输出高电平时电流由电阻决定，省掉电阻会让引脚长期超载。
  • 接舵机时一定不要用板子的 3.3V 供电。舵机启动和堵转的电流远超板载稳压器的能力，典型现象是「舵机一动，单片机就复位」。
  • PA0 还是 WKUP（唤醒）引脚。本实验它只做 PWM 输出，不受影响；但如果以后要用待机唤醒功能，记得这个引脚被占用了。

完整代码

功能：TIM2 通道 1 在 PA0 上输出 1kHz 的 PWM， 占空比从 0% 到 100% 平滑来回变化，形成呼吸灯效果。 参数：PSC = 71（计数时钟 1MHz）、 ARR = 999（周期 1ms，即 1kHz）、 CCR 在 0~1000 之间来回变化。

关于工程文件的一点说明

这份 main.c 把 htim2 和 MX_TIM2_Init() 都写在了一起，方便独立阅读。 如果你是 CubeMX 生成的工程，htim2 默认定义在 tim.c 里，直接粘贴会出现 Symbol htim2 multiply defined 的链接错误—— 把工程里的 tim.c 移除（或删掉其中重复的定义）即可。 PA0 的复用功能配置由 CubeMX 生成在 stm32f1xx_hal_msp.c 的 HAL_TIM_PWM_MspInit() 里， 注意 CubeMX 在配 PWM 通道时会把 GPIO 初始化写在 HAL_TIM_MspPostInit()（位于 tim.c 末尾）， 两者的分工是：MspInit 开时钟，MspPostInit 配引脚模式。

void Error_Handler(void);

#endif /* __MAIN_H */

 * main.c —— STM32F103C8T6 定时器 PWM 示例：PA0 呼吸灯
 * 功能：TIM2_CH1 在 PA0 输出 1kHz PWM，占空比 0% → 100% → 0% 循环变化
 * 参数：PSC = 71  → 计数时钟 = 72MHz / 72 = 1MHz（1 个计数 = 1µs）
 *       ARR = 999 → 周期 = 1000µs = 1ms → f = 1kHz
 *       CCR ∈ [0, 1000]，占空比 = CCR / 1000
 * 硬件：PA0 --[220Ω]-- LED 正极，LED 负极 -- GND
 * ============================================================================ */

#include "main.h"

/* 呼吸灯的速度：每 5ms 改变一次占空比，每次变化 8 个计数单位 */
#define BREATH_STEP_MS   5U
#define BREATH_STEP_VAL  8

/* ------------------------------ 全局变量 ------------------------------ */
TIM_HandleTypeDef htim2;        /* TIM2 句柄：main.h 里已 extern 声明 */

/* ------------------------------ 私有函数声明 ------------------------------ */
void SystemClock_Config(void);
static void MX_GPIO_Init(void);
static void MX_TIM2_Init(void);
void Error_Handler(void);

/* ============================================================================
 * main()：程序入口
 * ============================================================================ */
int main(void)
{
  int16_t duty = 0;             /* 当前占空比对应的 CCR 值，用有符号数方便做减法 */
  int16_t step = BREATH_STEP_VAL;   /* 变化方向：正数变亮、负数变暗 */

  HAL_Init();                   /* 初始化 HAL（含 SysTick 1ms 中断） */
  SystemClock_Config();         /* 时钟 72MHz —— PSC/ARR 的推算全部基于这个值 */
  MX_GPIO_Init();               /* 配置 PA0 为复用推挽输出 */
  MX_TIM2_Init();               /* 配置 TIM2：PSC=71, ARR=999，通道 1 为 PWM 模式 1 */

  /* ★ 关键一步：启动 PWM 输出。
   * 没有这一句，前面的配置全部只是「写好了寄存器但没打开开关」，
   * 示波器上什么都看不到 */
  HAL_TIM_PWM_Start(&htim2, TIM_CHANNEL_1);

  /* 先把占空比设成 0，避免上电瞬间 LED 突然全亮一下 */
  __HAL_TIM_SET_COMPARE(&htim2, TIM_CHANNEL_1, 0);

  while (1)
  {
    /* ---------- 1. 更新占空比 ---------- */
    duty += step;                             /* 朝当前方向走一步 */

    if (duty >= 1000)                         /* 到达 100%（ARR+1 = 1000） */
    {
      duty = 1000;
      step = -step;                           /* 掉头，开始变暗 */
    }
    if (duty <= 0)                            /* 到达 0% */
    {
      duty = 0;
      step = -step;                           /* 掉头，开始变亮 */
    }

    /* ---------- 2. 立刻生效：只改 CCR，周期不变 ---------- */
    __HAL_TIM_SET_COMPARE(&htim2, TIM_CHANNEL_1, (uint32_t)duty);

    /* ---------- 3. 控制变化速度 ----------
     * 这里其实用 HAL_Delay 也没问题，因为我们只是「隔一段时间改一次 CCR」，
     * 真正产生 PWM 的是硬件，不受这个延时精度影响。
     * 但如果要同时做别的事情（按键、串口），就该换成前面讲的定时中断了 */
    HAL_Delay(BREATH_STEP_MS);
  }
}

/* ============================================================================
 * TIM2 初始化：1kHz PWM
 * ============================================================================ */
static void MX_TIM2_Init(void)
{
  TIM_ClockConfigTypeDef  sClockSourceConfig = {0};
  TIM_MasterConfigTypeDef sMasterConfig      = {0};
  TIM_OC_InitTypeDef      sConfigOC          = {0};

  __HAL_RCC_TIM2_CLK_ENABLE();          /* ★ 第一句永远是时钟使能：TIM2 挂 APB1 */

  htim2.Instance               = TIM2;                  /* 使用 TIM2 */
  htim2.Init.Prescaler         = 71;                    /* PSC = 71 → 72MHz / (71+1) = 1MHz */
  htim2.Init.CounterMode       = TIM_COUNTERMODE_UP;    /* 向上计数：0 → ARR */
  htim2.Init.Period            = 999;                   /* ARR = 999 → 1000 个计数 = 1ms 周期 */
  htim2.Init.ClockDivision     = TIM_CLOCKDIVISION_DIV1;/* 数字滤波器用的死区时钟分频，本实验无关 */
  htim2.Init.AutoReloadPreload = TIM_AUTORELOAD_PRELOAD_DISABLE;  /* 改 ARR 立即生效，方便调试 */
  if (HAL_TIM_Base_Init(&htim2) != HAL_OK)              /* 初始化时基单元（PSC/ARR/计数模式） */
  {
    Error_Handler();
  }

  sClockSourceConfig.ClockSource = TIM_CLOCKSOURCE_INTERNAL;   /* 用内部时钟，不走外部引脚 */
  if (HAL_TIM_ConfigClockSource(&htim2, &sClockSourceConfig) != HAL_OK)
  {
    Error_Handler();
  }

  if (HAL_TIM_PWM_Init(&htim2) != HAL_OK)               /* ★ 初始化 PWM 模式（必调） */
  {
    Error_Handler();
  }

  sMasterConfig.MasterOutputTrigger = TIM_TRGO_RESET;   /* 主从模式：本实验不用触发别的外设 */
  sMasterConfig.MasterSlaveMode     = TIM_MASTERSLAVEMODE_DISABLE;
  if (HAL_TIMEx_MasterConfigSynchronization(&htim2, &sMasterConfig) != HAL_OK)
  {
    Error_Handler();
  }

  /* ---------------- 配置 PWM 输出通道 ---------------- */
  sConfigOC.OCMode     = TIM_OCMODE_PWM1;          /* PWM 模式 1：CNT < CCR 时输出有效电平 */
  sConfigOC.Pulse      = 0;                        /* 初始 CCR = 0 → 0%，即上电全灭 */
  sConfigOC.OCPolarity = TIM_OCPOLARITY_HIGH;      /* 有效电平为高：CCR 越大越亮 */
  sConfigOC.OCNPolarity = TIM_OCNPOLARITY_HIGH;    /* 互补通道极性（TIM2 没有互补通道，写默认值） */
  sConfigOC.OCFastMode  = TIM_OCFAST_DISABLE;      /* 快速模式关闭，标准用法 */
  sConfigOC.OCIdleState = TIM_OCIDLESTATE_RESET;   /* 空闲状态电平（调试暂停时的行为） */
  sConfigOC.OCNIdleState = TIM_OCNIDLESTATE_RESET;
  if (HAL_TIM_PWM_ConfigChannel(&htim2, &sConfigOC, TIM_CHANNEL_1) != HAL_OK)
  {
    Error_Handler();          /* ★ 没有这一步，PA0 永远是低电平 */
  }
}

/* ============================================================================
 * GPIO 初始化：PA0 配置为复用推挽输出
 * ★ 复用（Alternate Function）的含义：这个引脚不再由 CPU 写 ODR 控制，
 *   而是把输出权交给 TIM2 这个外设
 * ============================================================================ */
static void MX_GPIO_Init(void)
{
  GPIO_InitTypeDef GPIO_InitStruct = {0};

  __HAL_RCC_GPIOA_CLK_ENABLE();             /* 不开 GPIOA 时钟，引脚配置无效 */

  GPIO_InitStruct.Pin   = GPIO_PIN_0;             /* PA0 = TIM2_CH1 */
  GPIO_InitStruct.Mode  = GPIO_MODE_AF_PP;        /* ★ 复用推挽输出：PWM 必须是这个模式 */
  GPIO_InitStruct.Pull  = GPIO_NOPULL;
  GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_HIGH;   /* PWM 边沿较陡，用高速档信号更干净 */
  HAL_GPIO_Init(GPIOA, &GPIO_InitStruct);
}

/* ============================================================================
 * 时钟配置：HSE(8MHz) → PLL ×9 → SYSCLK = 72MHz
 * ★ 定时器的所有频率都从这里推出来，这一段错了，PWM 频率就会整体偏移
 * ============================================================================ */
void SystemClock_Config(void)
{
  RCC_OscInitTypeDef RCC_OscInitStruct = {0};
  RCC_ClkInitTypeDef RCC_ClkInitStruct = {0};

  RCC_OscInitStruct.OscillatorType = RCC_OSCILLATORTYPE_HSE;
  RCC_OscInitStruct.HSEState       = RCC_HSE_ON;
  RCC_OscInitStruct.HSEPredivValue = RCC_HSE_PREDIV_DIV1;
  RCC_OscInitStruct.HSIState       = RCC_HSI_ON;
  RCC_OscInitStruct.PLL.PLLState   = RCC_PLL_ON;
  RCC_OscInitStruct.PLL.PLLSource  = RCC_PLLSOURCE_HSE;
  RCC_OscInitStruct.PLL.PLLMUL     = RCC_PLL_MUL9;      /* 8MHz × 9 = 72MHz */
  if (HAL_RCC_OscConfig(&RCC_OscInitStruct) != HAL_OK)
  {
    Error_Handler();
  }

  RCC_ClkInitStruct.ClockType = RCC_CLOCKTYPE_HCLK | RCC_CLOCKTYPE_SYSCLK
                              | RCC_CLOCKTYPE_PCLK1 | RCC_CLOCKTYPE_PCLK2;
  RCC_ClkInitStruct.SYSCLKSource   = RCC_SYSCLKSOURCE_PLLCLK;
  RCC_ClkInitStruct.AHBCLKDivider  = RCC_SYSCLK_DIV1;   /* HCLK  = 72MHz */
  RCC_ClkInitStruct.APB1CLKDivider = RCC_HCLK_DIV2;     /* PCLK1 = 36MHz → TIM2CLK = 36×2 = 72MHz */
  RCC_ClkInitStruct.APB2CLKDivider = RCC_HCLK_DIV1;     /* PCLK2 = 72MHz */
  if (HAL_RCC_ClockConfig(&RCC_ClkInitStruct, FLASH_LATENCY_2) != HAL_OK)
  {
    Error_Handler();
  }
}

/* ============================================================================
 * 出错处理
 * ============================================================================ */
void Error_Handler(void)
{
  __disable_irq();
  while (1)
  {
  }
}

同一份代码改成舵机驱动

只要改三个数字，这份代码就变成了舵机控制器。 这也顺便验证了你是否真的理解了 PSC / ARR / CCR 三者的关系： 

/* ---------- ① 改时基：从 1kHz 改成 50Hz ---------- */
htim2.Init.Prescaler = 71;        /* 不变：计数时钟仍是 1MHz，1 个计数 = 1µs */
htim2.Init.Period    = 19999;     /* 由 999 改成 19999：20000µs = 20ms 周期 = 50Hz */

/* ---------- ② 改主循环：不再扫 CCR，而是直接给角度 ---------- */
__HAL_TIM_SET_COMPARE(&htim2, TIM_CHANNEL_1, 500);    /* 0.5ms → 0°   */
HAL_Delay(1000);
__HAL_TIM_SET_COMPARE(&htim2, TIM_CHANNEL_1, 1500);   /* 1.5ms → 90°  */
HAL_Delay(1000);
__HAL_TIM_SET_COMPARE(&htim2, TIM_CHANNEL_1, 2500);   /* 2.5ms → 180° */
HAL_Delay(1000);

/* ---------- ③ 封装成一个按角度设置的函数，写起来更直观 ---------- */
/* angle: 0 ~ 180（度） */
void Servo_SetAngle(uint8_t angle)
{
  /* 把 0~180° 线性映射到 500~2500µs。
   * 因为计数时钟是 1MHz，CCR 的数值恰好就是微秒数，所以不需要再做换算 */
  uint32_t ccr = 500 + ((uint32_t)angle * 2000) / 180;
  __HAL_TIM_SET_COMPARE(&htim2, TIM_CHANNEL_1, ccr);
}

/* 用法：Servo_SetAngle(90);   → 转到中位 */
为什么选 1MHz 计数时钟是个好习惯

注意上面这两个例子：调光时 CCR 的满量程是 1000， 舵机时 CCR 直接就是微秒数。 之所以都这么顺，是因为我们把计数时钟固定成了 1MHz—— 一个计数正好 1µs，于是「时间」和「计数值」在数值上相等， 省掉了所有换算。工程上这叫「选一个好算的基准」， 比每次心算 72 / (PSC+1) 有效得多。

关键代码解析

  • GPIO_InitStruct.Mode = GPIO_MODE_AF_PP;—— 如果这里误写成 GPIO_MODE_OUTPUT_PP， 引脚就还归 CPU 管，定时器的 PWM 信号根本出不来。 现象是「示波器量不到波形，但程序其他部分都正常」。 凡是外设占用引脚（PWM、串口、SPI），一律复用模式。
  • int16_t duty——用有符号类型是为了让 duty += step 在 step 为负时能正常递减， 判断 duty <= 0 也才有意义。 如果用 uint16_t，减到 0 之后再减就会绕回到 65535， 现象是「呼吸灯刚到最暗就突然全亮」。
  • __HAL_TIM_SET_COMPARE() 是宏而不是函数调用， 它直接往 CCR1 寄存器写值，开销极小， 所以可以放心地放在定时中断里每毫秒调用一次——那才是做呼吸灯的正规方式。
  • HAL_TIM_Base_Init() 与 HAL_TIM_PWM_Init() 都调用了。前者配置时基（PSC/ARR/计数模式），后者配置 PWM 工作模式， 两个函数内部都会调用 MspInit，所以合起来用是标准写法。 漏掉 HAL_TIM_PWM_Init()，通道配置就无效。
  • sConfigOC.Pulse = 0;——初始 CCR 写 0， 配合主循环开头的 __HAL_TIM_SET_COMPARE(..., 0)， 保证上电时 LED 是灭的。如果不设，CCR 的复位默认值是 0， 但如果被上一次运行的残留值影响，就可能出现「上电瞬间闪一下」。
  • 想用 TIM2 的重映射通道（TIM2_CH1_ETR → PA15）时， 必须先关闭 JTAG：调用 __HAL_AFIO_REMAP_SWJ_NOJTAG()。 因为 PA15 默认被 JTAG 占用，不禁用它，你的 PWM 就会被调试接口抢走。 用默认的 PA0 则完全没有这个问题——这也是本实验选 PA0 的原因之一。

现象演示说明

正确现象

  1. 下载完成后，PA0 上的 LED 从熄灭开始逐渐变亮，到最亮后逐渐变暗，如此循环。
  2. 变亮和变暗各约 0.6 秒，一个完整的呼吸周期约 1.3 秒，节奏均匀、没有突跳。
  3. 整个过程中 CPU 可以做别的事——在 while(1) 里加一句串口打印，串口输出照样准时，LED 呼吸也完全不受影响。这就是硬件 PWM 与软件模拟的本质区别。
  4. 如果有示波器，量 PA0 对 GND，能看到周期 1ms（1kHz）的方波，高电平宽度从 0µs 连续变到 1000µs，再变回来。
  5. 如果改成舵机版本（ARR = 19999），能听到舵机转到 0°、90°、180° 三个位置并在每个位置稳定停留 1 秒。

观察点与判据

你观察到的 说明什么 下一步查什么
LED 一直不亮，或一直全亮 PWM 没有真正输出，或 CCR 停在极值 确认 HAL_TIM_PWM_Start() 被调用、HAL_TIM_PWM_ConfigChannel() 没漏、PA0 配的是 GPIO_MODE_AF_PP、__HAL_RCC_TIM2_CLK_ENABLE() 有使能
LED 亮度能变，但变化极快、像在闪 PWM 频率太低（跌进了人眼可感知的范围） 核对 ARR 是不是写成了 99 而不是 999；确认主循环里的 HAL_Delay(BREATH_STEP_MS) 没被删掉
呼吸节奏比预期快一倍 按 PCLK1 = 36MHz 算了 PSC，忘了「APB1 分频不为 1 时定时器时钟 ×2」 把 PSC 从 35 改回 71；在 Watch 里确认定时器时钟确实是 72MHz
频率偏差约 10%（示波器量到 900Hz 而不是 1000Hz） HSE 晶振没起振，时钟回退到内部 HSI：HSI ÷ 2 = 4MHz 经 PLL ×16 = 64MHz（而不是 HSE 8MHz × 9 = 72MHz），定时器时钟跟着变成 64MHz Watch 里加 SystemCoreClock 看是不是 72000000
LED 亮度只有大小两档、中间很突兀 人眼对亮度的感知是非线性的（近似 gamma 2.2） 把线性递增的 duty 换成平方或查表输出，见下面的提示
舵机抖动、抽风或者完全不动 频率不是 50Hz，或脉宽超出 0.5~2.5ms，或电源功率不够 确认 ARR = 19999、PSC = 71；确认舵机用外部 5V 供电并与单片机共地；把 CCR 限制在 500~2500 之间
让呼吸更自然：给占空比加一层 gamma 校正

线性地改变占空比，给人的感觉是「中间那段变化特别快，两端变化很慢」—— 因为人眼对亮度的响应近似 gamma 2.2 的幂函数。 修正办法很简单：内部仍按 0~1000 线性扫描，但写入 CCR 之前先做个平方： 

/* duty 是 0~1000 的线性值，映射成 0~1000 的感知亮度值 */
uint32_t ccr = ((uint32_t)duty * (uint32_t)duty) / 1000U;
__HAL_TIM_SET_COMPARE(&htim2, TIM_CHANNEL_1, ccr);

改完再对比一次，你会发现呼吸的「中间段」变慢了、两端变快了， 整体观感反而更接近真正的呼吸。这类「物理量线性、感知量非线性」的修正 在蜂鸣器音量、电机调速、加热控制里都会遇到，是很通用的工程思维。

顺手记录实验数据

用示波器或逻辑分析仪测三组数据并列表： ① 周期（应为 1000µs）、② 最小/最大脉宽（应为 0µs 和 1000µs）、 ③ 完整呼吸周期时长（理论 = 125 步 × 2 × 5ms = 1250ms）。 再把实测频率和公式 72MHz / (72 × 1000) 对一下， 误差通常在 0.1% 以内。这份「公式算 → 仪器测 → 误差分析」的三段式记录， 是实训报告里最有说服力的部分，也是电子类岗位面试常问的内容。

常见报错排查方案

PWM 的排错有个高效套路： 先用示波器（或万用表直流档）确认引脚有没有在动，再怀疑参数。 有波形但频率不对，是计算和时钟的问题；压根没波形，就是配置和启动的问题。 下面五条按出现频率排序。

现象：编译下载都成功，PA0 上却一点波形都没有

原因：按可能性排序——① HAL_TIM_PWM_Start() 没调用（配置了但没打开开关）；② HAL_TIM_PWM_ConfigChannel() 没调用（通道没配成 PWM 模式）；③ __HAL_RCC_TIM2_CLK_ENABLE() 没使能，所有配置被静默丢弃；④ PA0 配成了 GPIO_MODE_OUTPUT_PP 而不是 GPIO_MODE_AF_PP，输出权还归 CPU；⑤ 引脚接错（接在 PC13 上，那里根本没有定时器通道）。

解决：按上面五条逐一核对。最快的验证办法是把 __HAL_TIM_SET_COMPARE(&htim2, TIM_CHANNEL_1, 500) 固定成 50% 占空比， 然后用万用表直流电压档量 PA0 对 GND—— 正确时应读到约 1.65V（3.3V 的 50%）。 这个「占空比 = 平均电压」的技巧非常好用，万用表也能测 PWM。

现象：PWM 频率是设定值的两倍或一半

原因：定时器时钟算错了。最常见的就是忘了「APB1 预分频不为 1 时，定时器时钟 = PCLK1 × 2」： TIM2/3/4 挂在 APB1（36MHz）上，但实际计数源是 72MHz。 按 36MHz 去算 PSC，得到的分频系数就少了一半，输出频率自然翻倍。

解决：统一按 72MHz 计算，回归公式 f = 72MHz / ((PSC+1) × (ARR+1))。 另外要检查是不是漏掉了那个 +1： PSC = 71 是 ÷72 而不是 ÷71，ARR 同理， 这两个 +1 造成的误差通常在 1%~1.5%，容易在示波器上看出来。

编译报错：Error: L6200E: Symbol htim2 multiply defined (by tim.o and main.o)

原因：把本教程的 main.c 直接粘进了 CubeMX 生成的工程，而工程里的 tim.c 也定义了 htim2，同一个全局变量被定义了两遍。

解决：只保留一份。要么把工程里的 tim.c 从工程中移除 （右键 → Remove File），要么把 main.c 里的 TIM_HandleTypeDef htim2; 删掉、 改用 tim.h 里的 extern 声明。 注意初始化函数 MX_TIM2_Init() 也只能保留一份。

现象：LED 在闪而不是在「呼吸」，肉眼能看到明显的通断

原因：PWM 频率太低，跌到了人眼可感知的范围（低于 60~90Hz 就会觉得闪）。 可能是 ARR 写小了一个数量级（比如写成 99）， 也可能是把 / 和 * 搞混、 算出来的周期比预期大得多。还有一种隐蔽情况：PSC 写成了 719， 计数时钟变成 100kHz，1kHz 的 PWM 需要 ARR=99，此时分辨率只剩 100 档， 亮度变化会有台阶。

解决：把 PSC = 71、ARR = 999 这对参数原样抄回去，先用示波器确认周期是 1ms，再谈亮度效果。 记住那条经验规则：调光频率 ≥ 1kHz，并且分辨率至少 100 档。

现象：舵机一上电就疯狂抖动，或者转动角度完全对不上

原因：① PWM 频率不是 50Hz（舵机内部芯片按 20ms 周期解析，给 1kHz 它无法识别）； ② 脉宽超出了 0.5~2.5ms 的有效范围（CCR 给了 0 或 19999，等于一直低或一直高）； ③ 舵机电源功率不足，一动就把电压拉低导致单片机复位； ④ 外部电源与单片机没共地，PWM 信号没有共同参考点。

解决：确认 PSC = 71、ARR = 19999； 把 CCR 严格限制在 500~2500，并在代码里加一句 if (ccr < 500) ccr = 500; if (ccr > 2500) ccr = 2500; 做保护； 舵机单独用 5V/2A 电源供电，并且把它和单片机的 GND 接在一起。

另外一类：TIM1 输出没波形，但 TIM2 同样的代码却正常

因为 TIM1 是高级定时器，它的 PWM 输出多了一道总闸—— BDTR 寄存器里的 MOE（主输出使能）位。 MOE 不置位，通道配得再对也没有任何输出。 好消息是 HAL_TIM_PWM_Start() 内部会为高级定时器自动置位 MOE， 所以用 HAL 通常不会遇到；但如果你看到某个寄存器版教程只写了 TIM_CtrlPWMOutputs(TIM1, ENABLE) 之类的手动使能， 那就是在补 MOE 这一刀。 记住结论：高级定时器比通用定时器多一个「主输出使能」开关。

小结与练习

定时器是 STM32 里最「值钱」的外设：PWM、输入捕获测频、编码器接口、 精确定时、DMA 触发，全都建立在同一套时基之上。 这一篇需要带走的结论有五条：

  • PSC 管「数多快」，ARR 管「数到几」，CCR 管「翻转到哪」——三个寄存器的分工要能一口说出来。
  • f = 72MHz / ((PSC+1) × (ARR+1))，两个 +1 一个都不能漏；占空比 = CCR / (ARR+1)。
  • APB 分频不为 1 时，定时器时钟是 APB 时钟的两倍——TIM2/3/4 在 72MHz 主频下拿到的也是 72MHz。
  • 配置 ≠ 启动：HAL_TIM_PWM_ConfigChannel() 之后必须 HAL_TIM_PWM_Start()。
  • 频率由负载决定：调光 ≥ 1kHz，舵机严格 50Hz（脉宽 0.5~2.5ms），电机 1~20kHz。
动手练习
  1. 把频率改成 2kHz 并验证：要求计数时钟仍是 1MHz，算出 ARR 应该是多少， 改完下载，用示波器或万用表确认（提示——ARR = 499）。 再用 50% 占空比量一次 PA0 的直流电压，应该还是约 1.65V。 想一想：为什么频率改了、占空比不变，平均电压就不变？
  2. 用定时中断代替 HAL_Delay 做呼吸灯：把 TIM3 配成每 1ms 中断一次 （PSC = 71、ARR = 999），在 HAL_TIM_PeriodElapsedCallback() 里 每 8 次中断改一次 TIM2 的 CCR。做完之后在主循环里加一个按键扫描， 验证「按键响应不再被呼吸灯的延时拖慢」。
  3. 做一个双通道呼吸灯：让 TIM2_CH1（PA0）亮的时候 TIM2_CH2（PA1）暗、反之亦然， 两个 LED 交替呼吸。提示——两个通道共用同一个 ARR， 所以周期是一致的，你只需要让两个 CCR 满足 ccr1 + ccr2 = ARR + 1 这个互补关系；想清楚这为什么会让总电流保持恒定（这在实际产品里是降低电源纹波的手段）。
