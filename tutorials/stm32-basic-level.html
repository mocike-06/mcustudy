3.3V 电平与硬件安全

你在 51 上习惯了「5V 接上去就能用」：传感器是 5V 的、继电器模块是 5V 的、连电源都是 5V。换成 STM32 之后，这一切的前提变了——它是一颗 3.3V 的芯片，引脚能承受的电压有硬上限，而 51 那一侧的 5V 信号正好越过了这条线。这一篇是「接线之前必看」的一篇：哪些引脚能直接接 5V、哪些接上去就烧、拿不准时怎么量、驱动负载为什么必须加三极管，以及那些「程序忽然重启」「ADC 读数一直是满格」背后的硬件原因。看完它，你能省下至少一块板子的钱。

原理介绍

先说清这一篇要解决什么问题。你从 51 转过来，脑子里有一套默认假设：「高电平就是 5V，低电平就是 0V，任何引脚接任何信号都能用」。这套假设在 51 上基本成立，因为 51 的 IO 是 5V 的，而市面上的模块也大多是 5V 的。

到了 STM32，这三条假设全部需要修正：

  • 高电平不再是 5V，而是 3.3V——芯片的供电和引脚电压上限都降到了 3.3V 这个量级。
  • 引脚不是「都能接」，而是分等级的——有些引脚能扛 5V，有些接上去就烧。而这在引脚排布上完全看不出来，只有查数据手册才知道。
  • 引脚不是「想给多少电流就给多少」——每个引脚有 20mA 的硬上限，整片芯片也有总上限。超了不会「工作不正常」，而是直接损坏或者把整片芯片拖到复位。

这一节先把这三件事各自的原理讲清楚，最后一节给你一张「能不能接」对照表——遇到具体接线时直接查表即可。

STM32 是一颗 3.3V 器件：电压是条模拟量，不是「高低」两个字

在 51 的世界里，你习惯把电压想成两种状态：5V 和 0V。但真实世界里电压是一条连续的曲线，芯片内部判断「这算高还是算低」，靠的是两条门限：

STM32F103（3.3V 供电）对输入电压的判定：

   3.3V ┤━━━━━━━━━━━━━━━━━━━━━━━  ← VDD（芯片供电电压）
        │
   2.0V ┤─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─  ← VIH：高于这条线，芯片【保证】读成 1
        │
        │      不 确 定 区
        │   （读成 0 还是 1 没有保证，
        │     随温度、批次、电压波动而变）
        │
   0.8V ┤─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─  ← VIL：低于这条线，芯片【保证】读成 0
        │
   0.0V ┤━━━━━━━━━━━━━━━━━━━━━━━  ← VSS（地）

【关键结论】落在 0.8V ~ 2.0V 之间的电压，芯片读出来什么都可能。
           工程上的规矩：送进引脚的电平，要么低于 0.8V，要么高于 2.0V，
           并且要留出足够余量（一般要求高电平 ≥ 2.4V，低电平 ≤ 0.4V）。

再看输出侧。STM32 引脚输出高电平时，电压接不接近 3.3V 取决于它带了多少电流：

ST 数据手册里的参数含义工程上的实际值
VDD芯片主供电电压范围2.0V ~ 3.6V，标准用 3.3V
VDDA模拟部分（ADC）供电同样 2.0V ~ 3.6V，板上一般和 VDD 接在一起
VOH输出高电平电压空载时接近 3.3V；输出 8mA 时不低于 VDD−0.4V，即约 2.9V
VOL输出低电平电压带载时不超过 0.4V，空载接近 0V
VIH输入判为「高」的最低电压3.3V 供电时约 2.0V
VIL输入判为「低」的最高电压3.3V 供电时约 0.8V

把这些数字和 51 摆在一起，两个方向的麻烦就都浮现出来了——注意是两个方向，新手通常只想到第一个：

【方向一】5V 器件输出 → STM32 输入   （51 的输出接 STM32 的引脚）

   51 输出高 = 5.0V ──────────────►  STM32 引脚
                                      ↑
                        引脚耐压上限约 3.6V（VDD+0.3V，非 FT 引脚）
                        5.0V 远超上限 → 引脚内部的保护二极管导通
                        → 电流倒灌进 3.3V 电源网络 → 发烫 / 损坏

   ⚠ 这是最危险、也最常见的错误。
     只有标着 FT 的引脚能安全接下这个 5V。

【方向二】STM32 输出 → 5V 器件输入   （STM32 的输出接 51 的引脚）

   STM32 输出高 = 3.3V ──────────►  51 输入引脚
                                      ↑
                        51 的普通 IO 是 TTL 门限：VIH ≈ 2.0V、VIL ≈ 0.8V
                        3.3V > 2.0V → 51 读得对，这个方向基本不用管 ✔

   ⚠ 但「5V 器件」不等于「VIH 一定低」：同厂的 CMOS 器件 VIH ≈ 0.7 × VCC = 3.5V，
     3.3V 喂进去它就认不出高电平，那种情况才会「莫名其妙不工作」。
     51 手册里 0.7 × VCC 那一档门限是给 XTAL1 / RST / EA 这几个脚用的（VIH1），
     不是普通 IO 口——拿它当 IO 门限，就会得出「3.3V 读不到」的错误结论。

【结论】
   · 5V → 3.3V：51 输出高就是 5V，不能直连 STM32 的普通输入（非 FT 引脚）——
     先查引脚是不是 FT，不是 FT 就得做电平转换（或分压）
   · 3.3V → 5V：看对方器件的 VIH。51 的普通 IO 是 TTL 门限 VIH≈2.0V，接得进去；
                 CMOS/74HC 系列 VIH≈3.5V，接不了；TTL/74LS 系列 VIH≈2.0V，可以直接接。
为什么 51 那边反而更「宽容」

因为 51（STC89C52RC）是 5V 器件，它的引脚耐压天然就覆盖了 0~5V，所以 3.3V 的信号接进去不会损坏它，普通 IO 口还能把 3.3V 正常读成高电平（TTL 门限 VIH = 2.0V），通常不用做电平转换。而 STM32 是 3.3V 器件，5V 信号接进去是物理上超出耐压，会真真切切地损坏芯片。所以「能不能接」这件事是不对称的：3.3V 进 5V 器件通常能读对（最坏也只是不工作），5V 进 3.3V 器件是会烧。而 STM32 作为 3.3V 器件，恰好处于「怕别人、不怕自己」的位置——你只需要重点防住「外面进来的 5V」。

5V 容忍（FT）引脚：STM32 身上唯一能直接接 5V 的地方

ST 知道世界上遍地是 5V 器件，所以刻意给一部分引脚加了「5V 容忍」的能力。在数据手册里，这个能力标记为 FT（Five-volt Tolerant）。

怎么查一个引脚是不是 FT？去 ST 官网下载 STM32F103C8 的数据手册（Datasheet，文件名类似 stm32f103c8.pdf），翻到 Table 4. Pinouts and pin description（引脚定义表）。这张表有一列叫 I/O structure（I/O 结构），里面的字母就是答案：

标记全称 / 含义能不能接 5V典型引脚
FTFive-volt Tolerant，5V 容忍能（数字输入时）PA8~PA15、PB2~PB15
TTa3.3V 模拟输入，带模拟功能不能，绝对上限 VDD+0.3V ≈ 3.6VPA0~PA7、PB0、PB1（这些也是 ADC 通道）
TC标准 3.3V IO，标了标准输入保护不能PC13 / PC14 / PC15（还额外限制 ≤ 3mA）
BBOOT 相关引脚，内部有特殊上下拉不能当普通 IO 用BOOT0
RST复位引脚，内部带上拉不能接 5V，接 GND 会复位NRST
一条能救命的速记规则：ADC 引脚都不是 FT

在 STM32F103 上，凡是能当 ADC 输入用的引脚（PA0~PA7、PB0、PB1），都不是 5V 容忍的。原因很直接：ADC 要精确测量引脚上的模拟电压，就不能让保护二极管在 3.6V 以上导通去「钳位」电压，否则测出来的值全错。所以 ST 把这些引脚做成了纯 3.3V 的 TTa 结构。

反过来记也成立：看到 PA0 到 PA7 或 PB0/PB1，就当它绝对不能接 5V。而 PA8 以上的引脚基本都是 FT（PA8~PA15 全部是 FT）。这条规则不需要查手册就能用，是你接线时最实用的一条直觉。

把 5V 接进非 FT 引脚，芯片内部发生了什么？每个引脚内部都有两个 ESD 保护二极管：一个从引脚指向 VDD，一个从 VSS 指向引脚。正常工作时输入电压在 0~3.3V 之间，两个二极管都反向截止，不导通。一旦引脚电压超过 VDD+0.3V（约 3.6V）：

【正常情况】输入 3.3V，两个保护二极管都截止

              3.3V (VDD)
                 │
                 ▼  ← 二极管①（引脚→VDD），反向截止，不导通
   引脚 ─────────┴──────── 内部电路（栅极输入）
                 ▲  ← 二极管②（VSS→引脚），反向截止，不导通
                 │
                GND

【超压情况】输入 5V，二极管①正向导通

              3.3V (VDD)
                 │
                 ▼  ← 二极管①导通！电流从这里灌进 VDD 网络
   引脚 ──5V─────┴──────── 内部电路
                 ▲
                 │
                GND

   后果链条：
   ① 导通电流从引脚流进 VDD 网络，把整片的电源电压「抬」起来；
   ② VDD 被抬高，其他本来就正常的引脚反而超压了（连锁反应）；
   ③ 电流带来的功率在芯片内部变成热 → 芯片发烫；
   ④ 电流超过二极管承受能力（数据手册规定引脚注入电流 ±5mA）
      → 二极管烧毁 → 引脚永久损坏，或者整片芯片报废。

   ⚠ 最坑的一点：这个过程【没有任何征兆】。
     程序可能还在跑，只是某个引脚忽然不响应了 ——
     很多人以为是代码问题，在那里查寄存器配置。
FT 的三个重要前提，少一个都会出事
  • 只在「数字输入」模式下才成立。引脚配置成模拟模式（ADC 采样）时，5V 容忍能力失效；配置成推挽输出时，如果外部还硬灌 5V 进来，同样出事。所以「FT 引脚」这个概念只在「我把它当输入用」时才有意义。
  • 它只保护输入，不产生 5V 输出。FT 是「我能接受 5V 进来」，不是「我能输出 5V 出去」。FT 引脚输出高电平依然是 3.3V。
  • 5V 也有上限，一般按 5.5V 以内使用。「5V 容忍」是给标准 5V 逻辑电平用的余量，不是让你接 9V、12V。接 12V 一样会烧。

电平转换的三种实用做法

如果你要接的 5V 信号没法接到 FT 引脚上（比如信号恰好是 PA0 的 ADC 通道，或者引脚已经用满了），就需要做「电平转换」。下面三种做法从简单到可靠排列，各有适用范围。

做法一：电阻分压（最简单，只适合「5V → 3.3V」单向、低速信号）

用两个电阻把 5V 按比例降下来。公式就是初中物理的分压公式：

Vout = Vin × R2 / (R1 + R2)

【电路】 5V 信号源 ── R1 ──┬──► 接到 STM32 引脚
                            │
                            R2
                            │
                           GND

【算例一】按 3.3V 的 0.909 倍设计（刚好 3.0V，留 0.3V 余量）

   取 R1 = 10kΩ（上），R2 = 15kΩ（下）：

        Vout = 5V × 15 / (10 + 15)
             = 5V × 15 / 25
             = 5V × 0.6
             = 3.0V            ✅ 低于 3.3V，安全，且高于 VIH(2.0V)，能读成高

   反过来把引脚上量到的电压换算回原电压：

        Vin = Vout × (R1 + R2) / R2
            = Vout × 25 / 15
            = Vout × 1.667

   也就是说，如果 ADC 读到 1.800V，那么信号源那边其实是 1.800 × 1.667 = 3.000V。

【算例二】常见配法对照

   R1（上）  R2（下）   分压后(输入5V)   反推系数     评价
   ──────── ───────── ─────────────── ─────────── ──────────────────
    2 kΩ     3.3 kΩ       3.11V          1.606     可用，但接近 3.3V 上限
    3 kΩ     6.8 kΩ       3.45V ✗        1.441     太高了，超上限，别用
   10 kΩ    15 kΩ         3.00V          1.667     ★ 推荐，余量合适
   10 kΩ    20 kΩ         3.33V ✗        1.500     贴上限，不建议
   20 kΩ    20 kΩ         2.50V          2.000     余量大，但抗干扰稍差

   原则：分压后的电压落在 2.4V ~ 3.0V 之间最理想 —— 
         既明显高于 VIH(2.0V)，又离 3.3V 上限有距离。

【阻值怎么选？两个约束同时满足】

   ① 不能太小：5V / (R1+R2) 就是常态耗电。
      取 25kΩ 时电流 = 5V / 25kΩ = 0.2mA，可以接受。
      取 250Ω 时电流 = 20mA，白白烧掉，还发热。

   ② 不能太大：STM32 的 ADC 采样时，内部采样电容需要被外部充电。
      如果源阻抗太大，电容来不及充满，读数就会偏低且不稳定。
      经验值：分压电阻总阻值控制在 10kΩ ~ 30kΩ 之间。

【做法一的三个致命限制，务必记住】

   ❌ 只能单向：只解决「5V 进 STM32」，不能反过来做「3.3V 出到 5V」。
   ❌ 只能低速：电阻 + 引脚电容构成 RC 电路，会拖慢边沿。
      信号频率超过约 100kHz 就开始明显变形，串口 115200 都可能出错。
   ❌ 只能点对点：不能用在 I2C 这种「一根线上挂多个器件」的总线上。

做法二：电平转换模块（最省心，双向，推荐给新手）

市面上几块钱的「4 路双向电平转换模块」是性价比最高的方案。它的核心是 MOS 管加两个上拉电阻，能在 3.3V 和 5V 两侧之间双向翻译信号。

常见型号通道数适合的信号注意点
4 路双向电平转换模块4I2C、UART、SPI、普通 IO两侧都要供电：LV 接 3.3V，HV 接 5V，GND 必须共地
TXS0108E8I2C、SPI、UART芯片级方案，适合自己画板；注意它带自动方向检测，不适合强驱动
TXB01044推挽信号不能用于开漏总线（I2C），容易自激振荡
74LVC2458单向信号方向由 DIR 引脚决定，需要额外一个控制脚
用模块时最容易漏的两件事

① 两侧都要供电。模块上的 LV 侧要接 3.3V、HV 侧要接 5V，两侧的 GND 还要连在一起。只接了信号线没接 5V，模块完全不工作——这是最常见的「模块是坏的」误判。

② 别把电源接反。LV 侧接到 5V、HV 侧接到 3.3V，模块会反向翻译，结果和没接一样甚至更糟。接线前先看清模块丝印上哪一侧是 LV。

做法三：开漏 + 上拉到 3.3V（最优雅，I2C 的标准解法）

这一种值得重点理解，因为它同时解决了「5V 器件 ↔ 3.3V 器件」的双向问题，而且成本只有两个电阻。

核心思想是：开漏输出的引脚只能「拉低」，不能「拉高」。高电平完全由外部上拉电阻决定——那么把上拉电阻接到 3.3V 而不是 5V，线上的高电平就变成了 3.3V，无论信号的「主人」是谁。

【电路】 3.3V ──[ 4.7kΩ ]──┬──────────── 信号线（同时也是 STM32 的引脚）
                            │
                            接 5V 器件的开漏输出脚 / 双向数据脚

【工作过程】

  ① 谁都不拉低时：
       3.3V ──[4.7kΩ]──┬── 线上电压 = 3.3V（由上拉电阻决定）
                        │
                        （两端引脚都是开漏，内部 NMOS 关断，相当于断路）
       → 两端都读到「高电平」。
       → STM32 读到 3.3V ✅ 不超压
       → 5V 器件读到 3.3V —— 只要它的 VIH ≤ 3.3V 就能认（多数 I2C 器件可以，
          因为 I2C 规范里 VIH = 0.7×VDD，5V 器件要求 3.5V，这一点要确认！）

  ② 任意一端拉低时：
       3.3V ──[4.7kΩ]──┬── 线上电压 ≈ 0V
                        │
                       ═╧═ 内部 NMOS 导通，直接接到 GND
       → 电流从上拉电阻流过这个 NMOS 到地（约 3.3V/4.7kΩ = 0.7mA）
       → 两端都读到「低电平」。
       → 关键：拉低是「短路到地」，所以不管哪一端拉低，另一端看到的都是 0V，
          不存在超压问题。

【为什么这个方案安全？】
   5V 器件从来不往线上「输出 5V」——它只会把线拉到 0V，或者放手不管。
   线上的电压永远由上拉电阻决定 = 3.3V。所以 STM32 永远不会看到 5V。

【上拉电阻怎么选？】
   · I2C 100kHz  → 4.7kΩ（最常用）
   · I2C 400kHz  → 2.2kΩ ~ 3.3kΩ（速率越高，上拉要越小，边沿才够陡）
   · 普通数字信号 → 4.7kΩ ~ 10kΩ
   · 太小：静态电流大、低电平被抬高（可能识别不到低）
   · 太大：上升沿变缓、高速时通信失败

【STM32 这一侧要怎么配？】
   引脚必须配成【开漏输出】或【复用开漏】：
       HAL: GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_OD;   // 普通 IO 开漏
       I2C: GPIO_InitStruct.Mode = GPIO_MODE_AF_OD;       // 复用开漏
   绝不能配成推挽输出 —— 推挽输出会主动输出 3.3V 高电平，
   和对面拉低的力量「打架」，大电流流过两个 MOS 管，可能烧掉。
还有「做法零」：从源头换掉

很多传感器和模块同时有 3.3V 版和 5V 版（比如 HC-SR04 超声波有 3.3V 版本、DHT22 有 3.3V 版本、很多 OLED 模块支持 3.3V~5V 宽压）。买之前先看一眼供电范围，能省掉整条转换链路。这是最省事、最不容易出错的做法，应该优先考虑。

另一个方向：如果你手上只有 5V 模块，也可以给整个系统用 5V 器件做主控（比如继续用 51），把 STM32 用在对 3.3V 友好的场合。工程上「换器件」往往比「加转换电路」更可靠。

GPIO 的八种模式：每种什么时候用

51 的 IO 只有「准双向口」一种模式（加上读锁存器/读引脚那点差别），而 STM32 的每个引脚都要你从八种模式里选一种。这八种模式分成两大类：输入四种、输出四种。

#模式HAL 里怎么写内部结构什么时候用
1输入浮空GPIO_MODE_INPUT
+ GPIO_NOPULL		高阻，不与任何电平相连，电平完全由外部决定外部已有确定驱动的信号：另一个芯片的输出脚、传感器的数字输出脚。注意：悬空时会乱跳
2输入上拉GPIO_MODE_INPUT
+ GPIO_PULLUP		内部约 40kΩ 电阻接到 VDD按键一端接引脚、另一端接 GND：平时读到高，按下读到低
3输入下拉GPIO_MODE_INPUT
+ GPIO_PULLDOWN		内部约 40kΩ 电阻接到 VSS按键一端接引脚、另一端接 VDD：平时读到低，按下读到高
4模拟GPIO_MODE_ANALOG断开数字输入缓冲器，引脚直连 ADC 通道ADC 采样引脚必须用这个；未使用的引脚也可以用（省电、抗干扰）
5推挽输出GPIO_MODE_OUTPUT_PP上下两个 MOS 管，主动输出高或低LED、驱动另一个芯片的输入脚、绝大多数输出场合。拿不准就用它
6开漏输出GPIO_MODE_OUTPUT_OD只有下面的 NMOS，只能拉低，高电平靠外部上拉I2C 总线、多个器件共享一根线（线与）、需要把高电平拉到 5V 的场合
7复用推挽GPIO_MODE_AF_PP推挽结构，但控制权交给外设（USART/SPI/TIM）USART 的 TX、SPI 的 SCK/MOSI、PWM 输出
8复用开漏GPIO_MODE_AF_OD开漏结构，控制权交给外设I2C 的 SCL/SDA（外设驱动 + 开漏）

怎么快速决定用哪一种？按顺序问自己三个问题：

【第一步】这个引脚是「读别人的信号」还是「输出信号给别人」？

   ├─ 读别人的信号（输入）→ 进第二步
   └─ 输出信号给别人（输出）→ 进第三步

【第二步】是「数字信号」还是「模拟电压」？

   ├─ 模拟电压（要用 ADC 测量）→ 第 4 种：模拟输入
   │                               ★ 配成数字输入会读到乱跳的 0/1，而不是电压值
   └─ 数字信号（只有高低两种）→ 进第二步之 b

       b) 外部信号源是什么类型？
          ├─ 别的芯片的输出脚（推挽驱动）→ 第 1 种：输入浮空
          │     （外部已经能主动输出高低，不需要内部上拉）
          ├─ 按键 / 开关 / 开漏输出 → 需要内部上拉或下拉：
          │     ├─ 开关另一端接 GND → 第 2 种：输入上拉（平时高，按下低）
          │     └─ 开关另一端接 VDD → 第 3 种：输入下拉（平时低，按下高）
          └─ 完全悬空不确定 → 一定要上拉或下拉，否则读数随机跳变

【第三步】这个引脚的控制权归谁？

   ├─ 我自己用代码控制高低 → 进第三步之 a
   └─ 交给外设（串口、SPI、定时器 PWM）→ 进第三步之 b

       a) 我自己控制：
          ├─ 需要输出高电平（作为信号源驱动别人）→ 第 5 种：推挽输出 ★默认
          ├─ 需要「线与」（多个器件共用一根线，谁都能拉低）→ 第 6 种：开漏输出
          └─ 需要输出高电平高于 3.3V（想拉到 5V）→ 第 6 种：开漏输出 + 外部上拉到 5V

       b) 交给外设：
          ├─ 普通信号（USART TX / SPI SCK、MOSI / PWM）→ 第 7 种：复用推挽
          └─ 开漏总线（I2C 的 SCL、SDA）→ 第 8 种：复用开漏

【一句话总结】
   拿不准就选【推挽输出】（输出）或【输入浮空/上拉】（输入），
   这两个覆盖了 90% 的场合。等到你需要 I2C 或 5V 上拉时再换开漏。
F1 的一个隐藏陷阱：输入上拉和输入下拉在寄存器里是「同一种配置」

STM32F103 的 CRL/CRH 寄存器里，每个引脚只有 4 个位（CNF 2 位 + MODE 2 位）。输入方向下：CNF=10 表示「带上拉/下拉的输入」——但这一种配置同时对应上拉和下拉两种模式，到底哪个生效，取决于 ODR 寄存器里对应的那一位：ODR=1 就是上拉，ODR=0 就是下拉。

这意味着：如果你自己写寄存器配「输入上拉」时忘了同时置 ODR 位，实际得到的是下拉，行为和你预期完全相反（按键平时读低、按下读高，正好反过来）。用 HAL 就没有这个问题——GPIO_Init() 内部会根据你的 Pull 字段自动去写 ODR 位。这是「为什么推荐用 HAL」的一个很具体的例子。

引脚电流限制：为什么不能直接用 IO 驱动电机、继电器

这是「从 51 过来」最容易翻车的地方之一，因为 51 的 IO 灌电流能力（约 20mA）在直觉上「挺大」，而 STM32 的数字看起来差不多，于是很多人照着 51 的经验直接接继电器。

STM32F103 的电流硬指标：

单个 IO 拉电流（输出高，电流流出引脚）最大 20mA同上。注意输出高时电压会被拉低，20mA 时可能只有 2.9V

【能直接接的：板载 LED】

   电路：3.3V ──[470Ω]── LED ── PC13
   红色 LED 正向压降约 1.8V，所以电阻上的电压 = 3.3V − 1.8V = 1.5V

        I = U / R = 1.5V / 470Ω ≈ 3.2mA

   ✅ 3.2mA 在 20mA 以内，安全。
   ⚠ 但 PC13 的上限是 3mA，3.2mA 已经【贴着上限】了 ——
     所以板载 LED 的亮度是可以用，但不要再往 PC13 上挂别的负载。

【不能直接接的：5V 继电器模块（不带驱动的裸继电器）】

   典型 5V 小型继电器线圈电阻约 70Ω：

        I = 5V / 70Ω ≈ 71mA

   ❌ 超单个 IO 上限 20mA 的 3.5 倍！

   就算你接的是 3.3V 继电器：
        I = 3.3V / 70Ω ≈ 47mA   ❌ 还是超标

【不能直接接的：直流小电机】

   TT 马达空载约 100~200mA，堵转可以到 500mA 以上。
   ❌ 超过 20mA 十倍以上，而且电机会产生反向电动势和大量噪声。

【不能直接接的：WS2812 灯带】

   每一颗灯珠全白时约 60mA。一颗就超标 3 倍，一条 30 颗的灯带要 1.8A。
   ❌ 完全不可能用 IO 直接驱动。

【超标的后果，比「烧引脚」更麻烦的是「整片复位」】

   ① 引脚内部 MOS 管过流 → 发热 → 烧毁（永久损坏）
   ② 大电流瞬间抽取 VDD 上的电荷 → VDD 电压跌落
      → 低于 2.0V 时芯片内部复位电路动作 → 程序突然从头开始跑
      → 现象：「一开继电器，程序就重启」，很多人查成代码问题
   ③ 电机/继电器线圈断电瞬间产生反向高压尖峰 → 干扰甚至击穿

正确做法：加一级驱动。让 IO 只负责「发出控制信号」（几毫安），真正的大电流由专门的器件去扛。

要驱动的负载推荐方案关键点
单个 LED（≤ 10mA）IO 直驱 + 限流电阻电阻按 (3.3 − Vf) / I 算。避免用 PC13/14/15
多个 LED / 大功率 LED三极管（S8050 / S8550）或 MOS 管IO 接基极/栅极，负载接集电极/漏极。基极串 1kΩ 电阻
继电器买「继电器模块」，或用三极管 + 续流二极管模块自带光耦隔离和三极管驱动，最省事。线圈两端必须并一个 1N4148/1N4007 续流二极管吸收反向尖峰
直流电机MOS 管（AO3400 / IRF540）或电机驱动模块（L298N / TB6612）要能正反转就用 H 桥模块。电机两端并续流二极管或 RC 吸收
多个负载（≥ 3 路）ULN2003 达林顿阵列7 路，每路可达 500mA，内部已经集成续流二极管，非常省事
WS2812 灯带专用 5V 电源 + 74HCT245 电平转换灯带必须独立供电，且 STM32 的 3.3V 数据信号要高到 5V 才能被可靠识别

供电：3.3V 到底从哪来

蓝药丸（Blue Pill）板子上有两个电源引脚容易搞混：5V 引脚和 3.3V 引脚。它们的来源和用途完全不同。

【USB 供电时的完整路径】

   USB 口 ──► 5V 引脚（板上标 5V）
     │            │
     │            └──► 可以直接给 5V 模块供电
     │
     ▼
   AMS1117-3.3  ← 板载 LDO（低压差线性稳压器）
     │
     ▼
   3.3V 引脚（板上标 3V3）──► STM32 的 VDD / VDDA
     │
     └──► 可以给小的 3.3V 模块供电（电流受 LDO 和 USB 限制）

【关键区别】

   5V 引脚                          3.3V 引脚

   来源：直接连 USB 的 5V           来源：板载 LDO 的输出
   能不能当输入：能，接外部 5V      能不能当输入：⚠ 有风险，见下
   给外部供电：能（USB 能提供多少   给外部供电：能，但注意 LDO 电流能力

三条绝对不能做的接法
  • 把 5V 接到 3.3V 引脚。这会直接把 5V 灌进 LDO 的输出端和 STM32 的 VDD 引脚。LDO 会损坏，STM32 也会损坏。接线时务必看清丝印：标 5V 的接 5V，标 3V3 的接 3.3V。
  • 同时用 USB 和外部 3.3V 电源给板子供电。两路电源会互相「倒灌」，轻则电压异常、重则烧掉 LDO。要外接电源就拔掉 USB。
  • 把 9V 电池或 12V 电源直接接到 5V 引脚。5V 引脚不是「宽压输入」，超过 5.5V 就会烧 LDO。要用电池就得加一个降压模块（比如 LM2596 降到 5V）。

供电不足是「玄学问题」的头号来源。它的表现非常像软件 bug，因为它会让芯片在运行中突然复位——看起来就像「程序跑飞了」。

排查供电问题的标准动作

第一步，用万用表量空载电压。3.3V 引脚应该在 3.25V ~ 3.35V 之间；5V 引脚在 4.75V ~ 5.25V 之间。偏离太多就说明供电本身有问题（USB 线太细、电源适配器虚标）。

第二步，带载再量一次。接上所有负载、让程序跑起来（尤其是让大电流外设动作）的同时量 3.3V。如果掉到 3.0V 以下，就是供电不足——解决办法是换更粗的 USB 线、给大负载单独供电、或者在 3.3V 和 GND 之间并一个 100µF ~ 470µF 的电解电容做缓冲。

第三步，怀疑射频模块就彻底隔离它。WiFi/蓝牙模块必须用独立的 LDO 供电（不要从板子的 3.3V 引脚取电），并且模块电源脚旁边放 100µF 以上电容。STM32 和模块之间只连信号线和 GND。

去耦电容：为什么每个电源脚旁边都要放 0.1µF

这是个「老师让你加你就加」的经典问题，但原理其实很好懂：数字芯片的电流消耗不是平稳的，而是脉冲式的。

【问题】芯片内部有成千上万个 MOS 管，每个时钟周期都有一批在同时翻转。
       翻转瞬间需要抽取一个电流尖峰，而平时几乎不耗电。

   电流
    │      ╱╲        ╱╲        ╱╲
    │     ╱  ╲      ╱  ╲      ╱  ╲
    │ ───╱    ╲────╱    ╲────╱    ╲───    ← 72MHz 下每秒 7200 万次
    └──────────────────────────────────► 时间

【麻烦】电流从电源（LDO / 电池）到芯片，中间要经过导线。
       任何一段导线都有【寄生电感】（约 1nH/mm）。

       电感的基本性质：U = L × di/dt
       —— 电流变化越快，电感上产生的电压跌落越大。

       芯片要的那一瞬间电流（di/dt 极大），不可能通过长导线及时送到，
       于是芯片电源脚上的电压会瞬间「塌」下去。

【后果】电压跌落 → 芯片内部某些电路工作不正常 →
       表现为随机复位、程序跑飞、ADC 读数错误、通信出错。

【解决】在电源脚旁边放一个小电容。电容的两端电压不能突变 ——
       它是一个【就近的电荷仓库】。

       3.3V ──┬───────────► 到芯片 VDD 引脚
              │
             ─┴─  100nF  ← 就放在引脚旁边（5mm 内最好）
             ─┬─
              │
       GND ───┴───────────► 到芯片 VSS 引脚

       芯片要电流的瞬间，先从这个 100nF 里取（它就在旁边，路径极短，
       寄生电感几乎为零），而不是从远处的电源经过长导线取。

       100nF 在 72MHz 附近的阻抗很低，正好负责这种高频尖峰。
       但它容量小，只能顶很短的时间 —— 所以还要有「大电容」配合。

【两级配合】
   · 100nF（0.1µF）陶瓷电容：每个 VDD 引脚旁边各放一个，管高频尖峰
   · 10µF ~ 100µF 电解/钽电容：放在电源入口处，管低频波动和整体储能
   · 再大一些（几百 µF）：给电机、继电器这类大负载做缓冲
问题答案
放多少个？每个 VDD 引脚配一个 100nF，一个都不能少。STM32F103C8T6（LQFP48）有 3 个 VDD 引脚 + 1 个 VDDA，所以至少 4 个 100nF。蓝药丸板上已经焊好了
放在哪？尽可能靠近引脚，最好在 5mm 以内。电容的作用依赖「路径短」，放在板子另一头就几乎没用了
为什么是 0.1µF 这个值？这是几十年工程实践的结果：容值够大能顶住尖峰，同时自谐振频率（约 10~20MHz）恰好覆盖数字电路的主要噪声频段。太大（如 1µF）反而高频阻抗变高
不加会怎样？不一定马上坏，但会出现「随机、偶尔、难复现」的故障：偶尔复位、偶尔通信出错、ADC 偶尔跳读。这类问题极难查，所以没人敢省这两个电容
面包板上要做吗？面包板有寄生电容和接触电阻，一般不严格需要。但如果出现随机复位，在面包板的电源轨上并一个 100nF + 一个 10µF是成本最低的一试

静电与操作规范：那些「莫名其妙就坏了」的时刻

人体在干燥环境下能积累几千伏静电（冬天摸门把手被电到，那一下通常是 3000V 以上）。STM32 内部 MOS 管的栅极氧化层只有几纳米厚，几十伏就能击穿它。

更麻烦的是，静电击穿往往不会让芯片立刻坏掉，而是留下「暗伤」：栅极氧化层被削弱，芯片当时还能用，但几周后开始随机出错。这类故障几乎无法归因，所以唯一可靠的办法是从一开始就做好防护。

该做的为什么
拿板子之前先摸一下接地的金属（电脑机箱、暖气片、水龙头）把身上的静电泄放掉。这一步成本为零，效果最明显，养成肌肉记忆

接线前断电，接完检查一遍再上电反复确认电源和地没接反、没有 5V 落到 3.3V 引脚上。花 30 秒省一块板子
不要把板子放在金属桌面、防静电泡棉的导电面上会直接短路板子底面的焊点和走线
不用时放进防静电袋，有条件用防静电垫和防静电手环长期存放和焊接时的主要防护手段
不要用金属镊子去碰引脚和芯片金属工具会把手上静电直接传导到引脚上
杜邦线要插到底，线头不要有散丝面包板接触不良是「玄学问题」的另一大来源，散丝还会造成随机短路
「玄学问题」对照表：看起来像灵异事件，其实都有物理原因
你看到的现象八成是这些原因

ADC 的输入范围：0 ~ 3.3V，接 5V 会烧

STM32F103 的 ADC 是 12 位的，它的输入电压范围是 0V ~ VREF+，而蓝药丸上 VREF+ 和 VDDA 是接在一起的，都是 3.3V。所以 ADC 引脚上绝对不能超过 3.3V。

【输入范围】0V ~ 3.3V（VREF+ = VDDA = 3.3V）

   12 位分辨率 = 2^12 = 4096 个刻度，读数 0 ~ 4095

   每一个刻度代表多少电压（LSB）？
       LSB = 3.3V / 4096 ≈ 0.000806V ≈ 0.806mV

   换算公式（读数值 → 电压）：
       电压 = 读数 × 3.3 / 4095

   举例：
       读数 0      → 0V
       读数 2048   → 2048 × 3.3 / 4095 ≈ 1.650V   （约一半）
       读数 4095   → 3.300V

【为什么接 5V 会烧？】

   ADC 引脚内部同样有两个 ESD 保护二极管（引脚→VDDA、VSSA→引脚）。

   输入 5V 时，引脚电压 > VDDA + 0.3V = 3.6V
   → 「引脚→VDDA」那个二极管正向导通
   → 电流从引脚灌进 VDDA 网络
   → 超过 ±5mA 的注入电流上限 → 二极管损坏 → 引脚报废

   ⚠ 而且 ADC 引脚（PA0~PA7、PB0、PB1）全部【不是 FT 引脚】——
     它们连 5V 容忍都没有。这一点前面已经强调过。

【要接 5V 传感器怎么办？分压】

   例：一个 0~5V 输出的压力传感器，接 PA0（ADC 通道 0）

       传感器输出 ── R1 (10kΩ) ──┬──► PA0
                                 │
                                 R2 (15kΩ)
                                 │
                                GND

   ① 传感器输出 5V 时，PA0 上的电压：
          5V × 15/(10+15) = 3.0V        ✅ 安全，低于 3.3V

   ② 传感器输出 0V 时，PA0 上 0V                      ✅

   ③ 程序里读到电压后，要乘回反推系数：
          原始电压 = 测得电压 × (R1 + R2) / R2
                   = 测得电压 × 25 / 15
                   = 测得电压 × 1.667

      测得 3.0V  →  原始电压 = 3.0 × 1.667 = 5.00V   ✅
      测得 1.5V  →  原始电压 = 1.5 × 1.667 = 2.50V   ✅

【分压电阻的两个额外要求】

   ① 总阻值别太大：ADC 采样时内部采样电容要充电，
      源阻抗太大会导致采样不充分、读数偏低。
      建议 (R1 + R2) 在 10kΩ ~ 30kΩ 之间。
      ★ 有些 STM32 的 ADC 要求源阻抗 < 1.4kΩ（对应最长采样时间），
        如果读数明显偏低，可以把采样时间设长一点，或者用运放做缓冲。

   ② 分压后别贴上限：目标落在 2.5V ~ 3.0V 之间。
      如果分压后是 3.29V，电源稍微一波动就超过 3.3V 了，很危险。

【另外两个容易忘的配置】

   · 引脚模式必须是 GPIO_MODE_ANALOG（模拟输入）。
     配成数字输入的话，读到的是被施密特触发器「整形成 0/1」的结果，
     而不是真实电压。
   · ADC 时钟不能超过 14MHz。72MHz 的 PCLK2 经过 ADCPRE ÷6 得到 12MHz，
     这是标准配置。见《时钟系统》那一篇。
一个常见误判：「ADC 读数一直是满量程」

如果你看到 ADC 读数恒定为 4095（或非常接近），第一反应应该是「引脚上的电压超了」，而不是「代码写错了」。可能的原因有三个：

  • 直接把 5V 传感器的输出接到了 ADC 引脚上，没有分压。这是最常见的一个。此时保护二极管正在导通，芯片可能已经在受损，立刻断电。
  • 传感器输出范围不是 0~5V，而是更高（比如某些 0~10V 输出的工业变送器）。这种要重新算分压比。
  • VREF+ / VDDA 没接好或没有去耦电容，导致参考电压异常。用万用表量一下 VDDA 引脚。

反过来，如果读数一直是 0，先查引脚模式是不是配成了 GPIO_MODE_ANALOG，再查传感器有没有供电、共地没有。

三条「不确定时」的通用判断法
  1. 先看电压，再看引脚。用万用表量信号源输出高电平时的实际电压（不要看标签，要看实测值）。如果 ≤ 3.3V，随便接；如果 > 3.6V，就必须查引脚或做转换。
  2. 看到 ADC 通道就当它是「3.3V 专属」。PA0~PA7、PB0、PB1 这十个引脚，无论当数字口还是模拟口，都不能接 5V。
  3. 拿不准就串一个 1kΩ 电阻试。在最坏的情况下，1kΩ 可以把注入电流限制在 (5−3.6)/1000 = 1.4mA，低于 ±5mA 的上限。这只是应急保护手段，不是正确做法，但能在你接线犹豫时保住芯片。

【适用】I2C 的 SDA/SCL、任何「多器件共享一根线」的总线

【接线要点】
   ① STM32 的 SDA/SCL 引脚必须配成【复用开漏】
          GPIO_InitStruct.Mode = GPIO_MODE_AF_OD;
      配成推挽会和对面的器件「打架」，可能烧引脚。
   ② 上拉电阻只接一次，接在 3.3V 上。
      如果 5V 器件模块上自带上拉电阻（很多模块都有），
      必须把它拆掉或断开，否则它会经 5V 拉高，
      STM32 那一侧就会看到 5V → 前功尽弃。
   ③ 两侧必须共地。

【为什么它能双向自动工作？】
   因为「拉低」永远是从上往下拉（短路到 GND），
   高电平永远由上拉电阻决定（3.3V）。
   所以不管是谁在说话，线上的电压都只有 3.3V 和 0V 两种，
   不存在「谁来输出 5V」的问题。
【适用】需要双向、又要高速的场合。市售「4 路双向电平转换模块」就是这个电路
【元件】一颗 N 沟道 MOS 管（如 BSS138）+ 两个上拉电阻

         │                                │
    [10kΩ]                           [10kΩ]
         │                                │
         ├─── LV ────┬─────────── HV ─────┤
         │           │                    │
   3.3V 器件    ┌────┴────┐         5V 器件

                │     │    │

                   │     │
                 (BSS138 N-MOS)
                   │
              栅极 G 接 3.3V  ← 关键：栅极接低压侧的电源

【工作原理（了解即可，用模块时不用管）】
   · 两侧都高（3.3V / 5V）：MOS 管栅极是 3.3V，
     源极也是 3.3V，Vgs = 0 → 截止 → 两侧被各自的上拉电阻拉高，互不影响
   · 3.3V 侧被拉低到 0V：Vgs = 3.3V − 0V = 3.3V → 导通
     → 5V 侧也被拉到接近 0V → 5V 器件看到低电平
   · 5V 侧被拉低到 0V：MOS 管的体二极管先导通，把 3.3V 侧拉到约 0.7V，
     然后 Vgs 上升使 MOS 管完全导通 → 3.3V 侧被拉到 0V

【市售模块的引脚（一般长这样）】

   │  LV     LV1  LV2  LV3  LV4   GND     │   ← 低压侧接 3.3V 和信号
   │  HV     HV1  HV2  HV3  HV4   GND     │   ← 高压侧接 5V 和信号
   └──────────────────────────────────────┘
       ↑
     两侧都要供电！LV 接 3.3V，HV 接 5V，两侧 GND 都接

【使用注意】
   · 两侧都要接电源，只接信号线模块不工作（最常见的误判）
   · 别把 LV / HV 接反
   · 连接时 LV1 对 HV1、LV2 对 HV2……通道要一一对应

     否则下次重新生成会被覆盖（详见《寄存器、标准库与 HAL》一篇）。

第二步：读取 5V 信号（分压后）并换算回原始电压

下面这段代码做两件事：① 用 PA0（ADC 通道 0）读取经分压的 0~5V 信号；② 把读数值换算成实际电压，再乘上分压比反推出传感器端的真实电压。

接线就是上一节「电路一」：传感器输出 → R1(10kΩ) → PA0 → R2(15kΩ) → GND。

/* ============================================================================
 * 读取 0~5V 传感器的模拟输出（经电阻分压后接入 PA0）
 *
 * 硬件接线：
 *   传感器 OUT ── R1 (10kΩ) ──┬── PA0（ADC1_IN0）
 *                              │
 *                              R2 (15kΩ)
 *                              │
 *                             GND
 *   传感器 VCC ── 5V， 传感器 GND ── 与 STM32 共地
 *
 * 分压比：Vout = Vin × R2/(R1+R2) = Vin × 15/25 = Vin × 0.6
 * 反推系数：Vin = Vout × (R1+R2)/R2 = Vout × 25/15 ≈ Vout × 1.6667
 * ============================================================================ */

#include "main.h"
#include <stdio.h>
#include <string.h>

/* ---------- 由 CubeMX 生成的句柄（在别的 .c 文件里定义） ---------- */
extern ADC_HandleTypeDef hadc1;
extern UART_HandleTypeDef huart1;      /* 用来把结果打印出来 */

/* ---------- 分压电阻的实际值（单位：欧姆） ----------
 * ★ 用你实际焊上去的电阻值填这里！
 *   标称 10kΩ 的电阻实际可能是 9.87kΩ，标称 15kΩ 可能是 15.2kΩ。
 *   想要精确测量，就用万用表量出真实值填进来。 */
#define DIVIDER_R1_OHM     10000.0f    /* 上电阻 R1 */
#define DIVIDER_R2_OHM     15000.0f    /* 下电阻 R2 */

/* ---------- ADC 参考电压 ----------
 * 蓝药丸上 VREF+ 接的是 3.3V。如果你的板子不一样，改这里。 */
#define ADC_VREF           3.300f

/* ---------- ADC 满量程读数（12 位 = 4095） ---------- */
#define ADC_FULL_SCALE     4095.0f

/* ============================================================================
 * 读取一次 ADC，返回引脚上的实际电压（单位 V）
 * ============================================================================ */
static float adc_read_voltage(void)
{
  uint32_t raw = 0;

  /* ① 启动一次转换 */
  if (HAL_ADC_Start(&hadc1) != HAL_OK)
  {
    return -1.0f;                    /* 启动失败，返回一个明显的错误值 */
  }

  /* ② 等待转换完成。第三个参数是超时时间（毫秒），
        必须给，否则 ADC 异常时程序会永久卡死在这里。 */
  if (HAL_ADC_PollForConversion(&hadc1, 100) != HAL_OK)
  {
    HAL_ADC_Stop(&hadc1);
    return -1.0f;
  }

  /* ③ 取出 0~4095 的原始读数 */
  raw = HAL_ADC_GetValue(&hadc1);

  /* ④ 停止本次转换（轮询方式用完就停，省电也避免状态混乱） */
  HAL_ADC_Stop(&hadc1);

  /* ⑤ 换算成电压：电压 = 读数 × VREF / 4095 */
  return ((float)raw * ADC_VREF) / ADC_FULL_SCALE;
}

/* ============================================================================
 * 把「STM32 引脚上的电压」反推成「传感器输出的原始电压」
 * ============================================================================ */
static float voltage_to_source(float v_pin)
{
  /* Vin = Vout × (R1 + R2) / R2 */
  return v_pin * (DIVIDER_R1_OHM + DIVIDER_R2_OHM) / DIVIDER_R2_OHM;
}

/* ============================================================================
 * 用串口打印结果的小工具
 * ============================================================================ */
static void uart_printf(const char *fmt, ...)
{
  char buf[128];
  va_list args;
  int len;

  va_start(args, fmt);
  len = vsnprintf(buf, sizeof(buf), fmt, args);
  va_end(args);

  if (len > 0)
  {
    HAL_UART_Transmit(&huart1, (uint8_t *)buf, (uint16_t)len, 100);
  }
}

/* ============================================================================
 * main
 * ============================================================================ */
int main(void)
{
  float v_pin;        /* 引脚上的电压（分压后） */
  float v_source;     /* 反推出来的传感器原始电压 */
  float v_avg;        /* 多次采样的平均值 */
  uint8_t i;

  /* ---------- HAL 库与时钟初始化（CubeMX 生成） ---------- */
  HAL_Init();
  SystemClock_Config();
  MX_GPIO_Init();
  MX_ADC1_Init();
  MX_USART1_UART_Init();

  uart_printf("\r\n===== 5V 信号分压采集 =====\r\n");
  uart_printf("R1 = %.0f 欧, R2 = %.0f 欧\r\n", DIVIDER_R1_OHM, DIVIDER_R2_OHM);
  uart_printf("分压比 = %.3f, 反推系数 = %.3f\r\n",
              DIVIDER_R2_OHM / (DIVIDER_R1_OHM + DIVIDER_R2_OHM),
              (DIVIDER_R1_OHM + DIVIDER_R2_OHM) / DIVIDER_R2_OHM);

  /* ---------- ADC 校准 ----------
   * ★ 这一步很多人会漏。HAL_ADCEx_Calibration_Start() 会执行一次
   *   内部自校准，不做的话读数可能有几十个 LSB 的固定偏差。
   *   F1 系列的校准函数在 stm32f1xx_hal_adc_ex.h 里。 */
  HAL_ADCEx_Calibration_Start(&hadc1);

  while (1)
  {
    /* ---------- 采 8 次取平均，抑制随机噪声 ---------- */
    v_avg = 0.0f;
    for (i = 0; i < 8; i++)
    {
      v_pin = adc_read_voltage();
      if (v_pin < 0.0f)
      {
        uart_printf("ADC 读取失败！\r\n");
        v_avg = -1.0f;
        break;
      }
      v_avg += v_pin;
      HAL_Delay(2);                  /* 每次采样之间稍作间隔 */
    }

    if (v_avg >= 0.0f)
    {
      v_avg /= 8.0f;                 /* 求平均 */
      v_source = voltage_to_source(v_avg);

      uart_printf("引脚电压 = %.3f V  →  传感器原始电压 = %.3f V\r\n",
                  v_avg, v_source);

      /* ---------- 顺便做个安全判断 ----------
       * 如果引脚电压超过 3.2V，说明分压比不对，或者传感器输出超范围了。
       * 这时候要立刻提醒自己检查电路，而不是继续读。 */
      if (v_avg > 3.2f)
      {
        uart_printf("  ⚠ 警告：引脚电压接近 3.3V 上限！\r\n");
        uart_printf("     请检查分压电阻是否接对、传感器输出是否超范围。\r\n");
      }
    }

    HAL_Delay(500);                  /* 每 500ms 更新一次 */
  }
}

/* ============================================================================
 * 【几个必须注意的点】
 *
 * ① HAL_ADCEx_Calibration_Start() 不能漏
 *    ADC 内部有电容失配，上电后需要校准一次。不做校准，
 *    读数可能整体偏移几十个 LSB（几十毫伏），你会以为是电阻精度问题。
 *
 * ② 分压电阻要用【实测值】
 *    标称 10kΩ 的碳膜电阻误差 ±5%，两个电阻的误差叠加，
 *    反推出来的电压可能偏 3~5%。要精确测量就万用表量一下真实阻值。
 *
 * ③ HAL_ADC_PollForConversion 必须给超时
 *    很多初学者的代码是 HAL_ADC_PollForConversion(&hadc1, HAL_MAX_DELAY)，
 *    一旦 ADC 因为配置错误不产生转换完成标志，程序就永久卡死在这里，
 *    看起来像「单片机死了」。给个 100ms 超时，出问题至少能返回。
 *
 * ④ 采样时间要够
 *    如果分压电阻总阻值较大（比如 30kΩ），ADC 内部采样电容来不及充满，
 *    读数会系统性偏低。解决办法是在 CubeMX 里把
 *    ADC → Parameter Settings → Sampling Time 从 1.5 Cycles 调到
 *    71.5 Cycles 或更长。源阻抗越大，采样时间要越长。
 *
 * ⑤ 共地！共地！共地！
 *    传感器和 STM32 的 GND 必须连在一起。
 *    只连了信号线不连地，读出来的电压是漂浮的随机值。
 *    这是「读数一直乱跳」最常见的硬件原因。
 * ============================================================================ */
/* ============================================================================
 * 如果信号是【数字量】（只有高低两种），而且接到了 FT 引脚上，
 * 就不需要 ADC，也不需要分压，直接读就行。
 *
 * 硬件：5V 传感器数字输出 ──► PA8（FT 引脚，能直接接 5V）
 *       传感器 VCC ── 5V，GND 与 STM32 共地
 * ============================================================================ */

#include "main.h"

/* 判断 PA8 上的电平，并统计高电平出现的次数 */
int main(void)
{
  uint32_t high_count = 0;
  GPIO_PinState level;

  HAL_Init();
  SystemClock_Config();
  MX_GPIO_Init();

  while (1)
  {
    /* HAL_GPIO_ReadPin 返回 GPIO_PIN_SET（高）或 GPIO_PIN_RESET（低） */
    level = HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_8);

    if (level == GPIO_PIN_SET)
    {
      high_count++;
      /* 这里的 high_count 如果想在中断里也访问，必须加 volatile */
    }

    /* 每读 1000 次翻转一次板载 LED，作为「程序还活着」的指示灯 */
    if (high_count % 1000 == 0)
    {
      HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);
    }

    HAL_Delay(1);
  }
}

/* ============================================================================
 * 【CubeMX 里 PA8 要怎么配？】
 *
 *   GPIO mode    : Input mode
 *   Pull-up/Pull-down : No pull-up and no pull-down
 *                      （因为传感器会主动输出高低电平，不需要内部上拉。
 *                        如果信号源是开漏输出，这里要选 Pull-up）
 *   User Label   : SIGNAL_IN
 *
 * 【为什么这个能直接接 5V？】
 *   PA8 属于 PA8~PA15 这一段，在 STM32F103C8 上全部标记为 FT。
 *   数字输入模式下可以承受 5V。
 *
 * 【如果是 PA0 呢？】
 *   PA0 是 TTa 结构，不是 FT，接 5V 会烧。
 *   这时候必须加分压电路（R1=10k、R2=15k），
 *   分压后 5V 变成 3.0V，才能安全地当数字输入读。
 * ============================================================================ */

现象演示说明

这一节回答一个很实际的问题：我接完之后，怎么知道接对了？答案是用万用表量几个点。下面这张表把「该量哪里、正常值是多少、量到别的值说明什么」全部列清楚。

万用表怎么用（给没用过的同学）

调到直流电压档（V⎓ 或 DCV），黑色表笔接板子的 GND（固定不动），红色表笔去点你要测的那个点。读数就是该点对地的电压。注意：如果调到电流档去量电压，万用表会瞬间短路，保险丝会烧——量电压永远用电压档。

三个「必须先量再上电」的检查
  1. 接线完成、还没插 USB 之前：用万用表的通断档（蜂鸣档）量一下 5V 引脚和 3.3V 引脚之间是否短路。蜂鸣器响 = 短路，绝对不要上电。
  2. 第一次接 5V 信号时：先只接信号线，不接 STM32 的电源，单独给信号源上电，量一下分压节点的电压是不是 ≤ 3.0V。确认了再接 STM32。
  3. 接大电流负载之前：先用万用表电流档量一下负载的实际电流。如果超过 20mA，停下来先加驱动电路，别抱着「试试看」的心态接上去。

常见报错排查方案

这一节的每一条都是「看起来像软件问题，其实是硬件问题」的经典案例。排查顺序建议：先断电、先量电压、先查接线，再去改代码。反过来做的话，你会在一个根本不成立的代码假设上花掉一整天。

现象原因解决
接了 5V 传感器之后，那个引脚就没反应了（读出来一直是低，或者一直乱跳） 接在了非 FT 引脚（PA0~PA7、PB0、PB1）上。5V 让引脚内部的保护二极管持续导通，引脚功能异常甚至已经损坏 ① 立刻断电；② 换到 FT 引脚（PA8~PA15、PB2~PB15）重试；③ 如果换了引脚还是不行，说明这个引脚已经烧了，换一个引脚；④ 无法换引脚就加分压电路
ADC 读数一直是 4095（满量程），不管传感器怎么变 引脚上的电压超过了 VREF+（3.3V）。最常见的是 5V 传感器输出没分压就接到了 ADC 引脚 ① 断电，量一下引脚对地电压；② 加分压电路（R1=10k、R2=15k）；③ 确认分压后 ≤ 3.0V 再上电；④ 检查 VDDA 是否正常、有没有去耦电容
芯片发烫，程序还能跑但温度明显不正常 有引脚在超压导通（保护二极管灌电流），或者 5V 落到了 3.3V 网络上，或者有引脚对地短路 立刻断电！不要抱着「还能跑就先不管」的心态。然后：① 检查 5V/3.3V 有没有接反；② 逐个断开外设，看是哪个引入的问题；③ 用通断档查短路；④ 量 3.3V 引脚的电流消耗
ST-Link 下载失败 / 时好时坏 / 识别不到芯片 ① 忘了共地（ST-Link 的 GND 没和板子连）；② SWD 线太长或有干扰；③ 供电不足；④ 芯片进入了低功耗模式或 BOOT0 接错 ① 先接 GND，再接 SWDIO/SWCLK，四根线（3.3V、GND、SWDIO、SWCLK）一根都不能少；② SWD 线尽量短于 15cm；③ 量一下 3.3V；④ BOOT0 接 GND 后重新上电
一开继电器（或电机），程序就复位重启 ① 继电器线圈电流（约 70mA）远超 IO 的 20mA 上限，拉低了 3.3V 电压触发欠压复位；② 线圈断电瞬间的反向尖峰干扰了电源 ① 加三极管/MOS/驱动模块，IO 只出控制信号；② 线圈两端并一个续流二极管（1N4148 或 1N4007，注意方向：阴极接电源正）；③ 3.3V 与 GND 之间并 100µF 以上的电解电容；④ 大负载用独立电源，只共地
STM32 输出 3.3V，但对方 5V 器件收不到（示波器看波形正常，对方就是不响应） 方向二的问题：3.3V 低于对方的 VIH。CMOS/74HC 系列 VIH ≈ 0.7×5V = 3.5V，3.3V 不够 ① 把 STM32 引脚配成开漏输出，外部上拉电阻接到 5V，这样高电平就是 5V；② 或者用 74HCT245（HCT 系列 VIH 只有 2.0V，能接受 3.3V 输入）或电平转换模块
ADC 读数乱跳，稳定不下来 ① 没共地（最常见）；② 分压电阻太大，采样电容充不满；③ 采样时间设太短；④ 没有做 ADC 校准；⑤ 电源噪声大/缺去耦电容 ① 先确认传感器 GND 和 STM32 GND 连在一起；② 分压总阻值降到 10k~20kΩ；③ CubeMX 里把 Sampling Time 调大到 71.5 Cycles；④ 加上 HAL_ADCEx_Calibration_Start()；⑤ 多做几次采样求平均
按键读到的电平和预期完全相反（没按读到低，按下读到高） 上拉/下拉配反了。按键接 GND 应该配上拉（平时高、按下低），配成下拉就正好反了 看按键的另一端接的是 GND 还是 VDD：接 GND 配 Pull-up，接 VDD 配 Pull-down。自己写寄存器时还要注意 F1 的陷阱——输入上拉/下拉在 CRH 里是同一种配置，靠 ODR 位区分，详见前面 GPIO 模式那一节
板子插上 USB 但电脑识别不到 / 板子不工作 ① USB 线是「只充电不传数据」的劣质线；② 5V 引脚被外部电源倒灌导致保护；③ 板上 3.3V 短路 ① 换一根确认能传数据的 USB 线（这是极其常见的原因）；② 拔掉所有外接电源；③ 用通断档查 3.3V 对 GND 是否短路；④ 看板上电源指示灯亮不亮
接上电平转换模块后完全没反应 模块的 LV / HV 两侧只接了信号线，忘了接电源，或者两侧电源接反 ① LV 侧接 3.3V、HV 侧接 5V、两侧 GND 都接——三个电源连接一个都不能少；② 确认没接反；③ 用万用表量模块两侧的供电引脚确认电压正确
一条黄金原则：闻到味道、摸到发烫，第一动作是拔电

芯片损坏往往在几秒内完成，而你的第一反应通常是「等等，我先看看代码」或者「再试一次」——这几秒钟足够把一个还能救的引脚彻底烧掉。记住顺序：拔电 → 量电压 → 查接线 → 最后才看代码。另外，如果闻到焦糊味，一定要找到源头再上电，不要直接重新插上试——烧掉的可能是 LDO，再上电会把 STM32 一起带走。

小结与练习

这一篇要记住的七句话

  • STM32 是 3.3V 器件，引脚输出高电平是 3.3V，非 FT 引脚的耐压上限约 3.6V。
  • 只有 FT 引脚能直接接 5V，而且只在数字输入模式下成立。ADC 引脚（PA0~PA7、PB0、PB1）全都不是 FT——这是最好用的一条速记规则。
  • 转换方向是不对称的：5V 进 STM32 会烧芯片，3.3V 进 5V 器件最多是不工作。所以重点防「外面进来的 5V」。
  • 三种转换做法各有边界：电阻分压只适合单向低速；电平转换模块最省心；开漏 + 上拉到 3.3V 是 I2C 的标准解法。
  • 每个 IO 最多 20mA，全部 IO 合计 150mA。电机、继电器、灯带一律要加驱动电路，否则轻则烧引脚，重则整片复位。
  • 供电是「玄学问题」的头号来源：随机复位、串口乱码、ADC 跳动，先量 3.3V 引脚再怀疑代码。
  • ADC 输入只能是 0~3.3V，接 5V 会烧。要测 5V 信号就分压，电阻总阻值 10k~30kΩ。

自检题

  1. 你有一个 5V 的传感器，数字输出要接到 STM32 上。在 PA0、PA8、PB5 这三个引脚里，哪些能直接接？为什么？
  2. 为什么说「ADC 引脚都不是 FT 引脚」？从 ADC 的工作原理角度解释一下。
  3. 把 5V 接到一个非 FT 引脚上，芯片内部发生了什么？为什么这个过程可能「没有任何征兆」？
  4. 要用电阻分压把 0~5V 降到安全范围，R1（上）= 20kΩ、R2（下）= 30kΩ，分压后是多少伏？程序里读到 1.8V 时，传感器实际输出是多少？
  5. STM32 输出 3.3V 接到某个 5V 器件，器件不响应。为什么？给出两种解决办法。
  6. 为什么不能用 IO 直接驱动继电器？如果一定要用，正确电路长什么样？必须加哪个元件？
  7. 程序每隔几秒重启一次，串口打印反复从头开始。写出你的排查步骤（至少三步）。
自检题答案
  1. 只有 PA8 能直接接。PA8 在 PA8~PA15 这一段，是 FT 引脚。PA0 属于 PA0~PA7，是 TTa 结构（ADC 通道），接 5V 会烧。PB5 属于 PB2~PB15 这一段，也是 FT，其实也能接——所以正确答案是 PA8 和 PB5 都能接，只有 PA0 不能。（这道题考的是「PA0~PA7 和 PB0/PB1 是例外」这条规则记得牢不牢。）
  2. 因为 ADC 需要精确测量引脚上的模拟电压。如果引脚带 5V 容忍能力，就意味着它在 5V 以内不会有保护二极管导通去钳位电压——但反过来，ST 为了让 ADC 引脚在任何情况下都能真实反映外部电压，把这些引脚做成了纯 3.3V 的 TTa 结构，没有 5V 容忍。功能需求和电气保护在这里是矛盾的，ST 优先保证了测量精度。
  3. 引脚内部的「引脚→VDD」保护二极管正向导通，电流从引脚灌进 VDD 网络，把整片电源电压抬高，功率变成热，超过 ±5mA 注入电流上限后二极管烧毁。说「没有征兆」是因为：这个过程不影响程序正常执行的部分，只是那个引脚功能失效了，看起来很像软件 bug。
  4. 分压后 = 5V × 30/(20+30) = 3.0V（安全）。反推系数 = (20+30)/30 = 1.667；读到 1.8V 时，传感器实际输出 = 1.8 × 1.667 = 3.0V。
  5. 因为对方的 VIH 高于 3.3V（CMOS/74HC 系列 VIH ≈ 3.5V），3.3V 达不到它的「判为高」门限。两种解法：① STM32 引脚配成开漏输出，外部上拉电阻接到 5V（高电平由 5V 决定）；② 用 74HCT245（HCT 系列 VIH 只有 2.0V）或电平转换模块。
  6. 因为继电器线圈电流约 70mA，超过单脚 20mA 上限 3.5 倍；大电流会拉低 3.3V 触发复位，断电瞬间的反向尖峰还会干扰电源。正确电路：IO → 1kΩ 基极电阻 → 三极管（S8050）基极，线圈接在 5V 和集电极之间，发射极接 GND。必须加续流二极管（1N4148 或 1N4007），并联在线圈两端，阴极（有环的一端）接 5V 侧。
  7. ① 先量 3.3V 引脚：带载运行时是否掉到 3.0V 以下（供电不足）；② 断开所有外设再试：如果不再重启，说明是某个外设拉低电压或引入干扰，逐个接回来定位；③ 检查有没有大电流负载直连 IO（继电器/电机），有就加驱动电路；④ 用通断档查 5V 与 3.3V、3.3V 与 GND 之间是否短路；⑤ 换一根能传数据的粗 USB 线。核心原则是先量电压、先查接线，最后才怀疑代码。

动手练习

  1. 用万用表建立「电压基线」。板子上电但不接任何外设，量出 3V3 引脚、5V 引脚、一个输出高电平的引脚、一个输出低电平的引脚这四个值，记在笔记本上。以后出问题时，第一件事就是和这四个基线对比。
  2. 亲手搭一次分压电路并验证。用 R1=10kΩ、R2=15kΩ 接 5V，用万用表量分压节点，应该在 3.0V 左右。然后把 R2 换成 20kΩ，看是否变成 3.33V——亲手体会一次「贴上限」有多危险。
  3. 做一个「5V 信号探测器」。把一个 5V 信号（比如 51 板子的某个输出）经分压接到 PA0，用 ADC 读出来，把结果通过串口打印到电脑。然后让 51 那边翻转电平，观察读数在 0V 和 3.0V 之间切换。这道练习把「电平转换 + ADC + 串口」串成了一条完整链路。
  4. 故意制造一次「ADC 满量程」。（注意：用一块不心疼的板子，或者只接一秒钟就断电。）把 5V 直接接到 PA0 上，串口读数会立刻变成 4095。然后用万用表量 PA0 对地电压，你会看到它被钳位在 3.6V 左右——这就是保护二极管正在导通、芯片正在受损的直接证据。看过一次，你这辈子都不会再接错。
  5. 用量程电流表测一次负载。拿一个 5V 继电器模块，用万用表的电流档串在它的 5V 供电线上，量出实际电流。再把结果和「IO 上限 20mA」对比一下——数字会让「必须加驱动」这件事瞬间变得具体。
  6. 检查你自己的板子有没有去耦电容。对照 STM32F103C8T6 的数据手册，数一数它有几个 VDD 引脚，再数一数你板子上有几个 100nF 电容。如果你自己画过板，这一条尤其要查。
