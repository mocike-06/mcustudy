本文是 51 单片机专栏的综合项目，会直接复用 LCD1602 液晶驱动 那一篇里的显示函数。

原理介绍

这一篇的硬件比前面几篇都简单——一共只多接三根线（VCC、GND、DATA）。 难点全在软件上：DHT11 用的是单总线协议， 只用一根数据线，既发又收，靠电平持续的时间长度来区分 0 和 1。 这意味着你写的延时函数准不准，直接决定读回来的数据对不对。

DHT11 是什么

DHT11 不是单纯的“敏感元件”，它内部集成了一颗小单片机：

  • 湿敏元件——电阻式，湿度变化引起电阻变化。
  • NTC 测温元件——热敏电阻，温度变化引起电阻变化。
  • 一颗 8 位单片机——负责把电阻值转换成数字量、做温度补偿，并管理单总线通信协议。
  • 出厂标定的系数——存在内部 OTP 里，所以你不需要自己校准。
参数 湿度 温度
量程 20% ~ 90%RH（元件本体 5% ~ 95%RH） 0°C ~ 50°C
精度 ±5%RH ±2°C
分辨率 1%RH 1°C
采样周期 不能小于 1 秒
供电 3.3V ~ 5.5V（推荐 5V）
DHT11 的小数位永远是 0，不是坏了

它的数据格式里确实留了“小数部分”两个字节，但 DHT11 的分辨率只有 1， 这两个字节固定读回 0x00。 想做 0.1°C 精度的记录，得换 DHT22 / AM2302—— 数据格式一样，但起始信号只要拉低 1ms 以上，读数据的思路可以照搬本篇代码。 这也是为什么本项目的显示只用到整数位。

单总线完整时序

为什么一根线能双向通信？因为双方都采用 “平时放手、要说话才拉低”的方式： 数据线通过一个 4.7kΩ ~ 10kΩ 上拉电阻接到 +5V， 没人理它时线上就是高电平；谁想说话，谁就把线拉低。 单片机这边用准双向口（写 1 就相当于“放手”），DHT11 那边是开漏输出。 没有上拉电阻，这根线永远是低电平，通信必然失败—— 这是本项目第一大坑。

一次完整的读取分成三个阶段：

【阶段 1】主机发起始信号
   主机（单片机）         ┌──────────────────────────────┐
   P3.4 电平   ───────────┘                              └────────
                          │<────── 拉低 ≥ 18ms ──────>│  释放（靠上拉电阻回到高电平）
                          目的：DHT11 内部单片机平时在休眠，需要足够长的低电平把它叫醒

【阶段 2】DHT11 响应（表示“我在，准备发数据”）
   20~40us 之后，DHT11 开始应答：
   DHT11 拉低            ┌────────┐                ┌──── 40 位数据开始
   P3.4 电平   ──────────┘        └────────────────┘
                        │< 80us >│<── 80us ──────>│
                          低电平      高电平

【阶段 3】40 位数据，每一位的格式都一样
   每一位 = 50us 低电平 + 一段高电平，高电平的长度决定这一位是 0 还是 1

        位 = 0 ：  ┌──┐                    ┌──┐
   P3.4 ──────────┘  └────────────────────┘  └────────
                  │50us│<─ 26~28us ─>│50us│  高电平短 → 0

        位 = 1 ：  ┌──┐                           ┌──┐
   P3.4 ──────────┘  └───────────────────────────┘  └───
                  │50us│<──────── 70us ────────>│50us│  高电平长 → 1

   采样策略：等这 50us 低电平结束（上升沿）之后，延时 40us 再看电平
             · 还是高电平 → 这一位是 1（因为 70us 还没走完）
             · 已经变低   → 这一位是 0（因为 26~28us 早就结束了）
             安全区间是 28us ~ 70us，取 40us 正好在正中间，最稳
阶段 谁在拉低 持续时间 含义
起始信号 主机（单片机） ≥ 18ms 把休眠中的 DHT11 叫醒
响应低电平 DHT11 80µs “我收到起始信号了”
响应高电平 —（上拉） 80µs “准备发数据”
数据位起始低电平 DHT11 50µs 每一位都以它开头，用上升沿对齐位边界
数据位高电平 = 0 —（上拉） 26 ~ 28µs 读到 0
数据位高电平 = 1 —（上拉） 70µs 读到 1

算一笔时间账：一位大约 76 ~ 120µs，40 位就是 3 ~ 5ms， 再加上起始信号的 18ms 和响应的 160µs， 读一次完整数据大约需要 22 ~ 25ms。 这个数字很关键，后面讲“为什么要关中断”“为什么不能读太快”都要用到它。

看波形是最好的学习方式

如果你手边有示波器或逻辑分析仪（几十块的那种 USB 逻辑分析仪就够）， 把探头夹在 P3.4 上抓一次通信，你会直接看到上面这张图的实物版： 一个很长的低电平（18ms）、两个 80µs 的方波、然后 40 组“短低 + 长短不一的高”。 对着实物波形调代码，比盯着文字猜快十倍。

40 位数据格式与校验

40 位数据按顺序分成 5 个字节。注意 DHT11 是 先发高位（MSB first）—— 这一点决定了代码里移位和赋值的方向，写反了字节里的 8 位就会整个颠倒。

字节序号 内容 本项目怎么用
第 1 字节 湿度整数部分 直接显示，例如 45 表示 45%RH
第 2 字节 湿度小数部分 DHT11 恒为 0，本项目丢弃
第 3 字节 温度整数部分 直接显示，例如 23 表示 23°C
第 4 字节 温度小数部分 DHT11 恒为 0，本项目丢弃
第 5 字节 校验和 用来判断这次数据是不是读错了

校验规则只有一句话： 第五字节 = 前四个字节之和的低 8 位。 举两个例子，算一遍就懂了： 

例 1：湿度 45%RH、温度 23°C
   45 + 0 + 23 + 0 = 68        68 没有超过 255，校验和就是 68
   完整 40 位数据： 45  0  23  0  68

例 2：湿度 90%RH、温度 50°C（两个都是量程上限附近）
   90 + 0 + 50 + 0 = 140       140 没超过 255，校验和就是 140

例 3：假设四个字节加起来超过 255，比如 200 + 0 + 100 + 0 = 300
   300 = 0x12C，取低 8 位 = 0x2C = 44
   在 C 语言里不用手动取模，把结果存进 unsigned char 时自动就截断了：
       unsigned char sum = buf[0] + buf[1] + buf[2] + buf[3];   ← sum 自动等于 44
   所以校验比较要写成 (unsigned char)(前四个相加) == buf[4]

为什么要有校验？因为这种“靠时间长短判 0/1”的协议天生怕干扰： 线太长、旁边有电机、中断插进来打乱了采样点，都可能把 1 读成 0。 有了校验和，读错的数据会被自己发现并丢掉， 你只要下一轮重读就行。本项目在主循环里就是这么做的： 校验不过就把这次数据扔掉，屏幕上记一个错误次数。

微秒延时与关中断

为什么不能用随便写的循环来延时

判断 0 和 1 的安全区间是 28µs ~ 70µs，窗口不算太窄， 但如果你用一个“每次循环几微秒”的粗略延时函数，误差很容易翻倍。原因有三个：

  • 晶振不同——12MHz 与 11.0592MHz 差 8.5%，串口那一课已经踩过这个坑。
  • 编译器优化等级不同——同一段循环，优化等级一改，机器周期数就变了。
  • 循环本身有开销——for (i = 0; i < 10; i++); 每次循环的判断、自增、跳转加起来大约 4 ~ 6 个机器周期，比你以为的“一条空指令”贵得多。

最可控的办法是用 _nop_()： 它编译出来就是一条 NOP 指令，正好占一个机器周期。 12MHz 晶振、12T 模式下 1 个机器周期 = 1µs， 所以想要 40µs 就老老实实堆 40 个 _nop_()—— 所见即所得，不受循环开销和优化等级影响（_nop_() 来自 intrins.h，编译器不会把它优化掉）。

换成 11.0592MHz 晶振时怎么办

11.0592MHz 下一个机器周期是 12 / 11.0592 ≈ 1.085µs， 同样 40 个 _nop_() 实际是 43.4µs， 仍然落在 28 ~ 70µs 的安全区间内，所以本项目代码不用改。 这也说明一个道理：只要安全区间够宽，就应该把采样点放在区间正中间， 给晶振误差和温度漂移留出余量，而不是贴着边界写。

用示波器校准的通用做法

如果延时窗口很窄（比如某些红外接收、单总线温度芯片），或者你要把代码移植到别的晶振上， 就需要实测校准。标准做法是“翻 IO 口 + 量脉宽”：

  1. 找一个空闲 IO（例如 P1.1），在延时函数进入前拉高、返回后拉低。
  2. 把这句 Delay_40us(); 单独放进主循环里死循环调用。
  3. 示波器测 P1.1 的方波周期就是一个完整循环的时间，高电平时间就是延时函数的实际耗时。
  4. 按实测值调整 _nop_() 的个数或循环次数。
  5. 校准完把翻转 IO 的代码删掉——它自己也要花时间。

为什么读数据时必须关中断

再算一次那笔账：一位数据的高电平只有 26µs 或 70µs， 而 51 的一个中断服务程序（尤其是里面还调了函数、刷了数码管的）执行时间动辄几十微秒。 如果读到一半定时器中断进来了：

  • 中断里的代码会占掉几十微秒，你那个“延时 40µs 再采样”就变成了“延时 80µs 再采样”， 原本是 0 的位早就进入下一位了，数据整体错位。
  • 更糟的是位边界（50µs 低电平）也可能被跨过去，导致后面 40 位全部对不齐。

所以标准写法是：读之前 EA = 0;， 读完立刻 EA = 1;。 这样做有两个必须知道的副作用，都属于工程取舍：

  • 这 22 ~ 25ms 内所有中断都会被推迟。 对本项目无影响（LCD 刷新和秒级计时都感觉不到）， 但如果同时在用 9600 波特率收串口数据，一帧只要 1ms， 连续 22ms 不响应就可能丢字节——那就得改成“先把串口数据收进缓冲区，再读 DHT11”， 或者干脆用带硬件缓存的方案。
  • EA = 0 只关总开关，不会改掉 ES / ET0 这些使能位。 所以 EA = 1 之后串口、定时器中断会照常工作，不需要重新初始化。 真正会出事的是某个提前返回的分支忘记把 EA 打开—— 那之后所有中断永久失效，程序表面还活着但功能全废。 本次代码里每一条 return 之前都补了 EA = 1;，就是这个原因。
采样间隔绝对不能小于 1 秒

DHT11 采集一次需要经历“测量 → 转换 → 存结果”的内部过程， 手册要求两次读取之间至少间隔 1 秒。 读太快会出现两种典型现象：一是温湿度数值明显滞后、变化迟钝； 二是校验和频繁出错（它内部还没准备好，返回的是旧数据或半成品）。 本项目用 Delay_ms(1500)，留了 50% 余量。

硬件接线说明

本项目 = 上一篇的 LCD1602 + 一个 DHT11。DHT11 只有三根线要接， 但其中上拉电阻这一项最容易漏。

     2. 再接 DHT11 的 VCC / GND（先不接数据线），万用表量 DATA 与 GND 之间应有 ~5V
     3. 最后把 DATA 接到 P3.4，上电测试
   这样分步做，出问题时你能立刻判断是“屏幕的问题”还是“传感器的问题”
上电前必查
  • 上拉电阻有没有接。三脚裸传感器没有内部上拉，不接就是“永远读不到数据”。
  • DHT11 的 VCC / GND 有没有接反。接反通电会立刻损坏传感器。
  • 三块电路（单片机、LCD、DHT11）有没有共地。只接信号不接 GND 是最隐蔽的错。
  • 数据线有没有和 LCD 的数据线（P2 口）串了。本项目 DHT11 特意放在 P3.4，就是为了避开 LCD 占用的 P3.5~P3.7。
  • 连接线不要太长。DHT11 手册建议数据线在 20m 以内，实验用杜邦线十几厘米最稳；线长了要加屏蔽或用双绞线。

完整代码

代码分成三块：微秒延时、DHT11 读取、 LCD 显示。前两块是本篇的新内容， LCD 那几个函数是上一篇原封不动搬过来的（注释做了精简）。 

#include <reg52.h>
#include <intrins.h>                  /* _nop_() 在这里声明，少了它会报 C202 */

/* ---------------- 引脚定义 ---------------- */
sbit DHT11_DATA = P3^4;             /* DHT11 单总线数据线（必须外接 4.7k~10k 上拉） */

#define LCD_DATA   P2               /* LCD 数据总线 D0~D7 → P2.0~P2.7 */
sbit LCD_RS = P3^5;                 /* RS：0 = 指令，1 = 数据 */
sbit LCD_RW = P3^6;                 /* RW：0 = 写，1 = 读 */
sbit LCD_EN = P3^7;                 /* EN：下降沿锁存数据 */

sbit LED_RUN = P1^0;                /* 心跳灯：程序还活着就能看见 */

/* ==================================================================
 * 第一部分：延时函数
 * ================================================================== */

/* 毫秒延时：起始信号的 18ms 和采样间隔都用它 */
void Delay_ms(unsigned int ms)
{
    unsigned int i, j;
    for (i = ms; i > 0; i--)
        for (j = 110; j > 0; j--);
}

/* 粗延时：约 (5 × us) 微秒（12MHz 下每次循环约 5 个机器周期）
 * 只用在“等待信号到来”这种不敏感的地方；
 * 判断 0/1 的关键采样点必须用下面的 Delay_40us()
 */
void Delay_us(unsigned char us)
{
    while (us--)
    {
        _nop_(); _nop_(); _nop_(); _nop_();
        _nop_(); _nop_(); _nop_(); _nop_();
    }
}

/* ------------------------------------------------------------------
 * 关键采样延时：40us
 *   12MHz 晶振、12T 模式：1 个机器周期 = 1us，一个 _nop_() 正好 1us
 *   所以堆 40 个 _nop_() 就是 40us，所见即所得，不受循环开销影响。
 *
 *   为什么是 40us？判断 0/1 的安全区间是 28us ~ 70us：
 *     早于 28us 采样：是 0 的位还是高电平，会被误判成 1
 *     晚于 70us 采样：是 1 的位已经变低，会被误判成 0
 *   取正中间的 40us，给晶振误差、温度漂移都留了余量。
 *   换成 11.0592MHz 时它实际是 43.4us，仍在安全区间内。
 * ------------------------------------------------------------------ */
#define Delay_40us()  do { \
        _nop_(); _nop_(); _nop_(); _nop_(); _nop_(); _nop_(); _nop_(); _nop_(); \
        _nop_(); _nop_(); _nop_(); _nop_(); _nop_(); _nop_(); _nop_(); _nop_(); \
        _nop_(); _nop_(); _nop_(); _nop_(); _nop_(); _nop_(); _nop_(); _nop_(); \
        _nop_(); _nop_(); _nop_(); _nop_(); _nop_(); _nop_(); _nop_(); _nop_(); \
        _nop_(); _nop_(); _nop_(); _nop_(); _nop_(); _nop_(); _nop_(); _nop_(); \
    } while (0)

/* ==================================================================
 * 第二部分：DHT11 单总线读取
 * ================================================================== */

/* ------------------------------------------------------------------
 * 等待数据线变成指定电平，带超时保护
 *   level：0 = 等低电平，1 = 等高电平
 *   返回 0 = 等到了；1 = 超时（大约 1ms 都没等到，说明传感器没应答）
 * 超时的意义：万一传感器没插好，程序不会卡死在这个死循环里
 * ------------------------------------------------------------------ */
unsigned char DHT11_WaitLevel(unsigned char level)
{
    unsigned char t = 200;          /* 每轮循环约 5 个机器周期，200 轮约 1ms */

    while (DHT11_DATA != level)
    {
        if (--t == 0)
            return 1;               /* 超时 */
    }

    return 0;
}

/* ------------------------------------------------------------------
 * 读一次 DHT11
 *   humi：输出，湿度整数部分（%RH）
 *   temp：输出，温度整数部分（°C）
 *   返回 0 = 成功；1 = 校验和错误；2 = 超时（传感器没应答）
 * ------------------------------------------------------------------ */
unsigned char DHT11_Read(unsigned char *humi, unsigned char *temp)
{
    unsigned char i, j;
    unsigned char buf[5];

    EA = 0;                         /* ---------- 关中断！读这 22ms 不能被任何人打断 ---------- */

    /* ---------- 阶段 1：主机发起始信号（拉低 ≥18ms 把 DHT11 叫醒）---------- */
    DHT11_DATA = 0;                 /* 主机拉低 */
    Delay_ms(20);                   /* 保持 20ms（手册要求 ≥18ms，多留一点余量） */
    DHT11_DATA = 1;                 /* 释放总线：写 1 后引脚处于弱上拉，线被 4.7k 拉到高电平 */

    /* ---------- 阶段 2：等 DHT11 响应（80us 低 + 80us 高）---------- */
    if (DHT11_WaitLevel(0)) { EA = 1; return 2; }   /* 等它拉低（20~40us 后开始） */
    if (DHT11_WaitLevel(1)) { EA = 1; return 2; }   /* 等这 80us 低电平结束 */
    if (DHT11_WaitLevel(0)) { EA = 1; return 2; }   /* 等 80us 高电平结束 → 第一位开始 */

    /* ---------- 阶段 3：读 40 位数据（5 个字节，高位先发）---------- */
    for (i = 0; i < 5; i++)
    {
        buf[i] = 0;                 /* 每读一个字节前清零 */

        for (j = 0; j < 8; j++)
        {
            /* 每一位都以 50us 低电平开头，先等它结束（上升沿 = 位边界） */
            if (DHT11_WaitLevel(1)) { EA = 1; return 2; }

            /* 高电平持续 26~28us 表示 0，70us 表示 1
             * 在 40us 处采样：还是高电平就是 1，已经变低就是 0
             */
            Delay_40us();

            buf[i] <<= 1;             /* 先左移一位，给新来的这一位腾出最低位（高位先发） */

            if (DHT11_DATA == 1)
            {
                buf[i] |= 0x01;                             /* 这一位是 1 */
                if (DHT11_WaitLevel(0)) { EA = 1; return 2; }   /* 等这 70us 高电平结束 */
            }
            /* 如果这一位是 0：40us 时高电平早就结束了，此刻正处在下一位的 50us 低电平里，
             * 直接进入下一轮循环即可，不需要额外等待 */
        }
    }

    EA = 1;                         /* ---------- 读完了，立刻恢复中断 ---------- */

    /* ---------- 阶段 4：校验（第五字节 = 前四字节之和的低 8 位）---------- */
    if ((unsigned char)(buf[0] + buf[1] + buf[2] + buf[3]) != buf[4])
        return 1;                   /* 校验不过，这次数据丢掉，让主循环下一轮重读 */

    *humi = buf[0];                 /* 湿度整数部分 */
    *temp = buf[2];                 /* 温度整数部分 */

    return 0;                       /* 成功 */
}

/* ==================================================================
 * 第三部分：LCD1602 驱动（与上一篇完全相同，注释略）
 * ================================================================== */

void LCD_Delay_short(void)
{
    unsigned char i;
    for (i = 0; i < 15; i++)
        _nop_();
}

void LCD_EN_Pulse(void)
{
    LCD_EN = 1;
    LCD_Delay_short();
    LCD_EN = 0;
}

void LCD_WriteCmd(unsigned char cmd)
{
    LCD_RS   = 0;
    LCD_RW   = 0;
    LCD_DATA = cmd;
    LCD_EN_Pulse();

    if (cmd < 0x03)
        Delay_ms(2);                /* 清屏 / 光标复位要 1.64ms */
    else
        LCD_Delay_short();
}

void LCD_WriteData(unsigned char dat)
{
    LCD_RS   = 1;
    LCD_RW   = 0;
    LCD_DATA = dat;
    LCD_EN_Pulse();
    LCD_Delay_short();
}

void LCD_Init(void)
{
    Delay_ms(50);                   /* 上电后控制器内部复位需要 >15ms */
    LCD_WriteCmd(0x38);             /* 8 位总线、2 行、5×8 点阵（连写三次更稳） */
    Delay_ms(5);
    LCD_WriteCmd(0x38);
    LCD_WriteCmd(0x38);
    LCD_WriteCmd(0x0C);             /* 开显示、关光标、不闪烁 */
    LCD_WriteCmd(0x06);             /* 地址自增、整屏不移动 */
    LCD_WriteCmd(0x01);             /* 清屏 */
}

void LCD_SetCursor(unsigned char row, unsigned char col)
{
    unsigned char addr = (row == 0) ? 0x00 : 0x40;

    if (col > 15) col = 15;
    LCD_WriteCmd(0x80 | (addr + col));
}

void LCD_ShowString(unsigned char row, unsigned char col, char *s)
{
    LCD_SetCursor(row, col);
    while (*s != '\0')
        LCD_WriteData((unsigned char)(*s++));
}

/* 显示定长十进制数：num = 23、len = 2 → 显示 “23”
 * 定长的好处是数字从 9 变到 10 时不会残留旧字符 */
void LCD_ShowNum(unsigned char row, unsigned char col, unsigned int num, unsigned char len)
{
    unsigned char buf[5];
    unsigned char i;

    if (len > 5) len = 5;

    for (i = 0; i < len; i++)
    {
        buf[len - 1 - i] = (unsigned char)('0' + num % 10);
        num /= 10;
    }

    LCD_SetCursor(row, col);
    for (i = 0; i < len; i++)
        LCD_WriteData(buf[i]);
}

/* ==================================================================
 * 主程序
 * ================================================================== */
void main(void)
{
    unsigned char humi = 0;         /* 湿度整数部分 */
    unsigned char temp = 0;         /* 温度整数部分 */
    unsigned char err;
    unsigned int  fail = 0;         /* 累计失败次数，方便判断是偶发还是接线问题 */

    LED_RUN = 0;

    LCD_Init();

    /* 先把固定文字一次写好，之后每轮只覆盖变化的数字 —— 这样屏幕不会闪 */
    LCD_ShowString(0, 0, "Temp:     C");
    LCD_ShowString(1, 0, "Humi:     %RH");

    Delay_ms(1000);                 /* DHT11 上电后需要 1s 越过不稳定状态，别急着读 */

    while (1)
    {
        err = DHT11_Read(&humi, &temp);

        if (err == 0)
        {
            LCD_ShowNum(0, 6, temp, 2);         /* 温度：第 7~8 格 */
            LCD_ShowNum(1, 6, humi, 2);         /* 湿度：第 7~8 格 */
            LCD_ShowString(0, 12, "    ");      /* 成功就把上一轮的错误提示擦掉 */
        }
        else
        {
            LCD_ShowString(0, 12, "E");
            LCD_ShowNum(0, 13, fail, 3);        /* 显示累计失败次数：E 1 / E 12 / E 137 */
            fail++;
        }

        LED_RUN = ~LED_RUN;                     /* 心跳灯：每次循环翻转一次 */

        Delay_ms(1500);                         /* 采样间隔必须 ≥1s，这里留足余量 */
    }
}

关键代码解析

  • #define Delay_40us() do { … } while (0)—— 用宏而不是函数，是为了避开函数调用的开销。 51 上一次 LCALL 加一次 RET 就要花掉大约 4 个机器周期（4µs），对 40µs 的精度来说这笔开销不能忽略。 外面套 do { … } while (0) 是宏定义的标准写法， 保证它用起来和一条语句完全一样（尤其是写在 if 后面时不会出错）。
  • DHT11_WaitLevel()——把“等某个电平”抽成一个带超时的函数， 是这段代码里最重要的工程习惯。没有超时保护时，只要传感器没插好， while (DHT11_DATA == 0); 就会永远转下去， 现象是“程序看起来死了、屏幕不刷新”。有了 200 次超时，最坏情况也只是返回错误码， 主循环下一轮接着试。
  • EA = 0; … EA = 1;—— 成对出现，而且每一条提前返回的路径上都补了 EA = 1;。 这是关中断代码最容易犯的错：正常路径记得开，错误路径忘了开， 结果程序“看起来在跑”，但串口、定时器全部失灵。
  • buf[i] <<= 1; 然后再 buf[i] |= 0x01;—— 这两句的顺序不能反，它对应的是 “DHT11 先发高位（MSB first）”。先左移把已经收到的位往高位挪， 再往最低位填入新收到的一位。如果写成先或后移，读回来的字节里 8 位就是反的 （例如 23°C 会读成 232°C 那种离谱数字）。
  • if (DHT11_DATA == 1) 里多了一次 DHT11_WaitLevel(0)——这一句是把 1 的 70µs 高电平“等完”，让循环回到“下一位的 50µs 低电平”这个统一起点上。 如果省掉它，下一轮进来时可能还停在高电平里， 于是“等上升沿”立刻返回，整个位边界就此错位。
  • LCD_ShowString(0, 0, "Temp: C") 只写一次， 之后每轮只调用 LCD_ShowNum 覆盖数字—— 和上一课讲的一样：固定文字写一次、变化的部分覆盖写、永远不清屏， 这是屏幕不闪的唯一诀窍。这里用定长 2 位显示，也避免了个位变十位时的字符残留。
  • LCD_ShowNum(0, 13, fail, 3)——把失败次数显示出来， 是调试期的“仪表盘”。如果这个数字一直是 0，说明通信很稳； 如果每读几次就涨一次，多半是上拉电阻偏大、线太长或者有干扰源； 如果它一路猛涨，就是接线或时序根本没对。有了它，你不需要串口也能判断系统状态。
  • Delay_us() 与 Delay_40us() 分工明确—— 前者是“差不多就行”的粗延时（约 5µs 一格），只用在超时计数器之类的地方； 后者是“所见即所得”的精确定时，只用在判断 0/1 的关键采样点。 把精度要求不同的延时分开写、分开注释，是嵌入式代码可维护性的关键—— 半年后你回来看，一眼就知道哪个能改、哪个不能碰。

现象演示说明

正确现象

  1. 上电后 LCD 先显示 Temp: C 与 Humi: %RH，数字位置是空的。
  2. 大约 1 秒后数字填上，例如第一行 Temp: 23 C、第二行 Humi: 45 %RH，之后每 1.5 秒更新一次。
  3. 更新时只有数字那两格在变，屏幕其余部分完全不动、不闪。
  4. P1.0 的心跳灯每 1.5 秒翻转一次（因为一次循环结束才翻转），说明主循环在正常运转。
  5. 对着传感器哈一口气：湿度会明显上升（可能涨到 60% 以上），温度也会升一两度；过一两分钟慢慢回落。
  6. 用手捏住传感器外壳：温度会缓慢上升——这是最直观的“它在真的测量”的证据。

观察点与判据

你观察到的 说明什么 下一步查什么
数字一直是 0，屏幕上没有错误提示 读数成功但值和实际不符（罕见） 确认 buf[0] / buf[2] 取的是第 1、3 字节，别取错了小数位
右上角出现 E 加一个猛涨的数字 通信根本没建立（超时返回 2） 上拉电阻、DATA 引脚、VCC/GND、共地，逐项用万用表确认
失败次数偶尔涨一次，大部分时候正常 通信基本对，但有干扰或采样点偏差 缩短连线、换 4.7kΩ 上拉、把 Delay_40us() 调到 35~45 之间试试
湿度温度都读出离谱的大数（比如 232、255） 位序读反了，或位边界错位 检查 buf[i] <<= 1; 是否写在赋值之前；检查 1 分支里有没有等完那 70µs
把采样间隔改成 200ms 后，校验错误明显变多 违反了“间隔 ≥1s”的要求 改回 1000ms 以上；DHT11 内部转换跟不上这么快的节奏
拔掉 DHT11 后程序不再刷新，心跳灯也不闪了 有死循环在等电平，没有超时保护 确认所有等待都走 DHT11_WaitLevel()，代码里不要留裸的 while (DHT11_DATA == 0);
屏幕显示正常，但串口/定时器功能突然全失效 某条路径关中断后没恢复 EA = 1 逐个检查 DHT11_Read 里的每一条 return，前面都必须有 EA = 1;
想验证“关中断到底有没有必要”

在 DHT11_Read 开头把 EA = 0; 改成 EA = 1;（等于不关中断）， 同时打开一个 1ms 的定时器中断、在里面加一句 Delay_us(2) 之类的小动作， 再观察失败次数。你会看到失败率明显上升——这就是时序敏感型协议的真实脾气， 写进实验报告比空口说“要关中断”有说服力得多。

常见报错排查方案

编译报错：error C202: '_nop_': undefined identifier

原因：用了 _nop_() 但没有包含它所在的头文件。_nop_() 不是 C 语言的关键字，而是 Keil 提供的内部函数，声明在 intrins.h 里。另外要确认芯片型号选的是 8051 系列（比如 AT89C52 / STC89C52），ARMMDK 的工程里没有这个函数。

解决：在文件开头加上 #include <intrins.h>。同一个头文件里还有 _crol_（循环左移）等常用内部函数，做流水灯时也用得到。

现象：失败次数一路猛涨，温湿度永远不更新

原因：通信根本没有建立起来，DHT11_Read 一直返回 2（超时）。按发生概率排序：① 数据线没接上拉电阻（三脚裸传感器必踩）；② DATA 接到了别的引脚，代码里的 P3^4 和实际接线不一致；③ VCC 与 GND 接反或没共地；④ 主机拉低时间不够（把 20ms 改成了 2ms 之类）。

解决：断开传感器，只上电单片机，用万用表量 DATA 引脚对 GND 的电压—— 装了上拉电阻应该是接近 5V 的高电平。如果量到 0V，说明引脚被短路或被别的代码拉死了。 再把传感器接上，量一次读数过程中的波形（有条件就上示波器）， 看那个 18ms 的低电平有没有真的出现。

现象：温湿度偶尔能读对，但校验和经常报错（失败次数缓慢上涨）

原因：通信建立了但时序不够稳。三种典型情况：① 读数据期间被中断打断（忘了 EA = 0;，或者中断里干了耗时的事）；② 采样间隔小于 1 秒，DHT11 内部还没转换完；③ 连线太长、旁边有电机/继电器等干扰源，线上电平被拉毛刺。

解决：先确认 EA = 0; 真的在读取函数开头；把 Delay_ms(1500) 加到 2000 试试；缩短数据线、把上拉电阻从 10kΩ 换成 4.7kΩ（更强的上拉抗干扰更好）；实在不行在 DATA 与 GND 之间并一个 100pF 小电容滤毛刺。

现象：读回来的数值离谱（比如温度 232、湿度 255），但校验居然能过

原因：位序或位边界错位。DHT11 是高位先发（MSB first），如果代码里把移位和赋值的顺序写反了，一个字节的 8 位就会整个颠倒——数值看着随机，但校验和仍然是自洽的，所以校验救不了你。

解决：确认是 buf[i] <<= 1; 先执行、再 buf[i] |= 0x01;。另外检查读到 1 之后有没有等完那 70µs（if (DHT11_WaitLevel(0))），少了这一句会让每一位都错开一点点，累积到最后就是彻底错位。

现象：拔掉传感器后程序就“卡住”了，屏幕不刷新、按键没反应

原因：代码里有不带超时保护的死等循环，例如 while (DHT11_DATA == 0);。传感器不在时这根线被上拉电阻拉成高电平，这个循环永远出不来，程序就真的停在那里了。

解决：所有等待外部信号的地方都必须带超时计数——本篇的 DHT11_WaitLevel() 就是标准做法（等 200 轮，约 1ms，等不到就返回错误码）。另外顺手检查一下：超时返回的路径上有没有恢复 EA = 1，不然中断会一直关着。

还有三个容易被当成故障的正常现象
  • 小数永远是 0。DHT11 的分辨率就是 1，小数位固定为 0，不是读数失败。 要 0.1 精度请换 DHT22 / AM2302（数据格式一样，起始低电平只需 >1ms）。
  • 上电后头一两秒数值偏大或跳变。DHT11 需要约 1 秒越过上电不稳定状态， 所以本项目在进入主循环前先 Delay_ms(1000)。省掉这一步就会出现“刚上电显示很怪，过一会儿才对”。
  • 湿度读数对呼吸极其敏感，温度却很迟钝。这是物理特性： 湿度靠的是敏感元件表面的水分子吸附，响应快；而测量温度的热敏电阻有热惯性， 要等整个外壳温度平衡，所以慢是正常的。

小结与练习

这个项目看起来只是“读个传感器、显示个数”，但它把前面几课的知识全部串起来了： 延时函数（第 1 课）、中断与关中断（外部中断那一课）、 LCD 总线时序与覆盖式刷新（上一课）、以及在“多快好省”和“稳”之间做工程取舍。

把下面五句话记住，DHT11 这类单总线协议以后都不用再查手册：

  • 一根线、一个上拉电阻、谁说话谁拉低——单总线的物理层。
  • 主机拉低 ≥18ms 叫醒它，随后是 80µs 低 + 80µs 高的应答。
  • 每一位都是 50µs 低电平开头，高电平 26~28µs 是 0、70µs 是 1。
  • 40 位 = 湿度整 + 湿度小 + 温度整 + 温度小 + 校验和，校验和是前四字节之和的低 8 位。
  • 读之前关中断、读完立刻开；采样间隔 ≥1s、所有等待带超时——三条保命纪律。

还有一条最重要的工程思维方式：对时序敏感的代码， 先把“安全区间”算出来，再把采样点放在区间正中间。 40µs 这个数字不是抄来的，而是从 28µs 和 70µs 中间取的—— 这样换了晶振、改了优化等级、温度变了，你都还有余量。

动手练习
  1. 加一个最大值 / 最小值记录。 用四个变量记住开机以来的最高温、最低温、最高湿、最低湿， 显示在第二行的空余位置（或者做成按键切换显示页面）。 顺便想一想：这个记录需要掉电保存吗？如果要，你会怎么做？
  2. 把串口接进来做数据记录。 复用串口那一课的 printf 重定向， 每 2 秒往电脑发一行 T=23C H=45%， 用串口助手录一段，观察哈气前后的变化曲线。 动手前先回答一个问题：读 DHT11 时要关中断 22ms， 而 9600 波特率下一帧只要 1ms，这会不会影响接收？该怎么解决？
  3. 用量出来的数据校准延时。 把 Delay_40us() 单独放进主循环死循环调用， 用示波器（或逻辑分析仪）测它的实际宽度， 再改成 20 个、60 个 _nop_() 各测一次， 画一张“_nop_ 个数 — 实测微秒数”的对照表，写进实验报告。
  4. 算出读取一次到底要多久。 用定时器 0 在 DHT11_Read 前后各记一次时间， 把耗时显示在屏幕上（毫秒级），再和理论值（约 22~25ms）对一下。 如果实测差得比较多，说明哪个环节的时间和你以为的不一样？
接下来可以做什么
  • 加一个按键（用外部中断那一课的方法）切换显示“实时值 / 最大最小值 / 上下限”。
  • 加上限报警：湿度超过 80%RH 就点亮一个 LED 或者驱动蜂鸣器。
  • 换成 ESP32 把同样的传感器数据发到网上——本站的 ESP32 专栏里有对应的 WiFi 上传案例。
  • 回头把 实训毕设 里的案例照着自己实现一遍，你会发现模块化的代码是可以直接搬的。
