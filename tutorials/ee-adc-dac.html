数据转换：ADC 与 DAC 原理

前面十九篇，我们一直在数字世界里打转：数制、逻辑门、组合电路、时序电路、脉冲整形——信号永远是 0 和 1。这一篇要回答一个更根本的问题：真实世界根本不认识 0 和 1，那单片机凭什么能测温度、读电压、输出电压？答案就是两个器件：ADC（模数转换器）和 DAC（数模转换器）。它们是一个翻译官，一边是连续变化的物理量，一边是 0/1 组成的数字码，所有传感器和执行器都要从这道门过。这一篇讲四件事：采样定理为什么是 fs ≥ 2·f_max、混叠为什么会让 1800Hz 的信号被读成 200Hz、量化误差为什么让每一位数只值 6 dB、以及 SAR / 双积分 / 闪速 / Σ-Δ 四类 ADC 各自适合干什么。最后全部落到 STM32：采样时间怎么按源阻抗算、VREFINT 怎么反推真实的 VDDA、多通道为什么必须配 DMA，以及蓝药丸没有 DAC 时怎么用 PWM + RC 顶上去。

为什么需要它

先看你一定会遇到的一个现场。你按教程把电位器接上 STM32 的 PA0，中间抽头接引脚，两端分别接 3.3V 和 GND，程序里读一次 ADC、按 V = raw * 3.3 / 4095 换算，打印出来。把电位器拧到正中间，你期望看到 1.65V，实际打印出来可能是 1.62V；换一块板子再试，同样的位置变成 1.70V；把 USB 线换成一根更长的，读数又变了。

你去量 VDDA，发现它不是 3.300V 而是 3.117V——那 1.62V 与 1.65V 的差别根本不是「ADC 不准」，而是你把换算的基准用错了。再往深一层：你甚至会发现读数最后一位永远在跳（量化噪声），把电烙铁靠近板子跳得更厉害（噪声耦合），用一个 100kΩ 的电位器比用 10kΩ 的读数偏低（源阻抗太大、采样电容充不满）。

第二个现场更隐蔽。你要测一个从传感器出来的 1.8kHz 交流信号，单片机主循环里以 1kHz 的节奏读 ADC，把数据画成曲线——曲线是一条漂亮的、慢悠悠的 200Hz 正弦波。你以为是传感器坏了，换一个还是 200Hz；你把信号源频率调高到 2.2kHz，画出来还是 200Hz。这不是坏了，这叫混叠（aliasing），是采样这件事本身的数学性质，任何软件都补不回来。

这两个现场加起来，就是这一篇要解决的全部问题：怎么把一个连续量正确地翻译成数字（ADC），怎么把数字正确地翻译回连续量（DAC），以及这个翻译过程会引入哪些误差、哪些是原理性的、哪些是可以设计掉的。

一个反直觉的事实：数字电路内部其实也是「模拟」的

你可能觉得「0 和 1」是绝对的。但在芯片内部，所谓高电平不过是 3.3V 附近的一个电压，低电平是 0V 附近的一个电压，中间隔着一条不确定带。数字电路的全部本事，就是用正反馈和门限把连续电压「整形」回两个离散状态（这正是上一篇施密特触发器在做的事）。

所以数字世界的「干净」是有代价的：每一次整形都丢掉信息。ADC 和 DAC 之所以难做、之所以有那么多种架构，就是因为它们要在这个「丢失」发生之前，用有限个台阶尽可能忠实地记录连续量。理解这一点，你就能理解为什么「位数」「基准」「采样率」这三件事会反复出现在所有 ADC 的讨论里。

下面五条全部来自真实会踩的坑。它们的共同点是：代码看起来完全正确，用示波器量硬件也看不出问题，但你得到的数据就是错的。不懂原理，你会在这些地方花掉整周的时间。

核心概念

这一节是整篇的主干。要理解 ADC 和 DAC，你只需要抓住一件事：把连续量变成数字量，需要做两次「离散化」——先在时间轴上离散化（采样），再在幅度轴上离散化（量化）。这两步各自引入一类误差，而且性质完全不同：

  • 时间轴离散化（采样）引入的是「频率上的错认」——信号频率太高就会被伪装成低频（混叠）。这是原理性的、不可逆的错误，唯一解法是采样前先限制带宽。
  • 幅度轴离散化（量化）引入的是「幅度上的舍入」——台阶太粗就只能记个大概。这同样不可逆，但它的表现是「噪声」，可以通过位数、过采样、滤波去改善。

再加一步「物理上怎么做到」（采样保持电路），你就得到了所有 ADC 的共同骨架。剩下的 SAR、双积分、闪速、Σ-Δ 四种架构，无非是用不同的方式去实现「比较」这个动作，各有各的速度与精度取舍。

采样定理与混叠：为什么采得太慢会「认错频率」

假设你要测一个连续变化的电压 v(t)。ADC 不可能把每一瞬间的值都记下来（那是无穷多个数），它只能每隔一段时间 T_s 取一个值，这个动作叫采样，f_s = 1 / T_s 就叫采样率（单位 Sa/s，每秒采多少个点）。

于是第一个问题来了：T_s 取多大才够？如果信号变化很快而我采得很稀，两个采样点之间发生的所有事情我全都看不见——这就是采样定理要回答的问题。

采样定理（奈奎斯特-香农定理）：要无失真地恢复一个最高频率为 f_max 的信号，采样率必须满足

f_s ≥ 2 · f_max

而 f_s / 2 这个界限被称为奈奎斯特频率（折叠频率）。直观理解是这样的：

【为什么是 2 倍？】一个正弦波，一个周期内最少要采到几个点才能确定它的频率？

   采到 1 个点：只知道「有信号」，频率完全不知道
   采到 2 个点：能看出「上去了、下来了」，知道有一个周期
                （但幅度和相位还不准 —— 所以 2 倍是【理论下限】，不是工程取值）

   ────────────────────────────────────────────────────────────────
   采样点分布（•=采样点）

   每周期 1 个点：      每周期 2 个点：      每周期 4 个点：
   •         •         •       •          •   •   •   •
   看不出频率          勉强看出周期        形状基本正确
   ✗ 完全错误          △ 理论下限           ○ 工程可接受

   每周期 8 个点：      每周期 16 个点：
   • • • • • • • •     ••••••••••••••••
   形状很正确          几乎和原波形一样
   ● 工程常用           ◎ 高保真

   ────────────────────────────────────────────────────────────────
【工程上的实话】
   2 倍只是数学下限，实际至少要 5~10 倍。原因有两个：
   ① 抗混叠滤波器不是理想砖墙，过渡带里还有残余，采样率要留余量；
   ② 你不可能精确知道信号的最高频率，只能按「可能出现的最高频率」设计。
   所以学校里的实验要求「采 50Hz 工频用 1kHz 采样」，是给了 20 倍余量。

如果违反了会怎样？不会报错，会「认错频率」。这就是混叠。它的机制是：采样把频率轴「折叠」了，所有高于 f_s/2 的频率都会翻折到 0 ~ f_s/2 之间，冒充一个根本不存在的低频信号。

【题目】信号频率 f = 1800 Hz，采样率 f_s = 1000 Hz（T_s = 1ms）。
        ADC 读出来会是什么频率？

【第一步：算采样点在信号波形上的位置】
   信号周期 T = 1 / 1800 = 555.6 us
   采样周期 T_s = 1000 us
   每个采样周期，信号走了 1000 / 555.6 = 1.8 个周期

【第二步：只看「小数部分」】
   每采一个点，相位前进 1.8 个周期 = 1 个整周期 + 0.8 个周期
   整周期部分对采样结果毫无影响（正弦波是周期的），
   所以每步真正留下的只有 0.8 个周期 —— 也就是 0.2 个周期【倒退】

   倒退 0.2 周期 / 采样点  →  折算成频率：
       0.2 周期 × 1000 采样点/秒 = 200 周期/秒 = 200 Hz

【第三步：核对具体数值】v(n) = sin(2·pi·1800·n/1000)，n 是采样序号

   n       0      1       2       3       4       5       6
   ------------------------------------------------------------
   v(n)   0.00  -0.95   -0.59   +0.59   +0.95    0.00   -0.95
                   ↑                       ↑
                采样到了负峰            采样到了正峰

   把这些点连起来：0 → -0.95 → -0.59 → +0.59 → +0.95 → 0 → -0.95
   这正是【一个周期 5ms（200Hz）的正弦波】，而且是反相的！

抗混叠滤波器的设计有两个关键参数，一定要会算：

  • 通带截止频率 f_c 取你关心的最高信号频率 f_max（比如测温度这种慢变量，f_max 取 10Hz 就够了）。通带内的信号要尽量不衰减、不失真。
  • 在 f_s − f_max 处要有足够衰减（通常要求衰减到低于 1 LSB，也就是 −(6.02N + 1.76) dB）。这里有个容易搞错的地方：需要压掉的不是 f_s/2，而是 f_s − f_max——因为频率在 f_s/2 到 f_s 之间的成分会折叠到 f_max 附近，同样会污染你关心的频段。
【需求】测一个温度变送器输出的电压，关心的是 0~10Hz 的变化，
        单片机 ADC 用 1kHz 采样（f_s = 1000 Hz），12 位。

   会混叠到 0~10Hz 的频率：f_s - f_max = 990Hz 以上

一个反直觉但极重要的推论：采样率越高，抗混叠越容易

很多人以为「采样率越高越容易混叠」——正好相反。采样率越高，奈奎斯特频率越高，越不容易混叠，对抗混叠滤波器的要求也越松。真正危险的是「采样率刚好卡在信号频率的 2~3 倍」这种设计：这时混叠几乎一定会发生，而且滤波器必须在很窄的过渡带里做出很大衰减，成本和难度都陡增。

反过来，如果你故意用很低的采样率去采一个带宽很窄的信号（比如在 Σ-Δ ADC 内部，故意用远高于信号频率的采样率），那叫过采样，它不但不产生混叠，还能提高信噪比——这在后面 Σ-Δ 那一节会讲。

量化与编码：台阶有多细、误差有多大、为什么每位值 6 dB

时间轴处理完了，现在处理幅度轴。采样之后的每个值仍然是一个精确的连续电压（比如 1.23427V），要把它写进有限位宽的寄存器，必须归到最近的台阶上。这个动作叫量化。

【为什么定义为 1/2 而不是 1？】
   因为"最近的台阶"只有一个，最坏情况就是偏到两个台阶的正中间。
   如果误差能到 1 个 LSB，说明你的量化器没有取最近台阶（比如直接截断），
   那种量化的误差范围是 0 ~ -1 LSB（总是偏小），是有偏的 —— 
   真实 ADC 会通过内部加 0.5 LSB 偏置，把误差对称到 ±q/2。

q = V_FS / 2^N（单极性，0 ~ V_FS 满量程），量化误差 ≤ ±q/2

其中 N 是位数，V_FS 是满量程电压。注意一个细节：有些资料（尤其是代码里）会把换算写成 V_FS / (2^N − 1)，理由是「数字码从 0 到 2^N−1，正好是 2^N − 1 个间隔」。两个口径都有人用，对 12 位来说差别只有 0.02%，可以忽略；但你要知道自己用的是哪一个，否则在做误差预算时会和别人的数字对不上。

SNR ≈ 6.02N + 1.76 dB 是怎么来的

「位数每加 1 位，信噪比提高约 6 dB」这句话你一定听过。它其实可以从量化误差推导出来，而且推导过程只有三步。假设输入是一个占满量程的正弦波（这是测量 ADC 动态指标的标准条件）：

【第一步：算信号功率】

   满量程正弦波：峰峰值 = V_FS，幅度 A = V_FS / 2
   有效值（RMS）= A / √2 = V_FS / (2√2)
   信号功率  P_s = (V_FS/(2√2))² = V_FS² / 8

【第二步：算量化噪声功率】

   量化误差 e 在 ±q/2 之间均匀分布（三角/锯齿状），q = V_FS / 2^N
   均匀分布在 [-q/2, +q/2] 的随机量，其方差为 q²/12
        （均匀分布方差 = (b-a)²/12，代入 a=-q/2, b=+q/2）
   所以噪声功率  P_n = q² / 12 = V_FS² / (12 · 4^N)

【第三步：相除，取对数】

   SNR = 10·log10(P_s / P_n)
       = 10·log10( (V_FS²/8) / (V_FS²/(12·4^N)) )
       = 10·log10( 12·4^N / 8 )
       = 10·log10( 1.5 · 4^N )
       = 10·log10(1.5) + N · 10·log10(4)
       = 1.76 dB         + N · 6.02 dB

   ★ SNR ≈ 6.02·N + 1.76  (dB)

【再看"每加 1 位值 6 dB"的直观含义】

   位数 +1  →  台阶数 ×2  →  台阶高度 q 减半
            →  量化噪声【电压】减半
            →  量化噪声【功率】变成 1/4
            →  功率比变成 4 倍
            →  10·log10(4) = 6.02 dB

   6 dB 在电压上就是 2 倍 —— 记住这一条，所有 ADC 指标你都能口算了。
   反过来说：想多要 1 位有效精度，就得把噪声电压压到一半。

用这个公式验算上表：12 位 → 6.02×12 + 1.76 = 74.0 dB；10 位 → 61.96 dB。顺便注意那个 1.76 dB 是怎么来的：它是 10·log10(1.5)，来自「正弦波功率」与「量化噪声功率」两个系数之比。所以如果你测的不是正弦波而是别的波形（比如方波、斜坡），这个常数会变——这就是为什么数据手册测 SNR 时一定要写清测试条件。

ENOB（有效位数）：标称 12 位，实际可能只有 10 位

上面 74 dB 是「理想 12 位」的信噪比。但真实芯片里有基准噪声、时钟抖动、比较器失调、INL/DNL、采样保持非线性、电源纹波……这些都会往信号上叠加噪声，让实测 SNR 低于理论值。为了衡量「实际相当于多少位」，工程上定义了 ENOB：

ENOB = (SNR_实测 − 1.76) / 6.02（单位：位）

  • 看到末两位跳动，不要试图去修它，要做的是「把跳动变得可接受」：加软件滤波（滑动平均）、加过采样、改采样时间、改善去耦与基准。

采样保持电路（S/H）：为什么转换期间必须把电压「冻住」

现在你已经知道要做采样和量化了。但把这两件事直接连起来会有一个物理问题：一次 ADC 转换不是瞬间完成的。12 位 SAR 要比较 12 次，每次都要几百纳秒，一次完整转换要微秒量级。在这段时间里，如果输入电压还在变，那前几次比较用的是 1.230V，后几次比较用的是 1.245V——你得到的结果不属于任何一个时刻的真实值，而是一锅夹生饭。

解决办法非常朴素：在开始转换前的一瞬间，用一个开关和一个电容，把输入电压「抓住」并保持住，然后在转换期间用这个电容上的电压去比较。这就是采样保持电路（Sample and Hold，S/H，也叫跟踪保持 T/H）。

理想化地说完了，看真实电路里的三个非理想因素。它们解释了「为什么高速高精度 ADC 那么难做」：

非理想因素物理来源造成的误差怎么缓解

孔径时间与孔径抖动：为什么高速采样要拼时钟质量

这两个概念考试常考、工作里也真的会遇到，值得单独说清楚：

  • 孔径时间 t_ap：从控制信号发出「保持」命令，到开关真正断开之间的延迟。它是一个固定的延迟——固定延迟只造成「采样时刻整体后移」，通常可以忽略或校准掉。
  • 孔径抖动 t_j：t_ap 每一次都不一样的那部分（随机抖动）。它才是真正的杀手——因为它让每次采样的时刻都在晃动，而信号在动，于是采样到的电压也就跟着晃动，等效于给信号叠加了噪声。
【误差公式】采样时刻错开 Δt，电压就错 ΔV = (dV/dt) × Δt

   信号是正弦波 v(t) = A·sin(2·pi·f·t) 时，斜率最大处（过零点）：
       dV/dt|max = 2·pi·f·A

   所以最大电压误差：
       ΔV_max = 2·pi·f·A·t_j

【算一个真实的例子】
   输入：1V 幅度（2V 峰峰值）的正弦波，f = 100 kHz
   抖动：t_j = 100 ps = 1e-10 s

   dV/dt|max = 2·pi·1e5·1 = 6.283e5 V/s = 0.628 V/us
   ΔV_max    = 0.628 V/us × 1e-4 us = 62.8 uV
                                  ↑ 100ps = 0.0001us

   和 12 位 LSB（3.3V 满量程时 806uV）比：62.8uV 只有 1/13 LSB，
   → 这个抖动可以忽略

   把抖动放大到 1ns：
   ΔV_max = 0.628 V/us × 1e-3 us = 628 uV
   → 已经接近 1 个 LSB，12 位精度基本被毁掉了

【等效信噪比公式】把上面的误差当作噪声，可直接得到抖动限制的 SNR：
       SNR_jitter = -20·log10(2·pi·f·t_j)   (dB)

   t_j = 100ps, f = 100kHz :  -20log10(6.28e-4) = 64.0 dB → 约 10.3 位
   t_j = 1ns,   f = 100kHz :  -20log10(6.28e-3) = 44.0 dB → 约 7.0 位
   t_j = 100ps, f = 1MHz   :  -20log10(6.28e-3) = 44.0 dB → 约 7.0 位

   ★ 结论：抖动的影响与【信号频率】成正比。
     同一个 100ps 的时钟，采 100kHz 时相当于 10 位，
     采 1MHz 时只剩 7 位 —— 所以高速 ADC 对采样时钟的抖动
     要求极其苛刻，时钟的相噪比它的频率精度更重要。
采样时钟抖动 t_j能保证 12 位精度（74dB）的最高信号频率能保证 8 位精度（50dB）的最高信号频率
1 ns（普通 MCU 定时器触发）31.8 kHz约 795 kHz
100 ps（较好的时钟）318 kHz约 7.95 MHz
10 ps（晶振级低抖动）3.18 MHz约 79.5 MHz
1 ps（专用低抖动时钟）31.8 MHz约 795 MHz

上表按 f_max = 2^-(SNR/20) / (2π t_j) 估算，只考虑孔径抖动一项、假设输入为正弦波、忽略其他噪声源，用于看量级与趋势，不是器件选型限值。

STM32 的采样保持电路在哪？

你在 STM32 的引脚上看不到「开关 + 电容」——它被集成在芯片内部的 ADC 里。数据手册给出的是两个等效参数：采样开关的等效电阻 R_ADC（约 1kΩ 量级）和采样电容 C_ADC（约 8pF 量级）。

这一节讲的所有东西，到第 4 节会全部对上一个你可能早就见过但没在意的配置项：每个 ADC 通道的「采样时间」（Sampling Time）。它就是这里的「采样阶段」时长——STM32 允许你按通道设置 1.5 / 7.5 / 13.5 / 28.5 / 41.5 / 55.5 / 71.5 / 239.5 个 ADC 时钟周期，就是为了让你根据外部源阻抗去匹配采集时间。为什么源阻抗大就必须延长采样时间？因为要给那个 RC 充电电路留够时间常数。

逐次逼近型（SAR）：单片机里最常见的一类，讲最细

如果你只用过一种 ADC，那一定是 SAR（Successive Approximation Register，逐次逼近寄存器型）。STM32、51 扩展的 ADC0809、绝大多数「单片机内置 ADC」，全部是 SAR。它的思想只有一句话：

像用天平称东西一样，从最大的砝码开始试，能放下就留下，放不下就换小一号的。

【游戏】我心里想一个 0~4095 之间的整数，你最多猜几次能猜中？

   笨办法：从 0 开始一个一个试 → 最坏 4096 次
   聪明办法：每次猜"剩下范围的中间值"，根据"大了/小了"砍掉一半
             4096 → 2048 → 1024 → 512 → …→ 1
             最多 12 次就够了！  （2^12 = 4096）

【这个游戏就是 SAR ADC 的全部原理】

   心想 = 输入电压 Vin（连续值，0 ~ V_REF）
   猜数 = 内部 DAC 输出电压 V_DAC
   大了/小了 = 比较器的输出
   12 次猜测 = 12 位转换，12 个 ADC 时钟的比较周期

【关键在于"砍掉一半"这个动作有多快】
   ① SAR 逻辑把当前试探位置 1（比如 bit11）
   ② 内部 DAC 立刻输出这个码对应的电压 V_DAC
   ③ 比较器判断：V_DAC 比 Vin 大还是小？
      大 → 这一位清 0（"这个砝码太重了"）
      小 → 这一位保留 1（"放得下，留着"）
   ④ 换下一位，重复 ②③
   ⑤ 12 位走完，寄存器里的码就是结果

【为什么只用 1 个比较器？】
   Flash 型要用 2^N - 1 个比较器（12 位就是 4095 个！）
   SAR 用【时间】换【硬件】：只有 1 个比较器，
   但要用 12 个时钟周期去"逐个试"。
   这就是芯片里几乎所有内置 ADC 都选 SAR 的原因：
   面积小、功耗低、成本低，速度也够用。

等一下：为什么表里得到 2978，而我算的「理想码值」是 2978.9？

你如果自己动手算一遍，一定会发现这个别扭的地方。原因在于这张表用的是教科书模型：判决规则是「V_DAC > Vin 就把这一位清 0」，等价于保留 DAC 电压不超过 Vin 的那个最大码——它得到的是向下取整的结果，误差范围是 0 ~ −1 LSB（永远偏小），而不是课本上那个漂亮的 ±1/2 LSB。

真实 ADC 是怎么做到 ±1/2 LSB 的？它在比较门限上加了一个半个 LSB 的偏移，也就是把判决门限从「码值 × LSB」下移到「(码值 − 0.5) × LSB」，于是判决变成了四舍五入。在你刚刚看的这张表里，这个偏移只影响最后一次比较：门限从 2.4001V 变成 (2979 − 0.5) × 0.805664mV = 2.3997V，而 Vin = 2.4000V > 2.3997V，于是 bit0 翻转为 1，最终结果变成 2979 = 0xBA3，对应 2.40007V，误差只有 +0.07mV —— 这才落在 ±1/2 LSB 之内。

两种口径最多差 1 个码，对工程结论毫无影响；但你要记住这个对应关系：「±1/2 LSB 量化误差」是实现了半 LSB 门限偏移的器件的说法，而纯二分搜索本身是「0 ~ −1 LSB」。数据手册里给的失调误差指标，很多时候就是把这点偏移折算进去之后的残差。

三个值得注意的细节

① 结果全靠比较器的「是/否」，所以 SAR 的精度完全取决于内部 DAC 和基准。比较器只需要判断大小，不需要判断「差多少」——这让电路可以做得很简单、很快。但反过来说，内部 DAC 的电阻（或电容）匹配误差会直接变成 INL/DNL，基准的漂移会直接变成增益误差。

② 转换时间与位数成正比。12 位要 12 个比较周期，16 位就要 16 个。所以同为 SAR，16 位通常比 12 位慢。STM32 的 ADC 转换时间 = 采样时间 + 12.5 个 ADC 周期（12 次比较 + 一点固定开销），那个 12.5 就是这么来的。

③ 表里最后两步的差别只有 0.7mV，这就是 12 位的分辨率极限。如果此时板子上的噪声有 1mV，那么 bit0 和 bit1 的判决就会随机翻转——这正是「读数永远在最后两位跳」的根本原因，也是 ENOB 低于标称位数的物理来源。

SAR 的速度与精度权衡

方面SAR 的表现为什么
速度中等到快：几十 kSa/s ~ 几 MSa/s每次比较需要「DAC 建立 + 比较器判决」，位数越多越慢
分辨率8 ~ 18 位最常见再往上，内部 DAC 的匹配精度和噪声就撑不住了
功耗低（只在转换时耗电）没有静态偏置电流，适合低功耗场合
成本 / 面积最低（只有 1 个比较器 + 1 个 DAC）这就是它统治「单片机内置 ADC」的原因
抗干扰一般转换期间直接对输入采样，输入上的噪声会直接影响判决
必须做的配套采样保持 + 抗混叠滤波 + 稳定基准转换期间输入不能变，且比较的"尺子"必须是 V_REF

最后强调一句：STM32 里的 ADC 就是 SAR。所以你之前配置的那些东西——采样时间、校准、外部触发——全都是为 SAR 服务的：采样时间对应 S/H 的采集阶段，校准对应内部 DAC 与比较器的失调修正，外部触发是为了让采样时刻精确可控（减少孔径抖动的影响）。第 4 节会把这些一一对上。

双积分型：精度最高、抗工频最强、但慢得有理

SAR 是「用二分法猜」。双积分型（dual-slope）走的是完全不同的路子：它先让输入电压给一个电容充电一段固定时间，再用基准电压把这个电荷「放掉」，然后数放电用了多少个时钟周期。听起来绕，但它的精度来源非常漂亮。

【结构】

                    ┌───────────┐
   Vin ──►[ 开关1 ]──┤           │
                    │  积分器    │──►┌──────────┐    ┌────────────┐
  -V_REF ►[ 开关2 ]──┤  R + C    │   │  比较器   │───►│ 计数器/控制 │
                    │           │   │ (过零检测)│    │  逻辑       │
                    └───────────┘   └──────────┘    └─────┬──────┘
                                                          │ 数字结果
   两个开关轮流接通：第一阶段接 Vin，第二阶段接 -V_REF

【积分器输出波形 —— 这就是"双积分"名字的由来】

        │        ╱╲                      ← 第二阶段：斜率固定（由 V_REF 决定）

【看斜率】
   第一阶段斜率 ∝ Vin   （输入电压越大，充得越高，爬得越陡）
   第二阶段斜率 ∝ -V_REF（固定不变，由基准决定）

   → Vin 越大，T1 结束时充得越高，T2 就越长
   → T2 的长短，就是 Vin 的"度量"

【数学关系（记这一个式子就够了）】

   第一阶段：V_o(T1) = -(Vin / (R·C)) · T1
   第二阶段：从 V_o(T1) 出发，用 +V_REF/(R·C) 的斜率爬回 0
            需要的时长  T2 = (Vin / V_REF) · T1

   用同一个时钟去数 T1 和 T2：
       T1 = 2^N · T_clk       （固定，让计数器走满 2^N 个周期）
       T2 = N2 · T_clk        （可变，N2 就是计数器的读数）

   代入：N2 · T_clk = (Vin/V_REF) · 2^N · T_clk
   ────────────────────────────────────────────────
        ★  N2 = (Vin / V_REF) · 2^N

【这个式子里没有 R，没有 C，没有时钟频率】
   它们全被约掉了！这就是双积分型精度高的全部秘密：
   积分电阻、积分电容的绝对值、时钟频率的绝对值都不影响结果，
   唯一重要的是【基准电压】和【计数的准确性】。

从这个式子能直接看出双积分型的两个特点，而且是一体两面的：

  • 精度高、温漂小。RC 的温漂、时钟频率的温漂（只要在一次转换的几十毫秒内足够稳定）都不会进入结果。所以 3½ 位、4½ 位数字万用表几十年来一直用它——一颗 ICL7106 就能做到 0.05% 的基本精度，而且不需要精密电阻和精密电容。
  • 抗工频干扰最强。第一阶段积分时间是固定的 T1。如果 T1 正好取工频周期的整数倍（50Hz 时取 20ms、40ms、100ms），那么加在输入上的工频干扰在积分区间内正负相消，积分结果恰好为 0——50Hz 及其整数次谐波（100Hz、150Hz…）被彻底抹掉。从频域看，固定时长积分本身就是一个梳状滤波器，在 1/T1 的整数倍处有无穷深的零点。
  • 速度慢，而且慢得有理由。一次转换至少要 T1 + T2_max = 2 · T1。取 T1 = 20ms（为了抗工频），最坏情况一次转换要 40ms，也就是每秒最多 25 次。想快就得缩短 T1，但一缩短就失去抗工频能力——这就是它只能做「慢速高精度」的原因。
特性原因
分辨率可以做到很高（4½ 位、5½ 位）分辨率只取决于计数器的位数和 T1 的长度，与模拟电路的匹配精度无关
不需要精密电阻电容R、C 在公式里被约掉。只要在 40ms 内稳定即可
抗 50Hz 工频干扰极强T1 取工频整周期，干扰在积分中相消

闪速型（Flash）：最快、最贵、最耗电

如果完全不考虑成本，只追求「一次出结果」，那就是 Flash 型：用 2N − 1 个比较器并行工作，每个比较器的门限比下一个高 1 个 LSB。一个时钟周期之内，所有比较器同时给出「高于/低于」的结果，再送进优先编码器变成二进制码。它不需要逐次逼近，所以又叫并行比较型。

Σ-Δ 型：为什么能做到 24 位却只能做低速

Σ-Δ（Sigma-Delta，也写作 Delta-Sigma）是四种里最"反直觉"的一种：它的核心比较器只有 1 位——也就是它每次只判断「比刚才高还是低」，本质上是个 1 位 ADC。一个 1 位 ADC 怎么可能得到 24 位的结果？靠三个招式：过采样、噪声整形、数字滤波。

【结构：一个带反馈的积分器环路】

   Vin ──►┌───────┐    ┌────────────┐        ┌──────────────┐
          │ 差分  │───►│  积分器     │───────►│ 1 位比较器    │──► 1 位码流
       ┌─►│ 求和  │    │ (累加误差)  │        │（只看正负）    │    (1/0 序列)
       │  └───────┘    └────────────┘        └──────┬───────┘
       │                                            │
       │        ┌──────────────┐                    │
       └────────┤  1 位 DAC     │◄───────────────────┘
                │ (反馈 +V_REF  │
                │  或 -V_REF)   │
                └──────────────┘

【第一招：过采样】
   采样率远高于奈奎斯特频率（比如音频用 3MHz 采 20kHz 的信号）
   → 量化噪声被摊到很宽的频带上，落在我们关心频带内的噪声变少
   → 每把采样率提高 4 倍，带内噪声减半（+6dB，等于多 1 位）

【第二招：噪声整形（noise shaping）—— 这才是 Σ-Δ 的精髓】
   环路里的积分器对信号是"直通"的，但对量化噪声是"高通"的：
       · 输入信号 Vin  →  输出原样通过（低通特性，不衰减）
       · 量化噪声       →  被积分器"推开"，赶到高频去

   噪声功率
      ▲
      │                    ╱  ← 整形后的量化噪声（高频堆积）
      │                  ╱
      │                ╱
      │──────────────╱─────────────────────
      │▓▓▓▓▓▓▓▓▓▓▓▓▓   ← 我们关心的信号频带（0 ~ f_max）
      │▓ 信号 ▓         带内的噪声被压得很低
      └──────────────────────────────────► 频率
      0      f_max         f_s/2        f_s

【第三招：数字滤波 + 抽取（decimation）】
   用数字低通滤波器把高频的整形噪声全部滤掉，
   再把采样率降下来（抽取），输出一个"低速、多位"的结果。

   1 位码流（3MHz）  ──►┌──────────────┐──► 24 位数据（几十 Hz ~ 几十 kHz）
                        │ 数字低通+抽取  │
                        └──────────────┘
   整个过程：高速低精度  →  低速高精度

【一句话记住 Σ-Δ】
   它把"精度"这件事从【模拟电路的匹配】搬到了【数字滤波的计算】上。
   模拟部分只需要一个积分器和一个 1 位比较器（好做、好匹配），
   剩下的精度靠过采样比和数字滤波器（几乎免费、不会漂）去换。
   代价就是：必须"多采很多次"，所以速度上不去。
【典型近似公式】（OSR = 过采样比 = f_s / (2·f_max)）

   一阶 Σ-Δ：SNR = 6.02N + 1.76 - 5.17 + 30·log10(OSR)
              → 过采样比每翻一倍，SNR 提高 9 dB，约合 1.5 位
   二阶 Σ-Δ：SNR = 6.02N + 1.76 - 12.9 + 50·log10(OSR)
              → 过采样比每翻一倍，SNR 提高 15 dB，约合 2.5 位

   ★ 阶数越高，噪声整形越狠（截止更陡），但环路稳定性越难保证。

【算一个例子：一阶、N=1（1 位比较器）、OSR = 256】

   SNR = 6.02×1 + 1.76 - 5.17 + 30·log10(256)
       = 6.02 + 1.76 - 5.17 + 30×2.408
       = 6.02 + 1.76 - 5.17 + 72.2
       = 74.8 dB
   ENOB = (74.8 - 1.76) / 6.02 = 12.1 位

   → 一个 1 位比较器 + 256 倍过采样 = 12 位有效精度！

【换成二阶、OSR = 256】
   SNR = 6.02 + 1.76 - 12.9 + 50×2.408 = 115.3 dB
   ENOB = (115.3 - 1.76)/6.02 = 18.9 位

   → 这就是为什么工业称重、温度采集芯片能标 24 位输出：
     实际 ENOB 通常在 19~22 位之间，而"24 位"是输出字长。

【为什么它一定慢？】
   输出速率 = f_s / OSR。想要 19 位有效，就得 OSR = 256 以上；
   而环路的采样率 f_s 又受模拟电路（积分器建立、比较器速度）限制，
   通常几百 kHz 到几 MHz。
       3 MHz / 256 = 11.7 kHz  ← 这就是输出速率的上限
   想要更高的输出速率，只能降 OSR，也就降精度。
   这就是"24 位只能做低速"的定量原因。

Σ-Δ 的两个「坑」：多路复用与群延迟

① 不适合快速切换通道。Σ-Δ 的精度来自「很长时间的过采样累加」。你用多路开关轮流切换 8 个通道，每次切换后数字滤波器都要重新收敛——需要丢掉切换后的若干个（甚至几十个）输出才能用。这就是为什么「8 通道 24 位采集卡」的实际每通道速率往往只有标称值的几分之一。

② 有可观的群延迟。数字低通滤波器会引入延迟，OSR 越大、阶数越高、输出速率越低，延迟越长。做闭环控制时这个延迟会吃掉相位裕度。如果你要「采集 → 立刻反应」，SAR 更合适；如果你要「慢慢测准」，Σ-Δ 更合适。

③ 注意别和「混叠」搞混。过采样不但不产生混叠，反而是抗混叠的利器：因为 f_s 远高于信号带宽，奈奎斯特频率很高，外部的抗混叠滤波器只需要简单的 RC 就够了。所以 Σ-Δ 芯片常常只需要在输入端加一个 RC（甚至靠内部数字滤波器 + 简单 RC 就够）。

ADC 的关键指标：分辨率不等于精度

这是整个 ADC 话题里最容易搞混、也最容易被商家利用的一点。分辨率说的是「尺子上有多少刻度」，精度说的是「这把尺子准不准」——两者完全独立。一把刻度细到 0.1mm 的尺子，如果它的零点做歪了 5mm，那它依然是「0.1mm 分辨率、5mm 误差」。

【一个 12 位 ADC 的两种"病"】

INL 与 DNL：那个会「丢码」的指标

这两个指标只差一个字，含义完全不同，一定要分清：

  • INL（积分非线性，单位 LSB）：实际转换曲线与理想直线之间的最大偏差。它描述的是「曲线弯了多少」。INL 决定绝对精度——INL = ±2 LSB 就意味着你的读数可能有 2 个码的系统性偏差，光靠校准消不掉。
  • DNL（微分非线性，单位 LSB）：每个实际台阶的宽度与理想 1 LSB 之差的最大值。它描述的是「台阶宽窄是否均匀」。DNL 决定会不会丢码、会不会不单调。
【先把"宽度守恒"这件事想清楚】

   输入电压从 0 一路扫到 V_FS，整个输入范围是一个固定的长度：
        总长 = 2^N 个【理想 LSB】

   而 ADC 的输出只有 2^N 个码，它们要【瓜分】这 2^N 个 LSB 的总长度：

   ┌────┬────┬────┬────┬────┬────┬────┬────┐   ← 理想：8 个码，每个宽 1 LSB
   │ 0  │ 1  │ 2  │ 3  │ 4  │ 5  │ 6  │ 7  │      总长 = 8 LSB
   └────┴────┴────┴────┴────┴────┴────┴────┘

   现在 DNL 让某个台阶变宽了（比如码 3 的宽度变成 3 LSB，DNL = +2 LSB）：

   ┌────┬────┬────┬──────────────┬────┬────┐        ✗ 出问题了
   │ 0  │ 1  │ 2  │      3       │ 5  │ 6  │
   └────┴────┴────┴──────────────┴────┴────┘
                                  ↑
                     码 4 不见了！码 7 也被挤出了范围
                     （总长只有 8 LSB，码 3 一个人吃掉了 3 个）

   ★ 这就是"宽度守恒"给出的结论：
     总长度是固定的 2^N 个 LSB，谁多占了，
     就必须有别的码被挤成零宽度 —— 被挤成零的那个码，就是【丢码】。

【严格一点的表述（工程上的判据）】

   · DNL = -1 LSB  → 该码的宽度正好被压成 0 → 【这个码必然丢失】
   · DNL > +1 LSB  → 该台阶特别宽，一定会把相邻码挤窄
                      → 【允许/容易出现丢码与非单调】
   · 手册上写 "DNL < ±1 LSB，保证无丢码（no missing code）"
     反过来说就是：只要 |DNL| 超过了 1 LSB，
     就【不能再保证】每个码都出现、也不能保证输出单调。

【丢码会带来什么实际危害？】

   ① 闭环控制里：输出码跳过某个值 → 那一段的"等效增益"突然变大
      → 控制环在这一小段上增益突变 → 抖动、甚至极限环振荡
   ② 爬坡/寻优算法里：非单调意味着"往上走反而变小"
      → 算法会找错方向，收敛变慢或卡住
   ③ 数据采集里：某个电压区间永远采不到那个码
      → 做直方图统计时出现"空洞"，看起来像传感器坏了

   所以：做闭环控制、做精密测量时，一定要看手册的 DNL 指标，
   宁可多花几块钱买 DNL 保证 < 1 LSB 的器件。

接下来三个指标是「接线和外围电路」层面的坑，很多人的 ADC 读不准就是因为踩了它们：

【一个反直觉的事实】
   很多人以为 ADC 输入是"高阻"，接什么都不会影响信号。
   但 SAR 的输入其实是【开关电容】——它每个采样周期都要
   从信号源"偷"一点电荷去给内部采样电容充电。

   Vin ──[R_src]──┬──[ 开关 ]──┬──── 内部 C_ADC（约 8pF）
                  │            │
                  │            └──── 每次采样都要充一次电
               外部信号源

   等效的平均输入电流：
        I_in ≈ C_ADC × Vin × f_s

   算一下（C_ADC = 8pF、Vin = 3.3V、f_s = 1MHz）：
        I_in ≈ 8e-12 × 3.3 × 1e6 = 26.4 uA

   看起来很小，但它必须由信号源提供。如果 R_src 很大：
        R_src = 100kΩ  →  压降 = 26.4uA × 100kΩ = 2.64V  ！！
   → 读数会低得离谱

【所以"输入阻抗高"这句话要打个问号】
   · 直流看：确实是高阻（漏电只有 nA 级）
   · 交流/动态看：每个采样周期抽一次电荷，等效于一个电阻
          R_in ≈ 1 / (C_ADC × f_s)
          1 / (8e-12 × 1e6) = 125 kΩ  ← 并不是无穷大！

   采样率越高、采样电容越大，等效输入阻抗越低。
   （这也解释了为什么高速 ADC 一定需要前级驱动运放。）

【还有一个更隐蔽的危害：通道间串扰】
   多通道扫描时，如果源阻抗太高，采样电容"没放干净"：
       通道 1（3.3V）→ 采样 → 残留一部分电荷
       → 切到通道 2（0V）→ 残留电荷污染通道 2 的读数
   表现：给通道 2 加 0V，却读到几十 mV；
        而且这个"鬼影"会随通道 1 的电压变化而变化。

【共模输入范围】
   对差分输入的 ADC，两个输入端的"公共部分"（共模电压）
   必须落在手册规定的范围内（常见是 V_REF/2 ± 0.1V 之类）。
   超出后内部采样开关会工作异常，读数会突然变得莫名其妙。
   单端输入时，这个约束体现在"输入电压必须落在 0 ~ V_REF 之间"
   —— 负电压或超过 V_REF 的电压会通过内部保护二极管灌电流，
      轻则读数全错，重则烧引脚。

基准电压 V_REF：决定「绝对精度」的那把尺子

所有 ADC 的输出码，本质上都是一个比值：

码值 = round( Vin / V_REF × 2^N ) ⟺ Vin = 码值 × V_REF / 2^N

看第二个式子就明白了：V_REF 飘多少，你算出来的电压就飘多少。因为它是整个换算里的唯一「标尺」。这跟分辨率、ENOB 都没关系——尺子本身的长度错了，刻度再细也没用。

【算一下】12 位、标称 V_REF = 3.3V

   V_REF 飘 1%          → 3.3V × 1% = 33 mV
   折算成 12 位的码数    → 33mV / 0.805664mV = 40.96 ≈ 41 LSB

   ★ 也就是说：你辛辛苦苦用 12 位 ADC 去分辨 0.8mV，
     结果基准一飘，读数就整体偏了 41 个码（33mV）。
     分辨率白给了 —— 这就是"分辨率不等于精度"的最直观例子。

【更真实的例子：温漂】
   常见 MCU 的 VDDA 兼作基准，总误差 2%~5%
   普通 LDO 供电：1%~2%
   专用基准（如 REF3033）：初始 0.05%，温漂 20~75 ppm/°C

   按 50 ppm/°C 算，温度变化 40°C：
       50e-6 × 40 = 2000 ppm = 0.2%
       → 3.3V × 0.2% = 6.6mV = 8.2 个 LSB（12 位）
   → 一个冬夏温差，读数就系统性漂了 8 个码。这就是为什么
     "高精度测量"和"便宜的基准"是不能共存的。

【为什么"用 VDDA 当基准"是零成本方案里最差的一种】
   VDDA 既要给整个 MCU 供电（数字开关噪声全在上面），
   又要当 ADC 的标尺。数字部分的电流突变会让 VDDA 抖动，
   于是"被测信号"和"标尺"一起抖，读数就跟着跳。
   低成本改善：VDDA 加 π 型 RC 去耦 + 独立的 LDO + 大电容。
   更彻底：换成外部基准（STM32 有 VREF+ 引脚的型号可直接接）。

DAC 的主要类型：从权电阻到 R-2R 梯形网络

DAC 要做的事情和 ADC 正好相反：给一个数字码，输出一个正比于它的电压或电流。核心难点只有一个：怎么让每一位的「权重」正好是 2 的幂次。三种主流结构就是三种不同的答案。

① 权电阻网络：最直观，但做不高位

【思路】每一位配一个电阻，阻值按 2 的幂次递减，电流就按 2 的幂次递增

        b3(MSB)                b0(LSB)
          │                      │
        ┌─┴─┐  R               ┌─┴─┐  8R
   V_REF┤开关├──[ R ]──┐        │开关├──[ 8R ]──┐
        └─┬─┘          │        └─┬─┘           │
          │            │          │             │
         GND          ├──────────┼─────────────┤
                      │          │             │
                              ┌───┴───┐         │
                              │  -    │◄────────┘
                              │  运放  │     所有电阻都接到【虚地】
                          ┌───┤  +    │     所以每路电流 = V_REF / 该路电阻
                          │   └───┬───┘
                         GND      │
                                  ├──── V_out = -I_total × R_f
                                  │
                               [ R_f ]

【电流分配】
   b3 支路：I3 = V_REF / R      （权重 8）
   b2 支路：I2 = V_REF / 2R     （权重 4）
   b1 支路：I1 = V_REF / 4R     （权重 2）
   b0 支路：I0 = V_REF / 8R     （权重 1）

   总电流 I = I3·b3 + I2·b2 + I1·b1 + I0·b0
           = (V_REF/R) · (8b3 + 4b2 + 2b1 + b0)/8
           = (V_REF/R) · D/8

【致命缺点：阻值跨度太大】
   N 位需要 N 种阻值，最大 : 最小 = 2^(N-1) : 1

       8 位 ：  1 : 128
      10 位 ：  1 : 512
      12 位 ：  1 : 2048
      16 位 ：  1 : 32768   ← 已经在集成电路里做不出来了

   为什么做不出来？
   ① 面积：8R 的电阻要占 8 倍面积，16 位时最大电阻要占 32768 倍
   ② 匹配：同一芯片上 1kΩ 和 32MΩ 的电阻，工艺偏差、温度系数、
           电压系数完全不一样，无法保证"正好 2 倍"的关系
   ③ 寄生电容：大电阻必然伴随大寄生电容，速度上不去

   → 所以权电阻网络只适合 4~6 位的低成本场合（比如某些老式
     音量控制、低成本可编程电源），或者作为教学例子。

② R-2R 梯形网络：只用两种阻值实现二进制加权

这是工业 DAC 里最经典的结构，也是考试的重点。它只用 R 和 2R 两种阻值，就能让每高一位的电流正好是下一位的 2 倍。为什么能做到？靠的是一个非常漂亮的「等效电阻递归」性质。

【结构】水平方向一串 R 电阻，每个节点往下挂一个 2R 到开关，
       最右端还要一只 2R 接到地 —— 这只叫「终端电阻」，少不得！

                  I_total（流入运放虚地）
                     │
                     ▼
    V_REF/0 ──2R──┐   R      R      R          ┌── 2R ── GND
   (b3, MSB)      ├──┤├──┬──┤├──┬──┤├──┬───────┤   ← 终端电阻
                  │     │      │      │        │
              ┌───┴──┐  │  ┌───┴─┐    │   ┌────┴───┐
              │ 开关  │  R  │开关 │    R   │  开关   │
              └───┬──┘  │  └──┬──┘    │   └────┬───┘
                  │     │     │       │        │
        V_REF 或 GND     ▼  V_REF/GND  ▼    V_REF/GND
                        b2          b1        b0(LSB)
                    ┌────┴────┐
       b3 节点 ─────►│ 运放 -   │
                    │         │──► V_out = -I_total × R_f
                    │  运放 +  │
                    └────┬────┘
                        GND
   ★ b3 所在的节点直接接到运放的虚地端（0V）
     所以每个 2R 支路的开关一端是 V_REF 或 GND，另一端是某个节点电压

【核心性质：从任何一个节点往右看，等效电阻都是 2R】
   证明用【归纳法】，从最右端往左推：

   ① 最右端（b0 节点）往右看：只有那只终端电阻 2R
        → 等效电阻 = 2R                              ✓

   ② 往左退一格（b1 节点）往右看：
        先是水平电阻 R，然后遇到 b0 节点。
        在 b0 节点处，往上挂的 2R（b0 的开关支路）和往右看的 2R
        是【并联】的：  2R ∥ 2R = R
        所以从 b1 往右看 = R + R = 2R                 ✓

   ③ 再往左退一格（b2 节点）：同理
        R + (2R ∥ 2R) = R + R = 2R                    ✓

   ④ 一路推到 b3：往右看也是 2R                      ✓

   ★ 结论：每个节点往右看都是 2R。而运放的虚地端是 0V，
     所以每个节点往左看也是 2R（左边最终都通到 0V）。
     于是每个节点是"三个 2R 交汇"的对称结构。

【为什么电流会逐位减半？】
   在任意一个节点上，本位的 2R 支路注入的电流，
   会被"往左"和"往右"两条各 2R 的路径【平分】：
        往左 = 往右 = 注入电流的一半

   而"往右"的那一半，到了下一个节点又会被再平分一次……

        b3 注入 I3 ──► 一半直接进运放（这就是 b3 的贡献）
        b2 注入 I2 ──► 一半往左进运放，恰好是 I2 / 2
        b1 注入 I1 ──► 经过两次平分，进运放的是 I1 / 4
        b0 注入 I0 ──► 三次平分，进运放的是 I0 / 8

   ★ 每往低位走一级，贡献就减半 —— 这正是二进制加权！

【每路电流的大小】
   因为节点电压在"虚地 + 对称分压"下最终等效为 0V，
   每个 2R 支路的电流就是：
        I = V_REF / (2R)      （本位为 1 时）
        I = 0                 （本位为 0 时，开关接地）

   第 k 位的电流贡献（k = N-1 是 MSB，k = 0 是 LSB）：
        I_k = (V_REF / 2R) / 2^(N-1-k)

   总电流：
        I = Σ I_k · b_k = (V_REF / (2R · 2^(N-1))) · Σ b_k · 2^k
          = (V_REF / (2R · 2^(N-1))) · D
      其中 D = 各位码值组成的整数（0 ~ 2^N - 1）

   输出电压（R_f = R 时）：
        V_out = -I · R_f = -V_REF · D / (2 · 2^(N-1)) = -V_REF · D / 2^N

   ★★ 这就是 R-2R 的最终结论：
        V_out = -V_REF × D / 2^N
      满量程（D = 2^N - 1）时 V_out ≈ -V_REF。
      只有两种阻值，却实现了完美的二进制加权。
R-2R 的三个记忆要点

① 终端电阻不能省。最右端那只 2R 接地是归纳法的起点。少了它，最右端的等效电阻就不是 2R，整个二进制关系全部崩掉，输出会完全非线性。这是 R-2R 电路最常见的接线错误。

② 两种阻值的匹配是精度的关键。芯片上做 R 和 2R 很容易保证「2 倍关系」（用两个 R 串起来当一个 2R，或者用同样宽度的电阻条按长度比），这是 R-2R 能在集成电路里实现、而权电阻网络不能的根本原因。

③ 运放的虚地和 R_f 决定输出形式。如果 R_f = R，满量程输出约等于 −V_REF；想要正电压输出，就在后面再加一级反相器，或者用双极性接法（把 V_REF 换成 ±V_REF）。

③ 电流舵型（current steering）：高速 DAC 的主力

R-2R 靠电阻网络的分压/分流来决定权重，电流舵型则换了个思路：每一位直接配一个恒流源，用一对差分开关把电流「导向」输出端或者地。输出就是把被导出的电流直接相加（通常是差分电流输出），所以不需要电阻网络。

  • 为什么快：电流开关只在两个电流路径之间切换，节点电压摆幅很小（避免了三极管进入饱和区），所以开关速度极快，建立时间可以做到纳秒级。高速 DAC（视频、通信、DDS 波形合成）几乎都是电流舵型。
  • 精度的关键：不是电阻匹配，而是电流源的匹配。恒流源用同尺寸的 MOS 管加同样的偏置就能做得比较准；位数更高时，往往把「二进制权重」改成温度计码（thermometer code）——也就是用 2N−1 个等权重的电流源，靠「开几个」来表示码值。等权重让匹配误差只影响 INL 而不影响单调性，也大幅减小毛刺。
  • 代价：2N−1 个电流源需要复杂的译码逻辑，面积和功耗都上去了。所以实际器件常常是「高 6 位温度计码 + 低几位二进制」的混合分段结构（segmented DAC），在面积、精度、毛刺之间折中。

DAC 的关键指标与输出方式

指标含义为什么关心它
分辨率 位数 N；1 LSB = V_FS / 2N 决定"最小能调多少"。12 位 3.3V 时 1 LSB = 0.806mV；控制 0~10V 输出时 1 LSB = 2.44mV
建立时间
(settling time)		 从输入码跳变，到输出稳定在 ±1/2 LSB 以内所需的时间 决定最大更新率。1µs 建立 → 最快约 1MSa/s；10µs → 100kSa/s。波形合成时它直接决定你能输出多高的频率
单调性
(monotonicity)		 码值增加时，输出一定增加（至少不减小），绝不回头 对闭环控制至关重要（下面单独讲）
毛刺
(glitch)		 码变化瞬间出现的短暂错误跳变，用"毛刺能量 (nV·s)"衡量 给执行器带来尖峰、给音频带来"咔哒"声、给波形合成带来杂散
失调与增益误差 同 ADC：整条曲线平移 / 斜率不对 可两点校准掉；闭环控制里失调会变成"稳态误差"
INL / DNL 同 ADC：曲线弯曲 / 台阶宽度不均 做精密波形输出、做精密电压源时必须看

为什么「单调性」对闭环控制特别重要

【正常（单调）的 DAC】
   控制环：误差 e = 目标 - 实测，DAC 输出 = 上次数值 + Kp·e
   目标是让电机转到 1000 转，现在 900 转 → e = +100
   → DAC 输出增加 → 电机加速 → 误差减小 → 收敛 ✓

   输出
     ▲                    ╱
     │                 ╱
     │              ╱
     │           ╱          ← 码值增加，输出一定增加
     │        ╱
     └──────────────────────► 码值
     0                   4095

【非单调的 DAC】（某个码处输出反而变小了）
   输出
     ▲                    ╱
     │                 ╱
     │              ╱
     │           ╱
     │        ╱
     │───┐ ╱     ← 码值从 2047 加到 2048，输出反而【掉了 3mV】
     │   └╱
     └──────────────────────► 码值
     0                   4095

【会发生什么？】
   ① 积分型控制（PI、PID 的 I 项、或者"累加式"逼近）走到这个码附近：
      输出越小 → 误差越大 → 继续加码 → 输出又变小 → 误差更大 …
      → 正反馈！数值会一路加到撞上量程上限，然后卡在那里
      → 表现：系统"跑飞"、输出饱和、电机突然冲到最大速度

   ② 爬山法 / 最速下降法之类的寻优算法：
      算法假设"输出增加 = 误差减小"，非单调处判断全部反了
      → 收敛变慢，或者永远在某个区间里来回振荡（极限环）

   ③ 增量式伺服（比如步进细分、压电微位移）：
      你可能用 DAC 输出做到 1µm 级的定位，
      非单调会造成"差一步回不去"的定位误差。

【所以：做闭环控制，DAC 的单调性必须是【保证】的，
   而不是"典型值是这样"。查手册时要找
   "guaranteed monotonic over temperature" 这句话。
   一般 12 位以内的 DAC 芯片都能保证单调，
   位数越高越难（因为权重匹配更难）。】

毛刺（glitch）：最坏情况是「所有位一起翻转」

【成因】DAC 不是一个"整体"，而是 N 个开关。
        各个开关的延迟不同、各路寄生电容不同，
        → 在码变化的瞬间，会短暂地出现一个"中间码状态"。

【最坏情况：主进位（major carry）0111...1111 → 1000...0000】

   12 位从 2047 变到 2048：
       0111 1111 1111  (2047)
    →  1000 0000 0000  (2048)

   理想情况下只应该变化 1 个 LSB（0.8mV）。
   但 12 个开关【全都要翻转】！如果 MSB 先动、低 11 位后动：

   ① MSB 先变成 1，低位还没清 0：
        1111 1111 1111  (4095)  ← 满量程！！
   ② 低位随后清 0：
        1000 0000 0000  (2048)

   输出波形：
     V_out
       ▲
   V_FS┤      ╱▔▔▔╲          ← 一个冲到满量程的尖峰（毛刺）
       │     ╱     ╲
       │    ╱       ╲
       │   ╱         ╲
       │  ╱           ╲
   1LSB┤ ╱             ╲─────  ← 稳定在 2048 对应的电平
       │╱
       └─────────────────────► 时间
        ↑ 码变化瞬间

   ★ 一个只应该动 0.8mV 的变化，却瞬态冲到了满量程（3.3V）。
     这就是 DAC 毛刺的典型量级 —— 比信号本身大 3 个数量级。

【毛刺的危害】
   ① 控制执行器：给电机/电磁阀/压电陶瓷一个尖峰电压
      → 电机"咔"一声、电磁阀误动作、压电陶瓷承受应力冲击
   ② 音频：每次大码变化都"咔哒"一下，听感很差
   ③ 波形合成（DDS）：毛刺是周期性的 → 在频谱上形成杂散
      → 输出的正弦波不够"干净"，做信号源不合格
   ④ 精密电压源：如果后面接了采样保持或ADC去读，
      可能正好在毛刺期间采样 → 读到完全错误的电压

【怎么缓解】
   · 选带"去毛刺（deglitch）"的 DAC，或选用温度计码译码的器件
     （温度计码下相邻码只翻转 1 个开关，毛刺极小）
   · 输出端加低通滤波（RC 或运放有源滤波），把窄尖峰滤掉
   · 软件上"先降后升"：需要大跳变时，中间先经过一个安全值
   · 在毛刺期间禁止下游采样（用同一个定时器协调）
   · 更快的建立时间 → 毛刺持续时间短，能量小

输出方式：电压输出 vs 电流输出

对比电压输出型电流输出型
芯片内部已集成输出运放，直接给出电压只给电流（常见 0~20mA 或差分电流）
外围电路几乎不用（可能要加一级缓冲）需要外部运放做 I-V 转换（或直接驱动电流环）
速度受运放压摆率限制，一般较慢快（电流开关建立快）
抗干扰 / 传输距离差（电压在长线上易受干扰与压降）好（电流环 4~20mA 可传几百米，工业标准）
典型应用板内基准、可控电压源、PWM 替代、音频工业变送器、长线传输、高速波形输出

顺便说一个工业上的经典设计：4~20mA 电流环为什么用 4mA 而不是 0mA 作零点？因为 0mA 也意味着「导线断了」。用 4mA 表示量程下限，那么「电流小于 3.6mA」就明确表示故障——零点偏置换来了一条断线检测能力。这是传感器与 DAC 领域非常典型的一种工程智慧：牺牲一点量程，换一个能自诊断的系统。

三种「用单片机做 DAC」的方案

方案分辨率速度成本 / 外围适合什么主要缺点
① 用 MCU 自带的 DAC 外设 8 / 12 位（看型号） 快（几 MSa/s 更新） 零外围，但要选对型号 波形输出、音频、闭环控制设定值、可编程基准 很多型号根本没有 DAC（下面细说）
② PWM + RC 低通滤波 理论 = PWM 位数（16 位定时器可做 10~12 位有效） 慢（更新率几十 ~ 几百 Hz） 两个元件（R + C），最便宜 设定值输出、调光、调速、慢速基准（对纹波要求不高的场合） 纹波与响应速度不可兼得；输出阻抗高、带载能力弱
③ 外接 DAC 芯片 8 / 10 / 12 / 16 位 中（受 I²C/SPI 速率限制，几十 kSa/s 常见） 几元 ~ 几十元 + 两个上拉/去耦 多通道输出、需要真单调与高精度、需要掉电保存输出值 要写驱动（I²C/SPI）；要多占引脚；速率受总线限制
买之前一定要查：这块 MCU 到底有没有 DAC？

这是新手最容易踩的坑之一。STM32 的 DAC 外设不是全系列都有的：

  • 没有 DAC：STM32F103C8T6（也就是最常见的「蓝板子 / 最小系统板」）、F0 系列、G0 大部分型号。很多人拿 F103C8T6 做音频输出，翻遍手册也找不到 DAC 寄存器——因为它真的没有。这时候只能用 PWM + RC，或者外接 DAC 芯片。
  • 有 DAC：STM32F4 系列（如 F407、F411）、F7、H7、L4 部分型号，通常是 2 个 12 位 DAC 通道，可以输出到引脚，还支持 DMA 驱动的波形输出和三角波/噪声波发生器。

所以选型时不要看「STM32 有 DAC」，要看你手上那一颗的具体型号的数据手册里有没有 DAC 章节。这也正好说明了「真 DAC」方案的第一条缺点：它绑死了你的选型自由度。

动手算一遍

前两节讲的是「为什么」和「是什么」，这一节开始动手。下面八道题全部是工程里真的会遇到的计算：选型时要算、写代码时要算、调不出来时更要算。建议你拿张纸跟着算一遍，尤其是例三——自己走完 12 次比较，SAR 就彻底变成你的了。

每道题的格式都是「已知条件 → 分步计算 → 结论 → 一句点评」，所有估算都会说明是按什么典型值算的。

例一：12 位 ADC 的 LSB 与量化误差

题目：STM32F103 的 ADC 是 12 位，用 VDDA 当基准，实测 VDDA = 3.300V。现在从一个传感器读到 1.234V 的输入电压。求：(1) 1 LSB 等于多少？(2) 最大量化误差是多少？(3) ADC 输出的码值是多少？(4) 用码值反算出来的电压是多少、误差多大？(5) 如果代码里图省事写成 raw × 3.3 / 4095 会差多少？

【第 1 步：1 LSB 有多大】

   q = V_FS / 2^N = 3.300V / 4096 = 8.05664e-4 V = 0.805664 mV

   ★ 答：1 LSB = 0.806 mV（约 0.8mV）
     这句话的含义：小于 0.8mV 的电压变化，ADC 原则上分辨不出来。

【第 2 步：最大量化误差】

   理想量化（round-to-nearest）误差范围 = ±q/2
       = ±0.805664 / 2 = ±0.402832 mV

   ★ 答：±0.403 mV（约 ±0.4mV）

【第 3 步：算码值】

   码值 = Vin / q = 1.234V / 0.805664mV = 1531.65
   四舍五入 → 【1532】 = 0x5FC
             （二进制 0101 1111 1100）

【第 4 步：反算电压，检查误差】

   V_反算 = 1532 × 0.805664mV = 1234.277 mV = 1.234277 V
   误差 = 1.234277 - 1.234000 = +0.277 mV
   用 LSB 表示：+0.277 / 0.805664 = +0.34 LSB   ✓ 在 ±0.5 LSB 之内

   ★ 答：读数 1532，对应 1.2343V，误差 +0.28mV

【第 5 步：口径差异（4095 还是 4096？）】

   如果代码写成 V = raw × 3.3 / 4095：
       1532 × 3.3 / 4095 = 1.234579 V
   和标准口径 1.234277V 相差：0.302 mV = 0.37 LSB

   两种写法的差异只有 0.02%，但：
   · 做误差预算时，0.37 LSB 已经不能忽略了（12 位一共就 4096 个码）
   · 和别人对数字时，一定要问清用的是哪个口径
   · 工程习惯：代码里用 4095，理论推导里用 2^N —— 知道两者差在哪就行

【这道题真正要你记住的】
   "12 位 ADC 能分辨 0.8mV"这句话，只有在【基准准确 + 噪声足够小 +
    没有 INL】的前提下才成立。按 ENOB ≈ 10 位算，
    实际能稳定分辨的电压是 3.3/1024 = 3.2mV 左右 —— 比 0.8mV 差 4 倍。

例二：混叠频率与所需采样率

题目：你要用 ADC 监测一台电机的振动，关心的是 0 ~ 2kHz 的振动成分。程序里采样率设成了 5kHz（每 200µs 采一次）。电机驱动器有一个 4.5kHz 的啸叫（PWM 引起的机械噪声）。(1) 这个 4.5kHz 会不会混叠？混到哪里？(2) 会带来什么后果？(3) 采样率至少取多少才安全？(4) 抗混叠滤波器该怎么定？

【第 1 步：判断会不会混叠】

   奈奎斯特频率 = f_s / 2 = 5000 / 2 = 2500 Hz
   信号频率 4500 Hz > 2500 Hz  →  【会混叠】

【第 2 步：混到哪里】

   f_alias = | f - k·f_s |，取 k 使结果落在 0 ~ 2500Hz
   k = 1 ：| 4500 - 5000 | = 500 Hz     ✓ 落在关心频段内

   ★ 答：4500Hz 被读成 500Hz

【第 3 步：后果】

   500Hz 正好在你关心的 0~2kHz 频段里！
   → 你会在频谱上看到一个 500Hz 的"振动峰"
   → 很容易误判为"机械共振"、"轴承松动"、"联轴器不对中"
   → 于是你去拆机器，结果什么问题都没有

   ★ 混叠最坑的地方：它制造出一个看起来非常合理的假信号。
     而且如果电机转速变化（PWM 频率跟着变），
     这个假峰的频率也会跟着漂 —— 更像真的了。

【第 4 步：采样率该取多少】

   理论下限：f_s ≥ 2 × f_max = 2 × 2000 = 4000 Hz  → 取 4kHz
   工程取值：留 5~10 倍余量 → 【10 ~ 20 kHz】，建议 20kHz

   取 f_s = 20kHz 时：
       奈奎斯特频率 = 10 kHz，4500Hz 远低于它 → 不混叠 ✓

【第 5 步：抗混叠滤波器】

   通带截止：f_c = f_max = 2 kHz（关心的最高频率）
   需要压掉的频率：f_s - f_max = 20k - 2k = 18 kHz
   衰减量目标：12 位 → 约 74 dB（压到量化噪声底以下）

   一阶 RC 在 18kHz 处的衰减 = 20·log10(18/2) = 19.1 dB
   多阶滤波器的衰减按阶数倍增：
       一阶：19 dB      ✗ 远远不够
       二阶：38 dB      ✗ 不够
       三阶：57 dB      ✗ 还差一点
       四阶：76 dB      ✓ 够（用两级 Sallen-Key 实现）

   ★ 结论：要么用四阶有源滤波（成本和调试难度都上去了），
     要么【把采样率提上去】。这是个非常典型的工程抉择：

     如果改取 f_s = 50 kHz：
         需要压掉的频率变成 48 kHz，相对 f_c = 2kHz 是 24 倍
         二阶：40·log10(24) = 55 dB
         三阶：60·log10(24) = 83 dB  ✓ 够，而且只要三阶

     采样率提高 2.5 倍，滤波器从四阶降到三阶（甚至二阶勉强可用）。
     这就是"采样率留余量"的真实价值：它把难题从【模拟电路】
     转移到了【数据量】上 —— 而数据量在今天的单片机上是便宜的。

【顺手算一下数据量】
   20kHz × 2 字节 = 40 kB/s；50kHz = 100 kB/s
   F103 的 ADC + DMA 搬运 100kB/s 毫无压力（DMA 不占 CPU）。

例三：跟着 SAR 走完 12 次比较

题目：还是 12 位、V_REF = 3.300V（1 LSB = 0.805664mV）。这次输入电压换成一个「小信号」：Vin = 1.0000V。(1) 请自己把 12 次比较走完，写出每一步的试探码、DAC 输出电压、判决结果和最终码值。(2) 如果 ADC 时钟是 12MHz（F103 在 72MHz 主频下的常用配置）、采样时间配成 55.5 个周期，一次转换要多久？最高能到多少采样率？

【准备】判决规则（教科书模型）：V_DAC > Vin 就清 0，否则保留 1
        1 LSB = 3.300V / 4096 = 0.805664 mV
        理想码值 = 1.0000 / 0.805664e-3 = 1241.2

【12 次比较】

  次 位    试探码   V_DAC = 试探码×0.805664mV   与 1.0000V 比较   该位  累计
  ─────────────────────────────────────────────────────────────────────────
   1  b11   2048    1650.0 mV   1.0000 < 1.6500   清 0     0
   2  b10   1024     825.0 mV   1.0000 > 0.8250   保留 1   1024
   3  b9    1536    1237.5 mV   1.0000 < 1.2375   清 0     1024
   4  b8    1280    1031.2 mV   1.0000 < 1.0312   清 0     1024
   5  b7    1152     928.1 mV   1.0000 > 0.9281   保留 1   1152
   6  b6    1216     979.7 mV   1.0000 > 0.9797   保留 1   1216
   7  b5    1248    1005.5 mV   1.0000 < 1.0055   清 0     1216
   8  b4    1232     992.6 mV   1.0000 > 0.9926   保留 1   1232
   9  b3    1240     999.0 mV   1.0000 > 0.9990   保留 1   1240
  10  b2    1244    1002.2 mV   1.0000 < 1.0022   清 0     1240
  11  b1    1242    1000.6 mV   1.0000 < 1.0006   清 0     1240
  12  b0    1241     999.8 mV   1.0000 > 0.9998   保留 1   1241

【结果】
   码值 = 1241 = 0b0100_1101_1001 = 0x4D9
   反算电压 = 1241 × 0.805664mV = 999.83 mV = 0.99983 V
   误差 = 0.99983 - 1.00000 = -0.17 mV = -0.21 LSB   ✓ 在 ±0.5 LSB 内

【注意这道题和 2.4V 那道题的关键差别】
   2.4V 时第 1 次比较是"保留"（MSB = 1），码值是 2978（约 0xBA2）
   1.0V 时第 1 次比较是"清 0"（MSB = 0），码值是 1241（0x4D9）
   → 第 1 次比较直接决定了信号落在量程的【上半段还是下半段】。
     这也解释了为什么"小信号测量"精度差：
     一个只用到量程 1/3 的信号，白白浪费了 1 位多。

   如果这个传感器永远只输出 0~1V，正确做法是：
       ① 把 V_REF 换成 1.000V（外部基准）→ 立刻多出 1.7 位
       ② 或者先用运放把 0~1V 放大到 0~3.3V（注意别超量程）
       —— 这叫"信号调理"，是 ADC 应用里最划算的一笔投资。

【第 2 部分：转换时间与最大采样率】

   STM32 的 ADC 一次转换 = 采样时间 + 12.5 个 ADC 周期
       采样时间配 55.5 个周期（常用值）
       转换阶段固定 12.5 个周期（12 次比较 + 一点开销）
   → 总共 55.5 + 12.5 = 68 个 ADC 周期

   ADC 时钟配多少？这是 F103 上很关键的一步，很容易配错：
       ADC 的时钟来自 PCLK2，只能选 2 / 4 / 6 / 8 分频（RCC_CFGR 的 ADCPRE）
       主频 72MHz 时 PCLK2 = 72MHz，那么可选项是：
           /2 = 36 MHz  ✗ 超过上限（F103 的 f_ADC 最大 14MHz，会读出乱码）
           /4 = 18 MHz  ✗ 仍然超
           /6 = 12 MHz  ✓ 唯一合适的高频选择
           /8 =  9 MHz  ✓ 也安全（更慢一点）
       → 【定 12 MHz】，1 个 ADC 周期 = 1/12MHz = 83.3 ns

   T_conv = 68 × 83.3ns = 5667 ns = 5.667 us
   最大采样率 = 1 / 5.667us = 176.5 kSa/s ≈ 176 kSa/s

   ★ 答：一次转换约 5.67µs，最高约 176 kSa/s

   【反过来算】如果你需要 100kSa/s（每 10µs 一个数）：
       T_conv 必须 ≤ 10µs，现在的 5.67µs 其实够用，还剩一倍余量
       → 如果想更快，缩短采样时间（比如 13.5 周期）：
         13.5 + 12.5 = 26 个周期
         T_conv = 26 / 12e6 = 2.167 us → 461 kSa/s ✓ 快得多
       → 但采样时间短了，对源阻抗的要求就变高了（见第 4 节）
   ★ 这就是"速度、精度、源阻抗"三者互相牵制的具体样子。

   【顺便记一个坑】ADCPRE 是很多人第一次用 ADC 时踩的坑：
      以为"主频越高越好"，把 ADCPRE 设成 /2 → 36MHz 的 ADC 时钟，
      结果读出来的数全是乱的（可能一直是 4095 或者乱跳），
      查半天找不到原因。记住 F103 的 ADC 时钟上限是 14MHz。

例四：双积分型的计数值与转换时间

题目：一台用双积分原理做的面板表：时钟 1MHz，基准电压 V_REF = 2.000V，第一阶段定时 T1 取 20ms（正好是 50Hz 工频的一个整周期，用来抗工频干扰）。现在输入 1.250V。(1) 第一阶段的计数是多少？(2) 第二阶段的计数 N2 是多少？(3) 一次转换要多长时间？每秒最多转换几次？(4) 这套方案的分辨率相当于多少位 ADC？(5) 如果现场是 60Hz 工频，T1 该怎么改？

【第 1 步：第一阶段的计数 N1】

   时钟周期 T_clk = 1 / 1MHz = 1 us
   T1 = 20 ms，所以固定计满
       N1 = 20ms / 1us = 20000 个计数
   → 这就是"计数器的满量程"，也是分辨率的上限

【第 2 步：第二阶段的计数 N2（核心公式）】

       N2 = (Vin / V_REF) × N1

   代入：
       N2 = (1.250 / 2.000) × 20000 = 0.625 × 20000 = 12500

   ★ 答：N2 = 12500
     显示出来就是 1.2500 V（4½ 位表，直接把 N2 按小数点显示）

【第 3 步：转换时间】

   T1 = 20.0 ms（固定，每次都要走完）
   T2 = N2 × T_clk = 12500 × 1us = 12.5 ms
   一次转换 = T1 + T2 = 20.0 + 12.5 = 32.5 ms
   转换速率 = 1 / 0.0325 = 30.8 次/秒

   【最坏情况】Vin 接近 V_REF 时，N2 → N1 = 20000
       T2_max = 20 ms，一次转换 = 40 ms → 25 次/秒
   → 设计时要按最坏情况算：★ 每秒最多 25 次

【第 4 步：等效分辨率】

   一个计数对应的输入电压变化 = V_REF / N1 = 2.000V / 20000 = 0.1 mV
   → 1 个计数 = 0.1mV = 100 uV

   等效位数 = log2(N1) = log2(20000) = 14.3 位

   ★ 答：相当于 14.3 位的 ADC —— 但它每秒只出 25 个数。
     对比一下：STM32 的 12 位 ADC 每秒能出 20 万个 12 位结果。
     一个是"慢而准"，一个是"快而粗"，选哪个取决于你的需求。

【第 5 步：60Hz 工频怎么办】

   抗工频的原理是"让 T1 正好等于工频周期的整数倍"：
       50 Hz：周期 20.00 ms → T1 取 20ms / 40ms / 100ms
       60 Hz：周期 16.67 ms → T1 取 16.67ms / 33.33ms / 100ms

   注意 100ms 是 50Hz 和 60Hz 的【最小公倍数】附近的取值：
       100ms / 20ms = 5 个 50Hz 周期   ✓
       100ms / 16.67ms = 6 个 60Hz 周期 ✓
   → 所以出口型的万用表常常把 T1 设成 100ms，
     这样 50Hz 和 60Hz 都能抗。
     代价是转换时间翻到 200ms（最坏），每秒只有 5 个数。

   ★ 这是一个很典型的工程折中：抗干扰能力 ↔ 测量速度。

例五：R-2R 网络在某数字码下的输出

题目：一个 4 位 R-2R 梯形网络 DAC：R = 10kΩ，反馈电阻 R_f = 10kΩ（正好等于 R），基准电压 V_REF = 3.300V。现在数字码是 1011。(1) 用公式算出输出电流与输出电压。(2) 用「逐位叠加」再验算一遍。(3) 满量程输出是多少？(4) 1 LSB 对应的输出电压是多少？

【第 1 步：用总公式】

   公式（见第 2 节 R-2R 的推导）：
       I = (V_REF / (2R × 2^(N-1))) × D
       V_out = -I × R_f

   代入 N = 4、R = 10kΩ、V_REF = 3.3V、D = 1011(二进制) = 11(十进制)：

       I = (3.300 / (2 × 10000 × 2^3)) × 11
         = (3.300 / 160000) × 11
         = 2.0625e-5 × 11
         = 2.26875e-4 A
         = 【0.226875 mA】

       V_out = -0.226875mA × 10kΩ = 【-2.26875 V】

【第 2 步：逐位叠加验算（superposition）】

   每一位单独作用时的输出电压，就是"这一位的权重"：

   b3 (MSB, 权重 8)：  V3 = -(V_REF/2R) × R_f = -(3.3/20000) × 10000 = -1.6500 V
   b2 (权重 4)：        V2 = V3 / 2 = -0.8250 V   → 但 b2 = 0，不贡献
   b1 (权重 2)：        V1 = V3 / 4 = -0.4125 V   → b1 = 1，贡献 -0.4125 V
   b0 (LSB, 权重 1)：   V0 = V3 / 8 = -0.20625 V  → b0 = 1，贡献 -0.20625 V

   叠加（码 1011 → b3=1, b2=0, b1=1, b0=1）：
       V_out = -1.6500 + 0 - 0.4125 - 0.20625 = 【-2.26875 V】  ✓ 与公式一致

   ★ 这份验算同时验证了两件事：
     ① 每往低位走一级，权重正好减半（1.65 → 0.825 → 0.4125 → 0.20625）
     ② 这就是 R-2R"用两种阻值实现二进制加权"的具体表现

【第 3 步：满量程输出】

   码 = 1111，D = 15
       V_FS = -V_REF × 15/16 = -3.3 × 0.9375 = 【-3.09375 V】
   或逐位叠加：1.6500 + 0.8250 + 0.4125 + 0.20625 = 3.09375 V  ✓ 一致

   ★ 注意：满量程电压【不等于】V_REF，而是 V_REF × (2^N - 1)/2^N。
     4 位时差了 1/16 = 6.25%，12 位时只差 0.024%。
     这个"差一个 LSB"的现象，是所有 DAC 的共性。

【第 4 步：1 LSB 的输出电压】

   1 LSB = V_REF / 2^N = 3.3 / 16 = 【0.20625 V】

   ★ 验证：V1 - V0 = 0.4125 - 0.20625 = 0.20625 V ✓
     码值每加 1，输出就增加 0.20625V。

【工程点评】
   4 位只有 16 个台阶，1 LSB = 206mV —— 这在控制里几乎没法用。
   真实的 DAC 一般在 8~16 位：
       8 位：1 LSB = 3.3/256  = 12.9 mV（可调光、粗略调速）
      12 位：1 LSB = 3.3/4096 = 0.806 mV（精密设定值、波形输出）
      16 位：1 LSB = 3.3/65536 = 50 uV（精密电压源、仪表）
   而 R-2R 结构的优势在于：不管多少位，永远只有 R 和 2R 两种阻值。

例六：过采样换来的有效位数

题目：STM32 的 12 位 ADC，读数末两位总是跳（ENOB 约 10 位）。你想通过过采样把它压稳。(1) 用 4 倍、16 倍、64 倍过采样分别能提升多少位？(2) 16 倍过采样后等效多少位、SNR 提升多少 dB？(3) 代价是什么？(4) 有什么前提条件是必须满足的？

【第 1 步：基本规律】

   把采样率提高到原来的 M 倍（M = 过采样倍数），再做平均，
   带内噪声功率降为 1/M：

       信噪比提升 = 10·log10(M)   (dB)
       位数提升   = 10·log10(M) / 6.02 = 0.5·log2(M) = log4(M)  (位)

   ★ 一句话规律：【采样倍数每乘 4，有效位数加 1 位】

       4 倍 = 4^1  → +1 位   (SNR +6.02 dB)
      16 倍 = 4^2  → +2 位   (SNR +12.04 dB)
      64 倍 = 4^3  → +3 位   (SNR +18.06 dB)
     256 倍 = 4^4  → +4 位   (SNR +24.08 dB)

【第 2 步：16 倍过采样的具体账】

   ★ 答：16 倍过采样 → 提升 2 位 → 等效 14 位
         SNR 提升 = 10·log10(16) = 12.04 dB
         等效 SNR：原来约 62 dB（10 位）→ 约 74 dB（相当于理想 12 位）

   注意这里有个"巧合"值得点出来：
       12 位 ADC 用 16 倍过采样，等效 14 位，
       但它的【噪声底】是 74dB，正好等于理论 12 位的水平。
       换句话说：过采样不能突破芯片本身的精度上限
       （INL、基准漂移还在那里），它只是把"随机噪声"平均掉，
       让你把本来被噪声埋掉的那两位"捞回来"。

【第 3 步：代价】

   ① 时间：16 倍过采样 = 采 16 次求平均
         原来一次转换 5.67us → 16 次 = 90.7 us
         等效采样率从 176 kSa/s 降到 11.0 kSa/s
      → 【用速度换精度】。这就是那个永恒的天平。
   ② 代码复杂度：要开一个数组做累加，或者用 STM32 的硬件过采样
   ③ 内存/CPU：16 次累加可以用 uint32 存，运算量很小；
      但如果用浮点平均、或者要做几十阶的滑动平均，就要算算 CPU 占用

【第 4 步：前提条件（这几条不满足，过采样就是白做）】

   ① 噪声必须是"随机"的（白噪声）
      如果噪声是确定的、和采样同步的干扰 —— 平均根本压不掉！
      典型例子：采样率正好是工频 50Hz 的整数倍时，
      每次采样都落在工频的同一相位上 → 16 次平均后工频纹丝不动。
      ★ 这是过采样最常见的失败原因。

   ② 信号带宽必须远小于采样带宽
      过采样的本质是"把噪声摊到更宽的频带上"。
      如果被采信号本身就占满了奈奎斯特带宽，就没有"摊"的余地了。

   ③ 噪声要足够大，大到能"随机化"量化误差
      如果输入信号非常干净（噪声小于 1 LSB），
      量化误差会变成确定的周期性误差（与信号相关），
      平均反而可能得到"假的高分辨率"。
      工程上有时会【故意注入一点抖动（dither）】来解决这个问题。
      ★ 这一条非常反直觉：想要更准，有时要先加一点噪声。

   ④ 不能改善系统性误差
      失调、增益、INL、基准漂移 —— 过采样一个都修不了。
      它们是真误差，不会因为多采几次就消失。

【第 5 步：STM32 上的两种做法】

   软件过采样（F103 这种没有硬件过采样的型号）：
       循环采 N 次，把 raw 累加到一个 uint32 里，最后右移 log2(N) 位
       raw_sum / N —— 注意累加时别溢出：12 位 × 16 次 = 最大 65520
       用 uint16 刚好够，但保险起见用 uint32

   硬件过采样（F3 / L4 / H7 等有 OVS 位的型号）：
       配置 ADC 的过采样寄存器：OVSR 选比例（2~256），OVSR 移位选 0~8
       例如：比例 256 + 右移 4 位 → 得到 16 位结果，等效多 4 位
       好处：全自动、不占 CPU、不需要中断里做累加
       ★ 硬件过采样最多做到 256 倍（+4 位），这是寄存器位宽的限制

例七：由纹波要求反算 PWM + RC

题目：手上的板子只有 STM32F103C8T6（没有 DAC 外设），要用 PWM + RC 滤波做一个模拟电压输出。条件：PWM 频率 100kHz（72MHz 定时器 720 分频得到），占空比可调 0~719 共 720 级（约 9.5 位分辨率），V_DD = 3.300V。(1) 1 LSB 是多少？(2) 要求输出纹波不超过 1 个 LSB，RC 至少要多少？(3) 取 R = 270Ω、C = 10µF 时实际纹波多大？(4) 从写一个值到输出稳定要多久、更新率多高？(5) 这套方案能做什么、不能做什么？

【第 1 步：输出分辨率】

   占空比级数 = 720（ARR = 719，比较值 0 ~ 719）
   等效位数 ≈ log2(720) = 9.49 位  → 按 720 级算，不是 1024 级

   1 LSB = V_DD / 720 = 3.300 / 720 = 【4.583 mV】

【第 2 步：纹波公式】

   一阶 RC 滤波后，PWM 方波的残余纹波（三角波近似，适用于 f_pwm >> f_c）：

       ΔV_pp ≈ V_DD × D × (1 - D) / (f_pwm × R × C)

   ★ D = 0.5 时最坏（D(1-D) = 0.25），所以按最坏情况算：
       ΔV_pp ≈ 3.300 × 0.25 / (100000 × RC) = 0.825 / (1e5 × RC)

   要求 ΔV_pp ≤ 1 LSB = 4.583 mV：
       0.825 / (1e5 × RC) ≤ 4.583e-3
       1e5 × RC ≥ 0.825 / 4.583e-3 = 180.0
       ★ RC ≥ 1.80e-3 s = 【1.80 ms】

   【等价的经验规则】由上式可推出
       f_pwm / f_c ≥ 1.57 × 2^N      （f_c = 1/(2·pi·R·C)）
   本例：f_c = 1/(2·pi·1.80e-3) = 88.4 Hz（N = log2(720) = 9.49，2^N = 720）
        1.57 × 720 × 88.4 = 100 kHz ✓ 正好

【第 3 步：取 270Ω + 10µF 的实际纹波】

   R × C = 270 × 10e-6 = 2.70e-3 s = 2.70 ms  （略大于 1.80ms ✓）
   ΔV_pp = 0.825 / (1e5 × 2.7e-3) = 0.825 / 270 = 3.056 mV

   ★ 实际纹波 = 3.06 mV ≈ 0.67 LSB ✓ 满足要求（还留着约 1/3 的余量）

   ⚠ 这 1/3 的余量是在最坏点 D = 0.5 上算的，不算宽裕：
     如果占空比要覆盖整个 0~100%，靠近两端时纹波会变小（D(1-D) 小），
     最坏点永远在 D = 0.5。所以按 0.5 算就够了。

【第 4 步：响应速度 —— 这才是真正的代价】

   从一次"写入新的比较值"到输出稳定，是一阶 RC 的阶跃响应：
       V(t) = V_target × (1 - e^(-t/RC))，时间常数 tau = RC = 2.70 ms

   要求稳定到 ±1/2 LSB = ±2.29 mV（相对满量程 3.3V）：
       e^(-t/tau) ≤ 2.29e-3 / 3.3 = 6.94e-4
       t / tau ≥ ln(1/6.94e-4) = ln(1440) = 7.27
       t ≥ 7.27 × 2.70 ms = 【19.6 ms】

   ★ 也就是说：每次改输出值，要等 19.6ms 才能真正稳定
     → 输出更新率上限 = 1 / 0.0196 = 【约 51 Hz】

   ★★ 这就是 PWM + RC 方案的真相：
      分辨率做到了约 9.5 位（720 级，每级 4.58mV），但更新率只有 51Hz。
      拿来输出一个正弦波？51Hz 的更新率最多合成几 Hz 的波形，而且
      严重失真（每个周期只有几十个点）。
      → 做【慢速设定值】合格，做【波形输出】不合格。

【第 5 步：能做什么、不能做什么】

   ✓ 能做：
     · 调光（LED 亮度，人眼对纹波不敏感）
     · 调速（电机给定，机械惯性天然是低通）
     · 慢速设定值（温控目标、电源电压设定、偏置电压）
     · 比较器门限、传感器激励
     · 只要更新率 < 几十 Hz 就够的场合

   ✗ 不能做：
     · 音频输出（要 20kHz 带宽）
     · 波形发生器（要快速更新）
     · 需要快速跳变的控制（比如电流环给定）
     · 高精度电压基准（纹波 + 输出阻抗 + V_DD 不稳）

【两个必做的补丁】

   ① 输出必须加电压跟随器
      RC 的输出阻抗就是 R = 270Ω。接一个 10kΩ 的负载就会分压：
         3.3V × 10k/(10k + 0.27k) = 3.212V  → 误差 88mV = 19 LSB！
      用一个运放做电压跟随器（或用带运放的 DAC 缓冲芯片），
      把输出阻抗降到毫欧级。

   ② V_DD 必须稳
      输出电压 = V_DD × D，所以 V_DD 飘 1% 输出就飘 1%（33mV = 7 LSB）。
      PWM+RC 方案对电源的依赖和真 DAC 是一样的 —— 
      它省掉的是 DAC 芯片，不是"对基准的要求"。

【想再快一点怎么办？】
   把 RC 减小 → 纹波变大；把 PWM 频率提高 → 纹波变小（同一 RC 下）
   所以正确方向是【提高 PWM 频率】：
       把 PWM 提到 500kHz（72MHz / 144）：
           RC ≥ 0.25×720/(5e5) = 0.36 ms
           取 270Ω + 2.2µF = 0.594ms → 纹波 = 0.825/(5e5×5.94e-4) = 2.78mV
           建立时间 = 7.27 × 0.594ms = 4.32 ms → 更新率 231 Hz ✓
   → 提升 4.5 倍。代价：定时器分辨率下降（72MHz/500kHz = 144 级，
     只有 7.2 位！）★ 这就是 PWM 方案的根本矛盾：
     频率越高 → 占空比级数越少 → 分辨率越低。
     两者不可兼得，只能靠【二阶滤波】或【外接 DAC 芯片】破解。

例八：基准飘 1% 与 VREFINT 反推

题目：你的一块 STM32F103 板子，代码里按 3.3V 做换算，V = raw * 3.3f / 4095。用万用表量 VDDA，实际只有 3.115V（USB 供电加了个二极管，压降吃掉了 0.185V）。(1) 这个 5.6% 的偏差会让读数错多少？(2) 怎么用芯片内部的 VREFINT 自己把这个偏差修回来？(3) 已知出厂校准值 VREFINT_CAL = 1520（在 VDDA = 3.3V、25°C 下测的，存放在 0x1FFFF7BA），当前读 VREFINT 通道得到 1610，求真实 VDDA。(4) 此时某通道读到 raw = 3000，真实电压是多少？用 3.3V 硬算会差多少？

【第 1 步：基准偏差带来的读数误差】

   ADC 的输出码是【比值】：raw = Vin / VDDA × 4095
   你反算时用的是：      V = raw × 3.3 / 4095

   两个式子里的 VDDA 不一致 → 反算结果整体按比例偏：

       偏差比例 = (3.300 - 3.115) / 3.115 = 0.185 / 3.115 = 5.94%
       → 读数【偏大 5.94%】

   而且要注意：这是【乘性误差】（正比于读数大小），不是固定偏移：
       真实 1.000V → 读成 1.059 V   （差 59mV）
       真实 2.000V → 读成 2.119 V   （差 119mV）
       真实 3.000V → 读成 3.178 V   （差 178mV = 220 个 LSB！）
   ★ 一个二极管压降，就让 12 位 ADC 的绝对精度退化到 8 位以下。
     这就是"基准决定绝对精度"的最现实例子。

【第 2 步：VREFINT 的原理】

   VREFINT 是芯片内部一个【固定的 1.20V 左右】的基准源，
   它自己的电压不随 VDDA 变化（这就是它能当"尺子"的原因）。

   STM32 出厂时，厂家在 VDDA = 3.3V、25°C 条件下
   逐片测出 VREFINT 通道的 ADC 读数，存到芯片的信息区：
       STM32F103 的地址 = 0x1FFFF7BA（16 位半字）

   于是关键的关系是：
       VREFINT_CAL = 1.20V / 3.300V × 4095   （出厂时测的）
       raw_vrefint = 1.20V / VDDA  × 4095    （现在测的）

   两式相除，1.20V 和 4095 都被约掉：
   ────────────────────────────────────────────
       ★  VDDA = 3.300V × VREFINT_CAL / raw_vrefint
   ────────────────────────────────────────────

   ★ 注意：VREFINT 的绝对值有 ±3%~5% 的初始偏差，所以【不能】拿它
     当电压基准去测绝对电压；但它出厂时是【同一颗芯片、同一个内部源】
     测出来的，所以用它来【反推同一颗芯片的 VDDA】精度足够。
     这就是"用它做相对校准，而不是绝对基准"。

【第 3 步：算真实 VDDA】

   VDDA = 3.300 × 1520 / 1610
        = 3.300 × 0.944099
        = 【3.1155 V】

   ★ 和万用表量的 3.115V 只差 0.5mV —— 这个方法相当准！

   【为什么 raw 会变大？】
       VREFINT 电压是固定的 1.2V，而 VDDA 越大，
       1.2V 占满量程的比例越小 → raw 应该越小。
       现在 raw 从 1520 涨到 1610（变大了）
       → 说明 1.2V 占的比例变大了 → VDDA【变小了】 ✓
       方向感一验就通，不容易记反公式。

【第 4 步：修正后的真实电压】

   ① 用修正后的 VDDA 换算：
       V = 3000 × 3.1155 / 4095 = 3000 × 7.6081e-4 = 【2.2824 V】

   ② 用 3.3V 硬算（错误做法）：
       V = 3000 × 3.300 / 4095 = 【2.4176 V】

   ③ 误差：
       2.4176 - 2.2824 = 0.1352 V = 【135 mV】
       相对误差 = 135mV / 2282mV = 5.9%
       折算成 12 位的码：135mV / 0.805664mV = 168 个 LSB

   ★ 答：真实电压 2.282V；用 3.3V 硬算会得到 2.418V，
     差了 135mV（5.9%）—— 比 12 位 ADC 的 1 LSB 大了 168 倍。

【在代码里怎么用】

   ① 开机时读一次 VREFINT 通道（ADC1_IN17），算出 VDDA_real，存全局变量
   ② 以后所有换算都用 VDDA_real，而不是写死的 3.3f
   ③ 注意 VREFINT 通道的采样时间要配长：
      手册要求这两个内部通道的采样时间不小于 5.1us
      （温度传感器 ADC1_IN16 上电后还要等约 10us 稳定）
      → 采样时间配 239.5 个周期：239.5 / 12MHz = 19.96us ✓ 满足（还留了余量）
   ④ 内部通道的读数也要多次平均（过采样），否则反推出的 VDDA 会跳
      → 建议 16~64 次平均，只在开机时算一次就够了
   ⑤ 想更准：可以在生产时用外部万用表量一次 VDDA，
      把比例系数存进 Flash，作为"二级校准"
      —— 这就是量产的"单点校准"流程

【一句话总结这道题】
   12 位 ADC 的"12 位"，说的是【分辨率】；
   要把它变成【精度】，你必须知道 VDDA 到底是多少。
   不知道 VDDA 的 12 位 ADC，实际精度可能只有 8 位。

在单片机上的样子

前面三节讲的是原理，这一节全部落到 STM32（以最常见的 STM32F103C8T6 为例，别的型号大同小异）。你会发现：原理里的每一个概念，在芯片里都有一个具体的寄存器或者配置项对应；反过来，几乎每一个"ADC 读不准"的问题，都能在原理里找到原因。

源阻抗与采样时间

上一节讲过 S/H 的本质是「让 C_ADC 跟着输入充电」。既然是充电，就有个时间问题：信号源的阻抗越大，充电越慢；采样时间不够，电容就充不到输入电压，读出来的数就偏小。

STM32 的 ADC 输入端可以简化成这样一个模型：

   外部信号源            内部采样开关            内部采样电容
   ┌──────────┐          ┌─────┐               ┌─────┐
   │ 传感器   │── R_src ──┤ 闭合 ├── R_ADC ──────┤C_ADC├── 到逐次逼近电路
   │ 分压器等 │          └─────┘  (约 1kΩ 量级)  └─────┘  (约 8pF 量级)
   └──────────┘

   ★ R_ADC 与 C_ADC 是芯片内部的东西，你看不见也改不了。
     不同手册、不同型号的值略有差别，按【典型值量级】理解即可：
     要精确设计时，以你手上那颗芯片的数据手册为准。

   充电过程是一个指数曲线：
       V_C(t) = Vin × (1 - e^(-t/τ))，   τ = (R_src + R_ADC) × C_ADC

   要充到 12 位精度的 1/4 LSB 以内（误差 1/16384），需要：
       e^(-t/τ) ≤ 1/2^14
       t ≥ τ × ln(2^14) = τ × 9.70

   ★ 结论公式：t_需要 ≈ (R_src + R_ADC) × C_ADC × 9.70
     把 R_ADC ≈ 1kΩ、C_ADC ≈ 8pF 代进去 → t_需要 ≈ (R_src + 1000) × 7.76e-11 秒
     （R_src 用量纲为欧姆的数值代入）

源阻抗太大时的三个典型症状

① 读数偏小且随通道变化。高阻抗信号没充到应有电压，读出来总是低一截；换个通道（源阻抗不同）偏差还不一样。

② 通道之间串扰，出现"鬼影"。前一个通道的电荷还留在 C_ADC 上，切到下一个通道时拉低了它的读数 —— 表现为「大信号通道旁边的通道读数总是不准」。缩短采样时间会让它更严重。

③ 在信号源后面并一个大电容想"稳定"读数，结果更糟。100nF 的电容看着能滤波，但它和采样电容之间会有电荷分享：切换通道瞬间，100nF 通过 R_src 给 C_ADC 充电，如果 R_src 大（比如 100kΩ 分压），充一次的时间常数会变得非常大。多通道扫描时，这个电容还会把前一个通道的电压"记住"并带到下一个通道。

正确做法：在信号源后面加一级运放电压跟随器（源阻抗立刻降到 1Ω 以下），采样时间就可以用最短档；确实要在 ADC 引脚前加 RC 抗混叠滤波时，电容取 1nF~10nF 量级，并把采样时间相应加长。

读数换算与 VDDA 反推

ADC 给你的永远是 0~4095 的码值，不是电压。要变成电压，必须知道基准。F103 上默认的基准就是 VDDA（模拟电源），所以换算公式是：

   ① 码值 -> 电压（浮点写法，直观）
          V = raw × VDDA / 4095

   ② 码值 -> 毫伏（整数写法，单片机里更常用）
          mV = (raw × VDDA_mV + 2047) / 4095
          （+2047 是四舍五入；整数运算比浮点快得多，
            在中断里高频换算时特别有用）

   ③ VDDA 自己是多少？用内部参考电压 VREFINT 反推：
          VDDA = 3.300V × VREFINT_CAL / raw_vrefint
          VREFINT_CAL 在 F103 上存放于 0x1FFFF7BA（16 位）
          是出厂时在 VDDA = 3.3V、25°C 下逐片测出来的

   ★ 为什么用 4095 而不是 4096？
     工程习惯用 4095（保证满量程正好等于 VDDA），
     理论推导用 2^N（保证 LSB 定义干净）。
     两者相差 0.024%，12 位下约 0.37 LSB ——
     自己写代码要固定一种口径，和别人对数时要先问清。

为什么不能直接写死 3.3f？因为你的板子上的 VDDA 大概率不是 3.3V。常见的几种情况：

供电方式典型 VDDA对读数的影响怎么办
USB 5V 经二极管 + LDO3.3V 附近，但随负载变化便宜 LDO 精度 ±2%，读数就有 ±2% 的乘性误差用 VREFINT 反推

顺手一个：芯片温度也能读

F103 内部还有一个温度传感器，接在 ADC1_IN16 上（VREFINT 是 IN17）。换算公式（V25 = 1.43V、斜率 4.3mV/°C 是手册典型值，逐片有偏差，不适合做精密测温）：

它的绝对误差有好几度，但用来做「芯片有没有过热」的判断足够了。

工作模式：单次 / 连续 / 扫描 / 间断

STM32 的 ADC 有四个开关（在 cube 里就是几个复选框），组合出所有常见用法。先把每个开关单独搞清楚：

模式行为寄存器位适合什么场景注意
单次转换触发一次，转完整个序列（或序列里的第一个）就停默认（CONT = 0）按键检测、开机自检、低频监测每次都要重新启动，别指望它自己循环
连续转换转完立刻自动开始下一轮，不停ADC_CR2 的 CONT = 1连续采集、示波器式采样必须配 DMA 或及时读 DR，否则数据被覆盖
扫描模式一次触发把整个序列（最多 16 个通道）依次走完ADC_CR1 的 SCAN = 1多通道轮询（3 路传感器一起读）开了扫描就必须配 DMA，否则只剩最后一个通道的数
间断模式每次触发只转 n 个通道（n = 1~8），下一次触发接着往下走ADC_CR1 的 DISCEN = 1 + DISCNUM想分批处理、或每步之间要做别的事触发次数要算清楚，很容易漏读通道

还有一个比模式更容易被忽视的问题：谁来触发转换？

触发源怎么用采样间隔准不准典型用途
软件触发代码里写 ADC_CR2 的 SWSTART，或在 CubeMX 里选 Regular Conversion launched by software不准低频监测、按需测量（在中断或主循环里随时发起）
定时器 TRGOTIMx 的 TRGO 输出接到 ADC 的 EXTTRIG，选对应的 EXTSEL 值很准（硬件触发，无软件抖动）需要等间隔采样的场合：波形采集、振动分析、功率计算
外部引脚 / EXTI外部信号边沿触发转换取决于信号本身与外部事件同步（比如编码器过零、外部时钟沿）

「为什么我采的波形频率总在抖？」

如果你用软件触发 + HAL_Delay() 或者主循环里裸采，采样间隔会随程序执行时间、中断、RTOS 调度而抖动。做 FFT 时这种抖动会让频谱变糊、噪声底抬高。

正确做法：用定时器的 TRGO 硬件触发 ADC。定时器的周期由时钟精确决定，抖动只有纳秒级 —— 这就是前面讲的「孔径抖动」在单片机里的工程对应物。

规则组与注入组的分工

STM32 的 ADC 有两套完全独立的转换序列，这是它比很多单片机灵活的地方：

对比项规则组（Regular）注入组（Injected）
通道数最多 16 个最多 4 个
数据放哪共用一个 ADC_DR（所以必须配 DMA，否则互相覆盖）各有独立寄存器 ADC_JDR1~JDR4（不会覆盖）
能否打断对方会被注入组打断可以打断规则组（像中断一样）
触发方式软件 / 定时器 / 外部软件 / 定时器 / 外部，可独立配置
典型用途常规多通道轮询采集需要「精确时刻 + 优先处理」的关键量

注入组最经典的用法：电流采样

电机 FOC 控制里，电流必须在 PWM 的中央对齐时刻采样（此时开关噪声最小）。做法是把电流通道配成注入组，用定时器的另一个 TRGO 触发它 —— 规则组继续慢悠悠地采温度、母线电压，注入组则在每个 PWM 周期精确地插进来采一次电流，采完直接进 JDR，不占用 DMA 通道，也不会被规则组的数据覆盖。

这是「规则组干粗活、注入组干精密活」的典型分工。如果你只用规则组 + DMA 去做这件事，会发现电流数据里混着别的通道，时序也对不上。

多通道必须配 DMA

这是初学者最常踩的坑，没有之一。原因很简单：规则组的所有通道共用一个 ADC_DR。扫描模式下，硬件转完通道 1 就把结果写进 DR，转完通道 2 又写进同一个 DR —— 前一个数就被覆盖了。

  扫描序列：IN0 → IN1 → IN2 → IN17

   t1: 转完 IN0，ADC_DR = IN0 的值      ← 你的代码还没读到
   t2: 转完 IN1，ADC_DR = IN1 的值      ← IN0 的值被覆盖了！
   t3: 转完 IN2，ADC_DR = IN2 的值      ← IN1 也没了
   t4: 转完 IN17，ADC_DR = IN17 的值
   t5: 你的 while 循环终于来读 DR       ← 只读到 IN17

   结果：三个外部通道一个都读不到，只拿到 VREFINT。
        （或者运气好读到几个，但通道顺序是错的 —— 更坑，
          因为数据看着"有值"，你会以为是传感器的问题）

   配了 DMA 之后：
       每次 EOC 自动把 DR 搬到一个数组里，一个都不丢：
       adc_raw[0] = IN0, adc_raw[1] = IN1, adc_raw[2] = IN2, adc_raw[3] = IN17
       CPU 完全不参与搬运。
DMA 配置项必须怎么配配错的后果
外设地址（CPAR）&ADC1->DR（数据寄存器）搬错地方，数据全是垃圾
内存地址（CMAR）你的数组首地址，如 adc_raw—
传输方向外设 → 内存反过来会把内存写进 ADC
数据宽度必须 Half Word（16 位）配成 Byte 会只搬低 8 位，高 4 位永远丢失 —— 读数最大只有 255！

上电校准与过采样

SAR 型 ADC 内部是一堆电容组成的 DAC 阵列，电容之间总有微小失配，会让转换结果带一个固定的失调。厂家提供了一个自校准功能：硬件会自己去测这个失调并把它减掉。

   ① 打开 ADC 时钟、配好 ADCPRE（12MHz）
   ② 置 ADON = 1 打开 ADC
   ③ 等 t_STAB 稳定（约 1us）
   ④ 启动校准：置 CAL = 1（HAL 里是 HAL_ADCEx_Calibration_Start）
        · 启动前若不确定，先置 RSTCAL = 1 复位校准寄存器
        · 校准过程约 83 个 ADC 周期（手册值），期间不能启动转换
        · 轮询等待 CAL 位被硬件清 0
   ⑤ 校准完成，开始正式转换

   ★ 为什么必须在【上电后、任何转换之前】做？
     校准是在特定条件下做的一次"零点测量"，
     转换中途做会让时序乱掉、数据错乱。
     官方例程里就一句话：上电 → 校准 → 再开始采。

   ★ 首次转换的数据建议丢弃：校准刚结束，第一个结果偶尔不准。

校准解决的是系统性失调，解决不了随机噪声。想让读数稳定，靠的是过采样：

过采样倍数等效提升一次读数耗时（按 5.67µs/次）等效采样率适合
1（不平均）—5.67 µs176 kSa/s要速度不要精度
4 倍+1 位22.7 µs44 kSa/s一般滤波
16 倍+2 位90.7 µs11 kSa/s最常见的折中
64 倍+3 位363 µs2.8 kSa/s慢速精密测量（温度、称重）
256 倍+4 位1.45 ms690 Sa/s静态量，几乎不要求速度

过采样前先问一句：噪声是随机的吗？

如果噪声来自「和采样同步的干扰」（最常见的就是采样率恰好是 50Hz 的整数倍，每次都采在工频的同一相位），那么平均 256 次也压不掉它 —— 每一采样到的干扰值都一样，平均值还是那个干扰值。

这种情况要先解决干扰源（硬件滤波、屏蔽、改变采样时刻），而不是靠平均。

PWM + RC 当 DAC 用

STM32F103C8T6 没有 DAC 外设（F4/F7/H7 的部分型号才有）。想输出模拟电压，最省钱的办法就是「PWM + RC 低通滤波」。前面例七已经把数学算透了，这里只说怎么配。

② 换一颗带 DAC 的芯片：F4/F7/H7/L4 的很多型号带 2 路 12 位 DAC，支持定时器触发 + DMA 搬运，可以直接输出任意波形（音频、任意函数）。如果你做的项目真的要"输出波形"，一开始选型就该选带 DAC 的型号 —— 这是选型阶段的事，不是软件能补的。

完整代码：多通道 ADC + DAC 输出

下面是两段可以直接放进工程里的代码。第一段是「多通道 ADC + DMA + VREFINT 校准 + 过采样 + 电压换算」的完整流程，第二段是「PWM 模拟 DAC」的完整实现。都按 F103 + HAL 库写，关键处都有中文注释说明为什么这么写。

/* ============================================================
 * STM32F103 + HAL：多通道 ADC + DMA + 真实电压换算
 *   ADC1 规则组顺序：IN0(PA0) -> IN1(PA1) -> IN2(PA2) -> IN17(VREFINT)
 *   触发源：TIM3 的 TRGO（硬件等间隔触发，无软件抖动）
 *   DMA1_Channel1：循环模式，每轮搬 4 个半字
 *   前提：RCC_CFGR 的 ADCPRE = /6（ADC 时钟 12MHz，不超过 14MHz 上限）
 * ============================================================ */
#include "main.h"

extern ADC_HandleTypeDef hadc1;
extern TIM_HandleTypeDef htim3;

#define ADC_CH_NUM        4u            /* 3 个外部通道 + 1 个内部 VREFINT */
#define ADC_IDX_VREFINT   3u            /* VREFINT 在缓冲区里的下标 */
#define VREFINT_CAL_ADDR  0x1FFFF7BAu   /* F103 出厂校准值的存放地址 */
#define VREFINT_CAL_VDD   3.300f        /* 出厂校准时的 VDDA */
#define OVERSAMPLE_N      16u           /* 过采样倍数：16 倍约提升 2 位 */

static uint16_t adc_raw[ADC_CH_NUM];    /* DMA 的目标缓冲区 */
static volatile uint8_t adc_frame_ready;/* DMA 回调里置位：一轮搬完了 */
static float vdda_real = VREFINT_CAL_VDD;

/* ---------- ① 由出厂校准值反推真实 VDDA ---------- */
static float ADC_GetRealVdda(void)
{
    const uint16_t cal = *(volatile uint16_t *)VREFINT_CAL_ADDR;
    uint32_t sum = 0u;
    uint32_t raw;

    if (cal == 0u || cal == 0xFFFFu) {
        return VREFINT_CAL_VDD;         /* 校准值无效，退回标称 3.3V */
    }

    HAL_ADC_Start_DMA(&hadc1, (uint32_t *)adc_raw, ADC_CH_NUM);
    for (uint32_t frame = 0u; frame < 32u; frame++) {
        HAL_Delay(1);                   /* 攒够几十帧，每帧都刷新 VREFINT */
        sum += adc_raw[ADC_IDX_VREFINT];
    }
    HAL_ADC_Stop_DMA(&hadc1);

    raw = sum / 32u;                    /* 平均，压掉随机噪声 */
    if (raw == 0u) {
        return VREFINT_CAL_VDD;         /* 保护：避免除零 */
    }
    return VREFINT_CAL_VDD * (float)cal / (float)raw;
}

/* ---------- ② 码值 -> 电压（浮点，读数少时用） ---------- */
static inline float ADC_RawToVolt(uint16_t raw)
{
    return (float)raw * vdda_real / 4095.0f;    /* 工程口径：除以 4095 */
}

/* ---------- ③ 码值 -> 毫伏（整数，高频调用用） ---------- */
static inline uint32_t ADC_RawToMilliVolt(uint16_t raw)
{
    const uint32_t vdda_mv = (uint32_t)(vdda_real * 1000.0f + 0.5f);
    return ((uint32_t)raw * vdda_mv + 2047u) / 4095u;   /* +2047：四舍五入 */
}

/* ---------- ④ 软件过采样：同一通道连采多次求平均 ---------- */
static uint16_t ADC_ReadAveraged(uint8_t idx)
{
    uint32_t sum = 0u;

    for (uint32_t i = 0u; i < OVERSAMPLE_N; i++) {
        sum += adc_raw[idx];            /* DMA 在后台不断刷新这个值 */
        HAL_Delay(1);                   /* 让 DMA 至少换过一帧新数据 */
    }
    /* 12 位 x 16 次最大 65520，用 uint32 绝不会溢出 */
    return (uint16_t)(sum / OVERSAMPLE_N);
}

/* ---------- ⑤ 主流程 ---------- */
int main(void)
{
    HAL_Init();
    SystemClock_Config();               /* 72MHz；ADCPRE 必须是 /6 */
    MX_GPIO_Init();
    MX_DMA_Init();                      /* 注意：DMA 必须比 ADC 先初始化 */
    MX_ADC1_Init();
    MX_TIM3_Init();

    /* 上电必须先校准：把电容阵列的失配造成的失调测出来并减掉 */
    if (HAL_ADCEx_Calibration_Start(&hadc1) != HAL_OK) {
        Error_Handler();
    }

    vdda_real = ADC_GetRealVdda();      /* 约 30~40ms，开机做一次即可 */

    HAL_TIM_Base_Start(&htim3);         /* TIM3 的 TRGO 开始触发 ADC */
    HAL_ADC_Start_DMA(&hadc1, (uint32_t *)adc_raw, ADC_CH_NUM);

    while (1) {
        if (adc_frame_ready) {          /* DMA 回调置位：新的一帧到了 */
            adc_frame_ready = 0u;
        }

        uint16_t r0 = ADC_ReadAveraged(0);      /* PA0 上的传感器 */
        uint16_t r1 = ADC_ReadAveraged(1);      /* PA1 */
        uint16_t r2 = ADC_ReadAveraged(2);      /* PA2 */

        uint32_t mv0 = ADC_RawToMilliVolt(r0);
        uint32_t mv1 = ADC_RawToMilliVolt(r1);
        uint32_t mv2 = ADC_RawToMilliVolt(r2);

        (void)mv0; (void)mv1; (void)mv2;        /* 实际项目：送显示/上传/控制 */
        HAL_Delay(100);
    }
}

/* ---------- ⑥ DMA 搬完一整轮的回调 ---------- */
void HAL_ADC_ConvCpltCallback(ADC_HandleTypeDef *hadc)
{
    if (hadc->Instance == ADC1) {
        adc_frame_ready = 1u;           /* 4 个通道都刷新了 */
    }
}

这段代码里几个容易忽略的点

① 为什么 VREFINT 要放在规则组里一起采？因为它也会被 DMA 自动搬走，不需要单独启动一次转换；而且它和外部通道在同一个序列里，采集条件一致，反推出来的 VDDA 更可信。

② 为什么 ADC_ReadAveraged 里用 HAL_Delay(1)？因为 DMA 在后台刷新数组，你要给它时间换一帧新数据。如果采样由 TIM3 触发且间隔是 100µs，那就等更短的时间（可以用标志位而不是 HAL_Delay）。

③ VREFINT 的采样时间要够长。CubeMX 里给 VREFINT（IN17）单独设 239.5 周期（19.96µs），手册要求内部通道采样时间不小于 5.1µs；外部通道可以另设 13.5 周期。

④ 过采样不等于滤波。它压的是随机噪声；如果读数是「有规律地跳」（比如跟着电机转），先查干扰源和接地，别指望平均。

/* ============================================================
 * 用 TIM2_CH1 的 PWM + RC 滤波，替代 DAC 输出模拟电压
 *   目标：0 ~ 3300mV 可调，等效分辨率约 9.5 位
 *   时钟：72MHz，PWM 频率 100kHz -> PSC = 0, ARR = 719
 *   硬件：TIM2_CH1(PA0) -> 270Ω -> 10µF -> 电压跟随器 -> 负载
 *   （输出必须加跟随器：270Ω 的源阻抗接 10kΩ 负载会掉 88mV！）
 * ============================================================ */
#include "main.h"

extern TIM_HandleTypeDef htim2;

#define PWM_ARR        719u         /* 自动重装值：占空比 720 级 */
#define PWM_FREQ_HZ    100000u      /* PWM 频率 = 72MHz / (ARR + 1) */
#define PWM_R_OHM      270u         /* 滤波电阻 */
#define PWM_C_UF       10.0f        /* 滤波电容（µF） */
#define PWM_VDD_MV     3300u        /* 供电电压：它的稳定度直接决定输出精度 */

/* ---------- 毫伏 -> 比较值：这就是"用 PWM 做 DAC"的核心计算 ---------- */
static uint16_t PWM_CalcCcr(uint32_t mv)
{
    uint32_t ccr;

    if (mv >= PWM_VDD_MV) {
        return PWM_ARR;                     /* 上限保护：不能超过 ARR */
    }
    /* duty = mv / VDD；比较值 = duty x (ARR + 1) */
    ccr = (mv * (PWM_ARR + 1u)) / PWM_VDD_MV;
    return (uint16_t)(ccr > PWM_ARR ? PWM_ARR : ccr);
}

/* ---------- 设定输出（单位：毫伏） ---------- */
void PWM_DacSetMilliVolt(uint32_t mv)
{
    __HAL_TIM_SET_COMPARE(&htim2, TIM_CHANNEL_1, PWM_CalcCcr(mv));
}

/* ---------- 输出纹波与建立时间自检（设计阶段算一次） ---------- */
void PWM_DacSelfCheck(void)
{
    const float rc     = (float)PWM_R_OHM * PWM_C_UF * 1e-6f;       /* 2.7ms */
    const float ripple = 3.3f * 0.25f / ((float)PWM_FREQ_HZ * rc);  /* 最坏 D=0.5 */
    const float settle = rc * 7.62f;    /* 稳定到 ±0.5LSB 需要 7.62 个时间常数 */
    const float rate   = 1.0f / settle; /* 最高更新率 */

    (void)ripple; (void)rate;   /* 调试时打印：应得约 3.06mV 和约 51Hz */
}

/* ---------- 例：慢速正弦输出（更新间隔必须大于建立时间） ---------- */
void PWM_DacDemoSlowSine(void)
{
    /* 16 点正弦表：中心 1650mV，幅度 1000mV（0.65V ~ 2.65V） */
    static const uint16_t sine_mv[16] = {
        1650u, 2033u, 2357u, 2574u, 2650u, 2574u, 2357u, 2033u,
        1650u, 1267u,  943u,  726u,  650u,  726u,  943u, 1267u
    };

    for (uint32_t i = 0u; i < 16u; i++) {
        PWM_DacSetMilliVolt(sine_mv[i]);
        HAL_Delay(25);      /* 25ms 一步：16 步 = 400ms 一个周期 = 2.5Hz */
    }
    /* ★ 这个例子说明了 PWM+RC 的极限：
     *   一个周期只能放 16 个点，且每步 25ms 只是勉强大于 19.6ms 的建立时间，
     *   波形会滞后、幅度会缩水。
     *   想输出更快的波形（音频、任意波形），必须换带 DAC 的芯片。
     */
}

如果不想用 HAL 库，或者想搞清楚 CubeMX 到底替你写了什么，下面这段纯寄存器初始化很有帮助 —— 它把「时钟、序列、采样时间、校准」四件事一次做完：

/* 纯寄存器配置 ADC1：4 个通道、扫描 + DMA、内部通道长采样 */
static void ADC1_RegisterInit(void)
{
    /* ---- ① 时钟：PCLK2 72MHz / 6 = 12MHz（不超过 14MHz 上限） ---- */
    RCC->APB2ENR |= RCC_APB2ENR_ADC1EN;
    RCC->CFGR &= ~RCC_CFGR_ADCPRE;         /* 先清零分频位 */
    RCC->CFGR |=  RCC_CFGR_ADCPRE_DIV6;     /* 再写入 /6 */

    /* ---- ② 工作方式：扫描模式 + DMA，软件触发 ---- */
    ADC1->CR1 = ADC_CR1_SCAN;               /* 一次触发走完整个序列 */
    ADC1->CR2 = ADC_CR2_EXTSEL |            /* EXTSEL = 111：SWSTART */
                ADC_CR2_EXTTRIG |           /* 允许外部(软件)触发 */
                ADC_CR2_DMA;                /* ★ 别忘这一位，否则 DMA 不动 */
    /* 如果要定时器触发：EXTSEL 改成 T3_TRGO 对应的值（0b100） */

    /* ---- ③ 规则组序列：IN0 -> IN1 -> IN2 -> IN17，共 4 个 ---- */
    ADC1->SQR1 = (3u << 20);                /* L = 3 表示 4 个转换 */
    ADC1->SQR2 = 0u;
    ADC1->SQR3 = (0u) | (1u << 5) | (2u << 10) | (17u << 15);
    /* SQR3 里每 5 位放一个通道号：SQ1 在 bit0，SQ2 在 bit5，依此类推 */

    /* ---- ④ 采样时间：外部通道 55.5 周期，内部通道 239.5 周期 ---- */
    ADC1->SMPR2 = (5u) | (5u << 3) | (5u << 6);   /* SMP0~SMP2 = 101 */
    ADC1->SMPR1 = (7u << 21);               /* SMP17 = 111（通道 17 的位域） */

    /* ---- ⑤ 打开 ADC，等稳定后再校准 ---- */
    ADC1->CR2 |= ADC_CR2_ADON;              /* 上电 */
    for (volatile uint32_t i = 0u; i < 1000u; i++) { }   /* 等 t_STAB(约 1us) */

    ADC1->CR2 |= ADC_CR2_RSTCAL;            /* 复位校准寄存器 */
    while (ADC1->CR2 & ADC_CR2_RSTCAL) { }  /* 等硬件清 0 */
    ADC1->CR2 |= ADC_CR2_CAL;               /* 启动校准（约 83 个 ADC 周期） */
    while (ADC1->CR2 & ADC_CR2_CAL) { }     /* 等硬件清 0 */

    ADC1->CR2 |= ADC_CR2_ADON;              /* 部分型号需要再写一次才真正启动 */
}

最后提醒一句：ADC 的精度是「系统级」问题

软件做对了，也只是把芯片的能力发挥出来。要让 12 位真的变成 12 位，硬件上还得做这些事：模拟电源加 LC/RC 滤波并单独走线、VDDA 与 VSSA 就近去耦（100nF + 1µF）、模拟地与数字地单点相连、采样点尽量靠近芯片引脚、远离 PWM 和电机驱动走线。

这也是为什么很多「ADC 读数跳动」的问题，改代码改不出来 —— 它根本不是代码的问题。

常见误解与坑

下面这十条，每一条都是「听起来很有道理，但会让你在实验室里耗掉一整天」的那种。每一条都按「错误认知 → 为什么错 → 正确做法」写清楚，建议你在动手接传感器之前先扫一遍。

坑 1 ·「ADC 是 12 位，所以测出来就是 12 位精度」

错在哪：12 位说的是分辨率（能分出多少个台阶），不是精度（离真值有多远）。实际精度被噪声、INL、失调、增益误差和基准漂移一起决定，还要被 VDDA 不准再砍一刀。

正确做法：按 ENOB 估实际能力（F103 的 12 位 ADC 实际约 10 位有效，3.3V 下能稳定分辨的电压约 3mV，不是 0.8mV）；要绝对精度就先解决基准，再谈别的。

坑 2 ·「读数跳动，多平均几次就好了」

错在哪：平均只能压掉随机噪声。如果干扰和采样同步（最典型的是采样率恰好是 50Hz 的整数倍，每次采样都落在工频的同一相位），平均 256 次之后那个干扰纹丝不动。

正确做法：先看跳动的规律：随机的用平均（过采样）；有规律的查干扰源（共地、屏蔽、电源去耦、走线远离 PWM）；周期性的改变采样时刻或做整周期采样。

坑 3 ·「先采进来，混叠了再用数字滤波滤掉」

错在哪：混叠是多对一的映射，一旦发生，1800Hz 和 200Hz 在数据里完全一样，任何算法都分不出来。数字滤波救不回已经混叠的成分，它只能滤掉你还认识的东西。

正确做法：抗混叠滤波器必须放在 ADC 之前（模拟侧），而且要按「在 (f_s − f_max) 处衰减到量化噪声底以下」来定阶数和截止频率。

坑 4 ·「采样率只要大于信号频率的 2 倍就够了」

错在哪：fs ≥ 2·f_max 是理论上不丢信息的下限，前提是信号里完全没有超过 f_max 的成分 —— 而现实信号里总有。刚好踩在 2 倍上，滤波器需要接近理想（做不到），而且没有给时钟抖动、抗混叠过渡带留任何余量。

正确做法：工程上取 5~10 倍。余量越大，抗混叠滤波器越好做（可以从四阶降到二阶），代价只是数据量 —— 而数据量在今天的单片机上是便宜的。

坑 5 ·「在 ADC 输入脚前面并一个大电容，读数就更稳了」

错在哪：大电容（比如 100nF）和内部采样电容 C_ADC 之间会发生电荷分享。多通道扫描时更糟：这个电容会把前一个通道的电压「记住」并带到下一个通道，制造出查不出来的串扰鬼影。

正确做法：源阻抗大的时候在信号源后加电压跟随器（把源阻抗降到 1Ω 以下）；确实要加 RC 抗混叠，电容取 1nF~10nF 量级并相应加长采样时间。

坑 6 ·「ADC 校准可做可不做，反正误差很小」

错在哪：SAR 内部的电容阵列失配会带来一个固定的失调，不校准的话这个偏置会一直加在你的每一个读数上，而且它随温度变。你以为的「传感器不准」，很可能就是它。

正确做法：上电后、任何转换之前，固定跑一次校准（约 83 个 ADC 周期，几微秒的事），并丢弃校准后的第一个数据。

坑 7 ·「输入电压超过 VDDA 一点点没关系」

错在哪：引脚内部的保护二极管会导通并把电流灌进 VDDA 网络，轻则读数被钳在 4095、污染整块板的模拟电源，重则引脚损坏。5V 传感器直接接 ADC 引脚是最常见的翻车方式。

正确做法：先分压或用运放做电平转换，保证任何情况下 ≤ VDDA；再串一个限流电阻（1kΩ 量级）+ 对地的小电容做保护；量程也别浪费，能选到接近满量程的档位最好。

坑 8 ·「DAC 的单调性不重要，反正不要求多准」

错在哪：在闭环控制里，非单调会直接变成正反馈：控制器输出增大、被控量反而减小，PI 的积分项会一路积分到饱和，系统跑飞或自激振荡。这类故障看起来像「参数没调好」，其实是器件特性。

正确做法：闭环或需要寻优的场合，选手册上写明「guaranteed monotonic over temperature」的 DAC；对毛刺敏感的场合加去毛刺电路或选带去毛刺的型号。

坑 9 ·「多通道 ADC 在循环里轮询读 DR 就行，不用上 DMA」

错在哪：规则组所有通道共用 ADC_DR，硬件转下一个通道时会直接把上一个覆盖掉。你可能只读到最后一个通道的值，也可能读到错位的数据 —— 后者更坑，因为「看着有值」。

正确做法：扫描模式一定配 DMA（循环模式、传输宽度 Half Word、ADC_CR2 的 DMA 位置 1）；单通道单次转换才值得用轮询。

坑 10 ·「PWM + RC 可以完全替代 DAC，做音频也没问题」

错在哪：为了压纹波必须把 RC 时间常数做大，而时间常数一大建立时间就长（典型值算出来 19.6ms，更新率只有约 51Hz）。同时，PWM 频率越高占空比级数越少，分辨率跟着掉 —— 频率、分辨率、响应速度三者是死结。

正确做法：慢速设定值（温控、调光、偏置）放心用 PWM + RC；要输出波形就在选型阶段选带 DAC 的型号（F4/F7/H7/L4 的很多型号有），或者外接 DAC 芯片。

小结与自检

这一篇从「为什么需要数据转换」一路走到 STM32 的寄存器和代码，把两个世界之间的翻译官拆开看了一遍。要点如下：

  • 为什么要转换：真实世界连续，CPU 只认 0/1。ADC 把连续量翻译成码值，DAC 反过来。读电位器、读热敏电阻、测电池电压、输出波形、控制电流，背后都是这两件事。
  • 采样定理：fs ≥ 2·f_max 是无失真采样的下限，采样率越高越好做抗混叠。混叠是多对一映射，信息永久丢失 —— 用 1kHz 采 1800Hz 会读成 200Hz，而且这个假信号看起来非常合理。
  • 抗混叠滤波器必须在 ADC 之前：它和数字滤波的本质区别是「在采样之前把不认识的频率拿掉」；采样之后再滤，混叠的成分已经变成了低频，滤不掉了。
  • 量化：q = V_FS / 2^N，量化误差 ±q/2。位数每加 1 位，SNR 提高约 6.02 dB（SNR ≈ 6.02N + 1.76 dB）。ENOB = (SNR − 1.76) / 6.02，标称 12 位实际约 10 位是正常现象。
  • 采样保持：转换期间必须把电压冻住。孔径时间决定能采多快的信号，孔径抖动决定高频下的信噪比（ΔV = 2πfA·t_j）。
  • 四类 ADC：SAR 快而通用（单片机主流，N 位 N 次比较）；双积分慢而准、抗工频（面板表）；Flash 最快最贵（高速示波器、流水线型 ADC）；Σ-Δ 位数最高但只能做低速（称重、温度、音频）。
  • 指标的分工：INL/DNL 描述台阶的「宽度」和「位置」，|DNL| 超过 1 LSB 就会丢码；失调和增益误差可以校准，INL 和基准漂移不能。V_REF 飘 1%，满量程读数就飘 1%（12 位下是 41 个 LSB）。
  • DAC 的两条主线：权电阻网络阻值跨度大难集成；R-2R 只用两种阻值实现二进制加权（任一节点往右看等效 2R），输出 V_out = −V_REF·D/2^N。
  • DAC 指标里最该记住的是单调性和毛刺：非单调在闭环里会变成正反馈；毛刺在 major carry（0111…1 → 1000…0）时最大，最坏能冲到满量程。
  • 在 STM32 上：工作链是「通道选择 → 采样保持 → 逐次逼近 → 数据寄存器 → DMA」；ADC 时钟必须 ≤ 14MHz（72MHz 主频时配 /6 = 12MHz）；源阻抗决定采样时间；多通道扫描必须配 DMA；上电先校准。
  • 读数换算与基准：V = raw × VDDA / 4095；VDDA 不准时用 VREFINT 反推（VDDA = 3.3V × VREFINT_CAL / raw_vrefint）。过采样每 4 倍提升约 1 位有效分辨率，代价是速度。
  • 没有 DAC 时的办法：PWM + RC，按纹波要求反算 RC（f_pwm/f_c ≥ 1.57×2^N），并接受 51Hz 量级的更新率；输出必须加电压跟随器，V_DD 必须稳。

一句话把这篇文章收起来

ADC 的工作是「在正确的时间，用正确的尺子，量一个被冻住的电压」。采样定理管「时间」，基准和 INL 管「尺子」，采样保持管「冻住」，后面所有的代码和寄存器配置，都只是把这三件事落实到硬件上。

自测题（先自己想，再看答案）

1. 用 2kHz 的采样率去采一个 3.2kHz 的正弦波，会读到什么频率？为什么说这个结果「很危险」？

答：混叠频率 f_alias = |3200 − 2000| = 1200Hz，而 1200Hz 超过了奈奎斯特频率 1000Hz，所以还要再折叠一次：|1200 − 2000| = 800Hz。最终读成 800Hz。危险在于：它是一个完全落在可听/可分析范围内的假信号，幅值和真信号一样，看不出任何异常 —— 你会去排查一个根本不存在的 800Hz 振动源。

2. 一个 12 位 ADC，V_REF = 5.000V，输入 3.000V，码值是多少？如果 V_REF 实际是 4.950V（飘了 1%），读出来的码值会变吗？算出来的电压会错多少？

答：LSB = 5/4096 = 1.2207mV，理想码值 = 3.000/1.2207e-3 = 2457.6 → 2458（0x99A）。基准飘 1% 后，硬件按 4.950V 转换：码值 = 3.000/(4.950/4096) = 2482.4 → 2482，码值本身变了（因为 LSB 变了）。如果你还按 5.000V 换算：2482 × 1.2207mV = 3.0299V，比真值 3.000V 大了约 30mV —— 正好是 1% 的乘性误差。这就是「基准决定绝对精度」。

3. 为什么说「DNL 大于 1 LSB 就会丢码」？丢码在什么场合是致命的？

答：因为 2^N 个码的总宽度是守恒的（合起来正好是整个量程）。如果某个码的台阶被撑宽到超过 1 LSB，就必然有别的码被压缩；被压缩到 0 宽度时，那个码值永远不会出现，这就是丢码。致命场合：① 用码值做查表索引或地址；② 闭环控制里码值必须严格对应电压（丢码处会出现控制死区）；③ 逐点扫描标定时会漏掉点。

4. STM32 的 ADC 时钟为什么不能随便配成 PCLK2 的 1/2？配错了会有什么现象？

答：F103 的 ADC 时钟上限是 14MHz，72MHz 主频下 /2 = 36MHz 远超上限，内部逐次逼近逻辑来不及建立，比较结果不可靠。现象是读数恒为 4095、或者随机乱跳、或者同一电压读两次差很多 —— 而且这些现象「看起来像硬件问题」，很容易查错方向。正确做法是 /6 = 12MHz。

5. 一个 10kΩ 的电位器分压直接接到 ADC 引脚，采样时间设成 1.5 个周期，读数会怎么样？怎么解决（给出两种办法）？

答：1.5 周期（125ns）远小于 10kΩ 源阻抗所需的约 854ns，采样电容充不到输入电压，读数会明显偏小，而且随电位器位置（源阻抗变化）而不成比例地偏。解决办法：① 把采样时间加长到 13.5 周期（1.125µs）或更长；② 在电位器输出后加一级运放电压跟随器，把源阻抗降到 1Ω 以下，采样时间就可以用最短档。

6. 为什么 DAC 在 0111…1 变成 1000…0 时毛刺最大？如果要输出一个用于精密偏置的固定电压，你会在意毛刺吗？

答：这个码变（major carry）时所有位同时翻转：低位的开关全部关断、MSB 开通。开关的动作不可能完全同时，如果 MSB 先动（或低位后关断），中间会短暂出现全 1 的状态，输出瞬间冲到接近满量程 —— 一个 12 位 DAC 可能从 1.65V 冲到 3.3V 再回来，然后在后续电路里被采样、被放大、被积起来。固定偏置的场合（输出值一直不变）不在意毛刺，因为根本不发生码变；但在波形输出、闭环扫描、多通道切换的场合必须在意。

动手练习

  1. 量一次自己的 VDDA。用 CubeMX 配一个 ADC1_IN17（VREFINT）通道，采样时间设 239.5 周期，读 32 次求平均，按 VDDA = 3.300 × VREFINT_CAL / raw 反推，再拿万用表量 VDDA 对一下。差值在 20mV 以内，说明你已经掌握这个技巧了。
  2. 用定时器触发 + DMA 采一段波形。把信号发生器接 PA0，TIM3 的 TRGO 触发 ADC，DMA 循环搬 256 个点，通过串口上传到电脑画出波形。然后故意改成软件触发 + 主循环采样，对比两次波形的抖动 —— 你会直观看到「触发源」为什么重要。
  3. 给一个 10kΩ 电位器配采样时间。先按 1.5 周期读一遍，再按 13.5、55.5、239.5 周期各读一遍，把同一个位置的读数记下来。画一条「读数 vs 采样时间」的曲线，验证例二那张表 —— 这是最有说服力的一次实验。
  4. 用 PWM + RC 做一个 0~3V 可调输出。按 100kHz / ARR = 719 配好，用 270Ω + 10µF 滤波，输出接万用表（注意加跟随器或接高阻档）。写下 10 个设定值，记录实测电压和稳定时间，再和例七算出来的 3.06mV 纹波、19.6ms 建立时间对一下。
  5. 算一次你自己的误差预算。假设你的系统要测 0~3V、要求误差小于 1%：把量化误差、VDDA 偏差、INL（查手册）、失调（校准后）、噪声（实测峰峰值）各占多少列出来，看看哪一项是瓶颈 —— 大多数人的答案是「VDDA 偏差」，而不是 ADC 本身。
