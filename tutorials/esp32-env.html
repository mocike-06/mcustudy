原理介绍

环境搭建这件事，新手最容易把它当成「照着一二三点点点」的机械操作， 于是只要中间有一步和教程不一样，就完全不知道该怎么办。 这一节先把背后的机制讲明白：Arduino IDE 本身只是一个编辑器加一个调度器， 真正把 C++ 代码变成 ESP32 能执行的二进制文件的，是一整套外部的交叉编译工具链。 装开发板包，本质上就是把这套工具链装到你的电脑上。

为什么 ESP32 要额外装包

Arduino IDE 装好之后，内置只认识 Arduino UNO、Nano 这类 AVR 芯片。 ESP32 用的是 Xtensa LX6 双核处理器， 和 AVR 是完全不同的指令集，编译器、链接脚本、启动代码、烧录工具、Wi-Fi 协议栈全都不一样。 所以 IDE 需要一张「开发板清单」告诉它：去哪儿下载 ESP32 专用的工具链、下载哪个版本。

Arduino 官方只维护 AVR 系列，ESP32 的这张清单由乐鑫（Espressif）自己维护， 地址就是下面这一串。把它填进 IDE，IDE 才知道「esp32 by Espressif Systems」这个包的存在： 

https://espressif.github.io/arduino-esp32/package_esp32_index.json

这个 JSON 文件里并没有工具链本身，它只是一张「目录」：里面写着各个版本的核心包下载地址、 对应平台（Windows / macOS / Linux）、以及每个版本的校验值。IDE 拿到目录后， 再去真正的下载地址把几百 MB 的工具链拉下来。所以你会看到安装过程分两段—— 先是几秒的「正在下载索引」，然后是漫长的「正在下载 esp32 核心」。

国内网络下这一步几乎一定会失败

索引文件本身托管在 GitHub Pages 上，工具链压缩包托管在 GitHub Releases 上。 国内直连经常出现「下载索引卡住」「下到 60% 断了」这类现象， 这不是你的操作错了，而是网络问题。 解决办法有两个，见下面 IDE 版本选择与国内镜像。

一行代码从 IDE 到芯片

点一下「上传」按钮之后，电脑里其实发生了一连串动作。理解这条链路， 后面排错时你就知道每一步该看什么信息： 

  ┌─────────────────────────────────────────────────────────────────┐
  │ 1. 预处理   .ino -> .ino.cpp                                     │
  │    自动补上 #include <Arduino.h>，把函数原型提到文件顶部          │
  ├─────────────────────────────────────────────────────────────────┤
  │ 2. 编译     .cpp -> .o                                           │
  │    编译器：xtensa-esp32-elf-g++（ESP32 专用交叉编译器，跑在 PC 上）│
  ├─────────────────────────────────────────────────────────────────┤
  │ 3. 链接     .o + 核心库 + Wi-Fi/BT 协议栈 -> sketch.ino.elf      │
  │    这一步最占内存、也最慢，第一次编译要 1~3 分钟                   │
  ├─────────────────────────────────────────────────────────────────┤
  │ 4. 打包     .elf -> .bin（合并 bootloader / 分区表 / 应用程序）    │
  │    工具：esptool.py，同时负责计算 Flash 里的写入地址               │
  ├─────────────────────────────────────────────────────────────────┤
  │ 5. 烧录     通过 USB 转串口，把 .bin 写进 Flash                    │
  │    esptool 先拉低 EN 让芯片进入下载模式，写完再复位                │
  ├─────────────────────────────────────────────────────────────────┤
  │ 6. 运行     ROM 引导程序 -> bootloader -> 你的 setup() / loop()    │
  └─────────────────────────────────────────────────────────────────┘

看懂第 5 步，就理解了新手最常见的一个坑：ESP32 的串口是一根线两用—— 平时它是你的程序打印日志的通道，上传时它又被 esptool 借去当下载通道。 esptool 需要让芯片进入「下载模式」才能写 Flash，而进入下载模式靠的是把 GPIO0 拉低再复位。板子上做了自动复位电路来自动完成这个动作， 但电路偶尔会失效——这时候就要你手动按住 BOOT 键， 这就是「一直显示 Connecting」的根因。

IDE 版本选择与国内镜像

写 ESP32 只需要一个软件，但版本选错会平白多出一堆麻烦。先把选型结论给出：

方案 版本要求 优点 注意
Arduino IDE 2.x 2.3.x 及以上 自动补全、串口绘图器、内置开发板管理器界面 本教程以它为准
Arduino IDE 1.8.x 1.8.19 体积小、启动快，老教程截图一致 新版 ESP32 核心需要手动改 Java 堆内存，否则编译报内存不足
arduino-cli 1.0+ 命令行、可写脚本、适合批量编译 需要自己会看命令行报错
VS Code + PlatformIO PlatformIO 6.x 工程管理最规范，库依赖可锁定版本 调试信息是英文，初学阶段容易迷路

关于国内网络，有两个成熟做法，推荐先用第一种，改配置文件的思路以后一直用得上：

  • 方法一：给 Arduino IDE 配代理。 在 IDE 的「文件 → 首选项 → 网络」里填入本机 HTTP 代理地址 （例如 http://127.0.0.1:7890）。 这样索引和工具链都走代理，最省事，也不需要改代码。
  • 方法二：手动替换下载源。 把开发板管理器网址里的域名换成国内镜像（如清华 TUNA、南京大学镜像的 GitHub 反向代理）， 形式通常是把 https://espressif.github.io/arduino-esp32/package_esp32_index.json 换成 https://mirrors.tuna.tsinghua.edu.cn/... 之类的镜像地址。 镜像会同步官方索引，但同步有延迟， 所以经常会遇到「最新版本在镜像里还搜不到」——这不是故障，等一天或换回官方源即可。
  • 兜底方案：手动离线安装。 用浏览器或下载工具把 .zip 形式的 esp32 核心包下载到本地， 再在 IDE 里用「导入 .zip 库」的方式装进去。慢但一定能成， 适合机房、实验室这种统一环境。
装哪个版本的核心？

开发板管理器列表里会列出十几个 esp32 版本。给新手的建议是 选列表里最新的稳定版（写这段时的主流是 3.x 系列）， 不要为了「和某篇老教程一致」去装 1.0.x。 老版本缺少新芯片支持、Wi-Fi 库有已知问题，而且很多现在的示例代码编译不过。 唯一例外是老师明确要求统一版本，那就全组统一，别各装各的。

硬件接线说明

这一篇不需要面包板和外设，唯一的「接线」就是把开发板用 USB 线接到电脑上。 但恰恰是这根线和板子上那两个小按键，制造了新手 80% 的失败。 所以这一节要把板子上的每一个接口、每一个按键都交代清楚。

开发板接口与两个按键

先记住这一条：GPIO6 ~ GPIO11 绝对不能接任何东西

这六个引脚在模组内部已经连到 SPI Flash 芯片上，用来存放你的程序。 把外部电路接到它们上面，轻则程序跑飞，重则写坏 Flash 让板子再也启动不了。 新手「烧板子」的头号原因就是这个。引脚图上的 GPIO9、GPIO10 之所以还印在排针上， 是因为有些模组没用到它们，但 ESP32-WROOM-32 用满了，你当它们不存在就好。

USB 转串口芯片与驱动

ESP32 芯片本身没有 USB 控制器（那是 S2/S3 才有的事）， 所以开发板上都焊了一颗USB 转串口芯片， 把 USB 协议翻译成串口。它决定了你的电脑能不能看见这个 COM 口， 也决定了你要装哪个驱动。市面上主流就两种：

芯片 常见于 Windows 里显示的设备名 驱动
CP2102 / CP2102N 官方 ESP32-DevKitC、较贵的开发板 Silicon Labs CP210x USB to UART Bridge (COMx) Silicon Labs 官方 VCP 驱动（CP210x Universal Windows Driver）
CH340 / CH340C / CH9102 国产低价开发板、NodeMCU 类板子 USB-SERIAL CH340 (COMx) 沁恒（WCH）官方 CH341SER 驱动
（未装驱动） — 未知设备 / 带黄色感叹号的 USB2.0-Serial 先看芯片丝印，再装对应驱动

怎么知道自己板子上是哪颗？看 USB 座旁边那颗 5 毫米见方的小芯片上的丝印， 或者看板子背面印的型号。实在看不清就用笨办法：先装 CH340 驱动，重插一次看设备管理器里有没有多出 COM 口； 没有就换 CP2102 驱动。两个驱动同时装在电脑里不会冲突。

  1. 装驱动前先把开发板从电脑上拔下来，装完再插上，避免系统缓存了「未知设备」的状态。
  2. 右键「此电脑 → 管理 → 设备管理器」，展开端口 (COM 和 LPT)， 看到一个带 COM 号的设备就说明成功了。
  3. 把开发板拔掉，那个 COM 口会消失；再插上又出现——用这个「一插一拔」的动作确认到底哪个 COM 号是它， 而不是电脑上其他虚拟串口。这一步能省掉后面大量的选错口排错。
上电前必查
  • USB 线是不是数据线。判断方法：插上后设备管理器里有没有新 COM 口，没有就是充电线。
  • 开发板下面有没有压在金属桌面或散落的元件上，排针短路是最冤的故障。
  • 有没有同时接外部 5V 电源和 USB。二者只能选一个。
  • 杜邦线一根都还没接。环境搭建阶段不要接任何外设， 这样出问题时变量最少。

完整代码

环境搭好之后不能只看「编译成功」四个字，那只能说明工具链装对了， 说明不了板型、串口、波特率是否正确。下面这段程序的作用是 把芯片的真实信息打印出来： 只要这些信息正常显示且不乱码，四件事就全部验证通过。 

/* =====================================================================
 *  esp32-env-check.ino —— ESP32 开发环境自检程序
 *  目标板：ESP32 Dev Module（ESP32-WROOM-32）
 *  作用：上传成功后，用串口监视器一次性验证
 *        「开发板包 / 板型 / 串口 / 波特率」四项配置是否正确
 *  波特率：115200（串口监视器右下角必须选同一个值）
 * ===================================================================== */

#include <esp_system.h>   /* 提供 esp_reset_reason()，用来判断上次复位是正常上电还是掉电 */

/* ---------------------------------------------------------------------
 * 把复位原因枚举翻译成中文
 * 为什么值得单独写这个函数：ESP32 供电不足时会自己复位，
 * 现象是「程序刚起来就重启」，而复位原因会明确告诉你是 BROWNOUT
 * ------------------------------------------------------------------- */
const char* resetReasonText(esp_reset_reason_t r) {
    switch (r) {
        case ESP_RST_POWERON:   return "上电复位 / 按了 EN 键（正常）";
        case ESP_RST_EXT:       return "外部复位引脚被拉低";
        case ESP_RST_SW:        return "软件复位（调用了 ESP.restart()）";
        case ESP_RST_PANIC:     return "程序崩溃复位（空指针、数组越界等）";
        case ESP_RST_INT_WDT:   return "中断看门狗复位（中断服务函数里耗时太久）";
        case ESP_RST_TASK_WDT:  return "任务看门狗复位（loop 被阻塞超过 5 秒）";
        case ESP_RST_WDT:       return "其他看门狗复位";
        case ESP_RST_DEEPSLEEP: return "深度睡眠唤醒（正常）";
        case ESP_RST_BROWNOUT:  return "掉电复位：供电不足！换 USB 口或换线";
        case ESP_RST_SDIO:      return "SDIO 复位";
        default:                return "未知原因";
    }
}

void setup() {
    /* ---------- 串口初始化 ----------
     * 115200 是 ESP32 的通用波特率。
     * 注意：这里只是「电脑与开发板之间」的通信速率，
     * 和 Wi-Fi、蓝牙的速率完全无关，改它不会影响无线性能。      */
    Serial.begin(115200);

    /* 这个延时不是可选项：USB 转串口芯片在板子上电后需要一点时间
     * 才会被电脑枚举出来。不加延时，开机头几行字最容易丢失，
     * 新手最常见的误判就是「程序没跑」——其实只是第一行没被收到。 */
    delay(1500);

    Serial.println();
    Serial.println("==================================================");
    Serial.println("          ESP32 环境自检  esp32-env-check");
    Serial.println("==================================================");

    /* ---------- [1] 工具链与核心版本 ----------
     * 这两行能打印出来，就说明「开发板包」装对了。 */
    Serial.println("[1] 工具链 / 核心版本");
    Serial.printf("    Arduino-ESP32 核心 : %s\n", ESP.getCoreVersion().c_str());
    Serial.printf("    ESP-IDF SDK 版本   : %s\n", ESP.getSdkVersion());
    Serial.printf("    本程序编译时间     : %s %s\n", __DATE__, __TIME__);

    /* ---------- [2] 芯片信息 ----------
     * 能读到型号和 Flash 容量，说明 esptool 与芯片通信正常。 */
    Serial.println("[2] 芯片信息");
    Serial.printf("    芯片型号   : %s\n", ESP.getChipModel());
    Serial.printf("    芯片版本   : v%d\n", ESP.getChipRevision());
    Serial.printf("    核心数量   : %d\n", ESP.getChipCores());
    Serial.printf("    CPU 主频   : %d MHz\n", ESP.getCpuFreqMHz());
    Serial.printf("    Flash 容量 : %u 字节（约 %.1f MB）\n",
                  ESP.getFlashChipSize(),
                  ESP.getFlashChipSize() / 1048576.0f);

    /* ---------- [3] 内存 ----------
     * 空闲堆内存是后面写 Wi-Fi / 蓝牙程序时的重要指标：
     * 连上 Wi-Fi 会吃掉约 40KB，开蓝牙又要几十 KB，
     * 堆不够就会出现「莫名其妙连不上、连上就重启」。 */
    Serial.println("[3] 内存");
    Serial.printf("    当前空闲堆 : %u 字节\n", ESP.getFreeHeap());
    Serial.printf("    历史最小堆 : %u 字节\n", ESP.getMinFreeHeap());

    /* ---------- [4] 复位原因 ----------
     * 这是排查「反复重启」问题的第一现场证据。 */
    Serial.println("[4] 本次启动原因");
    Serial.printf("    %s\n", resetReasonText(esp_reset_reason()));

    /* ---------- [5] 芯片唯一 ID ----------
     * 出厂时烧在 eFuse 里的 48 位 MAC，全球唯一、不可修改。
     * 做课设时可以直接拿它当设备编号。 */
    Serial.println("[5] 芯片唯一 ID");
    uint64_t chipId = ESP.getEfuseMac();
    Serial.printf("    MAC 地址 : %04X%08X\n",
                  (uint16_t)(chipId >> 32), (uint32_t)chipId);

    /* ---------- [6] 波特率自检提示 ---------- */
    Serial.println("--------------------------------------------------");
    Serial.println("上面这段文字如果完整显示且不是乱码，");
    Serial.println("说明开发板包、板型、串口、波特率全部配置正确。");
    Serial.println("如果全是乱码，请把串口监视器波特率改成 115200。");
    Serial.println("--------------------------------------------------");
}

void loop() {
    /* 每 2 秒报一次心跳，用来观察内存有没有持续减少（内存泄漏）。
     * 这里用 millis() 做非阻塞定时，而不是 delay(2000)：
     * delay 会让整个 loop 停住，一旦以后加了 Wi-Fi 或按键就会出问题，
     * 从一开始就养成「用时间戳判断」的习惯。 */
    static uint32_t lastTick = 0;              /* static：值在两次 loop 之间保留 */
    if (millis() - lastTick >= 2000) {
        lastTick = millis();
        Serial.printf("[心跳] 已运行 %lu 秒，空闲堆 %u 字节\n",
                      millis() / 1000, ESP.getFreeHeap());
    }
}

关键代码解析

  • #include <esp_system.h>—— Arduino 的 ESP32 核心其实是「ESP-IDF + Arduino 封装层」两层结构， 所有 esp_ 开头的底层功能都在 IDF 的头文件里。 认识这一点很重要：以后你在网上看到的 ESP-IDF 例程，大部分都能直接搬进 Arduino 里用。
  • Serial.begin(115200) 与串口监视器右下角的波特率 必须是同一个数字。 波特率是双方约定的「每秒多少位」，两边不一致时接收方会在错误的时刻采样， 收到的就是一堆乱码。这是新手看到「乱码」时 99% 的原因，不是板子坏了。
  • delay(1500)——新手常把它删掉，然后抱怨「第一行打印丢了」。 USB 转串口芯片上电后要等电脑完成枚举，这期间发出去的数据没人接，直接丢掉。 代价是启动慢 1.5 秒，换来的是每次上电都能看到完整日志，非常划算。
  • ESP.getCoreVersion().c_str()—— getCoreVersion() 返回的是 Arduino 的 String 对象而不是 C 字符串。 printf 的 %s 只认 C 字符串（const char*）， 所以必须调用 .c_str() 转换。漏掉它不会编译报错， 但运行时打印出来是空白或乱码——这是 C++ 里非常典型的「隐式转换陷阱」。
  • esp_reset_reason()——只用一行就能区分「正常上电」 和「供电不足导致的重启」。 如果你看到 掉电复位：供电不足， 就不用再怀疑代码了，直接去换 USB 口、换线、或者给板子单独供电。
  • static uint32_t lastTick—— 在函数里定义的 static 变量只初始化一次， 之后每次进入 loop() 都保留上次的值。 这是嵌入式里实现「定时做某件事」的标准写法， 比 delay() 高一个层次，务必掌握。
用命令行验证环境（可选，但很有用）

如果你装了 arduino-cli，可以不开图形界面就完成同样的验证。 做课设要反复编译时，命令行比点鼠标快得多： 

# 1. 添加 ESP32 开发板索引（只需执行一次）
arduino-cli config init
arduino-cli config add board_manager.additional_urls https://espressif.github.io/arduino-esp32/package_esp32_index.json

# 2. 更新索引并安装 esp32 核心（这一步比较大，耐心等）
arduino-cli core update-index
arduino-cli core install esp32:esp32

# 3. 确认装好了，能列出 ESP32 Dev Module 就说明成功
arduino-cli board listall | grep -i "ESP32 Dev Module"

# 4. 看看开发板插在哪个串口（Windows 上写 COM3 这种，Linux/macOS 写 /dev/ttyUSB0）
arduino-cli board list

# 5. 编译 + 上传（把 PORT 换成上一步查到的串口）
arduino-cli compile --fqbn esp32:esp32:esp32 esp32-env-check
arduino-cli upload  --fqbn esp32:esp32:esp32 -p COM3 esp32-env-check

# 6. 打开串口监视器看输出，波特率必须和 Serial.begin() 一致
arduino-cli monitor -p COM3 --config baudrate=115200

注意第 5 步的 esp32:esp32:esp32 就是 「ESP32 Dev Module」在命令行里的正式编号（FQBN）。 图形界面里选板型和这里是同一件事。

常见报错排查方案

下面五条覆盖了环境搭建阶段 95% 的失败情况。 每条都按「报错原文 → 原因 → 解决」写，方便你直接把报错复制去搜索。

报错原文：A fatal error occurred: Failed to connect to ESP32: Timed out waiting for packet header

原因： esptool 反复发送同步命令，但芯片一直没回应。最常见的原因是芯片没进入下载模式—— 自动复位电路（靠串口的 DTR/RTS 两根线控制 EN 和 GPIO0）在部分板子、部分驱动版本上不能可靠工作。 其次是串口被别的程序占着（串口监视器自己没关、另一个 IDE 窗口还开着、手机助手类软件后台挂着）。

解决： 先把所有可能占用串口的程序关掉。然后按这个动作重来一次： 按住 BOOT 键不放 → 点 IDE 的上传按钮 → 等输出窗口出现 Connecting........ 时松开 BOOT 键。 如果还不行，就改成：按住 BOOT → 按一下 EN → 松开 EN → 点上传 → 松开 BOOT。 另外确认「工具 → 上传速度」是 921600 或 115200， 有些劣质 USB 线跑不了 921600，把它降到 115200 往往立刻就好了。

报错原文：Error downloading https://espressif.github.io/arduino-esp32/package_esp32_index.json （或进度条卡在某个百分比不动）

原因： 纯网络问题。这个索引和后面的工具链都托管在 GitHub 上，国内直连不稳定。 表现有三种：索引拉不下来、工具链下到一半断了、装完但显示「安装失败」。 不是你哪里点错了，重复点几次也可能碰巧成功，但那不是解决办法。

解决： 优先用「文件 → 首选项 → 网络 → 代理」填本机代理地址（如 http://127.0.0.1:7890），然后重启 IDE 再装。 没有代理就把网址换成国内镜像（清华 TUNA 等镜像站有 GitHub 反向代理）， 注意镜像同步有延迟，最新版可能搜不到，那就装次新的稳定版。 实在不行走离线包：用下载工具下好 esp32 核心的 .zip， 在 IDE 里「导入 .zip 库」。 还有一个隐藏坑：在校园网 / 公司网络下，代理设置会被系统代理覆盖， 如果填了代理仍然失败，试着用手机热点验证一下是不是网络环境的问题。

报错原文：工具 → 端口 菜单是灰色的，或者设备管理器里出现带黄色感叹号的「未知设备 / USB2.0-Serial」

原因： 电脑没有识别到板载的 USB 转串口芯片。三种可能： 驱动没装（最常见）、用的是纯充电线（线里只有电源两根芯，没有数据芯）、 或者 USB 口供电不足导致枚举失败。

解决： 第一步换一根线——必须是你确定传过文件的线，这一条能排掉近一半的问题。 第二步换 USB 口，优先机箱后面板直出的口。 第三步装驱动：看 USB 座旁边芯片的丝印， CP2102 就装 Silicon Labs 的 CP210x 驱动， CH340 / CH9102 就装沁恒的 CH341SER 驱动， 装之前先拔掉板子，装完再插。装上后设备管理器里会出现 端口 (COM 和 LPT) 分类，里面有 COM3 之类的条目。 注意：Windows 11 有时会自动装上一个不匹配的旧版 CP210x 驱动， 此时需要在设备上右键「更新驱动程序 → 从列表中选择」，手动换成新版。

报错原文：串口监视器里全是乱码（例如 ⸮⸮⸮ 或一串方框），偶尔夹杂半个汉字

原因： 串口监视器的波特率和 Serial.begin() 里写的不一致。 波特率不一致时，接收方在错误的位时刻采样，解出来的字节就是随机的—— 偶尔会碰巧对上一两个字符，所以你会看到「大部分乱码、偶尔正常」的现象，很有迷惑性。

解决： 把串口监视器右下角的下拉框改成和代码里一样的值。 本教程统一用 115200。 如果改成 115200 还是乱码，检查是不是串口监视器还开着「显示时间戳」之类会插入额外字符的选项， 或者芯片时钟配置被改了（极少见，只有改过 board_build.f_cpu 才会）。

报错原文：Brownout detector was triggered / rst:0x7 (TG0WDT_SYS_RESET) 后反复重启

原因： Brownout 是「掉电检测」——芯片发现 3.3V 电压掉到安全线以下， 主动复位以保护自己。它不是软件问题，而是供电问题： USB 线太细压降大、插在电流受限的前面板 USB 口、或者用了劣质 USB 集线器。 ESP32 开机瞬间要建立 Wi-Fi 校准数据，电流会冲到 500mA 左右， 这个瞬间最容易触发。

解决： 按性价比从高到低试：换一根粗一点的短 USB 线 → 换到机箱后面板的 USB 口 → 不用集线器直插 → 用带独立供电的 USB Hub → 从 VIN 脚接一个 5V/1A 的独立电源 （此时必须拔掉 USB）。 如果程序里为了省电调用了 WiFi.setSleep(true)， 也可以在确认供电正常之前先关掉睡眠，减少瞬时电流波动。

小结与练习

这一篇做的事情看起来只是「装软件」，但真正需要带走的是一张判断地图。 整篇的核心结论可以压成三句话：

第一，开发板包不是插件而是工具链。 装它的过程就是把 Xtensa 交叉编译器、ESP-IDF 协议栈和 esptool 烧录工具搬到你的电脑上， 所以它才有几百 MB，也才会受网络影响。 第二，上传是一次「串口借用」。 esptool 要通过把 GPIO0 拉低让芯片进入下载模式，自动电路不可靠时就得手动按 BOOT—— 这就是 Connecting 卡住的全部秘密。 第三，乱码先怀疑波特率，重启先看复位原因。 这两条经验能让你在没有示波器、没有逻辑分析仪的情况下，快速判断问题出在配置还是硬件。

串口监视器波特率 115200
动手练习
  1. 故意制造一次乱码。 把串口监视器波特率改成 9600，观察输出变成什么样； 再改回 115200，确认恢复。亲手做一遍，以后看到乱码就不会慌。
  2. 把复位原因用起来。 在 loop() 里加一行 if (Serial.available()) { if (Serial.read() == 'r') ESP.restart(); }， 然后在串口监视器里发送字符 r，看 [4] 那一行变成了什么。 这一步同时练会了「串口接收」和「观察复位原因」两件事。
  3. 测出你这块板子的真实启动耗时。 在 setup() 开头记下 millis()， 在串口打印第一行之前再记一次，把差值打印出来。 这个数字反映了 USB 枚举延迟，以后再遇到「第一行丢失」时，你就知道该把 delay() 设成多少。
