原理介绍

前面几篇教程里，主程序一直是这个结构：while (1) 里干完一件事再干下一件。 这种写法叫查询方式（轮询）——按键按没按，要 CPU 亲自去读引脚； 如果主循环里有 Delay_ms(500)，那这 500ms 里按键按下去多少次它都不知道。 外部中断解决的正是这个问题：让硬件替你盯着引脚，事件来了再叫 CPU 去处理。

中断到底解决了什么问题

打个比方：你在自习室做题（主程序），快递到了（外部事件）。轮询方式相当于每做一道题就跑到门口看一眼， 大部分时候白跑；中断方式相当于你留了手机号，快递员到了打你电话，你放下笔去拿， 拿完回来接着做刚才那道题——断点会被保存，回来还能继续。

对比项 查询方式（轮询） 中断方式
CPU 占用 一直在读引脚，纯浪费 事件发生前完全不占用
响应速度 最慢要等一整轮主循环 几个机器周期内进中断（微秒级）
会不会漏事件 主循环里一延时就可能漏掉 硬件锁存标志，不会漏（只要没被屏蔽）
代价 写起来简单 要考虑优先级、重入、时序被打断

所以判断标准很直接：这个信号是“事件”还是“状态”？ 按键、光电门、编码器脉冲、串口来字节属于事件，错过就没了，必须用中断； 电位器电压、温度传感器读数属于状态，什么时候读都是当前值，轮询完全可以。

中断源与 INT0 / INT1 引脚

STC89C52RC（标准 8052 内核）一共有 5 个中断源，每个中断源有一个固定的中断号。 Keil C51 里写 interrupt n，编译器就知道该把函数地址填到哪个向量上：

中断源 中断号 中断向量地址 触发引脚 / 条件
外部中断 0（INT0） 0 0x0003 P3.2
定时器 0（T0） 1 0x000B TF0 溢出
外部中断 1（INT1） 2 0x0013 P3.3
定时器 1（T1） 3 0x001B TF1 溢出
串口（UART） 4 0x0023 TI 或 RI 置位
P3.2 / P3.3 是复用引脚，用了中断就不能再当普通 IO

P3 口的每一个引脚都有第二功能，P3.2 既是普通 IO 又是 INT0，P3.3 既是普通 IO 又是 INT1。 你把按键接到 P3.2 之后，程序里就不要再写 P3 = 0x00; 这种整口操作，也不要把别的输出器件挂到 P3.2 上—— 否则中断会被你自己的输出电平反复触发。同理，P3.0 / P3.1 是串口下载口， 新手接按键时容易顺手接到 P3.0，结果下载程序和按键互相打架。

TCON 与触发方式 IT0 / IT1

外部中断的“怎么触发”由 TCON 寄存器（字节地址 0x88，可位寻址）决定。 TCON 的 8 个位一半属于定时器、一半属于外部中断，这里只看和中断有关的那 4 位：

位 名称 含义
TCON.0 IT0 INT0 触发方式：0 = 低电平触发，1 = 下降沿触发
TCON.1 IE0 INT0 中断请求标志，硬件置位，响应后自动清除
TCON.2 IT1 INT1 触发方式：0 = 低电平触发，1 = 下降沿触发
TCON.3 IE1 INT1 中断请求标志

实际项目里为什么一律选下降沿？ 关键在“标志位是谁清的”。IT0 = 0（低电平触发）时，IE0 这个标志直接跟随引脚电平： 引脚是低电平，IE0 就是 1。CPU 响应中断时会自动把 IE0 清掉，但只要你手指还按着按键、 引脚还是低电平，IE0 立刻又被硬件置成 1，于是中断服务函数一返回就马上再进去一次—— 现象就是按一下、LED 翻转几十次，或者主程序干脆再也跑不动。

改成 IT0 = 1（下降沿触发）之后，只有电平从高跳到低的那一瞬间才置一次 IE0， 跟你按多久完全无关，CPU 响应后标志自动清零，按键松手也不会再触发。 这就是所有按键、光电门、编码器的标准做法：一次边沿 = 一次事件。

低电平触发还有用吗？

有，但只适合“信号有效期间需要一直响应”的场合——例如某个模块的报警引脚会持续输出低电平， 你希望它低着的整段时间里 CPU 反复来处理，那才用低电平触发。 另外要注意：低电平触发时，中断服务函数返回前信号必须已经恢复高电平， 否则会立刻再进一次，形成事实上的死循环。

IE 寄存器与两级使能

中断允不允许，由 IE 寄存器（字节地址 0xA8，可位寻址）控制。 它设计成两级开关：EA 是总闸， EX0 / EX1 是分闸。

位 名称 含义
IE.7EA总中断允许：1 = 打开总闸，0 = 屏蔽所有中断
IE.4ES串口中断允许
IE.3ET1定时器 1 中断允许
IE.2EX1外部中断 1 允许
IE.1ET0定时器 0 中断允许
IE.0EX0外部中断 0 允许

两个开关必须同时打开才进得了中断。只写 EX0 = 1; 而忘了 EA = 1;， 是新手最常见的“中断死活不进”的原因；反过来只写 EA = 1; 而忘了 EX0 = 1; 同样没用。也可以一次把整个字节写进去： IE = 0x81;（EA = 1、EX0 = 1，其余位为 0）。

另外 51 有两个优先级，默认都是“低优先级”。同一个优先级的中断不能互相打断， 也就是 INT0 的中断服务函数执行到一半时，再来一个 INT0 请求只能排队等着。 默认的自然优先级从高到低是：INT0 → T0 → INT1 → T1 → 串口。 需要改优先级时用 IP 寄存器（例如 PX0 = 1; 把 INT0 提到高优先级）， 但零基础阶段先记住“中断服务函数要短”，比研究优先级更实用。

中断服务函数与标志位清除

中断服务函数（ISR）在 Keil C51 里靠关键字 interrupt 声明， 后面跟中断号。以 INT0 为例： 

/* 外部中断 0：中断号 0，对应引脚 P3.2，向量地址 0x0003 */
void ExInt0_ISR(void) interrupt 0
{
    /* 这里写“事件发生时要立刻做的事”，越短越好 */
}

/* 外部中断 1：中断号 2，对应引脚 P3.3，向量地址 0x0013 */
void ExInt1_ISR(void) interrupt 2
{
}
  • 关键字 interrupt 必须写在参数表之后， 写成 void interrupt 0 ExInt0_ISR(void) 是编译不过的。
  • 中断服务函数不能有返回值、不能有参数。它的调用者是硬件， 没人给你传参、也没人接你的返回值。
  • 加了 interrupt 0 之后，函数名可以随便起，编译器只认那个中断号； 真正决定“谁触发它”的是中断号，不是函数名。
  • 还有可选的 using n（n = 0~3）指定寄存器组切换， 只有在中断和主程序同时大量使用局部变量、且对压栈开销敏感时才需要，初学阶段不要加。

标志位 IE0 为什么会自己清零

这是和定时器、串口最容易混淆的一点。8051 的中断标志清除分两类：

标志位 属于 谁来清零
IE0 / IE1 外部中断 下降沿触发时硬件自动清除；低电平触发时跟随引脚电平
TF0 / TF1 定时器溢出 硬件自动清除（进中断后不用管）
TI / RI 串口发送 / 接收 必须软件清零，忘了就反复进中断

所以外部中断的服务函数里不需要写清标志的语句， 这是它比串口中断省心的地方。但也别把“硬件帮我清”理解成“我可以乱来”： 如果 ISR 执行期间又来了一次下降沿，IE0 会被重新置 1，等 ISR 返回后会补执行一次。 按键抖动正好会制造这种“补执行”，所以消抖不能省。

为什么中断服务函数里绝对不能做耗时操作

这是本篇最重要的一条纪律。假设你在 ISR 里写了 Delay_ms(10) 做消抖， 会同时踩到三个坑：

  1. 主循环停摆 10ms。 动态数码管要求每 1~2ms 刷新一位，否则人眼就会看到闪烁； ISR 里卡 10ms，等于让数码管断刷新 10ms 以上，现象是显示发暗、抖动、甚至只剩一位亮。
  2. 同级中断被堵住。 51 的同级中断不能嵌套，这 10ms 里如果又来了按键、或者定时器溢出， 全部只能排队，定时器计时会变慢，串口收到的下一个字节可能把上一个覆盖掉（丢数据）。
  3. 抖动期间的事件会挤成一堆。 触点抖动本来就在几毫秒内，你在 ISR 里等 10ms，等于把后面的抖动边沿又攒成了一次新的中断请求。
正确分工：ISR 只记事件，主循环干重活

中断里只做“翻转一个引脚”或“置一个标志位”，耗时都在几个机器周期到几十微秒之间； 消抖、显示、计算、通信全部放回主循环。后文的关键代码解析给了一个现成的双写法对照。

按键消抖：硬件与软件两套方案

机械按键在闭合和断开的一两毫秒内，金属触点会像皮球一样弹跳好几次， 在示波器上是一串毛刺。这串毛刺在下降沿触发下就是好几次独立的中断， 所以必须消抖：

  • 硬件消抖（推荐先做）。 在按键两端并联一只 0.1µF 电容。它和上拉电阻组成 RC 低通， 时间常数约 10kΩ × 0.1µF = 1ms，把毛刺“抹平”，边沿变成一条干净的下坡。 好处是不占 CPU，也不需要在程序里加任何延时。
  • 软件消抖（硬件没加电容时的补救）。 进中断后延时 10ms 再读一次引脚，仍然是低电平才算一次有效按下。 注意：这个 10ms 一定要放在主循环里做， 而不是塞进 ISR——正确写法是 ISR 里只置标志，主循环看到标志后延时确认。

两套方案可以叠加使用：硬件电容消掉大部分毛刺，软件再确认一次， 这种“双保险”在现场干扰大的设备（电机、继电器旁边）里是很常见的做法。

硬件接线说明

这一节的目标是让你闭着眼睛也能接对。 外部中断的电路本身很简单（一个按键 + 一个上拉电阻 + 一个电容）， 但“接到哪个引脚”和“上拉电阻有没有装”这两件事直接决定程序跑不跑得起来， 所以下面把每一根线都列清楚。

接线顺序建议

  1. 先接电源和地，用万用表确认 VCC-GND 之间是 5V 且没有短路，再动别的线。
  2. 接晶振与两个 30pF 电容，再接复位电路。
  3. 接按键回路：先把 R1 从 P3.2 拉到 +5V，再串按键到 GND， 最后把 C1 并联在按键两端（也就是 P3.2 与 GND 之间）。
  4. 接两路 LED 和限流电阻，注意 LED 长脚是正极，正极朝 +5V 那一侧。
  5. 全部接完、复检一遍引脚编号，最后才上电。
上电前必查
  • 按键接的是不是 P3.2——接成 P3.0 / P3.1 会和串口下载打架，接成 P1.x 则根本没有中断功能。
  • 10kΩ 上拉电阻有没有装。省掉它的典型现象是“手一碰板子灯就乱翻”，因为引脚处于悬空状态。
  • 0.1µF 电容是并联在按键两端，不是串联在按键和引脚之间；串进去会变成低通滤波器，引脚永远读不到低电平。
  • 按键是否可靠接地：用万用表通断档量一下按下时 P3.2 与 GND 是否导通（应导通，电阻接近 0）。
  • 两路 LED 的限流电阻别漏，否则可能烧 LED 或烧引脚。

完整代码

下面这份代码可以直接在 Keil C51 里新建工程、编译、下载。 它做了两件互不干扰的事：主循环让 P1.1 的“心跳”灯每秒闪一次， 外部中断让 P1.0 的灯每按一次按键翻转一次。 这样你既能验证中断生效，也能一眼看出中断有没有拖慢主程序。 

#include <reg52.h>            /* 51 单片机寄存器定义：IT0、EX0、EA、P1、P3 都在里面 */

/* ---------------- 引脚定义 ----------------
 * 用 sbit 给寄存器的某一位起个名字，比记 P1^0 直观得多。
 * 注意 sbit 的写法是“寄存器 ^ 位号”，不是位运算。
 */
sbit LED_TOGGLE = P1^0;       /* 被按键翻转的 LED（灌电流接法，低电平点亮） */
sbit LED_HEART  = P1^1;       /* 主循环里的“心跳”灯，用来证明主程序没被卡住 */
sbit KEY_INT0   = P3^2;       /* 外部中断 0 的输入引脚，按键接在这里 */

/* ------------------------------------------------------------------
 * 软件延时：12MHz 晶振、12T 模式下内层循环约 1ms
 * 这个函数只允许在主循环里用，绝对不要放进中断服务函数
 * ------------------------------------------------------------------ */
void Delay_ms(unsigned int ms)
{
    unsigned int i, j;
    for (i = ms; i > 0; i--)
        for (j = 110; j > 0; j--);
}

/* ------------------------------------------------------------------
 * 外部中断 0 服务函数
 * interrupt 0 ：中断号 0 → INT0，对应引脚 P3.2，向量地址 0x0003
 * 要求：无返回值、无参数、执行时间越短越好
 * ------------------------------------------------------------------ */
void ExInt0_ISR(void) interrupt 0
{
    LED_TOGGLE = ~LED_TOGGLE;   /* 只做一件事：翻转 LED，几个机器周期就结束 */
}

void main(void)
{
    /* ---------- 1. 引脚初始状态 ---------- */
    LED_TOGGLE = 1;             /* 低电平点亮，先写成 1 熄灭 */
    LED_HEART  = 1;
    KEY_INT0   = 1;             /* 51 的准双向口作输入前先写 1，这是标准习惯 */

    /* ---------- 2. 设置 INT0 为下降沿触发 ---------- */
    IT0 = 1;                    /* TCON.0 = 1 → 下降沿触发；写 0 则是低电平触发 */

    /* ---------- 3. 打开中断：分开关 + 总开关，两个都要 ---------- */
    EX0 = 1;                    /* IE.0 = 1，允许外部中断 0 */
    EA  = 1;                    /* IE.7 = 1，打开总中断 */
    /* 上面两行等价于一句话：IE = 0x81; */

    /* ---------- 4. 主循环：和中断无关的常规工作照常进行 ---------- */
    while (1)
    {
        LED_HEART = 0;          /* 心跳灯亮 */
        Delay_ms(500);
        LED_HEART = 1;          /* 心跳灯灭 */
        Delay_ms(500);
    }
}

关键代码解析

  • sbit LED_TOGGLE = P1^0;——sbit 是 Keil C51 的扩展关键字， 用来把一个可位寻址的寄存器位定义成变量名。这里的 ^ 是位号分隔符， 不是异或运算，别写成 P1 ^ 0（多了空格虽然也能编译，但容易看错）。
  • IT0 = 1;——决定“怎么算一次事件”。写 1 是下降沿触发， 按住按键不放也只会触发一次；写成 0 就是低电平触发，按住会反复进中断。全篇最关键的一行。
  • EX0 = 1; EA = 1;——两级使能必须都开。 顺序无所谓，但两句都要有；EA 是全局总闸， 以后调试串口中断时如果发现外部中断也不响应了，第一个要查的就是它。
  • void ExInt0_ISR(void) interrupt 0——interrupt 0 告诉编译器把函数入口地址填到 0x0003 的中断向量里。函数名随便起， 但中断号必须和引脚对应：P3.2 用 0，P3.3 用 2。
  • LED_TOGGLE = ~LED_TOGGLE;——中断里唯一的动作。 为什么不用 if (KEY_INT0 == 0) 判断一下？ 因为下降沿触发已经保证“只有真正出现边沿才进来”，不用再读引脚。
  • KEY_INT0 = 1;——51 的 P1/P2/P3 是准双向口， 作为输入前先写 1，让内部弱上拉生效，读引脚才能读到稳定的高电平。 漏掉这一句，遇到某些板子时会出现读取忽高忽低。
进阶写法：中断只置标志，主循环消抖

如果手上没有 0.1µF 电容，或者按键特别差，可以用这个“中断置标志 + 主循环延时确认”的写法。 它把 10ms 的延时从 ISR 里挪到了主循环，是中断编程里最标准的分工方式。 

bit key_flag = 0;            /* 全局标志：中断只负责把它置 1 */

/* 中断里只干一件几微秒就能完成的事 */
void ExInt0_ISR(void) interrupt 0
{
    key_flag = 1;            /* 不要在这里延时，也不要在这里刷数码管 */
}

/* 主循环里的处理：延时确认 + 真正干活 */
while (1)
{
    /* ... 数码管刷新、其它常规任务 ... */

    if (key_flag)            /* 有按键事件了 */
    {
        key_flag = 0;        /* 先清标志，避免处理期间又被置位 */
        Delay_ms(10);        /* 等触点抖动过去（这一步在主循环，安全） */

        if (KEY_INT0 == 0)   /* 10ms 后引脚仍然是低电平 → 确认是一次有效按下 */
        {
            LED_TOGGLE = ~LED_TOGGLE;
        }
    }
}

这个写法还有一个额外好处：如果按键被一直按住（引脚一直是低电平）， 下降沿只会在按下那一刻出现一次，所以这里也只会执行一次， 不会像轮询那样被“按住不放”刷屏。

现象演示说明

下载完之后按下面的清单逐条对照。两盏灯的分工是这一节的观察核心： 心跳灯代表主程序，翻转灯代表中断，两者的节奏互不影响才说明程序结构是对的。

正确现象

  1. 上电后接 P1.1 的心跳灯以约 1 秒为周期亮灭闪烁，节奏非常均匀。
  2. 每按一次 K1，接 P1.0 的灯翻转一次：按下前是灭的，按一下变亮，再按一下变灭。
  3. 按住 K1 不放，灯只翻转一次——这是下降沿触发的直接证据。
  4. 按按键的过程中，心跳灯的亮灭间隔看不出任何变化（说明主循环没有被拖住）。
  5. 松开按键、什么都不做时，翻转灯保持原状态，不会自己乱跳。

观察点与判据

你观察到的 说明什么 下一步查什么
按一次，灯翻转好几次（跳 2、3 次） 触点抖动被当成了多次下降沿，消抖没生效 确认 0.1µF 电容是否真的并联在按键两端；或改用“中断置标志 + 主循环延时 10ms”的写法
按住不放，灯疯狂翻转 触发方式实际是低电平触发，IE0 被电平反复置位 检查 IT0 = 1; 是否漏写或被后面的整字节写 TCON 覆盖了
完全没反应，心跳灯正常闪 主程序在跑，但中断没被允许或引脚接错 按顺序查：EA / EX0 是否都置 1、按键是否真的接在 P3.2、上拉电阻是否装了
两盏灯都不亮、板子像没上电 程序没跑起来或供电有问题 量 VCC 是否 5V；确认 HEX 下载成功；查晶振与复位电路
按一下灯变亮但不会变灭 ISR 里执行了两次以上，或者你把翻转写成了赋值 检查是不是写成了 LED_TOGGLE = 0;，应写成取反
一上电就不停翻转，按键没碰过 引脚悬空或被干扰，也可能是低电平触发 + 引脚被拉低 先确认上拉电阻与电容装好；再把 IT0 改成 1 观察是否恢复
顺手做一次定量测量

用秒表量心跳灯 10 个周期的实际耗时，和理论值 10 × 1s = 10s 对比。 软件延时是估算出来的，误差 10% 以内都算正常；如果偏差特别大， 说明晶振频率和你以为的不一样（很多开发板出厂焊的是 12MHz 而不是 11.0592MHz）。 这个“理论 vs 实测”的对比写进课设报告里，比贴一张效果图专业得多。

常见报错排查方案

下面每一条都按「报错原文 / 现象 → 原因 → 解决」写。第一条和第三条是新手命中率最高的两个坑， 建议先看它们。

编译报错：error C141: syntax error near 'interrupt'

原因：两个可能。一是你装的是 Keil MDK-ARM（ARM 编译器不认识 8051 的 interrupt 关键字）；二是把关键字位置写错了，比如写成 void interrupt 0 ExInt0_ISR(void)。

解决：确认装的是 Keil µVision for C51；关键字必须写在参数表之后：void ExInt0_ISR(void) interrupt 0。另外注意函数声明（原型）里不能带 interrupt 0，只在函数定义处写。

编译报错：error C202: 'IT0': undefined identifier

原因：漏了 #include <reg52.h>，或者用了 <reg51.h> 又在中途重复包含，导致位定义没进来。

解决：文件第一行补上 #include <reg52.h>。如果用的是很老的编译器（头文件里没有 IT0 的位定义），可以自己补一行：sbit IT0 = TCON^0;、sbit EX0 = IE^0;。

现象：按一下按键，LED 翻转好几次（有时连跳两下）

原因：按键触点的机械抖动。一次按下在硬件上是一串快速的高低跳变，下降沿触发会把每一个跳变都当成一次事件。没有硬件电容时这是必然现象，不是程序 bug。

解决：两条路，最好都做。硬件上在按键两端并联 0.1µF 电容；软件上改用本文「进阶写法」，中断里只置 key_flag，主循环里 Delay_ms(10) 后再读引脚确认。注意延时必须在主循环，不能塞进中断服务函数。

现象：按住按键不放，LED 一直翻转 / 主程序像卡住

原因：IT0 实际是 0（低电平触发），引脚只要保持低电平，中断标志 IE0 就会被硬件反复置 1，中断服务函数一返回立刻又进去。

解决：确认 IT0 = 1; 存在，并且后面没有再用 TCON = ... 这样的整字节赋值把它覆盖掉（要改也用 TCON |= 0x01; 这种位操作）。排查时可以临时在 ISR 里翻转心跳灯，观察是否“一进就出不来”。

现象：按按键毫无反应，但心跳灯正常闪

原因：按可能性从高到低排：① EA 或 EX0 有一个没打开；② 按键接到了 P3.0 / P3.1 / P1.x 而不是 P3.2；③ 10kΩ 上拉电阻漏装，引脚悬空读不到干净的下降沿；④ 按键另一端没真正接到 GND；⑤ 中断号写错（P3.3 上却写了 interrupt 0）。

解决：按这个顺序三步定位：先用万用表量按下按键时 P3.2 对地是否导通（排除 ④）； 再临时把 IT0 = 0; 试一下——如果低电平触发能响应，说明中断通路是好的，问题在边沿信号质量（补上拉/电容）； 最后检查 EA = 1; 与 EX0 = 1; 是否都在初始化里，别被别的分支清掉了。

现象：加了中断之后数码管开始闪烁、串口开始丢数据

原因：中断服务函数里做了耗时操作（延时消抖、刷新数码管、发送字符串）。ISR 执行期间主循环完全停摆，同级中断也不能嵌套，动态扫描的刷新节奏和串口接收缓冲都会被破坏。

解决：把 ISR 精简到只剩“翻转引脚 / 置标志位”，所有延时、显示、通信搬回主循环。判断标准很简单：ISR 的执行时间应该远小于主循环一轮的耗时（一般控制在几百微秒以内）。

小结与练习

这一篇从“为什么要中断”讲到“中断里只能写几行代码”，真正需要背下来的只有四句话：

  • IT0 = 1; —— 事件型信号一律用下降沿触发，一次边沿算一次事件。
  • EX0 = 1; EA = 1; —— 分开关加总开关，少一个都进不去。
  • interrupt 0 对应 P3.2，interrupt 2 对应 P3.3。
  • 中断服务函数只记事件，消抖、显示、计算统统留给主循环。

外部中断是所有“事件驱动”程序的起点：后面学定时器中断是同一套框架（换中断号、换标志位规则）， 学串口中断也是同一套框架（只是 TI/RI 要记得软件清零）。 把这四个知识点记牢，51 的中断体系基本就通了。

动手练习
  1. 改用 INT1 实现同样功能。 把按键挪到 P3.3，程序里要改三处：触发方式位、使能位、中断号。 写完后想一想：如果把 P3.2 和 P3.3 各接一个按键、分别翻转 P1.0 和 P1.1，需要注意什么？
  2. 做一个小型计数器。 用「中断置标志」的写法统计按键次数，把次数（0~255）用二进制显示在 P2 口的 8 个 LED 上。 提示：主循环里 P2 = ~count; 就能显示计数值，因为 LED 是低电平点亮。
  3. 把中断用成测速仪。 在 P3.2 上接一个光电门或霍尔传感器（信号是脉冲），中断里给变量加 1， 定时器每 1 秒把这个数清掉并显示出来，就得到了转速或频率。 想一想：为什么这类测量用轮询一定会丢脉冲？
  4. 故意制造 bug 并观察。 临时在 ExInt0_ISR 里加一句 Delay_ms(10);， 观察心跳灯的节奏变化；再把 IT0 改成 0，按住按键观察现象。 亲手复现一次，比背十遍结论都管用。
