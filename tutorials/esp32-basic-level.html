3.3V 供电与 GPIO 安全

在 51 上你可以把 5V 传感器随手接上去，在 ESP32 上这么干会直接烧引脚。 这一篇讲两件新手最常翻车的事：电供不供得上（WiFi 发射瞬间要 500mA， 电脑 USB 口经常给不出，于是板子不停重启）和电压接得对不对 （IO 绝对最大 3.6V、ADC 只能量 0~3.3V、用 WiFi 时 ADC2 直接失效）。 最后给出一张「能不能接」对照表和一张万用表实测判据表，照着做就不会烧板子。

原理介绍

学 51 的时候，你几乎不用想「电」的问题：5V 电源、5V 传感器、5V 单片机，全部直连， 引脚灌进去 20mA 也没人心疼。换到 ESP32 之后，规则全变了： 它是 3.3V 器件，IO 的绝对最大额定只有 3.6V； 同时它内部还塞了一个 WiFi 发射机，瞬时电流能冲到 500mA 以上。 前者会烧引脚，后者会让板子莫名其妙地重启。这两件事合起来，就是新手「板子又坏了」的九成原因。

先记住这三句话，本节所有内容都是它们的展开
  • 电压上界 3.3V：IO 脚上出现 5V 就是超规格，哪怕只有一瞬间。
  • 电流下界要够：电源必须能顶住 500mA 的瞬时峰值，否则复位。
  • 用 WiFi 就别碰 ADC2：那是硬件占用，不是软件 bug，换到 ADC1 的引脚就好。

ESP32 是 3.3V 器件

打开 ESP32 的 datasheet，在「Absolute Maximum Ratings（绝对最大额定值）」一节会看到： 任何 IO 引脚上的电压范围是 -0.3V ~ 3.6V。 注意「绝对最大额定」的意思不是「在这个范围内可以正常工作」，而是 超过就可能永久损坏——它是破坏性极限，不是工作范围。 正常工作范围是 0 ~ 3.3V（VDD33）。

更坑的是：ESP32 的 IO 不是 5V 容忍（not 5V tolerant）。 很多 STM32 的引脚标着 FT（Five-volt Tolerant），可以直接吃 5V 输入——ESP32 一个都没有。 你在 STM32 上养成的「反正 FT 脚能接 5V」的习惯，必须在这里停住。

平台IO 工作电压5V 输入能不能直连典型坑
51（STC89C52RC，5V 供电）5V能3.3V 器件接到 51 上反而可能识别不到高电平
STM32F103（3.3V 供电）3.3V标注 FT 的引脚能，其余不能忘记查引脚是否带 FT，直接接 5V
ESP323.3V全部不能5V 传感器直连 → 引脚击穿，常伴随整片 IO 失效
3.6V 这条线为什么这么容易踩

因为很多模块「看起来是 3.3V 的」：DHT11 有 3.3V 版本也有 5V 版本，HC-SR04 是 5V 供电、 它的 Echo 输出也是 5V 电平（Trig 可以 3.3V 驱动，Echo 不能直接读）， 某宝上大量「5V 继电器模块」的控制脚内部上拉到 5V。 接之前唯一可靠的做法是：给模块单独供电后用万用表量一下它的信号脚对地电压， 量到 5V 就必须做电平处理。

电流需求：平均要多少

估算供电够不够，先看「平均电流」。平均值决定你的电源会不会发烫、电池能用多久； 而下面要讲的峰值决定板子会不会重启。ESP32 的平均电流和它「在干什么」强相关：

工作状态典型电流（3.3V 侧）说明
深度睡眠（Deep Sleep，只留 RTC）约 10 µA电池设备靠它续命；WiFi 断开
轻度睡眠 / Modem-sleep（WiFi 保持连接）约 3 ~ 20 mA会周期性醒来听 AP 的信标
CPU 全速空转（240MHz，不开射频）约 30 ~ 50 mA你的 loop() 死循环大概就是这个量级
WiFi 已连接、无数据收发约 80 ~ 100 mA新手最常待的状态，也是多数教程给的「平均值」
WiFi 持续收发数据约 120 ~ 160 mA跑 MQTT 上报、HTTP 请求时
WiFi 发射瞬间（TX burst）500 mA 以上（峰值）只持续几百微秒，但足以把弱电源拉垮

把这张表翻译成一句话：你要准备的是一个「能持续给 150mA、瞬时给 500mA」的 3.3V 电源。 只按平均电流选电源，是新手供电翻车的根本原因。

板子上有一颗 AMS1117-3.3 稳压芯片（能输出 800mA~1A）， 它本身是够的；真正拖后腿的经常是它前面的那条路： 电脑 USB 口的限流、劣质 USB 线的线阻、面包板/杜邦线的接触电阻。 当 3.3V 轨瞬间跌破 Brownout 检测阈值（默认约 2.43V）时， 芯片会主动复位保护自己——这就是你在串口里看到的 Brownout detector was triggered。

为什么「同一个程序，昨天还好好的」

因为峰值是随机的：离路由器近、信道拥挤、重传次数多，峰值就更高更频繁。 这也解释了为什么「手机热点一连就重启、家里路由器就正常」—— 不是代码问题，是发射功率和重传策略不同导致的电流差异。

ADC 输入范围与换算

ESP32 的 ADC 是 12 位的，analogRead() 返回 0 ~ 4095，默认量程对应 0 ~ 3.3V （Arduino-ESP32 默认使用 11dB 衰减档，把满量程拉到约 3.3V）。换算公式简单到只需要一步除法： 

电压(V) = analogRead(引脚) / 4095.0 * 3.3

例：读到 2048  ->  2048 / 4095 * 3.3 = 1.650 V
    读到 4095  ->  3.300 V（满量程，通常说明输入已经到顶或超范围）
    读到    0  ->  0.000 V（可能是真的接地，也可能是引脚悬空/读不到）

但真实芯片有三个必须知道的现实：

  • 两端不线性：大约低于 0.15V、高于 3.15V 的区段，读数会明显偏离理想直线。 做精确测量时把信号限制在 0.15V ~ 3.15V 之间。
  • 单次读数有噪声：同一根线连续读 10 次，最大最小值可能差几十个字。 工程做法是连续采样 16 次取平均（本页代码示例就是这么写的）。
  • 有零点偏移：接到 GND 时读数可能不是 0 而是几到几十。 要求高的场合要实测两点（GND 与已知电压）做线性校正。
ADC 引脚本身也不是 5V 容忍的

很多人以为「ADC 可以量电压，那我量 5V 电池电压也行」——不行。 往 ADC 引脚上直接灌 5V，和往普通 IO 上灌 5V 一样会烧。 要量超过 3.3V 的电压，必须先用电阻分压（见 分压电路怎么算）。

ADC2 与 WiFi 的冲突

这是 ESP32 最著名、也最容易被误判成「代码写错了」的硬件限制： 一旦启用 WiFi，ADC2 就归 WiFi 驱动使用，你的 analogRead() 会读不到值 （返回 0、要么一直不变、要么直接报错）。这不是 bug，是芯片内部 ADC2 被射频子系统接管的既定事实， 连 ESP-IDF 官方文档都专门写了一段说明。

ADC 单元通道对应的引脚能不能和 WiFi 同时用
ADC1 GPIO36、GPIO37、GPIO38、GPIO39、GPIO32、GPIO33、GPIO34、GPIO35 能（做联网项目就用这一组）
ADC2 GPIO4、GPIO0、GPIO2、GPIO15、GPIO13、GPIO12、GPIO14、GPIO27、GPIO25、GPIO26 不能（WiFi 启动后失效）
实战结论

只要你的项目要联网，就把所有模拟量采集固定放在 GPIO32、GPIO33、GPIO34、GPIO35、GPIO36、GPIO39 上 （GPIO37、GPIO38 在 WROOM-32 模组上没有引出）。 记住这个六脚清单，以后看到「我的光敏电阻一联网就读不到值」立刻就能反应过来。

输入专用引脚 34/35/36/39

ESP32 有四个「只能输入」的引脚：GPIO34、GPIO35、GPIO36、GPIO39。 它们的特点和坑都在下面这张表里：

引脚能做输入吗能做输出吗有内部上拉吗典型用途
GPIO34能不能没有ADC 采样、外部上拉的按键
GPIO35能不能没有ADC 采样
GPIO36（VP）能不能没有ADC 采样
GPIO39（VN）能不能没有ADC 采样

典型事故：把按键接在 GPIO34 上，代码写 pinMode(34, INPUT_PULLUP)， 结果读出来一直是同一个值。原因就是这四个脚没有内部上拉电阻， INPUT_PULLUP 在这里是空操作（编译不报错，运行也不报错，就是没用）。 正确做法是外接一只 10kΩ 电阻到 3.3V，或者把按键换到 GPIO4、GPIO13 这种带内部上拉的普通引脚上。

内部上拉与下拉

除了那四个输入专用引脚，其余 GPIO 都有可软件开关的内部上拉/下拉电阻，对应 INPUT_PULLUP。它们的阻值大约在 30kΩ ~ 80kΩ （典型 45kΩ），属于「弱上拉」。

场景用内部上拉够吗说明
板上一只按键，引线几厘米够教学实验的标准做法：按键一端接 GPIO、一端接 GND，pinMode(pin, INPUT_PULLUP)
引线几十厘米、或走在电机旁边不够弱上拉抗干扰差，改成外接 10kΩ 上拉（阻值小、抗干扰强，代价是按键电流变大到 0.33mA，可忽略）
I2C 总线（SDA/SCL）勉强多数模块自带上拉；长线或多设备时用外部 4.7kΩ
GPIO34/35/36/39根本没有必须外接上拉，或改用别的引脚
需要「默认低、按下变高」用下拉Arduino-ESP32 的 pinMode() 支持 INPUT、OUTPUT、INPUT_PULLUP、INPUT_PULLDOWN 四种模式，写 INPUT_PULLDOWN 就能启用内部下拉；但 GPIO34~39 内部没有上拉/下拉，这四个脚仍要外接电阻

分压电路怎么算

把高于 3.3V 的电压降到 ADC 能接受的范围，最便宜的办法就是两个电阻分压。 公式是： 

              R1（上电阻）
    Vin ────────[======]────────┬──────── Vout（送给 ADC 引脚）
                               │
                            [======] R2（下电阻）
                               │
                              GND

    Vout = Vin * R2 / (R1 + R2)
    分压比 k = R2 / (R1 + R2)       ->      Vin = Vout / k

  取 R1 = 10kΩ，R2 = 15kΩ：
    k = 15 / 25 = 0.6
    Vin = 5V   ->  Vout = 3.00V     （安全，留了 0.3V 余量）
    Vin = 12V  ->  Vout = 7.20V     （仍然超范围！12V 要重新选电阻）

  反例：网上常见的 R1 = 10kΩ，R2 = 20kΩ：
    Vout = 5 * 20/30 = 3.33V         （已经贴到 3.3V 上限，没有余量，不推荐）
分压电路的三个注意点
  • 总阻值别太大：R1 + R2 建议控制在 10k ~ 100k 之间。太大（比如 1MΩ 级）会被 ADC 采样电路的输入阻抗影响，读数偏低。
  • 加一只 0.1µF 电容：在 ADC 引脚与 GND 之间并一只 0.1µF 陶瓷电容，能明显压掉读数抖动。
  • 软件里要除回分压比：代码读到的只是分压后的电压，记得 Vin = Vout / 0.6，并且把这个系数写成常量，方便校正。

方案 A：只用 USB（最简，但峰值可能不够）

                                      │
                                   板载 AMS1117 -> 3.3V
                                      │

方案 B：外部 5V 电源供电（推荐，做联网项目就用这个）

   5V/2A 电源适配器
        │
        ├─── +5V ──> ESP32 的 VIN（或 5V）引脚
        │
        └─── GND ──┬── ESP32 的 GND 引脚
                   │
                   └── 外设（舵机 / 继电器 / 电机驱动）的 GND   <-- 共地，必须接！

   注意：外设的电源正极从 5V 电源直接取，绝对不要从 ESP32 的 3V3 引脚取。

方案 C：面包板供电轨

   电源模块 5V 轨 ── ESP32 VIN
   电源模块 GND 轨 ── ESP32 GND ── 所有外设 GND

   在 ESP32 的 3V3 与 GND 之间就近并一只 100µF 电解 + 0.1µF 陶瓷电容，
   可以显著减少 WiFi 发射时的电压跌落（很多开发板已经焊了，自己再加一只更保险）。

完整代码

三个实验从易到难：先学会把 ADC 原始值变成电压，再学分压测 5V， 最后学「带内部上拉的按键」以及输入专用引脚的正确接法。 三份代码都是完整可编译的，直接复制进 Arduino IDE 就能跑。

实验一：ADC 读数换算电压

/*
 * ESP32 基础篇 / 3.3V 供电与 GPIO 安全
 * 实验一：读取 ADC1 引脚的电压
 *
 * 接线：GPIO34 <--- 待测电压（0 ~ 3.3V）
 *       GND    <--- 与待测电路共地
 *
 * 安全提示：待测电压绝对不能超过 3.3V！要测 5V 请看实验二的分压接法。
 */

const int PIN_ADC   = 34;      // 必须用 ADC1 的引脚（32/33/34/35/36/39）
const int SAMPLES   = 16;      // 每次取 16 个样本做平均
const float VREF    = 3.3;     // 满量程参考电压
const float MAX_RAW = 4095.0;  // 12 位 ADC 满量程

void setup() {
  Serial.begin(115200);
  delay(300);                  // 等 USB 串口稳定，否则前几行会丢

  // 12 位分辨率（默认就是 12 位，写出来是为了让你知道这个设置存在）
  analogReadResolution(12);

  // 11dB 衰减：把量程拉到约 0 ~ 3.3V（Arduino-ESP32 默认值）
  analogSetPinAttenuation(PIN_ADC, ADC_11db);

  Serial.println("========================================");
  Serial.println("ADC 采样实验开始");
  Serial.printf("引脚：GPIO%d  分辨率：12 位  采样次数：%d\n", PIN_ADC, SAMPLES);
  Serial.println("========================================");
}

void loop() {
  // ① 连续采样 SAMPLES 次，累加后取平均，压掉随机噪声
  long sum = 0;
  int  rawMin = 4096;
  int  rawMax = -1;

  for (int i = 0; i < SAMPLES; i++) {
    int raw = analogRead(PIN_ADC);
    sum += raw;
    if (raw < rawMin) rawMin = raw;
    if (raw > rawMax) rawMax = raw;
    delay(2);                  // 每次采样间隔 2ms，避免采到同一时刻的噪声
  }

  float rawAvg = sum / (float)SAMPLES;
  float voltage = rawAvg / MAX_RAW * VREF;

  // ② 打印：原始值、平均值、波动范围、换算出的电压
  Serial.printf("原始值 %4d ~ %4d | 平均 %7.2f | 波动 %3d | 电压 %.3f V\n",
                rawMin, rawMax, rawAvg, rawMax - rawMin, voltage);

  // ③ 顺手做个体检：读数贴顶或贴底时给出提示
  if (rawAvg > 4080) {
    Serial.println("  ! 读数已到满量程：输入可能超过 3.3V，或引脚悬空。先断电检查接线！");
  } else if (rawAvg < 15) {
    Serial.println("  ! 读数接近 0：可能真的接地，也可能是引脚没接上 / 忘记共地。");
  }

  delay(500);
}

实验二：分压测 5V

这个实验给出一套「测量高于 3.3V 电压」的完整做法：硬件用 R1 = 10kΩ、R2 = 15kΩ 分压， 软件把分压比除回去，并用万用表读数校正系数。 

/*
 * 实验二：分压测 5V
 *
 * 接线：
 *   5V 电源正极 ──[ R1 = 10kΩ ]──┬── GPIO34
 *                                │
 *                             [ R2 = 15kΩ ]
 *                                │
 *   5V 电源负极 ─────────────────┴── ESP32 GND（共地！）
 *
 *   ADC 引脚对地再并一只 0.1µF 电容，读数会稳很多。
 *
 * 原理：Vout = Vin * R2/(R1+R2) = Vin * 0.6
 *       所以 Vin = Vout / 0.6
 */

const int   PIN_ADC   = 34;
const int   SAMPLES   = 32;
const float VREF      = 3.3;
const float MAX_RAW   = 4095.0;

// 分压比 = R2 / (R1 + R2)
const float DIVIDER_K = 15.0 / (10.0 + 15.0);   // = 0.6

// 校正系数：用万用表量出真实电压后微调这个值
// 例如万用表读 5.02V、串口算出 4.95V，就让 CAL = 5.02/4.95 ≈ 1.014
const float CAL       = 1.000;

void setup() {
  Serial.begin(115200);
  delay(300);
  analogReadResolution(12);
  analogSetPinAttenuation(PIN_ADC, ADC_11db);

  Serial.println("========================================");
  Serial.println("分压测 5V 实验");
  Serial.printf("R1 = 10kΩ  R2 = 15kΩ  分压比 k = %.3f\n", DIVIDER_K);
  Serial.println("提示：用万用表量同一个点（GPIO34 对 GND），与下面的");
  Serial.println("      「分压点电压」对照，两者应当接近。");
  Serial.println("========================================");
}

void loop() {
  long sum = 0;
  for (int i = 0; i < SAMPLES; i++) {
    sum += analogRead(PIN_ADC);
    delay(2);
  }

  float rawAvg  = sum / (float)SAMPLES;
  float vPin    = rawAvg / MAX_RAW * VREF;      // ADC 引脚上的电压（分压后）
  float vInput  = vPin / DIVIDER_K * CAL;       // 还原成被测电源电压

  Serial.printf("ADC 平均 %7.2f | 分压点 %.3f V | 被测电压 %.3f V",
                rawAvg, vPin, vInput);

  if (vInput < 3.0)      Serial.println("   (偏低，检查 5V 电源或接线)");
  else if (vInput > 5.5) Serial.println("   (偏高，确认你测的是不是 5V 电源)");
  else                   Serial.println("   (正常范围内)");

  delay(1000);
}

实验三：INPUT_PULLUP 读按键

按键接法只有两种正确姿势：普通 GPIO 用内部上拉， 输入专用引脚必须外接上拉。下面的代码同时演示这两种， 并带上消抖，你可以直接对照自己的接线。 

/*
 * 实验三：按键读取（含消抖）
 *
 * 接法 A（推荐）：GPIO4 ── 按键 ── GND        使用内部上拉
 * 接法 B（输入专用脚）：GPIO34 ── 按键 ── GND
 *                      GPIO34 ──[10kΩ]── 3.3V  必须外接上拉！
 *
 * 注意：不要用 GPIO0 / GPIO2 / GPIO12 / GPIO15 接按键，
 *       它们是启动绑带引脚，上电瞬间的电平会影响芯片启动模式。
 */

const int PIN_BTN_INTERNAL = 4;    // 普通 GPIO：有内部上拉
const int PIN_BTN_EXTERNAL = 34;   // 输入专用：没有内部上拉，必须外接

const unsigned long DEBOUNCE_MS = 30;

// 每个按键各自记录「上一次的稳定电平」与「上一次变化的时间」
int           lastStable[2]  = { HIGH, HIGH };
unsigned long lastChange[2]  = { 0, 0 };

void setup() {
  Serial.begin(115200);
  delay(300);

  // ① 普通 GPIO：一行搞定内部上拉
  pinMode(PIN_BTN_INTERNAL, INPUT_PULLUP);

  // ② 输入专用引脚：这里写 INPUT_PULLUP 也不会报错，但内部没有上拉电阻，
  //    实际不起作用（这是新手最常踩的坑）。必须外接 10kΩ 到 3.3V。
  pinMode(PIN_BTN_EXTERNAL, INPUT);

  Serial.println("========================================");
  Serial.println("按键实验");
  Serial.printf("接法 A：GPIO%d（内部上拉）\n", PIN_BTN_INTERNAL);
  Serial.printf("接法 B：GPIO%d（必须外接 10kΩ 上拉到 3.3V）\n", PIN_BTN_EXTERNAL);
  Serial.println("按下按键应看到「按下」，松开看到「松开」");
  Serial.println("========================================");
}

// 带消抖的读取：返回 true 表示「这一刻刚刚按下」
bool buttonPressed(int idx, int pin) {
  int now = digitalRead(pin);

  if (now != lastStable[idx]) {
    // 电平变了，先怀疑是抖动，等 DEBOUNCE_MS 再确认
    if (millis() - lastChange[idx] >= DEBOUNCE_MS) {
      lastChange[idx] = millis();
      lastStable[idx] = now;
      if (now == LOW) return true;    // 上拉接法：按下 = 接地 = 低电平
    }
  } else {
    lastChange[idx] = millis();
  }
  return false;
}

void loop() {
  if (buttonPressed(0, PIN_BTN_INTERNAL)) {
    Serial.printf("[%8lu ms] 接法 A（GPIO%d）：按下\n", millis(), PIN_BTN_INTERNAL);
  }
  if (buttonPressed(1, PIN_BTN_EXTERNAL)) {
    Serial.printf("[%8lu ms] 接法 B（GPIO%d）：按下\n", millis(), PIN_BTN_EXTERNAL);
  }

  // 每秒打印一次两个引脚的实时电平，方便接线排查
  static unsigned long lastReport = 0;
  if (millis() - lastReport >= 1000) {
    lastReport = millis();
    Serial.printf("实时电平： GPIO%d = %d   GPIO%d = %d   (1=松开/高，0=按下/低)\n",
                  PIN_BTN_INTERNAL, digitalRead(PIN_BTN_INTERNAL),
                  PIN_BTN_EXTERNAL, digitalRead(PIN_BTN_EXTERNAL));
  }
}

关键代码解析

代码作用新手要注意的点
analogReadResolution(12)设置 ADC 位数，返回 0~4095ESP32 默认就是 12 位；写成 10 位会变成 0~1023，很多示例代码是从 Arduino UNO 抄来的，会误导你
analogSetPinAttenuation(pin, ADC_11db)设置输入衰减，决定量程上限11dB 档才对应约 3.3V 满量程；换 0dB 档满量程只有约 1.1V，超了就一直读 4095
analogRead(pin)读一次原始值读 ADC2 的引脚在 WiFi 启动后无效；读悬空引脚会得到漂移的乱数，不是芯片坏了
raw / 4095.0 * 3.3原始值换算成电压分母必须写 4095.0（浮点），否则整数除法会把小数全丢掉，结果永远是 0 或 1
连续采样 N 次取平均抑制随机噪声N 取 16~32 比较均衡；N 太大反而会让响应变慢
pinMode(pin, INPUT_PULLUP)启用内部上拉对 GPIO34/35/36/39 无效（没有内部上拉），必须外接电阻
millis() 消抖过滤按键机械抖动不要用 delay() 消抖，那样会卡住整个程序
analogSetPinAttenuation / 分压系数把量程与量程换算解耦分压比、校正系数都写成 const float 常量，换硬件时只改一处

为什么读到 3.3V 就会触发「满量程」提示

因为 3.3V 正好是满量程边界，加上 11dB 档的非线性区（3.15V 以上）， 读数会贴到 4095 附近。这不是故障，是设计使然。 要留出余量，可以把被测电压设计成最高只到 3.0V——这也是实验二 把分压比选成 0.6（5V → 3.0V）而不是 0.667（5V → 3.33V）的原因。

实测判据表（万用表 × 串口对照）

测量点万用表怎么量应该读到不对时说明什么
3.3V 轨 黑表笔接 GND，红表笔接 3V3 引脚（直流 20V 档） 3.25 ~ 3.35 V 低于 3.2V：供电不足或线损太大；高于 3.4V：稳压芯片异常，别接外设了
5V 轨（VIN 引脚） 黑接 GND，红接 VIN 4.75 ~ 5.25 V（USB 供电时） 低于 4.5V：USB 线太细或口限流，WiFi 峰值时必然复位
ADC 输入点（实验一） 黑接 GND，红接 GPIO34 上那根线 与串口打印的「电压」相差在 ±0.05V 以内 差得多：万用表量到 3.3V 而串口显示 0.5V，多半是没共地或引脚接错
分压点（实验二） 黑接 GND，红接 R1/R2 中间那一点 约等于被测电压 × 0.6，与串口「分压点电压」一致 万用表 3.0V、串口 1.8V：分压电阻取值或接线错了（R1/R2 位置颠倒）
按键两端电平 黑接 GND，红接 GPIO 引脚，按压与松开各量一次 松开 ≈ 3.3V，按下 ≈ 0V 松开时读到 0.4V 之类的中间值：GPIO34 忘了外接上拉，引脚在悬空
系统电流（可选） 把万用表串在 5V 供电路径上（10A 档），观察连 WiFi 时的摆动 常态 80 ~ 160mA，连接瞬间有跳变 指针/数字大幅摆动同时板子复位：峰值供不上，换电源或加电容
把实测数据抄进实验报告

「3.3V 轨实测 3.29V、分压点实测 3.00V、串口算出 5.00V、误差 0.04%」 这样一行数据，比十张接线照片都更能说明你真的做出来了。 顺带说一句：万用表是你唯一能验证「电到底对不对」的工具， 做硬件的人不能只信串口打印。

常见报错排查方案

下面八条覆盖了「供电」与「电平」两类翻车现场，每条按 现象 → 原因 → 解决 写。遇到问题时按编号顺序排查， 前三条能解决九成的「一联网就重启」。

现象：WiFi 一连上板子就重启，串口打印 Brownout detector was triggered 或 rst:0x8 (TG1WDT_SYS_RESET)

原因： 供电顶不住 WiFi 发射的峰值电流。3.3V 轨在发射瞬间被拉到 Brownout 阈值（约 2.43V）以下， 芯片主动复位保护自己。典型诱因：电脑前面板 USB 口、又细又长的充电线、 带限流的 USB Hub、劣质面包板电源模块。

解决： ① 换一个 5V/1A 以上的充电头供电（别用电脑 USB 口）； ② 换一根短而粗的 USB 数据线，插机箱后面的 USB 口； ③ 在 3V3 与 GND 之间就近并 100µF 电解 + 0.1µF 陶瓷电容； ④ 拔掉一起挂在 3V3 上的外设（舵机、继电器），让它们单独供电。 验证方法：串口能正常打印 IP 且连续跑十分钟不重启，就算解决了。

现象：ADC 读数一直是 4095，怎么改代码都不变

原因： 三种可能：① 输入电压真的超过量程（比如把 5V 直接接到了 ADC 引脚）； ② 引脚悬空没接任何东西，高阻输入被环境噪声拉满； ③ 衰减档位设成了 0dB（满量程只有约 1.1V），1.5V 的输入就已经贴顶了。

解决： ① 先用万用表量 ADC 引脚对地电压，超过 3.3V 立刻断电，改成分压输入； ② 悬空引脚改用 analogSetPinAttenuation(pin, ADC_11db) 并把引脚接地试验， 接地应读到接近 0； ③ 确认代码里没有被显式改成 ADC_0db——analogRead() 默认就在 11 dB 档（约 150~3100 mV），降档是要自己写出来的； ④ 顺便检查有没有共地——不共地时读数同样不可信。

现象：没联网时 ADC 正常，一开 WiFi 读数就变成 0 或不变

原因： 你把模拟量接在了 ADC2 的引脚上（GPIO4、0、2、15、13、12、14、27、25、26）。 WiFi 驱动启动后会接管 ADC2，你的 analogRead() 自然读不到东西。 这是芯片硬件限制，ESP-IDF 官方文档有明确说明。

解决： ① 把模拟量全部改接到 ADC1 的引脚：GPIO32、33、34、35、36、39 （GPIO37/38 在 WROOM-32 模组上没引出）； ② 改线后确认引脚没有别的复用功能冲突； ③ 记住这个结论：联网项目 = 只用 ADC1。

现象：按键接在 GPIO34 上，代码写了 INPUT_PULLUP，但读出来一直是 0（或一直是 1）

原因： GPIO34/35/36/39 是输入专用引脚，芯片内部没有上拉/下拉电阻。 pinMode(34, INPUT_PULLUP) 不会报错，但也不起任何作用， 引脚实际处于悬空状态，电平随机。

解决： ① 在 GPIO34 与 3.3V 之间外接一只 10kΩ 电阻做上拉，代码改成 pinMode(34, INPUT)； ② 或者把按键换到 GPIO4、GPIO13、GPIO14、GPIO27 这类带内部上拉的普通引脚上，直接用 INPUT_PULLUP； ③ 无论哪种接法，按键另一端都接 GND，不要接 5V。

现象：接上 5V 传感器后某个引脚永久失效，程序里那个脚再也没反应（或者整片 IO 都异常）

原因： 往 GPIO 上直接灌了 5V，超过 3.6V 绝对最大额定，输入保护结构被击穿。 这类损坏通常不可逆，而且可能连带影响相邻引脚。

解决： ① 立刻断电，拔掉那个模块，逐个引脚用「输出方波 + LED」的办法确认哪些脚还活着； ② 报废的引脚在代码里标注出来（// GPIOxx 已损坏，勿用），先换个脚继续做； ③ 之后所有 5V 信号必须经分压或电平转换模块（TXS0108E、四路双向电平转换板）； ④ 养成习惯：接任何新模块前，先给模块单独上电量它的信号脚电压。

现象：程序能上传、能打印，但一接上舵机或继电器就重启，拔掉就正常

原因： 外设的电流是从板子的 3V3 引脚（或同一个 USB 口）里抢的。 舵机堵转峰值可达 700mA，远超板载稳压和 USB 口能提供的余量， 结果就是 ESP32 被「饿」到复位。

解决： ① 外设改为独立电源供电（舵机用 5V/2A 适配器或电池组）； ② 外设电源的 GND 必须与 ESP32 的 GND 连在一起，否则信号无效； ③ 在舵机电源端就近并 470µF 以上的电容吸收堵转冲击； ④ 控制信号线（橙色）可以直接接 GPIO，信号电流很小，不在限制之内。

现象：ADC 读数一直在跳，同一根线两次读数能差 100 以上

原因： ① 引脚悬空或被测源内阻过高（高阻节点容易拾取噪声）； ② 引线太长，和电机、继电器、WiFi 天线走在一起； ③ 电源纹波大（USB 供电 + 大量数字负载）； ④ 没有做软件平均。

解决： ① ADC 引脚对地并 0.1µF 陶瓷电容，就近焊接； ② 缩短信号线，远离大电流走线； ③ 软件连续采样 16~32 次取平均（本页实验一、二的写法）； ④ 要求高的场合改用外部 ADC（如 ADS1115，I2C 接口，16 位）绕开 ESP32 内置 ADC 的噪声与非线性。

现象：LED 一开始很亮，工作几分钟后这个引脚彻底不亮了，量电压一直是 0

原因： 没串限流电阻（或者把 LED 直接怼在 3.3V 与 GPIO 之间）， 引脚被逼着持续输出远超安全值的电流（默认驱动档位约 20 mA，可查上限 40 mA），输出级被烧毁。

解决： ① 每个 LED 必须串限流电阻，3.3V 供电下取 220Ω ~ 1kΩ，电流控制在 5 ~ 10mA； ② 用 digitalWrite 做呼吸灯之类的 PWM 时留意平均电流； ③ 检查是不是把 LED 接成了「GPIO 高电平点亮、不串电阻」——这是最经典的烧脚方式； ④ 已损坏的引脚在代码里标注弃用，换一个脚。

小结与练习

这一页要你记住的六件事

  • ESP32 是 3.3V 器件，IO 绝对最大额定 3.6V，没有 5V 容忍引脚。
  • 供电要按峰值 500mA 设计，只按平均 100mA 选电源必然翻车。
  • GPIO 单脚推荐 ≤ 20mA，所有 IO 合计保守按 ≤ 100mA 算；电机、继电器、舵机一律用独立电源 + 开关管。
  • ADC 满量程 0~3.3V 对应 0~4095，两端非线性，测高压必须先分压。
  • 用 WiFi 就用 ADC1（GPIO32/33/34/35/36/39），ADC2 会被 WiFi 占用。
  • GPIO34/35/36/39 只能输入、没有内部上拉，按键要外接 10kΩ。

自检题

  1. 你手上有一个 5V 供电的霍尔传感器，输出信号也是 5V 电平。有哪三种办法能安全接到 ESP32？（至少写出两种并说明取值）
  2. 为什么单节锂电池 3.7V 不能直接接到开发板的 3V3 引脚？（要从 AMS1117 的压差说起）
  3. 板子连着电脑 USB 口时一切正常，插到充电宝上就反复重启，最可能的原因是什么？怎么验证？
  4. 读到 analogRead(34) 返回 4095，请给出三种不同的原因和各自的验证方法。
  5. 为什么「用 WiFi 时 ADC2 读不到值」不是代码 bug？遇到这种情况你会怎么改接线？
  6. 按键接在 GPIO34 上，INPUT_PULLUP 为什么没用？正确接法是什么？
  7. 你的 LED 亮度很高，同事说「不用串电阻，ESP32 脚能出 40mA」。这句话哪里对、哪里危险？
  8. 分压测 5V 时你选了 R1 = 10kΩ、R2 = 20kΩ，为什么这个取值不推荐？改成什么更好？

动手练习

  1. 做一次供电压力实验：分别用「电脑 USB 口」和「5V/1A 充电头」给同一块板子供电， 各跑一遍「连 WiFi + 每 200ms 发一次 MQTT/HTTP 请求」的程序，记录是否出现 brownout 复位。 结论写进实验报告：峰值电流不是理论，是可以复现的现象。
  2. 做一次 ADC 精度标定：用 R1 = 10kΩ、R2 = 15kΩ 量一节 5V 电源， 同时用万用表量分压点，把两者差值填入 CAL 校正系数， 观察校正前后误差从百分之几降到千分之几。
  3. 故意制造一次「ADC2 失灵」：把光敏电阻先接 GPIO4（ADC2）读一遍， 再连上 WiFi 读一遍，然后把线换到 GPIO34 再读。亲手复现这个现象， 比背十遍文档都记得牢。
