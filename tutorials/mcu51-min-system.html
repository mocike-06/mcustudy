原理介绍

「最小系统」的意思是：把一切外设都拆掉之后，还能让单片机正常执行程序的最少电路。 拆到不能再拆，剩下的就是四部分。任何一部分缺失或接错，单片机的表现都是一样的—— 纹丝不动，像块砖头。这就是为什么新手最怕硬件问题： 现象完全相同，原因却可能在四个地方。

1

单片机本体

STC89C52RC，40 脚 DIP。内含 CPU、8KB Flash、512B RAM、4 个 8 位 IO 口、3 个定时器。

2

晶振电路

晶振 + 两个 22~30pF 电容。它是 CPU 的心跳，没有它 CPU 一条指令都不执行。

3

复位电路

10µF + 10kΩ 上电复位，加一个按键做手动复位。它保证 CPU 从确定的起点开始跑。

4

电源

稳定的 5V，每个电源引脚旁一个 104 电容。电源不稳，一切时序都无从谈起。

除了这四部分，还有两个「不算元件但必须处理」的引脚：第 31 脚 EA/VPP （决定从哪里取指令）和 P0 口的上拉电阻（决定 P0 能不能输出高电平）。 这两处是画原理图时最容易漏、也最容易被老师扣分的地方，下面各用一节讲。

晶振电路与负载电容

51 内部有一个反相放大器：XTAL1（第 19 脚）是放大器输入， XTAL2（第 18 脚）是输出。把晶振和两个电容接在这两个脚之间， 就构成了经典的皮尔斯振荡器（Pierce Oscillator）—— 晶振在它的固有谐振频率上形成正反馈，放大器持续输出方波，这个方波再被 12 分频成机器周期。

两个电容不是「随便加的」，它们的作用有两个： 一是给晶振提供规定的负载电容（晶振的频率是在特定负载电容下标定的，容值不对频率就偏）， 二是和晶振一起决定振荡的相位条件（提供 180° 相移，让正反馈成立）。 工厂给出的容量范围 22~30pF，来自下面这个式子： 

晶振手册给出的负载电容 CL = 20pF（也有 30pF 的型号，看规格书）

两个匹配电容一般取相同值 C1 = C2 = C，则：

        CL  =  (C1 × C2) / (C1 + C2)  +  Cs        Cs = 杂散电容（PCB 走线、引脚、焊盘）
            =  C / 2  +  Cs                        Cs 实测一般 3 ~ 5pF

  →  C  =  2 × (CL - Cs)  =  2 × (20 - 5)  =  30pF

结论：CL = 20pF 的晶振配两个 30pF；CL = 12pF 的晶振配两个 15pF
     （2 × (12 - 5) = 14pF，取 E12 标准值 15pF；Cs 仍按 5pF 估）。
     成品板上常见的 22pF 对应 CL ≈ 16pF 的晶振（2 × (16 - 5) = 22pF）——
     所以「22~30pF」不是随手定的经验值，而是从晶振规格书的 CL 反推出来的；
     照抄别人的匹配电容之前，先看清自己晶振规格书上的 CL。

电容取大了会怎样：起振变慢、甚至在某些批次上根本不起振（表现为上电偶尔不跑）
电容取小了会怎样：频率偏高、受温度与湿度影响更大，串口通信偶发乱码
电路板布线越长，Cs 越大，越应该取小一点的匹配电容
对比项 11.0592MHz（推荐） 12.000MHz

12MHz 下能凑出的标准波特率 — 2400bps（误差 0.16%）或 4800bps（SMOD=1，误差 0.16%）

什么时候选它 只要用了串口，尤其是要 9600 / 19200 等标准波特率 纯 IO 实验、要「1µs 一个好算」的教学场景

这就是那个奇怪数字的来历：11.0592MHz = 9600 × 32 × 36，能被串口所需的分频链整除， 所以误差为 0。UART 一帧 10 位、接收方在中间采样，总波特率误差超过约 2%~3% 就会开始出错， 12MHz 的 8.5% 已经远超这个限度—— 不是 12MHz 不好，而是它天生不适合标准波特率。

晶振电路的三个常见错误
  • 把电容串在晶振与引脚之间——必须是从每个引脚分别对地接一个电容。
  • 晶振离芯片太远（超过 1cm）。走线电感会让振荡不稳定，请紧贴第 18、19 脚放置。
  • 用万用表去量晶振两端电压判断好坏。万用表的输入电容会直接让振荡停摆，测出来「没电压」不代表坏了，正确做法是用示波器（10× 探头）或频率档看 XTAL2。

复位电路与 RC 计算

复位的作用是把 CPU 拉回一个确定的初始状态： 程序计数器 PC 清零（从 0000H 开始执行）、各 SFR 恢复默认值、IO 口输出高电平。 51 的 RST（第 9 脚）是高电平有效： 只要 RST 上的电压高于输入高电平门限，并保持两个机器周期以上，芯片就会复位。

12MHz 晶振下一个机器周期是 1µs，所以理论上只要高电平持续 2µs 就能复位。 我们用的是 10µF + 10kΩ，时间常数 τ = R × C = 10kΩ × 10µF = 100ms， 也就是把复位电平（RST ≥ 2.0V）保持了约 92ms——富余了四万六千倍。 这不是浪费，而是在为电源上升时间、晶振起振时间、按键抖动留余量。

上电后时间 t RST 电压 V(t) = 5 × e−t/τ 是否高于复位门限（约 2.0V）
05.00V是（正在复位）

反过来，断电时这个电容必须能放掉电， 否则再次上电时它还是满电的：RST 电压等于 5V 减去电容上存的电压，几乎是 0V， 压根够不到 2.0V 的复位门限，芯片这一次上电根本不会复位（现象：程序不从头跑，甚至像没启动一样）。 电容通过同一个 10kΩ 电阻放电，放电时间常数也是 100ms， 所以「关掉电源后等半秒以上再开」是个好习惯；实验室里那种「关了马上开、板子就不启动」的怪现象， 基本都出在这里。

手动复位按键的做法是把它并在电容两端： 按下时 RST 通过按键直接接 +5V，立刻拉高复位；松开后电容重新充电。 工程上通常在按键回路里串一个 100Ω 左右的电阻，用来限制电容瞬间放电的电流 （不串的话，触点瞬间电流可达安培级，长期使用会烧蚀按键触点）。

电解电容极性不能接反

10µF 通常用电解电容，正极接 +5V，负极接 RST。 接反的后果不是「复位慢一点」，而是电容漏液、鼓包甚至炸开； 即使没炸，反向漏电流也会让 RST 电压异常，表现为上电时跑时不跑。 拿不准方向时，选无极性的 10µF 钽电容或陶瓷电容更省心。

EA/VPP 第 31 脚：从哪里取指令

EA 是 External Access Enable（外部访问允许）的缩写， 它决定 CPU 复位后第一条指令从哪里取：

  • EA = 1（接 VCC / 高电平）——先访问片内程序存储器，地址超过片内容量后再自动转向片外。STC89C52RC 片内有 8KB Flash，我们的程序都写在这里，所以必须接高电平。
  • EA = 0（接 GND / 低电平）——所有取指都去片外 ROM。片外没有接程序存储器时，CPU 读到的是总线上的浮空数据（通常是 0xFF），执行结果就是「跑飞」。现象是灯完全不亮，或者随机乱闪。

为什么这个脚特别容易出问题？因为很多开发板把它做成跳线帽， 方便你切换「用片内 Flash」和「扩展外部 ROM」。跳线帽松动、掉落、或者被同学拔去别处， 都会让 EA 悬空——悬空时电平不确定，可能这次上电是 1、下次是 0， 于是你就遇到了最折磨人的「有时能跑有时不跑」。 做最小系统时，直接把它焊死在 VCC 上最省事。

电源与 104 去耦电容

STC89C52RC 的标称工作电压是 5V；STC 资料上常见的下限写法是 3.8V（部分批次/资料写 3.4V）。 工程上按 5V ±10%（4.5V~5.5V） 设计，低于 3.8V 不要用，用 5V 最稳； 低压下若要跑高晶振频率（比如 11.0592MHz），先降频再试。 第 40 脚 VCC、第 20 脚 GND 之间的距离越短越好，供电回路的线要粗一点（或铺铜）。

每个电源引脚旁要并一个 104 电容 = 0.1µF = 100nF 的陶瓷电容， 位置尽量在 1cm 以内。它的作用不是「滤波」两个字能说清的，具体是：

  • 提供本地电荷储备——CPU 内部几百万个晶体管在时钟沿同时翻转， 瞬间电流变化率 di/dt 极大；电流要从电源经导线过来，导线电感会立刻产生压降 （u = L · di/dt），VCC 上就会出现几十毫伏的尖峰。 贴在引脚旁的电容能在纳秒级内补上这部分电流，让 VCC 稳住。
  • 给高频噪声提供低阻抗回路——数字噪声被就近旁路到地， 不会沿着电源线扩散到模拟部分（ADC 采样、传感器供电）。
  • 抑制电源线上已有的纹波——与电源入口的大电解电容配合， 大电容管低频、104 管高频，各管一段。

缺了 104 的典型症状很有辨识度：程序平时跑得好好的， 一按复位键就死机、或者手机一来电话就重启、串口下载偶发失败。 它不属于「能不能跑」的问题，而是「能不能稳定跑」的问题—— 做课程设计时，去耦电容是评委一眼就能看出你有没有工程素养的细节。

大电容与小电容怎么配

常见做法是：电源入口放一个 100µF 电解（管低频、储能）+ 每个芯片电源脚一个 104 陶瓷（管高频）。 只放 104 会导致电源缓慢波动无人处理，只放电解则因为电解电容自身电感大、响应慢，对高频尖峰几乎无效。

P0 口为什么必须外接上拉电阻

这是 51 内部结构里最值得单独讲的一件事。四个 IO 口的输出级结构并不一样：

IO 口 内部输出结构 输出高电平时 能不能直接输出高电平
P1 / P2 / P3 准双向口：一个上拉场效应管 + 一个下拉场效应管 上拉管导通，但有较大的等效内阻，只能给出几百微安 能（弱高电平，拉电流能力很小）
P0 开漏（Open Drain）：只有下拉管，没有上拉管 两个管子都关断，引脚呈高阻态（浮空） 不能，必须外接 10kΩ 上拉电阻

为什么 P0 要设计成开漏？因为它还要兼职做地址/数据复用总线 （外扩存储器时低 8 位地址和数据分时共用 P0）。做总线时多个器件要挂在一根线上， 如果都有强上拉就会「打架」，所以 P0 只保留下拉驱动能力，高电平靠外部上拉电阻提供—— 这是典型的「线与」总线设计思路。

对最小系统的影响是：只要你想用 P0 输出高电平（比如用 P0 驱动 LED、读按键）， 就必须接 10kΩ 上拉电阻，常用一整个 10kΩ × 8 的排阻（9 脚排阻，公共端接 VCC）最省地方。 不接的现象非常具有迷惑性：用万用表量 P0 引脚，写 1 时电压只有 1V 多一点（不是 0 也不是 5V）， 接 LED 会微亮或不亮，你会以为是程序问题，其实是引脚根本没被拉上去。

P3 口的第二功能要注意

P3 的 8 个引脚每一个都有第二功能：P3.0/P3.1 是串口 RXD/TXD， P3.2/P3.3 是外部中断 INT0/INT1，P3.4/P3.5 是定时器计数输入 T0/T1， P3.6/P3.7 是外部存储器写/读选通。做最小系统时把它们留空即可， 但不要把它们接到固定电平，否则以后想用外部中断或串口时会很麻烦。

   │ 20 GND ───────────────────────── GND                             │
   │                                                                  │
   │  1~8 P1.0~P1.7 ──► LED ×8 ──[470Ω] ── +5V   （灌电流接法）        │
   │                                                                  │
   │ 10 P3.0 RXD ◄──── USB 转串口模块 TXD                             │
   │ 11 P3.1 TXD ────► USB 转串口模块 RXD                             │
   │ 29 PSEN  悬空        30 ALE 悬空                                  │
   └──────────────────────────────────────────────────────────────────┘

   四要素：电源(40/20 脚) + 晶振(18/19 脚) + 复位(9 脚) + 单片机本体
   两个必须处理：EA(31 脚) 接高电平；P0 口要用就加上拉电阻

接线顺序建议

  1. 先只焊电源：VCC、GND、104 电容。上电用万用表量 VCC 对 GND 是 4.9~5.1V，并确认没有短路。
  2. 接晶振与两个 30pF 电容。注意是从第 18、19 脚分别对地接，不是串在中间。
  3. 接复位电路：10kΩ 到地、10µF 正极到 VCC、按键串 100Ω 后并在电容两端。
  4. 把第 31 脚 EA 接到 VCC——建议直接焊接，不用跳线帽。
  5. 把第 10、11 脚引到排针，方便插 USB 转串口模块。
  6. 最后接 P1 口的 8 组 LED 与 470Ω 限流电阻。
  7. 全部接完后再断电目视检查一遍（电容极性、二极管方向、有没有连焊），然后上电。
上电前必查
  • 电源正负极有没有接反——反接一次就可能烧掉芯片，40 脚器件的 VCC/GND 是斜对角的，最容易插反。
  • 10µF 电解电容的极性：正极接 +5V，负极接 RST，反了会鼓包。
  • 第 31 脚 EA 是否确实接在 VCC 上（这是最隐蔽的一处）。
  • 晶振的两个 30pF 是否装齐——省掉它们最常见的现象是「有时能跑、有时不跑」。
  • 如果用到 P0 口，10kΩ 排阻的公共端（通常是红线那一脚）是否接到了 VCC。

完整代码

最小系统搭好之后，需要一段程序来逐项验证四要素。 下面这段「上电自检程序」把四种状态用灯的语言报告出来： 全亮 1 秒（电源与 EA 正常）→ 慢闪 3 次（复位正常，每次都从头开始）→ 1Hz 心跳（晶振在起振，程序稳定运行）。 如果心跳明显比 1 秒快或慢，说明板上晶振的频率和你以为的不一样。 

#include <reg52.h>                  /* 51 寄存器定义头文件 */

/* 自检协议（用 8 颗 LED 报告最小系统状态）：
 *   阶段 1：8 灯全亮 1 秒      → 芯片在执行指令，说明电源与 EA(31 脚) 正常
 *   阶段 2：8 灯慢闪 3 次      → 程序每次上电都从头执行，说明复位电路正常
 *   阶段 3：1Hz 心跳（全亮全灭）→ 时钟在稳定振荡，说明晶振电路正常
 *   心跳明显变快或变慢         → 晶振实际频率与预期不符，需回查晶振型号
 */

/* ------------------------------------------------------------------
 * 软件延时：12MHz 晶振下内层循环约 1ms
 * 11.0592MHz 时机器周期长 8.5%，同样的循环次数实际约 1.09ms
 * ------------------------------------------------------------------ */
void Delay_ms(unsigned int ms)
{
    unsigned int i, j;
    for (i = ms; i > 0; i--)
        for (j = 110; j > 0; j--);
}

void main(void)
{
    unsigned char i;

    P1 = 0xFF;                      /* 上电先把 8 个引脚拉高，灯全灭（灌电流接法） */

    /* ---------- 阶段 1：全亮 1 秒，证明电源与 EA 正常 ---------- */
    P1 = 0x00;                      /* 全部拉低 → 8 颗灯同时点亮 */
    Delay_ms(1000);

    /* ---------- 阶段 2：慢闪 3 次，证明复位电路正常 ---------- */
    for (i = 0; i < 3; i++)
    {
        P1 = 0xFF;                  /* 全灭 */
        Delay_ms(300);
        P1 = 0x00;                  /* 全亮 */
        Delay_ms(300);
    }

    /* ---------- 阶段 3：1Hz 心跳，证明晶振在稳定工作 ---------- */
    while (1)
    {
        P1 = 0x00;                  /* 亮 */
        Delay_ms(500);
        P1 = 0xFF;                  /* 灭 */
        Delay_ms(500);
    }
}

关键代码解析

  • P1 = 0x00; 与 P1 = 0xFF;—— 这里不需要 sbit 位定义，直接对整个字节赋值就能同时控制 8 个引脚。 这也顺便证明了 P1 口「8 位并行输出」的本质：写一个字节，8 个引脚的锁存器同时更新。
  • P1 = 0xFF; 是上电第一件事——为什么强调这个？ 因为 51 复位后各 IO 口的默认值就是 0xFF（全高）， 我们显式写一遍，是为了让代码意图明确，也便于以后换成 P0 口时提醒自己别忘了上拉电阻。
  • Delay_ms(1000)——延时循环靠 CPU 空转实现， 它依赖晶振频率：晶振停了，CPU 就不执行指令，灯会停在某个固定状态一动不动； 晶振频率翻倍，所有延时都会减半。这就是「用灯的快慢反推晶振」的原理。
  • while (1)——主循环只做一件事：翻转 P1。 阶段 3 的输出（全亮/全灭）比单个 LED 心跳更容易远距离观察， 也更方便你用手机秒表在几步外计时。
  • 自检的顺序有讲究：先验证「能不能执行指令」，再验证「是不是从头开始」， 最后验证「时钟准不准」。这样一旦灯在阶段 1 就没反应， 你可以立刻断定问题出在电源/EA/晶振，而不用怀疑复位电路。
想直接测晶振频率？

上面用灯来间接判断。如果你有示波器，把探头打到 XTAL2（第 18 脚）， 应该看到一个峰峰值 4V 左右的近似正弦波，频率就是晶振频率。 也可以用带频率档的万用表（把量程放到 MHz 档）读一个近似值—— 注意读数通常比标称值低百分之几，那是探头与万用表输入电容把负载电容拉大了，属正常现象。

现象演示说明

最小系统是一个「全有或全无」的电路：四要素都对了，现象会严格按阶段出现； 任何一个不对，现象都会停在整个流程的某一步。所以下面这张判据表 本质上是把「症状」映射到「四要素中的哪一个」。

正确现象（按时间顺序）

  1. 合上电源开关的瞬间，8 颗灯同时全亮，持续约 1 秒。
  2. 随后全灭 0.3 秒、全亮 0.3 秒，不快不慢地重复 3 次——这就是肉眼可数的「自检闪」。
  3. 第 4 次起进入心跳：全亮 0.5 秒、全灭 0.5 秒，长期不停。
  4. 按一下复位键，整套现象立即从头重演（又先全亮 1 秒、再闪 3 次）。
  5. 断开电源后立刻再上电，现象同样从头开始（说明复位电容已经放完电）。

观察点与判据

你观察到的 说明什么 下一步查什么
8 颗灯全灭，一动不动，按键也没反应 CPU 一条指令都没执行：供电、晶振、EA 三选一 依次量：VCC 是否 5V → XTAL2 是否振荡 → 第 31 脚 EA 是否 5V
灯常亮不灭，永远停在阶段 1 RST 一直是高电平，芯片一直处在复位态（最常见是 10µF 接反或短路） 断电后量 RST 对地电压：正常上电瞬间约 5V，约 92ms 后降到 2.0V 以下，500ms 后接近 0V

心跳明显偏快（比如 0.5 秒一个周期） 板上晶振频率比预期高一倍，或 Keil 里 Xtal 设置与实际不一致 看晶振外壳上印的频率；重新按实际频率核算延时循环次数

做课程设计时，「最小系统是否可靠」通常占总分的很大一块。 建议在报告里写清：晶振型号与负载电容的计算过程、复位 RC 的时间常数计算、 EA 与 P0 的处理方式、去耦电容的位置，再附一张上电波形（有示波器的话量 RST 上电后从 5V 降到 0V 的那条曲线）。 这些内容比贴一张「灯亮了」的照片有说服力得多。

常见报错排查方案

硬件问题没有编译器给你的报错文字，但有同样明确的「症状原文」。 下面按「症状 → 原因 → 解决」列了六条，也是实验室里问得最多的六种。

症状：下载成功，但上电后 8 颗灯全灭、一动不动

原因：CPU 没有执行指令。按可能性排序：① 晶振没有起振（电容漏装、晶振虚焊、晶振损坏）；② 第 31 脚 EA 悬空或接地；③ 电源电压不足 4.5V。

解决：先量 VCC（应为 4.9~5.1V）；再用示波器看 XTAL2 有无振荡波形（有波形说明晶振没问题）；最后用万用表量第 31 脚对地电压，必须是 5V。三步定位。

症状：上电后 8 颗灯常亮不灭，按复位键也没变化

原因：RST 被持续拉高，芯片始终处于复位状态。最常见是 10µF 电解电容接反（漏电流大）、电容击穿短路，或者按键焊反/被压住导致 RST 常年接在 VCC 上。

解决：断电量 RST 与 GND 之间是否短路；确认电容正极接 VCC、负极接 RST；拔掉按键再试。可以临时把 10µF 拆掉（只用 10kΩ 对地），看程序是否能跑——能跑就说明问题在复位电路。

症状：用 P0 口写 1，万用表量到只有 1V 左右，LED 微亮

原因：P0 是开漏结构，内部没有上拉场效应管。输出 1 时引脚是高阻态，电压由外部电路决定，自然到不了 5V。这不是程序写错了。

解决：给 P0 口加 10kΩ 上拉电阻（推荐 10kΩ × 8 的 9 脚排阻，公共端接 VCC）。如果只是点灯，直接用 P1/P2/P3 口更省事——它们内部有弱上拉。

症状：程序「有时能跑、有时不跑」，复位按住时间长短会影响结果

原因：晶振起振余量不足。匹配电容取太大（如用 47pF 代替 30pF）、晶体老化、或者布线过长引入额外杂散电容，都会让振荡要「挣扎」一下才起振。

解决：把两个电容换成 22pF 或 30pF（按晶振规格书的 CL 反算）；把晶振尽量贴近第 18、19 脚；换一颗新的晶振。注意：不要试图用万用表去量晶振引脚，那会让它停振。

症状：STC-ISP 提示「正在检测目标单片机 ...」后超时，反复上电也不行

原因：虽然看起来是软件问题，但在最小系统板上有两个硬件根源：① 晶振没起振——STC 芯片靠串口波特率与内部时钟配合握手，时钟不对就握不上；② 串口线与 P3.0/P3.1 接错或没共地。

解决：先确认 P3.0 接模块 TXD、P3.1 接模块 RXD、GND 共地；再把 STC-ISP 的最高波特率降到 4800 甚至 2400 后重试；最后用示波器确认晶振在工作。

症状：运行中偶尔自己重启，手机靠近时更明显

原因：这是典型的电源完整性问题——缺去耦电容，或者电源本身用的是劣质 USB 口/长杜邦线，抗干扰能力差。 解决：在第 40 脚旁紧贴一个 104 陶瓷电容；电源入口加 100µF 电解；缩短供电线；有条件时用独立稳压电源（如 7805 + 变压器）而不是电脑 USB 口。

小结与练习

这一篇的核心是一张「四要素 + 两处必查」的清单： 电源（5V + 104）、晶振（+ 两个 30pF）、复位（10µF + 10kΩ）、单片机本体， 外加 EA 接高电平 与 P0 口要上拉。 每一个元件的参数都不是经验口诀，而是从器件手册的指标反算出来的： 负载电容来自晶振的 CL，复位 RC 来自「两个机器周期」这个最低要求，去耦电容来自 di/dt 引起的电源跌落。

动手练习
  1. 把复位 RC 改小算一遍：把 10µF 换成 1µF（τ = 10ms），重新算出 RST 电压从 5V 降到 2.0V 以下的时间点（约 9ms）， 再对比「两机器周期 = 2µs」的要求，说说为什么仍然够用、以及在什么情况下会不够用。
  2. 验证 EA 的作用：把第 31 脚从 VCC 改接到 GND，重新上电，记录现象； 再改回 VCC 确认程序恢复。如果你的板子是 Proteus 仿真，这一项不用改硬件就能做，也一样要记录现象。
  3. 在 Proteus 里搭最小系统并量波形：画出最小系统原理图，用虚拟示波器同时看 XTAL2 与 RST 两个点， 截下上电瞬间的波形，标注出 RST 从 5V 降到 2V 门限的时间，与本文表格里算出的 92ms 对比。
