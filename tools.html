单片机在线工具

四个调程序时最常用的小工具：进制转换、51 定时器延时计算、串口文本与 HEX 互转、CRC 校验。 全部由浏览器里的 JavaScript 即时运算，不上传任何数据、断网也能用， 想抄的初值和代码直接点复制按钮就行。

4 个工具 纯本地运算 无需联网 数据不外传
进制转换 51 延时计算器 串口转换 CRC 校验
使用说明

所有输入框都是实时联动的——改一个框，其余结果立刻跟着变，不需要点“计算”按钮。 计算全部在本地完成，关掉网络照样能用；刷新页面会清空输入，重要的初值记得随手复制到工程里。

使用说明与常见场景
  • 三个框随便填哪个都行，另外两个会自动算出来；粘贴 0x1F、1111 0000 这种带格式的内容也能识别，离开输入框时会自动整理干净。
  • 算寄存器初值：例如定时器算出初值 15536，转成十六进制看到 0x3CB0，就能直接写成 TH0 = 0x3C; TL0 = 0xB0;。
  • 算 IO 口输出：要让 P1 的 8 个 LED 中某一颗熄灭，先想出二进制的位模式（如 1111 1110），转成十六进制就是 0xFE。
  • 看字节序：串口协议里 16 位数据是“高字节在前”还是“低字节在前”，用字节视图一眼就能确认。
  • 内部用 BigInt 计算，最大支持 64 位整数，不会出现 32 位溢出导致结果错乱的问题。
  • 把结果分享给别人：地址后面加 ?v=0x1F 这样的参数，打开时就会自动填好。

Tool 02 · 51 Timer Delay

51 单片机延时计算器

按晶振频率、时钟模式与工作方式反算定时器初值，并直接生成一段可编译的 Keil C 代码。

含完整代码
容易算错的几个地方
  • 机器周期不是晶振周期。传统 51 一个机器周期 = 12 个振荡周期，所以 12MHz 晶振下一个机器周期是 1µs；STC 的 1T 系列才是 1 个振荡周期。
  • 方式 1 单次最长只能定时 65536 个机器周期。12MHz/12T 下约 65.5ms，超过就必须靠多次溢出累加，代码里的 OVERFLOW_TIMES 就是这个次数。
  • 方式 1 和方式 0 必须在中断里手动重装初值，只有方式 2 是硬件自动重装，忘了重装会导致第二次定时直接乱掉。
  • 要做串口通信就选 11.0592MHz。它能让波特率误差为 0；用 12MHz 虽然能算，但波特率会有偏差，收发容易出错。
  • 定时器中断里不要放长延时或串口打印，会拖长中断时间，导致定时越来越不准。
使用说明
  • 选好晶振、工作方式，填上“需要延时多久”，下面立刻给出机器周期、需要的总机器周期数、溢出次数、TH/TL 初值和实际误差。
  • 误差那一栏如果显示“固有误差”，说明是机器周期取整带来的不可避免的偏差（最大不超过一个机器周期），属于正常现象。
  • 生成的代码可以直接全选复制到 Keil 里编译：已经包含 TMOD 配置、初值装载、中断服务函数与中断开关。
  • 把这段代码当模板，把 OVERFLOW_TIMES 和 TH/TL 换成自己的值，就是最标准的 51 定时器写法。

Tool 03 · Serial Converter

串口转换（ASCII ↔ HEX）

调串口时的“翻译官”：把要发的文字变成十六进制字节，或把抓到的字节流还原成文字。

双向实时

使用说明
  • 两个框是双向实时的：在左边打字，右边立刻出现对应的十六进制；在右边改字节，左边立刻还原成文字。
  • 十六进制一侧很宽容：0x 前缀、空格、逗号、冒号、连字符、换行都能当分隔符，从串口助手直接整段粘贴过来就行。
  • 写 Modbus、AT 指令这类协议时，用“每字节加 0x 前缀 + 逗号分隔”，结果可以直接粘进 C 数组。
中文为什么变成乱码了？

这个工具按 UTF-8 编码转换，而 Keil 工程和大多数串口助手默认用的是 GBK。 同一个汉字在两种编码下的字节完全不同，所以“文本 → HEX”的结果贴到串口助手里可能显示为乱码，或者反过来还原不出来。 这属于两端编码不一致，不是数据算错了。要传中文，建议约定统一用 UTF-8； 如果做不到，就干脆别在串口协议里传中文，只传 ASCII 字符加数值，最省事也最不容易出问题。

Tool 04 · CRC Check

CRC 校验计算

输入十六进制数据，自动算出 CRC-8 / CRC-16 校验值，并生成可直接使用的 C 数组。

6 种算法

支持 0x 前缀，空格、逗号、冒号、连字符分隔；不含校验值本身。

该选哪个算法？
算法 典型用途 备注
CRC-16/MODBUS Modbus RTU、工业仪表、485 通信 发送时低字节在前
CRC-8/MAXIM-DOW DS18B20、DS2431 等 1-Wire 器件 读回 8 字节暂存器后用第 9 字节对比
CRC-8 自定义通信协议的数据帧校验 实现最简单，1 字节开销
CRC-16/CCITT-FALSE X.25、部分无线模块与蓝牙协议 初值 0xFFFF
CRC-16/XMODEM XMODEM 文件传输、固件升级帧 初值 0x0000
CRC-16/ARC 早期磁盘与部分工业仪表 IBM 传统算法
使用说明
  • 输入框里只填参加校验的数据，不要把校验值本身也填进去，否则算出来的一定不对。
  • 结果面板会同时给出十六进制、十进制、参与计算的字节长度；16 位算法还会给出高字节在前和低字节在前两种顺序，按你的协议挑一个。
  • 下面的 C 数组已经把原始数据和校验值拼在一起了，直接复制到工程里就能用。
  • 页面顶端那个绿色的自检徽章，是用权威标准值（对 ASCII 字符串 "123456789" 的校验结果）在每次打开页面时自动验证一遍算法实现——徽章是绿的，说明算出来的值可信。
  • 单片机端要自己写 CRC 函数时，别用查表法的网传代码直接抄，先用这个工具生成几组“数据 → 校验值”的对照，测通了自己写的函数再用。

还想要什么工具？

这四个工具覆盖了调程序时最高频的计算需求。如果你在做课设时反复手算某个东西——比如波特率误差、 PWM 占空比换算、电阻分压、电池续航估算——那它就值得做成一个页面工具。 工具都是纯前端 JavaScript，没有后端依赖，照着 assets/js/tools.js 里的写法加一个函数就能扩展。
