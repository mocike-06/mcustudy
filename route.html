阶段 1

通用基础：电学 · 数字电路 · C 语言

建议 2~3 周

这一步不是让你从头学一遍《C 语言程序设计》，但下面这几块必须真的懂， 不能只混个眼熟：电路怎么算、二进制怎么转、寄存器是什么、代码写完怎么变成芯片里的程序。 这些是三个方向共用的地基——无论你最后走 51、STM32 还是 ESP32，都绕不过去。

不要跳过这一阶段
跳过地基直接抄代码，你会得到一种很典型的体验：代码能跑，但一旦现象不对，你完全不知道该从哪里查。 更糟的是，后面遇到「P1 的字节地址是 0x90」 「把 TMOD &= 0xF0 写进去」这种句子时， 你会以为自己学不会单片机，其实只是缺了这一层。

想要更系统的？这里还有一张知识体系地图
基础篇只讲「动手时够用」的部分。如果想按学科本来的顺序把理论补齐 （电路 → 模电 → 数电 → CPU 与中断 → 芯片外设 → RTOS）， 我们照着高校热门教材的目录，整理了 45 篇知识专题， 都收在 知识体系地图 里， 分三层，每篇都标了对应的教材章节。

重点知识

  • 电路怎么算——欧姆定律与分压公式、LED 限流电阻、 高低电平的含义与 3.3V/5V 能不能直连。这是看懂原理图的前提，也是唯一一类“算错就一定不工作”的知识。 详见 电学基础、 常用元件 与 数字电路与电平。
  • 数制与位运算——嵌入式里用得最多的东西，没有之一。 先把二进制与十六进制互转练熟，再掌握四个标准动作：置位用 |、 清零用 & ~、翻转用 ^、 判断某一位用 &、移位用 << 和 >>。 点灯、配置寄存器、解析协议，全靠它。详见 数制与位运算。
  • 寄存器与 SFR——单片机的所有外设本质上都是“一组映射到地址上的开关”， 写寄存器就等于拨开关，位寻址则是直接拨其中一位。这是全站出现频率最高、却最容易被跳过的概念。详见 单片机内部结构与寄存器。
  • C 语言真正要用的部分——数组（单片机里主要用于“查表”： 数码管段码表、LED 流水模式表、LCD 字模表，重点是 code 关键字把常量放进 Flash）、 指针（*p 取值、&a 取地址， 以及“函数想修改调用者的变量时必须传指针”）、宏定义（给引脚和常量起名字， 带参数的宏一定要加括号）、数据类型位宽。 51 上 char 是 8 位、int 是 16 位（不是 PC 上的 32 位），long 才是 32 位。 详见 C 语言基础。
  • 从源码到芯片——编译器把 .c 变成 HEX 经历了哪几步、 为什么优化等级会毁掉软件延时、下载为什么要冷启动。知道这条链路， 一半的“编译不过”和“下载没反应”都能自己解决。详见 从源码到芯片。

位运算速查

/* 以 P1 口的第 3 位（P1.3）为例，其余位保持不变 */

P1 |=  (1 << 3);        /* 置 1：把 P1.3 拉高 */
P1 &= ~(1 << 3);        /* 清 0：把 P1.3 拉低 */
P1 ^=  (1 << 3);        /* 翻转：原来是 1 就变 0，是 0 就变 1 */

if (P1 & (1 << 3)) {    /* 判断某一位是不是 1 */
    /* 注意括号：& 的优先级比 == 低，写 (P1 & 0x08 == 8) 是错的 */
}

/* 循环左移一个字节（流水灯最常用的写法） */
unsigned char rol8(unsigned char x)
{
    return (x << 1) | (x >> 7);   /* 移出去的最高位补到最低位 */
}
动手练习：LED 流水灯逻辑
  1. 假设 8 个 LED 接在 P1 口，且低电平点亮。写出“只有最右边一颗亮”时 P1 的二进制值，然后用进制转换工具转成十六进制。
  2. 把流水灯一圈的 8 个状态值写成一个数组，用 for 循环依次输出，循环体里加一段简单的软件延时。
  3. 改用位运算实现：不用数组，只用 (x << 1) | (x >> 7) 让一个变量自己循环移位。
  4. 进阶：把这个逻辑写成一个纯 C 程序，在 Keil 里用软件仿真单步执行，观察变量的值怎么变——不接硬件也能验证逻辑对不对。
避坑提示
  • 别把 int 当 32 位用。51 的 int 只有 16 位，最大 32767，减法算超过这个范围就会溢出成负数，计数值要用 unsigned int 或 long。
  • 位运算的括号不能省。& 的优先级低于 ==，if (P1 & 0x01 == 1) 会被理解成别的东西，必须写 if ((P1 & 0x01) == 1)。
  • 数组越界不会报错。51 上没有运行时检查，写越界只会悄悄改掉别的变量，然后你会看到一个“莫名其妙变了值”的 bug。
  • #define 结尾不要加引号外的东西。宏定义行末加分号，展开后就会出现两个连续分号或多一个分号，导致语法错误。
  • 中断里会改的变量要加 volatile。否则编译器优化后可能一直读寄存器里的旧值，导致主循环里的判断永远不成立。

阶段 2

STC89C52 51 单片机入门

建议 3~4 周

真正的入门阶段。51 结构简单、资料最多、寄存器一眼能看完，是建立“单片机到底怎么工作”这个概念最划算的芯片。 这个阶段结束后，你应该能独立完成“按键触发 + 定时控制 + 串口上报 + 屏幕显示”这类组合功能。

重点知识

  • IO 口——准双向口的含义、灌电流与拉电流的区别、限流电阻怎么算。要记住 P0 口是开漏输出，驱动 LED 必须外接上拉电阻，这一点和 P1/P2/P3 不一样。
  • 定时器——机器周期与晶振的关系、TMOD 与 TCON 的配置、方式 0/1/2 的区别、TH/TL 初值怎么算、定时器中断怎么写。这是整个 51 里最重要的一块。
  • 外部中断——INT0/INT1 的触发方式（低电平触发与下降沿触发）、中断号、中断服务函数里能做什么和不能做什么。
  • 串口通信——SCON 与波特率的计算、为什么串口通信推荐 11.0592MHz 晶振、发送与中断接收的写法。
  • LCD1602——HD44780 控制器的指令集、RS/RW/EN 三个控制脚的作用、8 位与 4 位数据总线的取舍、为什么要等忙标志。
动手练习：串口收发 + 定时器计时
  1. 用延时计算器算出 50ms 定时所需的初值，做一个用定时器精确计时的秒表，在串口助手里每秒打印一次计数值。
  2. 做一个“串口点灯”：上位机发 LED_ON 点亮，发 LED_OFF 熄灭，收到无法识别的指令就回复一句提示。
  3. 接收部分不要用“死等”方式，改成串口中断 + 缓冲区：中断里只负责把收到的字节存进数组，主循环里再判断完整的一帧，这是实际项目的标准做法。
  4. 把秒表的值显示到 LCD1602 上，同时串口上报——两个输出通道同时验证，能更快定位问题出在计算还是出在显示。
避坑提示
  • 晶振别乱选。要做串口通信就用 11.0592MHz，它能整除标准波特率、误差为 0；用 12MHz 虽然定时算起来是整数很舒服，但波特率会有偏差，通信用它容易出错。
  • 串口乱码几乎都是这三件事。一是晶振与波特率不匹配；二是两边波特率没对齐（注意串口助手默认可能是 9600）；三是两边编码不同，中文当然显示成乱码，用串口转换工具对一下字节就知道是谁的问题。
  • 晶振旁边的两个 30pF 电容不能省。它们不是“滤波”，是配合晶体起振的负载电容，省掉以后现象是“有时能跑有时不跑”，非常难查。
  • 中断服务函数里不要写延时、串口打印这类耗时操作。中断执行时间过长会丢掉后续的中断请求，表现为“偶尔少计一次数”。
  • 只有可位寻址的地址才能用 sbit 定义。例如 TMOD 的地址是 0x89，不是 8 的倍数，所以不能写 sbit xxx = TMOD^0;，必须整体赋值。

阶段 3

Proteus 仿真

建议 1 周

仿真不是“玩具”，它最大的价值是把硬件问题和程序问题分开。 元件还没到货、板子焊错了、芯片烧了，都可以先用仿真验证程序逻辑； 反过来，仿真里跑得通的现象也能帮你确认代码本身没问题。

重点知识

  • 原理图绘制——放置元件、连线与网络标签的区别、电源与地怎么接、晶振和复位电路怎么画。养成用网络标签而不是拉长线的习惯，图会干净很多。
  • 仿真调试——给你的单片机加载 Keil 生成的 HEX 文件、运行与暂停、用探针观察引脚电平、用虚拟串口终端看串口输出、用虚拟示波器看 PWM 波形。
  • 元件库导入——当搜索不到某个元件时怎么办：先确认拼写和库名，再导入第三方库文件并注册到 Library 目录，最后重启软件。
动手练习：最小系统仿真
  1. 从零画一遍 51 最小系统：单片机 + 晶振 + 两个 30pF 电容 + 复位电路 + 电源，然后在 P1 口接 8 个 LED 和限流电阻。
  2. 把阶段 2 写的流水灯程序编译出的 HEX 加载进去，运行仿真，确认灯真的在流动。
  3. 接一个虚拟串口终端（COMPIM 或 virtual terminal），把阶段 2 的串口点灯程序跑一遍，用键盘在终端里敲指令。
  4. 故意把晶振频率从 11.0592MHz 改成 12MHz 再运行，观察串口输出变成乱码——亲手复现一次，比看十遍文字印象深。
避坑提示
  • 报错“No model specified for U1”不是电路画错了，是这个元件只有图形符号、没有仿真模型。换一个带仿真模型的型号（例如用 AT89C52 代替找不到模型的型号）即可。
  • 仿真跑起来完全没反应，先查三件事：HEX 文件有没有正确加载（路径别带中文）、晶振属性里的频率填了没有（默认可能是 0）、电源和地有没有接上。
  • 仿真通过 ≠ 实物一定通过。仿真不会体现接触不良、电源带不动、干扰、走线电感这些真实问题。仿真用来验证逻辑，实物用来验证电路，两者不能互相替代。
  • 注意元件库的版权风险。网上流传的第三方元件库多为自己整理的版本，建议只用于个人学习，别用在商业项目里。
  • 项目文件不要放在中文路径下。Proteus 对中文路径的支持时好时坏，加载 HEX 失败有一半是路径问题。

阶段 4

STM32 HAL 库开发

建议 4~6 周

从 8 位跨到 32 位，最大的变化不是“功能更多”，而是思维方式的转变： 引脚要复用、外设要先开时钟、中断有优先级、代码由工具生成。 这个阶段建议用 STM32CubeMX 生成工程骨架 + HAL 库写业务逻辑，把精力放在理解外设上，而不是背寄存器地址。

重点知识

  • GPIO——推挽输出与开漏输出的区别、上拉/下拉输入的选择、四种速度档位的影响，以及 HAL 库里的写、读、翻转三个函数。
  • USART——CubeMX 里配波特率与引脚、阻塞发送与中断接收、把 printf 重定向到串口的方法，以及接收不定长数据的几种思路。
  • 定时器与 PWM——定时器时钟从哪来、预分频与自动重装值怎么算频率、PWM 的占空比怎么调。这是做电机调速、呼吸灯的基础。
  • ADC——12 位分辨率、参考电压、轮询/中断/DMA 三种采集方式，以及原始值到电压的换算公式。
  • I2C 与 OLED——I2C 的地址与读写时序、用 HAL 库发送一个字节、SSD1306 驱动的移植、显存刷新的概念。
  • 外部中断——EXTI 线与引脚的映射关系、NVIC 优先级分组、回调函数的机制。
动手练习：电压采集 + PWM 调光
  1. 用 ADC 采集一个电位器的分压电压，把原始值按公式换算成电压，显示到 OLED 上，同时通过串口打印。
  2. 给采集到的电压做软件滤波：连续采样 10 次取平均，观察显示值跳动的幅度有没有变小。
  3. 用定时器输出一路 PWM 驱动 LED，做一个“呼吸灯”：占空比在一段时间内从 0 平滑升到最大值再降回来。
  4. 把两个功能合起来：用 ADC 读到的电压值去控制 PWM 的占空比，做成一个手动调光旋钮。
  5. 再加一路外部中断按键，按下时切换“手动调光 / 自动呼吸”两种模式。
避坑提示
  • 时钟没使能，外设就完全不动。这是 STM32 最经典的坑：代码看着没问题，引脚就是没反应。用 CubeMX 生成代码时会自动加上使能语句，但如果你是手写初始化，忘了 __HAL_RCC_GPIOx_CLK_ENABLE() 就会卡在这里。
  • 时钟配置错误会连锁反应。外部晶振频率填错、PLL 倍频算错，会导致串口波特率全错、定时器时间全错。串口乱码时，先查时钟树和系统主频，别急着改代码。
  • HAL 库的回调函数里不要做耗时操作。HAL_GPIO_EXTI_Callback 这类回调是在中断上下文里执行的，里面不能调用 HAL_Delay（它会依赖 SysTick 中断，造成死锁）。
  • CubeMX 重新生成代码会覆盖你写的部分。一定要把代码写在 /* USER CODE BEGIN */ 和 /* USER CODE END */ 之间，写在区域外的内容下次生成时就没了。
  • 烧录后不运行，先查跳线和复位。BOOT0/BOOT1 的跳线位置不对会让芯片从错误的地址启动；有些板子还需要手动按一下复位。
  • HAL 库比标准库慢、代码也更大。这是拿开发效率换运行效率的取舍。做实时性要求高的场合（例如高频 PWM 或精确时序）时，该直接操作寄存器就操作寄存器。

阶段 5

ESP32 物联网实战

建议 2~3 周

收口阶段，也是最容易做出“能拿出去演示”的作品的阶段。 ESP32 自带 WiFi 和蓝牙，不用外挂模块，几十块钱就能做出手机能控制的东西—— 这对课设、实训、毕业设计来说性价比极高。

重点知识

  • GPIO 与 ADC——数字输入输出、哪些引脚有特殊限制、哪些引脚能做模拟输入、用 LEDC 输出 PWM。
  • WiFi 连接——STA 模式（连路由器）与 AP 模式（自己当热点）的区别与适用场景、断线重连的处理。
  • 蓝牙——经典蓝牙串口的使用方式、手机端怎么收发数据、与 BLE 的选型区别。
  • MQTT——Broker、Topic、发布与订阅这套模型，以及如何接入公共物联网平台，让数据能被远程看到。
  • 传感器——DHT11 读温湿度、DS18B20 单总线读温度、多传感器挂同一条总线时怎么区分。
动手练习：手机远程控制 LED
  1. 先跑通 WiFi 连接，把 ESP32 拿到的 IP 地址通过串口打印出来，确认网络这一步没问题。
  2. 在 ESP32 上跑一个内置的 Web 服务器，让手机浏览器访问那个 IP 就能看到一个带两个按钮的页面。
  3. 点按钮控制 LED 亮灭：手机上发出请求，ESP32 解析请求并改变 GPIO 电平，页面刷新时显示当前状态。
  4. 进阶一：把 LED 状态换成继电器，就能控制台灯、风扇这类真实电器（注意强电安全，务必断电接线）。
  5. 进阶二：把 DHT11 的温湿度数据也显示在同一个网页上，做成一个手机端的小型监控面板。
避坑提示
  • 配网失败，先确认路由器是不是 2.4GHz。ESP32 不支持 5GHz 频段，很多人家里的路由器默认只开 5G 或者双频合成了一个名字，这时 ESP32 是连不上的。把 2.4G 单独分一个 SSID 出来。
  • 串口全是乱码，先看波特率。ESP32 的日志默认是 115200，串口助手还停在 9600 就全是乱码。另外在 Arduino IDE 里要选对开发板型号，选错了也会乱码。
  • GPIO6~GPIO11 不要用。这几个脚接着芯片内部的 Flash，占用之后程序会直接跑不起来，而且是那种“烧录成功但不运行”的迷惑现象。
  • 下载失败时按住 BOOT 键。自动下载电路有时不灵敏，按住 BOOT 键再点上传、看到开始写入后松开，基本都能解决。
  • WiFi 打开后 ADC2 不能用了。这是硬件层面的资源冲突，不是代码问题。需要同时用 WiFi 和模拟采集时，改用 ADC1 对应的引脚（GPIO32~GPIO39）。
  • 主循环里记得留出让出 CPU 的机会。在 loop() 里加一个 delay()，否则 WiFi 协议栈得不到运行时间，会触发看门狗复位，表现为“连上 WiFi 几秒后就重启”。

After That

五个阶段之后做什么

路线走完只代表“工具都会用了”，真正的提升来自做完一个完整的东西。

1

选一个题目做完整

去实训毕设案例里挑一个， 从硬件选型、画图、焊板、写程序一直到写报告走完一遍。完整性比难度重要得多。

2

把代码整理成能给别人看的

分模块、写注释、统一命名。答辩时老师问“这段是干什么的”，你能立刻指出来，印象分完全不同。

3

补一个“可扩展方向”

在报告最后写一两段“如果继续做，还可以加什么”。这属于加分项， 也是你后面做毕设时的现成切入点。

关于“学不完”这件事

嵌入式的东西确实多，模电、数电、操作系统、网络都沾一点。但请注意区分两种知识： 阶段 1 列出的那几块是地基——它们必须懂，而且越早懂越省时间； 剩下的深度（复杂的电源设计、RTOS 调度细节、射频匹配）属于“用到再学”的类型。 不要指望把这些全学完再动手，也不要在什么都不懂的情况下硬抄代码， 按这条路线把最小闭环走通，你就已经超过大多数停在“准备阶段”的人了。
